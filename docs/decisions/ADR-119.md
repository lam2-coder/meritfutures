## ADR-119: the demo world is a VALUE at `scripts/demo/world.ts`, not a Postgres seed, and naming it reopens `CI-09` on purpose  (2026-08-26, status: proposed)

**[STRATEGY section 4.1](../testing/STRATEGY.md) has closed `CI-09`'s replay self-audit leg `(b) Waiting` since 2026-08-20 on an artifact called *"a demo-world seed script"*, and [session 121](../sessions/2026-08-21-session-121.md) rowed that artifact **"Registered. Names neither a path nor a manifest key"**.** That is one of the four conditions [ADR-073](ADR-073.md) section 2 (b) requires to be a path or a manifest key and is not, and `CI-06/gate-inventory` has reported it unprobeable on every run since. **NAMING THE PATH IS THE RULING**, which is why the condition sat open for six days across nine sessions: a session that invented a path would have closed a registered condition by fiat, and the register exists so that cannot happen quietly.

This entry rules the path, rules that the world is a **value and not a database**, records that the artifact's arrival **turns `CI-06/gate-inventory` red on purpose**, and names the two pieces of work that are owed and the sessions that take them.

- **Origin:** [STRATEGY section 4.1](../testing/STRATEGY.md)'s `CI-09` row, session **231**. The number was **RESERVED BEFORE DISPATCH and REQUIRED** ([ALLOCATION](ALLOCATION.md)), and the row is amended in place per [ADR-065](ADR-065.md) T3. **Not a money path by subject.** It unblocks [`P4-g`](../plans/P4-portal-and-site.md), which is: [M12 section 3.1](../plans/M12-transparency-platform.md) will not publish a statistic computed over a day whose self-audit diverged, and until today no self-audit had ever run over a day.

- **Context:** [session 118](../sessions/2026-08-20-session-118.md) found the distinction this entry turns on and stated it in one line: **"HAS A SUBJECT" AND "HAS AN INPUT" ARE DIFFERENT THINGS.** [`replay.ts`](../../apps/worker/src/batch/replay.ts) is 628 lines and `runReplayAudit` is exported and reachable. What it has never had is a WORLD. Its `OI-14` refusal fires on `storedRows > 0 && inScope === 0`, so over zero stored rows it does not fire at all and a nightly built on it would report `accountsAudited: 0, diverged: 0`, green, every night, over nothing. [ADR-073](ADR-073.md) section 5 refused to build the leg for exactly that reason and named the artifact that would unblock it.

### 2. THE RULING

> **1. THE ARTIFACT IS [`scripts/demo/world.ts`](../../scripts/demo/world.ts), A PATH, AND THE REGISTER ENTRY FOR *"a demo-world seed script"* IS RETIRED.** `CI-09`'s replay self-audit condition names that path and no other string, and [STRATEGY section 4.1](../testing/STRATEGY.md)'s row is amended to carry it. The unprobeable register shrinks from four entries to three, which is the direction [session 121](../sessions/2026-08-21-session-121.md) said nobody looks and `register-shrinks-when-an-artifact-is-re-ruled` asserts.
>
> **2. THE DEMO WORLD IS A VALUE AND NOT A DATABASE, AND THIS IS THE HALF A LATER SESSION WILL WANT TO OVERTURN.** The world is `BatchPorts` over an in-memory day stream, because `runReplayAudit` reads `BatchPorts` and nothing reads Postgres into one (finding 1), and because `rule_states` could not serve a `prior` back even if something did (finding 2). **A database seed today would give the replay leg a SUBJECT and still no INPUT**, which is session 118's distinction repeated one level down and is the one thing this session had to not do quietly.
>
> **3. [INFRA section 11](../architecture/INFRA.md)'s SEED SCRIPT IS A SECOND, DIFFERENT ARTIFACT AND IS NOT THIS ONE.** It seeds plans, a calendar, 50 traders, flags, payouts and affiliate data into a local database so **surfaces** are developable offline. It is unbuilt, it is not blocked by this entry, and when it is built it is a Postgres seed. **Neither artifact substitutes for the other**, and this clause exists so that a session reading INFRA's sentence does not conclude that `CI-09`'s condition was met by it, or the reverse.
>
> **4. NO FIXTURE FORMAT IS INVENTED. THE WORLD IS M1'S DAY STREAM, WHICH IS `apps/worker`'s OWN TYPE.** An account's world is its `AccountDay[]`, folded through `foldAccountDay`, with the resulting `RuleStateRow`s kept. [ADR-072](ADR-072.md)'s vocabulary is untouched and no `GS-nnn` row moves. The stored side is written by the batch's fold and is never hand-authored, so the world cannot contain a state the engine would not produce.
>
> **5. THE FOLD IS `foldAccountDay` AND NOT `runNightlyBatch`, AND THAT IS FORCED RATHER THAN PREFERRED.** Finding 7: the report drops the `RuleState` a second day needs and `RuleStateRow` cannot rebuild one. There is still exactly ONE fold, it is the batch's, and M01 section 3.7's *"there is no second code path"* is satisfied in the sense that section means it: one expression of the fold, called from one more place.
>
> **6. THE ARRIVAL OF THIS ARTIFACT TURNS `CI-06/gate-inventory` RED, AND THE RED IS THE CONDITION WORKING.** ADR-073 (b)'s second sentence is *"the day it arrives the row is a finding until the stage is written"*, and STRATEGY section 4 restates it. Landing the world without the stage is therefore expected to fail that gate, it does, and section 5 below records the exact output on the exact commit. **A gate that fails on good news is not a gate to route around**, and no probe, register entry or row wording in this entry is chosen to make it green.
>
> **7. THE REFUSAL ON `accountsAudited === 0` LIVES IN THE SEED RUNNER AND IS OWED A HOME IN `replay.ts`.** ADR-073 section 5 closed with *"when it is built it refuses on `accountsAudited === 0`"*. `runReplayAudit`'s `OI-14` guard cannot see that case, `apps/worker` was outside this session's fence, and so the refusal is in [`seed-world.ts`](../../scripts/demo/seed-world.ts) and [`world.ts`](../../scripts/demo/world.ts) today. **A refusal in the caller is weaker than a refusal in the audit**, because the next caller inherits nothing, and section 6 rows it as owed rather than leaving it as a comment.

### 3. The alternative, argued: seed Postgres, which is what "seed script" sounds like

**It is the reading the words invite and it is the wrong one, and it is worth arguing rather than asserting because it will be proposed again.**

PostgreSQL 16 is in this container. All 47 migrations apply. Writing a script that inserts a plan version, a calendar, six accounts, ninety-four `daily_marks` and ninety-four `rule_states` rows is an afternoon, and at the end of it **`runReplayAudit` still cannot read one of them**. There is no adapter. The audit's whole input surface is `BatchPorts`, and the set of things in this repository that produce a `BatchPorts` from a database is empty.

**The second half is worse, because it does not clear when the adapter lands.** `BatchReadPort.accountDaysFrom` returns `AccountDay[]`, and `AccountDay.prior` is a `RuleState`. `RuleState` carries `lifetimeSettledCents`, `breached` and `breachKind`; `rule_states` has a column for none of the three. So a world seeded into Postgres **cannot be read back as a day stream at all** without a migration, and this session was dispatched with `0048` held free.

**So a Postgres seed today buys a row count and no audit.** It would satisfy a reader grepping for the word "seed" and would leave `CI-09`'s leg exactly where ADR-073 left it, with the difference that the register entry would have been retired and the condition would look closed. **That is the failure mode ADR-073 section 2 (b) is entirely about**, and it is why this entry rules the shape of the artifact and not only its path.

**What would change this ruling**, stated so the reversal is cheap when it is right: an adapter implementing `BatchPorts` over `scopedDb`/`systemDb`, plus a migration giving `rule_states` the three fields or a ruled derivation for them. **On that day the value-shaped world does not become wrong**; it becomes the fast one, and the database-shaped world becomes the one that additionally proves the adapter. Both are worth having and this entry blocks neither.

### 4. What the world is, and the four things it deliberately does not exercise

**Six accounts across three cohorts, twenty-five weekday sessions, Core EOD at 50K, 94 stored rows.** It is the demo's own default run ([`main.ts`](../../scripts/demo/main.ts)), seeded rather than printed, and that is deliberate: a second demo population whose divergence from the first nobody would notice is how a fixture stops describing anything. Three accounts reach the funded phase and three breach, which is what [`scripts/demo/README.md`](../../scripts/demo/README.md) already documents about the same seed.

| Not exercised | Why, and what it costs |
|---|---|
| **Settlements** | Every `AccountDay.settlements` is empty. There is no settlement source in this repository and one invented here would be a money fact nobody ruled. Group H never runs, no account acquires a `cadenceAnchorDay`, **R-37 is skipped on every row** |
| **The calendar** | Consecutive weekdays, no holidays, no early closes, no halts. **There is not one calendar row in this repository** ([P2](../plans/P2-rules-engine.md) section 6) and transcribing the CME publication from recollection is what `TR-01` forbids. R-04 is present in the engine and unexercised |
| **The context gates** | `CLEAN_CONTEXT` answers all five of R-40's questions permissively. `INV-23` keeps them out of the hash, so they change no comparison; they are stored because `0015`'s column is `NOT NULL` |
| **The file and the normalizer** | The world calls `simulate()` and converts in memory. `INV-M2-11` is about the CSV rendering and the normalizer and **this proves nothing about either** |

**NONE OF THE FOUR WEAKENS WHAT THE AUDIT PROVES**, and the reason is structural rather than reassuring: the audit's subject is `INV-04`, that replaying the stream reproduces the stored state byte for byte. **A rule the world never exercises is a rule the world never exercises on BOTH SIDES of that comparison.** What a thin world costs is coverage of the ENGINE, which is `CI-03`'s job and not this leg's.

**Money is integer cents in every row, asserted and not assumed.** `assertIntegerCents` walks all seven money fields of every row the world holds and refuses on the first that is not a `bigint`, because a `number` that happens to be integral today reads exactly like a `bigint` and a seeded float in a demo world becomes a seeded float in every replay that reads it.

### 7. Three questions the dispatch asked, and the answers

**3. Does `CI-09` need a workflow leg? YES, AND IT IS OWED.** Section 6 item 2. `nightly.yml` is not in this session's fence and the leg is one job whose body is one command.

**One clause, checkable, executable, scoped to this entry's files: the world seeded and replayed, with the replay's output compared against the seed's OWN EXPECTATION, and then the same comparison proved able to fail.**

| # | What ran | Result |
|---|---|---|
| 1 | The world built from the default seed | **6 accounts, 94 stored rows.** 3 reached funded, 3 breached, 0 refused |

### 10. Alternatives considered

- **Seed Postgres.** Section 3, at length. **Rejected on two measurements**, either sufficient: nothing reads a database into `BatchPorts`, and `rule_states` cannot serve a `prior` back.
- **Put the world in `packages/db/src/seed/`.** It is where a reader looks and it is where the calendar sources are. **Rejected**: that directory is `packages/db`'s, its contents are SQL-bound inputs, and a `BatchPorts` value that never touches the database would be the second thing in it that is not a database seed. It would also need a manifest line and would spend a `VG-12` admission on a script.
- **A new workspace package, `@merit/demo-world`.** **Rejected** for the reason `scripts/demo/tsconfig.json` already records about the demo: *"making a demo a workspace package spends a VG-12 admission on a script that prints a table."* The admission is [session 23](../sessions/2026-08-15-session-23.md)'s open founder action and is not a session's to spend.
- **`scripts/ci/demo-world.ts`, beside `nightly-harness.mjs`.** **Rejected**: `scripts/ci` is reached by no `tsconfig`, so a TypeScript file there is typechecked by nothing and rots. `scripts/demo` is named explicitly in the root `typecheck` script and is a source root in `vitest.config.ts`, which is what gives the world a typecheck and a suite for free.
- **Keep the row's wording at *"a demo-world seed script"* and land the world quietly.** **Rejected, and it is the alternative this entry exists to refuse.** The register entry's stated reason is *"the condition names neither a path nor a manifest key"*; after this entry that reason is false, and a gate green over a false reason is furniture.
- **Fold with `runNightlyBatch`.** **Rejected by measurement rather than by preference** (finding 7): the report drops the state a second day needs.
- **Widen `SqlExecutorReason` with a `'seed'` member.** **Not reached**, because the world touches no database. Section 7.

### 12. Approval
