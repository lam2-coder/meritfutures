### 7. The blind spot, turned from a declaration into a setting

**`BLIND` ALREADY HELD AN ENTRY CALLED `transitive` BEFORE SECTION 6 WAS RUN**, saying this module names direct dependants only and that a caller must not read a short list as *nothing else is affected*. **Section 6 then produced an instance of exactly that entry**, which is the best evidence available that a written blind spot is worth more than a longer findings list.

So it is answerable rather than only named. `closure(root, target, hops)` and `--hops=N`:

| hops | files reached | what they are |
|---|---|---|
| **1** | **4** | `apps/api/test/event-placement.test.ts`, `apps/worker/test/replay-adapter.test.ts`, `packages/tooling/checks/absence-claims.mjs`, `packages/tooling/test/absence-claims.test.ts`. **EXACTLY ADR-419 SECTION 3.2's FOUR** |
| **2** | **6** | the four, plus `packages/tooling/checks/repo-invariants.mjs` and **`packages/tooling/test/repo-invariants.test.ts`, the file section 6 measured going red** |
| **3** | **15** | and by here it is answering a different question |

**EVERY FILE THE DELETION ACTUALLY REDDENED IS INSIDE THE TWO-HOP CLOSURE, AND ONE OF THEM IS OUTSIDE THE ONE-HOP CLOSURE.** A derived answer and a measured answer agreeing is worth more than either alone, and the disagreement at one hop is the whole of what four rows kept getting wrong.

**THE CLOSURE FOLLOWS `import` AND `path-literal` AND REFUSES TO FOLLOW `enumeration`, AND THE REFUSAL IS PRINCIPLED RATHER THAN A PERFORMANCE CHOICE.** "A reads B and B reads C" is a fact about A and C. "A walks the directory C is in" is not: a walk makes every file under a directory a first-hop dependant of every other one, so a closure over enumerations returns the tree at the second step and means nothing. `config-glob` and `prose` are excluded in the same spirit, being about a MOVE and about a SENTENCE rather than about a run. **A case seeds two files under one walked directory and requires the closure to return NOTHING**, so this exclusion cannot be undone by accident.

**IT IS OPT-IN AND NEVER DEFAULT.** A caller who did not ask for depth must not be handed a list whose entries mean something weaker than the ones they asked for.

### 8. What the module found about itself, recorded rather than quietly fixed

**THE FIRST VERSION OF THIS SUITE MADE THE MODULE REPORT 59 PATH-LITERAL SITES AGAINST A FILE THAT HAS 9.** Its fixtures seeded trees at `apps/api/src/events.ts` because that is the file the row is about, and the module then read those fixture literals as sites. **It was not wrong.** A `path-literal` site is a repo-relative path inside a string literal, and those were repo-relative paths inside string literals.

**AND THE REGISTER'S OWN PROSE DID IT TOO.** `KINDS` explains each kind in a string a `--kinds` run prints, three of those strings spelled the live path, and the module therefore reported ITSELF as a dependant of the file it was written about.

| what was changed | why not the other way |
|---|---|
| every fixture path moved to a namespace no tracked file uses, `apps/lantern/**` and `packages/alpha*` among them | narrowing the kind to "a literal a runner then OPENS" would need to decide which reads are reads, and a kind that decides is a kind that can decide wrong silently |
| the register's prose names the files by description instead of by path | same |

**THE LIMIT IS REAL AND IS NOT REPAIRED: `path-literal` CANNOT TELL A LITERAL THAT READS A FILE FROM A LITERAL THAT MERELY NAMES ONE.** It is recorded in `KINDS`, in a comment in the suite, and here. **Any fixture in this tree that spells a live path makes its file a derived dependant of that path**, which is a fact worth knowing before somebody writes the next fixture, and it is a second shape of the synthetic-tree tax ADR-419 section 8 found in leg 7.

**ONE CASE THIS ROW WROTE DID NOT BIND WHAT IT CLAIMED TO, AND THAT IS RECORDED TOO.** The cycle case asserted the closure reports each file at the hop it was FIRST reached; removing the guard that makes that true left the case GREEN, because the fixture's graph never revisited a file. It was caught by the RED watch in section 9 and by nothing else. The fixture now has a file reachable at hop 1 and again at hop 2, and removing the guard turns it red. **A case that cannot fail is a case that was never written**, and it survived a careful reading and died to a mechanical one.
