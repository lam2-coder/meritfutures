## ADR-164: the live cache is a Postgres table reachable only by a fifth role, and the grant that makes `INV-M2-14` structural is a REVOKE against `0026`'s own default  (2026-08-27, status: proposed)

**[`164`](ALLOCATION.md) was reserved REQUIRED and it claims migration [`0050`](../../packages/db/migrations/0050_live_cache_and_role.sql).** [P6 section 10 item 1](../plans/P6-live-tier.md) held `P6-c` for a founder answer; that answer is **delegated to this session** by the `164` row, which requires one of three readings **argued** rather than assumed. This entry argues the first and states what the other two cost.

**The sentence the entry starts from.** Four approved documents state a permission over an object with no medium, and [`0026`](../../packages/db/migrations/0026_roles_and_grants.sql) ends with `ALTER DEFAULT PRIVILEGES ... GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO merit_app`. **So the separation `INV-M2-14` needs gets FURTHER AWAY when a table is added rather than closer**, and reading 1 is not the cheap default it looks like. It is the right one anyway, and finding 1 below is that hazard executed rather than asserted.

- **Origin:** [P6](../plans/P6-live-tier.md) `P6-c`, branch `claude/p6c-live-cache`, session **278**. The number was RESERVED BEFORE DISPATCH and REQUIRED ([ALLOCATION](ALLOCATION.md)), so none was chosen here; the `164` row is amended **in place** per [ADR-065](ADR-065.md) T3.

- **MONEY PATH BY FILE. `E2` READ OWED.** It changes the grant model, and the grant model is what [SECURITY](../architecture/SECURITY.md) `C-26` calls *"structurally impossible rather than defended"*.

### 2. The ruling

> **1. THE LIVE CACHE IS A POSTGRES TABLE, `live_account_state`, AND READING 1 IS TAKEN ON `GS-132` RATHER THAN ON CONVENIENCE.** One row per account, upserted, discardable by design, keyed on `account_id`. The deciding argument is finding 10: `GS-132` is the phase's stated done-condition and it requires the cache to be **populated from outside**, so a medium that cannot be reached from outside the process that writes it has failed the phase before the phase starts.
>
> **2. A FIFTH ROLE, `merit_live`, AND IT IS `0034`'s SHAPE AND NOT `0026`'s.** `NOLOGIN`, enumerated grants, and **no `ALTER DEFAULT PRIVILEGES` anywhere**, so a table a later migration creates is invisible to the live tier until somebody grants it deliberately. It holds `SELECT, INSERT, UPDATE` on the cache, `SELECT` on `platform_account_refs`, and nothing else in the database.
>
> **3. THE REVOKE IS `ALL` AND NOT `UPDATE, DELETE`, AND THAT IS THE ONE PLACE THIS FILE DEPARTS FROM ITS THREE PRECEDENTS.** Finding 7 is that `0032`, `0039` and `0049` each take two verbs because each is implementing append-only. Finding 8 is that the sentence here is about **reading**. `REVOKE ALL ON live_account_state FROM merit_app, PUBLIC` is `FM-M12-08` and `DEP-M12-08` written as the permission they say they are.
>
> **4. ANY PROCESS THAT READS OR WRITES THE LIVE CACHE CONNECTS AS `merit_live`, AND NO PROCESS HOLDS BOTH `merit_app` AND `merit_live`.** Finding 9 is why this is a ruling and not a note: one process is one role, so while the API and the worker share `merit_app` **no grant in PostgreSQL can separate "the API may read the cache" from "the stats worker may not"**. **WHICH process holds `merit_live` is NOT ruled here.** The address is `P6-b`'s and the mechanism is `P6-g`'s, on [ADR-124](ADR-124.md)'s ground that a document may name what a mechanism needs and refuse to write it.
>
> **5. THE STORE IS NOT APPEND-ONLY, AND THE DEPARTURE IS RULED RATHER THAN INHERITED.** Every append-only table in this schema is append-only because its history **is** the product. [ADR-020](ADR-020.md) says the opposite of this one: *"Tier 2 is a view"*, and feed loss degrades to the last closed session rather than to an older tick. **So there is no expiry sweep**, `merit_live` gets no `DELETE`, and [P6 section 3.5](../plans/P6-live-tier.md)'s open question about needing `P5-a`'s range term resolves to **NO**.
>
> **6. THE MONEY ARITHMETIC IS THE DATABASE'S.** `intraday_movement_cents` is `GENERATED ALWAYS AS (equity_cents - opening_equity_cents) STORED`, in integer cents, on finding 16's ground. **The opening equity is the day's FIRST TICK and never an authoritative baseline**, which is what keeps clause 2's grant list at one table: an ingest that had to read `daily_marks` for a baseline would need the grant `INV-M2-14` forbids by name.
>
> **7. THREE COLUMNS ARE REFUSED AND EACH REFUSAL IS RECORDED, BECAUSE A MERGED MIGRATION CANNOT BE CORRECTED.** `kind` is simulator vocabulary and `V-M2-16` is open (finding 17). `at_utc` is the feed's own clock, read by nothing in the landed contract, and storing it beside `as_of_instant` invites staleness to be computed from the wrong one, which [ADR-152](ADR-152.md) clause 1 forbids. `projected_floor_distance_cents` needs a rule threshold the engine owns and a grant on `rule_states` that clause 2 does not give.

### 3. What this entry FORECLOSES

| | Foreclosed | Why it is written down rather than left to judgement |
|---|---|---|
| **F1** | **Granting `merit_app` ANY privilege on `live_account_state`, `SELECT` included** | **This is the one that will be reached for**, by the session that finds the live read path blocked and wants the smallest diff. It makes `FM-M12-08` and `DEP-M12-08` false **silently**: nothing fails, the read works, and the stats worker acquires a read grant on the indicative tier on the most public surface Merit operates. Clause 3 exists to be quoted at it |
| **F2** | **`ALTER DEFAULT PRIVILEGES ... TO merit_live` in any later migration** | It would give the live tier the default that made this file necessary, in the one direction `INV-M2-14` cannot survive. `0034` states the same refusal for `merit_dispatcher` and this is the second use of it |
| **F3** | **Reconciling a tick into anything the engine reads, in any slice** | [ADR-020](ADR-020.md)'s hard rule, `INV-M2-14`, `C-26`. `0050`'s closing `REVOKE ALL ON fills, raw_ingest_rows, daily_marks, rule_states FROM merit_live` is the belt; it changes no catalogue row against the file as written and binds the likeliest mistake, which is a fifth table appended to a grant list somebody was already editing. **It cannot bind the future and nothing in PostgreSQL can**, which is `0034`'s own honest caveat repeated |
| **F4** | **A second `DATABASE_URL` reader written into [`client.ts`](../../packages/db/src/client.ts) by this slice** | Clause 4 names the consequence and does not implement it. That file is outside this fence and its own header says why a second reader is a decision: *"a second reader is a second place a deployment can be configured"*. **Named as OWED to `P6-b` and `P6-g`, not taken** |
| **F5** | **Treating `live_account_state` as append-only in a later migration** | Clause 5 rules the opposite deliberately. A `REVOKE UPDATE` here would break the upsert that is the table's only write pattern, and the reflex that would produce it is the six-precedent pattern in findings 7, which is right for every other table this schema has added since `0026` and wrong for this one |
| **F6** | **A monotonicity trigger on this table** | The guard belongs in the ingest's `ON CONFLICT ... DO UPDATE ... WHERE excluded.sequence > live_account_state.sequence` predicate, which is `P6-f`'s. An out-of-order tick that rewound the row is a display defect on a **labeled indicative** number and never a money defect, because clause F3 keeps the figure off every money decision. **Owed, and named so `P6-f` does not have to re-derive it** |

### 4. Alternatives considered, which are `P6` section 10 item 1's other two readings

| Reading | Cost, stated rather than waved at |
|---|---|
| **A process-local store in the socket server** | **`GS-132`'s poisoning step becomes untestable from outside the process** (finding 10), and `GS-132` is the phase's stated done-condition. **It is also at least two caches rather than one** (finding 12): `api` and `api-admin` are two services, so the trader's dashboard and the operator's live Open Liability would read the same feed through two stores that diverge, and every additional instance of either service is another. And **`P6-f`'s already-written fence puts the ingest in `apps/worker`**, a third process, so the fence would have to move before the slice could be built. **Refused** |
| **A second stateful service** | **The honest part first: [OVERVIEW section 3](../architecture/OVERVIEW.md)'s sentence does NOT decide this and this entry does not pretend it does.** Finding 11's two limbs both fail to transfer. A cache whose entire content is **discardable by design** needs no backup and no restore, so the first limb reaches only the words *"reason about"*; and `INV-M2-14` makes the ingest write **nothing but the cache**, so there is no second write for a transaction to be atomic with and the PITR limb does not reach at all. **What refuses it is a different argument.** Redis would make the separation **a convention again**: the engine's inability to read the cache would rest on the worker not importing a client, and `INV-M2-14`, `C-26`, `FM-M12-08` and `FM-M13-07` every one say **permission**. A grant a `0026`-shaped probe can read is the thing four approved documents are describing, and an absent import is not one. **Refused, on a ground the queue's entry does not supply** |
| **Reading 1 without a fifth role, revoking only `UPDATE, DELETE`** | The cheap version, and it is the shape six migrations already have (finding 7). It leaves `merit_app` holding `SELECT`, which is precisely what `FM-M12-08` forbids, and it would let the whole grant model read as done while the sentence it exists to implement stayed unimplemented. **Refused, and F1 is that refusal made quotable** |
| **Reading 1 with `merit_live` also granted `DELETE`** | An expiry sweep is the only caller and clause 5 removes the need for one. A live tier that can delete rows can also remove the evidence that it was ever wrong, and `0050`'s belt takes `DELETE` back after the grant list on `0034`'s executed precedent. **Refused** |

### 5. What a founder read adds and this entry cannot

**Every fact in section 1 is a file's own words or a transcript.** Findings 1, 2 and 3 are executions against PostgreSQL 16.13 and their output is in the pull request and in [DELTA_MANIFEST](../../packages/db/DELTA_MANIFEST.md).

**Clause 4 is the judgement.** It states a requirement whose cost lands on two other slices, and the cost is not small: while `merit_app` is held by both the API and the worker, the live read path cannot be either of them as they are configured today. **The alternative is to accept that `FM-M12-08` is a convention** and grant `merit_app` `SELECT`, which is F1. This entry takes the side that a sentence four approved documents write as a permission should be one, and **a founder who reads it the other way should reject clause 3 rather than amend it**, because clause 3 and clause 4 are the same decision seen from two ends.

**Clause 7's three refusals are the second judgement.** Each keeps a column out of a file that can never be edited, and each is cheap to add later in a new migration and impossible to remove. **The direction of that asymmetry is why they are refusals rather than inclusions**, and finding 17 is the specific reason for the first.

### 6. The fence, and the two cells it should not have and the one it lacks

**`P6-c`'s fence names [`schema.ts`](../../packages/db/src/schema.ts) and [`scope.ts`](../../packages/db/src/scope.ts) and does not name [`scoped-db.test.ts`](../../packages/db/test/scoped-db.test.ts). Both halves of that are wrong and both were executed rather than argued** (finding 18).

**The two it should not have.** `live_account_state` is **not registered**, on [ADR-092](ADR-092.md)'s rule as that test's own adjacent comment quotes it: *"the first session that NEEDS a table registers it"*. `P6-c` writes the store, the role and the grant and **no reader**; the ingest is `P6-f`'s and the two live surfaces are `P6-g`'s and `P6-j`'s. [`0049`](../../packages/db/migrations/0049_reserve_coverage_snapshots.sql)'s `reserve_coverage_snapshots` is the same call, made one paragraph earlier in the same test, one day earlier. **Registering it would also have required a third hand-maintained line inside the unfenced test file**, because `SQL_NAME` is total by `Record<TableKey, string>` and is deliberately not derived.

**The one it lacks.** `scoped-db.test.ts` asserts `expect(createdTables).toBe(112)` over `^CREATE TABLE` in the **whole migration set**. **Any migration that creates a table fails it, registered or not**, and this one was watched failing at 113 against 112. **A fence that authorises a `CREATE TABLE` and withholds that file authorises a red tree.** The count is corrected and never relaxed, and the comment beside it records the eventual `derived` via `accounts` rule so the session that does need it does not re-derive it.
