### 4. Where leg E goes, and why the verdict is declarable

**IT KEYS ON BEING CALLED BY A BUILDER, WHICH IS THE WHOLE REASON IT REACHES ANYTHING.** Legs A and D key on the callee's own name, so a refusal under a non-verb name is invisible to both. Leg C keys on a `throw` in the builder's **own** body, so a refusal extracted into a helper is invisible to it. **Leg E is the remaining edge of that triangle**, and legs C and E do not overlap: C sees a throw written in the builder, E sees one written in what the builder calls.

**WHY DECLARE RATHER THAN CONVICT, STATED AS THE TRADE AND NOT AS A PREFERENCE.** Convicting ships a check that is red on landing over three functions nobody should rename. The route out of red would be to add a term to the predicate until those three fall outside it, and **that is [ADR-458](ADR-458.md)'s error class exactly**: a rule tuned against the tree it was measured on. Declaring keeps the predicate at item 1's three terms and moves the judgement into a table a reviewer reads, which is the instrument leg D already uses on empty matrix cells and which this file already argues for at length.

**WHAT IS GIVEN UP IS NAMED.** An author who adds an expression-shaped guard under a non-verb name **and** writes a `DECLARED_THROWER` entry claiming it is not a guard has evaded leg E. That is leg D's identical limit, stated at leg D's own site as _"IT DOES NOT ADJUDICATE AN ABSENCE"_, and this leg inherits it rather than escaping it. **What the leg converts is a silent arrival into a written claim somebody signed.**

**THE TABLE IS KEYED ON THE CALLEE'S NAME AND NOT ON `builder::callee`, WHICH IS THE ONE PLACE IT DIFFERS IN SHAPE FROM `DECLARED_ABSENCE` BESIDE IT.** Leg D's question varies per builder: does **this** builder need that guard. Leg E's does not: whether a function **is** a refusal rule is a fact about the function. Keying per builder would demand a duplicate entry the day a second builder calls it, and the reviewer would learn nothing from the duplicate.
