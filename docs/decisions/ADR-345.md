### 2. RULING ONE: what the sweep does when it finds a discrepancy

**THE CORPUS IS NOT SILENT AND IT ANSWERS IN ONE LINE.** [M02](../plans/M02-rithmic-bridge.md) `ST-M2-8`: *"Mismatch sets `recon_blocked`, alarms, excludes from eligibility."* [M01](../plans/M01-rules-engine.md)'s `FM-04` says the same from the engine's side, and `0014_marks.sql`'s own header says a mismatch *"sets accounts.recon_blocked = true and blocks eligibility until a HUMAN resolves it"*.

**SO THE ANSWER IS THREE THINGS AND CORRECTION IS NOT ONE OF THEM.**

| | What the corpus commits to | State after this row |
|---|---|---|
| **RECORD** | one `reconciliations` row per account-day, carrying both balances, the status and which of Merit's derivations was compared (`SD-M2-06`) | **BUILT.** `sweep.ts` writes it and this adapter carries it to the table |
| **BLOCK** | `accounts.recon_blocked = true`, which `R-40` reads as a payout-eligibility veto (`packages/rules-engine/src/payout/evaluate.ts:104`, `reconClear`) | **BUILT**, and set in ONE DIRECTION ONLY |
| **ALARM** | `recon.mismatch_detected`, [EVENTS](../architecture/EVENTS.md):188, `{account_id, trading_day, our_balance_cents, platform_balance_cents, delta_cents}`, consumers `ALERT, FEED, EVID` | **ABSENT.** Section 8 finding 1 |
| **CORRECT** | **NOTHING IN THE CORPUS ASKS FOR IT AND TWO PLACES FORBID IT** | not built, and must not be |

**THE REFUSAL TO CORRECT IS THE RULING AND IT IS NOT MINE.** [RB-02](../ops/runbooks/RB-02-recon-mismatch.md) is the mismatch runbook and every one of its four shapes ends at a person: request redelivery rather than repairing the file, because *"a repaired vendor file is a file Merit wrote"*; a backdated correction *supersedes* and replay recomputes forward; an unattributable balance delta is *"Quarantine. Never classify as realized P&L, never guess"*. And `0014`'s ruling 2 is **SUPERSESSION, NEVER UPDATE**, so a sweep that adjusted the mark it disagreed with would erase the disagreement it was run to find. `ports.ts` had already excluded `dailyMarks` from the write union on exactly that ground before this row existed.

**A RECONCILIATION JOB THAT SILENTLY CORRECTS IS A JOB THAT HIDES THE DEFECT IT EXISTS TO FIND.** The dispatch put that as the hazard and the corpus had already ruled it: `reconciliations.status = 'resolved'` requires `resolved_by` and `resolution_note` (`reconciliations_resolution_is_explained`), and neither is a value a sweep has. So the type has no path to `resolved` and the database would refuse one that did.

**THE ASYMMETRY IS THE CONTROL.** The sweep may SET the block and may never CLEAR it, so a `match` on a later day cannot lift a block an operator has not looked at. That is implemented by writing no `accounts` value at all on a match, and section 7's second transcript watches it hold against a real database.

**1. THE BLOCK HAS NO RELEASE, AND THIS IS THE ONE THAT WOULD DO REAL HARM.** `recon_blocked` is a payout-eligibility veto. Re-derived at the moment of writing: the only write of that column under any `src/` in this workspace is `sweep.ts:614`, it writes `true`, and **nothing writes `false` anywhere, in code or in a route**. A clock in front of this today is a control that can stop a trader being paid and no control that can start it again. **THE REMEDY IS NOT TO WEAKEN THE BLOCK**, which would be the control deleting itself; it is a row that writes the human's transition, and `reconciliations_resolution_is_explained` already says what that row has to collect.

**2. **3. **WHAT SCHEDULING WOULD COST ON TOP OF ALL THAT.** `CRON_INVENTORY`'s row carries the `NOT YET WIRED OR SCHEDULED` marker and `test/schedule.test.ts` case 4.2 asserts the markers against `UNSCHEDULED_CRON_ROWS` in BOTH directions, so moving the disposition means editing a frozen document, which is an ADR and not a commit. **THAT IS NOT WHY THE ANSWER IS NO.** The answer is no because of blockers 1 and 3; the marker is downstream of the answer.

### 4. What the adapter is, and the one thing it could have got wrong quietly

`apps/worker/src/recon/adapter.ts` implements `ReconSweepIo` over `WorkerDb`. `batch/adapter.ts` is the idiom and every structural choice is transcribed from it: the transaction type is DERIVED from the door (`Parameters<Parameters<WorkerDb['batch']>[0]>[0]`) so no second file names `@merit/db`, the door is an ARGUMENT so a suite substitutes a recorder, and the clock is an ARGUMENT and not a call (`job.ts`'s rule).

**THE FILTER IS TRANSLATED AND NEVER FORWARDED, AND THAT IS THE WHOLE OF WHY THIS FILE IS LONGER THAN A DELEGATION.** `ReconFilter` is `Readonly<Record<string, unknown>>`; `RowFilter<K>` is `Readonly<Partial<Record<AddressableColumn<K>, unknown>>>`. The first is not assignable to the second, which is the accessor's design rather than a friction: a column name is checked by `tsc` at the call site or it is checked nowhere. So every filter this adapter passes on is built from column literals, one shape per table, and a filter naming anything else is a **THROW**.

**DROPPING AN UNRECOGNISED COLUMN IS THE DEFECT THIS FILE MOST EASILY COULD HAVE HAD.** A read silently reduced from `{tradingDay, supersededBy}` to `{tradingDay}` on `daily_marks` is syntactically perfect and returns **every superseded correction ever written for the day**. The sweep would then compare Merit's state against a mark the estate has already replaced and report a mismatch for every account that was ever corrected, which is `FM-M2-08` manufactured rather than found. A MISSING narrowing is refused for the same reason as an extra one, and the suite watches both, asserting that the refused call never reached the door.

**ONE WRITE THE PORT TYPE ALLOWS IS REFUSED HERE.** `RECON_WRITE_TABLES` contains `accounts` because the BLOCK is a mismatch's consequence, and `insert` is declared over that same union. **A RECONCILIATION SWEEP MUST NEVER CREATE AN ACCOUNT.** The type cannot say so without splitting the union and `ports.ts` is not this row's file, so the refusal is in the adapter and is walked by a case.

**`ADR-102`'s `WHERE`-LESS WRITE PATH IS NOT THIS PORT'S BLOCKER, AND THE DIFFERENCE IS THE METHOD NAME.** `provisioning/ports.ts` measures `SystemTx.update(key, values)` rendering an `UPDATE` with no `WHERE` and `SystemTx.rows(key)` selecting the whole table, and declares two ports blocked on it. `ReconTx` names neither: its three methods are `rowsWhere`, `insert` and `updateAt`, the accessor composes a predicate for the first and the third, and `addressPredicate` additionally refuses a filter term and an empty address. Every read this sweep makes is narrowed and every write names one row.

**MONEY IS INTEGER CENTS AND THE ADAPTER PERFORMS NO ARITHMETIC AT ALL.** Every `*_cents` column involved is `bigint` with `{ mode: 'bigint' }` pinned in the Drizzle declaration; the values cross this boundary untouched; `sweep.ts`'s `requireCents` refuses a `number` at the row boundary. There is no `Number(`, no arithmetic operator on a balance and no float in the adapter or its suite. The one place a lossy conversion could have entered is the `reconciliations` update address, and the adapter refuses an `id` that is not a `bigint` there.

**[ADR-344](ADR-344.md) LANDED THE SAME CAPABILITY ON `main` FIRST, WROTE THE SAME ARGUMENT AT MORE LENGTH, AND CHOSE A SHAPE THIS ROW HAD REASONED AROUND RATHER THAN AGAINST.** `src/db.ts` now carries `export { atMost, isNull }`, re-exported and **NOT WRAPPED**, and states the reason this row's wrapper would eventually have collided with: `packages/db` recognises a term by IDENTITY and not by shape, so a function here that rebuilt the returned object, spread it or froze a copy of it would hand back something the accessor refuses, and the refusal would arrive at the first live scan rather than at the line that caused it. **`columnIsNull()` DELEGATED AND SO DID NOT ACTUALLY BREAK THAT**, but it was one more spelling of one capability on the file [ADR-165](ADR-165.md) exists to keep small, and two spellings is the drift.

**SO THE MERGE TOOK `main`'s FILE WHOLE AND THIS ROW'S EXPORT IS GONE.** `apps/worker/src/db.ts` is byte-identical to `origin/main` in this branch, `git diff origin/main -- apps/worker/src/db.ts` is **EMPTY**, and the adapter imports `isNull` through it. **THE ONE THING THIS ROW STILL OWNS IS THE NARROWING**, and it is a guard rather than a wrapper for exactly the reason above: `isNull()` returns the whole `FilterTerm` union and `ReconFilterTerm` is one member, so `reconIsNull` reads the discriminant, THROWS on anything else, lets `tsc` narrow on the same line, and hands back **the object `packages/db` minted, untouched**. **WHY THE CAPABILITY IS NEEDED AT ALL IS UNCHANGED AND IT IS THE DEFINITION OF "LIVE".** `daily_marks_live_per_account_day_uq` is `(account_id, trading_day) WHERE superseded_by IS NULL`, so the live mark IS that predicate. A sweep without the term reads every mark and re-derives the index's own rule by hand, over rows it pulled across the boundary to do it. [ADR-157](ADR-157.md) admits `IS NULL` **on the read path by name**.

**`LIVE_DB` GAINED NO METHOD FROM EITHER ROW**, so `test/db.test.ts`'s `Object.keys(LIVE_DB)` assertion is untouched by both.
