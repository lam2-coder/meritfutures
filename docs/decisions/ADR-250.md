### 2. Where the module lives, which the row required to be declared

**`packages/rules-engine/src/gates-codec.ts`, and the reason is a dependency direction rather than a preference.**

The row's fence admits `packages/rules-engine/src/**` **only if the codec belongs beside the type it encodes**, and it does. ### 3. Why a decoder was owed as well as an encoder, and why the assertion is a round trip

**AN ENCODER WATCHED ALONE IS GREEN ON A BAG NO DECODER CAN REBUILD.** That is not a hypothetical: it is the exact failure [ADR-206](ADR-206.md) section 5 measured. Postgres holds `9007199254740993` exactly, because `jsonb` numbers are `numeric`; the same value read back through `JSON.parse` as a NUMBER returns `9007199254740992`. **Postgres is not the lossy leg and the read port is.**

So every case in this slice that matters goes out through `JSON.stringify` and back through `JSON.parse` before it is compared. **An object copy would have carried the `bigint` this codec exists to keep out of the column**, and a suite that skipped the JSON leg would have been green on the one encoding the ruling refuses.

**THE CENTS LEAVES COME BACK AS THE SAME BASE-10 STRINGS THEY WENT IN AS**, which is what the row required, and they come back as `bigint` in the type. Seven leaves take that form and there is no eighth: `winDays.floorCents`, `buffer.haveCents`, `buffer.needCents`, `consistency.profitNeededToDiluteCents`, `minimumAmount.withdrawableCents`, `minimumAmount.capCents` and `minimumAmount.minPayoutCents`.

**NO FLOAT EXISTS ANYWHERE ON THIS PATH.** `Cents` is `bigint` in the type and a base-10 string on the wire, and the two renderings are bound to each other rather than described twice: the suite renders every cents leaf through the codec and through `ENGINE_GATE_LEAVES`' own closure and asserts the strings are identical, character for character. **If either rendering ever moves, that case is what fires.**

### 4. The shape of the two directions, and why they are not symmetrical

**THE ENCODER IS TOTAL AND REFUSES NOTHING.** [ADR-206](ADR-206.md) is explicit that the encoding has to be total over `Cents`, because "a write path that refused a legal state would leave the day with no row at all", which is `DO-3` and a raised reconciliation against a figure the engine computed correctly. So the encoder validates nothing: it renders.

**EVERY REFUSAL IN THE MODULE IS ON THE DECODE SIDE**, and the asymmetry is the point. What arrives at the decoder is `unknown`: whatever `jsonb` gave the driver, from a row written by a build that is not this one, by a backfill, or by hand in `psql`. A decoder that trusted it would hand `evaluatePayout` an `EngineGateResults` with a `NaN` in it and the payout verdict would be computed off that.

**THE CENTS CHECK IS A ROUND TRIP AGAINST THE RENDERING RATHER THAN A REGULAR EXPRESSION**, and this is the one place the implementation is cleverer than the ruling required. `BigInt(text).toString(10) === text` admits exactly the strings the encoder can emit and nothing else. A pattern would have been a second statement of `money()` with nothing comparing them, which is `FM-16` at the leaf. In one line it disposes of every near miss a hand-written row produces, each of which is a case in the suite: the empty string (`BigInt` reads it as zero), a padded string (whitespace is tolerated and lost), a leading zero, an explicit plus sign, negative zero, hexadecimal, and exponential notation.

**KEY ORDER IS READ BY NOTHING.** `ADR-206` ruling 6, and `jsonb` sorts keys by length and then bytewise, so what Postgres returns is not what was written. The decoder reads every leaf by name and the suite proves it by re-sorting a bag into `jsonb`'s own order and decoding it again.

**`ENGINE_GATE_LEAVES` IS NOT IMPORTED BY THE MODULE, AND THAT IS DELIBERATE.** Building the bag by walking the array would mean SPLITTING each dotted path and indexing back into the value, which is `M01` section 1.4's banned key iteration wearing a different hat and which no type checker sees through. The leaves are written out once per direction and the comparison against the array is performed by the SUITE, which is [ADR-206](ADR-206.md) section 8's own recommendation: "the suite-side check over the executable list". **The two copies are COMPARED rather than merged**, so a bag that grew a leaf goes red in a named case instead of hashing differently in production.

### 10. Where this entry is most likely wrong

**THE ROUND TRIP IS THROUGH `JSON.parse` AND NOT THROUGH POSTGRES, AND THAT IS THE LOAD-BEARING GAP.** [ADR-206](ADR-206.md) section 6 wrote its specimen into a real row through the whole foreign-key chain and read it back; this session did not, because no database is reachable from it and inventing one would have been a worse claim than a stated absence. **What is executed here is the leg the ruling identified as lossy** (`jsonb` to driver to `JSON.parse` to `bigint`) and the ADR's own specimen is decoded and re-encoded byte for byte as a check against that entry's bytes. **What is NOT executed is the store's own behaviour**: that `jsonb` accepts this bag, that the fourteen `CHECK` constraints admit the row it sits in, and that the key order Postgres returns is the one section 4's case simulates. All three are `ADR-206` section 6's measurements, taken on a real row, and this entry relies on them rather than repeating them.

**THE DECODER IS STRICTER THAN ANY DOCUMENT REQUIRES AND THAT IS A JUDGEMENT.** Nothing in `ADR-206` or `rule_states.md` says a decoder must refuse a leading zero, a padded string or a non-integer count. The argument for the strictness is that the alternative is a silently wrong `bigint` on a money path and that `hash.ts` applies the same safe-integer test to the same leaves; **the argument against it is that a decoder which refuses is a decoder that can leave a readable row unreadable**, and the failure mode of that is a payout endpoint answering 503 on a row that is merely untidy. **If a founder wants the read to be permissive where the write is total, section 4 is the sentence to move.**

**AND THE STORED TYPES ARE A SHAPE THIS SESSION CHOSE.** `RuleStateWriterIo.encodeEngineGates` returns `unknown` precisely because that interface declined to choose the outer shape, and `StoredEngineGates` is this entry choosing it. It follows from ruling 1 and nothing else was reasonably available, but it is a declaration a later reader will treat as settled, and it deserves a line in the `E2` read for that reason rather than for its content.
