## ADR-190: an operator route answers eight things and none of them is 503, the uncomposed source keeps its 500, and a console renders no status it did not receive (2026-08-28, status: proposed)

**Three documents and one shipped route say every operator route answers 503 today. Measured over a real `compose()` and Fastify's own `inject`, across all 28 registered operator routes one at a time: 10 of the 23 `/admin/*` routes answer 401 `unauthenticated` to an anonymous caller and 500 `internal_error` to one carrying a cookie, and 13 answer 503 `service_unavailable` before authenticating at all.** So the sentence is not simply false: it is true of the majority of the operator surface and false of the ten routes the console reads, which is why it survived two sessions reporting it. This entry rules what a route answers in each state, rules that the uncomposed source **keeps its 500** on a ground the dispatch did not carry, and rules that a console screen renders **no error kind it did not receive**. **No source file under `apps/api/src` is edited, and that is measured rather than deferred: `admin-reads.ts` cannot move its own status.**

- **Origin:** [ALLOCATION](ALLOCATION.md) row `190`, session **350**, dispatched as `claude/the-503-that-is-not`. **The reservation's substance holds and two of its premises do not**, which is section 1. The row is amended in place under [ADR-065](ADR-065.md) T3 rather than answered with a second row.

- **NOT THE MONEY PATH.** No migration number is taken and none is needed, no transaction is opened, no ledger account is named, no `SystemReason` or `SqlExecutorReason` member is added, no `pg` is imported and no cast past a key type is written. What moves is one console route, two suites and one plan subsection.

- **THE ENTRY SHIPS `proposed` WITH AN UNSIGNED APPROVAL LINE.** What is **derived** is the eight-state table, the partition of the operator surface, and the two measurements in section 4 that close the 500-versus-503 question. What is **judged** is clause 2's discriminator, which decides that one class keeping one status is worth more than a monitor being able to page on an uncomposed port; and clause 4, which registers a split across four modules that this fence cannot repair. Section 12 is that question.

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every claim below was read at its own file before it was relied on, and the three that came back different are findings 4, 5 and 6.

### 2. THE RULING

**Clause 1. What an operator route answers is EIGHT states, not two, and the table is the ruling.** Section 3 enumerates them and [`admin-reads.test.ts`](../../apps/api/test/admin-reads.test.ts) section 9 asserts every row over a real `compose()`.

**Clause 2. AN UNCOMPOSED SOURCE ANSWERS 500 AND `admin-reads.ts` DOES NOT MOVE.** Not because 503 would need a new code -- it would not, finding 5 -- but because the status is a property of the CLASS and the class carries thirteen refusals that are not about composition (finding 9). Section 4 measures what moving it costs.

**Clause 3. THE THREE 500 STATES ARE ONE DOCUMENT ON THE WIRE, DELIBERATELY.** A response that distinguished *"this deployment composed no session source"* from *"it composed no read source"* from *"a handler threw"* would tell an unauthenticated caller which of this deployment's ports are uncomposed. The discrimination a monitor needs is in [`server.ts:154`](../../apps/api/src/server.ts)'s log line, where the thrown error names the source in its own message.

**Clause 4. THE SPLIT ACROSS THE OPERATOR SURFACE IS REGISTERED, NOT RESOLVED.** Ten routes authenticate first and thirteen answer 503 first. **On this ruling's ground the ten are right and the thirteen are answering the wrong question**, and the repair is four modules and a `server.ts` line in no fence this wave. Section 7 item 1.

**Clause 5. A CONSOLE SCREEN RENDERS NO ERROR KIND IT DID NOT RECEIVE.** An `AdminErrorKind` is derived from a response: [`client.ts:228`](../../apps/admin/src/http/client.ts) computes it from `response.status` and [`:244`](../../apps/admin/src/http/client.ts)'s `AdminApiFailure` carries that status beside it. **A route that performs no read has received nothing and names nothing.** Section 6.

### 4. Clause 2, and the two measurements that closed it

**The naive reading is that `admin-reads.ts` is wrong and should join the thirteen.** Finding 8 is a strong argument for it: four sibling admin modules answer 503 for an unwired backend, [`kyc.ts:337`](../../apps/api/src/routes/kyc.ts) argues for it explicitly, and section 2 of the contract declares the code. **Both measurements below refuse it, and neither is a preference.**

**MEASUREMENT ONE. THE MODULE CANNOT MOVE ITS OWN STATUS.** `AdminReadError` was given `readonly statusCode = 503` and the suite re-run: **44 of 44 passed, and every answer was still 500 `internal_error`**. [`server.ts:150`](../../apps/api/src/server.ts) reads `STATUS_CODE[status]`, [`:67`](../../apps/api/src/server.ts)'s table has no 503 key, and [`:154`](../../apps/api/src/server.ts) logs *"unmapped error status, answering internal_error"* and sends 500. **So the fence's conditional -- edit `admin-reads.ts` only if the ruling moves the code -- describes an edit that does not exist.** The ruling either changes `server.ts`, which is in no fence this wave, or it does not change the code.

**MEASUREMENT TWO, AND IT IS THE ONE THAT DECIDES RATHER THAN BLOCKS.** With `STATUS_CODE` and `TITLE` both given their `service_unavailable` entry as well, so that the 503 really reached the wire, **12 cases failed across 2 files**. Four of them are the ones that matter:

| Failing case | What it says |
|---|---|
| *"a liability body carrying a float in cents is refused rather than served"* | a **float in a money field** would answer *try again shortly* |
| *"the flag queue is refused when it inverts triage"* | an **inverted triage order** would answer *try again shortly* |
| *"a pack whose digest is not a SHA-256 is refused, because it authenticates nothing"* | an **unauthenticatable evidence pack** would answer *try again shortly* |
| `admin-breaker`'s *"a float in a `_bp` field is refused"* | and the same for the breaker's own surface |

**That is finding 9 executed rather than asserted.** `AdminReadError` is the class the module throws when the data a wired source returned may not be shown to an operator, and 503 is a lie about every one of those: the source is composed, it is working, and it produced something wrong. **Retrying reproduces it.** [ADR-110](ADR-110.md) ruling 7's sentence is the right one for this class -- *"it does not answer 503, which invites a retry against a process that will never succeed"* -- and it is right for a reason that entry did not have: the class is not only about wiring.

**The honest cost of ruling this way, stated rather than hidden.** An operator who reaches a 500 is told nothing about whether a human must ship code or an environment must be configured, and a monitor cannot page separately on the two. **Clause 3 accepts that cost on the wire and locates the discrimination in the log**, and `AdminReadError`'s messages already carry it: *"no admin session source is wired"* at [`:212`](../../apps/api/src/routes/admin-reads.ts) and *"no admin read source is wired"* at [`:746`](../../apps/api/src/routes/admin-reads.ts), each reaching [`server.ts:154`](../../apps/api/src/server.ts) inside `err`.

**What would make a 503 right here is a SECOND CLASS, not a second status.** A refusal that means *"this deployment composed nothing"* is a different fact from *"this source returned something unservable"*, and once they are two classes each can carry its own answer. **That is a change to `admin-reads.ts` and `server.ts` together and it is registered as item 2 rather than taken**, because a class split is exactly the shape that must not land on an unsigned ruling.

### 6. Clause 5, and why it is a rule about PROVENANCE rather than about a number

**Correcting `toAdminErrorKind(503)` to `toAdminErrorKind(401)` would have been the wrong repair**, and it is worth saying plainly because it is the repair the reservation reads like. The home route performs no read. **A page that names 401 because a suite measured 401 is still a page asserting a status it did not receive**, and the next status change moves it back out of step in a file nobody is looking at.

So the rule is: **an error kind is a value derived from a response this console received.** [`client.ts:228`](../../apps/admin/src/http/client.ts) is the only place a kind is computed and it takes a `number` that came from `response.status`; [`:244`](../../apps/admin/src/http/client.ts)'s `AdminApiFailure` carries the kind and that status together, so a kind in the console's own types can always be traced to a response. **A constant cannot.**

**What [`page.tsx`](../../apps/admin/src/app/page.tsx) does now.** `NOT_YET`, the `AdminErrorKind` import and the `data-error` attribute are gone; the union at [`:90`](../../apps/admin/src/app/page.tsx) is `supplied | unsupplied` with no `error` member, which is the shape [`flags/page.tsx`](../../apps/admin/src/app/flags/page.tsx) already had; and the two measured answers are in the `ADR-171` entry's `blockedBy` prose at [`:104`](../../apps/admin/src/app/page.tsx), where an operator reads them, together with finding 10.

**AND IT IS A CONTROL RATHER THAN THREE SESSIONS' GOOD JUDGEMENT.** `M6-A-60` in [`render.test.ts`](../../apps/admin/test/render.test.ts) sweeps every file under `src/app/` for `AdminErrorKind`, `toAdminErrorKind` and `data-error` with comments stripped, so a screen may still EXPLAIN the statuses its endpoint answers and may not name one in code. It carries a counterfactual over [`client.ts`](../../apps/admin/src/http/client.ts) itself, because a sweep for a name that exists nowhere is a sweep that can never fail. `M6-A-61` reads the served bytes of the home route.

**`unavailable` STAYS IN THE VOCABULARY AND ITS PRODUCERS ARE NAMED.** Session 344 argued the member should stay because the console must tell *"not built yet"* from *"broke just now"*. Section 5 makes that argument stronger than it was: **13 registered `/admin/*` routes send a 503 today**, so the member has producers on the same surface rather than a hypothetical future one.

### 10. Alternatives considered

- **Correct the console to `toAdminErrorKind(401)`.** Refused, section 6. It is the same defect with a right number in it, and it goes stale the next time the answer moves.
- **Move `admin-reads.ts` to 503, joining the thirteen.** Refused on measurement two: it would answer *try again shortly* to a float in a cents field. The argument for it is real and it is registered as item 1 for the write modules, where the class carries only the wiring fact.
- **Mint a code for the uncomposed case.** Refused, and the reason is not the one the reservation gives: **no minting is required**, `service_unavailable` already exists in section 2 and on 13 routes. What is required is a class split, which is item 2.
- **Put the discrimination in the response's `detail`.** Refused. [API_CONTRACT section 2](../architecture/API_CONTRACT.md) says `detail` *"never leaks internals"*, and *which ports this deployment did not compose* is the internals of a deployment, offered to a caller who has not authenticated.
- **Delete `unavailable` from `AdminErrorKind`.** Refused, section 6. Thirteen routes on this surface produce it.
- **Repair section 4.1 and `client.ts` too, since they carry the same false sentence.** Refused: outside the fence. *"Never weaken a gate to pass it and never widen a fence to finish. They are the same move."* Item 5 names all five with line numbers instead.

### 11. Consequences

- **The console stops asserting a status.** One screen said `unavailable`; three said nothing and explained; all four now say nothing and explain, and a sweep holds the fifth to it before it is written.
- **The eight-state table is executable.** The number a document claims about an operator route can now be checked in one command, which is the thing that was missing while three documents agreed with each other and with nothing else.
- **The 500 is now a decision with a reason attached rather than a default.** It was already argued at [`admin-reads.ts:109`](../../apps/api/src/routes/admin-reads.ts) on a precedent; it is now argued on a measurement of what else that class refuses.
- **The operator surface is knowably inconsistent.** Nobody had measured the whole of it before. Ten routes and thirteen routes answer differently to the same anonymous request, and item 1 is the first time that is written down anywhere.
- **A latent defect in `server.ts` is named.** Seven of section 2's sixteen codes can be produced by a throw and **nine cannot**, `service_unavailable` among them, and the tree stays green only because nothing throws them. The day a route does, its status is silently rewritten to `internal_error` with the real one in the log.
- **No migration is touched, no `apps/api` source file is edited, and the vocabulary is closed where it was.**

### 12. Approval

**Approval line: UNSIGNED.**

**What a founder read adds and this entry cannot.**

**Clause 2 is the judgement, and its ground moved during the session.** The reservation argued the 500 was defensible because a 503 would need a new canonical code. **That is false** and the entry says so. The ground it now stands on is finding 9: the class carries thirteen refusals that are not about wiring, and measurement two shows what a 503 would say about each of them. **If a reader thinks the right answer is to split the class rather than to keep one status**, they are agreeing with section 4's own last paragraph, and the difference between that reader and this entry is only whether the split lands on an unsigned ruling.

**Clause 4 rules about thirteen routes in four modules this session cannot touch, and that is the widest thing here.** It says the write modules are answering the wrong question and then does nothing about it. A founder who reads item 1 and disagrees is disagreeing with the ruling, not with the fence, and the entry would rather be told that now than have four modules changed on it later.

**Finding 11 is a disclosure and it is registered rather than escalated.** An anonymous caller can enumerate thirteen operator write endpoints by the status they answer. It is bounded -- the operator API is a separate service on `ADMIN_ORIGIN` per [INFRA](../architecture/INFRA.md), and what is disclosed is the existence of paths already written in an approved contract -- but **it is exactly the disclosure `admin-writes.ts`'s own comment refuses one line before it happens**, and whether it waits for a fence is a call this entry should not make alone.
