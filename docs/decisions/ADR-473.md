### 3. The instrument: what it decides, and the one thing it refuses to

[`packages/tooling/checks/repairable-sites.mjs`](../../packages/tooling/checks/repairable-sites.mjs), with [its suite](../../packages/tooling/test/repairable-sites.test.ts).

```
node packages/tooling/checks/repairable-sites.mjs [--at <ref>] <path:line> ...
node packages/tooling/checks/repairable-sites.mjs [--at <ref>] --list <file>
```

**IT ANSWERS ONE QUESTION: MAY A REPAIR TOUCH THIS LINE AT ALL.** It does not say whether a pointer is dead, whether the sentence around it is true, or whether deleting a number would improve it. Those are [ADR-467](ADR-467.md) section 9's USE against MENTION question, which that entry rules undecidable over Merit prose, and they stay a human judgement. `ADR-471` section 3 named the axis; this is it built.

The test is one call to [`stripComments`](../../packages/tooling/checks/strip-comments.mjs), `ADR-279`'s one-state scanner, with the whole file around the line, comparing the surviving text at that line index against the raw line. That reader **preserves string literals** and **preserves newlines**, both stated in its own header, and both are exactly what this needs.

**SEVEN VERDICTS AND ONLY ONE PERMITS A REPAIR.**

| verdict | meaning | eligible? |
| --- | --- | --- |
| `COMMENT` | the line's whole content is comment | **YES** |
| `MIXED` | code with a comment after it | no, and it is handed back for adjudication rather than waved through: the pointer may be on either half and a list of `file:line` does not carry the text that would say which |
| `CODE` | the line survives whole. A seed, a `write` argument, an expected finding, an assertion | no. **This is the seven** |
| `BLANK` | the index carries nothing | no |
| `RANGE` | the index is past the end of the file | no |
| `ABSENT` | no such file at that reading | no |
| `OPAQUE` | not a file this reader models | **NEITHER. UNCLASSIFIED** |

**`OPAQUE` IS THE LOAD-BEARING VERDICT AND IT IS WHY THIS IS NOT AN ABSENCE CHECK WEARING A VERDICT'S CLOTHES.** `stripComments` models the JavaScript family and nothing else. A `file:line` into a `.md`, a `.sql` or a `.yml` is a site this instrument HAS NO OPINION ABOUT, and the one thing it must never do is report such a site as eligible because it found no comment in a file it cannot read. That is `ADR-274`'s warned class and the defect `strip-comments.mjs`'s own header describes: an absence check over an emptied file goes GREEN and nobody ever looks. Section 5 is the first list in this corpus to contain one, and it is this row's own.

**`--at <ref>` IS NOT A CONVENIENCE.** A published `file:line` is a claim about a file at the instant it was written. Read against a later worktree the instrument faithfully classifies whatever moved into place. Section 5 measures how often that matters and section 7 is one site where it decides the answer.

### 4. INSTRUMENT, not a gate, and `ADR-471`'s own ground is the weakest of the four

**THE VERDICT AGREES WITH `ADR-471` SECTION 9 ITEM 1 AND THE ARGUMENT DOES NOT.** That entry refuses the gate because *"its motivating case is `ADR-469` section 10 item 1, which is a dated record nobody may repair, so the gate would ship permanently red on a finding no commit is permitted to close"*, citing [ADR-450](ADR-450.md) section 6's **second** ground, that a gate whose findings may not be discharged is a gate somebody deletes. That argument is sound and it is third best. Three stronger ones are available here and two of them are measurements.

**FIRST, AND DECISIVE: THE GATE CANNOT SEE ITS OWN MOTIVATING CASE, WHICH IS `ADR-450` SECTION 6's FIRST GROUND AND NOT ITS SECOND.** A gate must harvest its own population out of the corpus. The corpus's dominant form for a repair list is a path written ONCE and then a run of bare `` `:NNN` `` tokens, and `ADR-469` section 10 item 1 is exactly that: thirteen sites, one path. A harvester keyed on `path:line`, which is what every citation derivation in this tree is, **sees that list as ONE site and not thirteen.** Measured over `docs/decisions/`: **3,114 path-keyed sites, and a further 1,357 bare `` `:NNN` `` tokens that only a path inherited from within `RI-15`'s six lines reaches**, which is 30 percent of the population invisible to the keyed form. On `ADR-469` alone it is **15 path-keyed against 37 inherited-bare**; on `ADR-471`, **11 against 53**. And the inheritance is not a fix, it is `ADR-467` section 9's cross-attribution class: binding a bare token to one of several paths named in the same sentence is the half that entry rules undecidable. **So the gate would report on its own motivating case at one site in thirteen, which is `ADR-429` section 10's ninth instance bought under time pressure, quoted by `ADR-450`: a check that passes while the property it names is false.**

**SECOND, AND IT IS STRUCTURAL RATHER THAN A JUDGEMENT: A GATE HAS NO REF TO READ AT.** A gate reads the working tree, by construction. Section 5 measures that **11.1 percent of the sites whose publishing entry names a resolvable base ref classify differently against the worktree than against that ref**, with 19 going `COMMENT` to `CODE` and 20 going `CODE` to `COMMENT`. **A gate would therefore be wrong on about one site in nine in both directions**, telling a row that a seed is repairable and that a repairable comment is a seed. **The row COMPILING a list has the ref in its hand and the gate never does.** This is not a defect a better gate fixes; it is the difference between the two positions.

**THIRD, THE SCALE, WHICH TURNS `ADR-471`'s QUALITATIVE ARGUMENT INTO A QUANTITATIVE ONE AND STRENGTHENS IT.** A gate asserting that published pointer lists name only comment lines would ship not with one undischargeable finding but with **1,678**, every one of them in a dated record. `ADR-450` section 6's second ground reported 402 vacant pointers as demanding repairs the corpus forbids; this is four times that.

**AND THE HONEST STATEMENT OF WHAT IS BEING GIVEN UP.** A founder may still prefer a gate with a known red, on `ADR-471`'s own approval-block reasoning that a red naming a dated record is exactly the pressure `ADR-467` section 12 item 3's stacked question needs. **This row's answer is that the gate would not name the dated records well enough to be that pressure**: at one site in thirteen on its motivating case, and wrong in both directions on one site in nine of what it did see, the red would be about the harvester and not about the corpus. **The pressure `ADR-467` section 12 item 3 needs is a founder's ruling, and a gate is not a way of asking for one.**

**WHAT WOULD CHANGE THE ANSWER, WRITTEN DOWN SO IT CAN BE CHECKED LATER.** If entries began publishing repair lists in a machine-readable block, one `path:line` per site with the base ref beside them, both the first and second grounds fall away at once and the gate becomes writable. **That is a convention change and not a check**, which is the same shape as `ADR-450` section 8's conclusion, and section 10 item 3 prices it.
