### 4. Whether an exact control is possible, which is the whole question this row was sent to answer

**THE DISPATCH DEFINES EXACT AND THE DEFINITION IS THE TEST.** A control is exact when it asserts a number derived from the tree at check time against a number the tree states, with no approximation of intent. *The suite reports N skipped and the register says N* is exact. *No test is skipped that should run* is an approximation and is forbidden.

**THE ANSWER IS YES, AND IT TURNS ON ONE FACT: THE NUMBER ALREADY EXISTS.** Vitest counts the skips itself, in the environment the job actually has, and `--reporter=json` writes the count to a file. So the check is a comparison of two integers and it approximates nothing. It is not a model of the run; it is the run's own arithmetic.

**AND IT COSTS NO EXTRA SUITE RUN, WHICH IS THE CONDITION THE DISPATCH ATTACHED TO THE REFUSAL.** `CI-02` and `CI-04` each already perform a `vitest run`. Adding `--reporter=json` to a command line that is already there produces the report as a by-product; the new step reads the file and exits. **The suite is not run inside the check, so the refusal branch does not open.**

**THE VERSION OF THIS FILE THAT WOULD HAVE BEEN WRONG IS THE OBVIOUS ONE, AND IT IS REFUSED IN THREE TERMS.** Reading the test sources and counting `test(` calls inside `describe.skipIf(` blocks is the shape a row under time pressure reaches for. [ADR-429](ADR-429.md) section 10 rules it out by name: a static check approximating a dynamic property *"would be a check that passes while the property it names is false"*, which is *"the failure this corpus has paid for more often than any other"*. **That argument was read, agreed with, and applied to this row rather than re-argued.** Three reasons it applies, in ascending order of how badly:

1. **THE COUNT IS NOT ALWAYS COMPUTABLE FROM THE TEXT.** A `test.each`, a loop, or a helper that generates cases defeats it, and a counter that guesses is the approximation.
2. **A SKIP NEED NOT COME FROM A `skipIf` AT ALL.** `describe.skip`, a runtime `ctx.skip()`, a stray `-t` filter and the marker `numTodoTests` counts each produce a green non-run, and a counter that enumerates the constructs it knows about passes silently over the one it does not.
3. **FATAL ON ITS OWN: THE COUNT IS A PROPERTY OF THE ENVIRONMENT AND NOT OF THE TREE.** [`pool-executor.test.ts:79`](../../packages/db/test/pool-executor.test.ts) is `describe.skipIf(HAS_DATABASE)` and [`:97`](../../packages/db/test/pool-executor.test.ts) is `describe.skipIf(!HAS_DATABASE)`. **They are complements.** Which one skips is decided by `DATABASE_URL` at run time, so a tree-only counter would have to MODEL the environment it expects to find. **A check that models the environment is a check that has encoded somebody's intent**, which is precisely what the ruling forbids, and it would be green on the day CI acquires a database and the model stops being true.

**THE SHAPE THE DISPATCH ASKED FOR IS THE SHAPE THIS TAKES: THE COUNT IS STATED IN ONE PLACE, AND CHANGING THE SUITE WITHOUT UPDATING THAT PLACE IS RED.** The one place is `REGISTER` in [`packages/tooling/checks/skipped-tests.mjs`](../../packages/tooling/checks/skipped-tests.mjs). **It has no opinion about whether a skip is legitimate**, which is what stops it being an intent check: a case that stops running and a case that starts running produce the same red, and the message for each says the same thing.

### 5. What was built, and the one line in the fence that needed justifying

**ONE CHECK MODULE, ONE TEST FILE, AND FOUR LINES OF WORKFLOW.**

- **[`packages/tooling/checks/skipped-tests.mjs`](../../packages/tooling/checks/skipped-tests.mjs)**. Holds `REGISTER`, three rows today. Exports `registerFindings` (the half that needs no report), `countsByFile`, `reportFindings` and a CLI.
- **[`packages/tooling/test/skipped-tests.test.ts`](../../packages/tooling/test/skipped-tests.test.ts)**. **Seventeen cases**, none of them skipped, watching the check pass on an agreeing report and go red on each of six disagreements.
- **[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)**, two jobs.

**THE REGISTER IS PER FILE AND NOT A SINGLE TOTAL, AND THE REASON IS A BLIND SPOT A TOTAL HAS.** One skip removed from file A and one added to file B leaves a total unchanged. A per-file table is red on that and a total is not, and the extra cost is that renaming a file that carries skips is also red, which is a change that ought to be recorded.

**A ROW IS `{ file, skipped, unwritten, why }` AND `why` IS ASSERTED OVER BY NOTHING.** It is a note for whoever reads a red build. **The `unwritten` field is Vitest's second not-run status, the one `numTodoTests` counts**, and it is spelled that way because [`packages/tooling/eslint.base.js:53-56`](../../packages/tooling/eslint.base.js) bans the framework's own word for it in any comment, at `error`. **The rule was not weakened, disabled or narrowed to admit a register's vocabulary**; the register changed its vocabulary. That is [CLAUDE.md](../../CLAUDE.md)'s *never weaken a gate to pass it* applied to a case where the gate is inconvenient and correct.

**IT REFUSES TO UNDER-ASSERT RATHER THAN REPORTING A CLEAN RUN IT DID NOT MEASURE.** Three refusals, each of which turns a silent pass into a red: a report with no test files THROWS, something that is not a Vitest report THROWS, and a report whose `numPendingTests` or `numTodoTests` disagrees with its own per-case statuses is a finding that says the checker cannot read the report. **That last one is what would fire if a Vitest upgrade changed the JSON shape**, which is otherwise the way this control would quietly stop working.

**THE WORKFLOW EDIT IS THE ONE THING IN THIS FENCE THAT NEEDED A REASON AND HERE IT IS.** The fence admits [`ci.yml`](../../.github/workflows/ci.yml) *only if* the control must be run and cannot be run by an existing step. **It cannot.** Every `CI-06` gate runs under `gates.mjs check`, which reads the tree and never runs a suite; every `RI-nn` runs under `repo-invariants.mjs`, which is the same. The number this control needs exists only inside a run, so the assertion has to sit beside a run. **The edit is four lines and it changes no existing step's pass or fail**: `CI-02`'s and `CI-04`'s `vitest run` lines each gain `--reporter=default --reporter=json --outputFile="$RUNNER_TEMP/..."`, and each job gains one step that reads the file.

**`--reporter=default` IS NAMED BESIDE THE JSON ONE DELIBERATELY.** Passing `--reporter=json` alone replaces the reporter and takes the human-readable run out of the log in exchange for a file. **Verified on this row's own tree rather than assumed**: with both named, the run prints its usual summary AND writes the report.

**AND THE REPORT GOES TO `$RUNNER_TEMP` RATHER THAN THE WORKSPACE**, so that no step downstream of it sees a dirty tree.

### 8. Why no `CI-06` letter is spent and no `RI-nn` is minted

**BOTH WERE CONSIDERED AND BOTH ARE REFUSED, AND THE REFUSAL IS STRUCTURAL RATHER THAN THRIFTY.**

**A `CI-06` GATE CANNOT HOLD THIS.** Every gate in [`scripts/corpus/gates.mjs`](../../scripts/corpus/gates.mjs) derives its finding from the tree, and `CI-06g`'s generated spans are the corpus's own remedy for a derivable count. **A skip count is not derivable from the tree** for section 4 item 3's reason, and a `<!--gen:-->` span would be worse than nothing here: `generate` REWRITES a span to match its query, so a span that could compute this would silently self-heal on the day the number moved. **The corpus prefers a span to a check where both are available. Neither is available here**, and that is the finding rather than a gap.

**AN `RI-nn` CANNOT HOLD IT EITHER**, on the same ground: `repo-invariants.mjs` reads the tree. **The one half of this control that IS static** -- that every register row names a file that exists -- **is held by a case in [`packages/tooling/test/skipped-tests.test.ts`](../../packages/tooling/test/skipped-tests.test.ts) instead**, which is the pattern `absence-claims.mjs`, `dependants.mjs` and `response-shape-copies.mjs` already use: a reader in `checks/`, exercised by a test. **Minting a number for it would take an `RI` slot for the smallest half of the thing.**

**SO THE CORPUS CARRIES ONE NEW COMMITMENT AND IT IS NAMED IN FULL: two `CI` stages now have a step that can fail for a reason no `CI-06` letter and no `RI-nn` covers**, and the only places that describe it are the module's header, this entry, and the workflow comments beside the steps. **That is a real cost of putting the assertion where the run is, and it is stated rather than absorbed.**

### 11. What a founder read adds and this entry cannot

**THE FIRST DECISION IS WHETHER A CONTROL THAT LIVES OUTSIDE THE GATE AND INVARIANT REGISTERS IS ONE THIS CORPUS WANTS.** Section 8 argues it is forced: the number exists only in a run, and every `CI-06` letter and every `RI-nn` reads the tree. **But the consequence is a check that `gates.mjs list` and `repo-invariants.mjs list` do not name**, so a reader auditing what this repository enforces will not find it there. **A founder may prefer a thin `RI-nn` that asserts only the register's static half, purely so the thing has a number and a row.** This row did not take one because a number for the smallest half of a control reads as coverage the number does not have, and that judgement is exactly the kind a row should not make silently.

**THE SECOND IS WHETHER THE TAX IS THE RIGHT WAY ROUND.** Section 7 prices it at about one firing in ninety rows, and every firing lands on a row whose actual subject is something else. **The alternative was a control that fires only when a case STOPS running**, which costs almost nothing and which this row refused because it encodes intent. **A founder can overrule that trade**, and the cost of overruling it is that the day [ADR-429](ADR-429.md)'s eleven skips start running is a day nothing says so.

**THE THIRD IS THE HOLE IN SECTION 10 AND WHO CLOSES IT.** `golden` is unbound because its workflow was outside this fence. **That is a fence artefact and not a reasoned scope**, and the honest thing to say about it is that the register's shape does not distinguish a project nobody checks from a project with no skips.
