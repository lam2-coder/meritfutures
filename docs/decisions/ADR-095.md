## ADR-095: the UI framework is Next.js App Router in `apps/portal` and `apps/site`, and the decision that outlives it is what it FORECLOSES  (2026-08-24, status: proposed)

This entry rules the framework: **Next.js `16.3.2`, App Router, on React `19.2.8`, in `apps/portal` and `apps/site` and in no other package**, entered through `pnpm-workspace.yaml`'s `catalog:` as one [`VG-12`](../testing/STRATEGY.md) admission. **The choice is the smaller half of this entry.** [P4 section 11](../plans/P4-portal-and-site.md) rule 8 asks for the other half by name, and section 3 is it: a rendering technology chosen today is the thing every Merit UI is written against for years, and three of its foreclosures land on controls this corpus already relies on.

- **Origin:** [P4](../plans/P4-portal-and-site.md) section 4.3, dispatched as session **183**, slice `P4-c`. The number was allocated by [session 181](../sessions/2026-08-24-session-181.md) before this session ran, so none was chosen here; [ALLOCATION](ALLOCATION.md)'s `095` row is amended **in place** per [ADR-065](ADR-065.md) T3.

- **Context:** [`apps/portal/src/index.ts`](../../apps/portal/src/index.ts) states the gap at the point of declaration and declines to close it, and [session 111](../sessions/2026-08-21-session-111.md) and [session 158](../sessions/2026-08-24-session-158.md) each recorded it as owed and out of their own fences. - **NOT MONEY PATH**, and **high consequence anyway.** Nothing here touches the ledger, the engine, payout or auth, so [ADR-003](ADR-003.md)'s strict regime does not bind this session. ### 2. THE RULING

**RULING 1. Next.js `16.3.2`, App Router, on React `19.2.8` and `react-dom@19.2.8`, with `@types/react@19.2.18` and `@types/react-dom@19.2.5`.** Five catalog entries, exact per [`.npmrc`](../../.npmrc)'s `save-exact`, in `pnpm-workspace.yaml`'s `catalog:` block so the version is approved once on a diff to that block rather than once per manifest.

**The React type packages land NOW and not with the first page, and the reason is a collision rather than tidiness.** [P4 section 9](../plans/P4-portal-and-site.md) rows `pnpm-lock.yaml` as **serial three ways** across `P4-c`, `P4-d` and `P4-i`, and the two slices that actually write pages, `P4-e` and `P4-h`, hold neither the lockfile nor the catalog in their fences. A page-writing slice that had to add `@types/react` would have to join a serialization it was never scheduled into.

**RULING 2. Two applications, named.** `apps/portal` and `apps/site`. **`apps/api` gets none**, which is [ADR-083](ADR-083.md)'s ruling and not this one's, and **`apps/admin` gets none by this entry**: the admin console is [M06](../plans/M06-admin-ops-console.md)'s and is in no P4 slice, so an entry whose fence is P4 `P4-c` may not decide it. Section 3 records what that leaves open.

**RULING 3. No Next.js route handler and no Server Action may serve `/api/v1`, any operator path, or any surface [API_CONTRACT](../architecture/API_CONTRACT.md) specifies.** [ADR-083](ADR-083.md) section 3 governs, unchanged and unweakened: the API is its own deployable and a surface that CONTAINS it has a privileged back door by construction. **This ruling exists because the framework being admitted is exactly the one ADR-083 named**, and admitting it without restating the boundary would leave the boundary resting on a rejected-alternatives table cell.

**RULING 4. ONE carve-out, narrow and named: cache control on `apps/site`.** [M09 section 3.2](../plans/M09-marketing-site.md)'s publish sequence has the API call the site (`API->>Site: revalidate(paths for this plan)`) and `INV-M9-04` makes the return value part of the publish transaction's definition of done. A framework cache can only be invalidated from inside the process that holds it, so that hop **must** terminate in `apps/site`. It is permitted as a **cache-control hook and never as an API surface**, on [M09](../plans/M09-marketing-site.md)'s own four conditions: admin origin, service credential, path allowlist, and **no trader data read**. Anything wider is Ruling 3's.

**RULING 5. The `build` script lands in both manifests in this commit, and `CI-07` is RE-RULED rather than implemented.** Section 6.

**RULING 6. No page, no layout, no route, no `next.config`, no `tsconfig` change.** This entry admits a dependency and rules a boundary. The first rendered document is `P4-e`'s and `P4-h`'s.

### 6. What `CI-07` becomes, and why this entry does NOT implement it

**`CI-07`'s artifact was *"a `build` script in any `apps/*/package.json`"* and RULING 5 makes it arrive.** [STRATEGY section 4.1](../testing/STRATEGY.md)'s own rule is that the day the artifact arrives *"the row is a finding until the stage is written"*, and `CI-06/gate-inventory` implements it as the assertion that fails on good news. **The row moves in this commit or the gate lies in the direction that looks like success.**

**It moves to a new dated condition and NOT to an implementation, and the reason is the fence.** An implemented leg must name a workflow under [`.github/workflows/`](../../.github/workflows/) and a top-level job key in it, which `CI-06/gate-inventory` verifies. **`.github/workflows/ci.yml` is not in `P4-c`'s fence** ([P4 section 8](../plans/P4-portal-and-site.md)); it is in `P4-i`'s. [P4 section 11](../plans/P4-portal-and-site.md) rule 5 makes the fence absolute and rule 13 makes widening it and weakening a gate the same move, so the stage is not written here and section 9 reports whose it is.

**The new artifact is a path, and the row could not be honestly closed on anything weaker.** [ADR-073](ADR-073.md) section 2 (b) requires a path or a manifest key, and `CI-06/gate-inventory` reports on every run that **four of the six conditions meet neither**. This one now does.

> **Artifact: a `page`, `layout` or `route` file under `apps/*/src/app/`.**

**It is absent, and the reason the stage still cannot be written was EXECUTED rather than argued.** With `next@16.3.2` installed and a `build` script in place, `next build` in `apps/site` at this commit exits **1**:

```
▲ Next.js 16.3.2 (Turbopack)
✓ Running next.config took 15ms
> Build error occurred
Error: > Couldn't find any `pages` or `app` directory. Please create one under the project root
```

**So a `CI-07` written today could only fail forever**, which STRATEGY section 4's first paragraph forbids, and skipping it instead is forbidden by [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) rule 2. **That is the same two-sided argument the row already carried, against an artifact that has moved one step down the chain**: the build script existed and had nothing to build.

**AND MOVING IT REMOVES A CONSTRAINT ANOTHER SIGNED ENTRY WAS LEANING ON, WHICH IS NAMED HERE RATHER THAN LEFT TO BE DISCOVERED.** [ADR-083](ADR-083.md) section 5 derived *"the framework had to be one that needs no build step at all"* from this exact probe, *"a condition on the candidate set"* rather than a preference, and its own foreclosure table hedges it: NestJS is *"not merely rejected but unavailable **while that gate stands as written**"*. **After this entry that gate does not stand as written.** `ADR-083`'s ruling survives on its three measured properties and on its back-door argument, both independent of any probe; **the enforcement does not**, and section 9 items 3 and 3b carry it. **A gate is a bad place to keep another decision's premise**, and this is the corpus finding out why.

### 8. The defect this commit exposed, which was NOT in scope and is repaired anyway

**`next@16.3.2` declares `@playwright/test` as an OPTIONAL PEER DEPENDENCY**, and pnpm's lockfile records a package's `peerDependencies` block verbatim. So installing Next.js writes this into [`pnpm-lock.yaml`](../../pnpm-lock.yaml):

```yaml
  next@16.3.2:
    peerDependencies:
      '@playwright/test': ^1.51.1
```

**`CI-08`'s probe read that as Playwright having arrived**, and the gate failed on a row this session's fence does not hold:

```
FAIL   CI-06/gate-inventory
       docs/testing/STRATEGY.md:191 CI-08: the artifact "@playwright/test present in the
       lockfile" HAS ARRIVED (pnpm-lock.yaml names `@playwright/test`)
```

**Playwright is NOT installed.** A declaration inside another package's optional-peer block is a statement about a package that is absent, and `CI-08`'s condition names *"`@playwright/test` **present** in the lockfile"*. **This is the same lesson the probe's own comment already records one line up**: it is anchored so that `@vitest/browser-playwright` does not trip it, and `VG_PROBES` is anchored so that `fastify-plugin` does not trip `fastify`. **Both anchors bound the NAME and neither bounds the CONTEXT**, and an optional peer is the context case.

**The probe is repaired to read an installed package, which is a lockfile entry KEY**, and `falsify.mjs` gains the pair that proves it in both directions: a real install must still fire, and an optional-peer declaration must not. **`CI-08`'s STRATEGY row is untouched**, because nothing about it was wrong: its artifact is still absent and its cell still says so.

**Two things this deliberately does not do.** It does not touch `VG_PROBES`, whose `fastify` needle has the same latent imprecision, because [P4 section 8](../plans/P4-portal-and-site.md) gives the `VG` register to `P4-d`; section 9 reports it. And it does not relax what `CI-08` asserts.

> **A file at `apps/portal/src/app/api/v1/admin/payouts/route.ts` exporting `GET` leaves `pnpm run lint`, `node packages/tooling/checks/repo-invariants.mjs` and `pnpm -r run typecheck` ALL at exit 0, and `apps/api/test/surface.test.ts` at 10 passed.** So after this entry, an operator-shaped API route served from inside a UI deployable is refused by **nothing in this repository**.

**The direction it fails in.** If the clause is wrong, this entry has overstated a gap and the cost is a lint rule nobody needed. **If it is right, which is what the run says, then [ADR-083](ADR-083.md)'s *"no privileged back door"* is, from this commit, a rule with no mechanism inside the two deployables best placed to break it.** `ADR-083` closed that door with **two status codes one row apart**, 403 for a permission check and 404 for an absent route, and the whole construction rests on the operator path not existing in the public deployment. **A route handler in `apps/portal` makes it exist**, and the failure is silent: the app builds, the route serves, every gate stays green, and the first evidence is an incident. **The clause is cheap to check and the failure is expensive and quiet, which is why it is the clause rather than the closure count or the version pin.**

**Approval line: UNSIGNED.** This entry is `proposed`. **`VG-12`'s human leg is not discharged by writing a catalog line**, and a merge of this pull request is what grants it (section 5).

Whether that ground is strong enough to spend the next several years of UI work on is the founder's, and nothing in this session can turn it into a measurement.
