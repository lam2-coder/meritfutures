## ADR-363: the live count was a hand-written literal standing on a resolver that reads one hop, and the three defaults NAMED `production*` were counted as refusing without anything opening them; the answer is now derived from the leaves and the residual judgement is two ports rather than fourteen (2026-09-06, status: proposed)

**[ADR-357](ADR-357.md) built the right control and left its own control hand-maintained.** It added `DEFAULTS`, which reads back off the tree and reddens when a default changes, and beside it `LIVE_DEFAULT`, which read `new Set(['useTurnstileVerifier'])` and read back off nothing at all. **The gap between them is `defaultOf`.** That function resolves a port's default **exactly one hop**: it finds the setter's target, finds that target's module-scope binding, and returns the initializer **as a string**. So `useAffiliateDeps` recorded the text `productionAffiliateDeps`, and no assertion in this repository ever opened it.

**THE RULING IS THAT THE RECORDED NUMBERS ARE RIGHT AND THE REASON THEY WERE RIGHT WAS LUCK.** Three of the thirteen refused because a value whose NAME begins `production` happened to hold a refusing member. `LIVE_DEFAULT` is now derived by following each default past the first hop to its leaves, and `{blocked: 14, refusing: 13, live: 1}` is unchanged.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `363`, branch `claude/a-live-count-nobody-derives`, session **558**.
- **THE DELIVERABLE IS A DERIVATION, FOUR ASSERTIONS AND ONE LEAF NOBODY HAD SEEN.** No port is wired, no number moves, and no `src/` file is changed.
- **NOT THE MONEY PATH ITSELF. IT IS THE CONTROL OVER THE MONEY PATH'S HONESTY.** Ships `proposed` with an **UNSIGNED** approval line. **Merging is not signing.**
- **NO MIGRATION WAS TAKEN OR EDITED.** `git diff --stat origin/main -- packages/db/migrations scripts/db` is **EMPTY**.
- **`apps/api/src` IS BYTE-IDENTICAL TO `origin/main`.** Six falsification seeds edited it and every one was restored and verified with `sha256sum -c`.

### 2. THE RULING

1. **`LIVE_DEFAULT` IS DERIVED FROM THE TREE AND IS NO LONGER DECLARED.** The chain is followed past the first hop: an identifier is followed to its binding, an object literal is descended member by member, a call is followed into the factory it names across a relative import, and the walk stops at leaves.
2. **`refuses` MUST BE PROVEN AND NOTHING ELSE EVER BECOMES A REFUSAL BY DEFAULT.** The grammar is asymmetric on purpose, which is section 4.
3. **TWELVE OF THE FOURTEEN PROVE REFUSING WITH NO JUDGEMENT AT ALL.** The residual judgement is **two ports**, where it was fourteen.
4. **THE DERIVED SET EQUALS THE RECORDED ONE.** `{blocked: 14, refusing: 13, live: 1}` does not move, and no number was adjusted to reach that.
5. **ONE LEAF WAS FOUND THAT ADR-357's TABLE DID NOT SEE**, and it is section 5. It does not change the count, and it is reported because the derivation is what surfaced it.

### 3. Why "they all refuse today" is the danger and not the reassurance, measured rather than argued

The dispatch's claim is that a later edit to `productionAffiliateDeps` would leave every gate green while `refusing: 13` became a lie. **That was not reasoned about. It was seeded and watched.**

`productionAffiliateDeps` was given a backend that serves, `{ backend: { affiliate: async () => ({ code: 'MERIT' }) } }`, and the file was run. **Three of ADR-357's controls stayed GREEN:**

| case | under a serving affiliate default |
|---|---|
| `every blocked port records the module-scope default it actually holds` | **PASSES.** `defaultOf` still returns the string `productionAffiliateDeps` and `DEFAULTS` still matches |
| `the wired count is reported` at `{declared: 25, wired: 11, blocked: 14}` | **PASSES** |
| `exactly one blocked port is live with nothing installed, and it is named` at `{blocked: 14, refusing: 13, live: 1}` | **PASSES** |

**Only the two derived cases went red.** So on the base tree the whole gate set would have reported thirteen refusals over a port that served, which is the class this repository already has a name for: a check that goes green on a commented-out control, the reason `RI-25` exists.

**AND THE SEED THAT WOULD HAVE BEEN CAUGHT IS THE ONE THAT MATTERS LEAST.** Changing a default's FIRST hop, `= null` to something live, does redden `DEFAULTS`, because the recorded text changes. **Changing what the name POINTS AT does not.** The hand-written answer was defended against the visible edit and blind to the quiet one.

### 4. The grammar, and why it is asymmetric

The walk lives at [`wiring.test.ts:2099`](../../apps/api/test/wiring.test.ts) and the leaf rule at `wiring.test.ts:2074`.

| verdict | what it means | what happens |
|---|---|---|
| `refuses` | **PROVEN**, out of a closed list: `null`, `undefined`, an empty string, a function that throws and does nothing else, a function that returns a rejection, a function that returns nothing, and an object every one of whose members is one of those | counted among the refusals |
| `unproven` | parsed, and **not** a proven refusal | must carry a written ruling, or the suite is RED |
| `unresolved` | did not parse at all | **RED**, naming the port and the text the walk stopped on |

**THE ASYMMETRY IS THE WHOLE CONTROL.** A resolver that silently gave up would be indistinguishable from one that proved a refusal, and the count would go green on the give-up. So the burden sits on `refuses`: everything the grammar does not prove is one of the other two, and **neither of the other two can ever become a refusal by default.** The consequence is that the gate cannot go green on a shape nobody has read, which is the property the row asked for, and it is the inverse of "assume it refuses".

**IT DOES NOT READ THE WORD `UNWIRED_`, AND THAT IS ADR-357's OWN MEASUREMENT APPLIED RATHER THAN REPEATED.** That entry wrote the name-reading probe, ran it, and refused it on its own result: it classifies thirteen correctly and `PRODUCTION_CHECKOUT_ADAPTERS` **wrongly**, because that value names no `UNWIRED_` member and refuses by being empty. **The walk proves all four of its members refuse without reading a name at all**, and section 5 is the case that runs the other way: a value that carries the word and is **not** proven.

**THE MODULES ARE STILL READ AS TEXT.** No route module is imported, for this file's own standing reason: importing one binds a port.

### 5. The leaf nobody had seen: an unwired default carrying a working clock

**`UNWIRED_WITHDRAWAL_BACKEND` holds `now: () => new Date()`** at [`wallet-withdrawals.ts:1128`](../../apps/api/src/routes/wallet-withdrawals.ts). It is a working clock and not a refusal, and **the four sibling defaults that carry a `now` all throw from it instead**. ADR-357 section 3 recorded this port under `UNWIRED_WITHDRAWAL_BACKEND` and classified it "refuses" without descending into it. The name was doing the work.

**THE RULING IS THAT THE PORT STILL REFUSES, AND IT IS MEASURED AT BOTH DOORS RATHER THAN ASSERTED.** The creation door reads the clock at `wallet-withdrawals.ts:2468` and the very next statement rejects, because `begin` at `wallet-withdrawals.ts:1112` refuses and `unwiredOrThrow` at `wallet-withdrawals.ts:2381` answers 503. The cancellation door reads it at `wallet-withdrawals.ts:2604` and `transact` refuses at `wallet-withdrawals.ts:2621` into the same handler. **A timestamp computed and discarded is not a request served**, so the port belongs among the thirteen and the count does not move.

**THIS IS THE HAND-MAINTAINED HALF, AND IT IS SMALLER AND LOUDER THAN WHAT IT REPLACED.** `UNPROVEN_RULING` at `wiring.test.ts:2200` holds **two** entries, and the assertion requires its key set to equal the derived `unproven` set **in both directions**. So a default that stops being a proven refusal cannot reach `refusing` until somebody writes the sentence, and a ruling cannot outlive the shape that needed it. **What was hand-written before was the ANSWER. What is hand-written now is an INPUT to an answer that is computed, and it is enforced for presence and for necessity.**

### 8. Where this entry is most likely wrong

- **`useWithdrawalBackend`'s ruling is a judgement and it is the one to attack.** It rests on an ORDERING at two call sites: the clock is read, and the next thing refuses. **A third door, or a reordering of either existing door, could put that timestamp somewhere a caller sees**, and nothing in this file watches the ordering. Section 6 of [ADR-359](ADR-359.md) built exactly that assertion for the certificate clock, in that route's own suite, and the equivalent for withdrawals is **not** built here: it is another module's suite and another row's fence. **What is guarded here is that the leaf cannot change without this ruling being re-read**, which is weaker than guarding the ordering and is stated so nobody reads it as stronger.
- **The clock is arguably the defect rather than the finding.** `UNWIRED_WITHDRAWAL_BACKEND.now` is the only unwired `now` in the deployable that does not throw, and the consistent repair is to make it throw like its four siblings. **That is a `src/` change, this row's fence forbids `apps/api/src` entirely, and it would be this row taking another row's object as a means.** It is recorded as an open question rather than taken.
- **The grammar is a closed list and closed lists go stale.** A future default written as a ternary, a spread, a `new`, or a value reaching a package is `unresolved` and turns this file RED with no defect present. **That is the intended direction of the error** and it is still a cost, paid by whoever writes the next default.
- **"Serves" is never proven, only "refuses" is.** A leaf the walk calls `unproven` may in fact refuse for a reason no grammar can see. The remedy is a written ruling, which is what `UNPROVEN_RULING` is for, and the risk is that the ruling is wrong rather than that it is absent.
