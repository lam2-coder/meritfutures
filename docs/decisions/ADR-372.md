### 4. Is the text derivation right? It is correct here, and three things hold it up

**THE PATTERN IS ANCHORED AT THE START OF A LINE.** That anchor, and not any understanding of the language, is what refuses the shapes the row was sent to look for.

| what could hide an install | refused | by what |
|---|---|---|
| a call inside a conditional | **yes** | the anchor, because the body is indented |
| a call inside a function nobody invokes | **yes** | the anchor, same reason |
| a call behind an early return | **yes** | `return` is not legal at module top level here, and the anchor refuses it wherever it is legal |
| a call commented out with `//` | **yes** | the anchor, because the comment marker occupies column zero |

**AND THE INDENTATION THAT DOES THREE QUARTERS OF THAT WORK IS THE FORMATTER'S, NOT THE SCANNER'S.** Every nested shape above is refused because `prettier` indents a nested statement and `format:check` is a gate. **The scanner is relying on a control in a different runner to mean what it means**, which is worth writing down once even though the reliance is sound: `format:check` is green on every commit and there is no path by which an unindented nested statement reaches `main`.

**SO THE THIRD THING IS THE ONLY ONE INSIDE THE SCANNER, AND IT IS A CONVENTION RATHER THAN A RULE.** This file comments with `//` and never with a block. A block comment defeats the anchor completely, and section 5 is that measurement.

**THE TWO DERIVATIONS AGREE EXACTLY ON THIS TREE**, and the agreement is now a case rather than this paragraph. `apps/api/test/start-program.test.ts` reads the pattern OUT of `wiring.test.ts` rather than copying it, asserts the extraction before using it, and compares the set it yields with the set a run would install.

### 5. The four shapes counted as wired that install nothing, and the one `RI-25` was minted for

**`RI-25` EXISTS IN THIS REPOSITORY BECAUSE A CONTROL PASSED WHILE THE THING IT GUARDED WAS MERELY COMMENTED OUT, AND THE ROW WAS SENT TO LOOK FOR EXACTLY THAT CLASS HERE.**

**THE CLASS IS REAL AND THERE IS NO INSTANCE OF IT ON THIS TREE.** Both halves are asserted. Each shape below is a whole module, scanned by the pattern `wiring.test.ts` owns and parsed by the reader the other cases use, and the two disagree on four of the seven.

| shape | scanner | a run | |
|---|---|---|---|
| an honest top-level install | counts it | installs it | agree |
| a `//` comment | refuses it | installs nothing | agree |
| a call nested in a conditional | refuses it | installs nothing | agree |
| **a BLOCK comment** | **counts it** | installs nothing | **DISAGREE** |

### 6. The half-install: this file cannot produce one, and the reason it cannot is one statement nobody was guarding

**[ADR-356](ADR-356.md) PRICED THE HALF-INSTALL AT 200/500 AGAINST 503/503 AND RULED THE HALF-INSTALL WORSE**, because a partial install silences the operator-facing statement of the blocker for every route while fixing some of them. The row asked whether this file can produce a deployment that half-installs and then serves.

**IT CANNOT, AND THERE ARE TWO INDEPENDENT REASONS.**

**FIRST, NO INSTALL CAN FAIL.** Every adapter factory this file calls was read for a `throw` reachable at CONSTRUCTION time, meaning a throw outside every nested function in its body. **All eleven have none**, and neither does `postmarkOtpSender`, which `databaseAuthBackend` evaluates as a default argument on this very call. Each returns an object of closures, and every environment read and every refusal lives inside a method, per request. **There is no configuration a deployment can be missing that makes one of these eleven lines throw.**

**SECOND, AND THIS IS THE ONE THAT WOULD STILL HOLD IF THE FIRST FAILED: THERE IS NO WINDOW.** `app.listen` is reached only inside `main`, and `await main()` is the last of the twenty-six top-level statements. An exception anywhere in module evaluation, including inside an import, aborts before `main` is entered. **The process then serves nothing at all rather than serving some routes and refusing others**, which is not the failure ADR-356 ruled worse: it is the total outage that ruling preferred, in its strongest form.

**AND THE PROPERTY IS HELD BY THE PLACEMENT OF ONE STATEMENT, WHICH NOTHING ASSERTED.** The file's own header rules it in prose: the installs sit before `main()` because *"a window in which the process is listening and the backend is still the fail-closed default would serve 503 to real traffic for as long as the event loop took to come back around, which is a race nobody would ever reproduce and everybody would eventually see"*. **That sentence has been right and undefended for as long as the file has existed.**

**THE EDIT THAT WOULD BREAK IT IS THE EDIT THIS FILE INSTRUCTS THE NEXT SESSION TO MAKE.** The same header rules the conflict shape for the concurrent route slices that collide here as an APPEND, *"keep every line"*. **An append that lands past the final statement is exactly this defect**, `wired` cannot see it because a line pattern has no notion of before, and the port would be reported as wired while a deployment bound its socket with that backend still at its fail-closed default. **Seed 3 moved one install below `main()` and watched the new case go red.**

### 13. Where this entry is most likely wrong

- **THE READER IS A SYNTAX TREE AND NOT A TYPE CHECKER.** It knows that a statement is a top-level call to a name beginning `use` or `set`; it does not know that the name resolves to a port setter rather than to an import of something else with the same shape. `tsc` closes that gap on every commit and this file does not duplicate it, but the claim "eleven installs" is a claim about SYNTAX plus the resolution `tsc` proves separately.
- **THE `throw` CLAUSE IS THE ONLY REACHABILITY MODELLING IN THE READER, AND REACHABILITY IS BIGGER THAN THAT.** A top-level `await` of a promise that never settles would leave every statement below it unreached, and nothing here models it. **The straight-line case forecloses the shapes that would need it**, which is why that case is first: it is the assumption every other case rests on, asserted rather than assumed.
- **"NO CONSTRUCTION-TIME THROW" WAS DERIVED SYNTACTICALLY AND NOT BY CALLING THE ELEVEN FACTORIES.** A throw inside a helper each factory calls during construction would be invisible to it. The factories were also read, and all eleven return an object literal directly, but the mechanical half of that claim is weaker than the read half.
- **SECTION 8 ARGUES THAT LINE ORDER IS INERT AND THE ARGUMENT IS FROM ONE READING OF `main`.** If any future statement in this file were to serve a request before the last install, the ordering claim would become a run-time one and section 6's case is what would notice.
