## ADR-288: a red security gate on `main`, and the ruling is that an unrewritable commit is PINNED while the tree it left behind is REPAIRED  (2026-08-30, status: proposed)

**`CI-05`'s `VG-1` was red on `main` and this row is the only thing that mattered until it was green. It is green.** Both halves of `VG-1` failed, `gitleaks git .` at [`ci.yml:440`](../../.github/workflows/ci.yml) and `gitleaks dir .` at [`:443`](../../.github/workflows/ci.yml), on the same two lines. **No secret was exposed and none ever was.** The two findings are test fixture idempotency keys: lowercase hyphenated English labels with an ADR number interleaved, typed by hand into a case that refuses before it reaches a backend.

**THE RULING IS A SPLIT, AND THE SPLIT IS THE WHOLE ENTRY.** The working tree is **REPAIRED** and the history is **PINNED**, and the two halves are decided on opposite grounds because only one of them can still be changed.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `288`, session **479**, branch `claude/a-red-security-gate-on-main`. **NO MIGRATION. NO `src/` LINE. NO `RI-nn` MINTED**, and `RI-32` is still free.

- **NOT A MONEY PATH ROW**, though it touches a money-path test file. The only change to `apps/api/test/payouts.test.ts` is two string literals and a comment; no assertion, no case, no route and no expectation moved.

- **HISTORY WAS NOT REWRITTEN.** No rebase, no amend, no force-push, no `filter-branch`, on any branch. Commit `00cb1bbb` is untouched and remains an ancestor of `origin/main`.

- **NO GATE WAS WEAKENED.** `generic-api-key` is not disabled and not loosened, the entropy floor is unchanged, no directory and no path is excluded, no inline annotation idiom was introduced, and `.github/workflows/ci.yml` is byte for byte unchanged. Section 5 is the proof and it was watched rather than argued.

- **TWO OF THE ROW'S OWN PREMISES ARE FALSE AND SECTION 1 SAYS SO.** This repository HAS recorded a confirmed false positive before, and the local `dir` count the row predicts does not reproduce.

- Ships `proposed` with an **UNSIGNED** approval line. Merging is not signing.

### 2. What the two values actually are, and why seven siblings never tripped

The file's fixture convention is `idem-<word>`: `idem-honest-path` (`:441`), `idem-hold-path` (`:730`), `idem-replay` (`:808`), `idem-reuse` (`:829`), `idem-foreign` (`:847`), `idem-refused` (`:865`) and `'k-x'` (`:926`). **Seven fixtures, none of which has ever tripped `VG-1`.** Session 476 wrote two more and interleaved a digit run into the same shape.

**THE DIGIT RUN IS THE WHOLE OF THE DEFECT.** `generic-api-key` requires two things together: a binding whose name carries a key-ish word, and a literal whose Shannon entropy clears its floor. The seven siblings satisfy the first and fail the second. Three characters of decimal inserted into a hyphenated English label satisfy both, because a run of digits inside lowercase letters is precisely what raises per-character entropy. **The two literals are described here and NOT reproduced**, in this entry, in [`.gitleaksignore`](../../.gitleaksignore) and in the session log, because a document quoting them carries the finding into the record of the finding. That is not caution invented here: [`STATE.md:4219`](../STATE.md) records a session whose first draft of this same paragraph reproduced its own literal and turned `CI-05` red a second time, and [`:7222`](../STATE.md) records a third session doing it again in a session log.

**Measured rather than reasoned.** A probe file was written with both spellings and five candidate replacements, each in three syntactic positions, and scanned. Only the two digit-carrying spellings fire, and they fire only in the two positions where a key-ish binding name sits beside them. `idem-absent`, `idem-after-fold`, `idem-fold`, `idem-none` and `idem-refold` are silent in every position.

### 3. The working tree is REPAIRED, and that is not a suppression

**Ruling 1. Both fixtures are renamed forward to the file's own convention: `idem-absent` and `idem-after-fold`.** `gitleaks dir .` then reports `no leaks found` and **no `dir` entry is added to [`.gitleaksignore`](../../.gitleaksignore) at all.**

This is the half that could still be fixed, so it is fixed. A `dir` fingerprint here would have been the weakening, because it would buy green while leaving in the tree the thing that produced the finding, which is the sentence [`STATE.md:4219`](../STATE.md) and [`:4286`](../STATE.md) both close on.

**A COMMENT IS ADDED AT THE FIXTURE AND IT IS NOT AN ANNOTATION.** It carries no `gitleaks:allow`, no directive and no pragma; it is nine lines of prose saying why the names carry no digits. The row forbids "a blanket inline silencing idiom that the next session will copy" and it is right to: an idiom that silences is copied without being read. A comment that explains has the opposite property, and the only thing worth copying from it is the convention it points at, which already existed seven times over.

**The suite is unmoved.** `apps/api/test/payouts.test.ts` runs 41 cases and all 41 pass. The renamed values are opaque strings to every assertion that touches them; the case asserts a 503, then a 409 on the same value, then a 200 on a different one, and none of those depends on what the values spell.

### 4. The history is PINNED, and this is the ruling

**Ruling 2. The two findings are recorded as confirmed false positives by full `commit:file:rule:startline` fingerprints appended to [`.gitleaksignore`](../../.gitleaksignore), the mechanism this repository already owns.**

**THE ROW OFFERED A `.gitleaks.toml` OR `--baseline-path` AND BOTH ARE WORSE THAN THE FILE THAT ALREADY EXISTS.**

| Candidate | Refused because |
| --- | --- |
| A new `.gitleaks.toml` allowlist at the root | It would be a SECOND suppression mechanism beside a first, and a repository with two places to look has one nobody reads. It also carries a live footgun: a root `.gitleaks.toml` REPLACES the default rule set unless it opts back in, so the failure mode of a typo is every rule silently gone. [`STATE.md:3769`](../STATE.md) already refused this shape on its own ground, that it "exempts the PATH permanently where the defect was one STRING once" |
| `--baseline-path` | It requires a flag on [`ci.yml:440`](../../.github/workflows/ci.yml), which the row permits only if the ruling requires one, and it suppresses by comparison against a committed snapshot of ALL current findings rather than by pinned identity. A baseline is a blanket that happens to be empty today |
| Loosening the rule, excluding `**/test/**`, raising the entropy floor | Each is weakening a gate to pass it, and the second is the sharpest: a real credential pasted into a test is exactly what `VG-1` exists to catch |
| Rewriting `00cb1bbb` out of history | Forbidden absolutely by this row and by the constitution. `git merge-base --is-ancestor 00cb1bbb origin/main` exits **0**, so the rewrite is a rewrite of the DEFAULT BRANCH, which invalidates every checkout and every open branch in the repository |

#### 4.1 The four refusals this ruling owes an answer to, and the corpus answers them itself

**THIS REPOSITORY HAS REFUSED A GITLEAKS SUPPRESSION FOUR TIMES.** A session reaching for [`.gitleaksignore`](../../.gitleaksignore) that does not know this is a session about to repeat a decision it never made.

1. [`STATE.md:3769`](../STATE.md): "**The remedy that was refused is the one inside the fence**: a `.gitleaks.toml` allowlist is weakening a gate to pass it".
2. [`STATE.md:4219`](../STATE.md): "the alternative considered and rejected was a `.gitleaksignore` fingerprint, which buys green by keeping the thing that should not be there".
3. [`STATE.md:4286`](../STATE.md): "**A `.gitleaksignore` fingerprint was refused** for the reason the last occurrence gives".
4. [`STATE.md:7224`](../STATE.md): "**The repair is the commit REWRITTEN rather than a `.gitleaksignore` entry**".

**ALL FOUR WERE ON UNMERGED BRANCHES, AND THE FOURTH STATES THE DISTINGUISHING RULE IN THE CORPUS'S OWN WORDS.** [`STATE.md:7225`](../STATE.md) continues: *"on that file's own stated ground, that session 254's four fingerprints are defended only because their commits are in `main` while this one sat on an unmerged branch nothing is based on."*

**That sentence is the ruling, already written, by a session that refused a fingerprint.** The refusal presupposes the removal is available. Where the commit is in `main`, it is not available, and the entry that refused a fingerprint is the same entry that says a fingerprint is defensible in exactly this case. `00cb1bbb` is in `main`. The prior three all record a rebase plus `--force-with-lease` over the session's own commits, authorised by the founder before it was run, on a branch `main` did not carry; [`STATE.md:4350`](../STATE.md) states its branch "**NOT MERGED**" in the same paragraph.

**AND THE SHAPE DIFFERS INDEPENDENTLY, WHICH MATTERS BECAUSE THE ANCESTRY ARGUMENT ALONE WOULD LET ANYTHING THROUGH.** [`STATE.md:3769`](../STATE.md)'s two values were "a real provider's webhook-secret prefix plus sixteen hex characters: a credential **by shape**". [`:4219`](../STATE.md)'s was "a real base64 image header bound to a local variable named `secret`". **Those are things that should not be in the repository whether or not a scanner notices.** A lowercase hyphenated English label with an ADR number in it is not a credential by shape, by entropy, by origin or by any reading, and no rewrite of a default branch would be spent on it if the scanner were silent. **Both conditions hold here. Either one absent, and the answer is different.**

#### 4.2 What is actually suppressed

**Two points in a history that cannot change.** A `git` fingerprint pins commit, file, rule and start line, and every field is exact. Neither entry can suppress the same rule in another file, the same file at another line, or anything at all in a commit that does not already exist. **The rule runs at full strength over every commit and every file**, which section 5 measured rather than asserted.

**The honest cost is the one [`.gitleaksignore:61`](../../.gitleaksignore) already names**: a secret committed at exactly one of these two (commit, file, line) points would be suppressed. A commit's content is fixed once written, so that is impossible rather than unlikely.

### 5. Watched going red, with the entries in place

**A control nobody has seen fail is a decoration.** Three seeds, each with the two new fingerprints present in [`.gitleaksignore`](../../.gitleaksignore).

**Seed 1, the working-tree half, at the sharpest possible point.** A synthetic credential was written into `apps/api/test/payouts.test.ts` at **line 1151**, the exact line one fingerprint pins, in the exact file it pins. `gitleaks dir . --redact --no-banner --exit-code 1` reported **`leaks found: 1`** and exited **1**. The pin does not reach the working tree, because no `dir` entry exists.

**Seed 2, the history half, and it is the narrowness proof.** A scratch repository was built carrying a byte copy of this repository's `.gitleaksignore`, with a file at the same path, `apps/api/test/payouts.test.ts`, carrying synthetic credentials at **line 1151 and line 1170**, the same two pinned line numbers, under the same rule, committed as `c646893`. `gitleaks git . --redact --no-banner --exit-code 1` reported **`leaks found: 2`** and exited **1**. **Same file, same rule, the same two lines, a different commit, and both are caught.** The commit field is doing the work, which is what a fingerprint is for.

**Seed 3, and it is a finding rather than a confirmation.** The first attempt at seed 1 used an obviously fake value with the letters `FAKE` in it, exactly as the row instructs. **`gitleaks dir .` reported `no leaks found`.** Isolated in a five-line probe: a high-entropy value containing `fake` is silent, one containing `example` is silent, and the same value with a neutral four-character run inserted instead is caught. **`generic-api-key` carries a stopword allowlist, and "label the seed obviously fake" defeats "watch the gate go red".**

**THAT IS WORTH MORE THAN THIS ROW.** The two instructions are individually correct and jointly produce a session that seeds a credential, sees green, and concludes the gate works when it never fired. A seed must be high-entropy and **stopword-free**, and the word that makes it recognisably synthetic must live in a nearby comment rather than inside the value. Recorded here so the next session that is told to seed one does not lose an hour, or worse, does not lose the finding.

**The file was restored from a byte copy taken before the first seed and `sha256sum -c` reports `apps/api/test/payouts.test.ts: OK`** against `f3d042750c2661e60d8a0668f96a5a3064b4ae1599d687c4295f726b17db65f8`. `git status` was read after each restore.

### 6. What is NOT built, and why

**`.github/workflows/ci.yml` IS UNCHANGED.** The row permits it only if the ruling requires a flag, and it does not: `.gitleaksignore` is read from the source directory by default, which the four pre-existing entries prove by having suppressed their findings in this session's very first scan, before a line of this branch was written.

**`docs/architecture/SECURITY.md` IS UNCHANGED.** Its only `VG-1` mention is [`:32`](../architecture/SECURITY.md), a `C-14` control row naming `VG-1` and `VG-2` as the enforcing gates. That sentence is true before this entry and true after it. `VG-1`'s wiring record lives at [`STRATEGY.md:207`](../testing/STRATEGY.md), which says "**Wired**" and names both steps, and it is also unchanged and also still true. **A disposition note added to either would be a fact about one commit written into a document about a control.**

**NO INVARIANT IS MINTED, AND ONE IS OWED.** `packages/tooling/checks/repo-invariants.mjs` is outside this fence and no `RI-nn` was taken. **The gap is real and is registered here rather than left to be discovered:** nothing in this repository checks that a `.gitleaksignore` entry is still LIVE. A fingerprint naming a commit that no longer exists, a file that has been deleted, or a line that no longer carries a finding is dead weight that silently grows, and the file's own header at [`:80`](../../.gitleaksignore) already worries about the fragility of its two line-numbered `dir` entries. **The check is mechanical and cheap:** scan with the ignore file, scan without it, and assert that the difference is exactly the set of entries the file declares. That is the shape [CLAUDE.md](../../CLAUDE.md) asks for when it says to prefer a new CI gate over a bigger model whenever the error is checkable. It needs a fence that reaches the invariants runner and it does not have one here.

### 7. The defect was never a fixture name, and it is the dispatcher's

**`CI-05` FAILED ON ALL THREE OF #632, #633 AND #634 AND ALL THREE WERE MERGED.** The row states this against itself and it is the most useful sentence in it.

**The merge ritual verified gates, invariants, vitest, typecheck, lint and format, and never opened the pull request's own CI.** Every one of those six is a LOCAL check, and [`package.json:21`](../../package.json) deliberately excludes the `CI-05` scanners from `verify` on a sound stated reason. [`STATE.md:3769`](../STATE.md) wrote that consequence down in plain words four months of sessions ago: "**`pnpm run verify` is green on a tree `CI-05` refuses** ... so `verify` exit 0 is not sufficient evidence for a session-end claim". **A ritual composed entirely of checks that cannot see a stage is a ritual that cannot see that stage.**

**THE COUNTERFACTUAL IS THE POINT.** Had the ritual looked once at #632, `00cb1bbb` would have been sitting on an unmerged branch. The repair that three earlier sessions used would have been available, this file would have gained nothing, and section 4 would not have needed to exist. **A fingerprint in `.gitleaksignore` is the permanent cost of one unread status check.**

**So the fix is not in this repository's code and this entry does not pretend to write it.** It is one line in the merge ritual: **read the pull request's own CI conclusion before merging, and treat a red required stage as blocking regardless of what the local checks say.** [`.gitleaksignore`](../../.gitleaksignore)'s new section closes by saying that a THIRD entry in that file is evidence the process fix did not land, and should be read that way rather than as a third fixture that got unlucky.

### 8. Where this is most likely wrong

**The ancestry test is doing a great deal of work and it is a test about GIT rather than about SECURITY.** "The commit is in `main`" makes the repair unavailable; it says nothing about whether the finding is benign. Section 4.1 pairs it with a shape test for exactly that reason, but the pairing is stated in prose here and enforced by nothing. **A session under time pressure could satisfy the ancestry half, assert the shape half, and add an entry for something that really is a credential.** The invariant section 6 registers does not close that either, since it checks liveness rather than judgement.

**The stopword finding may be broader than section 5 measured.** Three values were isolated. `generic-api-key`'s allowlist is upstream's and this entry did not read it, so the list of words that silence it is not enumerated here and should not be assumed to be three.

**And the `dir` entries inherited from session 254 are still line-numbered and still fragile**, by their own admission at [`.gitleaksignore:80`](../../.gitleaksignore). Nothing in this entry improves them and nothing in it makes them worse.
