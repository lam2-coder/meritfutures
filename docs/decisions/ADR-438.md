### 5. THE FINDING. Three columns disagree, and all three are the SAFE direction

**THIS IS THE OUTPUT OF THE CHECK ON ITS FIRST RUN AND IT OUTRANKS THE CHECK.**

| Column | The DDL | The transcription |
| --- | --- | --- |
| `kyc_verifications.raw_result` | `raw_result jsonb NOT NULL DEFAULT '{}'`, [`0003_kyc.sql:103`](../../packages/db/migrations/0003_kyc.sql) | `jsonb('raw_result').notNull()`, [`schema.ts:1793`](../../packages/db/src/schema.ts) |
| `sanctions_screenings.list_refs` | `list_refs text[] NOT NULL DEFAULT '{}'`, [`0003_kyc.sql:170`](../../packages/db/migrations/0003_kyc.sql) | `text('list_refs').array().notNull()`, [`schema.ts:1820`](../../packages/db/src/schema.ts) |
| `identity_phones.release_evidence` | `release_evidence jsonb NOT NULL DEFAULT '{}'`, [`0029_phone_identity_and_auth.sql:139`](../../packages/db/migrations/0029_phone_identity_and_auth.sql) | `jsonb('release_evidence').notNull()`, [`schema.ts:1900`](../../packages/db/src/schema.ts) |

**ALL THREE ARE THE SAME DIRECTION AND IT IS THE FAIL-CLOSED ONE, WHICH IS STATED RATHER THAN ASSUMED.** The DDL declares a default and the transcription records none, so a write type derived from `schema.ts` would **REQUIRE** a value the database would have supplied. The cost is a required field. **It is never a NULL and never a wrong value**, because the transcription cannot cause an omission it does not permit.

**THE OPPOSITE DIRECTION IS THE DANGEROUS ONE AND ITS POPULATION IS ZERO, ASSERTED RATHER THAN REGISTERED.** A transcribed default the DDL does not declare would let a narrowed write omit a `NOT NULL` column the database defaults nothing into, and the row would be refused at the database or, on a nullable column, silently take a NULL. `every disagreement is the SAFE direction` holds that list `[]` over the whole registered population.

**NO `*_cents` COLUMN IS AMONG THEM AND THAT IS ITS OWN ASSERTION** rather than an observation about the three names above, so the day a money column joins the list the case names it directly.

**NOTHING IS REPAIRED AND THE REASONS ARE DIFFERENT FOR EACH SIDE.** A migration is nobody's to edit: **migrations are sacred, never edited, only superseded**, and the dispatch forbids it outright. [`schema.ts`](../../packages/db/src/schema.ts) is not this row's file, and the dispatch says so in as many words: *"read it; it is your input, not your target"*. **So the three are recorded as MEASURED LITERALS in `TRANSCRIPTION_OMITS_DEFAULT`**, with both halves of each asserted, and the register is derived back from the whole registry so it cannot grow quietly.

**THE REGISTER IS A COMMAND IN BOTH DIRECTIONS AND THAT IS WHY IT IS NOT AN EXEMPTION.** A fourth disagreement is RED. **Repairing one of the three is ALSO RED**, so the repair is a diff somebody takes deliberately with this entry in front of them rather than a silent green. Section 7 case 5 is that watched failing.

**WHICH WAY THE REPAIR SHOULD GO IS NOT THIS ROW'S TO RULE, AND ONE THING IS WORTH RECORDING FOR WHOEVER DOES.** [`0029:190`](../../packages/db/migrations/0029_phone_identity_and_auth.sql) declares `CHECK (released_at IS NULL OR release_evidence <> '{}'::jsonb)`, so on that column `'{}'` is the not-yet-released sentinel and a caller REQUIRED to write it is a caller stating which case it is in. **The transcription may be the better reading of the two on that column.** That is an argument, not a ruling, and it is left for a row that owns `schema.ts`.

### 8. What a GREEN comparison still leaves unproven

**[ADR-112](ADR-112.md) FORECLOSURE 4 AND [ADR-299](ADR-299.md) SECTION 5.1 ITEM 5 BOTH SURVIVE THIS ROW INTACT, AND THIS SECTION IS WHY.** [`ADR-299:5.1`](ADR-299.md)'s ruling is *"the runtime guards must not be dropped on the strength of the declared type"*. **Nothing here retires a single runtime check, and a row reading this entry as permission to would be reading it wrong.**

1. **IT IS COMPARED AGAINST THE MIGRATIONS AS TEXT, NOT AGAINST A DATABASE.** The fold is a second transcription. A default that exists in a live database and in no migration is invisible to both sides, and so is the reverse. **No leg of this check connects to Postgres.**
2. **IT IS COMPARED OVER THE REGISTERED POPULATION, WHICH IS NOT THE DATABASE.** [ADR-112](ADR-112.md) foreclosure 4's words at [`ADR-112:92`](ADR-112.md) are *"nothing yet makes the transcription complete"*, and this row re-derived the instance: **four tables the migrations CREATE are transcribed nowhere** -- `identity_merges`, `identity_signal_weights`, `live_account_state` and the vendor `pgboss` schema. **At least six `DEFAULT` clauses live on those tables and no leg of this comparison reads one**, and `live_account_state` carries three `*_cents` columns, which is [ADR-437](ADR-437.md) section 12 item 4 confirmed independently. **The failure stays fail-closed**, because a table `schema.ts` does not name is a table no accessor can address.
3. **IT COMPARES PRESENCE OVER THE POPULATION AND THE VALUE ONLY ON THE TWELVE MONEY COLUMNS.** For the other 401, `schema.ts` may record `.default(7)` where the DDL says `DEFAULT 0` and this is green. **That is a smaller hole than it sounds and the reason is worth writing down**: no column in this tree uses `$defaultFn` (derived: **zero** occurrences in [`schema.ts`](../../packages/db/src/schema.ts)), so drizzle-orm evaluates no default client-side, omits the column from the statement, and **the DATABASE's value is what lands**. The transcribed value is inert at runtime and load-bearing only as documentation and as a type. **It is still a hole, and a row that wants it closed should close it over the whole population rather than by widening the money list.**
4. **IT DOES NOT COMPARE THE `GENERATED ALWAYS AS` EXPRESSION**, section 6. Five columns are transcribed generated and the comparison reads `false` on both sides for each. 6. **AND THE FACT THE TYPE STILL DOES NOT CARRY IS THE VOCABULARY.** [ADR-437](ADR-437.md) section 6.2's `state: string` observation is unchanged by anything here: a narrowing *"would refuse a misspelled column name and admit `'armd'`"*. **A compared DEFAULT does not make a `CHECK` into a type.**
