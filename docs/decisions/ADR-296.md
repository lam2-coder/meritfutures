## ADR-296: a crashed gate is an unknown and not a failure. The corpus runner counts ERROR apart from FAIL, gives it its own exit code, and stops printing a sentence that claims a measurement it did not make (2026-08-30, status: proposed)

**[ADR-294](ADR-294.md) section 7 reported that `scripts/corpus/gates.mjs` carried the same class of defect as `repo-invariants.mjs` and deliberately did not repair it, because `scripts/` was outside that row's fence.** This entry is that repair, and the first thing it owes the record is that **the defect here is NARROWER than the one ADR-294 fixed, and the difference is not cosmetic.**

**WHAT THIS RUNNER ALREADY DID RIGHT, MEASURED AT SOURCE BEFORE ANYTHING WAS CHANGED.** A gate whose body throws prints `ERROR  <id>  <title>` and the message. It is not silent. The denominator does not shrink. The process exits non-zero. **So a crashed gate has never read `33 of 33`**, and no session has ever been able to quote this runner saying every gate held on a run where one did not run. [ALLOCATION](ALLOCATION.md) row `296` states this precisely, having checked it, and the dispatcher's earlier paraphrase, which was the ADR-294 defect transposed whole, was corrected before the row was written. **Restating that argument here as though this runner were as broken would be the same failure this project keeps recording: a claim carried between documents instead of checked against the primary source.**

**WHAT WAS ACTUALLY WRONG IS TWO THINGS AND NEITHER IS THE COUNT.**

**(1) THE CRASH WAS TALLIED AS A FAILURE.** `failed++` in the `catch`, and one counter for both outcomes. A run of thirty-three gates producing thirty-two passes, zero fails and one crash printed `32 of 33 gates pass.` followed by *"A gate that fails is a corpus that is wrong, not a gate to relax."* **The tally asserts thirty-two measurements and one gate that did not hold. The truth is thirty-two measurements and ONE UNKNOWN**, and the sentence beside it sends the reader to repair the corpus, which is the one place the defect is not.

**(2) THE EXIT CODE COULD NOT TELL THE TWO APART.** A crash exited `1`. A genuinely violated corpus exits `1`. A shell that can only see a number had no way to distinguish *"this corpus is wrong"* from *"this run did not measure the corpus"*, and those want different responses from whoever reads them.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `296`, session **489**, branch `claude/a-crashed-gate-is-an-unknown`. **NON-MONEY. TOOLING.** `apps/**` and `.github/workflows/**` are untouched and were not read for edit. **`packages/**` IS UNTOUCHED TOO, AND SECTION 8 RECORDS THE ONE JUDGEMENT THAT DECISION FORCED**, which is where the suite went instead.

- **NO GATE WAS WEAKENED, DELETED, RENUMBERED, SKIPPED OR MADE CONDITIONAL.** The `GATES` array holds the same thirty-three members in the same order. Not one gate body was edited except to seed a crash for the length of one run and put it back.

- **`RI-36`, RESERVED TO THIS ROW BY NAME, IS LEFT FREE.** Section 6 names the three invariants this session considered minting and shows each is either untrue of this tree, red on landing, or a check on a test name.

- **THE COUNT IS UNCHANGED AT THIRTY-THREE.** `33 of 33 gates pass.` on this tree before the change and after it, and section 3 carries both runs so the claim is readable rather than asserted.

### 1. What the runner did, quoted rather than described

```js
    } catch (err) {
      console.log(`ERROR  ${gate.id}  ${gate.title}`);
      console.log(`       ${err.message}`);
      failed++;
      continue;
    }
...
  console.log(
    `\n${selected.length - failed} of ${selected.length} gates pass.` +
      (failed ? ' A gate that fails is a corpus that is wrong, not a gate to relax.' : ''),
  );
  return failed ? 1 : 0;
```

**THREE OF THE FOUR THINGS THAT MATTER WERE ALREADY RIGHT IN THOSE TEN LINES.** `ERROR` is its own word. `selected.length` is the denominator and the `catch` does not touch it. `return failed ? 1 : 0` is non-zero on a crash, so CI has never been fooled by this and the corpus has never been guarded by a gate that quietly stopped running.

**THE FOURTH IS `failed++`, AND IT IS SITTING BETWEEN THE OTHER THREE.** It is the line that makes the summary a lie about kind rather than about count, and it is the line that collapses two exit codes into one. `gates.mjs`'s own header, forty lines above the `GATES` array, has said since the day it was written: *"A GATE THAT CANNOT RUN IS NOT A GATE THAT PASSED."* That rule governed the GATES. It did not govern the REPORT, which is the identical division of labour ADR-294 found one runner over.

### 2. The reproduction, by walking into it

**The premise was measured at source before it was ruled on, and the measurement is what narrowed the row.** The reporting loop was read first, and only then was a crash seeded.

**THE SEED IS ONE LINE INSIDE ONE EXISTING GATE'S BODY**, and that shape was chosen rather than appending a thirty-fourth gate. A new gate moves `GATES.length`, which is the `gate_count` generated span, which turns `CI-06g` red across `INDEX.md` and `STATE.md` with a hundred and eighty-two findings, and a transcript carrying that is a transcript about `CI-06g`. **The claim under test is that a crash on a thirty-three-gate run reads `32 of 33`, so the run has to have thirty-three gates in it.** `CI-06r` was seeded because it is mid-list, so the transcript shows PASS blocks above and below the crash:

```js
  run() {
    throw new Error('SEEDED CRASH: this gate body threw, so it measured nothing');
```

**EVERY EXIT CODE BELOW WAS READ WITHOUT A PIPE.** `node scripts/corpus/gates.mjs check > /dev/null 2>&1; echo $?` reads the runner's own status; `... | tail` reads `tail`'s, which is how a session records a false pass. The runner does not print the `EXIT=` line; the shell appended it, because the exit code is half of what this entry is about and a transcript that omitted it would be arguing for the other half only.

### 4. The ruling

**A gate whose body throws is an ERROR, which is a third outcome and not a heavier FAIL.**

| | Meaning | Counted in | Exit |
|---|---|---|---|
| **PASS** | The gate ran and found nothing | `passed` | `EXIT.OK`, 0 |
| **FAIL** | The gate ran and found something | `failed` | `EXIT.VIOLATED`, 1 |
| **ERROR** | The gate DID NOT RUN | `errored` | `EXIT.CRASHED`, 3 |
| usage | No such gate id, or no such subcommand | none | `EXIT.USAGE`, 2 |

**FOUR PROPERTIES, AND ONLY TWO OF THEM ARE CHANGES.**

**(1) THE DENOMINATOR DOES NOT MOVE, AND IT NEVER DID.** This is stated as a property rather than claimed as a repair. `selected.length` was already the total and the `catch` already left it alone. It is written down here because it is the one thing a reader arriving from ADR-294 will assume was broken, and because the tempting repair, subtracting the crashed gate to make the arithmetic true, is refused for the reason that file gives: it converts a broken runner into a smaller clean one, which is the same lie with better manners.

**(2) THE CRASH IS COUNTED APART FROM THE FAILURE. THIS IS THE CHANGE.** `errored` is its own counter. `32 passed, 0 failed, 1 errored, of 33 gate(s).` says what the run did. `32 of 33 gates pass` said what a reader would have to guess at.

**(3) THE PASS SENTENCE IS NOT PRINTED ON A RUN THAT CRASHED. THIS IS THE OTHER CHANGE, AND IT IS THE LOAD-BEARING ONE.** `N of N gates pass.` is a claim about a completed measurement, and the clause attached to it, *"A gate that fails is a corpus that is wrong, not a gate to relax"*, is a diagnosis. On a crashed run the measurement is incomplete and the diagnosis is aimed at the wrong file. **The exit code was already non-zero and the sentence was still the part a session quotes**, which is exactly why ADR-294 called this half load-bearing over there. It is more so here, because here the exit code was the only signal that ever disagreed with the prose.

**(4) A CRASH GETS ITS OWN EXIT CODE, AND IT DOMINATES.** `2` was already taken by usage, so a crash is `3`, and it is the same vocabulary `repo-invariants.mjs` gained in ADR-294. **Two runners guarding one tree should not disagree about what `3` means**, and ADR-294's own approval note raised the opposite ordering as a founder question: whether that file should have waited to speak three codes until this one moved. It did not wait, this one has now moved, and the vocabularies match. On a run producing both a crash and a violation, the crash wins: findings you can read are the smaller news when a gate went unread.

**A RUN WITH NO CRASH SAYS EXACTLY WHAT IT ALWAYS SAID.** Wording and exit code, on a clean run and on a violated one, including the forty-finding truncation and its `... and N more` tail. Section 3.3 and 3.4 are that claim on the real corpus and two suite cases are that claim held still.

**THE RUNNER STREAMS.** `runGates` takes an `emit` rather than calling `console.log`, so the suite reads the transcript this file actually prints instead of a second copy of the wording. **The gate BODIES still write their `note:` lines to `console.log` directly, and that is stated rather than repaired**: rerouting thirty-three gate bodies is a change to thirty-three gates, and this row is a change to a report.

**`GATES`, `EXIT` AND `runGates` ARE EXPORTED, AND `process.exit(main())` IS NOW GUARDED BY `invokedDirectly`.** A file that exits at module scope cannot be imported by anything, so the export and the guard arrive together, and the guard is itself a regression risk: it could silently stop the CLI from exiting. **A suite case reads both halves**, spawning the script for real and reading its status.

### 5. The suite, and the RED that was watched

Seven cases in [`gates-runner.test.ts`](../../scripts/corpus/test/gates-runner.test.ts), under `the corpus runner reports a crashed gate apart from a passed and a failed one`. Four assert the crashed half: the ERROR line and the three-way tally, the absent pass sentence, the fixed denominator, and the exit code with its dominance over a violation. Three assert the half that did not move: the wording and exit codes of a clean and a violated run asserted as whole transcripts, the forty-finding truncation, and the CLI still exiting.

**A REPORT CANNOT BE WATCHED FAILING BY SEEDING THE CORPUS, so the arithmetic it refuses was restored instead**: the single `failed` counter and the one summary line were put back inside `runGates`, and the block was run.

```text

 Test Files  1 failed (1)
      Tests  4 failed | 3 passed (7)
```

**Four of the seven went RED and three stayed green, which is the split the fix predicts.** The three are the unchanged half. A case going red there would mean this change had reached past the crashed branch of the report, which is the one thing it must not do.

### 6. `RI-36` is left free, and here is what was considered

The row reserved `RI-36` to this session if the work needed one. **It does not, and the three candidates are named rather than left as a gap somebody re-opens.**

**(1) "No runner in this tree counts a crash as a fail."** This is ADR-294 section 6's first candidate, and the reason it was refused there has now expired: it would have been RED ON LANDING because `gates.mjs` carried the defect and was out of fence. **It would be GREEN today.** It is still refused, for the reason that outlived the first one: it is a token-level rule over control flow, reading `catch` blocks for which counter they increment, and its first false positive on a runner that legitimately handles an error some other way gets it weakened. **The property is behavioural and both runners now assert it behaviourally, in a suite each, against a transcript.**

**(2) "Every exported runner returns a tally with an `errored` member."** A shape check on a return type, which TypeScript already reads for `repo-invariants.mjs` and which `scripts/corpus/tsconfig.json` now reads for this one. An invariant that duplicates the compiler is a second copy that can disagree with it.

**(3) "The gate registry and the runner's own report agree about how many gates there are."** True today and vacuous: both read `GATES.length`, so the check would compare a number to itself. The real property underneath it, that the count in the documents matches the count in the runner, is already `CI-06g` and the `gate_count` span, which is precisely what went red when a thirty-fourth gate was seeded in section 2.

**A NEW INVARIANT IS A GOOD ANSWER WHEN A PROPERTY IS TRUE OF THE TREE AND NOBODY IS WATCHING IT. Here the property is true of one function, and the function now has a suite.**

### 7. What this does not catch, stated rather than discovered later

**(1) A GATE THAT THROWS WHILE THE MODULE IS BEING EVALUATED.** Every gate in `GATES` is constructed before any gate runs, so a throw at module scope kills the process before the first `try`. Node exits non-zero with a stack trace and NO summary line, so it cannot be mistaken for a count, which is the property that matters. **`gates.mjs` has no imported gates at all**, so the module-boundary case ADR-294 asserts with `ri11` has no counterpart here; all thirty-three bodies are local to the file, and the `try` reads them the same way.

**(2) A GATE THAT RETURNS `[]` WITHOUT LOOKING.** The report can only tell a gate that threw from a gate that returned. A gate that silently reads nothing and reports PASS is invisible here, and it is what the sentinel throws inside the gate bodies exist for: `CI-06/derivable-counts` throws when it has examined zero cardinals, precisely so that reading nothing becomes a crash rather than a pass. **Nothing in this change reduces the need for more of them, and this change is what makes them report honestly when they fire.**

**(3) A CRASH IN `generate`, `allocation`, `list` OR `anchors`.** Those subcommands return their own codes and run outside `runGates`. `generate` in particular writes files, and a crash partway through it is not a reporting problem this entry can reach.

**(4) THE `note:` LINES ARE NOT ROUTED THROUGH `emit`.** A caller supplying its own `emit`, which today means the suite, collects the runner's lines and not the gate bodies' notes. Stated in the code and here, because a future reader building a report on top of `runGates` will otherwise find it out by losing output.

### 10. Approval

**Status `proposed`. The approval line below is UNSIGNED and merging is not signing.**

- **Decision:** `scripts/corpus/gates.mjs` reports three outcomes rather than two. A gate whose body throws is an **ERROR**: it is counted in its own tally apart from PASS and FAIL, it is **not subtracted from the denominator** (which it never was), it sets exit code **3** (`EXIT.CRASHED`, distinct from `1` for a violation and `2` for a usage error, and dominating a violation in the same run), and it **suppresses the `N of N gates pass.` sentence entirely**, together with the *"a corpus that is wrong"* clause attached to it, in favour of a three-way tally and a statement that the run did not measure the corpus. A run with no crash prints and exits exactly as before. `EXIT`, `runGates` and `GATES` are exported and `process.exit` is guarded, so the report can be read by a suite.
- **Consequences:** the corpus runner and the invariant runner now speak the same four exit codes, which closes the ordering question ADR-294's approval note raised. `RI-36` stays free. **`scripts/corpus` is a Vitest source root and a `tsc` project**, so a suite over any corpus script now has a home, which is a door this entry opens and does not walk through. Nothing in the tree reads exit code `3` today: `falsify-ci.mjs` compares `status === 0`, and `package.json` and the workflows let the shell decide, so the distinction is there for the next reader rather than for a caller that exists.

**What a founder read adds and this entry cannot.**

**THE FIRST THING TO DECIDE IS THE FENCE, AND IT IS NOT THE SAME QUESTION ADR-294 LEFT.** That row's open question was scheduling: a known defect left live in a more important file. This row's is placement. The row granted *"tests over it"* and excluded `packages/**`, and the tree made those two clauses incompatible in the one way nobody could have seen from the dispatch. **Section 8 records what was tried, why it failed, and what the three infrastructure lines buy.** A founder who would rather have had a stopped session and a re-dispatched row than three lines in `vitest.config.ts`, `package.json` and a new `tsconfig.json` should say so, because the same choice will present itself the next time a `scripts/` runner is owed a suite.

**THE SECOND IS WHETHER SUPPRESSING THE PASS SENTENCE IS RIGHT WHEN THE COUNT WAS NEVER WRONG.** This is a genuinely closer call here than in ADR-294. There, `29 of 30 invariants hold.` put an unmeasured check on the held side of the arithmetic. Here, `32 of 33 gates pass.` is arithmetically true: thirty-two gates did pass. **What is false is the clause beside it and the impression the pair leaves.** The cheaper alternative keeps the familiar line and appends a qualifier, and it keeps a number that travels between sessions stripped of its context, which is the failure this project has recorded repeatedly. **A founder who reads that trade differently would keep the line.** It is a judgement about how a number travels rather than about arithmetic.

**THE THIRD IS THE EXPORT SURFACE.** `GATES` is now exported, and nothing but the suite reads it. An exported array of thirty-three gate objects is an invitation for a future script to import the corpus runner and drive it, which may be exactly right and may be how a second caller starts depending on gate internals that were private for a year. **It could have stayed unexported at the cost of one suite case**, the one that reads whether importing the module runs the gates.

- **Approval:** `___________________________` (UNSIGNED. **Merging is not signing.**)
