## ADR-084: `ScopedDb` gets a real client, the scope is a DECLARED registry, and one consequence of ADR-008 is superseded  (2026-08-23, status: accepted)

**[ADR-008](ADR-008.md) is `accepted` and made this part of its own acceptance: *"The `scopedDb(identity)` wrapper and the ESLint ban on direct client imports (VG-4) are part of the acceptance, not a follow-up."* The ban shipped on 2026-08-13 and the wrapper did not. This entry lands it.**

**It also SUPERSEDES ONE CONSEQUENCE SENTENCE OF ADR-008, in section 1, rather than recording it as a finding.** That sentence is signed, this session makes it false, and an accepted entry does not move because a later entry noticed it.

- **Context:** [`packages/db/src/index.ts`](../../packages/db/src/index.ts) declared `ScopedDb` as an interface with ONE FIELD and said in its own header that *"NEITHER THE CLIENT NOR THE ACCESSOR EXISTS YET."* The workspace declared **zero runtime dependencies**. [Session 143](../sessions/2026-08-23-session-143.md) measured this as the shared precondition under all six of [P3](../plans/P3-ledger-billing-identity.md)'s stated contents.

### 1. What this supersedes in ADR-008, and what it does not

[ADR-008](ADR-008.md)'s Consequences, at [`ADR-008.md:5`](ADR-008.md), one line above the signature that closed it on 2026-08-13 at [`:6`](ADR-008.md), reads:

> Types are generated from the schema so drift is a compile error.

**That sentence is false on this tree, and this section retires it.** Drizzle generates types from the **TypeScript** schema. Here the SQL is the source and [`schema.ts`](../../packages/db/src/schema.ts) is the transcription, so **the generation runs the opposite way from the one the clause assumed**. Nothing emits types from the DDL, and drift is a **wrong answer at runtime** rather than a compile error.

**What replaces it**, in the same breath rather than as an open item:

> Where the SQL is the source and the TypeScript is the transcription, drift is caught by a MECHANICAL ASSERTION over both, not by the compiler. [`test/scoped-db.test.ts`](../../packages/db/test/scoped-db.test.ts) reads the seven `CREATE TABLE` bodies out of [`migrations/`](../../packages/db/migrations/) and asserts column-name-set agreement with the declarations, and re-derives on every run that no later migration changes a column on any of the seven.

**Reading the SQL to assert against it is not generating a schema from it.** Nothing is emitted and nothing is written back.

**What is NOT superseded**, stated so the entry does not read wider than it is: ADR-008's choice of Drizzle stands; its *"migrations are plain SQL files that can be reviewed line by line"* consequence stands and this entry depends on it; and the `scopedDb` + VG-4 acceptance clause stands and is what this entry discharges. **Exactly one consequence sentence moves.**

**The precedent for amending inside a signed entry is [session 95 / PR #149](../sessions/2026-08-20-session-95.md)**, which signed fourteen ADRs and, rather than ratifying a live hole, **declined ADR-062** because `OQ-062-01` stood and wrote [ADR-075](ADR-075.md) to shut it. **The precedent for the DEFECT is session 149 / PR #190**, which signed ADR-077 through ADR-083: rulings that were live before they were signed. A signed sentence the tree refutes is the same defect pointing the other way, and recording it in a consequences list would have added an eighth.

**The closure figure is 14 and not 6.** Six is `pg`'s DIRECT dependency count, and a supply-chain control counts the closure. The narrower number was in this session's own plan and the lockfile refuted it.

**`onlyBuiltDependencies: []` stays satisfiable**: `pnpm install` ignored no build script.

### 3. Scoping is by construction, and totality is a compile error

Four classes, partitioning one question -- **how does a row reach an identity?**

| Class | Meaning | Members |
|---|---|---|
| `root` | the row IS the identity | `identities` |
| `owned` | an identity column on the row | `accounts`, `ledger_accounts` (nullable) |
| `derived` | one declared FK hop, or an `EXISTS` semi-join | `ledger_entries`, `ledger_transactions` |
| `firm` | belongs to no identity; the scoped accessor **refuses** it | `treasury_balances`, `liability_snapshots` |

`SCOPE_RULES` is declared against a mapped type over `TableKey`, so **a table added to `schema.ts` without a rule does not compile** and a rule naming a table that does not exist does not compile either.

**SEVEN OF 111, REPORTED AS SEVEN OF 111.** The other 104 are unreachable through either accessor: naming one is a compile error at the call site rather than an unscoped read at runtime.

**`ledger_accounts` is `owned` with a NULLABLE column, and that is not a weaker class.** Its `scope` is CHECKed to `('firm','identity')` and the table's own constraint ties it to `identity_id`. Filtering `identity_id = $1` excludes the firm rows **without a second predicate**, because SQL NULL never equals anything. An added `IS NOT NULL` would look careful and assert nothing.

**`ledger_transactions` needs a semi-join and the reason is arithmetic.** It carries no identity column at all and reaches one only through its entries, of which it has more than one: double-entry means a trader leg and a firm leg on the same transaction, so a plain join returns the transaction **once per matching entry**.

### 4. The registry is DECLARED and never derived

A mechanical "walk the FK to something carrying `identity_id`" derivation returns **25** tables and is wrong on at least three:

| Table | What derivation would do |
|---|---|
| `treasury_balances.recorded_by -> users` | scopes **the firm's treasury** to whichever admin typed the attestation |
| `impersonation_sessions.admin_user_id` | reaches the **admin's** identity, not the subject's |
| `sessions.device_fingerprint_id -> identity_signals` | reaches **whoever shares a device** |

**Auto-derivation here is not conservative, it is confidently wrong**: each produces a scoped query that RETURNS ROWS, for the wrong identity, with no error anywhere.

### 5. The legitimate unscoped reader is named, branded and closed

`systemDb(reason)` takes a two-member vocabulary: `'nightly-batch'` (Appendix B.5 partitions across every account, and `ports.ts` declares `accountsWithStoredState()` *"for EVERY account that has ever existed"*) and `'operator-console'` (the admin liability dashboard; `liability_snapshots` is EC-095's three named numbers and is firm by construction).

**"Forgot to scope" becomes "wrote the word system"**, which is a diff a reviewer reads.

### 6. The two refusals, watched failing to compile

Both are at **`CI-01`** in [`falsify-ci.mjs`](../../scripts/ci/falsify-ci.mjs) and not in the vitest suite, on the precedent that file already states about the engine's `R-17`: vitest *"runs transpiled code and a type error is simply gone by then."* Case objects go **24 to 26** and `CI-01` case objects **10 to 12**; the harness's own tally, which counts gates rather than case objects, reports **66 of 69 watched failing on the violation aimed at them**. The three exceptions are the `CI-05` cases whose scanners are not installed in this container -- `gitleaks`, `semgrep`, `syft`/`grype` -- and they are `ERROR` on the baseline too, unchanged by this entry. **`pnpm run falsify:ci` is deliberately not part of `pnpm run verify`** (`package.json` says so in its own `//falsify:ci` key) and is reported separately.

```
src/__falsify__-firm.ts: error TS2345: Argument of type '"treasuryBalances"'
  is not assignable to parameter of type 'ScopedTableKey'.

src/__falsify__-brand.ts: error TS2322: Type '{ readonly __brand: "SystemDb";
  readonly reason: SystemReason; readonly identityId: IdentityId; ... }'
  is not assignable to type 'ScopedDb'.
    Types of property '__brand' are incompatible.
      Type '"SystemDb"' is not assignable to type '"ScopedDb"'.
```

**The second seed carries `identityId` deliberately.** Without it TypeScript reports *"Property 'identityId' is missing"*, which passes a naive needle while proving the **wrong thing**: that the shapes differ, not that the brands do. With it present the seed emits **exactly one** error and the needle demands `__brand`, so the case fails if the brand ever stops being what refuses.

### 7. The suite was asserting the code against itself, and a seeded violation survived

**Recorded because it is the most useful thing this session found.** The first version of the suite passed **all 22 assertions** against a seed seeding `accounts` scoped by **`user_id`** instead of `identity_id`. The render test took its expected column FROM THE RULE, so a wrong rule and a wrong expectation agreed with each other.

**A user is a login and an identity is the person** ([ADR-041](ADR-041.md) is why they are two columns), so that seed returns a different set of rows, silently, for every trader whose identity has more than one login. **It is the exact failure ADR-008 scoped the wrapper to bound, and the suite could not see it.**

Four checks now take their expectation from the **migrations** instead: an `owned` column must be declared `REFERENCES identities(id)`; `root` must be `identities` itself; a `derived` rule must name an FK the DDL declares in one direction or the other; and no `firm` table may carry a column reaching `identities`. The failure message quotes the database's own declaration:

```
accounts.user_id must reference identities(id), and its DDL is:
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE RESTRICT
```

**`traversal` is checked rather than trusted** for the same reason: every `hop` must name the via table's primary key and every `semi-join` must not, so a rule mislabelled as a hop is a test failure rather than a comment nobody reads.

### 8. The absence the drift assertion rests on, measured WIDE and re-run at write time

An absence is the one kind of claim a wider grep refutes, and this session's own plan stated it too narrowly: it claimed no `ADD COLUMN` on the seven. **Two of the seven ARE named by a later `ALTER TABLE`.**

```
packages/db/migrations/0009_ledger.sql:105:ALTER TABLE ledger_transactions
packages/db/migrations/0010_payouts.sql:304:ALTER TABLE accounts
--- DROP TABLE / DROP COLUMN / RENAME anywhere in the directory ---
(none)
--- ALTER COLUMN anywhere, with its table ---
0029_phone_identity_and_auth.sql:527:  ALTER COLUMN email_normalized DROP NOT NULL;
0032_trading_calendar_holidays_coverage_revisions.sql:107:ALTER TABLE trading_calendar ALTER COLUMN session_open_at DROP NOT NULL;
0032_trading_calendar_holidays_coverage_revisions.sql:108:ALTER TABLE trading_calendar ALTER COLUMN session_close_at DROP NOT NULL;
```

Both are **`ADD CONSTRAINT`** and neither changes a column: `0009:105` adds `ledger_transactions_no_self_reversal`, and `0010:304` adds a foreign key on `terminal_settlement_id`, **a column `0007` already declared**. The three `ALTER COLUMN` statements are on `otp_challenges` and `trading_calendar`, none of the seven. Each of the seven has exactly one `CREATE TABLE`.

**The suite re-derives this on every run** -- `ADD`/`DROP`/`ALTER COLUMN` and `RENAME`, not `ADD COLUMN` textually -- so the day one lands the check fails rather than silently reading a stale `CREATE`. **Five of the seven are declared in `0009_ledger.sql`; `identities` is `0002` and `accounts` is `0007`.**

### 9. Consequences

- **`client()` is not re-exported.** Outside `packages/db`, reaching the database and choosing a scope are the same act. Exporting it would leave the ESLint rule as the only thing between an app and an unscoped query, and a lint rule is a control an `eslint-disable` comment routes around.
- **`pg.Pool` needs a long-lived process and TCP.** An HTTP or serverless deployment of any surface is **foreclosed** (Neon's HTTP driver, Cloudflare Workers). Consistent with [ADR-083](ADR-083.md)'s long-lived Railway service, and expensive the day that moves.
- **Every new table is a diff on `scope.ts`, forever.** That is the cost and it is the point.
- **A third class, `reference`, is named and not declared.** A class with no member asserts nothing and no caller exists to decide it.
- **`drizzle-kit generate` is foreclosed permanently**, being the inverse of this flow. It is already banned by `no-raw-db-client`.
- **The pool is lazy**, so importing `@merit/db` opens no socket. The corpus gates, the golden loader and every unit suite import it for types.
