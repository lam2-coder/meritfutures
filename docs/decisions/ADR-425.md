### 12. OPEN QUESTION for the founder: the retirement needs a ruling no row can supply

**THIS SECTION IS THE ROW'S OWED ITEM AND IT IS ADDRESSED TO THE FOUNDER.** It is stated here rather than waited on, and nothing in this entry depends on an answer.

**THE MEASURED SITUATION, IN FOUR FACTS DERIVED ABOVE.**

1. **The delete-breaking population of `apps/api/src/events.ts` is 51 files**, not the 5 three rows priced and not the 21 [ADR-422](ADR-422.md) derived. Sections 3 and 6.
2. **Deleting it takes `gates.mjs check` to 32 of 33, with `CI-06a` reporting 72 findings.** Section 5.
3. **56 of those 72 breaking links sit in 26 DATED RECORDS, and ADR-386 forbids repairing them.** Section 6.
4. **`gates.mjs generate` repairs none of it**, so there is no generated-span route around it. Section 5.

**THE RULING THIS ROW ASKED FOR HAS BEEN GIVEN, AND IT CLOSES THE HALF THIS ROW COULD NOT.** The dispatcher ruled that a dated record's markdown link may **NOT** be repaired when its target is deleted, on [ADR-386](ADR-386.md) at `:169` and at `:178`, both read at primary source on `bfd6c400` and both quoted below rather than paraphrased:

> `:169` **"THE PROPERTY IS THAT NO CITED LINE MOVES. Where one must, every pointer in a LIVE file is repaired and listed, and every pointer in a DATED RECORD is NAMED, because that one cannot be repaired by a commit."**

> `:178` a signed or dated record cites a line, and `RI-15`'s miss (4) and `RI-16`'s exclusion 1 both rule that repairing that pointer **"would rewrite the record to say something it did not say."**

**THE GROUND OF THE RULING IS DATEDNESS AND NOT POINTER SYNTAX**, so it reaches a relative markdown link exactly as it reaches a line-number citation: repairing either makes the record say something it did not say on its date. **Stated plainly so a later reader is not misled: ADR-386's own sentences are written about CITED LINES, and extending them to a link TARGET is the ruling rather than a quotation from it.** The 56 are therefore NAMED and left alone, which is what this row did before the ruling arrived, and the entry is unchanged by it.

**SO WHAT IS LEFT IS ONE QUESTION AND ONLY A FOUNDER CAN ANSWER IT.**

> **Retiring `apps/api/src/events.ts` now requires EITHER a founder ruling that relaxes the dated-record rule for a deleted target, OR an authorised arrangement that keeps the path resolvable without the module (a tombstone). NO ROW CAN SUPPLY EITHER.** A row that relaxed the rule would be widening a fence to fit the operation it wanted; a row that invented a tombstone would be inventing an arrangement to get a gate green, which is the shape of weakening a gate to pass it. **The third answer, which costs nothing, is that the module STANDS**: it is 88 lines, it breaks nothing, and no gate is red while it is there.

**AND THE QUESTION IS NOT ABOUT THIS MODULE.** Any file this corpus has ever linked to from a dated record is now known to be undeletable on the same grounds. This module is simply the first one anybody tried to delete after `CI-06a` and the dated-record rule both existed. **That generality is the reason it is worth a founder's time and the reason it is not worth another row's.**
