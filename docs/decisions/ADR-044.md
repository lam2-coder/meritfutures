## ADR-044: The AI and LLM policy. A permission boundary that adds no scope, and a narration boundary on the trader surface  (2026-08-16, status: accepted)

- **Context:** A grep for `llm`, `genai`, `machine learning`, `generative` and
  `ml` across every document in `docs/` returns **zero hits**. The corpus is
  roughly forty documents and thirty thousand lines and it says nothing at all
  about whether Merit may use a language model in its own product. The only
  place the subject appears is the constitution, at
  [E3](../../MERIT_BUILD_MASTER_PROMPT.md), in a single bullet that decided the
  prompt-injection posture "**so it's never improvised later**" and named exactly
  two future features: a support assistant in M10 and a risk-analysis copilot in
  M7.

  **That silence is the problem this ADR exists to end, and it is a dangerous
  kind of silence.** [STATE](../STATE.md)'s operational definition of FREEZE is
  that a behavior not in the corpus is not in scope and a behavior in the corpus
  is a commitment. Under that rule the corpus currently prohibits every AI
  feature by omission, which is not what anyone decided, and the first session
  that wants one has no ruling to read and will improvise. E3 anticipated this
  exact failure and pre-empted it for one narrow case.

  **The founder's brief permitted four feature classes and prohibited three.**
  Reviewing it against the primary sources found four defects in the brief
  itself, and all four are ruled below rather than inherited. The review is
  recorded because three of the four are the kind of error that reads as correct.

- **Decision:**

  ### 1. THIS ADR ADDS NO SCOPE. IT IS A PERMISSION BOUNDARY.

  **Nothing below is a commitment to build anything.** Each permitted class still
  requires its own amendment to the module that would own it, costed and gated
  like any other scope, before one line of it exists. This ADR rules what would
  be *permissible* if proposed, and it rules what is refused outright.

  The distinction is load bearing and it is why this section is first. Five
  frozen module plans (M06, M07, M10, M13, M15) describe no AI behavior of any
  kind today. An ADR that merely listed four permitted features would, under
  FREEZE's own reading, convert them into four commitments in five frozen
  documents that nobody has costed, and the next reader would be correct to treat
  them that way. **Permitting is not specifying.**

  ### 2. The narration boundary, which is the whole trader-surface ruling

  **A model may narrate, order, prioritize and explain numbers the deterministic
  system has already computed. A model may not derive a number.** Arithmetic is
  not a permitted output. Where a figure appears in model output it arrived as
  model input, computed by the engine, and it is passed through unaltered.

  This is not a stylistic preference and it is not the same rule as "label it
  advisory". [M13](../plans/M13-trader-analytics-journal.md) is governed by one
  sentence, and it is the sentence the brief's item (a) walked into:

  > every number here is a different view of the same closed-session facts the
  > engine used, and the moment it becomes a second computation of anything the
  > engine also computes, Merit has two rulebooks.

  M13 names its own failure mode one line later, and the failure is not a wrong
  label. It is **a trader who believes something slightly different from what the
  engine will enforce, and then meets the engine on the day it matters.** M13
  cites Topstep's real complaint theme as the precedent. A model that computes is
  a second rulebook whatever it is labeled, and a nondeterministic one, so the
  label cannot carry the weight the brief asked it to carry.

  **The narration boundary is checkable and "advisory" is not**, which is the
  argument for it over the alternative. A golden fixture can pin the exact set of
  values handed to the model and assert that every numeral in the output appears
  in that set. A reviewer can read a prompt template and see whether it asks for a
  calculation. Neither is possible against a labeling rule.

  **The known weakness, stated rather than discovered later:** a model asked to
  explain a number tends to restate arithmetic, and "you are 3 days from the
  minimum" is a derivation dressed as narration. The boundary does not make that
  impossible. It makes it a **finding** rather than a design.

  ### 3. Permitted classes

  | | Class | Conditions |
  |---|---|---|
  | **(a)** | **[M13](../plans/M13-trader-analytics-journal.md) trader-facing performance narration** over the trader's own fills | **The narration boundary, section 2.** Labeled advisory. Every figure is engine-computed and passed through. **Not** a rules statement, and the surface says so at the point of use rather than in a footnote |
  | **(b)** | **Support assistant** ([M10](../plans/M10-integrations.md), [M15](../plans/M15-discord-integration.md)), read-only over published documentation **and the trader's own live gate state** | Never tool-capable. Untrusted input renders as data and never executes as instruction. **Requires the threat-model pass named in section 4, because this amends E3 rather than following it** |
  | **(c)** | **[M06](../plans/M06-admin-ops-console.md) and [M07](../plans/M07-risk-abuse.md) investigation assistance.** Model-drafted cluster summaries and evidence narratives | **For human review, never for action.** The detectors themselves stay deterministic, auditable and replayable, unchanged by this ADR. A model output is never an input to a detector, a score, or an enforcement decision |
  | **(d)** | **Internal ops drafting.** Incident comms, daily liability digests, support triage | Internal surfaces only. A digest is a reading aid over a computed figure, never the source of one. Anything leaving the building is class (e) below and is reviewed |

  ### 4. (b) amends E3. It does not follow it.

  The brief cited E3 as authority for the support assistant. **E3 does not
  authorize it.** The constitution reads:

  > support-bot scope is read-only over **published docs** *until a threat-model
  > pass says otherwise*

  The trader's live gate state is internal, per-identity data and is not published
  documentation. Item (b) is therefore the "otherwise", and **E3 already named its
  price: a threat-model pass.** Citing E3 for it would have been a decision
  wearing a confirmation's clothes, which is the specific thing this corpus's
  review layer exists to catch.

  **This ADR amends E3** to permit per-identity gate state in the support
  assistant's read scope, **conditional on that threat-model pass landing before
  the feature is built**, not before it is designed. The pass is a named
  precondition on the M10 and M15 amendments, not a footnote. Everything else in
  E3's bullet stands unchanged and unweakened: not tool-capable, no access to
  internal actions, outputs render as data.

  ### 5. Prohibited without a further ADR

  1. **Any model involvement in an eligibility, breach, payout, enforcement or
     ledger decision.** Not as an input, not as a pre-check, not as an
     optimization, not as a ranking that a human then rubber-stamps.
     Determinism and replayability are not negotiable and
     [ADR-002](ADR-002.md) is why.
  2. **Model-decided enforcement of any kind**, including any action taken
     automatically from a model output.
  3. **Unreviewed AI-generated copy on a published, static surface**: marketing,
     ToS, rules text, statistic definitions, and anything
     [M12](../plans/M12-transparency-platform.md) publishes. **Scoped
     deliberately.** The brief's wording was "unreviewed AI-generated
     user-facing copy", which as written prohibited class (a) three lines after
     permitting it, because per-trader runtime narration can never be
     pre-reviewed by construction. Static surfaces are reviewed. Class (a) is
     controlled by the narration boundary instead, and the two mechanisms are
     different because the two surfaces are.

  ### 6. Degradation, and why ADR-020's pattern does not transfer whole

  Every permitted class is an advisory layer over authoritative deterministic
  state, in [ADR-020](ADR-020.md)'s shape. **The analogy breaks in one place and
  the break is the important part.**

  ADR-020's indicative tier is nondeterministic in *freshness* only. It is
  reproducible, and its degradation story is specific: feed loss falls back to
  the last closed session with the label changing to match, "because a live
  number that silently freezes is worse than an honest stale one". **There is
  always a correct thing to fall back to.**

  A model layer has no stale-but-correct fallback. There is no cached previous
  answer that is still true. So graceful degradation here can only mean one
  thing, and it is a stronger requirement than ADR-020's:

  > **The deterministic surface underneath is complete and usable on its own, and
  > the model layer is strictly additive and removable.** Deleting it degrades the
  > product and breaks no flow. If a surface cannot be shipped with the model
  > layer absent, the surface is misdesigned and the feature is refused.

  This is stated in those words because "graceful degradation required" gets
  built as a spinner.

  ### 7. ML fraud scoring stays deferred

  Post-launch, review-queue signal only, bought and not built, consistent with
  [ADR-023](ADR-023.md). It never auto-enforces, which is section 5 item 2, and
  it never becomes an input to [ADR-022](ADR-022.md)'s scored graph, which is
  section 3 class (c). A purchased score that feeds a deterministic detector is a
  vendor dependency in the money path and needs its own ADR.

  ### 8. `CI-06o`, because prohibition 1 must be mechanical

  **A rule that says "no model on the money path" and is enforced by people
  remembering it is a control that exists, stays valid, and enforces nothing**,
  which is this project's named failure mode. `CI-06o` is claimed in
  [ALLOCATION](ALLOCATION.md) and specified here:

  > No module that resolves, directly or transitively, from `packages/rules-engine`
  > or from the payout, ledger or auth paths may import a model SDK or reach a
  > model endpoint. The banned-identifier list is declared in one place, and a
  > path added to the money-path set without being added to the gate's scope is
  > itself a finding.

  **It is unwritten today and this ADR says so rather than implying otherwise.**
  Until it runs and has been watched failing on a seeded violation, prohibition 1
  is prose. Three mechanisms already exist to build it against: `types: []` on
  `packages/rules-engine` removes ambient globals at compile time, the
  `merit/engine-purity` lint rule reads the source, and `RI-01` reads the
  manifest. The gate is cheapest now, while the payout, ledger and auth packages
  do not yet exist and it is close to vacuous, which is the same argument
  [ADR-042](ADR-042.md) made for its SQL shape check.

- **Alternatives considered:**

  - **Say nothing and rule case by case.** Rejected on E3's own reasoning,
    written for this exact subject: decide it now so it is never improvised
    later. Silence under FREEZE is not neutral, it reads as prohibition, and a
    session that wants a feature will resolve the ambiguity by guessing.
  - **Prohibit all LLM use in the product.** Rejected. It costs a real retention
    surface and a real support-cost reduction, and the risk is separable by class
    rather than uniform. The prohibition that matters is narrow and is section 5.
  - **Permit (a) under an "advisory" label with no narration boundary**, as
    briefed. **Rejected on M13's governing sentence**, quoted in section 2. The
    label addresses a misreading and M13's failure mode is a misbelief. Two
    rulebooks stay two rulebooks when one of them is labeled.
  - **Treat this ADR as scope**, listing the four features as committed. Rejected
    in section 1. It would add four uncosted features to five frozen module plans
    by implication, and FREEZE's reading would make them commitments.
  - **Cite E3 as authorization for (b)** and move on. Rejected in section 4. It
    is a widening of a constitution clause and the honest form says so and pays
    E3's stated price.
  - **A model-output review queue instead of the narration boundary**, where a
    human approves each generated insight. Rejected: it does not scale to a
    per-trader surface, and it converts a product feature into a support cost
    that grows with the funded book.

- **Consequences:**

  - **The constitution is amended at E3**, for the first time on this subject.
    The amendment is narrow (per-identity gate state joins the support
    assistant's read scope) and it carries E3's own stated condition.
  - **Five module plans gain a named permission and no scope.** M06, M07, M10,
    M13 and M15 each need an amendment ADR before any of this is built. The
    amendment is where the cost, latency and failure-mode analysis per feature
    lands, because that analysis is feature-specific and writing it here would be
    speculative for four features that may never be proposed.
  - **`CI-06o` is claimed and unwritten**, and prohibition 1 is unenforced until
    it runs. This is the one thing in this ADR that is a promise rather than a
    control, and it is named in section 8 rather than left for a reader to
    discover.
  - **The narration boundary needs a fixture shape that does not exist.** Pinning
    the value set handed to a model and asserting every numeral in the output
    appears in it is a golden-loader capability, and the loader is at three
    fixtures with a stubbed engine. It arrives with the M13 amendment, not before.
  - **Nothing in P1 or P2 changes.** No migration, no schema, no engine behavior,
    no gate that runs today. This ADR touches the corpus and the constitution and
    nothing else.

- **Founder ruling (2026-08-16): ADOPTED**, with all four review findings
  accepted as ruled above.
