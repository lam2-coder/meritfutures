## ADR-043: The append-only registries become directory-per-entry  (2026-08-15, status: accepted)

- **Context:** Four documents in the corpus are append-only registries that every
  branch writes to: `DECISIONS.md`, `SESSION_LOG.md`, `EDGE_CASES.md` and
  `architecture/DATA_MODEL.md`. They are the collision surface. Two sessions that
  touch nothing else in common still both append to `DECISIONS.md`, and the merge
  is a conflict in a frozen document every time. `DATA_MODEL` is the second worst
  at 96 `### <table>` sections. This is not a hypothetical: [ADR-034](ADR-034.md)
  exists because two branches took the same ADR number, and [ADR-036](ADR-036.md)
  exists because the same race was found on migration numbers, where it is
  unrecoverable.

  **Changing the structure of a frozen document requires an ADR rather than a
  commit**, which is why this exists.

- **Decision:** Each registry becomes a directory with one file per entry.
  `DECISIONS.md` becomes `docs/decisions/`, and the remaining three follow in
  their own pull requests under this ruling.

  **THE SPLIT IS NOT UNIFORM, AND THE RULE IS: SPLIT WHAT IS APPENDED TO, KEEP
  TOGETHER WHAT IS CLOSED, AND NEVER SPLIT A TABLE A GATE READS AS A TABLE.**

  | Thing | Unit | Why |
  |---|---|---|
  | **ADRs** | One file each, `ADR-nnn.md` | The live registry. This is the collision |
  | **Gate closures** | One file per closure, its rulings kept inside | A closed gate record is not appended to after the gate closes, so it carries no collision risk, and nine rulings that only mean "what the Wave 3 batch 1 gate decided" are not nine documents |
  | **The three allocation tables** | One file, `ALLOCATION.md` | `CI-06f` and `CI-06h` read them **as tables**, through one shared parser over the first cell of each row. A table split into a file per row is not a table |
  | **`GOLDEN_SCENARIOS`** | One file per section | Ruled below |
  | **`INDEX`, `STATE`, `DELTA_MANIFEST`** | Unchanged | Generated, living, and read as a table respectively |

  **Filenames are the identifier verbatim**: `ADR-039.md`, not `ADR-0039.md`. The
  corpus cites `ADR-039` and every gate parses `\d{3}`, so a four-digit filename
  would be a permanent mismatch between what a document says and what a link must
  spell, across roughly 1,100 links. The headroom past 999 is not worth a pad step
  in every hand-written link.

  **An entry file is a FRAGMENT, not a corpus document.** It carries no
  frontmatter and gets no `INDEX.md` row. Each registry directory has a `README.md`
  that IS a corpus document, carries the status for the set, and lists every entry.
  Without this, splitting four registries would take the corpus from 72 documents
  to roughly 340, take `INDEX.md` from 85 rows to about 400, and stop it being a
  map a person can read.

  **That exemption is paid for rather than taken.** `CI-06c` currently guarantees
  "if a thing is not in INDEX.md, it does not exist", and exempting 340 files from
  it would be weakening a gate to pass it, which the constitution forbids. So
  **`CI-06n`, the registry-index gate**, asserts in both directions that every
  entry file has a row in its registry README and every README row resolves to a
  file. The guarantee becomes transitive rather than lost: INDEX carries the
  README, the README carries the entry.

- **The `GOLDEN_SCENARIOS` ruling, and why it differs:** Per section, not per
  entry. `GOLDEN_SCENARIOS` holds 257 identifiers in 301 **table rows** across 33
  sections. **A row is not a document.** Per-entry would produce 257 files whose
  entire content is one table row, and the batteries (`GS-030` to `GS-051`, the
  Appendix B4 set; `GS-246` to `GS-255`, the D0 attack set) only mean anything
  read together. Per section gives 30 entry files plus 3 prose sections, splits on
  the boundary at which sessions actually append, and keeps each battery whole.
  **The same reasoning applies inside `EDGE_CASES`**: its 119 block-form entries
  split per entry, and its 22-row Appendix B4 battery stays one file, because that
  battery is the same shape as a `GOLDEN_SCENARIOS` section.

- **Alternatives considered:**
  - **Leave them single and rely on merge discipline** (rejected: the discipline
    has already failed twice on numbered registries, and both times the remedy was
    a gate rather than more care).
  - **Four-digit filenames** (rejected above: identifier mismatch across every
    link, for headroom the corpus will not reach).
  - **Entry files as full corpus documents** (rejected: 340 frontmatter blocks and
    a 400-row INDEX, which destroys the artifact whose whole value is being
    readable).
  - **Frontmatter but no INDEX row** (rejected: that is the weakening, with
    nothing put in its place. `CI-06n` is the thing put in its place).
  - **A `RULING-nnn` namespace for the standing rulings** (rejected: a fourth
    numbered registry, needing its own allocation table and its own gate, invented
    to hold records that already have stable names. They are named by their own
    heading slug, so the rewrite from `DECISIONS.md#<slug>` to a path is derivable
    rather than a table somebody maintains).

- **Consequences:**
  - Every gate reading these documents by path needs a new reader, and **the brief
    named six of them; there are nine.** `CI-06b` and `CI-06c` change scope,
    `CI-06h` reads the migration allocation table out of `DECISIONS.md`, and
    `CI-06i` reads `DATA_MODEL.md` for `### <table>` sections. A gate whose input
    path no longer exists must ERROR rather than find nothing and pass, which is
    rule 2 of `gates.mjs` and is now asserted per gate by `falsify.mjs`.
  - **The split is mechanical and the script is kept**, because the map it derives
    is the input to the link rewriter, and a rewriter driven by a hand-typed map is
    the failure this change exists to end.
  - Content conservation is asserted rather than assumed: the splitter is checked
    by confirming every non-blank line of the source appears in exactly one output
    file.
  - **`CI-06n` is claimed in the CI gate identifier allocation table, and the
    first letter this session reached for was `k`.** `k`, `l` and `m` are reserved
    by FOLD-01, FOLD-02 and S-E, all three unmerged, so `k` was taken and reading
    the table is what caught it. That is the third claim this table has caught in
    one week, on the session whose whole subject is collision, and it is recorded
    here rather than quietly corrected because **the table working is the evidence
    that the table should exist**.
