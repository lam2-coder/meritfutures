## ADR-130: A derivable count can belong to ONE DOCUMENT, and the count vocabulary could not say so  (2026-08-27, status: proposed)

**`CI-06/derivable-counts` is the enforcement half of [ADR-034](ADR-034.md), and it was silent on the one site the register had been holding open for it.** `OI-24` has named M06 section 2's hand-maintained delta count, and named its remedy, since session 95. The gate landed in [#309](https://github.com/lam2-coder/meritfutures/pull/309). The count stayed unpoliced, at every value that sentence can hold, and the remedy the gate itself names for an unpoliced population could not be applied to it. This entry rules why, and narrows the vocabulary's addressing so a per-document population is expressible.

- **Origin:** `OI-24`, session **242**. The number was **RESERVED BEFORE DISPATCH and CONDITIONAL** ([ALLOCATION](ALLOCATION.md)): the condition was *"if the gate does NOT flag a prose count you can see with your own eyes"*, and it fired. **Not money path.** No migration, no schema, no engine; the change is one predicate in one gate body and one query in `SPAN_QUERIES`.

### 1. Context: the site the gate was built for, and did not reach

M06 section 2 opened with a count of its own delta table. It read *"Five deltas"*, session 89 corrected it to *"Six deltas"*, and `SD-M6-10` made it wrong again three sessions later. Session 95 left it wrong **on purpose** and filed `OI-24`, on the argument that a count corrected twice in three sessions is proof it cannot be hand-maintained rather than an argument to maintain it harder. It stood at *"Seven deltas"* against a table whose rows the generator now derives, and the sentence and the table disagreed.

`CI-06/derivable-counts` exists to catch exactly this. It did not, and the reason is not a bug in its reader.

### 2. The finding, in three measurements

Every figure below was taken on this branch with the runner as it stood before this entry.

| Measurement | Result |
|---|---|
| The gate over the tree, with the sentence reading *"Seven deltas"* | `0 in scope`. Silent |
| The gate over the tree with the span removed and the count **retyped in prose at the value the table actually holds** | `0 in scope`. **Still silent** |
| The gate over the tree with the scoped entry this entry rules, same retyped prose | One finding, naming the file, the line, the query and the remedy |

**The second row is the finding.** A gate whose stated purpose is to name a derivable count *"while it is still RIGHT, which is the only moment a span can be installed without anyone having to decide what the truth is"* was silent on the site at the moment it was right. The declared false negative it accepts, *"a count that has already drifted is invisible here"*, does not cover it: this site is invisible **at every value**, drifted or not.

### 3. Why: the vocabulary addresses a NOUN, and a noun is corpus-wide

`DERIVABLE_NOUNS` binds one noun to one scalar query over the whole tree. `deltas` is bound to `manifest_changes`, the corpus-wide figure read from [`DELTA_MANIFEST`](../../packages/db/DELTA_MANIFEST.md). M06 section 2 states the size of **its own** delta table. Both are derivable, both are called deltas, and only one of them can be the value the recogniser anchors on.

The gate names the remedy for a population it does not carry: *"a derivable population with no entry is unpoliced, and the remedy is another argued entry rather than a looser match."* **That remedy could not be applied here**, and the runner already says why, one entry up, about a different pair: *"two vocabulary entries for one noun would make the first shadow the second forever."* The vocabulary is scanned in declaration order and the first matching noun wins. An argued entry for M06's deltas, added the only way the vocabulary allowed, would have been unreachable.

So the site was not missed and it was not deferred. **It was unreachable by construction, and the construction was invisible because the gate's remedy sentence promised it was reachable.**

### 4. The sharpest evidence, and it is in the gate's own rationale

The rationale block measures three candidate recognisers and rejects the loosest with a list of specimens:

> almost every one of the 206 is a LOCAL SUBSET and not a population: `1 gate`, `2 gate`, `Six deltas`, `three tables`

**`Six deltas` is M06 section 2's own sentence, in the form session 89 corrected it to.** The canonical instance of `ADR-034`'s defect, open in the register with its remedy named, appears in the rationale of the gate enforcing `ADR-034` as a specimen of the noise a rejected rule would produce.

**That reading was right about the RULE and wrong about the SITE, and the two are separable.** The ANY-VALUE rule is correctly rejected: 206 findings on a clean tree is a gate switched off within a week. What does not follow is that a per-document count is not a population. `Six deltas` is a population, of a table, in a document, with a query that derives it. It reads like a local subset only because the vocabulary had no way to say **which** document a population belongs to, so every population it could express was corpus-wide by construction, and anything narrower had to look like a subset.

### 5. Decision

1. **A vocabulary entry may carry a `file` predicate**, and an entry that carries one is asserted only over the documents it matches. An entry with no predicate is corpus-wide, which is every entry the vocabulary carried before this ruling. The predicate **narrows and never widens**: a scoped entry matches fewer documents than the unscoped form, never more.
2. **A scoped entry is declared BEFORE any global entry it shares a noun with.** First-match-wins is the vocabulary's existing rule and this entry does not change it; declaration order is how a scoped entry escapes the shadow, and it is stated here rather than left for a reader to infer from the array.
3. **`m06_delta_count` is the first scoped entry**, bound to a query that counts M06 section 2's rows by first cell, which is `manifest_changes`' own form rather than a second way of reading a delta table.
4. **This does not reopen the value-anchoring ruling.** The recogniser still requires the cardinal to equal what its bound query returns. The change is which query a site is compared against, not whether the comparison is made.

### 6. What this does not do, stated rather than implied

- **It does not police the other derivable counts in M06.** Section 11 states the size of its parity matrix, the closing set and the excluded set, all three derivable from the matrix table, and the nouns those sentences use are not in the vocabulary at all. That is the gate's declared unpoliced case (*"the remedy is another argued entry"*), it is now genuinely available as a remedy for them, and it is **owed rather than done here**: three more argued entries is a session, and this one had one objective.
- **It does not make a scoped entry cheap.** Each one is still a recorded reading of a population with the reason it is restated, and a `file` predicate adds a second thing to argue: why this population belongs to these documents and not to the tree.
- **It does not close the already-drifted blind spot.** A per-document count that has already gone wrong is as invisible to a scoped entry as to a global one, for the same reason and by the same deliberate trade.
- **It does not reach `.ts`, `.tsx`, `.mjs` or `.sql`.** The gate reads markdown because `generate()` rewrites markdown, and that boundary is unchanged and still owed.

### 7. Alternatives considered

- **Add a second global entry for `deltas`.** Rejected: the runner records that it would be shadowed forever, and a vocabulary entry that can never match is worse than no entry, because the note line prints it and it reads as coverage.
- **Rename the noun in M06 so it stops colliding**, for instance *"schema changes"*. Rejected: it repairs one sentence by moving it out of the vocabulary's reach, which is the defect wearing a different word. The next document to count its own anything is in the same position.
- **Drop value-anchoring and match on the noun alone.** Rejected on the gate's own measurement, restated in section 4: 206 findings in live prose on a clean tree.
- **Delete the number from M06 and point at the table.** Rejected as insufficient rather than wrong. `ADR-034` permits it, and the sentence had in fact already been given a no-number form by one of the two paragraphs that arrived in `f6f8e58`, which did not stop the other paragraph from carrying a stale count in the same section. **A count that is absent is not a count that cannot come back**, and the register's own remedy for `OI-24` is the span.

### 8. Consequences

- `scripts/corpus/gates.mjs` gains one `SPAN_QUERIES` entry and one scoped vocabulary entry, and `ci06DerivableCounts.run()` gains one line. **Sessions 243 and 244 are also live in that file**, so the edit is kept to a single gate body plus the query it needs.
- The gate's run note now prints the scoped entry with the rest of the vocabulary, so a scoped population is visible in every run rather than asserted here.
- `OI-24` closes.
- Three further M06 counts are named as owed in section 6 above, with the remedy that now exists for them.

### 9. Approval

- **Approval line: PENDING, UNSIGNED. Remove M06 section 2's generated span, retype the count in prose at the value the table holds, and `CI-06/derivable-counts` goes RED naming that file, that line and that query; restore the span with `node scripts/corpus/gates.mjs generate` and it goes GREEN.** Executable, one clause, scoped to the one gate and the one document, and **it names no number**, which is the property this entry exists to defend. It was run before this line was written and both outputs are in the pull request.
- **Not money path.** No migration, no schema, no engine, no ledger. The [E2](../../MERIT_BUILD_MASTER_PROMPT.md) read is not owed on this entry and is not claimed by it.
- **The clause a later session will want to reverse is decision 2**, declaration order. It is load bearing rather than stylistic: a scoped entry declared after the global one it shares a noun with is unreachable, silently, and the run note would print it as coverage.

**What a founder read adds and this entry cannot.** Two of the decisions here are judgements rather than derivations. **That a vocabulary entry may be SCOPED to a file** (decision 1) reverses the reading the gate's own rationale took, which filed this very sentence as a specimen of the noise a rejected rule would produce. The entry separates the rule from the site and argues a per-document count is a population; the other reading, that it is a local subset and belongs outside the vocabulary, is the one the rationale wrote down and it is not absurd. **That declaration order is what rescues a scoped entry from the shadow** (decision 2) is named above as the clause a later session will want to reverse, and it is load bearing rather than stylistic: an entry declared in the wrong position is unreachable, silently, and the run note prints it as coverage. Nothing in the tree fails on that ordering today, so the judgement is whether a rule that only a reader can enforce belongs in a vocabulary this corpus built gates to stop trusting.
