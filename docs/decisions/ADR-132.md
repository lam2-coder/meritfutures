## ADR-132: a registry README indexes by ROW, and `CI-06n` stops accepting a sentence  (2026-08-27, status: proposed)

**`CI-06n`'s title has said "Every registry entry has a README ROW" since the day it was written, and its parser accepted any markdown link anywhere in the README.** Two claims, one gate, and the weaker one was the one that ran. This entry rules which half was right, narrows the parser to match it, and states the cost, which is a rule about what a registry README may look like from here.

- **Origin:** `OI-09`, opened 2026-08-16 by [session 32](../sessions/2026-08-16-session-32.md) and recorded by [session 33](../sessions/2026-08-16-session-33.md). The number was **RESERVED BEFORE DISPATCH and CONDITIONAL** ([ALLOCATION](ALLOCATION.md) row 132): *"Reconciling a gate's title with its behaviour is a repair unless the TITLE turns out to be the correct half, in which case tightening the gate changes what the corpus may say."* **The title is the correct half** (section 1, finding 2), so the condition fires and this entry exists.

- **NOT MONEY PATH.** One gate body in [`scripts/corpus/gates.mjs`](../../scripts/corpus/gates.mjs), which reads markdown and writes nothing. No migration, no schema change, no engine change. `0048` stays free.

- **The identifier is NOT touched.** `CI-06n` keeps its letter. Session 243 holds `OI-17` and the `CI-06<letter>` registry in this same file; this entry rules what the gate DOES and says nothing about what it is called. Section 4 rows the slug question for whoever holds the naming.

### 2. THE RULING

#### Clause 1. A registry README indexes its entries by TABLE ROW, and a row is a line beginning with a pipe, outside a code fence

`CI-06n` matches a ROW. The link must sit on a line whose first character is `|`, and that line must not be inside a fenced block.

**The fence half is not decoration.** [The ADR registry README](README.md) carries its own entry FORMAT in a fence, and a registry that documents its row shape must not have the documentation counted as coverage. That is the near-miss `CI-06s` names one registry along, where `corpus.yml` mentions a probe filename in a comment three lines above the step that runs a different probe: **a parser that reads a sample as the thing itself reports coverage that does not exist.**

#### Clause 2. WHAT THE CORPUS MAY NO LONGER SAY, stated as a rule rather than as a diff

> **A registry README may not index an entry with a sentence, and may not index one with a sample. An entry is in the registry when a table row links it.**

**That is the clause that made the number conditional and it is the one a later session will meet.** Nothing in the tree breaks today (finding 5), so the cost is paid entirely in the future: a session that adds an entry file and links it from a paragraph now goes RED where it would have gone green. **That is the intended behaviour.** A registry whose membership is decided by prose has no membership; it has mentions, and `FM-17`'s shape is that a registry which has stopped indexing reads exactly like one with nothing to index.

#### Clause 3. THIS IS A NARROWING OF A CLAIM'S READER, NOT A WEAKENING OF A GATE, and the direction is what decides it

Rule 1 of [`gates.mjs`](../../scripts/corpus/gates.mjs) forbids a gate that *"returns PASS for a check it did not perform."* **The test is directional.** This change makes `CI-06n` report MORE: an entry indexed only by a sentence was green and is now a finding. **Nothing that failed before passes now**, on any input.

**The forbidden move is the mirror of this one** and it is worth naming so the two are never confused: had the evidence run the other way, the repair would have been to weaken the TITLE to match the parser, and that would have narrowed a CLAIM the corpus is entitled to cite while leaving the check exactly as permissive. Both repairs end with title and behaviour agreeing. Only one of them ends with the corpus knowing more than it did.

#### Clause 4. The resolve direction narrows with it, and `CI-06a` holds what it gives up

`CI-06n`'s second direction reported any entry-shaped link that did not resolve. It now reports only rows, because a mention is not a row and this gate no longer claims anything about mentions.

**The coverage is not lost, it changes owner** (finding 6). `CI-06a` resolves every relative markdown link in every markdown file. **What `CI-06n` keeps is the registry-shaped half**: a row claiming an entry that is not there is a registry claiming coverage it does not have, which is a different failure from a broken link and is the one this gate exists for.

#### Clause 5. The finding says WHERE the rejected link is and WHY it does not count

An entry with no row is reported with the line number of the first link to it that is not a row, and with which kind it is:

```
docs/decisions/ADR-043.md: entry file with no row in docs/decisions/README.md, and the link at docs/decisions/README.md:21 is prose rather than a row
```

**This is why the fenced lines are scanned rather than skipped.** A gate that skips a fence and then reports *"no row"* over a README that visibly names the entry sends a reader looking for a missing file. An entry indexed by a sentence is one row away from correct, and a finding that names the sentence is the difference between a repair and a search.

#### Clause 6. The count of rejected links is PRINTED on every run

The run note carries `N entry link(s) outside any row, prose or fenced, claimed as nothing`. **Zero is the corpus saying every registry indexes by table.** A number above zero is the exact population `OI-09` was opened about, visible on every run instead of on the day somebody re-reads the parser.

### 3. The alternative, argued: repair the TITLE and leave the parser alone

**It is the cheaper repair, it needs no ruling, and it deserves an argument rather than a dismissal, because a gate is allowed to check less than its name suggests as long as it says so.** `CI-06n`'s `covers` line already said so. The honest edit would have been one word in a title.

**It fails at ADR-043** (finding 2). The gate was not written to a title somebody chose; it was written to a ruling that used the word ROW twice, in an entry whose other clause turns on *"a row is not a document"*. Narrowing the title would have made the gate agree with itself by discarding the property its own origin asked for. **The corpus would then be entitled to cite `CI-06n` for exactly nothing about registry structure**, and the transitive guarantee ADR-043 bought with `CI-06c`'s exemption would be a guarantee that any sentence can satisfy.

**And the sweep that repair would have required is the tell.** Had the title been the wrong half, every citation of `CI-06n` in the corpus would need auditing for one that leaned on the stronger reading. Those citations exist: [STRATEGY](../testing/STRATEGY.md)'s row, ADR-043's Context, and the `REGISTRIES` block comment in [`gates.mjs`](../../scripts/corpus/gates.mjs) each state the row property as fact. **Three documents were already asserting the stronger claim, which is evidence that the stronger claim is the one the corpus was built on.** Under this ruling all three become true rather than needing repair, and no sweep is owed.

- **It does not decide what a row is beyond a leading pipe.** Requiring a preceding header and delimiter was considered and rejected in section 7: it reads a table's shape to answer a question about membership, and would go RED on a legitimate row the moment a README grew a second table.

- **It writes no migration and adds no gate.** `CI-06n` is amended, and the gate count is unmoved.

### 7. Alternatives considered

- **Repair the title instead.** Section 3, at length. **Rejected at ADR-043**, which used the word ROW twice in the ruling that asked for the gate.
- **Leave it, because 648 of 648 pass either way.** **Rejected.** The number is the argument for tightening, not against it: a gate that costs nothing to make true and is not made true is a gate that will be cited for a property it does not have. `OI-09` was found by that citation failing, on the entry that wrote the gate.
- **Require the row to sit under a table header and delimiter.** **Rejected as over-fitting.** It answers "is this line inside a well-formed table" to decide "is this entry indexed", and the two come apart: a README with a second table, a row separated from its header by a blank line, or a table split by a paragraph would go RED on a legitimate row. A leading pipe outside a fence is the property the corpus actually uses, and every one of the five registries satisfies it today.
- **Keep the resolve direction over every link, and narrow only the entry direction.** **Rejected on the same principle the entry direction is narrowed for.** A gate whose two halves read the README two different ways carries the defect it was just repaired for, one direction along, and the finding it produced would be a broken link reported under a title about rows. `CI-06a` already owns broken links and owns them over more files.
- **Strip inline code as well as fences.** **Not taken, and stated rather than assumed.** A link inside backticks on a table row is still on that row, and treating a cell's contents as not-a-row would make the gate disagree with the reader's eye. No registry does this today.
- **Fix it in the falsify harness first and narrow the parser after.** **Rejected on the fence**, not on the merits. `falsify.mjs` is outside this session's fence and section 6 row 1 rows the seed rather than reaching for it.

### 8. Consequences

- **`CI-06n` now checks the property its title names**, and `OI-09` closes with a ruling rather than a note. The transitive guarantee ADR-043 bought is a guarantee about rows again: INDEX carries the README, and the README's TABLE carries the entry.
- **Three existing citations of the stronger claim become true.** [STRATEGY](../testing/STRATEGY.md)'s `CI-06n` row, [ADR-043](ADR-043.md)'s Context paragraph and the `REGISTRIES` block comment in [`gates.mjs`](../../scripts/corpus/gates.mjs) each state the row property as fact. None needed editing for content; STRATEGY's row is amended here only to record what a row IS.
- **A registry README's prose is now inert with respect to membership.** A future session that indexes an entry by a sentence gets a finding naming the sentence. **That is a rule about what the corpus may say, and it is why this needed an entry** rather than a commit.
- **The gate gives up one check and `CI-06a` keeps it.** A prose link that does not resolve is a `CI-06a` finding and no longer a `CI-06n` one. The corpus loses nothing; one gate stops claiming something another gate proves better.
- **The narrowing is unseeded in the harness and section 6 row 1 says so.** Until that seed exists, this entry's section 5 is the only record that the gate was watched failing, and a revert would be silent. **That is the largest thing this entry leaves open and it is named rather than left to be discovered.**
