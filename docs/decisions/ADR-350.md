### 3. Judgement one: what a published statistic commits Merit to

**A PUBLISHED STATISTIC IS THE FIRM MAKING A CHECKABLE CLAIM ABOUT ITS OWN PERFORMANCE, AND THE CHECKABILITY IS THE PRODUCT.** [M12](../plans/M12-transparency-platform.md)'s surfaces publish the figure, the numerator, the denominator, the window, the as-of day and the sample size, and the method page publishes the definition those were computed under. A reader is invited to take the definition and the components and confirm the arithmetic. **So the failure mode that matters is not a wrong number. It is a number that is right about a set nobody described.**

That reading decides everything below, and it produces one rule:

> **A FIGURE WHOSE COHORT DIFFERS FROM ITS OWN PUBLISHED DEFINITION IS WORSE THAN NO FIGURE**, because the reader cannot detect the difference and the surface's whole promise is that they can.

Three ways this run could publish a figure nobody could stand behind, and what this adapter does about each:

1. **A DENOMINATOR SHORT OF ITS DEFINITION.** `ST-02`'s ruled denominator has two parts and this tree can produce one of them. Publishing the one part would put a rate on a page whose method text describes a different cohort, at a difference no reader can see and no gate can measure. **REFUSED**, section 4.
2. **A SUPPRESSION THAT LIES ABOUT ITS OWN REASON.** `INV-M12-05` suppresses below `min_sample` and the surface renders *"not yet meaningful"* WITH THE SAMPLE SIZE SHOWN, which is what makes it a stated limitation rather than a concealment. An adapter returning an empty fact set for a statistic it cannot compute would publish `below_min_sample` with `sample_size: 0`, which is that same sentence carrying a false reason. **REFUSED**, and it is the reason `fundedLives` does not simply return `[]`.
3. **A SET SELECTED BY WIRING.** `FM-M12-02` is *"a halt publishes NOTHING and pages. It never publishes a partial set, BECAUSE A PARTIAL SET IS A SELECTED SET"*. A run that published the statistics whose facts happened to be constructible would be exactly that, with the selection taken by an adapter rather than by a person, and nothing would report it. **REFUSED BY CONSTRUCTION**, section 5.

**AND ONE THING THIS RULE DOES NOT LICENSE.** It does not license withholding an unflattering figure. `INV-M12-08` puts no approval step between computation and publication and the machine has no path to `suppressedReason` except the sample floor, which is fixed on the definition row before the data exists. Nothing in this adapter can decline a number for being low; the two refusals are about **which set** a number would describe, and both are stated in code with the parameter that discharges them named.

### 4. Judgement three: the two facts this tree cannot produce, named and refused

#### 4.1 `fundedLives`, and `ST-02`'s second denominator

[M12-statistic-definitions](../plans/M12-statistic-definitions.md) rules `ST-02`'s denominator as *"funded accounts whose funded life ENDED in the window (first payout, breach, or closure), PLUS THOSE STILL FUNDED PAST THE PLAN'S MAXIMUM PLAUSIBLE TIME-TO-FIRST-PAYOUT"*. `apps/worker/src/batch/ports.ts` already puts the second part on the adapter, because the machine holds no plan and resolves none.

**THE PARAMETER DOES NOT EXIST.** `PublishedFundedPhase` declares `drawdown`, `daily_loss_limit`, `min_trading_days`, `win_days`, `consistency`, `buffer_bp`, `cadence_gap_trading_days` and the settlement term. The three that bear on a first payout (`min_trading_days`, `win_days.required_count`, `cadence_gap_trading_days`) bound the **EARLIEST** a first payout can occur. The definition asks for the **LATEST one that is still plausible**, which is a judgement about the tail of a distribution and not an arithmetic consequence of a gate. No `firm_parameters` row carries it either.

Three ways to serve the port anyway, all refused:

| Option | Why it is refused |
|---|---|
| Return the ENDED lives alone | Publishes a rate under a denominator its own method page does not describe. Section 3's rule, exactly |
| Return an empty set | The cell falls under `min_sample: 100` and publishes a suppressed row reading *"not yet meaningful, sample 0"*, when the truth is that the figure cannot be computed at all. A false reason on a page whose product is stated reasons |
| Derive the threshold from the gates above | This worker choosing where a plan's plausible first cycle ends, which is the line `INV-16` and `M12` section 1.3 both draw |

**WHAT DISCHARGES IT IS A CONFIG ROW AND NOT A DIFF.** A value per plan, taken deliberately, in the shape the corpus already uses for every launch candidate. The refusal names it.

#### 4.2 `withdrawalSettlements`, and the day a rail settlement counts for

`WithdrawalSettlementFact.settledTradingDay` is *"the trading day the settlement counts for"* on `G-5`'s outcome anchor. **`wallet_withdrawals` CARRIES NO TRADING-DAY COLUMN**: `requested_at`, `approved_at`, `settled_at`, `cancelled_at` and `frozen_at` are all `timestamptz`.

**THE FOLD EXISTS AND IS NOT THE MISSING PIECE.** `tradingDayAt` in `packages/rules-engine` answers an instant in three outcomes, and the third decides this: an instant inside a loaded span and inside no session is POSITIVELY `not_a_session`. A bank moves money on its own hours, so a large share of rail settlements land on a weekend, a holiday or an overnight gap, and for every one the fold correctly answers that there is no trading day. **NO DOCUMENT RULES WHICH DAY THOSE COUNT FOR.** Rounding forward invents the anchor; rounding back moves a settlement across a window boundary into a cohort it was not in. Either is this adapter deciding a published window's membership.

**AND REFUSING IT KEEPS A PAIR HONEST THAT WOULD OTHERWISE COME APART.** `ports.ts`: *"`ST-06` EXISTS BECAUSE `ST-05` WITHOUT IT IS A LIE BY OMISSION."* `ST-05` is servable here. An adapter that answered five ports and shrugged at the sixth would publish Merit's near-zero internal leg (one transaction under [ADR-019](ADR-019.md)) with the multi-day external leg missing, which is `M09`'s `GS-147` in statistical form.

**WHAT DISCHARGES IT IS THE REPAIR THE PAYOUT LEG ALREADY HAS.** `payout_requests.effective_trading_day` exists precisely because *"the day it counts FOR"* is a decision taken once, at the write, by the code that knows the business event. A `settled_trading_day` on `wallet_withdrawals` is the same repair, and it is a migration rather than a read.

#### 4.3 `raiseStatisticsHalt`, which is the batch's blocker unchanged

`M12` section 5 gives the halt `stats.run_halted` and the event PAGES. This deployable holds every `emit` call site in the workspace (**9**, derived at reporting time) and holds no producer; `apps/api/src/events.ts` is the only composed writer and `apps/worker` declares `@merit/db` and `@merit/rules-engine` and nothing else. **AND WIRING A SINK WOULD NOT MAKE THIS ONE WRITE**: `buildEvent` refuses a name that is not a row of `EVENT_CATALOGUE` ([ADR-159](ADR-159.md) clause 1) and `stats.run_halted` is not one. So the port owes a catalogue row before it owes an adapter.

**THE CONSEQUENCE IS STATED RATHER THAN SOFTENED**: today a halted run cannot page. `test/statistics-adapter.test.ts` section 7 case 2 asserts it, over the halt this tree would actually reach.

**AN ADAPTER MAKES THE RUN RUNNABLE AND A SCHEDULE MAKES IT RUN AND PUBLISH. ONLY THE FIRST IS TAKEN.**

### 7. Findings

#### 7.1 `SettledPayoutFact.terminalSettlement` was documented as a null test, and the null test deletes payouts from a published average

`apps/worker/src/batch/ports.ts` declared the field as **`accounts.terminal_settlement_id IS NOT NULL`**. [`0010:306`](../../packages/db/migrations/0010_payouts.sql) declares `FOREIGN KEY (terminal_settlement_id) REFERENCES payout_requests(id)`, and `SD-M18-01`'s own row in [M18](../plans/M18-graduation-track.md) says the column exists so that *"a graduated account holding a balance is indistinguishable from one that paid out fully"* stops being true. **The column names WHICH request closed the account. The flag is a property of the PAYOUT and not of the ACCOUNT.**

**THE CONSEQUENCE IS ARITHMETIC AND IT IS IN THE SUITE.** `ST-04` EXCLUDES terminal settlements. Under the null test, every payout a graduated trader ever received is marked terminal, so all of them leave the mean and the median. On this row's fixture the correct mean is **40000 integer cents** over three payouts and the null test returns **15000** over two. Merit would have published an average payout with its highest-paying accounts silently removed, on the surface whose entire product is that the cohort is checkable.

**AMENDED IN PLACE UNDER `RI-14`, correction beside the original**, and `statistics-adapter.ts` takes the equality. **The migrations are untouched.**

#### 7.2 The supersession pointer was read backwards, and the suite caught it before the file was committed

The first `effectiveDefinitions` collected the ids rows POINTED AT (`superseded_by`) and called those retired. The pointer runs FORWARD: the live row is the one pointing at nothing (`statistic_definitions_live_uq` is `UNIQUE (stat_code) WHERE superseded_by IS NULL`), so the first version **retired the successor and kept the predecessor**. Every figure would have been published under the method it replaced, with `definition_version` on the row saying so and nobody reading it.

**WATCHED RED BEFORE GREEN**, by section 1 case 2 of the suite, which was written before the predicate was. The correction is at its own site in the file.

#### 7.3 A run that publishes nothing reports `published`, and there is no halt reason for it

If every effective definition is `plan` grain and the window held no activity, `planCells` returns no cells, no `stat_code` is marked produced, `publishRun([])` writes nothing, and the report is `status: 'published'` with `statCodes: []`. **That is [ADR-119](ADR-119.md)'s measured defect at a second site**: *"would report `accountsAudited: 0, diverged: 0`, GREEN, EVERY NIGHT, OVER NOTHING"*. `no_effective_definitions` covers the empty registry and covers nothing here.

**REPORTED AND NOT REPAIRED.** The repair is a member of `StatisticsHaltReason` and a rule about what "nothing to publish" means, which is a ruling rather than an adapter, and it belongs beside the `closed_admin` ruling section 6 also leaves open. The behaviour is pinned by a case rather than left to be rediscovered.

#### 7.4 The transparency surface is 404 rather than stale

Section 2. `GET /public/methods/:statCode` is wired, composed and serving an EMPTY registry, so all seven ruled codes 404 today. The dispatch's framing (*"method pages describe a method whose output does not exist"*) describes a state this tree has not reached: the definitions do not exist either, and they are the artifact with a founder signature and a launch date on it.
