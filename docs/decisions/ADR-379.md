### 4. The four shapes, re-measured, and the one that was not caught

**THE METHOD IS THE POINT.** Each shape was applied to the REAL `apps/api/src/start.ts` rather than to a fixture, at the last install, and the three files in this slice were run separately so that each one's answer is its own. Every seed was restored and verified with `sha256sum -c`.

| shape, seeded on the real file | `start-program.test.ts` | `start-construction.test.ts` | `wiring.test.ts` |
|---|---|---|---|
| a BLOCK comment at column zero | **RED** | **RED** | **RED** |
| the install moved below `await main()` | **RED** | **RED** | **RED** |
| dead code after a top-level `throw` | **RED** | **GREEN** | **RED** |
| the call inside a template literal | **RED** | **RED** | **RED** |

**THE THIRD ROW IS THE FINDING.** [ADR-374](ADR-374.md) section 5's table says of that shape that the walk also stops and the name vanishes. **The walk did not stop.** `factoriesInstalledBeforeMain` iterated every top-level statement and broke at `main()` alone, so a `throw` above the last install left all eleven factories in the pinned list, all four cases green, and nothing in that file saying that a run of the module it reads would abort partway.

**WHY IT MATTERS, STATED NARROWLY BECAUSE IT IS NARROW.** The shape cannot exist undetected on this tree: `start-program.test.ts` forbids a top-level `throw` outright, and `wiring.test.ts` truncates `wired` at one, and both were watched red on that seed. **What was defective is the file's own account of what it catches**, and a control believed to catch a class it does not is worse than one that never claimed to, because the belief is what stops somebody building the thing that would.

**AND THE DIRECTION OF THE ERROR IS THE UNSAFE ONE.** The reader OVER-reported: it named factories a run does not construct. Everything it asserts is a list being empty or a set of names being complete, and both stay satisfied while the module aborts. **That is how a guard goes quiet rather than red.**

**THE REPAIR IS ONE CLAUSE AND IT IS INERT.** The reader breaks at a top-level `throw` now. `start.ts` holds none, so no answer about this tree moves. **It is exercised anyway**, by a fixture case whose answer changes when the clause goes, on exactly the rule both sibling readers already follow for their own reachability clause. **After the repair the third row reads RED, RED, RED like the other three.**

**THE SUPERSEDED ROW IS NAMED AND NOT REPRODUCED**, under `RI-14`. [ADR-374](ADR-374.md) section 5's table stays where it is, beside this correction, because a row that was right about the other three and right that the shape is caught somewhere is not made wrong by being wrong about which file catches it.

**THE ONE PIN THAT NAMED THE OLD DERIVATION AS ITS GROUND IS STILL LOAD-BEARING, AND THAT IS THE ANSWER RATHER THAN A HEDGE.** The straight-line case forbids thirteen syntax kinds in `start.ts`, and its own comment said the remedy for a violation is to re-derive `wired` against the syntax tree. **That remedy has been taken, so the soundness it was protecting is no longer on loan from the shape of the file.** What the pin still holds is the premise under the ORDER argument: every statement runs exactly once, so "the installs run before `main()`" is a fact about a total order and not about one path through a branch. **A top-level `throw` would truncate that order, and the tree derivation reports a truncation as a SMALLER `wired`: a cardinal moving with no name attached to it.** At the pin it arrives carrying its own.
