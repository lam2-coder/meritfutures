### 3. The design, and the answer to the hard half

#### 3.1 The two legs, in one sentence each

- **Leg D. EVERY ROSTERED WALKER IS MEASURED ENUMERATING.** Each is called, in a child process, against a planted tree with a counted number of files, and what it reads is recorded. That is [ADR-470](ADR-470.md) section 3.4 item **4**, the semantic change.
- **Leg E. ANYTHING THAT ENUMERATES WHEN CALLED WITH NO ARGUMENT AT ALL IS IN THE ROSTER.** That is the roster's own definition run backwards, and it is section 3.4 item **3**, the primitive `ENUMERATORS` does not name.

#### 3.2 The hard half, and the answer

**THE ENTRY NAMED THE COST ITSELF: doing this without giving the check a second copy of every checker's inputs.** A measurement that required each checker to SUCCEED would need a corpus for `price-register`, a migration set for `generated-column-writes`, a source tree for `dependants`, and a suite directory for `tree-input-budget`. That is a second repository, maintained beside the first, going stale on its own schedule. **It would have been the right moment to refuse, and it was not necessary, because the price does not ask whether a checker WORKS. It asks whether it ENUMERATES.**

**AN ENUMERATION HAPPENS BEFORE ANY OF THE PARSING THAT WOULD NEED FIDELITY.** A checker handed eight placeholder files reads the directory, opens one of them, fails to make sense of it, and throws. **The throw is after the reading, and the reading is the whole measurement.** So the planted tree carries:

- **`PLANTED_LINE`**, one line of placeholder text, behind every file;
- **`PLANTED_EXTENSIONS`**, eight suffixes, which is the ONLY thing the planted tree knows about anything (a checker that filters its listing to `.sql` has to find one `.sql` name in it or the run reads nothing and the measurement learns less than it could);
- **no directory shape at all**, because the shape is MATERIALISED ON DEMAND out of the paths the checker itself asks for. The first enumeration of a path that does not exist creates it and plants `perDir` files in it, capped at `PLANT_CAP` directories.

**SO THE FIXTURE IS DERIVED FROM THE SUBJECT AT RUN TIME RATHER THAN WRITTEN DOWN**, which is the same discipline [ADR-470](ADR-470.md) applied to the roster one layer up.

#### 3.3 Three outcomes, and why two would be wrong

**A ROSTERED WALKER IS MEASURED, A FINDING, OR INCONCLUSIVE.**

- **MEASURED**: it enumerated a directory under the planted root, or it attempted a spawn. Eight of nine.
- **A FINDING**: it read the planted tree and enumerated nothing in it. Its roster entry says it walks and the run says it reads. **That is the subject.**
- **INCONCLUSIVE**: it never reached the planted tree at all. **One of nine**, and it is [`dependants.mjs`](../../packages/tooling/checks/dependants.mjs)`#main`, whose first statement is `const target = argv[0]` and which prints its usage and returns when there is none.

**COLLAPSING INCONCLUSIVE INTO EITHER OF THE OTHER TWO WOULD BE THE CHECK LYING ABOUT ITS OWN POPULATION.** Called clean, it hides the shape the subject is about. Called a finding, the check ships red on a walker that is doing nothing wrong, and the defect would be the measurement's own calling convention rather than the tree. **It is counted and named in the report, and it is section 10 item 1.**

**THE CALLING CONVENTION IS UNIFORM AND IT INVENTS NOTHING.** A parameter with a default is passed `undefined`, which is what makes the default apply. A parameter without one is passed **the empty array**, the same value for every walker, chosen because it is the value that carries the least meaning. **It is never anything shaped like a checker's real input**, which is the same refusal as section 3.2 in a second place.

### 4. The instrument, and why it has to be a child process

**THE MEASUREMENT IS A DORMANT PATCH OVER `node:fs` AND `node:child_process`.** While ARMED it serves every path inside this repository from the planted tree, records every enumeration, read and spawn, and throws on every write, spawn and `process.exit`. While DISARMED it is a pass-through, which is what lets the child do its own bookkeeping through the same functions.

**IT IS INSTALLED BY `--import` AND THE ORDERING IS NOT NEGOTIABLE, WHICH WAS MEASURED RATHER THAN ASSUMED.** An ESM `import { readdirSync } from 'node:fs'` binds at INSTANTIATION. A probe written before any of this code confirmed both halves: a module imported AFTER the patch sees it, and **a module imported BEFORE the patch sees nothing, even after the builtin's exports are re-synchronised**. There is therefore no in-process arrangement that reaches a module the parent has already loaded, and `dependants.mjs` is one of those. **`--import` with a `data:` module is the only ordering guarantee available**, it imports nothing of this repository, and it leaves no file behind.

**THE CHILD IS THIS SAME FILE IN ANOTHER MODE**, re-entered as `--measure-child`, which is not a user-facing option and which the usage text does not offer. A case asserts that.

**AND IT IS NOT AWAITED AT THE TOP LEVEL, WHICH COST ONE DEBUGGING PASS.** `run` and `census` are exports of this file and are two of the calls the child makes, so a top-level `await` left the module still EVALUATING while the child imported it back, and a dynamic import of a module mid-evaluation **never settles**. Node reported it as *"Detected unsettled top-level await"* and the check exited 2. The promise chain runs after evaluation instead.

### 5. What running the roster found that reading it could not

#### 5.1 A rostered walker whose enumeration is a process spawn, which is `ADR-470` section 3.4 item 3 alive in the tree

**[`absence-grammar-census.mjs`](../../packages/tooling/checks/absence-grammar-census.mjs)`#main` SPAWNS `git -C <repo> ls-files -z`.** The static fold cannot see it: `execFileSync` is not in `ENUMERATORS` and never can be, because it is not an `fs` call at all. **That function is in the roster only because its FALLBACK is a `readdirSync` walk**, which is exactly what [ADR-470](ADR-470.md)'s own header comment says of `dependants.mjs#population`: *"caught only because its fallback is a `readdirSync` walk."*

**SO THE ENTRY'S HYPOTHETICAL IS NOT HYPOTHETICAL, AND THE MEASUREMENT IS WHAT SAYS SO.** A checker written the same way WITHOUT an fs fallback would be invisible to the fold and would never be rostered, and leg E is now what would name it.

#### 5.2 Two rostered walkers enumerate and read none of the planted files, and that is not a defect

[`price-register.mjs`](../../packages/tooling/checks/price-register.mjs)`#derive` and `#run` enumerate the planted tree and open none of it, because they filter a listing by a name pattern the placeholder names do not match. **Their enumeration is measured; their read growth is not available.** This is why the verdict is a disjunction and not a single number: **6 of 9 read more of the larger planted tree than of the smaller**, and the other measured walkers are held by the enumeration itself.

#### 5.3 The two derivations disagree in exactly the direction that makes them worth having

| | Static fold ([ADR-470](ADR-470.md)) | Measured run (this row) |
| --- | --- | --- |
| walkers | **9** | 8 enumerate, 1 inconclusive |
| how `absence-grammar-census#main` walks | a `readdirSync` fallback | **a `git ls-files` spawn**, with the fallback second |
| how `dependants#main` walks | a defaulted root reaching a walk | **unmeasurable under an empty argument** |
| functions the fold cannot roster at all | a walk through a primitive it does not name | **leg E runs 7 of the 103 exported functions with no argument and finds none** |

**NEITHER DERIVATION IS A CHECK ON THE OTHER UNLESS THEY SHARE NO STEP**, and these share exactly one: `ENUMERATORS`. The patch is generated from that same array, and a case asserts it, so the day the two lists diverge is the day the agreement between them stops meaning anything.
