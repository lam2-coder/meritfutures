## ADR-057: one refuted sentence in four documents, and the ninth field on a breach row  (2026-08-18, status: accepted)

**Two residues, both left behind by rulings that were ACCEPTED, each found by the session that applied the ruling and neither in scope for that session to fix.** [M01](../plans/M01-rules-engine.md)'s `R-15` row and section 3.6's breach block are amended, together with [M01](../plans/M01-rules-engine.md)'s `OQ-4`, the [GLOSSARY](../GLOSSARY.md)'s `floor lock` entry and [ADR-014](ADR-014.md)'s decision block. **Neither ruling here changes any behaviour.** Both make a frozen document state what the merged tree already does, which is why this ADR amends rather than proposes, and it is the one thing to check before reading further.

---

### 1. `ADR-052` refuted a sentence and amended two of its five copies

[ADR-052](ADR-052.md) (accepted 2026-08-17) established that `CV-12` does **not** put the trailing floor at the locked value on the lock day. The two agree only where the closing balance lands on the trigger to the cent, and `R-15`'s trigger is `>=`, so a day may clear it by any amount. On `GS-024`'s lock day the trailing floor is `5,050,001` and the locked value is `5,010,000`.

**Its section 5 amendment table has four rows and the applying session applied three.** The fourth, `ADR-014`'s decision block, is still on disk carrying the `max` and the sentence `ADR-052` names. **And `R-15`'s row is in no row of that table at all**, because `ADR-052` declares in its own words that "`R-15`, `R-14`, `INV-06`, `INV-07`, `CV-11` and `CV-12`'s operator are unchanged."

**That declaration is true of the rule and false of the sentence sitting beside it in the same cell.** `R-15`'s Effect column is unchanged: `floor = floor_lock_floor_at_cents`, `floorLocked = true`, `hwb` frozen. What follows it in the same cell is not an effect, it is a **rationale**, and it is the refuted one. **An amendment table enumerates locations; a claim propagates by restatement.** Five documents restated this one and the table named two of them.

**The five copies, each read at its line before this was written:**

| Where | What it carries | Disposition |
|---|---|---|
| [M01](../plans/M01-rules-engine.md) section 2.4, `CV-12`'s "Rejected because" | corrected | already applied by `ADR-052` |
| [M01](../plans/M01-rules-engine.md) section 3.4, the binding expression and the paragraph after it | corrected | already applied by `ADR-052` |
| [M01](../plans/M01-rules-engine.md) section 3.5, `R-15`'s row | "CV-12 forces the trigger to sit exactly where the trailing floor already is, so **the floor never jumps**" | **amended below** |
| [M01](../plans/M01-rules-engine.md) section 11, `OQ-4` | "chosen so the trailing floor is already sitting exactly at the lock value when it engages and therefore never jumps (CV-12, R-15)" | **amended below** |
| [GLOSSARY](../GLOSSARY.md), `floor lock` | "engaging at exactly `drawdown + 10,000c` of closing profit so that the trailing floor is already sitting at the lock value when it engages and the floor never jumps" | **amended below** |
| [ADR-014](ADR-014.md), decision block | the `max`, and "`hwb` stops updating ... which is what makes the `max` above resolve to the locked value forever after ... so that CV-12 holds and the floor never jumps when it locks" | **amended below, on `ADR-052`'s own authority**, which named this site and did not reach it |

**`X = 10,000c` and every ruling on it stand.** What `CV-12` buys is not the equality; it is that the locked value sits **at or above** the prior day's trailing floor, so the lock day never lowers the stored floor. That is what makes `INV-06` hold across the lock, it is `ADR-052` section 3's proof, and it is the reason the parameter is the value it is. **The conclusion was right and the argument for it was wrong**, which is the harder half to notice and the reason four copies survived a ruling that refuted them.

### 1.1 The brief's premise about fixtures is void, and `GS-024` is why

**The objective as received states that "no fixture in the directory catches it" and that `GS-081` is deliberately built on the case where the claim happens to hold. The second half is true and the first is not.** Verified against the directory rather than inherited:

- **`GS-081`, `GS-015`, `GS-016` and `GS-056` all close their lock day at exactly `5,260,000`**, which is `size + 260,000` and the trigger to the cent. On those four streams the refuted claim is true and nothing detects it. `GS-081`'s own header states this as a design decision.
- **`GS-017`, `GS-019` and `GS-044` overshoot** and then end after `R-31` has rewritten the floor, so their end state cannot see the lock day.
- **`GS-018` overshoots by `39,999c` and pins no floor field at all.**
- **`GS-024` overshoots by `40,001c` and pins `floor_cents: 5010000`.** It is the executable statement of the corrected claim: an engine reading `R-15`'s row as written produces `5,050,001` and `GS-024` goes red. **It did go red, for as long as the defect existed, and session 55 turned it green by applying `ADR-052`.**

**So no fixture needs naming for this repair, and none is written.** [STATE](../STATE.md) line 916 and [ADR-052](ADR-052.md)'s own consequences both already say `GS-024` is "the only fixture in the corpus whose pinned floor differs between the two readings", which is the sentence the brief's premise contradicts. **`GS-024` is added to `R-15`'s Pinned by column**, because a row whose rationale was wrong for a day is a row that should name the file that would have caught it.

**No fixture can catch prose, and that is the honest limit of this half.** `GS-024` catches an engine that implements the refuted claim. It cannot catch a document that states it. The engine has been correct since session 55 and the document has been wrong since before `ADR-052`, which is the exact interval in which a reader repairing the code toward the document would have reintroduced the defect.

### 2. Section 3.6's breach block gains `engineGates`, and the divergence does not stand

**The question, stated as the residue records it.** [M01](../plans/M01-rules-engine.md) section 3.6's breach block sets **eight** fields. The engine writes **nine**: `gatesAfterBreach` supplies `engineGates`. `RE-U-025` now pins nine and says in its own comment that M01's eight do not include it. [ADR-054](ADR-054.md)'s applying session recorded this and deliberately did not decide it. **The options are that 3.6's block gains the field, or that the divergence stands with a stated reason.**

**It gains the field.** Three grounds, in the order they bind, and the third is the one that decides it.

**First, the divergence is internal to M01 rather than between M01 and the engine.** Section 2.2's `RuleState` declares `engineGates: EngineGateResults` as a required member. Section 3.6 returns a `RuleState`. A block that returns a value of a type the same document defines, omitting a member the same document requires, is a document disagreeing with itself. That is `ADR-052`'s shape and this is the second instance of it in `M01` in two days.

**Second, section 3.6's stated purpose is defeated by the gap.** Its own opening sentence is "pseudocode close enough to real that the diff between it and the implementation should be mechanical." A field the implementation writes and the pseudocode does not is precisely a non-mechanical diff, and it is the one a reader has to resolve on their own judgement. `RE-U-025` already had to resolve it, in a comment, with a pointer to `STATE.md`.

**Third, and this is the ground that settles it: carrying the field violates a property `M01` itself states.** Section 3.6 writes `s = { ...s, ... }`, so a field not listed **carries from the state that entered `DO-4`**. `RE-P-15` reads:

> `engineEligible` equals the conjunction of `engineGates`, for every generated state

A breach row is a generated state. The eight written fields include `engineEligible: false`. **If `engineGates` carries, then on any breach following an eligible day the conjunction is `true` while `engineEligible` is `false`, and `RE-P-15` fails.**

**That day exists and is already in the directory.** `GS-064` is "breach and payout eligibility on the same day": the account is eligible at day three's close and breaches on day four. Its note states the antecedent in its own words, that "every input the eligibility decision reads is still standing at the value that made the account eligible at the previous close". **Under the carrying reading `GS-064`'s breach row shows passing gate verdicts beside `engine_eligible: false`**, which is the worst row in an account's life displaying a satisfied-looking gate.

**The engine already reasons this way and cites nothing.** [`gates.ts`](../../packages/rules-engine/src/payout/gates.ts) says "EVERY `pass` IS `false`, INCLUDING THE TWO THAT CAN BE `skipped`. A closed account is not 'skipped past' its gates; it can never clear them again, and a `pass: true, skipped: true` on a breach row would put a satisfied-looking gate on the worst row in an account's life." **That is a trader-visible decision recorded in a source comment citing no authority**, which is the class [session 56](../sessions/2026-08-18-session-56.md) named as sitting one level below `CI-06q`'s reach. This ruling gives it one.

**What the amendment must not do, stated because the obvious form is wrong.** It must not call `evaluateEngineGates`. `R-37` can **refuse** a day when the calendar slice does not cover the cadence anchor, and a breach the fold declined to record on a caller's window choice is `R-24` broken. The gates on a breach row are **stated**, not evaluated, which is why `gatesAfterBreach` is a separate function. Section 3.6 names helpers it does not define (`refuse`, `withHash`, `initialState`, `allTrue`, `breachDetected`), so naming this one is in keeping.

**The alternative, and why it loses.** The divergence could stand on the reading that `engineGates` is an artifact of the TypeScript type rather than a rule, and that a specification should not carry implementation furniture. **It is not furniture.** Every `pass: false` on that record is a claim about what a closed account may still do, and `RE-P-15` is stated over it. A field that a stated property quantifies over is part of the specification by construction.

### 2.1 What checks it, named and not written

**`RE-P-15` is the check, it is already registered in [M01](../plans/M01-rules-engine.md) section 8.2, and it is unwritten.** No new identifier is claimed, because the row already exists. **It is deliberately not written here**: the fence is `docs/`, and a property test is `packages/rules-engine/test`.

**No `GS-nnn` can serve, and the reason is the loader rather than the corpus.** `engine_gates` is nested, and [`compare.ts`](../../packages/golden-loader/src/compare.ts) diffs flat fields with `Object.is`. `GS-064`'s own note records this ("the six gate verdicts live in `engine_gates` ... so no expectation reaches them"), and [session 56](../sessions/2026-08-18-session-56.md) recorded the same limit when `minimumAmount.withdrawableCents` moved invisibly to `CI-03`. **Naming a golden fixture for this would be naming one that cannot exist**, so `RE-P-15` is named instead.

### 4. Named and deliberately not touched

**Inside `docs/`:**

- **`GS-015`'s registry row and its title, "Floor lock engages continuously with no jump".** The row's body reads "At profit 260,000 the trailing floor reaches exactly `size + 10,000` and locks there", **which is true of `GS-015`'s stream** because that stream lands on the trigger to the cent. The title reads as the general claim and is not one. **Renaming it is a sweep** across the fixture filename, its `.expected.json`, the registry row, `STATE` and this ADR, and a fixture id's title is its identity. Named so the next reader does not take it for the refuted sentence surviving a sixth time.
- **`CV-11`'s row, and it is a FALSE LEAD that a next reader will otherwise repair.** [Session 55](../sessions/2026-08-17-session-55.md)'s commit applying `ADR-052` says "R-15's row and CV-11 carry the same 'never jumps' phrasing". **They do not.** `CV-11` reads "pre-lock it is strictly below by CV-12, **post-lock it equals it**", and under the assignment that is **TRUE**. It is the premise `ADR-052` section 2 turns on: the `max` makes it false, which is what makes `INV-21` unenforceable, which is what decided the ruling. **`CV-11` is the row `ADR-052` upheld and it must not be touched.** Read at its line before this ADR was written, precisely because a commit message in the history points at it.
- **[M01](../plans/M01-rules-engine.md) section 12's traceability row** "Floor locks at initial balance plus X | R-15, CV-12 | RE-U-015, GS-015, GS-016, RE-P-02". It carries no claim, only citations, and adding `GS-024` there is a coverage edit rather than a correction.

### 5. Consequences

- **No engine file changes. No fixture changes. No test assertion changes.** `CI-03`'s red set is empty before this ruling and empty after it. The tree is the thing that was right; four documents and one pseudocode block were the things that were wrong.
- **`RE-P-15` becomes writable against a stated block** rather than against a block it would contradict. Before this ruling, writing `RE-P-15` faithfully to section 3.6 produces a test that fails on `GS-064`'s shape.
- **[STATE](../STATE.md)'s open residue closes.** The entry at the `ADR-054` block is replaced by this ruling rather than deleted, so the question stays findable from where it was raised.
- **`ADR-052`'s application is completed.** Its section 5 table is now applied in full, three rows by session 55 and the fourth here. **The lesson is the one this ADR is named for**: an amendment table that enumerates locations does not find restatements, and this corpus restates heavily by design. **A ruling that refutes a sentence should grep for the sentence**, which is a cheaper habit than a gate and is what found four of these five.
- **The trader-facing published fact is unaffected**, for the reason `ADR-052` already gave: post-lock the floor is `size + $100` on every v1 plan, which is what the rules page says under either reading of why.

- **Founder approval (2026-08-18): the brief that commissioned this session ruled that both residues move by ADR and instructed that the rows the ruling names be amended, so the amendments above are applied rather than proposed.** The authority differs by half and the difference is stated rather than blurred. **Section 1 is [ADR-052](ADR-052.md)'s ruling, GRANTED 2026-08-17, applied to sites its own table missed**; it decides nothing new. **Section 2 is a new decision on the money path, explicitly delegated** ("pick one and say why"), and its reasoning is this session's and has not been read. **Recommended for a read rather than for a signature**: if section 2 is wrong, the amendment is one line and its reversal is one line, and the field it adds is already merged, already pinned by `RE-U-025` and unreachable by any golden fixture, so nothing turns on the timing.
