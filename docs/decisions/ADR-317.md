### 3. Obstacle 1. The ADR-176 ratchet, restated. **THE PROPERTY IS ONE STATEMENT OF THE SPLIT, NOT A LOCATION**

[`payouts.test.ts`](../../apps/api/test/payouts.test.ts), inside `describe('ADR-176: the request path holds no ledger handle')`, carried a case whose two assertions were, verbatim:

```
    expect(CODE).toMatch(/export function lt01\(/);
    expect(ADMIN).toContain("import { PAYOUT_ENDPOINT, lt01 } from './payouts.ts';");
```

Its block comment states the purpose in its own words: *"`lt01` must STAY exported here and `admin-payouts.ts` must keep importing it, because the alternative to one statement of `debit trader_withdrawable / credit trader_wallet / credit fees_revenue` is two of them, which is ADR-092 section 5's hazard on the money path. A session that 'finished' ADR-176 by moving `lt01` out and letting each door write its own goes red on the second case."*

**THE CLAUSE THAT DECIDES THIS IS "AND LETTING EACH DOOR WRITE ITS OWN".** What the pair protects is that the split is stated **once in this repository**. A move to `@merit/ledger` where both doors import it back preserves that exactly; two doors each writing their own destroys it. **The letter of the case fails and its purpose survives**, and the reason the letter cannot survive is [ADR-305](ADR-305.md)'s `F2`: a declaration pinned inside `apps/api` is a declaration `apps/worker` must either reach illegally or transcribe a second time, which is the very hazard the pin exists to prevent.

**THE TWO CASES WERE NOT DELETED. DELETING THEM WOULD HAVE BEEN WEAKENING A GATE TO PASS IT AND IS REFUSED.** They are replaced by one case saying the same property as a **count**:

```
    expect(declaring).toEqual(['payout.ts']);
    expect(LEDGER_INDEX).toMatch(/export \{[^}]*\blt01\b[^}]*\} from '\.\/payout\.ts';/);
    expect(CODE).not.toMatch(/\bfunction lt01\(/);
    expect(ADMIN_CODE).not.toMatch(/\bfunction lt01\(/);
    expect(ledgerSpecifiers(CODE)).toContain('lt01');
    expect(ledgerSpecifiers(ADMIN_CODE)).toContain('lt01');
```

where `declaring` is every `.ts` file under `packages/ledger/src` whose comment-stripped source declares a `function lt01(`, and `ledgerSpecifiers` reads the `@merit/ledger` import **block** rather than one line, because the specifier list is prettier's to wrap.

**WHY IT IS NOT WEAKER, STATED AS THE DIFFERENCE RATHER THAN AS AN ASSURANCE.**

| | Old pair | New case |
|---|---|---|
| Files it can see | **two**: `payouts.ts`, `admin-payouts.ts` | **three**: those two plus the whole of `packages/ledger/src` |
| A second `lt01` in `packages/ledger` | **invisible.** Nothing in it looked there | **red.** The census is `toEqual(['payout.ts'])` over a walked directory |
| A second `lt01` in `payouts.ts` | invisible; the case only required at least one | **red** |
| A second `lt01` in `admin-payouts.ts` | red, indirectly: the import string would have had to go | **red**, directly |
| A door that stops importing it | red | red |

**The one thing the old pair asserted that the new case does not is the LOCATION of the declaration**, and that is the thing this row was dispatched to change. Everything the old pair asserted about the COUNT, the new case asserts over a strictly larger set of files.

**THE HEADER COMMENT WAS REWRITTEN RATHER THAN LEFT TO BE READ AGAINST A CASE THAT NO LONGER MATCHES IT**, and it quotes the old assertions in full so a later reader can see what was pinned and judge the trade without a `git log`.

### 4. Obstacle 2. `PayoutMoneyError` had to go somewhere, and it went under its own name

`export class PayoutMoneyError extends Error` was declared in [`routes/payouts.ts`](../../apps/api/src/routes/payouts.ts) with `name = 'PayoutMoneyError'`, and it is thrown at **two** sites: `centsToJson`, which is a JSON-boundary concern, and `lt01`'s `INV-M5-03` refusal, which is ledger arithmetic. A package may not import from an app, so the class could not stay where it was and be thrown from the new home.

**THE MEASUREMENT FIRST, BECAUSE THE CHOICE TURNS ON IT.** `grep -rn PayoutMoneyError` across `apps` and `packages` returned **exactly four lines**: the declaration, the `name =` line and the two throws. **Nothing imports it. Nothing catches it**, by class or by `.name`, and `apps/api`, `apps/admin`, `apps/portal`, `apps/site` and `apps/worker` were all in that walk. `packages/ledger/src` declared **no error class at all**; its own style is `Error`, `TypeError` and `RangeError` thrown bare.

**THE THREE CANDIDATES, AND WHY THE FIRST WON.**

| | What it costs | What it changes |
|---|---|---|
| **Move the class, keep the name, re-export from `payouts.ts`** | a `Payout`-named class lives in a double-entry library, and `centsToJson` reaches into `@merit/ledger` for its error | **nothing.** One class, one name, both throw sites unchanged |
| Declare a ledger-side error, leave `PayoutMoneyError` for `centsToJson` | tidier by concern | the thrown class and `.name` at a **money-path** throw site |
| Throw a bare `Error` from `lt01`, matching the package's style | tidiest, no new class | the same, and drops the name entirely |

**THE FIRST IS TAKEN.** The row is code motion with no behaviour change; a class and its `.name` are observable on a thrown value whether or not anything reads them today, and "nothing catches it" is a fact about this tree at this moment rather than a licence. **Taking a tidiness ruling inside a motion ruled to change nothing is how a motion stops being one.**

**THE COST IS REAL AND IS NOT ARGUED AWAY.** The word `Payout` reads oddly from inside `packages/ledger`, and a JSON serializer in `apps/api` now imports its error from a library that knows nothing about JSON. Against that: the class's own docstring is *"Raised when a value on the money path is not integer cents"*, and `packages/ledger` is the module whose stated guarantee is that money is integer cents as `bigint` everywhere. **Splitting the two throw sites onto two classes is a legitimate later ruling**, it is named as available in the class's docblock, and it is not this row's.

**THE SURFACE OF `payouts.ts` IS UNCHANGED**: both `PayoutMoneyError` and `lt01` are re-exported from it by name, so no importer anywhere had to move for either.

### 5. The obstacle no row named: `LT-06`'s wallet-leg census went red on arrival

[`lt06-approval-builder.test.ts`](../../packages/ledger/test/lt06-approval-builder.test.ts) asserts that the wallet leg is *"stated ONCE in the whole of `packages/ledger/src`"*, over a walked directory, with this predicate:

```
const matchesWalletLeg = (line: string): boolean =>
  line.includes("identityAccount('trader_wallet'");
```

**`LT-01` NAMES THAT ACCOUNT TOO, AS A CREDIT, WHERE `LT-06` DEBITS IT.** `lt01`'s trader half is `identityAccount('trader_withdrawable', ...) -> identityAccount('trader_wallet', ...)`. So arriving in this package made the census two, and the case expected one. **It is a false positive of a real gate**: `payout.ts` holds no second statement of `LT-06`.

**THE PREDICATE IS UNTOUCHED, AND NARROWING IT WAS THE TEMPTING REPAIR.** A predicate narrowed until the new site falls outside it is a predicate that stops seeing sites it used to see, which is weakening a gate to pass it. What changed instead is the ASSERTION: the census is now stated **site by site**, `reversal.ts` for `LT-06`'s debit leg and `payout.ts` for `LT-01`'s credit leg, each with its reason, so a **third** occurrence anywhere under `src/` is still red on arrival.

**AND `LT-06` GAINED A PIN IT DID NOT HAVE.** The old case proved the population of one account's constructions and inferred `LT-06` from it. A second assertion now counts `firmAccount('withdrawals_in_flight')`, which is `LT-06`'s **other half** and belongs to no other transaction in this package: it is one line, in `reversal.ts`. **A second `LT-06` under any name, spelling its debit leg any way at all, is now red on the credit it cannot avoid.** The case is stronger than it was and it covers a case the old one could not.
