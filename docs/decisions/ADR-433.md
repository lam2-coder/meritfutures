### 5. The widening, and precisely what the probe asserts after it

**ONE HELPER, TWO INSTANCES, AND NO SECOND MECHANISM.**

```js
function assignmentTo(name) {
  return new RegExp(String.raw`(?<![=!<>])=\s*\b${name}\b`);
}
```

applied to the whole prepared body of each file, beside the punctuation proxy rather than instead of it.

**WHAT IS ASSERTED AFTER THIS ROW THAT WAS NOT ASSERTED BEFORE IT, IN ONE SENTENCE.** *The name standing as the whole right-hand side of an assignment is an install.* **One shape added to the value-position class and none removed**, which is why every [ADR-431](ADR-431.md) case stands unchanged beside the new ones and why the four verdicts over the real tree do not move.

| candidate | verdict | why |
|---|---|---|
| the name preceded by `=` and whitespace | **TAKEN** | it names the thing being asserted. Assignment position is a value position by TypeScript's own grammar |
| the name followed by `;` or end of line, which is `replay-audit-src-caller`'s existing proxy three artifacts down | **REFUSED, AND THE REFUSAL COSTS NOTHING TODAY** | it is a STATEMENT-END proxy and not an assignment proxy. It admits `export type W = typeof TRANSACTION_EVENT_WRITER;`, a TYPE position that installs nothing, and any prose line ending on the name. Measured over the shipped scope both readers report the same **ZERO** files, so this was chosen on what it will admit rather than on what it admits now |
| drop the punctuation proxy, treat any surviving occurrence as a value | **REFUSED, AND [ADR-431](ADR-431.md)'S MEASUREMENT REPRODUCES** | re-derived here: `present` on **five files under `apps/worker/src`** whose refusal STRINGS name the writer in order to deny it. Section 7 lists them |
| the name on the LEFT of the `=` | **REFUSED, AND IT IS THE LIKELIEST WAY TO WRITE THIS WRONG** | that is a DECLARATION and not an install. Section 8 seed 8 |

**THE LOOKBEHIND IS NOT DECORATION AND ITS VALUE IS MEASURED.** `[=!<>]` before the `=` excludes `==`, `===`, `!=`, `!==`, `<=` and `>=`: a COMPARISON against the name asserts nothing is installed and is frequently the line saying so. The shipped scope carries **2,223** comparisons against a bare identifier and **50** against a SCREAMING_CASE name. **NONE names either of these two names today**, so the lookbehind buys nothing on this tree this morning and the shape is dense enough that it will. `=>` is excluded structurally rather than by the lookbehind, since `>` is not whitespace, and the scope carries **936** arrow bodies returning a bare identifier.

**A COMPOUND ASSIGNMENT IS ADMITTED ON PURPOSE.** `||=`, `??=` and `+=` put a non-excluded character before the `=` and are assignments.

**IT REACHES TWO PROBES AND THAT IS NAMED RATHER THAN LEFT TO BE DERIVED**, on [ADR-431](ADR-431.md) section 10 row 4's own precedent for the same pair. `worker-queue-door-caller` carries the identical three characters on `LIVE_QUEUE`, so `const q = LIVE_QUEUE;` was the same miss one probe over. **Repairing one and not the other would leave the file holding two answers to one question**, which is that entry's row 2 and is a defect this file already carries once.

**NO VERDICT ON THE REAL TREE MOVED.** All four caller probes, before and after: `worker-queue-door-caller` **`present`** both sides, `event-sink-caller` **`absent`** both sides, `provisioning-saga-caller` **`absent`** both sides, `replay-audit-src-caller` **`absent`** both sides. `RI-35` reports **PASS** both sides, and all three seeds in section 4 report **`present`** with **1 finding** after.

### 12. Approval

**Status `proposed`. The approval line below is UNSIGNED and merging is not signing.** [ADR-431](ADR-431.md), whose section 10 this row answers, is itself `proposed` and unsigned, as are [ADR-415](ADR-415.md) and [ADR-410](ADR-410.md) behind it.

- **What a founder read adds and this entry cannot.**

  **THE FIRST DECISION IS THE ONE THIS ROW EXISTS TO PUT.** [ADR-431](ADR-431.md) asked whether a repair that makes a check EASIER to satisfy is ever safe, and answered that the question is badly put. **This row is its mirror and needs a different answer: when is a change that makes a check HARDER to satisfy a repair rather than a new gate?** Nobody signed off on a probe that reads assignments; a row widened it because a sibling entry said the hole was there.
