## ADR-207: `rule_states` stores `lifetime_settled_cents`, `breached` and `breach_kind`, and the state hash is the question this entry declines to answer  (2026-08-29, status: proposed)

**`RuleState` requires three fields that no table in this estate could hold, and the port that refuses because of it is WIRED IN PRODUCTION.** [`start.ts:76`](../../apps/api/src/start.ts) installs `databaseAccountReads` and its `readEligibility` rejects on `ELIGIBILITY_BLOCKER` ([`account-reads.ts:851`](../../apps/api/src/routes/account-reads.ts)) naming `lifetimeSettledCents`, `breached` and `breachKind`. **A trader asking whether they are eligible today gets a rejection because a column does not exist.** [`0065_rule_state_lifetime_and_breach.sql`](../../packages/db/migrations/0065_rule_state_lifetime_and_breach.sql) declares them. `0015_rule_states.sql` is merged and is superseded **by addition**, never edited (constitution E2).

- **Origin:** [ALLOCATION](ALLOCATION.md) row `207`, session **398**, dispatched as `claude/rule-state-columns`. Migration number `0065` was reserved with it and is **SPENT**.

- **MONEY PATH.** The columns are the lifetime money total the ladder and `INV-17`'s liability bound are stated against, and the verdict that closes an account. [**`E2`**](../../MERIT_BUILD_MASTER_PROMPT.md) **READ IS OWED.** The entry ships `proposed` with an **UNSIGNED** approval line. **Merging is not signing.**

- **WHAT IS MEASURED, WHAT IS DERIVED, AND WHAT IS JUDGED.** That the three columns are absent from the whole estate, that `rule_states` holds zero rows, and that the install counts move by exactly four constraints is **MEASURED**, live, in section 2. What is **JUDGED** is `text` over an `ENUM` (section 4) and storing a derivable column anyway (section 6).

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every claim below was read at its own file. The dispatch's premises survived; what did not survive is a count inside [ADR-206](ADR-206.md) and three line citations inside the `BLOCKED` map, both in section 10.

### 3. THE RULING

| Column | Type | Constraints |

### 4. `text` with a `CHECK` rather than a new `ENUM` type, on three measured reasons

The estate has thirteen enum types and one of them, `account_phase` ([`0001_extensions_and_enums.sql:45`](../../packages/db/migrations/0001_extensions_and_enums.sql)), is the engine's `Phase` union exactly. That is the argument FOR an enum and it is the one this entry declines.

1. **Every one of the thirteen is created in `0001` and no migration since has added one.** An enum in `0065` would be the first, which makes it a ruling about where new estate vocabularies live, and nobody has taken that ruling.
2. **This table already stores an engine union as bare `text`.** `rule_states.phase` is `text` while `account_phase` exists and is used by exactly one column, `accounts.phase`. An enum here would make the table internally inconsistent, one engine union as a type and another as bare text, which is worse than either uniform answer.
3. **A `CHECK` narrows.** Constitution E2's own mechanism is that "a constraint moves by `DROP` and re-`ADD` under one name", which is exactly how this vocabulary would be corrected. An enum value can be added and **can never be removed**, so an enum makes a closed vocabulary widenable and uncorrectable, which is the wrong way round.

**THE COST IS A COPY AND IT IS PAID WITH A COMPARATOR.** Three literals now sit in `0065` and three in `types.ts`, which is `FM-16` and which this corpus has found four times. [`rule-state-breach-vocabulary.test.ts`](../../packages/db/test/rule-state-breach-vocabulary.test.ts) derives both sides and compares them member for member **and in order**, carries no list of its own, and throws rather than passing vacuously if either parse returns nothing. Section 8 watches it fail.

### 5. THE STATE HASH IS THE QUESTION THIS ENTRY DECLINES TO ANSWER, AND SAYING SO IS THE POINT

[ADR-026](ADR-026.md) C-07 fixes **nineteen** hash inputs. `0035` added a column and **ruled it excluded** on [ADR-047](ADR-047.md)'s own reason, and the design record's line reads "The nineteen stay nineteen". **This entry adds three and rules neither way**, and the difference from `0035` is that there is no reason of that kind to give:

| Excluded today | Its reason |
|---|---|
| `context_gates` | not replayable, which is the whole of `SD-06` (`INV-23`) |
| `engine_version` | a version-like **input** to the fold, not a fact it produced |
| `calendar_revision_id` | the same, on [ADR-047](ADR-047.md) |
| `computed_at` | wall clock, not state |

**None of the four reaches the three new columns.** `lifetime_settled_cents`, `breached` and `breach_kind` are replayable facts the fold produced, which is precisely what `phase` (input 3) and `payouts_settled_count` (input 15) are, and those are hashed. **On the merits they belong in the hash.**

**WHAT THIS ENTRY DOES INSTEAD, AND WHY.** The only executable copy of the list is `HASHED_COLUMNS` at [`hash.ts:557`](../../packages/rules-engine/src/hash.ts), with `HashedState` at [`:519`](../../packages/rules-engine/src/hash.ts) typed as a `Pick` of eighteen `RuleState` fields. Both are in `packages/rules-engine`, which this fence does not hold, and moving the list is also an amendment to `ADR-026` C-07. **Ruling it here would declare a hash input set that no code computes**, which is worse than the gap: the prose and the executable copy would disagree, and `C-07` exists because an implicit input set is one that changes meaning silently. So `0065` writes the three into the `state_hash` column comment as **UNRULED**, in those words, rather than as excluded, and a comment claiming them as excluded would read as a ruling nobody made.

**THE COST OF DECIDING IT IS ZERO TODAY AND RISES WITH THE FIRST ROW.** The table holds zero rows and no writer exists, so a change to the hashed set right now invalidates nothing. Once `B5` term 1 lands and rows accumulate, adding an input means every stored hash is wrong and the nightly replay audit diverges on every account at once, which is the 5,000-page morning `ADR-047` exists to prevent, arrived at from the other direction. **This is the first item on the approval block.**

### 6. `breached` is derivable from `breach_kind`, and is stored anyway

**Read at every site the engine writes the pair**, which is what the reservation asked for rather than an assertion that it is obvious:

| Site | Writes |
|---|---|
| [`advance.ts:124`](../../packages/rules-engine/src/day/advance.ts) | the opening state: `0n`, `false`, `null` |
| [`advance.ts:321`](../../packages/rules-engine/src/day/advance.ts) and [`:322`](../../packages/rules-engine/src/day/advance.ts) | `true` with `breach.kind`, under a `kind !== null` guard |
| [`progression.ts:165`](../../packages/rules-engine/src/day/progression.ts) and [`:166`](../../packages/rules-engine/src/day/progression.ts) | **EXPIRY**: `false`, `null`, on a row whose phase is `closed` |
| [`breach.ts:75`](../../packages/rules-engine/src/day/breach.ts) | `false` with `kind: null` |
| [`breach.ts:88`](../../packages/rules-engine/src/day/breach.ts) | `true` with a total `BreachKind` |

**`breached` is true exactly when the kind is not null, at all five.** So it is derivable, and it is stored anyway, for one reason:

**THE REDUNDANCY IS THE DETECTOR, AND THE ALTERNATIVE FAILS SILENTLY IN THE WORST DIRECTION.** The realistic adapter defect is a mapping that carries one of the two fields and drops the other. Against `rule_states_breach_flag_matches_kind` that row is **REFUSED**, loudly, at the store. Against a `GENERATED ALWAYS AS (breach_kind IS NOT NULL) STORED` column, which is a real idiom in this schema and was the tempting answer, the same omission **writes a row saying a breached account is not breached**, silently, and the account stays open. A generated column makes the disagreement unrepresentable by making one half unwriteable, which is not the same thing as making the mistake visible.

**It is also this table's own established idiom rather than a new one.** `rule_states_settlements_imply_anchors` is `(payouts_settled_count = 0) = (payout_anchor_day IS NULL)`: two stored facts bound by an equality, on `0015`'s stated argument that a half-populated settlement is "the state the two-column split exists to make visible rather than to permit".

**`phase` DOES NOT DECIDE IT, AND THAT IS WHY THE COLUMN IS NOT REDUNDANT WITH ONE THAT EXISTS.** An expired account is `closed` and **not** breached, and `progression.ts`'s own comment says why: "a consumer reading `breachKind` to explain the closure would otherwise be told a drawdown type that never happened."

### 7. Three constraints refused, each on evidence

**1. The biconditional on the lifetime total.** `(payouts_settled_count = 0) = (lifetime_settled_cents = 0)` is the tidy-looking shape and it mirrors `rule_states_settlements_imply_anchors` exactly. **It is unsound against this estate.** [`0010_payouts.sql:54`](../../packages/db/migrations/0010_payouts.sql) declares `approved_cents bigint NOT NULL CHECK (approved_cents >= 0)`, so a settled payout of exactly zero cents is admitted, and [`settle.ts:161`](../../packages/rules-engine/src/payout/settle.ts) accumulates `state.lifetimeSettledCents + fact.approvedCents` beside `payoutsSettledCount + 1`. One such settlement gives count 1 and lifetime 0, which the biconditional refuses. **What lands is the implication that holds in both directions of the estate's own guarantees**: no settlements, no lifetime total. The zero-cent row is watched landing as ACCEPTANCE 4 in [DELTA_MANIFEST section 30](../../packages/db/DELTA_MANIFEST.md).

**2. `breached` implies `phase = 'closed'`.** True of the engine today at `advance.ts:319`. Refused because `phase` carries **no vocabulary constraint at all** (section 9): a `CHECK` binding a ruled column to an unruled open text vocabulary is a constraint whose other operand nothing defends, and it would have to be revisited the moment `phase` is closed properly.

**3. `INV-17`'s bound, `lifetime_settled_cents <= ladder * max cap`.** Refused because it is not row-local. The cap schedule reads `plan_version_sizes`, and a `CHECK` cannot see it. Recorded in the column comment rather than dropped, so the next reader finds the bound named and told where it is not enforced.

  **What a founder read adds and this entry cannot.**

  **THE FIRST THING TO DECIDE IS SECTION 5, BECAUSE IT IS THE ONLY THING THIS ENTRY LEAVES OPEN AND ITS PRICE GOES UP.** `ADR-026` C-07 fixes nineteen hash inputs and this migration adds three replayable columns that are not among them and are not excluded either. **On the merits they belong in the hash**, for the same reason `phase` and `payouts_settled_count` are in it, and this entry does not rule it because the executable list lives in `packages/rules-engine` and a declared hash the code does not compute is worse than an open question. **The decision is free right now**: zero rows, no writer. The judgement is that a redundant column bound by an equality `CHECK` catches the realistic adapter defect loudly, where a generated column would absorb the same defect and write a row saying a breached account is not breached. **A founder who prefers one fact over two should say so now**, because after rows land the change is a rewrite of a column rather than a choice.

  **THE THIRD IS SECTION 4, WHICH CHOOSES `text` OVER AN `ENUM` FOR A CLOSED VOCABULARY.** The three reasons are checkable in a minute: run `grep -rn "CREATE TYPE" packages/db/migrations` and see all thirteen in `0001`; look at `rule_states.phase` and see this table already storing an engine union as bare text; and note that an enum value can never be removed. **If the house rule is that closed vocabularies are enum types, `0065` should be superseded before rows land** and section 9's `phase` gap should be closed in the same slice, because those two decisions are one decision.

  **WHERE THIS ENTRY IS MOST LIKELY WRONG, named rather than left for a reader to find.** **The defaults.** `lifetime_settled_cents DEFAULT 0` and `breached DEFAULT false` are the engine's own opening state and they are also **forced**: five committed probe scripts insert into this table naming none of the three, so a `NOT NULL` without a default turns sixteen CI probes red.
