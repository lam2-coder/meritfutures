### 3. `submitCreative`, the obstruction no version of the entry has named

`affiliate_creatives` is registered `derived` via `affiliates` on `affiliate_id` ([`scope.ts:1209`](../../packages/db/src/scope.ts)). Every write verb in the estate was checked against it rather than assumed:

| Verb | Key type it takes | Reaches this table |
|---|---|---|
| `ScopedTx.insert` ([`scoped-db.ts:3607`](../../packages/db/src/scoped-db.ts)) | `OwnedTableKey` | no, the table is `derived` |
| `ScopedTx.insertUnder` ([`scoped-db.ts:3616`](../../packages/db/src/scoped-db.ts)) | `ParentedTableKey`, which is `Extract<DerivedTableKey, 'sessions'>` ([`scoped-db.ts:2149`](../../packages/db/src/scoped-db.ts)), **A CLOSED LIST OF ONE** | no |
| `ScopedTx.insertAsParty` | `PartyWritableTableKey`, a subset of `PairTableKey` | no, the table is not `pair` |
| `FirmTx.insert` ([`scoped-db.ts:3808`](../../packages/db/src/scoped-db.ts)) | `FirmTableKey` | no |
| `SystemTx.insert` | every `TableKey` | **not reachable at all**, see below |

**`ApiDb` EXPOSES NO SYSTEM HANDLE**, and that is the half worth checking rather than assuming. Its five doors are `scoped`, `firm`, `resolution`, `establishment` and `publicLookup` ([`apps/api/src/db.ts:173`](../../apps/api/src/db.ts)), and only the first two are generic over a table key. `SystemReason` is `'nightly-batch' | 'operator-console'` ([`scoped-db.ts:271`](../../packages/db/src/scoped-db.ts)), and a trader-surface request handler is neither. [`routes/payouts.ts`](../../apps/api/src/routes/payouts.ts) already measured this exact wall for `ledger_entries` and recorded that a door in `apps/api/src/db.ts` returning such a handle *"would be `systemDb` under another name"*.

**NOTHING IN THIS TREE WRITES `affiliate_creatives`.** A search across `packages/**` and `apps/**` returns the schema declaration, the registry rule and one test's table-name map, and no writer.

**THE REFUSAL THIS METHOD SERVED CALLED IT A READ.** It was given `AFFILIATES_READABLE`: *"`affiliates` is scope class `owned` on `identity_id`, so this read has a door and no adapter has been written for it yet."* Both halves are wrong. It is a WRITE, and `affiliates` is not the table it writes. **A refusal is the one place a later session reads to find out what to build, and this one sent that session to write an adapter over a door that does not exist.**

### 4. `requiredDisclosure`, where this row's own first finding was WRONG

**This section exists because the falsification changed the ruling.** The first derivation had `requiredDisclosure` blocked too, on this reasoning: it reads `tos_versions`, which is `firm` ([`scope.ts:1481`](../../packages/db/src/scope.ts)); `firm` keys are excluded from `ScopedTableKey`; and `CATALOG_TABLE_KEYS` is a closed list ([`scoped-db.ts:3403`](../../packages/db/src/scoped-db.ts)) that does not carry it. **That would have made the count THREE and it is wrong.**

`ApiDb.firm()` returns a `FirmTx`, whose `rows`, `rowsWhere` and `rowAt` are generic over `FirmTableKey`, and `tos_versions` is one. Routes in this deployable already open that door. **The catalogue list bounds what a SCOPED transaction may read, not what the deployable may read**, and [ADR-113](ADR-113.md) clause 2 is why this method needs nothing narrower: the disclosure is read AFTER the row is written and is pinned to nothing, so a second transaction costs nothing.

**So the entry's verdict was right and its reason was followable to the wrong table**, which is a smaller defect than `submitCreative`'s and the same kind: an adapter written from that sentence would try to read the disclosure inside the caller's scoped transaction, and that does not compile.

**Recorded because the corpus's rule is that a refutation is worth more than a confirmation, and this one refutes this row rather than the dispatch.**

### 6. Whether the port can be served, and the answer is PARTLY

| Endpoint | Methods | Servable |

### 7. Whether the default refuses loudly enough, which the dispatch asked and the answer is YES

**`UNWIRED_AFFILIATE_BACKEND` has no code path that returns a value.** `unwired()` returns `() => Promise.reject(new AffiliateBackendUnwired(method, because))`, so every method REJECTS, with a distinctly named error class carrying a per-method reason. `unavailableWhenUnwired` catches **only** `AffiliateBackendUnwired`, rethrows anything else, logs at `error`, and serves **503**.

**There is no configuration under which this port quotes a number.** That is the shape the dispatch asked about and it is the right one: a plausible-looking wrong commission is indistinguishable from a real one, and this default is distinguishable from a real one on every call.

**THE HAZARD ON THIS PORT WAS NEVER THE VALUE. IT WAS THE REASON.** The refusals fail closed and always did; what they were wrong about is what a session must build to make them stop, and that is the failure this row found twice in one message set.

### 8. Why no gate caught it, and what was built instead

**`RI-14` COULD NOT HAVE CAUGHT THIS AND THE SHAPE IS WHY.** That invariant is *"no reason claims a named thing does not exist while the tree exports it"* ([ADR-214](ADR-214.md)), widened to schema objects. It is a claim of **ABSENCE** measured against a **PRESENT** thing. `AFFILIATES_READABLE` claimed a door was **PRESENT** while the tree has none. **The same defect inverted, and outside every mechanical check in this repository.**

**AND `RI-14` AND A PROSE-MATCHING CASE ARE IN DIRECT CONFLICT, WHICH IS SHARPER THAN THE STALENESS [ADR-324](ADR-324.md) NAMED.** That row found that a case matching the WORDS goes stale in silence. What this row found is worse: `RI-14` requires a retired sentence to be **KEPT beside its correction**, so the moment a false *"this read has a door"* is repaired, the repaired message QUOTES the false sentence and the matched words are still in the string. **The convention that makes the corpus honest guarantees the case can never go red.** Measured rather than reasoned: after both refusals were repaired, [`affiliate-stats-obstructions.test.ts`](../../apps/api/test/affiliate-stats-obstructions.test.ts)'s case *"four methods say a door exists and an adapter does not"* was **still green**.

**SO THE MESSAGE'S OWN VOICE IS SEPARATED FROM WHAT IT QUOTES**, using the corpus's own convention rather than a new one: a retired clause is carried inside DOUBLE QUOTES at every site in this module, so stripping the quoted runs leaves what the port asserts TODAY. The expectation then comes from the key sets in `scoped-db.ts`. **A widening of `ParentedTableKey` or `CATALOG_TABLE_KEYS` turns the matching case red on the day it happens.**

### 9. Open questions, which are the founder's and are recorded as options rather than values

**NO COMMISSION RATE, ATTRIBUTION WINDOW, PAYOUT THRESHOLD, CURSOR OR URL IS INVENTED HERE.**

**OQ-358-01. The base URL `issueLink` mints against.** No environment variable in `apps/api/src` names one and [ADR-253](ADR-253.md) records that this method waits on *"an adapter and a base URL"*. Options: (a) a `MERIT_AFFILIATE_LINK_ORIGIN` variable on `operator-identity.ts`'s precedent, refusing when absent; (b) the existing public site origin, if one is already configured for the verify surface; (c) a `firm_parameters` row, which makes it changeable without a deploy and auditable. **Fail-closed on absence is assumed in all three and is itself reviewable.**

**OQ-358-02. What `statements`' cursor is keyed on.** [API_CONTRACT](../architecture/API_CONTRACT.md) section 1 rules pagination cursor-only with `{ data, next_cursor }`, `limit` max 100 default 25, and the contract itself records that *"the paging token's shape is not settled on this ref"*. Options: (a) the statement period, which is what an affiliate reads by; (b) `issued_at` plus the row id as a tiebreak; (c) the row id alone. **Void statements are returned by a scoped read deliberately, so whichever is chosen must be stable across a void.**

**OQ-358-03. Which widening `submitCreative` gets, and it is `packages/db`'s row rather than this one.** Options: (a) admit `affiliateCreatives` to `ParentedTableKey`, which is the narrowest change and is what the type was built for; (b) a named write door returning the created row, which is `attributionAffiliate`'s construction applied to a write; (c) rule the submission an operator act, which the module header already does for approve and reject. **(a) is not free**: `ParentedTableKey`'s docblock says the list is closed because the `derived` class contains one leg of a double-entry posting, so the argument for each admission is per table.

### 10. What is bound mechanically, so this ruling fails on good news

Every case below was falsified in both directions.

1. **A method claims a door in its own voice only where the key sets have one.** Reverting `submitCreative` to the retired constant turns **three** cases red.
2. **`submitCreative`'s refusal expires the day a write door appears.** Admitting `affiliateCreatives` to `ParentedTableKey` turns **three** cases red.
3. **`requiredDisclosure`'s refusal expires the day the catalogue widens.** Admitting `tosVersions` to `CATALOG_TABLE_KEYS` turns that case red. **This case was tautological in its first draft** and passed under every value; the tautology was found by running the falsification rather than by reading the case, and is recorded because the case looked correct.
4. **The quoted-retirement stripper is pinned in both directions.** It must shorten exactly the two messages carrying a retirement and leave every other message non-empty. Neutering it turns **two** cases red.
5. **The key-set readers are pinned for non-vacuity**, so a parser that silently matched nothing cannot make the cases above pass by accident.

### Approval

**Status: `proposed`. The approval line is UNSIGNED and merging is not signing.** No `status` field anywhere moves and nothing is marked `accepted`. **`E2` READ OWED**, and it is inherited as well as owed: [ADR-321](ADR-321.md), [ADR-324](ADR-324.md), [ADR-304](ADR-304.md) and [ADR-253](ADR-253.md) are each `proposed` and UNSIGNED, and this entry rests on all four.

  **What a founder read adds and this entry cannot.**

  **THE FIRST THING TO CHECK IS THE ONE NO GATE CAN: WHETHER A PARTIAL SERVE SHOULD HAVE BEEN TAKEN.** Section 6 shows two of the four endpoints reachable on doors that exist today, and this row declined both. The argument for declining is that a fail-closed default which refuses on all six is a different object from one that refuses on two, and that changing it on the same day its blocker inventory was found wrong is how a wrong inventory ships behind a green suite. **A reviewer could reasonably say that `GET /affiliate/statements` was owed and that the cursor question is the only thing standing in front of it.** If you rule that way, the row is a new number and this one is not edited.

  **THE SECOND IS WHETHER `submitCreative` SHOULD BE SERVED AT ALL FROM THE TRADER SURFACE.** Option (c) in `OQ-358-03` is not a fallback; it is a live reading of the module's own header, which already puts approve, reject and automatic withdrawal on the operator origin because `affiliate_creatives_decision_has_author` requires an author. **If a submission is also an operator-mediated act, the missing write door is a correct refusal rather than a gap**, and `POST /affiliate/creatives` is a contract row that wants re-arguing rather than an endpoint that wants building. **That judgement is not derivable from the schema and it decides whether a closed list gets widened.**

  **THE THIRD IS SECTION 8, AND IT IS THE PART A READ CHANGES.** This row asserts that `RI-14`'s keep-the-retired-clause rule and a prose-matching case cannot both work, and it repaired the conflict **at one file**. The same shape is available everywhere in this corpus that a retired sentence is quoted and a case matches words. **If you rule that this is an invariant rather than one file's problem, it is `RI-38` and it is a new row**, and the argument for waiting is that one site is not yet evidence of a class.

  **WHERE THIS ENTRY IS MOST LIKELY WRONG, named rather than left for a reader to find.** The claim that `requiredDisclosure` has a door rests on `ApiDb.firm()` being an acceptable authority for this read, and that is a JUDGEMENT the key sets do not make: `FirmTx` reaches every `firm` table in the estate, and a handler that opens it for a `tos_versions` row holds, for the duration of that call, a door onto `price_floors`, `firm_parameters` and every other row the firm owns. **Nine call sites in this deployable already accept that trade and none of them argued it in writing.** If you rule that a disclosure read owes a narrower door, then `requiredDisclosure` joins the other two, the count is THREE, and section 4's refutation of this row's own first finding is itself refuted.
