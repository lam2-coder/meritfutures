### 3. The dispatch's headline premise is false, and the file says so about itself

The dispatch states, in bold, that *"`EventSink` has no producer"*. **IT HAS ONE.** [`apps/api/src/events.ts`](../../apps/api/src/events.ts) declares `makeEventSink`, which composes a sink over an injected writer and clock, and `TRANSACTION_EVENT_WRITER`, which is the writer, performing `assertEventInsertTx`, then `encodeCentsForStorage`, then `assertSerialisablePayload`, then the insert, and refusing a write that did not return exactly one row. That file's own header says it in terms: *"THE INSERT IS STILL A PORT AND THE PORT NOW HAS AN ADAPTER, WHICH THIS SESSION COMPOSED"*, and names [ADR-348](ADR-348.md) as the entry.

**THE PRODUCER IS COMPLETE FOR WHAT IT CLAIMS, AND THAT WAS DERIVED RATHER THAN READ.** `EVENT_CATALOGUE` was parsed mechanically on this commit and carries **ten** rows: `payout.requested`, `payout.approved`, `payout.blocked`, `payout.held`, `payout.hold_released`, `payout.hold_enforced`, `payout.freeze_expiring`, `wallet.withdrawal_halt_released`, `flag.raised` and `detector.run_completed`. The header's claim that *"THE SET IS THE NAMES THIS TREE HAS A PRODUCER FOR, AND IT IS TEN"* reproduces exactly.

**SO STEP 3 OF THE DISPATCH, `if a producer is buildable today, build it`, IS DISCHARGED BY A ROW THAT ALREADY RAN, AND BUILDING A SECOND ONE WOULD BE THE DEFECT.** The dispatch also forbids wiring a sink against nothing, and a second producer beside the first is that failure in a costume: an install nothing can exercise, plus a duplicate nothing falsifies.

### 5. The refusal told its reader the blocker backwards

`EventSinkUnwired`'s message read, after correctly naming the install as the missing thing:

> which is a decision about a deployment rather than a file on disk

**BOTH HALVES ARE FALSE AND THE SENTENCE IS THE FIRST THING A WIRING SESSION READS.**

It is **not** a decision a deployment can take. An install needs one caller holding this module **and** a `SystemTx`, and no deployable in this tree holds both: `apps/api` holds the module and opens no system door, `apps/worker` holds the handle and is refused this module three separate ways, by `RI-04`, by `node-linker=isolated`, and by its own `test/event-sink.test.ts`. There is no deployment configuration that closes that.

And the missing thing **is** a file on disk. It is an address under `packages/` that both arrows can name, which is exactly what [ADR-104](ADR-104.md) ruled for `packages/ledger` when two deployables had to post and `RI-04` forbade an app depending on an app.

**THE COST OF LEAVING IT WAS NOT HYPOTHETICAL.** A session dispatched to wire this sink reads that clause and goes looking for a deployment to configure. The dispatch this row answers did exactly that: it asserts the producer is missing and asks for one to be built, when the producer has existed for five rows and the thing missing is an address.

The clause is corrected in place and **kept beside its correction**, on `RI-14`'s rule that a refuted claim may stay and must say so. `events.test.ts`'s existing case already states the discipline for this exact string, that *"the assertion follows the message each time rather than being deleted"*, so it follows it here.

**SO THE RELOCATION NEEDS NO NEW MANIFEST EDGE AND NO `VG-12` ADMISSION.** Every prior record left the reader to assume a new package a founder must create and admit. That is one available shape and it is the expensive one; the cheap one is a module under an address both deployables already depend on, and `packages/ledger` is [ADR-104](ADR-104.md)'s own precedent for precisely this shape.

**THIS ROW DOES NOT TAKE IT, AND THE REASON IS THE FENCE AND NOT THE PRICE.** `packages/**` and both app manifests sit outside this row's fence, and the dispatch's instruction on that is explicit. What changes is that the next row to hold that fence inherits a costed move rather than an open question.

**AND THE MEASUREMENT IS BOUND SO IT CANNOT ROT.** Section 4 of [`event-placement.test.ts`](../../apps/api/test/event-placement.test.ts) asserts both halves as separate cases, because they fail in opposite directions: the shared address must keep existing, and no `packages/*` must yet hold a producer. **The second fails on GOOD NEWS**, which is `RI-35`'s `event-sink-caller` discipline applied to the other side of the fence, and it is the leg worth having.

### 9. The vocabulary, which is a bigger obstruction than the handle

**THE DISPATCHER'S SUPPLEMENT ASKED WHETHER THE PRODUCER WOULD ACCEPT WHAT ITS CALLERS ACTUALLY EMIT, AND THAT QUESTION HAS A WORSE ANSWER THAN THE HANDLE QUESTION.** [`apps/worker/test/event-sink.test.ts`](../../apps/worker/test/event-sink.test.ts) was read, as instructed, and it is the closest thing in this tree to a specification of this file's subject: **nine** emit call sites across **four** modules, **nine** distinct names, with the name split against the catalogue derived at run time rather than typed.

### 10. Approval

- **What a founder read adds and this entry cannot.**

  **THE FIRST THING TO DECIDE IS WHERE THE PRODUCER LIVES, BECAUSE IT IS THE ONLY DECISION THAT CHANGES THE TREE.** Section 6 shows the move needs no new package and no new manifest edge, and that removes the cost argument for leaving it. It does not remove the judgement. Putting an event producer inside `@merit/ledger` is cheap and is a category error; putting it in a new `packages/events` is correct and spends a `VG-12` admission plus two manifest lines. **This entry deliberately does not choose**, because the choice is about what this estate's package boundaries MEAN and no measurement settles that. What it removes is the excuse that the question is expensive.

  **THE SECOND IS THAT A DISPATCH ASKED FOR SOMETHING THAT ALREADY EXISTED AND NOTHING IN THIS TREE COULD TELL IT SO.** The producer landed five rows ago and the row dispatched to build one was told, in bold, that there was none. The refusal message is the one artifact a wiring session reads first, and it was pointing at the wrong kind of blocker the whole time. **No gate reaches this and none could.** A founder deciding how much of this programme's cost is spent re-deriving state that a message could have carried should read section 5 before section 3.

  **THE THIRD IS THAT THE SHARPEST LEG THIS ROW WRITES FAILS ON GOOD NEWS**, and a founder should know that is deliberate. The day a `packages/*` module composes a sink, [`event-placement.test.ts`](../../apps/api/test/event-placement.test.ts) section 4 turns RED and the row that made it true is the row that gets told. That is `RI-35`'s discipline and it is the only kind of check that catches a header sentence quietly becoming false.
