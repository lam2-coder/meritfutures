## ADR-235: The code is the only credential, and the corpus asserted its strength in five places while no function in the repository produced one  (2026-08-29, status: proposed)

**[ADR-231](ADR-231.md) put `GET /verify/:code` into service this afternoon: public, unauthenticated, and answering a question about Merit's own payout book to whoever presents a code.** The code is the entire predicate. `INV-M11-05` fixes it at *"128 bits of entropy, no sequence"* ([`M11:54`](../plans/M11-certificates-social-proof.md)); [`M11:246`](../plans/M11-certificates-social-proof.md) says the entropy is the whole defence, *"the code space is not walkable, which makes the attack infeasible rather than merely rate limited"*; [`API_CONTRACT:1472`](../architecture/API_CONTRACT.md) and [`:1473`](../architecture/API_CONTRACT.md) each decline to inherit the catalog's rate budget because it *"is an enumeration budget on a 128-bit token"*; [`EC-091:3`](../edge-cases/EC-091.md) restates it a fifth time. Two shipped `.ts` files describe it as a property the deployment has.

**The measurement is not that the code was too short. It is that there was no code.** Nothing in `apps`, `packages`, `e2e` or `scripts` writes a `certificates` row, and no identifier resembling a certificate-code minter exists anywhere in the tree. Five documents describe the output of a function nobody had written, and the real entropy of a certificate code was not 128 bits and not 64 bits: it was undefined, because there was nothing to measure. Section 2 states the searches and their exit codes.

**So this entry does the second thing row `235` allowed rather than the first.** It reports the shortfall and fixes it: [`certificate-code.ts`](../../packages/db/src/certificate-code.ts) mints a code of **130** bits from `node:crypto`, and `RI-22` **executes that function on every `CI-01` pass and measures what comes out**. The threshold it measures against is read out of the five documents above rather than typed into the check, so the corpus sentence and the generator are now one runner apart instead of five documents apart.

**And the rate-limit question is ruled separately, because the row's own reading of `API_CONTRACT:1473` does not survive the line.** That row does not decline a rate limit for this endpoint. It rows one, per IP and per ASN, as data, and declines only the INHERITANCE of the catalog's specific budget. Section 5.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `235`, session **425**, dispatched as `claude/the-code-is-the-only-credential`. **`RI-22` was dispatched as the next free number and is taken**, its row written in the same commit as the check. **No migration number is reserved and none is taken**, which is section 6.1's whole difficulty and is the same wall [ADR-231](ADR-231.md) section 6.4 hit.

- **NOT THE MONEY PATH, AND IT IS LIVE TRAFFIC.** Ships `proposed` with an **UNSIGNED** approval line. `E2` is not owed: no money moves and no migration lands. What a founder read adds is in the approval block, and the first item is whether a mint may land ahead of its issuer at all.

- **WHAT IS MEASURED, WHAT IS DERIVED, AND WHAT IS JUDGED.** That the mint yields **130** bits over an alphabet of thirty-two distinct symbols, that two thousand draws collide zero times, that every position exercises the alphabet, and that eight seeded defects turn `RI-22` red is **MEASURED**, in sections 3 and 4, by running it. That no generator existed, that no writer of `certificates` exists, and that no rate limiter exists in this tree is **DERIVED** by search, at the scope each claim names. What is **JUDGED** is that the mint belongs in `packages/db` (section 3.1), that it may land ahead of the issuer (section 3.2), that `randomInt` is right where a modulo would also have been correct today (section 3.3), that no shape predicate is exported (section 6.2), and that the catalog declination stands while a limit remains owed (section 5).

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every citation in row `235` was re-derived at its own file and line, and one of them is section 5's finding.

**Every one of the eight files in the last result draws randomness for something else**, read at each site: session secrets and OTP codes ([`auth-backend.ts`](../../apps/api/src/auth-backend.ts)), a payout request id, a purchase id, a plan version id, and four that name the identifiers only to BAN them (the engine-purity rule, the harness's second-rulebook guard, the rithmic determinism guard and the CI falsifier). **None of them is near `certificates`.**

**So the answer to "what generator, what source of randomness, what alphabet, what length, and how many bits" is that there were none of those things.** The column is `text NOT NULL` under one unique index with no length bound and no alphabet bound ([`0020:125`](../../packages/db/migrations/0020_public_surface.sql)); the table's three `CHECK` constraints are payout kind, revocation completeness and deferral, and none names `code`. **That is [ADR-231](ADR-231.md) section 6 re-derived independently and it holds in every clause.**

**WHY A TOTAL ABSENCE IS WORSE THAN A SHORT CODE AND NOT BETTER.** A short code is a defect somebody can see in a diff. The first issuance slice would have written a code under deadline, with the invariant living in a plan document rather than in a function beside the insert, and **the way that goes wrong is a readable code, not an unreadable one**, because a readable code is the one that makes the support ticket easy.

### 3. The mint

[`packages/db/src/certificate-code.ts`](../../packages/db/src/certificate-code.ts). Thirty-two distinct symbols, twenty-six positions, `randomInt` per position, **130** bits.

| | |
|---|---|
| Alphabet | Crockford Base32, uppercase, omitting `I`, `L`, `O` and `U` |
| Length | 26 |
| Source | `randomInt` from `node:crypto`, one call per position |
| Bits | `floor(26 * log2(32))` = **130**, computed from the alphabet and typed nowhere |
| Structure | none. No prefix, no checksum, no separator, no time component, no per-kind marker |

**`CERTIFICATE_CODE_ENTROPY_BITS` IS COMPUTED AND THE FIGURE APPEARS IN NO CONSTANT.** An alphabet edited without a length edit moves it by itself. That is [ADR-034](ADR-034.md)'s remedy applied to a security parameter, and the alternative is the situation this entry exists to end: a number written in several places by hand.

**AND IT IS COMPUTED OVER THE DISTINCT SYMBOL COUNT RATHER THAN THE STRING LENGTH.** An alphabet that repeats one character is still thirty-two characters long and is thirty-one symbols of entropy, and every arithmetic taken over `.length` reports that loss as no loss at all. The module **refuses to load** on a repeat rather than reporting a number it cannot support.

#### 3.1 Why `packages/db`, which is a measurement and not a preference

[`M11:111`](../plans/M11-certificates-social-proof.md) puts the issuer in the **worker** (*"participant Iss as Issuer (worker)"*) and [ADR-231](ADR-231.md) put the verifier in the **api**. `RI-04` holds those apart as separate deployables, so the mint has to be reachable from two things that may not import each other. **`@merit/db` is the only package `apps/api/package.json` and `apps/worker/package.json` both declare**, read out of both manifests, so it is the one home that costs no new dependency and no `VG-12` admission. It also puts the mint one import from `PUBLIC_LOOKUP_ADDRESS`, whose entire safety claim is that this column's value cannot be guessed.

**`scope.ts` AND `scoped-db.ts` WERE READ AND NOT WRITTEN.** They are session **423**'s. This is a new file plus an additive export block in [`index.ts`](../../packages/db/src/index.ts), and it needed no line of either.

#### 3.2 Why it lands ahead of the issuer

[ADR-231](ADR-231.md) section 6 ruled that *"the slice that first writes a `certificates` row owes the 128-bit mint in the same slice"*, and named the alternative in the same breath: *"if you would rather the `CHECK` land first, on its own, before anything can write a weak code, that is a small session and it is the safer order"*. **This is that order, applied to the half that is not a migration.** A mint that exists before any issuer means the issuance slice inherits a measured token instead of inventing one, and `RI-22` leg 3 makes the inheritance mandatory rather than hoped for: any file writing a `certificates` row must name `mintCertificateCode`.

**THE COST IS AN EXPORT WITH NO CALLER, AND IT IS NAMED RATHER THAN HIDDEN.** [ADR-197](ADR-197.md) finding 1 is the argument against: `resolutionDb` landed unexported and a refusal string cited a pre-identity read that had existed for months. **The difference is what each thing costs while unused.** An unexported accessor is an authority nobody can reach, which gets misreported as absent; an unexported mint is a security parameter the next slice re-derives under deadline. This one is exported, executed by a check, and named in the port entry that will call it.

#### 3.3 `randomInt` where a modulo would also have been correct

`auth-backend.ts`'s `mintOtpCode` rules this already: *"the bias is removed by not writing the arithmetic"*. **Here the modulo would actually be safe today, which is the reason to refuse it.** Thirty-two divides two hundred and fifty-six exactly, so `randomBytes(26)` with `byte % 32` is uniform for THIS alphabet size. It stops being uniform the day somebody drops a confusable symbol and leaves thirty-one, and it does so silently, with the low symbols fractionally likelier and nothing in the tree saying so. **Safety that holds only while a constant nobody re-checks keeps its value is the same class of defect as a claim nobody runs.**

### 4. The assertion, seeded red eight ways before it was claimed to work

`RI-22`, in [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs). Three legs.

**Leg 1 reads the threshold out of the corpus.** `128` appears in no constant in the check. The five sites are parsed, they must name the SAME figure, and the mint is measured against it, so a corpus that raises the commitment to 192 fails on the next run rather than on the next reader.

**Leg 2 executes the mint** in a child `node --experimental-strip-types` and draws two thousand codes, then asserts over the DRAWS rather than over the source. This is `RI-20`'s move one class over, and it is the choice the subject forces: a static read settles the alphabet and the length and settles nothing about a constant position, a biased index or a counter, and all three of those are source that reads perfectly well.

**Leg 3 requires every writer of a `certificates` row to name `mintCertificateCode`.** Zero sites in the shipped tree, exercised in both directions by the suite.

**THE MARGINS ARE WIDE ENOUGH THAT A FAIR MINT CANNOT FAIL BY CHANCE, and the arithmetic is here rather than left as an assurance.** Over two thousand draws a given symbol is absent from a given position with probability `(31/32)^2000`, which is about `7e-28`; the coverage floor asks for ninety percent of the alphabet, so three simultaneous absences would be needed. A symbol's count at a position has mean `62.5` and standard deviation about `7.8`, and the dominance bound fires at three times the mean, which is sixteen standard deviations out over eight hundred and thirty-two cells.

### 5. The rate limit, ruled separately, and the row's own citation is the finding

**Row `235` says [`API_CONTRACT:1473`](../architecture/API_CONTRACT.md) *"leans on it to DECLINE a rate limit for this endpoint"*. Read at the line, it does not.** The row reads, in full and in this order: *"Public, and per IP and per ASN rather than per `code`"*, then *"the limits are data rather than prose, on the `POST /auth/otp` sms row's precedent"*, and only then the sentence the dispatch quoted, *"the catalog's 600/minute/IP is an enumeration budget on a 128-bit token and is deliberately not inherited here"*.

**What is declined is the INHERITANCE of one specific budget, not the existence of a limit.** The row specifies a limit in its first clause and holds its values as data in its second, exactly as the SMS row two tables up does.

**AND `INV-M11-05` ITSELF REQUIRES ONE, in the invariant's own words**: *"Certificate codes are unguessable **and the verification endpoint is rate limited** and non-enumerable"* ([`M11:54`](../plans/M11-certificates-social-proof.md)). [`M11:246`](../plans/M11-certificates-social-proof.md) counter 3 names the ASN dimension for this endpoint specifically. **So the rate limit is owed by the invariant regardless of what any measurement of the entropy returns**, and no arithmetic about the code space can discharge it.

**THE RULING, IN THE SHAPE THAT IS TRUE.**

1. **The catalog's `600/minute/IP` stays declined, and it stays declined on a number that is now real.** The mint yields **130** bits, `RI-22` measures it on every `CI-01` pass, and leg 1 binds that measurement to the five documents that assert it. Before today the declination rested on nothing at all; a general-purpose enumeration budget would have been the only enumeration control this endpoint had, and it would have been sized for a token that did not exist.
2. **A rate limit per IP and per ASN is OWED and is ABSENT.** No limiter exists anywhere in `apps` or `packages`, re-derived this session; `apps/api` declares one runtime dependency, `fastify`. The `rate_limited` canonical code and its `429` exist in [`server.ts`](../../apps/api/src/server.ts) and nothing on this route reaches them.
3. **The two are not substitutes and this entry declines to trade them.** `AS-M11-04` counter 1 is the entropy and counter 3 is the limit plus the `certificate_verifications` write, and the counters are numbered because they are different controls against the same attack. The limit is what makes an attempt VISIBLE; the entropy is what makes it FAIL. A campaign against a 130-bit space is invisible without counter 3 and it is still an incident.
4. **Nothing in `API_CONTRACT` moves.** Row `235` admits that document *"only if the rate-limit ruling changes"*. It does not change: the row was right and the dispatch's reading of it was wrong, and the repair belongs in this entry rather than in a frozen document that already says the correct thing.

### 6. What was refused

#### 6.1 A `CHECK` on `certificates.code`, which is still owed

**A bound in DDL is a migration**, and row `235`'s fence names `packages/db/src/**` by way of *"wherever the code is generated"* and does not name `packages/db/migrations/**`; no migration number is reserved for this row. **That is [ADR-231](ADR-231.md) section 6.4's wall reached from the other side**, and the same answer: widening a fence to finish and weakening a gate to pass it are the same move.

**THE GAP IS PINNED AND STAYS PINNED.** [`public-lookup.test.ts`](../../packages/db/test/public-lookup.test.ts) reads `0020` and asserts the absence, so the day a bound lands the case fails and sends its author to the ruling. **That case still passes**, because nothing here touches DDL. `RI-22`'s own `covers` line names the limitation in the first position: it cannot see the database, and a hand-written `INSERT` can still store a weak code.

#### 6.2 A shape predicate, and the refusal is a ruling

No `isCertificateCode` is exported, and the suite asserts the module's export surface is exactly four names so that adding one is a diff somebody has to argue for. [`API_CONTRACT:833`](../architecture/API_CONTRACT.md): *"a shape check ahead of the lookup is a faster path, and it hands an attacker the token's alphabet and length for free, which is `INV-M11-05`'s non-enumerability half failing beside its timing half"*. **The function that would make that easy to add is the function not written.**

#### 6.3 The rest

- **Editing `MERIT_BUILD_MASTER_PROMPT.md`** (frozen), **`M11`, `API_CONTRACT`, `SECURITY` and `EC-091`** (approved, and section 5 is why none of them moves).
- **Editing any migration.** `0020` and `0025` were read and not written.
- **[`scope.ts`](../../packages/db/src/scope.ts) and [`scoped-db.ts`](../../packages/db/src/scoped-db.ts)**, session **423**'s, read and not written. **[`wallet-withdrawals.ts`](../../apps/api/src/routes/wallet-withdrawals.ts)**, session **424**'s, not opened.
- **Keying `code_hash`.** [ADR-231](ADR-231.md) section 5.2 named an HMAC as the remedy if its section 6 resolved the wrong way. **It resolved the right way**: a preimage search over a 130-bit token is the same search as guessing the code, so the unkeyed digest's justification is discharged rather than merely restated, and adding a required secret today would defend a property that is now measured.
- **Inventing an issuer.** `M11` section 3.2 puts issuance behind an earning event with idempotency on `(account_id, kind, reference_id)` and a deferral branch, and none of that is this row's.
- **Widening `RI-22` to the rate limit.** A check that implied a control nobody built would be the exact defect this entry was opened on.

- **Approval:** `___________________________` (UNSIGNED. **Merging is not signing.**)

  **What a founder read adds and this entry cannot.**

  **THE FIRST IS WHETHER A MINT MAY LAND AHEAD OF ITS ISSUER AT ALL.** Section 3.2 argues it should and [ADR-197](ADR-197.md) finding 1 is the standing argument that it should not. The reason given for the exception is that an unused ACCESSOR and an unused SECURITY PARAMETER cost different things while nobody calls them, and that is a judgement about this estate rather than a rule anybody wrote down. **If you would rather the mint waited for the issuance slice, the check waits with it and the five sentences stay unenforced until then**, which is the trade in one line.

  **THE SECOND IS THE ORDER OF THE TWO REMAINING CONTROLS.** The column still has no `CHECK` and the endpoint still has no rate limit, and both are named as owed rather than taken. **The `CHECK` is the one that becomes irreversible**: once a weak code is committed to that column a bound cannot be added without deciding what to do with the row. `RI-22` leg 3 covers every writer in this tree and covers nothing outside it, so the residual exposure is a hand-run `INSERT` on a production database. **A small migration-only session would close it**, and this row could not take one because it reserved no number.

  **THE THIRD IS THE PARAMETER ITSELF.** Twenty-six symbols over thirty-two is 130 bits and the margin over `INV-M11-05` is two. The suite asserts that one position fewer would MISS the commitment, so a later author trimming the token for a prettier card is one character from a code the whole corpus overstates. **The alternative is a longer code with a margin nobody would be tempted by**, at the cost of a card that is harder to read aloud, and that trade is a product decision rather than a security one.

  **WHERE THIS ENTRY IS MOST LIKELY WRONG, named rather than left for a reader to find.** **`RI-22` measures a sample and a sample cannot prove uniformity.** A generator biased by a few percent per position passes every bound in section 4, and the check says so in its first sentence about what it does not catch. What actually defends the property is that the mint's per-symbol draw is `randomInt` and nothing else, which is a **static** fact the check reads and a future author could satisfy while doing something clever around it. **The honest statement is that leg 2 catches the defects that happen and does not certify the ones that do not.**
