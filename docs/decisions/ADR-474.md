### 5. The fix: the extension set is read out of the checkers themselves

#### 5.1 One shape is parsed and it is the one this module already parses

`suffixLiterals` walks every module under `CHECKS_DIR` in the census the check already builds, and takes the single string-literal argument of every `endsWith` call. **Structure off the blanked side and text off the kept one**, through `callsIn`, exactly as every other literal in this module is read. **No new scanner, no regular-expression literal parsing, and no second source model.**

`plantedExtensions` is that set unioned with `PLANTED_EXTENSIONS`. `measurementPatch` and `measure` take the set as a parameter and default to the floor, so the child is generated from the set the parent derived rather than from a constant the parent no longer uses.

#### 5.2 What it finds on this tree, and why the floor is still written down

**12 EXTENSIONS: 8 WRITTEN FLOOR, 9 DERIVED, 3 LITERALS REFUSED, 2 ARGUMENTS NOT LITERALS.**

```
EXTENSIONS  12 planted: 8 written floor and 9 read out of endsWith literal(s) in packages/tooling/checks
         set      .d.ts .json .md .mjs .sql .test.ts .ts .txt .yml _at absence-grammar-census.mjs package.json
         derived  .d.ts .md .mjs .sql .test.ts .ts _at absence-grammar-census.mjs package.json
         refused  3, no planted name can carry them: `)` `/` `/${target}`
         unfolded 2 suffix test(s) whose argument is not a string literal, which is the one class this parse cannot see through
```

**THE DERIVATION DOES NOT REACH THREE OF THE FLOOR'S EIGHT.** `.json` is reached only because `dependants.mjs` tests for a whole `package.json`; **`.yml` and `.txt` are reached by nothing at all**, because no checker in that directory spells either in a suffix test. **A derivation that REPLACED the written list would have planted two fewer kinds of name than the list it replaced, silently, in the diff that shipped the fix for silent thinning.** The floor is a floor for that reason and a case asserts it.

**THE DERIVATION ADDS FOUR AND THREE OF THEM ARE NOT EXTENSIONS.** `.d.ts` is. `_at` is a column-name test in `repo-invariants.mjs`, `package.json` is a whole filename in `dependants.mjs`, and `absence-grammar-census.mjs` is a whole filename too. **All three are planted anyway.** Section 7 argues why.

#### 5.3 The round size was a coincidence and the coincidence would have eaten the fix

`plant` walks `S.ext[i % S.ext.length]` for `i` from 0 to `perDir`. **The rounds were written `8` and `24` and the extension list was written with eight entries.** Those are the same 8. **A ninth extension in a round of eight is planted in the LARGE round only**, so its read column would have been `[0, n]`, `grewWithTheTree` would have been true, and the small round would have been measuring a tree that did not contain the thing the comparison was about.

`ROUND_SIZES` now holds multipliers and `roundsFor(ext)` returns `[ext.length, ext.length * 3]`. **At the floor's eight it returns 8 and 24**, which a case pins in both forms: derived from `PLANTED_EXTENSIONS.length`, and as the literal pair they used to be.

#### 5.4 The same seed, watched being caught

**RE-SEEDED, IDENTICALLY, AGAINST THE FIXED CHECK:**

| | Base, seeded, unfixed | Fixed, same seed |
| --- | --- | --- |
| the extension set | 8, `.sqlx` absent | **13, `.sqlx` present in `set` and in `derived`** |
| `#derivedSet` | `read=[0,0] of [8,24]` | **`read=[1,3] of [13,39]`** |
| `grew` | 5 | **6** |

**THE COMPARISON CAME BACK, AND THE ROUND SIZE CAME WITH IT**: `[13,39]` rather than `[8,24]`, which is section 5.3 in one line of output. **Restored byte-identical, `cmp` clean, `git status --porcelain` empty.**

**AND THE SUITE HOLDS BOTH DIRECTIONS PERMANENTLY.** One fixture walker filtering on `.ninth`, measured against `PLANTED_EXTENSIONS` (enumerates, `read` is `[0,0]`, `grewWithTheTree` false, `legRosterIsMeasured` silent, **nothing red**) and against the set derived from its own source (`read[0] > 0`, `read[1] > read[0]`, `grewWithTheTree` true). **The two cases differ in one argument.**

### 6. What the derivation cannot serve, measured rather than parsed

**EXTENSIONS ARE NOT THE ONLY WAY TO REJECT A NAME, and this tree already contained the proof at the base.** [`price-register.mjs:160`](../../packages/tooling/checks/price-register.mjs) is `const ENTRY = /^ADR-\d+\.md$/`. `merit-planted-1.md` carries the extension and fails the pattern, so **both of that checker's rostered walkers enumerated and read nothing, at the base, before this row existed, and nothing said so.**

**A SECOND PARSE FOR REGULAR-EXPRESSION LITERALS WAS CONSIDERED AND REFUSED, AND THE REASON IS NOT DIFFICULTY.** Deriving `ADR-\d+` from that pattern and planting `ADR-1.md` is **inventing a checker's input**, which is what [ADR-472](ADR-472.md) section 3.2 refused for argument values and refused correctly. A planted tree with fidelity to one checker's naming is a second copy of that checker's corpus.

**SO THE RESIDUE IS MEASURED INSTEAD.** `enumeratesUnread(v)` is `enumerates(v) && v.read.every((n) => n === 0)`: it watches the outcome rather than parsing for the cause, so it covers the prefix case, the extension case and any case nobody has thought of yet. **It is a COUNT AND A NAMING, and it is NOT a finding**, for the same reason `inconclusive` is not: a walker that enumerates names and never opens one is doing its job, and reddening on that would be this check inventing a defect out of its own planted tree. The report states it and `--list` marks the walker:

```
       ... 2 rostered walker(s) enumerate it and read none of it
       (packages/tooling/checks/price-register.mjs#derive, packages/tooling/checks/price-register.mjs#run),
       so the read comparison is not available for them
```

**WATCHED FIRING ON THE REAL TREE, WITH A SECOND SEED.** The same line 345 replaced with a filter requiring a name prefix (`/^merit-no-such-name-\d+\.sql$/`) moved the count from **2 to 3** and named `generated-column-writes.mjs#derivedSet` in the report. **The derivation did not fix it and could not**, and the check said so out loud instead of losing a comparison. Restored byte-identical, `cmp` clean.

### 7. What this parse does when it cannot decide, argued against `ADR-470` section 7

**THIS IS THE FIFTH PARSE IN THIS MODULE AND [ADR-470](ADR-470.md) SECTION 7 HOLDS FOUR OPEN.** A return-type annotation read as a body, a module-scope name lost to a nested one, a root that vanished into a ternary, and fixture source folded as code. **The four differ in mechanism and are identical in shape: every one of them LOST something and the check went on printing `PASS`.** One of them cost nine budgeted cases reported as unearned.

**SO THIS PARSE IS BUILT SO THAT ITS ERRORS ARE GAINS.**

| When it cannot decide | What it does | Why that is the safe direction |
| --- | --- | --- |
| it fails to find a suffix that is really there | **nothing is lost.** The floor is a floor and the union only adds | A miss leaves the set where it already was. **A parse that REPLACED the floor would turn every miss into exactly the silent thinning it exists to end** |
| the literal is not an extension (`_at`, `package.json`) | **it is planted anyway** | A name carrying a suffix nothing filters on costs one file and serves nothing. A name MISSING a suffix something does filter on costs the read comparison. **The asymmetry is the design and a case asserts it** |
| the literal is not a legal filename tail (`/`, `)`, `/${target}`) | **REFUSED AND COUNTED BY NAME**, printed in `--list` and counted in the report | This is the one class where something genuinely must go. **It goes where a reader can see it going**, which is the entire difference between this and the four above |
| the argument is not a string literal at all | **counted as `unfolded`**, printed with the sentence naming it as the class this parse cannot see through | Two of them exist today. A number that moves is a reader's signal that the class grew |
| **it decides NOTHING at all** | **`legSuffixesAreDerived` THROWS** | Falling back to eight written extensions and reporting a figure a reader cannot tell from a working one is the defect, not the remedy. This is leg A applied to this derivation and it is the same argument leg A makes about an empty scope |

**THE ONE THING THIS PARSE STILL CANNOT SEE IS SECTION 6's SUBJECT**, and section 6 answers it by measurement rather than by a sixth parse.

**AND THE TWO DERIVATIONS SHARE ONE MORE THING NOW.** [ADR-472](ADR-472.md) section 10 item 8 recorded that the patch and the fold read one `ENUMERATORS` and a case asserts it. **The patch and the parent now also read one extension set**, and a case asserts that too: `measurementPatch(REPO_ROOT, SELF, ['.only'])` must contain `['.only']`. **If the patch went on embedding the floor while the parent sized its rounds against the union, the small round would plant more files than there are extensions to cycle and the derivation would reach the child in name only.**
