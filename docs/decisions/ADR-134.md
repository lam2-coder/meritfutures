## ADR-134: a design record names exactly the columns its table carries, and the check that says so lands unregistered  (2026-08-27, status: proposed)

**[`CI-06i`](../testing/STRATEGY.md) requires a `### <table>` design record for every `CREATE TABLE` and a `CREATE TABLE` for every design record, in both directions. It does not compare the two records' COLUMNS, and its own header says so in a sentence that is half right:** *"It is deliberately a NAME-SET check rather than a column check. Column-level drift is caught by the generated diff against a live catalogue, which needs a database; this gate needs nothing but the tree, so it can run on every push."* **A live catalogue is needed to check a column's TYPE. It is not needed to check that a column EXISTS**, and the existence half is the half that costs a module a rebuild, because the next module is built by reading the design record rather than the DDL.

- **Origin:** `OI-15`, [DELTA_MANIFEST section 16](../../packages/db/DELTA_MANIFEST.md), session **246**. The number was **reserved before dispatch and CONDITIONAL** ([ALLOCATION](ALLOCATION.md) row 134): *"A design record gaining the columns its table already carries is transcription."* **That is exactly right about the record and it is not all this session did.** The repair itself rules nothing and is in the session log. This entry exists for the two things that are decisions: **what a design record OWES its table**, and **why the check that asserts it is not wired into `pnpm run verify` today.**

- **NOT MONEY PATH.** [`admin_actions`](../architecture/data-model/admin_actions.md) is the audit surface the money-path admin routes write to and no line here changes what any of them may do. Nothing is added to `packages/db`; `git status --porcelain packages/db` reports zero on the branch that carries this.

### 2. THE RULING

#### Clause 1. A design record names exactly the columns its table carries, in both directions

> **Every column a migration declares on a table appears in that table's design record, and every column a design record names is declared by a migration.**

**Both directions, on `CI-06i`'s own reasoning one level down.** A column the schema carries and the record omits is a module built blind. A column the record names and no migration creates is a module built against a fiction. `CI-06i` says exactly this about TABLES and stops; the argument does not stop where the gate does.

**The obligation is on NAMES and not on types.** The record may say `text` about a `uuid` and this ruling is silent, because that half genuinely needs a live catalogue and `CI-06i` is right about it. **A record whose column LIST is complete and whose types are wrong is a smaller failure than one whose list is short**, because a reader comparing a stated type against the DDL is a reader who already found the column.

#### Clause 2. A struck-through row is a TOMBSTONE and not a claim, and a tombstone the schema contradicts is a finding

Finding 4's row stays, and rows like it are the recommended form for a column an ADR refused. **The strikethrough is what separates *"this record forgot a column"* from *"this record answers a question about a column that does not exist"***, and the two are opposite qualities in the same shape.

**The exemption is not unconditional.** A record saying a column was never created, about a column a migration creates, is the fiction direction wearing a strikethrough, and it is reported as its own finding with its own message. An exemption that cannot be contradicted is an allowlist, which is the direction a check decays in.

#### Clause 3. The check lands as a file and is NOT registered in `gates.mjs`, and the condition for registering it is written rather than left to judgement

[`scripts/corpus/data-model-columns.mjs`](../../scripts/corpus/data-model-columns.mjs) implements clauses 1 and 2, runs on nothing but the tree, and **reports `FAIL` on this corpus today** for finding 3's three records.

**It is not in the `GATES` array, and that is a deferral with a date rather than a design.** All three failing records are outside this session's fence and the wave has four sibling sessions live. Registering a red gate would put `pnpm run verify` at non-zero, and the only remedy available inside this fence would be to narrow the check until it passed. **Working agreements section 9: never weaken a gate to pass it.** A check that exists, runs, and is watched failing on seven seeds is worth more than a check that was diluted until it was green.

> **Registration is owed to the session that repairs the last of the three.** It is an `import` line and one entry in `GATES`, and `falsify.mjs` gains one `SEEDS` entry whose seed is a deleted column row. Nothing else moves: the id is a slug rather than a letter, so [`CI-06p`](../testing/STRATEGY.md) requires no letter allocation and no `STRATEGY` section 4.4 row, which that gate's own `covers` line states as a deliberate limit.

**A reader who finds this entry with the check still unregistered should read that as work owed, never as a decision that it belongs outside the runner.**

#### Clause 4. The duplicated migration parser is a debt, and this is the sentence that records it

The new file parses the migrations itself. **`OQ-P1-04`'s ruling ([P1 section 7](../plans/P1-monorepo-scaffold.md)) is one parser called twice rather than two expressions of one parse**, which [`gates.mjs`](../../scripts/corpus/gates.mjs) applies in its own words on the very catalogue this file needs: *"one parser, called twice, which is OQ-P1-04's ruling applied before the second expression exists rather than after"*, and finding 6 is why that ruling cannot be honoured from a second file today.

**The duplication fails in the safe direction and that is the only reason it is tolerable.** A catalogue that parses NARROWER than `gates.mjs`'s reports a column the record has as absent from the schema, which is a loud false finding somebody investigates. It cannot produce a silent pass. **The remedy at registration time is to delete the copy**, since a gate inside `gates.mjs` reaches `columnCatalogue()` directly, and the registering session takes it.

#### Clause 5. The three records are named and NOT numbered here

Finding 3's three are handed to the dispatcher as findings rather than claimed as `OI-nn` rows, because [DELTA_MANIFEST](../../packages/db/DELTA_MANIFEST.md) is not in this session's fence and an identifier claimed from outside a fence is the collision [ADR-034](ADR-034.md) exists to end. They are in the pull request body and in [the session log](../sessions/2026-08-27-session-246.md).

**Each is a one-row repair on the shape this session's own record now carries**, and the three together are smaller than the entry describing them. **The reason to size them honestly rather than fix them quietly is that four sibling sessions are live in this wave**, and a session reaching outside its fence to make its own check green is the failure mode a fence is for.

### 3. What this entry does not rule

**It does not rule where a corpus check LIVES.** [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) states its own boundary (*"These are build-tooling invariants ... `scripts/corpus/` is the corpus runner's directory and these do not check the corpus"*) and a design-record reconciliation is plainly corpus, so `scripts/corpus/` is where it went by that file's rule rather than by a new one.

**It does not rule on `CI-06i`'s text.** The gate's header sentence about needing a database is left as it stands: it is true of types and the entry that would correct it is the one that registers the check, where the correction is a fact rather than a claim.

**It rules nothing about `admin_actions` itself.** Every column, constraint and index in the repaired record is transcribed from [`0017`](../../packages/db/migrations/0017_events_and_audit.sql) and [`0043`](../../packages/db/migrations/0043_admin_attributed_actions.sql), and [ADR-069](ADR-069.md) already ruled the two columns. **No schema change is proposed, and none is needed**: the reconciliation found the record wrong and the schema right, in every one of the four cases.
