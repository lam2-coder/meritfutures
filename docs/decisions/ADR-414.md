### 5. The address was the smaller half, and this is the finding

**EVERY ONE OF THE SIXTEEN SAT INSIDE A CLAIM THAT `apps/worker` COULD NOT REACH THE PRODUCER, AND ADR-410 FALSIFIED THAT CLAIM WHEN IT MOVED THE WRITER.** Repointing the path and leaving the claim would have produced a sentence that is false in the present tense, which is strictly worse than a stale address: an address sends a reader to the wrong file, a false reason sends them to the wrong conclusion.

The reasons were checked at their sources rather than argued:

| the clause, as it stood | at primary source, on this tree |
|---|---|
| *`RI-04` forbids the import* | **TRUE AND NO LONGER BITING.** `RI-04` refuses a deployable depending on a DEPLOYABLE. The producer is in a package |
| *`node-linker=isolated` makes an undeclared specifier unresolvable* | **TRUE AND NO LONGER BITING.** `@merit/ledger` is DECLARED |
| *`apps/worker` declares `@merit/db` and `@merit/rules-engine` and nothing else* | **FALSE, AND FALSE BEFORE THIS WAVE.** The manifest carries **four**: `@merit/db`, `@merit/ledger`, `@merit/queue`, `@merit/rules-engine` |
| *no sink is reachable from `apps/worker` at all* | **FALSE.** `db.test.ts` section 4 pins the permitted bare specifiers to **five** names and `@merit/ledger` is one of them |
| *`apps/api/src/events.ts` holds `EVENT_CATALOGUE`, `buildEvent`, `makeEventSink` and `TRANSACTION_EVENT_WRITER`* | **FALSE IN EVERY PARTICULAR.** That module publishes `EVENT_NAMES` and nothing else |
| *nothing under `packages/**` carries an event producer* | **FALSE.** `packages/ledger` carries it and publishes all four names from its barrel |

**AND ONE PARAGRAPH HAD ALREADY WRITTEN THE REPAIR THAT LANDED.** `sweeps/expiry-adapter.ts` closed its refusal by naming what would fix it, *"a package both arrows already reach rather than an import either side could write"*, and called that `P5-n`'s slice. ADR-410 is that package. **That block is kept and marked rather than deleted**, on `RI-14`'s rule that a false sentence deleted leaves nothing for the next reader to check, which is the idiom six of these files already use by name.

**HOW THE SENTENCES WERE REWRITTEN, AND THE CONSTRAINT IS THE POINT.** Where the sentence's job is to identify the producer it now names `TRANSACTION_EVENT_WRITER` and `@merit/ledger`, which are a declaration and a manifest line and survive the next move. Where a history clause records what the sentence used to say it names the DEPLOYABLE and never re-plants the file address, so the old path leaves `apps/worker` entirely rather than surviving inside quotation marks where the next row's grep will find it again. **`RI-35`'s `event-sink-caller` probe was read before a single one of these strings was written**: it matches `TRANSACTION_EVENT_WRITER` followed by `.`, `,` or `)` after `stripComments`, so every occurrence added here is backticked or followed by a word, and the invariant was re-run after each file.

### 6. What survives at the old address, and why this row did not close it

**`apps/worker/test/replay-adapter.test.ts` STILL IMPORTS `../../api/src/events.ts` AND THAT IS DELIBERATE.** The dispatch says an address genuinely required by an import should use the new one, and this row refused that instruction with a reason.

`apps/api/src/events.ts` states in its own header that it is *"a compatibility name for exactly one consumer and it publishes exactly what that consumer takes"*. **That consumer is this import.** Repointing it at `@merit/ledger` would resolve, because the manifest declares it and `db.test.ts` permits it, and it would leave a module in `apps/api/src` whose header states a reason that had just become false, **in a deployable this row may not write**. ### 11. Approval

- **What a founder read adds and this entry cannot.**

  **THE FIRST IS THAT THE PROGRAMME'S OWN INSTRUMENT UNDERCOUNTED ITS OWN DEFECT BY HALF.** ADR-410 found sixteen prose sentences with a path matcher and they reproduce exactly. **The same tree holds eight more sentences making the identical claim in words instead of paths**, and no grep for an address will ever find one. A founder deciding what a registered finding is worth should note that a register keyed on a STRING is a register of the occurrences somebody could grep for, and that the sentences which survive it are the ones written by people who were explaining rather than citing. **The cost of finding the other eight was reading the file.**

  **THE SECOND IS THAT A TRIPWIRE IN AN UNOWNED FILE MAKES A CORRECT ROW LOOK LIKE A BROKEN ONE.** ADR-410 registered the stale set as an assertion instead of repairing it, which was right, and it put that assertion in `apps/api/test` because that is where the row's fence was. **The consequence is that the row which does the work cannot land green**, and the only ways out are to cross a fence or to ship red. **A founder should decide whether a register of work owed belongs in a file the owing row can write**, because this shape will recur every time a wave hands one row a finding and another row the file that records it.

  **THE THIRD IS THAT LINE-COUNT NEUTRALITY CAME BACK AS A REQUIREMENT THROUGH THE DOOR ADR-386 LEFT OPEN, AND THAT IS CORRECT RATHER THAN A REGRESSION.** ADR-386 refused it as a rule and replaced it with *no cited line moves*. On this row that property BOUND two files to the line and left five free, which is the looser rule doing exactly what it promised. **But the binding pointers were in `apps/api/test/wiring.test.ts` and `apps/admin/src/index.ts`, and the reason they bind is that this row may not repair them.** So the real constraint on how a session writes prose is the shape of the fence it was given. **A founder should decide whether that is acceptable or whether repairing a drifted pointer in an unowned file should be a standing right**, because ADR-256 was granted exactly that right once and the grant is not general.
