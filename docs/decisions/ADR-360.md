**The dispatch expected an interface to count and the interesting number is one.** `AdminSessionSource` (`apps/api/src/routes/admin-reads.ts:235`) declares a single member, `lookup(token: string): Promise<AdminSessionLookup>`, sliced to its closing brace at `:237`. **So the shape [ADR-356](ADR-356.md) ruled on cannot arise here at all.** A half-install is an arrangement of live arms beside refusing ones, and a port with one member is installed or it is not.

What it does change is that `adminHandler` stops emitting the one `request.log.error` that names the uncomposed port. **The install is not partial progress. It is a net loss of the deployment's only honest signal**, and this row rules it a regression rather than a step.

### 4. What a request meets, derived from the handler rather than the docblock

1. The cookie is read first. `adminTokenFromCookie(request.headers.cookie)`.
2. `adminSessionSourceOrNull()` returns `null`. **`sessionSource` is initialised `null` at module scope and nothing under `src/` assigns it**, which `wiring.test.ts`'s `DEFAULTS` map already reads back off the tree (`setAdminSessionSource: 'null'`).

4. The lookup is short-circuited to `{ kind: 'unknown' }`, `authorizeAdmin` returns `unauthenticated`, and `adminUnauthenticated` sends **401**.

### 6. The half-install question, measured rather than assumed by analogy

**ADR-356's SHAPE DOES NOT HOLD HERE, AND SAYING SO IS THE POINT OF THIS SECTION.** That row measured `200/500` against `503/503` and ruled the half-install worse. **Two things differ and both are structural.**

**First, there is no half to install.** One member. And the default is `null` rather than an `UNWIRED_*` object: of the ports in `wiring.test.ts`'s `DEFAULTS`, three initialise to `null` and the rest to a refusing object. **A `null` default cannot present one live arm beside refusing ones**, which is the failure mode ADR-356 priced.

**Second, the FULL install is the one worth measuring, and its wire delta is ZERO.** The best source a deployment could install today is honest and reads an empty directory, so `lookup` returns `unknown` for every token. Laid side by side, with a cookie presented in **both** arms so the lookup genuinely runs:

| | unwired | wired over the empty directory |
|---|---|---|
| **wire** | `401 unauthenticated` | **the same bytes** |
| **log** | one line, `{ port: 'setAdminSessionSource' }` | **nothing** |
| **cost** | none | a transaction against two tables on **every** `/admin/*` request, including those answering 401 to a caller holding nothing |

**SO THE TRADE RUNS ENTIRELY DOWNHILL.** No caller is served better, an anonymous prober gets to schedule database work that nothing bounds, and the deployment loses the one place its own incompleteness is written down. **This row rules the full install a regression on that measurement**, which is a different ground from ADR-237 section 8's, whose objection ADR-343 spent.

**A NOTE ON HOW THIS WAS NEARLY GOT WRONG, KEPT UNDER `RI-14`.** The first draft of these cases installed a source and sent **no cookie**. `adminHandler` reads the cookie before consulting the source and short-circuits to `unknown` when there is no token, so the wired arm never reached `lookup` at all and the comparison was between two paths that both refused early. **A seed that made the source return `not-an-operator` left the suite GREEN, which is how the vacuity was caught.** Every wired case now presents a cookie and asserts the call landed.

### 8. Open questions, recorded as the founder's with options and no values

**NO DIGEST, NO TTL, NO CEILING AND NO PAGE SIZE IS INVENTED HERE.**

**OQ-1. What digest turns a presented operator token into `operator_sessions.token_hash`?** The column is `bytea NOT NULL UNIQUE` (`0073_operator_directory.sql:189`) and **no document in the corpus states the algorithm.** The tree's one precedent is `sessionTokenHash`, sha256 over the whole token (`apps/api/src/auth-backend.ts:196`), and `0073`'s own comment points at that column's **declaration** rather than at its digest. Options: (a) rule the trader precedent binding on the operator path and say so in an ADR; (b) leave it to the slice that writes the minter, since a digest is a contract between a minter and a reader and **this repository contains neither**; (c) rule it at purchase time against whatever the provider's session format turns out to be. **No option is taken here**, and taking (a) silently would be this row deciding a contract for an unbuilt component.

**OQ-2. What bounds `operator_sessions.expires_at`?** [ADR-312](ADR-312.md) already registers this as owed: *"the corpus states none, and it is owed by whichever slice lands the minter"*. `resolveOperatorSession` compares against a **passed clock** and treats expiry as exclusive, so the decision is built and the number is absent. `impersonation_sessions` carries a 2 hour ceiling in DDL as a worked precedent for the shape, and **it is a precedent for the shape and not a value to copy.**

**OQ-3. Should a deployment that cannot authenticate an operator refuse to START?** ADR-359's OQ-2 asked this of one route; this port is the case where it bites hardest, because **every** `/admin/*` route is behind it. Options: (a) leave it, and a running admin origin serves 25 routes that all refuse; (b) fail closed at boot on the operator surface only, which is narrower than ADR-359's version because the public surface withholds these routes anyway; (c) a startup report naming uncomposed ports without blocking. **Operational posture, and no code here assumes an answer.**

**OQ-4. Should the wire stay mute?** Carried from ADR-359 OQ-1 unchanged and **not re-litigated here**. If it is ever amended, the three channel cases in section 9 are the ones that must be re-argued rather than deleted.
