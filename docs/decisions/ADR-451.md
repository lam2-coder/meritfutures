## ADR-451: four cases asserted a write PostgreSQL refuses, the defect is twenty tables wide rather than the two the sibling named, and the widening it blocks is now green but watched by nothing (2026-09-08, status: proposed)

**Row 451 of the 448s wave. Branch `claude/identity-write-cases`, off `origin/claude/wave-448s` at `5b7fe6c`, session 646.**

**THE FOUR CASES ARE CORRECTED AND NOT REMOVED.** `setFor` at [`keyed-accessor.test.ts:196`](../../packages/db/test/keyed-accessor.test.ts) and `someOtherColumn` at [`write-accessor.test.ts:180`](../../packages/db/test/write-accessor.test.ts) each skipped the TENANCY columns and returned the first column left. On every registry table carrying an identity `id`, the first column left IS `id`, so the SET those helpers built named a column declared `GENERATED ALWAYS AS IDENTITY`, which PostgreSQL answers `428C9` to. Both helpers now also skip the columns the DATABASE writes. **Every assertion each of the four cases carried is still there and still runs**, because none of them ever asserted anything about WHICH column was named.

**THE DEFECT IS TWENTY TABLES WIDE AND [ADR-448](ADR-448.md) NAMES TWO.** Section 3. That entry's section 6 reads *"On `ledger_entries` and `liability_snapshots` the first column left is `id`"*. Derived here, both helpers pick a database-written column on **20** tables: **10** in `SCOPED_KEYS` and **10** in `FIRM_KEYS`. The two the entry names are the FIRST member of each of those two lists, which is what a per-key `expect` label reports when it fails. **The entry read its failure output and wrote it down as the population**, and the number it produced is 10 times too small on each side.

**THE DISPATCH'S PRICE NAMES A SET ONLY ONE OF THE TWO HELPERS HAS.** Section 4. It asks for *"one clause each ... adding the database-written columns to the set each already skips."* `setFor` has a `Set<string>` called `forbidden`; `someOtherColumn` has a single `string` compared with `!==` and no set at all. The correction is faithful to the intent and not to the wording, and the wording is reported rather than worked around.

### 4. What was changed, and why it is two lines in one file and three in the other

**`someOtherColumn` took one clause on one line**, at [`write-accessor.test.ts:184`](../../packages/db/test/write-accessor.test.ts): `column.name !== tenancy` became `column.name !== tenancy && !databaseWrites(column)`. Its docstring and its `throw` message were rewritten IN PLACE, one line for one line, because both said "tenancy" and both are now false about the rule they describe.

**`setFor` could not take the same shape and the reason is the printer.** The dispatch's price is a clause added to the `forbidden` set. That set is a multi-line array literal, and Prettier at `printWidth: 100` puts one element per line in an array it has already broken, so **an element is a LINE and this file cannot afford one** (section 5). Adding the clause to the loop's `if` instead overruns 100 columns at **107** characters and Prettier wraps it, which is also a line. **The three lines of the loop were therefore replaced by three lines** that say the same thing with a `filter` and a `find`, and the count is exactly preserved.

**THE PRICE'S WORDING IS REPORTED RATHER THAN SILENTLY REINTERPRETED.** It says "the set each already skips". `someOtherColumn` has no set: it holds one `string` and compares it with `!==`. Only one of the two helpers has a set, so the phrase is true of one of the two files it prices, and both corrections are written to the intent instead.

**THE HELPER IS DUPLICATED RATHER THAN SHARED, AND THAT IS THE FENCE.** `databaseWrites` is declared at the foot of each file. A shared module would be a third file and this row owns two. It is one `return` over two properties Drizzle declares, it asserts no count, and the two copies therefore cannot drift into disagreeing about a number. **[RI-14](../../packages/tooling/checks/repo-invariants.mjs) is served in each file's own words**: the block above each helper states what the helper corrects, keeps the corrected behaviour described rather than deleted, and records that `isGenerated` does not exist beside the two properties that do.
