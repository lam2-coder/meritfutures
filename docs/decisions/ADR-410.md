### 4. The home, ruled on the writer's shape, with the losing options named

**`packages/ledger`.** The producer imports nothing, declares its transaction structurally, takes the caller's OPEN transaction as its first argument with no overload that omits it, and holds no `@merit/db` import by construction. That is not merely compatible with `packages/ledger`, it is that package's existing idiom line for line: [`packages/ledger/src/tx.ts`](../../packages/ledger/src/tx.ts) declares `LedgerTx` as a structural restatement of `SystemTx`, states in its own header that this package *"declares none, cannot import `client()` ... cannot import `drizzle-orm` or `pg`"*, and closes the two-statements-of-one-shape hazard the only way a package with no dependency edge can, by a suite that READS `packages/db/src/scoped-db.ts` and compares. `EventInsertTx` and `EVENT_INSERT_BRAND` are that same construction, arrived at independently one deployable over. And [ADR-104](ADR-104.md) is the precedent for the shape of the problem rather than for the shape of the module: two deployables had to post, `RI-04` forbade an app depending on an app, and the answer was a library.

**`@merit/db` LOSES, AND IT LOSES TO A CHECK RATHER THAN TO A PREFERENCE.** It is the tempting answer, because the producer could then import `SystemTx` directly and stop restating a brand as a string. Two things refuse it and both were verified at source:

- `apps/api/test/db.test.ts` pins, as a map, every file under `apps/api/src` that names the accessor, and its `importsIn` helper matches `export ... from` as well as `import`. A module at `apps/api/src/events.ts` that re-exported the producer out of `@merit/db` adds a key to that map and turns that case RED, in a file this row's fence does not hold.
- **AND THE WORSE HALF IS THE WIRING THIS CHOICE WOULD LATER FORBID.** `apps/worker/test/digests.test.ts` case 10.2 asserts that `src/db.ts` is still the only file under `apps/worker/src` that imports `@merit/db`. A future row installing the sink would have to name the package in the file that composes it, or route the producer through the accessor door itself. The first breaks that assertion and the second widens the one door [ADR-165](ADR-165.md) exists to keep narrow. **A home that makes the wiring it exists to enable illegal is the wrong home.**

**`@merit/rules-engine` LOSES ON ITS STATED CONTRACT, AND NO GATE WOULD HAVE CAUGHT IT, WHICH IS WHY THE REASON IS WRITTEN DOWN.** Its manifest describes it as *"Pure rule computation, zero I/O"*, `RI-01` holds it to no workspace dependency and `RI-07` walks its transitive graph for Node builtins. The producer would pass all of that: it imports nothing, so the graph stays empty. **The `merit/engine-purity` lint rule was RUN over the producer placed in that package's `src` and reported zero problems**, and the probe was proved live by appending `export const seeded = new Date();` to the same copy and watching it report the clock error and `no-restricted-globals` together. So the refusal here is a judgement and it is stated as one: `TRANSACTION_EVENT_WRITER`'s entire purpose is to perform `tx.insert(...)`, and a package whose guarantee is that it computes and never writes is not made a better package by containing the one module in the workspace whose job is the write. **The check that would have caught the wrong answer does not exist, and asking for one would be asking a runner to hold a category.**

### 5. The relocation does not land under this fence, and the move was RUN rather than reasoned about

The move was performed. `apps/api/src/events.ts` was relocated to `packages/ledger/src/events.ts` with `git mv`, the package barrel gained the producer's exports, a re-exporting module was written at the original path, and `pnpm vitest run` was run against the result.

| invariants | **32 of 35**, with `RI-15` at 3 findings, `RI-16` at 2 and `RI-35` at 1 |

**THE FIVE FILES OUTSIDE THE FENCE, WITH WHAT EACH ONE ACTUALLY ASSERTS.**

| file | what broke | why a re-export at the old path does not save it |
|---|---|---|
| `apps/worker/test/breaker-adapter.test.ts` | *expected `[]` to have a length of 10* | it searches this file's TEXT for `export const EVENT_CATALOGUE` and parses the rows out of what follows |
| `apps/worker/test/event-sink.test.ts` | the catalogue parse returned nothing | same shape, through a path built out of `..`, `..`, `api`, `src`, `events.ts` |

| `packages/tooling/test/absence-claims.test.ts` | the shipped register no longer holds | `RI-35`'s probe again, from the register's own suite |

**`RI-04` IS WHY ALL THREE WORKER SUITES READ TEXT RATHER THAN IMPORTING.** That deployable may not import this one, so the only instrument available to it is the file, and the file is named by path. **A module left at that path that RE-EXPORTS the producer keeps every import in the tree working and satisfies none of the three**, because what they look for is the declaration and not the value.

**THE THREE INVARIANT FINDINGS, EACH WITH THE SMALLEST THING THAT WOULD CLEAR IT.**

- **`RI-15`, three findings, all from `apps/worker/src/schedule.ts`.** Two cite this file with a full path and a line and one is a bare pointer inheriting it. The two full-path pointers need only that the file still be long enough, which a re-exporting module can satisfy. **The third cannot be satisfied honestly.** It names `buildEvent` beside its pointer, so [ADR-212](ADR-212.md)'s anchor applies: the cited line must DECLARE that name or sit inside a declaration the sentence names. Four forms were measured at the cited coordinate: `export function buildEvent(...)` and `export const buildEvent = ...` satisfy the anchor, and `export { buildEvent } from '...'` and `export { build as buildEvent }` do not. **So the only way to keep that pointer green from inside this fence is to declare `buildEvent` a second time, in the file the move exists to take it out of.** That is a duplicate wearing an anchor's clothes, and it would make an invariant report a pointer as verified precisely where the thing it names had moved, which is the defect `RI-15` was written for. **It is refused rather than taken.**
- **`RI-16`, two findings, both `docs/decisions/ALLOCATION.md`.** Range only, and a long enough module at the old path clears both. This is the one finding of the six that sits in a file this row's registries include.
- **`RI-35`, one finding, and it is structural.** The `event-sink-caller` probe skips exactly one file while it hunts for an install, and the path is written into [`packages/tooling/checks/absence-claims.mjs`](../../packages/tooling/checks/absence-claims.mjs) as a constant. The producer's own refusal message quotes `makeEventSink({ writer: TRANSACTION_EVENT_WRITER, clock })`, which is the exact shape that probe treats as an install, and `stripComments` does not remove string literals. **Move the module and the exclusion stops covering it, and the register reports the artifact PRESENT because the module said how to install it.** The barrel line re-exporting `TRANSACTION_EVENT_WRITER,` is read the same way. Both were confirmed by running the probe's own predicate over every shipped source on the moved tree.

**AND THE DESTINATION IS NOT THE VARIABLE.** Every binding above keys on the SOURCE path, `apps/api/src/events.ts`. `@merit/db` and `@merit/rules-engine` produce the identical six findings, so section 4's ruling is not what this section refutes and one probe answers all three.

### 6. What the price actually is, itemised, and whose each line is

**THE MOVE IS NOT EXPENSIVE. IT IS FENCED.** The whole clearing condition is six one-line edits across five files, and this wave hands not one of those files to anybody.

| the edit | whose it is |
|---|---|
| two pointers in `apps/worker/src/schedule.ts`, best repaired by dropping the line numbers rather than repointing them | **NOBODY'S THIS WAVE.** The dispatch for this row states `apps/worker/**` is nobody's: read it, cite it by name, do not write it |
| one path constant in `apps/worker/test/event-sink.test.ts` | same |
| one path string in `apps/worker/test/breaker-adapter.test.ts` | same |
| one path string in `apps/worker/test/schedule.test.ts` | same |
| the `producer` constant and the `site` of the `event-sink-caller` claim in `packages/tooling/checks/absence-claims.mjs` | **`packages/tooling`'s**, which session 404 held and which is in no fence this wave |
| two pointers in `docs/decisions/ALLOCATION.md` | **this row's registries**, and repairing them alone buys nothing while the five above stand |

**SO THE HONEST STATEMENT OF THE BLOCKER CHANGES SHAPE FOR THE THIRD TIME AND THIS IS THE FIRST TIME IT IS ABOUT AN ADDRESS RATHER THAN A COST.** The record went: *a decision about a deployment* ([ADR-348](ADR-348.md), refuted by [ADR-408](ADR-408.md) section 5); then *a file on disk that costs a package a founder must admit* (refuted by ADR-408 section 6, which found three shared addresses); and now **a file on disk that costs nothing to create and cannot be created, because the path it would vacate is load bearing in three fences at once.** `apps/api/src/events.ts` is not only where the producer lives. It is the name three suites, three pointers and one register use to FIND the producer, and none of them can be told the new name from here.

**THE ONE SHAPE THAT WOULD LAND TODAY IS REFUSED FOR A REASON AND NOT SKIPPED.** A module at the old path that is long enough for the range checks and declares `buildEvent` at the cited coordinate clears `RI-15` and `RI-16`. It does not clear the three text parses and it does not clear `RI-35`, and it buys those two only by writing prose to a line budget set by a string literal in another deployable. **[ADR-397](ADR-397.md) and ADR-408 section 7 each bought line-count neutrality in a source file and each said what it cost; buying a line NUMBER is a different thing, and this entry declines it.**

### 7. What is bound rather than reported

**A MEASUREMENT IN AN ENTRY ROTS AND A CASE DOES NOT**, which is the rule ADR-408 section 6 applied to its own finding and the reason its section 4 leg exists at all. Section 6 of [`apps/api/test/event-placement.test.ts`](../../apps/api/test/event-placement.test.ts) derives all three populations at run time: the `file:line` pointers into this file from `apps/worker/src`, both pointer shapes read per LINE so the bare one is not dropped; the suites under `apps/worker/test` that search for `export const EVENT_CATALOGUE`; and the register constant that names this path as the module to exclude.

**EVERY ONE OF THEM FAILS ON GOOD NEWS**, which is section 4's discipline turned around to face the obstruction instead of the remedy. The day the last binding stops naming this path the relocation is unblocked, and the row that unblocked it is the row that gets told, rather than a later row rediscovering the price the way this one did, by running the move.

**THREE OF THE FOUR NEW CASES WERE WATCHED RED**, each under a seed in the file it reads, each restored and confirmed byte-identical by `sha256sum`: the pointers stripped from `apps/worker/src/schedule.ts`, the search string renamed in `apps/worker/test/schedule.test.ts`, and the `producer` constant repointed in the register. **THE FIRST SEED OF THE SECOND CASE PROVED NOTHING AND IS RECORDED RATHER THAN QUIETLY REPLACED**: renaming the declaration to `EVENT_CATALOGUE_X` left `export const EVENT_CATALOGUE` intact as a substring, the case stayed green, and the seed was corrected to `EVENTX_CATALOGUE` before the RED was believed. The fourth case is the guard that the walks reach files at all, and a guard that could be seeded by emptying a deployable is not seeded.

**SECTION 4's LEG IS UNTOUCHED AND THAT IS DELIBERATE.** The dispatch asked for it to be updated to assert the new truth, on the expectation that a `packages/*` module would hold a producer by the end of this row. None does, so *"no `packages/*` composes a sink today"* is still true, and updating an assertion to describe a change that was not made is the one thing worse than deleting it.

### 8. What this row did not do, stated plainly

**IT DID NOT MOVE THE MODULE, AND NOTHING MECHANICAL IS UNBLOCKED BY IT.** `expirySweepIo` still takes a sink as a required member, `UNWIRED_EVENT_SINK` is still the only sink any deployment can reach, and `apps/worker` still cannot name the producer. **The estate still satisfies `EVENTS` universal rule 1 for no transition it performs.**

**IT DID NOT WIRE `apps/worker`, WHICH THE DISPATCH FORBADE AND WHICH WOULD HAVE BEEN A SEPARATE SLICE EVEN IF IT HAD NOT.**

**IT DID NOT ASK FOR A `VG-12` ADMISSION, BECAUSE THE RULED HOME NEEDS NONE.** `packages/ledger` is already a dependency of both deployables and the producer declares no dependency of its own. A new `packages/events`, which ADR-408 section 10 calls the correct answer, would need two manifest lines in two files this fence does not hold and is not proposed here.

**AND THE VOCABULARY GAP ADR-408 SECTION 9 MEASURED IS UNMOVED AND UNADDRESSED.** Three of the estate's nine emitted names would build through this producer and six would not, and that obstruction outlives the address question whichever way the address question is settled. It is named here so that nobody reads this entry as the last blocker.

### 9. Approval

- **What a founder read adds and this entry cannot.**

  **THE DECISION IS NO LONGER WHERE THE PRODUCER LIVES, IT IS WHO IS ALLOWED TO REPOINT FIVE LINES.** ADR-408 section 10 asked a founder to decide the destination and said no measurement settles it. Section 4 above settles it as far as a measurement can, and section 5 then shows the destination was never the binding constraint: the move fails in six places and all six name the source path, so the same six failures follow every candidate. **What a founder is actually being asked for is a fence that spans `apps/worker/**`, `packages/tooling/checks/absence-claims.mjs` and this producer at once**, which is one row and roughly six lines of diff, and which no wave has yet been shaped to give anybody.

  **THE SECOND IS THAT THIS PROGRAMME HAS NOW PRICED ONE MOVE THREE TIMES AND EACH PRICE WAS RIGHT AND INCOMPLETE.** A blast-radius figure was recorded at 88 lines across 31 files and refused the move on volume. ADR-408 counted manifest edges, found none, and called the move cheap. Neither counted the bindings, and the bindings are the whole obstruction. **A founder deciding how much of this programme's cost goes into re-deriving the same question should note that the instrument that finally answered it was running the move and reading the failures**, which took one suite run, and that nothing in either tree offered that answer to a reader.

  **THE THIRD IS THAT THE SHARPEST THING THIS ROW DECLINED WOULD HAVE PASSED EVERY GATE.** A re-exporting module at the old path, long enough for the range checks and declaring `buildEvent` at the cited line, turns `RI-15` and `RI-16` green while the pointer it satisfies names a declaration that has moved. `RI-35` and the three worker suites would still have caught it here; on a tree where they did not, it would have landed. **A founder should decide whether the anchor rule wants a second leg for that shape**, because this row found it by looking for a way through and a less scrupulous row finds it the same way.
