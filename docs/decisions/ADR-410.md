### 4. The home, ruled on the writer's shape, with the losing options named

**`packages/ledger`.** The producer imports nothing, declares its transaction structurally, takes the caller's OPEN transaction as its first argument with no overload that omits it, and holds no `@merit/db` import by construction. That is not merely compatible with `packages/ledger`, it is that package's existing idiom line for line: [`packages/ledger/src/tx.ts`](../../packages/ledger/src/tx.ts) declares `LedgerTx` as a structural restatement of `SystemTx`, states that this package *"declares none, cannot import `client()` ... cannot import `drizzle-orm` or `pg`"*, and closes the two-statements-of-one-shape hazard the only way a package with no dependency edge can, by a suite that READS `packages/db/src/scoped-db.ts` and compares. `EventInsertTx` and `EVENT_INSERT_BRAND` are that same construction, arrived at independently one deployable over. [ADR-104](ADR-104.md) is the precedent for the shape of the problem: two deployables had to post, `RI-04` forbade an app depending on an app, and the answer was a library.

**`@merit/db` LOSES, AND IT LOSES TO A CHECK RATHER THAN TO A PREFERENCE.** It is the tempting answer, because the producer could then import `SystemTx` directly and stop restating a brand as a string. Two things refuse it and both were verified at source:

- `apps/api/test/db.test.ts` pins, as a map, every file under `apps/api/src` that names the accessor, and its `importsIn` helper matches `export ... from` as well as `import`. A module at the old path that re-exported the producer out of `@merit/db` adds a key to that map and turns that case RED.
- **AND THE WORSE HALF IS THE WIRING THIS CHOICE WOULD LATER FORBID.** `apps/worker/test/digests.test.ts` case 10.2 asserts that `src/db.ts` is still the only file under `apps/worker/src` that imports `@merit/db`. A future row installing the sink would have to name the package in the file that composes it, or route the producer through the accessor door itself. The first breaks that assertion and the second widens the one door [ADR-165](ADR-165.md) exists to keep narrow. **A home that makes the wiring it exists to enable illegal is the wrong home.**

**`@merit/rules-engine` LOSES ON ITS STATED CONTRACT, AND NO GATE WOULD HAVE CAUGHT IT, WHICH IS WHY THE REASON IS WRITTEN DOWN.** Its manifest describes it as *"Pure rule computation, zero I/O"*, `RI-01` holds it to no workspace dependency and `RI-07` walks its transitive graph for Node builtins. The producer passes all of that: it imports nothing, so the graph stays empty. **The `merit/engine-purity` lint rule was RUN over the producer placed in that package's `src` and reported zero problems**, and the probe was proved live by appending `export const seeded = new Date();` to the same copy and watching it report the clock error and `no-restricted-globals` together. So the refusal is a judgement, stated as one: `TRANSACTION_EVENT_WRITER`'s entire purpose is to perform `tx.insert(...)`, and a package whose guarantee is that it computes and never writes is not improved by holding the one module whose job is the write.

**AND A NEW `packages/events` IS NOT REFUTED, IT IS DEFERRED.** [ADR-408](ADR-408.md) section 10 calls it the correct answer at the price of a `VG-12` admission and two manifest lines. Nothing here forecloses it: the producer is one file and one barrel block, and moving it again would cost what this row's move cost minus the six repairs, which are done.

**ONE PART OF THAT REFUSAL IS PERMANENT AND IS NOT LIFTED BY A WIDER FENCE.** `RI-15`'s third finding names `buildEvent` beside its pointer, so [ADR-212](ADR-212.md)'s anchor applies: the cited line must DECLARE that name or sit inside a declaration the sentence names. Four forms were measured at the cited coordinate. `export function buildEvent(...)` and `export const buildEvent = ...` satisfy the anchor; `export { buildEvent } from '...'` and `export { build as buildEvent }` do not. **So the only way to keep that pointer green without touching the citing file is to declare `buildEvent` a second time, in the file the move exists to take it out of.** That would make an invariant report a pointer as verified exactly where the thing it names had moved, which is the defect `RI-15` was written for. It was refused before the fence widened and it is refused after. **The pointer was repaired by REMOVING THE COORDINATE, on [ADR-404](ADR-404.md)'s rule that a coordinate repaired to a value its own wave invalidates is the defect re-armed with a fresher date.**

**THE DISPATCHER READ THAT REFUSAL AND ANSWERED IT BY WIDENING THE FENCE RATHER THAN BY ARGUING WITH IT**, stating in terms that the contradiction was its own: the row told this session to move the writer and simultaneously fenced it out of every binding that names its source path.

### 7. The seventh binding, which is a finding about the check rather than about the move

**`RI-35`'s `event-sink-caller` PROBE CANNOT TELL A PUBLICATION FROM AN INSTALL, AND NOTHING HAD EVER ASKED IT TO.** It looks for `TRANSACTION_EVENT_WRITER` followed by `.`, `,` or `)` under any `src/`, as its proxy for a VALUE POSITION, and it excludes exactly one file, the module that declares the name. **A name inside a barrel's re-export LIST satisfies that proxy and is not a value position at all**, so publishing the writer in the same block as everything else made the register report an install that does not exist. That could not arise before this row, because the producer had never been published from a package.

**IT IS ANSWERED IN THE BARREL AND NOT IN THE PROBE, AND THE REASON IS RECORDED WHERE THE LINE IS.** `TRANSACTION_EVENT_WRITER` is published by a statement of its own, whose FIRST reason is what it is: everything else `packages/ledger` exports is a pure function, a constant or a type, and this is the one export that is an ADAPTER performing an insert into an append-only table. The probe consequence is stated beside it as the second reason rather than left to be discovered. **The probe's power over a real install is untouched**: a file that calls `makeEventSink(...)` or passes this value is still caught wherever it is written, which section 8's last case asserts by deriving that `apps/worker/src` contains no such call today.

**THE CORRECT REPAIR IS NOT THIS AND IT IS NAMED.** The register carries a `sweptBy` field for exactly this reasoning, and a registration there saying that a re-export list is not a value position is the shape this corpus uses for a known false positive. That is a change to `packages/tooling/checks/absence-claims.mjs` beyond the one constant this row was granted, and it is owed to whoever holds that package.

### 11. Approval

  **THE FIRST IS THAT A ROW'S FENCE AND A ROW'S OBJECTIVE WERE IN CONTRADICTION AND ONLY RUNNING THE WORK FOUND IT.** The dispatch asked for the move and fenced this session out of every binding that named the producer's source path.
