### 3. What `DetectorRunnerIo` requires, member by member

The interface is declared in [`apps/worker/src/detectors/ports.ts`](../../apps/worker/src/detectors/ports.ts) and has five members. Each was traced to whatever serves it.

| Member | What it must supply | Producer today |
|---|---|---|
| `transact` | The unit of work a run reads and writes in, taking the callback rather than handing back a handle | **`postgresDetectorTransact`**, over `LIVE_DB.batch` at `systemDb('nightly-batch')` |

**FOUR OF THE FIVE ARE SERVED, AND THEY ARE SERVED BY REAL CODE RATHER THAN BY A PLAN.** `postgresDetectorRunnerIo` in [`apps/worker/src/detectors/adapter.ts`](../../apps/worker/src/detectors/adapter.ts) composes them and is exported through the barrel. **The sentence in the dispatch that the runner "does not run" is therefore too strong as stated**, and the accurate sentence is the one section 6 derives: it runs, and everything it does is thrown away.

**AND THAT REASON IS NOW PARTLY OUT OF DATE IN ITS OWN TERMS.** It says *no adapter is installed*. An adapter IS installed, for four members, and `UNWIRED_DETECTOR_RUNNER_IO` is no longer the only inhabitant of its type. ### 6. The sentence that mattered most, and the repair that removes it

Sections 3 and 5 together produced a fact that no record in this tree stated, and it was true when this row started:

> **`D-02` runs today, finds its own canary, and writes nothing.**

`runner.ts` emitted `detector.run_completed` FIRST and UNCONDITIONALLY, inside the write transaction, before any page. The refusal rolled back the `detector_runs` row inserted before it. Run against the composed default, **every one of the fourteen came back `unrecorded`, the one that works included.**

**THAT IS A DEFECT AND NOT A DESIGN, AND THIS ROW RULES IT SO.** The reasoning that allowed it is in `adapter.ts` and it is sound about the case it is about:

> a `detector_runs` row committed without its `detector.run_degraded` page is that dashboard with an extra step

**IT WAS APPLIED TO A POPULATION IT IS NOT ABOUT.** A row committed without its page is `AS-M7-05`'s dashboard with an extra step **only where there is a page**, and a non-degraded run has none. The emit that was destroying every run row was `detector.run_completed`, whose consumers `EVENTS` gives as *"BI, ALERT on failure"*.

**AND NO RULE ANYWHERE BINDS THAT NAME TO THE RUN ROW.** `ports.ts`'s `DetectorEventPort` states the criterion it relies on `ADR-006` for, and it states it about one name: *"`detector.run_degraded` commits with the run row that is degraded, or neither does"*. [M07](../plans/M07-risk-abuse.md) and [EVENTS](../architecture/EVENTS.md) were both searched for a transactional requirement on `detector.run_completed` and neither carries one. Against that stands `INV-M7-07`, which is not ambiguous: *"Every detector run is recorded, including runs that raised nothing"*.

**SO THE ORDER IS INVERTED AND THE FAILURE IS SPLIT.**

| Event | When it is emitted | What its failure does now |
|---|---|---|
| `detector.run_degraded` | First, and only when the run is degraded | **THROWS. Unchanged.** The run row goes down with the page it could not write, which is the criterion `ports.ts` states |
| `detector.run_completed` | Second, on every run | **RETURNED, not thrown.** The run row commits and the refusal is put on the outcome the caller already reads |

**IT IS RETURNED AND NOT SWALLOWED, AND THAT DISTINCTION IS THE WHOLE CONTROL.** A swallowed emit is the no-op sink `adapter.ts` calls the worst available value in that file, arriving by another door. Every outcome under the refusing sink now carries `DetectorAdapterUnwired` by name in `DetectorRunOutcome.error`, so a caller learns the BI point was lost without the estate losing the run.

**WHAT THE COMPOSED DEFAULT DOES NOW:**

| Under `postgresDetectorRunnerIo(db)` | Before | After |
|---|---|---|
| A non-degraded run, which is all fourteen today | **unrecorded** | **RECORDED, carrying the refusal** |
| A degraded run | unrecorded | **unrecorded. Deliberately unchanged** |

The degraded case is asserted as a control in both `test/detector-adapter.test.ts` section 2 and the census, because a suite that stopped checking it would have bought `INV-M7-07` at `AS-M7-05`'s expense.
