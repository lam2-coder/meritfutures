## ADR-081: `hash.ts` moves into the engine, and the SHA-256 is hand-rolled because a standing ruling says so  (2026-08-23, status: accepted)

**This entry moves SD-08's canonical serialization from [`apps/worker/src/batch/state-hash.ts`](../../apps/worker/src/batch/state-hash.ts) to [`packages/rules-engine/src/hash.ts`](../../packages/rules-engine/src/hash.ts), where [M01 section 1.3](../plans/M01-rules-engine.md)'s layout puts it, and it invents nothing.** The placement was ruled by the [2026-08-17 review desk](../reviews/2026-08-17-review-desk.md) section 3, the export test was ruled by [ADR-078](ADR-078.md), and what is left for this session is to apply both and prove no digest moved.

- **Context:** the module was written in `apps/worker` deliberately and *"so that resolving it is a FILE MOVE"*. Its header named two conditions. The first was a wait: the review desk held it there *"until `RE-D-03` exists"*, and `RE-D-03` exists as `RI-07` in [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs)`:526`, which walks this package's transitive module graph. The second was the `node:crypto` question, which the header called *"not a decision to make in passing"* and which the same review desk had already decided.

- **Decision:** `hash.ts` lives in the engine. Its SHA-256 is **hand-rolled in integer arithmetic**, with no import of any kind beyond two relative ones. The public surface goes from **fourteen names to twenty, gaining exactly two functions**. **No stored digest changes**, and the proof is a hex value measured before the move and pinned in two test files afterwards.

---

## 1. This is an APPLIED ruling, and reading it as a new one is the way to get it wrong

The [2026-08-17 review desk](../reviews/2026-08-17-review-desk.md) section 3 is titled ***"`hash.ts` hand-rolls SHA-256. It does not take a lint exception, and it waits for `RE-D-03`"***. Its options table rejects the alternative in its own words: amending `RE-D-03` to exempt `node:crypto` is ***"out on constitution grounds. Working agreements, section 9: never weaken a gate to pass it."***

**So the only open question was whether the desk's reasoning still holds against the tree, and it holds harder than the desk stated.** The desk named two mechanisms. There are three, and the third is the one that settles it:

| | what it refuses | where |
|---|---|---|
| `RI-07` / `RE-D-03` | a Node builtin anywhere in the engine's transitive closure | [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs)`:526` |
| `merit/engine-purity` | **every** non-relative import under `packages/rules-engine/src/**`, plus the bare global `crypto` through the `no-restricted-globals` block beside it | [`engine-purity.js`](../../packages/eslint-plugin-merit/rules/engine-purity.js)`:124`, [`eslint.config.js`](../../eslint.config.js) |
| **`"types": []`** | `node:crypto` and `Buffer` as **types**, so the import is a COMPILE error before it is a lint finding | [`tsconfig.json`](../../packages/rules-engine/tsconfig.json)`:14` |

**The third is not a fourth spelling of the first two.** A lint rule can be disabled with a comment and a graph check can be argued with; the tsconfig one is the mechanism `tsconfig.json`'s own comment calls *"the only one a lint-disable comment cannot route around"*. **The hand-roll is not the better of two workable designs. It is the only shape that compiles.**

**M01 section 1.4 does contradict itself and that is recorded rather than resolved here.** Its banned-constructs table permits *"`crypto` **beyond a pure hash**"*, which reads as licence for the import; two paragraphs later the same section specifies `RE-D-03` as *"a dependency-graph assertion that the package's transitive imports contain **no Node builtins**"* and calls it a merge blocker. The review desk found this and ruled on it. **This entry does not amend M01**, which is frozen and would need its own ADR: it records that the enforcement half is the half the tree implements, three times over, and that the hand-roll satisfies **both** halves at once, which is what made the desk's answer the only one that survives.

## 2. The export, which is ADR-078's test run a second time, and TWO cases rather than six

[ADR-078](ADR-078.md) is precedent now. Section 1.3's layout lists `hash.ts` **exactly as it lists** `payout/clamp.ts` and `replay.ts`, so the site count decides nothing here either; 1.3's own reason decides it. *"Every additional export is a way for a caller to reimplement a rule slightly differently"* is **served** by withholding when nothing is lost, and **defeated** by withholding when a caller must therefore write its own. `apps/worker/src/batch/state-hash.ts` was that second implementation, in the open, exactly as `apps/worker`'s own fold was for `replay`.

Six names join the surface. **They are two cases, and the difference is stated because a future session will read this as precedent.**

**Case one: four names plus an error class, defeated by withholding IN PRODUCTION.** Nothing but `stateHash` computes the digest and nothing but `canonicalStateSerialization` produces the bytes a divergence report prints (M01 Appendix B.2: the page says which number moved). [`apps/worker/src/batch/replay.ts`](../../apps/worker/src/batch/replay.ts) walks `HASHED_COLUMNS` at `:167` and `ENGINE_GATE_LEAVES` at `:173` to name **which** field diverged, so withholding either table does not prevent a second copy of ADR-026 C-07's order, **it compels one**, in the file whose whole job is deciding whether two rows agree. `StateHashError` rides with them on [`index.ts`](../../packages/rules-engine/src/index.ts)'s own reasoning for `EngineEvent` and ADR-078's for `ReplayAssertionError`: a class computes nothing and has no second implementation to drift from.

**Case two: `EXCLUDED_COLUMNS` has NO production consumer, and it is exported anyway for a different reason.** [`apps/worker/src/index.ts`](../../apps/worker/src/index.ts)`:55` re-exports it and [`state-hash.test.ts`](../../apps/worker/test/state-hash.test.ts) asserts over it. That is all, and calling it *"the only executable copy of C-07's exclusion ruling"* would be dressing a test dependency as a production one. **The honest reason is that withholding it makes the differential oracle unreachable from `apps/worker`**, because the shim can only re-export what the engine exports, and that oracle is the entire external check on a hand-rolled cryptographic primitive. **A test is a legitimate reason to export a frozen table PRECISELY WHEN it is that, and not when it is a coverage exercise.** This entry is not a licence to export a table nothing reads.

**The clause below names the list rather than a count, because ADR-078 had to correct a count.** [`evaluate.golden.test.ts`](../../packages/rules-engine/test/evaluate.golden.test.ts) now pins twenty names, and it gains a sibling test that counts **functions** specifically, subtracting the four error classes by name because a class is `typeof === 'function'` too and a predicate cannot see the difference. **Ten functions become twelve.** The five new type exports (`HashedState`, `StateHashSubject`, `HashedColumn`, `ExcludedColumn`, `GateLeaf`) are erased at compile time and appear in neither list, which is said here so a reader does not go looking for them.

**`sha256` and `utf8Bytes` are MODULE exports of `hash.ts` and are deliberately NOT on the package surface.** `clampPayout` is the precedent exactly: [`payout/clamp.ts`](../../packages/rules-engine/src/payout) exports it and `index.ts` withholds it, because 1.3's list governs the **entry point** and not every module boundary inside the package. The engine's own tests already import internals by relative path, which is the only way the known-answer vectors reach a raw digest at all. **A primitive testable only through nineteen framed columns is one whose failures arrive as a state hash nobody can localise.**

## 3. A canonical digest is a compatibility surface, and that is the ruling this entry exists to make explicit

`state_hash` is not an internal detail of one function. **It is compared against a recomputation of the same state, months later, by a job that pages.** INV-04 is *"replaying every mark from day one reproduces stored state byte-identically"*, and M01 Appendix B.2 compares the hash **first**, diffing field by field only on mismatch, because a field-by-field comparison of roughly 1.25M rows is how a nightly self-audit becomes slow and then becomes disabled (FM-17).

**What makes the serialization canonical**, all of it load bearing and none of it inferable from the type:

| | |
|---|---|
| the covered set | ADR-026 C-07's **nineteen** columns, and no twentieth |
| the order | C-07's ordinals 1 to 19, carried in the array so it is checkable rather than merely true |
| column 19 | the twenty-five gate leaves in `EngineGateResults`' **declaration** order, never key iteration, which M01 1.4 bans and names *"canonical serialization in `hash.ts`"* as the replacement for |
| the framing | `<utf8 byte length>:<utf8 bytes>` per field, because plain concatenation is not injective and the collision is one column pair away: `traded_days_count = 1, win_days_count = 23` and `12, 3` both render `123`, which is exactly the pair R-33 and R-34 gate on |
| `null` | `~null`, a sentinel whose alphabet no covered value shares |
| numbers | `bigint` base-10; `integer` through `String` with a safe-integer refusal rather than a rounding |
| booleans | `true` / `false` |
| the bytes | UTF-8, with an unpaired surrogate replaced by `U+FFFD`, which is what Node and the WHATWG encoder both do |
| the digest | SHA-256, thirty-two bytes, which `rule_states_hash_is_sha256` checks |

**What is deliberately outside**, carried in `EXCLUDED_COLUMNS` with its reason per row: `context_gates` (SD-06 split the gates precisely so a freeze applied last March does not diverge every night), `engine_version` and `calendar_revision_id` (both version-like inputs; each would turn one ordinary change into a universal divergence), `computed_at` (wall clock, not state), and `id` / `state_hash` themselves.

**What a future change to any line of that table costs.** Every stored hash becomes unequal to a recomputation of the same state. The nightly then reports **replay divergence that did not happen**, on every row of every account at once, and **no migration repairs it**: the only remedy is the audited rewrite in M01 Appendix B.4. The framing was chosen while `rule_states` held zero rows, which `0035`'s header says in its own words, and **that moment does not come twice**. So the digest is now **pinned as a hex literal** in two test files rather than left as a property nothing states.

## 4. What running it found that reading it did not

**The digest is unchanged, and it was measured in the right order.** Before any file moved, on `origin/main` at `acd65a6`, through the `createHash('sha256')` that lived in `apps/worker` at the time, the fixture subject serializes to **309 bytes** and hashes to **`6f640ab71dacea9cb5f7c8502e2e11cafb8ab126d1c79c9c9761087112f60d60`**. That value is now asserted in both [`hash.test.ts`](../../packages/rules-engine/test/hash.test.ts) and [`state-hash.test.ts`](../../apps/worker/test/state-hash.test.ts). **A before-value measured after the move with the new code proves nothing**, and the distinction is easy to lose at the last commit.

**`apps/worker/test/state-hash.test.ts` became worth more than any test written for this session, and not one of its 603 lines was edited.** It transcribes the whole serialization by hand from C-07 and hashes it with `node:crypto`, then mutates all nineteen columns and all twenty-five leaves and asserts the digest moves. Routed through the shim it is now **an independent implementation of the serialization AND an independent SHA-256**, checked against the hand-rolled one. **Under `"types": []` the engine's own test directory cannot import `node:crypto` either**, so this file is the only place in the repository where the hand-roll meets OpenSSL, and keeping it unchanged is the strongest single control this entry has.

**The subtlest defect class is the UTF-8 encoder, and no fixture reaches it.** `Buffer.byteLength` does not exist in the engine, so `hash.ts` writes the encoder out, and it must agree with Node on **unpaired surrogates**, which both replace with `U+FFFD`. Every value in a real `rule_states` row is ASCII, so a fixture would pass while the encoder was wrong. The differential block drives lone highs, lone lows, a high followed by a non-surrogate, a high at end of string, valid pairs and a reversed pair through the real serializer, **asserting both halves each time**: the digest **and** the length prefix. A digest that matched while the prefix disagreed would mean both sides are wrong the same way, which is what a single-sided check cannot see.

**Both controls were watched failing on a seeded violation.** Encoding a lone high surrogate as itself instead of `U+FFFD` fails **7** tests across the two files; flipping one bit in `K[0]` fails **38**. A control watched only passing is a control nobody has evidence for.

**The hand-roll's wall clock, reported and not tuned.** At the nightly's 5,000 accounts, `stateHash` costs **121 ms** against **80 ms** for `node:crypto` over the identical serialization: **24.3 µs against 16.0 µs per account, 1.5x**. The whole difference across a night is **41 ms**. It is stated so nobody has to guess later, and it is not a licence to optimise a primitive whose correctness is the only property that matters.

## 5. Consequences

The other four are one class and three frozen tables.
- **`apps/worker/src/batch/state-hash.ts` survives as the `Buffer` boundary and nothing else.** `ports.ts:141` types the column as `Buffer` and `replay.ts:161` compares two with `.equals()`; the engine returns `Uint8Array` because `Buffer` does not exist under `"types": []`. One wrapped call, on the side of the boundary where `@types/node` is in scope. `nightly.ts`, `replay.ts` and `apps/worker/src/index.ts` are untouched, which is what let this fence hold to one file in `apps/worker/src`.

ADR-078 is accepted and a signed entry moves by amendment, not by a later session editing it in passing.

  **THE HAND-ROLLED SHA-256 WAS DIFFERENTIALLY RE-TESTED FOR THIS SIGNATURE, AND THAT IS WHY THIS LINE READS GRANTED RATHER THAN WITHHELD.** A fresh oracle sharing no code with [`hash.ts`](../../packages/rules-engine/src/hash.ts) was run against `node:crypto` over **281 inputs**: every length from 0 to 200 bytes; the block and padding boundaries 55, 56, 63, 64, 119, 120, 127 and 128 in both one-byte and two-byte encodings; the full single-code-unit range in sixteen blocks; **lone high and lone low surrogates, alone and embedded**; astral pairs to `U+10FFFF`; and the entry's own length-prefixed framing at every field count from 1 to 19 and at value widths 0, 1, 31, 32, 33, 255, 256 and 1024. **281 of 281 matched. Zero mismatches.**

  **What that oracle does NOT cover is stated rather than left to be assumed.** It exercises `sha256` and `utf8Bytes`, the primitive; `canonicalStateSerialization` is differentially tested against `node:crypto` by [`state-hash.test.ts:171`](../../apps/worker/test/state-hash.test.ts), which runs in CI and is the file this entry kept reachable by exporting `EXCLUDED_COLUMNS`.

  **WHAT THE DELEGATED GRANT DOES NOT BUY.** A differential over 281 inputs is evidence about the implementation and **not** a review of the design choice, and the entry is right that a changed digest is indistinguishable from a replay divergence. **[P2](../plans/P2-rules-engine-build.md) section 9 already records that `134` and `135` merged on delegated authority without an E2 read; this makes three, and the note there says in its own words that the requirement *"is not discharged by this note"*.** The same holds here. **The founder's line-by-line read of [`hash.ts`](../../packages/rules-engine/src/hash.ts) remains owed. The code is merged; this signature is what stops live money-path code from enforcing an UNSIGNED ruling while that read is outstanding, and it is not a substitute for it.**

  **THE ONE CLAUSE TO CHECK BEFORE SIGNING:** `RI-07` walks `hash.ts` and reports no Node builtin, and the fixture subject's digest is **`6f640ab71dacea9cb5f7c8502e2e11cafb8ab126d1c79c9c9761087112f60d60`** — the value measured on `origin/main` before the move — while `Object.keys(engine).sort()` is exactly the **twenty** names pinned in [`evaluate.golden.test.ts`](../../packages/rules-engine/test/evaluate.golden.test.ts), **gaining exactly two FUNCTIONS**.

  **It names the digest and the list rather than counts, on purpose**, and ADR-078 is why: a candidate clause that counts is a clause that drifts, and the count that entry was handed was wrong. A hex literal cannot drift at all.

  **What it costs if it is wrong.** A changed digest is **indistinguishable from a replay divergence**: the nightly pages on every row of every account at once, the cause is invisible in the diff because both sides are behaving correctly, and no migration repairs it. **The specific risk this entry accepts is the hand-rolled SHA-256.** It is mitigated rather than argued away: 28 known-answer vectors of which not one digest came from this code, a differential oracle against OpenSSL that predates the move and was not edited, and two seeded violations watched failing. **If that mitigation is judged insufficient, the remedy is not a lint exception** — the review desk closed that on constitution grounds — **it is keeping the serialization in the engine and the digest in `apps/worker`**, at the cost of leaving `hash.ts` half-written against M01 1.3's own description of it, *"canonical serialization and state hashing"*.

This entry adds a **hand-rolled cryptographic primitive on the money path**, which is the strongest case for a line-by-line read this project has produced.
