## ADR-087: the publish decision resolves to a run that FINISHED and ran over THIS row, and the digest half stays open because it has no producer  (2026-08-24, status: proposed)

**No frozen document is amended by this ruling.** [`0045_simulation_runs.sql`](../../packages/db/migrations/0045_simulation_runs.sql) made the link from a published `plan_version` to the `simulation_runs` row it was decided on **exist**; nothing made it **sound**, because a `CHECK` cannot read another table. This entry decides the mechanism that makes it sound, installs it as [`0047`](../../packages/db/migrations/0047_publish_decision_is_sound.sql), and states plainly which of the three named defects it does **not** close and why. **It is money path: `plan_versions` is the rule contract every funded account is sold under, so the signature is the founder's and this branch waits for the line-by-line read.**

- **Origin:** [session 120](../sessions/2026-08-21-session-120.md) opened `OI-29` in the migration that created the defect, in its own header: *"THE FK PROVES A ROW WAS NAMED AND PROVES NOTHING ABOUT WHAT IT SAYS."* [Session 132](../sessions/2026-08-22-session-132.md) split it, sending the digest half to `P2-g` and recording that *"its enforcement, a trigger or an application publish path, is P3's"*. This is that half, dispatched as `P3-e` by the [P3 build plan](../plans/P3-ledger-billing-identity.md).

- **Context:** [`0045:236`](../../packages/db/migrations/0045_simulation_runs.sql) carries

  ```sql
  ALTER TABLE plan_versions
    ADD CONSTRAINT plan_versions_publish_decision_recorded CHECK (
      status <> 'published'
      OR num_nonnulls(decided_on_simulation_run_id, simulation_waiver_reason) = 1
    );
  ```

  [DELTA_MANIFEST](../../packages/db/DELTA_MANIFEST.md) names three states that satisfy it and are wrong: a publish decided on a `failed` run, a publish decided on a run over a since-edited draft whose `rules_digest` no longer matches, and a publish decided on a run belonging to a different plan.

- **Decision:** a **trigger**, not an application publish path, and it closes **two of the three**. `0047` installs `assert_publish_decision_is_sound()` on `plan_versions`, scoped to a publish that names a run. Check A requires the run's `status` to be `complete`. Check B requires that, when the run names a plan version at all, it names **the row being published**. The staleness state stays open as `OI-29b`, because `rules_digest` **has no producer anywhere in the tree** and there is nothing for a comparison to agree with.

```
$ grep -n 'plan_versions_publish_decision_recorded' packages/db/migrations/*.sql
0045_simulation_runs.sql:236:  ADD CONSTRAINT plan_versions_publish_decision_recorded CHECK (
```

One line. The constraint was added by `0045` in session 120, together with both columns it reads (`SD-M21-02`). **`0004` is cited correctly for a different fact**: [`0004:183`](../../packages/db/migrations/0004_catalog.sql) is where the corpus states the trigger's cost, and [`0045:48`](../../packages/db/migrations/0045_simulation_runs.sql) quotes it from there. **Two facts, one file number, fused**, and the fusion propagated into three documents.

**What it would have cost.** A session writing `0047` from the reservation alone goes to `0004` for the predicate, does not find it, and either invents one or supersedes the wrong thing. The dispatch's own instruction is what caught it, and its stated reason was different: it warned against citing a constraint that a **later** migration had superseded, which is [session 129](../sessions/2026-08-22-session-129.md)'s `0015:208` error repeated three times. **The grep caught an error in the opposite direction, an origin cited too early rather than too late.** The instruction was worth more than the reason given for it.

`ADR-087`'s own ALLOCATION row and P3 section 8 are outside this session's fence. **They are reported here and in `ALLOCATION`'s `0047` row rather than edited.**

### 3. The ruling between the two mechanisms, and what the loser gives up

`0004:183` states the trigger's cost in terms: it *"is a weaker control: it can be disabled, and it fires per row rather than per constraint"*. **Both limbs are true of `0047` and neither is hedged.** `ALTER TABLE plan_versions DISABLE TRIGGER ALL` turns it off and nothing in the schema notices.

**The application publish path loses on a fact, not on a preference: it does not exist.**

```
$ grep -rn 'plan_versions' apps/ --include='*.ts'
apps/site/src/catalog/types.ts:136 ... (read-side types)
apps/worker/src/batch/ports.ts:42  ... (a comment)
```

Nothing in `apps/` writes a `plan_version`. **A control that would run in a code path nobody has written is not a control**, and it would stay absent for `psql`, for a migration, for an admin console, and for every path that is not it. The trigger is weaker where it runs and it runs everywhere.

**What the loser gives up, stated because it is the part that matters later.** The application path is **the only mechanism that could ever close the staleness state**, because it can call the TypeScript that would produce a `rules_digest`; a trigger cannot. **So this is not a refusal of the application path so much as an ordering of the two**, and section 4 is why the order is forced. When a publish path is written it should carry the digest comparison and this trigger should stay, because the trigger is what covers the paths the application is not.

### 4. Why the staleness state does not close, checked against the primary source rather than assumed

The [P3 build plan](../plans/P3-ledger-billing-identity.md) required this in terms: *"whether `rules_digest` is computable at all today is a fact you must check rather than assume."*

```
$ grep -rn 'rules_digest\|rulesDigest' --include='*.ts' --include='*.mjs' packages/ apps/ scripts/
(no output)
```

**Nothing writes `simulation_runs.rules_digest`.** [ADR-081](ADR-081.md) records that `hash.ts` is *"THE DIGEST HALF `OI-29` NEEDS, AND ONLY THE DIGEST HALF"*. **Measured against the file, that is not this subject.** [`hash.ts:691`](../../packages/rules-engine/src/hash.ts)'s `canonicalStateSerialization` takes a `StateHashSubject`, and [`hash.ts:557`](../../packages/rules-engine/src/hash.ts)'s `HASHED_COLUMNS` is nineteen **`rule_states`** columns. What ADR-081 landed is a pure SHA-256 and an injective framing discipline, both reusable and **neither pointed at `plan_versions.rules`**. The digest half of `OI-29` is not written.

**And the database could hash it, which is why this is a ruling and not a limitation.** `pgcrypto` is installed at [`0001:22`](../../packages/db/migrations/0001_extensions_and_enums.sql) for `gen_random_uuid()`, so `digest(rules::text, 'sha256')` runs today. Installing that comparison in `0047` would **define** the canonical serialization of the rule contract to be PostgreSQL's `jsonb::text`, in passing, in a trigger, on the money path, binding on a TypeScript writer that does not exist.

**`jsonb::text` is not canonical over numbers, measured on the same cluster:**

```
SELECT digest('{"a":1.0}'::jsonb::text,'sha256') = digest('{"a":1}'::jsonb::text,'sha256');  -->  f

'{"a":1.0}'::jsonb::text    -->  {"a": 1.0}
'{"a":1.00}'::jsonb::text   -->  {"a": 1.00}
'{"a":1e2}'::jsonb::text    -->  {"a": 100}
'{"a":1,"a":2}'::jsonb::text -->  {"a": 2}
```

It sorts keys and normalizes whitespace, and it preserves trailing zeros. **So a draft re-saved with `5.0` where it held `5` would digest differently while being the same rule contract, and the trigger would REFUSE A LEGITIMATE PUBLISH.** That is the failure direction a money path cannot take. `hash.ts` carries `money()` and `count()` renderers precisely because a canonical serialization has to make that decision explicitly; `jsonb::text` makes it accidentally.

**A temporal proxy is not available either.** `plan_versions` carries `created_at`, `published_at` and `retired_at` and **no `updated_at`** ([`0004:52-135`](../../packages/db/migrations/0004_catalog.sql)), so a draft edit leaves no timestamp for a run to be compared against. There is no second-best version of this check.

**`OI-29b` carries the remainder**, narrowed by check B: after `0047` the staleness case survives only for a run whose `plan_version_id` is `NULL`.

### 5. Check B is stronger than the state it closes, and the `NULL` branch is the fence's decision rather than this entry's

**Stronger.** DELTA_MANIFEST's third state is *"a run belonging to a different plan entirely"*. A guard written to that wording compares `plan_id` and **accepts a run over a different VERSION of the same plan**, which is the identical defect: the run ranged over some other version's rules either way. So the test is the row. `REJECTION 5` in the probe is the case the manifest does not name.

**And it stops where a pinned probe says it must.** `simulation_runs.plan_version_id` is nullable on purpose ([`0045:66`](../../packages/db/migrations/0045_simulation_runs.sql)): *"the run is over a draft, and a draft may not yet be a row the run can name."* Requiring a non-`NULL` anchor would close the last of the staleness hole **and would break `SUCCESS 4` and case `0028 A` of [`probe_simulation_decision_record.sql`](../../scripts/db/probe_simulation_decision_record.sql)**, both of which publish against a `NULL`-anchored run and both of which are asserted **writable** there.

**Turning an asserted-writable shape into a rejection is a change to what `0045` ruled, not an enforcement of it.** That file is outside this session's fence and the branch must end mergeable. **The hole is named with its cost rather than left to be found**, which is `0045`'s own habit applied to `0045`, and `SUCCESS 3` asserts it in the probe output so that the day somebody closes it, the probe says what they broke.

### 6. Foreclosure: a fourth check was available and is deliberately not installed

`completed_at <= published_at` is checkable in the same trigger with no extra read, and it would refuse a publish citing a run that had not finished when the decision was recorded. **It is not one of the three.**

**A money-path migration that installs an unruled constraint because it was cheap is how a schema acquires rules nobody decided**, and the next reader cannot tell which of its controls were ruled and which were convenient. It is recorded here as a candidate for a ruling and left out of `0047`. **The number is not spent on it and the ruling is not made by a session that was not asked to make it.**

### 7. Consequences

- **[`0047_publish_decision_is_sound.sql`](../../packages/db/migrations/0047_publish_decision_is_sound.sql) adds one function and two triggers. It supersedes nothing and retires no name.** [ADR-053](ADR-053.md)'s refusal to reuse a superseded constraint's name **does not arise**, and that is worth stating because the reservation expected it to: `0045`'s `CHECK` is not wrong, it is **incomplete**, and it keeps standing beside the trigger. The question was asked and answered rather than skipped.
- **Two triggers, one function, and the split is the scope.** A `WHEN` clause cannot read `TG_OP`, so *"on insert, or on the `draft -> published` transition"* needs two attachments. Without the `OLD.status IS DISTINCT FROM 'published'` limb the guard would re-run on every update to an already-published row; two `BEFORE ROW` triggers fire in **name order**, `plan_versions_publish_decision_is_sound` sorts before `plan_versions_published_immutable`, and a row refused for being **immutable** would report a soundness message instead. **The probe's `0028` case asserts that it does not.**
- **A `BEFORE ROW` trigger fires before the table's `CHECK` constraints, so the `IS NOT NULL` limb of both `WHEN` clauses is load bearing.** Cases `0045 A` and `0045 B` in the probe watch `plan_versions_publish_decision_recorded` go on refusing its two states **by name** with the trigger installed. Without that direction, a guard scoped one clause wider would silently take over those refusals and every caller resolving publish failures by constraint name would stop working, while both rows still appeared to be refused.
- **[`probe_publish_decision_is_sound.sql`](../../scripts/db/probe_publish_decision_is_sound.sql) is wired into [`corpus.yml`](../../.github/workflows/corpus.yml) and pinned in `CI-06h`'s required list in one commit**, per `CI-06s`. `DELTA_MANIFEST` section 18 records that a probe wired and left unpinned has happened three times.
- **Rejections are asserted by the check named in the message, not by SQLSTATE alone.** A trigger `RAISE` carries no `CONSTRAINT_NAME`, so `GET STACKED DIAGNOSTICS CONSTRAINT_NAME` returns empty and the sibling probe's technique is unavailable. Matching `OI-29 check A` / `OI-29 check B` is the equivalent discrimination; without it a row refused by any of the table's checks, or by `0028`, would score as this trigger working.
- **`OI-29` moves from open to PARTLY CLOSED and `OI-29b` opens.** `DELTA_MANIFEST` section 25 carries both, and the `OI-29` row is amended in place rather than joined by a second row.
- **Both data-model pages state the guard**, [`simulation_runs`](../architecture/data-model/simulation_runs.md) and [`plan_versions`](../architecture/data-model/plan_versions.md), because the next reader of `decided_on_simulation_run_id` is standing at the column and not in the manifest. That is [session 120](../sessions/2026-08-21-session-120.md)'s stated reason, applied to the repair as it was to the defect.
- **No `SD-nn` and no `U-nn`.** Nothing is added to the schema: no table, no column, no index. `tables`, `indexes` and `checks` are unchanged from `0046` and `triggers` goes 16 to 18.
- **No `CI-06` letter.** `CI-06s` already covers the wiring, and `x` is not a free letter: unlettered gates are the shape.
- **`0048` stays free.**
