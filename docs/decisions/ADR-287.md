**The predicate itself is fully ruled and fully buildable.** `G-HOLD-REQUIRED` is "an unresolved `risk_flags` row of **severity 4 or above**, in status `open` or `investigating`, against the account or the identity at request time" ([`STATE_MACHINES.md:414`](../architecture/STATE_MACHINES.md), ruled by [ADR-062](ADR-062.md) section 3). `severity` ([`0008_risk.sql:126`](../../packages/db/migrations/0008_risk.sql)) and `status` ([`:128`](../../packages/db/migrations/0008_risk.sql)) are both columns on a table this handle reads. **The route does not re-derive the band and an implementation must not either**; a second high-severity threshold defined in an adapter is this repository's most repeated defect.

**`risk_flags` CARRIES SEVENTEEN COLUMNS AND NEITHER OF THE OTHER TWO IS AMONG THEM.** Read in full at [`0008_risk.sql:114-170`](../../packages/db/migrations/0008_risk.sql): `id`, `identity_id`, `account_id`, `flag_type`, `severity`, `status`, `source`, `detector_run_id`, `evidence`, `first_detected_on`, `resolved_at`, `resolved_by`, `resolution_note`, `sla_due_at`, `first_touched_at`, `created_at`, `updated_at`. **AND THE WRITE SIDE MAKES BOTH MANDATORY, WHICH IS WHY THIS IS A BLOCKER RATHER THAN A GAP.** `payout_requests_hold_is_complete` ([`0031_payout_hold_and_identity_restriction.sql:63-72`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql)) makes all five hold columns present or all five absent, and `hold_tos_clause` ([`:51`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql)) and `hold_reason` ([`:52`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql)) are two of the five. **A severity-4 flag standing at request time therefore makes the hold branch of the money path UNWRITABLE on this tree**: the row the database will accept needs two values nothing can produce.

**`reason` IS ABSENT FOR A SHARPER REASON THAN "NO COLUMN", AND IT IS THE `open` HALF OF THE PREDICATE.** [M07:15](../plans/M07-risk-abuse.md) rules that "the detector's output is unchanged, still `open` and nothing else (`INV-M7-02`), and **no detector puts a request on hold**, because entering `investigating` is a human act with a written reason and a ToS clause." So a flag at `investigating` has a human's written reason somewhere and a flag at `open` has only `evidence`, which is the detector's numbers. **`G-HOLD-REQUIRED` fires on both.** A hold raised off an `open` flag has no written reason by construction, and `INV-M7-10`'s no-detector-detail promise forbids handing the trader the evidence instead.

**NO SUBSTITUTE IS ACCEPTABLE AND THAT IS WORTH STATING BECAUSE THREE LOOK PLAUSIBLE.** `flag_type` is a detector label and publishing it is the threshold disclosure [M07:365](../plans/M07-risk-abuse.md) refuses. `resolution_note` is `NULL` on exactly the two statuses this predicate reads, by `risk_flags_resolution_is_explained` ([`0008_risk.sql:165-169`](../../packages/db/migrations/0008_risk.sql)). A constant string is a hold nobody can justify, which is the thing `payout_requests_hold_is_complete` exists to make unwritable.

#### F2. `eligibility_snapshot_id` has no supplier anywhere in this repository

**`insertPayoutRequest` returns `Promise<{ readonly eligibilitySnapshotId: string }>`** ([`payouts.ts:564-566`](../../apps/api/src/routes/payouts.ts)), the route destructures it at [`:1177`](../../apps/api/src/routes/payouts.ts), and it becomes the wire field `eligibility_snapshot_id` at [`:1226`](../../apps/api/src/routes/payouts.ts), typed non-null on `PayoutResponse` at [`:248`](../../apps/api/src/routes/payouts.ts) and required by [API_CONTRACT section 6](../architecture/API_CONTRACT.md) at line **490**.

**THERE IS NO SUCH ID.** `grep -rn eligibility_snapshot packages/db/migrations` returns two lines and neither is an id: the column is `eligibility_snapshot jsonb NOT NULL` ([`0010_payouts.sql:74`](../../packages/db/migrations/0010_payouts.sql)). **The migration states in its own comment why there is no table**: "A jsonb column rather than a separate table because it is written exactly once, always read with its parent, and must never drift from it. A join here would add a way for THE PROOF AND THE DECISION to disagree" ([`0010_payouts.sql:70-73`](../../packages/db/migrations/0010_payouts.sql)). **A search of `docs/` for `eligibility_snapshot_id` returns exactly one line, `API_CONTRACT.md:490`.** No ADR names it, no design record carries it, and no gate has ever asked.

**SO A RULING IS OWED AND IT IS NOT A TRANSCRIPTION.** The two shapes an implementer would reach for are not equivalent and neither is obviously right. Returning `payout_requests.id` makes the field a second copy of `payout_request_id` in the same response object, which is a wire field that says nothing. Minting a fresh uuid returns an identifier that addresses nothing, which is worse: a client that stores it has a receipt for a proof it can never fetch, and no endpoint in the contract accepts one. **A migration adding a column is the third shape and it contradicts `0010`'s own stated reasoning**, so it is an `E2` supersession argument rather than an additive one. **This row does not take it.** Whichever way it goes, `payouts.ts`'s port shape or the frozen contract moves, and both are founder reads.

#### F3. Two fields of `PayoutRequestInsert` have no column, and the trap is that they look like they should

`PayoutRequestInsert` ([`payouts.ts:476`](../../apps/api/src/routes/payouts.ts)) declares `splitBp: number` and `clampReason: ClampReason` ([`types.ts:1041`](../../packages/rules-engine/src/types.ts)). **`grep -rn split_bp packages/db/migrations` and `grep -rn clamp_reason packages/db/migrations` each return ZERO lines.** `payout_requests` has no such column and no `ALTER TABLE payout_requests` in any migration adds one; the only file altering that table is `0031`.

**Both values are already stored, inside the snapshot.** `snapshotOf` ([`payouts.ts:1046`](../../apps/api/src/routes/payouts.ts)) writes `clamp.reason` at [`:1060`](../../apps/api/src/routes/payouts.ts) and `clamp.split_bp` at [`:1063`](../../apps/api/src/routes/payouts.ts), and the whole object lands in `eligibility_snapshot`. **This is a LANDMINE and not a blocker**, recorded because the failure mode is silent: an implementer mapping the insert shape field by field finds two fields with no column, and the correct action is to write neither, because writing them anywhere else would state the same money fact twice on the money path.

**A third field is missing in the other direction.** `payout_requests.plan_version_id` is `NOT NULL` ([`0010_payouts.sql:68`](../../packages/db/migrations/0010_payouts.sql)) and `PayoutRequestInsert` does not carry it. ### 7. THE SLICING. Nine sessions, in order, with stop conditions
