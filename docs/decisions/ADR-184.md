### 2. THE RULING

> **1. THE EVENT FEED'S READ BELONGS ON `AdminReadSource` AS A SEVENTH METHOD, `listEvents`, AND NOT ON A PORT OF ITS OWN.** The discriminator is finding 8 and it is measured rather than felt: this deployable has **one admin READ port and four admin WRITE backends**, so "one module, one port" is not the tree's rule; **reads share a port and writes do not** share one. The feed is a read through `systemDb('operator-console')`, the same door, the same unit of work, the same authority. A second read port would be a second name for one door, a second wiring obligation, and a second "not wired" refusal for one missing thing.
>
> **NEITHER DEFENCE IN [`admin-source/index.ts`](../../apps/api/src/admin-source/index.ts) COLLAPSES AND THEY MOVE DIFFERENTLY, WHICH IS THE POINT.** The `Partial` plus `AdminSourceNotComposed` half gains **one arm**, `listEvents`, because that half is about what a DEPLOYMENT has composed. The `IMPLEMENTED_ADMIN_READS` plus `Pick` half is **UNTOUCHED**, because that half is about what THIS DIRECTORY implements and it implements no feed module. **The two halves disagreeing here is them working**: one says "the port has seven methods", the other says "this directory supplies two", and both are true.
>
> **2. `INV-M6-10`'s TWO MODES ARE CARRIED IN THE REQUEST, AS A REQUIRED DISCRIMINANT WITH NO DEFAULT.** `?scope=` admits `operational`, `identity` or `account` and **is required**. `scope=identity` requires `identity_id`; `scope=account` requires `account_id`; **a subject sent under a scope that does not name it is `validation_failed` and is never ignored.** The parse yields a closed union or it yields errors, and **no arm of that union means "no scope"**, so no path downstream of it can be reached without one.
>
> **THE THREE REFUSALS ARE REFUSALS AND NOT CORRECTIONS, AND EACH HAS ITS OWN REASON.** An absent `scope` is not defaulted, because `operational` silently redacts a drill-down and either named arm hands a bulk screen the licence a named query earns: **both defaults are wrong, so there is none.** A named scope with no subject named is the widest query wearing a narrow label. And `?scope=operational&identity_id=...` is two different queries in one request: **ignoring the parameter is the handler remembering, and a property a handler has to remember is `FM-M6-10` waiting to happen.**
>
> **3. THE WITHHOLDING IS A PROPERTY OF THE RESPONSE AND NOT OF THE RENDERER, AND IT IS A RULE ON THE SHAPE OF THE KEY.** Any key ending `identity_id` or `account_id` is gated, so finding 14's two third-party uuids are covered by construction rather than by enumeration. **The withheld VALUES are never a field on the response**: a body carrying them would ship every withheld identifier to the caller, which is the bulk read with an extra step. The control asserting that is run **over the serialized body** and not over the rows.
>
> **4. THERE IS NO `total` AND NONE IS NEEDED.** [ADR-157](ADR-157.md) refuses the scalar aggregate on the read path and this entry does not widen it. Section 1's own pagination envelope already carries both honest facts: `data.length` is counted rather than claimed, and `next_cursor === null` is the difference between an exhausted query and a truncated page.

### 3. Why ruling 1 is not the answer it first looks like

**The shape that loses is real and was taken seriously**, because four of the five admin route modules declare their own port and the naive reading of that is "one module, one port". The measurement in finding 8 is what breaks the tie: **all four of those are WRITE backends.** `useCertificateRevokeBackend` revokes, `useAdminPayoutBackend` releases and enforces, `useAdminWalletBackend` corrects and sets a spend limit, `useAdminWriteBackend` freezes and closes. Writes are per-module because each is a different authority over a different table. **Reads are not**, and there is one read port for all of them.

**The second argument for a private port is stronger and it also fails, on a precedent one slice old.** `setAdminReadSource`'s `BLOCKED` reason ([`wiring.test.ts:139-147`](../../apps/api/test/wiring.test.ts)) is a SHAPE reason: "None of the six methods is a projection of one table ... A live adapter today would have to reach `sqlExecutor`". **That reason is false for the feed**, which is a keyed range read over one table. But it is **already false for two methods on the port**, and `admin-source/index.ts` records the resolution in terms: for `listFlags` and `readIdentityGraph` the reason "is now MEASURED FALSE ... The entry is `wiring.test.ts`'s, session 316 holds that file this wave, and this slice reports the narrowing rather than editing it." **The tree's settled answer to exactly this question is that the method stays on the port and the narrowing is reported.** This entry does the same rather than inventing a second answer for the third instance.

**What a private port would actually buy is nothing this surface needs.** Its safety property lives in the REQUEST and in the PROJECTION, which is where rulings 2 and 3 put it, and neither is a property of which port the rows arrive through.

### 4. Ruling 2 is the one that would have been easy to get wrong quietly

**The losing shape here is not an argument, it is a default.** Optional `identity_id` and `account_id` parameters with a handler that checks which are present is the obvious implementation, it reads fine, and it is `FM-M6-10` exactly: the surface is safe as long as every handler that ever touches it remembers which combination means "bulk". `M06` section 3.2a already says the difference "is one query parameter, which is why the constraint is stated here rather than inherited quietly".

**A required discriminant moves that from care to type.** The parse produces `{ kind: 'operational' } | { kind: 'identity', identity_id } | { kind: 'account', account_id }` or it produces errors, and the withholding takes the scope rather than the raw parameters. A later slice cannot write a handler that forgets, because there is no value it can hold that means "I did not check".

**This is `apps/admin/src/feed.ts`'s own ruling adopted rather than re-derived.** [`FeedScope:178`](../../apps/admin/src/feed.ts) is already "A CLOSED UNION AND NO DEFAULT" for the same reason. **The vocabulary is deliberately the same one**, because two spellings of one concept is how the two layers drift apart.

**And the sharpest evidence that the rule needed stating is one file over.** `/admin/flags` records at [`admin-reads.ts:1328`](../../apps/api/src/routes/admin-reads.ts): "FILTERABLE, not filtered ... an absent filter is the whole queue and is correct." **For `events` an absent filter is the bulk identity screen.** Two rules that read alike and mean opposite things is why the feed is its own module and not seven lines in that one.

### 6. The duplication this creates, reported rather than denied

**`apps/admin/src/feed.ts` applies the same withholding rule and this entry adds a second statement of it in `apps/api`.** That is [ADR-092](ADR-092.md) section 5's two-statements-of-one-fact hazard and `feed.ts`'s own header refuses a second PII check on exactly that ground.

**IT IS TAKEN DELIBERATELY AND THE REASON IS WHERE THE BYTES ARE.** `api-admin` serves `/api/v1/admin/events` on `ADMIN_ORIGIN`, so an operator session reaches the response **with no console in the path**. `AS-M6-05` is that reader by name: "a read-only admin session and no write capability can still take the identity graph and a pack per account." **A redaction that lives only in a renderer is a redaction a `curl` walks past.** And `RI-04` forbids `apps/api` declaring `@merit/admin`, so the copy cannot be shared as the tree stands.

**TWO SHAPES CLOSE IT AND NEITHER IS IN THIS FENCE.** Either the rule moves to a package both deployables may import, which is a new workspace package and a `VG-12`-shaped question; or `W6-h` re-points the console at the served body and drops its own copy, which makes `apps/admin`'s the defence-in-depth layer rather than a second authority. **The second is cheaper and is already `W6-h`'s shape.** Until one lands, **the two copies must be read together**, and the vocabulary was kept identical so that a diff between them is legible.

**WHAT THE FOUNDER IS BEING ASKED, IN THREE QUESTIONS.**

1. **IS THE FEED A SEVENTH METHOD OR A PORT OF ITS OWN?** Section 3's measurement says seventh method and the reads-versus-writes split is the evidence. **The judgement it cannot make is whether one read port for seven screens is still the right seam at seven**, rather than at six where it was designed. **What a founder read adds and this entry cannot.** Every fact above is a line in a file or the output of a command run in this session, and the two that were easiest to inherit, the route count and the wiring triple, were produced both times rather than recalled. **What no measurement here can supply is whether `operational` mode should exist at all.** This entry assumes it should, because an operator watching an incident needs a timeline and `M06` names the feed a launch surface. **But `operational` is a screen that reads the whole `events` table, and its safety rests entirely on a redaction rule this session wrote.** The alternative nobody has priced is a feed that is subject-named only, with no bulk mode, in which `INV-M6-10` is satisfied by there being no unfiltered page to redact rather than by redacting one correctly. **That is the sentence to read twice**, and section 6 is the second: this ruling puts two copies of one redaction rule in two deployables that cannot import each other, knowingly, and names the two slices that could close it.
