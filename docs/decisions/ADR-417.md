### 6. The control: leg 7, and what it refuses to write down

**AN ENTRY MAY NOW CARRY A `census`, AND THE CENSUS CONTAINS NO INTEGER.** It names the `names` the figure was about, the `scope` (`shipped` or `swept`), whether the reader strips comments, and the **PLACES** the entry accounts for, each with a sentence saying what it is. A place ending in `/` is a directory prefix; anything else is one file.

**LEG 7 DERIVES BOTH SIDES AND ASSERTS ONE IDENTITY:**

> the total the names reach in that scope **===** the sum of the parts the accounted places hold

It fails exactly when a reached line lands somewhere the entry does not account for, and the finding names that place, its line count, and the whole derived partition beside it, so the reader gets the numbers from the run rather than from a sentence somebody typed.

**THE ARITHMETIC IS NOW CHECKED AND NO ARITHMETIC IS WRITTEN DOWN**, which is ADR-034's second branch applied to a data field rather than to prose, and it is the shape the dispatch's own framing asked for.

**WHAT IT IS NOT.** It is not a second install detector. **Leg 2 is the leg that fails on good news**, and a place written as a directory prefix therefore blinds nothing: an install landing inside it is still the probe's to report, and conflating the two would give a weaker version of each.

**A WRITTEN PLACE THAT REACHES ZERO LINES IS DELIBERATELY NOT A FINDING, AND THE REASON IS A ROW RATHER THAN A PRINCIPLE.** A place empties when the thing in it is REMOVED, which is somebody else's repair landing correctly. **Row 418 is the row this would have caught out**: it holds `apps/api/src/events.ts`, which is an accounted place in `event-sink-caller`'s census, and deleting that compatibility module is one of the outcomes ADR-415 section 4.4 prices. Reddening on it would hand a neighbour a failure for doing the work it was sent to do.

**IT IS OPT-IN, AND THAT IS A LIMIT STATED RATHER THAN A DEFAULT.** Eight of the eleven entries in section 3 still carry an unbound figure and section 8 names every one. It is NOT made mandatory by parsing the prose, on this file's own header rule: a check that tries to decide which sentences it can read misses the ones it cannot, silently, which is the defect one layer down.

### 7. The hard constraint, and how this leg avoids it

**THE CONSTRAINT: `RI-35`'s FIRST LEG ANCHORS A VERBATIM SUBSTRING AND STORES NO LINE NUMBER, AND ADR-415 FOUND THE ESTATE ALREADY HOLDING A GREEN ON A FORMATTER'S LINE-WIDTH HEURISTIC.** A control over derived figures that reddened on a prettier reflow would be shipping the thing this row was sent to fix.

**THE ANSWER IS ONE SENTENCE: THE LEG HOLDS NO WRITTEN NUMBER, SO THERE IS NOTHING FOR A REFLOW TO DISAGREE WITH.**

Set out against the two shapes that DO fire on formatting:

| what it compares | fires on a reflow? |
|---|---|
| leg 1: a WRITTEN substring against file TEXT | **yes.** A rewording or a rewrap moves it, which is the property ADR-415 named |
| a written integer against a derived count | **yes, and worse.** Rewrapping one comment in an accounted file changes the derived count and reddens the leg at a diff that changed no meaning |
| **leg 7: a DERIVED total against a DERIVED sum** | **no.** Both sides come from the same walk at the same moment, so a rewrap that adds a line to an accounted file adds one to that part AND one to the total |

**THE IDENTITY IS INVARIANT UNDER EVERY CHANGE THAT KEEPS LINES WHERE THE REGISTER SAYS THEY ARE.** The only thing that breaks it is a name arriving in a NEW place, which is a fact about the tree rather than about its formatting.

**AND IT IS BOUND RATHER THAN ASSERTED, WHICH IS THE PART A LATER ROW SHOULD NOT LOSE.** A case builds a fixture, runs leg 7 green, then rewraps a comment in an accounted file, and asserts leg 7 is STILL green. The case then **derives both totals out of the leg's own finding text and asserts the second is larger than the first**, so it is evidence that the reflow really did move the number rather than a tautology over a reflow that changed nothing. Neither total is typed into the case, on this row's own subject.

**THE SAME PROPERTY WAS CONFIRMED ACCIDENTALLY AND IS WORTH RECORDING.** Prettier reformatted this row's own test file, rewrapping the census literals, and `RI-35` was green before and after.

**AND IT IS INDEPENDENT OF A REPAIR THIS ROW DOES NOT OWN.** ADR-415 records that `apps/api/src/events.ts` and `packages/ledger/src/events.ts` both claim to carry the anchored sentence and one of them is false, which row 418 is resolving. **BOTH ARE ACCOUNTED PLACES**, so the identity is silent whichever way that goes. Derived three ways over this base rather than reasoned about, and the totals differ every time while the identity holds every time:

| the tree | total reached | accounted | identity |
|---|---|---|---|
| as it stands | **28** over 10 files | 28 | **holds** |
| as if `apps/api/src/events.ts` went away | **25** over 9 files | 25 | **holds** |
| as if `packages/ledger/src/events.ts` went away | **17** over 9 files | 17 | **holds** |

**Both files were READ and NEITHER WAS WRITTEN**, and the three derivations above were computed by excluding a path from a walk rather than by touching the tree.

### 10. Approval

**Status `proposed`. The approval line below is UNSIGNED and merging is not signing.** [ADR-415](ADR-415.md), whose section 8 this row answers, is itself `proposed` and unsigned on this row's base, as is [ADR-410](ADR-410.md) behind it.

- **What a founder read adds and this entry cannot.**

  **THE FIRST DECISION IS WHETHER A REGISTER MAY CARRY A NUMBER AT ALL.** This row's answer inside `RI-35` is no, and it is a narrow answer: eleven figures, five of them false, one of them false from birth, one of them going false inside a single wave despite being anchored correctly by a careful row. **The general question is larger than this register.** `CI-06/derivable-counts` already rules that no prose under `docs/` states a count a runner can derive, and this row has just found the identical defect living in a `.mjs` comment where that gate does not look. A founder should decide whether the rule is about `docs/` or about counts.

  **THE SECOND IS WHETHER OPT-IN IS ENOUGH.** Leg 7 checks the three entries that carry a census and is silent about the eight that do not, and section 8 says why making it mandatory would need a parser over prose that this file's own header rules out. **That leaves a control whose coverage is a choice somebody has to keep making**, which is the shape of every register in this estate and is worth naming rather than discovering later.

  **THE THIRD IS THE ONE THIS ROW WOULD KEEP IF IT KEPT ONE.** ADR-415 did the work correctly. It measured a wrong figure, re-derived it from scratch, anchored the replacement to a commit, and shipped it with the instrument named. **Two commits later it was wrong.** Nothing about that row was careless, and the lesson is not about care: a written number is a claim about a moment, and a repository is not a moment. A founder pricing this programme should note that the corpus's standing remedy for a stale count, ADR-034's anchoring branch, was just measured failing inside one wave, and that the cost of the alternative was one leg, one data field on three entries, and twelve cases.
