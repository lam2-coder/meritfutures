## ADR-185: `EVENTS` section 11 carries TWELVE triggers, so the count moves and the table stands; and the repair is to DELETE the number rather than correct it, because a corrected number re-arms the identical trap  (2026-08-28, status: proposed)

**[M10:31](../plans/M10-integrations.md) and [M10:165](../plans/M10-integrations.md) both read *"the nine [EVENTS section 11](../architecture/EVENTS.md) triggers"*. Section 11 carries TWELVE rows, derived in this session at the source. So the count is wrong and the table is right.** That much is a measurement. **The ruling that costs something is the second one: the repair is NOT `nine` becoming `twelve`.** [ADR-034](ADR-034.md)'s remedy for a hand-maintained derivable count has exactly two branches, and this corpus has already written down that there is no third: *"generate the value, or delete it and point at the source ... in particular hand-repairing the column is not one, because that is what was being done, eleven times"* ([ALLOCATION:197](ALLOCATION.md)). **Typing `twelve` is that third branch. It would be true for as long as nobody adds a row to section 11, which is exactly how long `nine` was true: three days.**

**AND NOTHING IS REPAIRED BY THIS ENTRY, WHICH IS A CONCLUSION THIS SESSION MEASURED RATHER THAN PREFERRED.** The repair to `M10:31` is atomic with a change in [`apps/worker`](../../apps/worker/test/integrations-loops.test.ts) that this session's fence forbids, and the one shape that would have kept both halves inside the fence was executed and **produces a green suite whose own failure message is false**. Section 5 is that measurement. Every site is registered in section 4 with its repair named.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `185`, session **337**, dispatched as `claude/m10-trigger-count`. **The dispatch deliberately stated no number and the count was derived here**, at [EVENTS:396](../architecture/EVENTS.md), by reading the rows between that heading and the next one.

- **NON-MONEY PATH. No migration, no code, no gate change, and no `EVENTS` edit**, because the ruling does not move that side.

- **THIS ENTRY REPAIRS NO DOCUMENT.** It rules, and it registers four repairs it may not make and one it declines to make alone. **`docs/plans/M10-integrations.md` is inside this session's fence and is still not edited**, and section 5 is the whole of the reason.

### 2. THE RULING

**1. THE COUNT MOVES AND THE TABLE STANDS.** `EVENTS` section 11 is correct at twelve rows and every `"nine"` in the corpus that refers to it is false.

**2. THE REPAIR IS TO DELETE THE NUMBER AND NAME THE TABLE, NOT TO CORRECT IT.** `M10:31`'s cell becomes *"Every [EVENTS section 11] trigger, with suppression guards, and the minimum payload each needs"*; `M10:165` becomes *"every [EVENTS section 11] trigger, plus ..."*. **No cardinal.**

### 3. Why a corrected number is not on the menu, and it is the corpus's rule rather than this entry's preference

**[ADR-034:6](ADR-034.md) states the property: *"No document states a quantity a script can derive, unless the number sits in a generated span the script rewrites. Either generate it into the document or delete it and point at the script."*** [ALLOCATION:197](ALLOCATION.md) restates it as a closed set: *"[ADR-034]'s remedy has exactly two branches: generate the value, or delete it and point at the source. There is no third."*

**BRANCH ONE IS PRICED AND REFUSED, AND THE PRICE IS NOT THE ONE A READER WOULD GUESS.** A `<!--gen:-->` span would need a query in [`gates.mjs`](../../scripts/corpus/gates.mjs), which is a gate change and outside this fence. **But the deeper cost is a collision that the runner prints on every run.** `CI-06/derivable-counts`' live vocabulary, read from this branch's own run note, already binds the noun **`triggers`** to a query returning **21**, which is the count of SQL triggers in the migration set. **A second population under the same noun would make the gate's vocabulary ambiguous in the one word this repair turns on**, and resolving that is a gate design question and not a sentence.

**BRANCH TWO COSTS NOTHING AND IS THE ONE TAKEN.** `M10:31` and `M10:165` both already carry a markdown link to `EVENTS` section 11. **The pointer to the source is present in both sentences today; only the number needs to leave.** The repair deletes and does not add.

**AND A CORRECTED NUMBER IS NOT MERELY INFERIOR, IT IS THE SAME DEFECT WITH A DIFFERENT VALUE.** [ADR-034](ADR-034.md) states what the gate buys: *"It does not make counts trustworthy; it makes them absent or derived ... What it removes is the failure mode where the number and its source drift apart silently over months."* **`twelve` is a hand-maintained restatement of a fact stated one document over, which is [ADR-092](ADR-092.md) section 5's hazard exactly: *"Two hand-maintained statements of one map is precisely the drift class ... and it is sitting inside the suite that guards against it."*** Section 11 has grown once. The next row added to it falsifies `twelve` on the same afternoon, in the same silence, and the reader after that finds a `12` disagreeing with a `13` and repairs the cheap side.

**WHY NO GATE CAUGHT THIS, STATED FROM THE GATE'S OWN HEADER RATHER THAN INFERRED.** [`gates.mjs:8417`](../../scripts/corpus/gates.mjs) says it plainly: *"A COUNT THAT HAS ALREADY DRIFTED IS INVISIBLE HERE"*, and [`:8421`](../../scripts/corpus/gates.mjs) gives the reason -- the recogniser is value-anchored, so it names a number *"while it is still RIGHT, which is the only moment a span can be installed without anyone having to decide what the truth is"*. **`nine` drifted on 2026-08-16 and the gate was written on 2026-08-26. It was already invisible when the gate arrived.** The gate declines to adjudicate a drifted count on purpose, because that would ask a reader to decide what the truth is. **This entry is that adjudication. It is the thing the gate says it will not do, done by an ADR, which is where the corpus puts judgements.**

### 9. Approval

**Approval line: UNSIGNED.**

**WHAT THE FOUNDER IS ACTUALLY BEING ASKED, IN THREE QUESTIONS.**

1. **IS THE TABLE THE AUTHORITY?** The entry rules that it is, applying [ADR-180](ADR-180.md)'s test rather than its outcome. That entry ruled the prose right and the table wrong, on the ground that *"what separates them is not their unanimity but what each unanimity is made of"*. **Applied here it points the other way, and the reason is the composition.** The twelve are twelve distinct rows, each with its own message and guard, each carrying a payload row elsewhere in `EVENTS`, three of them added by a named commit as part of a ruled design, and every one independently bound to its `EVENTS` line by a running test. **The nine is one figure typed three times and re-read never.** A table of twelve authored facts outweighs one fact restated, and if that is wrong then section 11 is the side that is short and finding 1 is the entry that matters.
2. **IS DELETING THE NUMBER RIGHT WHEN THE READER LOSES SOMETHING?** A reader of `M10:31` today learns, wrongly, that there are nine. After the repair they learn there is a table and must open it. **That is a real cost and it is the cost [ADR-034](ADR-034.md) already chose to pay corpus-wide**: *"it makes them absent or derived"*. The entry takes absent because derived needs a gate change and a noun the gate's vocabulary has already spent.
3. **IS REGISTERING RATHER THAN REPAIRING THE RIGHT CALL WHEN THE PLAN IS IN THE FENCE?** This is the one to push back on. `M10` was handed to this session and comes back unedited. **The entry's position is that the alternative was to disable a control or redden the branch, and that a ruling with its repair named and blocked is worth more than either.** A founder who reads section 5 and concludes the tripwire should simply have been retired here is making a fence decision, not overturning a finding, and the four-file commit is specified well enough to be executed by the next session in one pass.

**What a founder read adds and this entry cannot.** Every count in this file was derived on this branch at the moment of writing: the twelve by reading between two headings, the 23 and the 11 and the 12 and the 1 by set operations over the catalogue, the 53 by counting files, and the four dated row counts by checking out four commits and counting each. **The history is the half worth a second read**, because it converts this from a typo into a mechanism: **the sentence was true, a different session added three rows to a table one document over, and the sentence became false without being touched.** No control in this corpus can see that, and `CI-06/derivable-counts` says in its own header that it will not try. **What no measurement here can supply is whether a corpus that argues in numbers should stop stating them in prose at all**, which is the general form of ruling 2 and is much larger than `M10`. This entry rules it for two sentences and names a third; the founder may want it ruled for the corpus.
