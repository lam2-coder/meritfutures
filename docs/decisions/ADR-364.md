### 2. THE RULING

**RULED: `setInternalOpsSource` stays uncalled, and it is DECLINED rather than BLOCKED**, on ADR-360's register. No door refuses two of its four members. What stands in the way is a purchase, a manifest authority and a door, one per member, and none of them is a decision this repository can take on its own.

**RULED: [ADR-360](ADR-360.md)'s "no half install exists to get wrong" DOES NOT CARRY, and the reason is the interface rather than a judgement.** That ruling was correct about a ONE-member port. This port declares four, and an object holding two throwing members beside a real read and a stub is well-typed, installable through the single setter, and answers **500 / 500 / 200 / 202** where an unwired deployment answers 500 on all four. **What remains true of this port is the narrower claim: its `null` DEFAULT cannot present a live arm, because `null` has no arms. The default is not the install.**

**RULED: [ADR-356](ADR-356.md)'s harm ruling DOES carry, and it lands on ONE of the four rows.** Three of the four are reads, and a read whose member throws answers the same 500 an unwired one answers, so a half install of those is invisible rather than harmful. `POST /internal/batch/run` is the exception: it is the row that COMMANDS, and a half install turns it from a refusal into a **202 Accepted** naming a job id.

**RULED: the module's own guard ALREADY BOUNDS THAT HARM, and the residue is unfalsifiable from inside this process.** `renderBatchRun` (`:759`) refuses `started` with a null job id in its own words, *"A run that started with nothing enqueued is a trigger that reports success and does no work"*. So an HONEST stub is a 500. What passes is a stub that FABRICATES an id, and no assertion in this deployable can catch that, because the id's truth lives in a queue `apps/api` is not allowed to import.

**RULED: the mute wire is CORRECT and STAYS, and it is ruled here on the contract rather than on precedent.** `problem` (`apps/api/src/server.ts:135`) carries a docblock stating that `detail` is deliberately never set, quoting API_CONTRACT section 2's *"never leaks internals or other users' data"*. **The remedy for section 4 is therefore not a detail field**, and the options are section 8's.

**RULED: no parameter is invented here.** No digest, no timeout, no page size, no retry count and no boot posture. Section 8 records four open questions as the founder's, with options.

### 4. What a request meets, walked from the handlers rather than read off a docblock

**THERE ARE TWO ANSWERS AND THE FIRST ONE IS NOT ABOUT THIS PORT AT ALL.**

On the **public** surface the four rows are never registered. `compose` classifies `/internal` by prefix and withholds them, and the origin answers `404 not_found`. That is ADR-083 section 4's structural 404 and `internal.test.ts` already holds it. **The port's refusal is unreachable there.**

On the **operator** surface, with nothing installed:

| row | what a request meets |
|---|---|
| `GET /internal/health/deep` | `500 internal_error` |
| `GET /internal/jobs` | `500 internal_error` |
| `GET /internal/recon/status` | `500 internal_error` |
| `POST /internal/batch/run`, well formed | `500 internal_error` |
| `POST /internal/batch/run`, malformed | **`400 validation_failed`, with an `errors[]` naming every field** |

**THE STATUSES WERE ALREADY HELD AND ARE NOT RE-ASSERTED.** `internal.test.ts` holds the 500 on every row and the 400-before-the-port. **What nothing held is the document**, and the document is the finding:

```
{"type":"https://meritfutures.com/problems/internal_error","title":"Internal error",
 "status":500,"code":"internal_error","instance":"req-1"}
```

**FIVE KEYS. The sentence `wired` throws is in none of them.** `STATUS_CODE` (`server.ts:98`) is closed over the codes a request can reach without a handler and 500 is not one of them, so every throw in this deployable lands on the same branch and `problem` (`:135`) builds the same five fields. Three consequences, each asserted:

1. **The four rows answer byte-identical documents** once the request id is removed. A reader holding the response cannot tell which row they called.
2. **A half installed member that throws answers the same document as no port at all.** The wire cannot distinguish an unfinished deployment from a broken dependency, which is a problem for `GET /internal/health/deep` specifically, since distinguishing broken dependencies is the entire purpose of that row.
3. **The operator who typed the request WRONG is told more than the one who typed it right.** The malformed trigger comes back naming `trading_day`, `run_id` and `reason`; the well formed one comes back with five keys.

**THE ONLY CHANNEL THAT CARRIES THE SENTENCE IS THE PROCESS LOG, AND NO SUITE IN THIS DEPLOYABLE CAN OBSERVE IT.** The error handler logs `{ err, status }` before answering. **`ServerOptions` declares `logger` as a BOOLEAN (`server.ts:154`) and `buildServer` (`:169`) hands that boolean straight to Fastify, so there is no sink an `inject` case can read back.** This is ADR-360's structural measurement, re-derived here rather than carried, and it is why section 4's cases measure the wire.

**THE 500 IS STILL THE RIGHT NUMBER AND THIS ROW DOES NOT REOPEN IT.** This module's header argues 500 over 503 because an operator told *"service unavailable"* retries, and every retry of the batch row is another manual trigger. That argument holds. **What this row measures is that the argument is a comment: the caller receives the number and not the reasoning, so the distinction between 500 and 503 is doing all of the work by itself.**

### 5. The half install, measured rather than assumed by analogy

**IT IS CONSTRUCTIBLE, AND THE TEST INSTALLS IT WITH NO CAST**, typed `InternalOpsSource` so that `tsc` checks the object against the port. The slice modelled is the plausible one: the recon read and the batch trigger landed, the two probes left for later.

| row | unwired | half installed |
|---|---|---|

| `GET /internal/jobs` | 500 | **500**, member throws |
| `GET /internal/recon/status` | 500 | **200**, real answer |

**[ADR-356](ADR-356.md) MEASURED A HALF INSTALL ANSWERING 200/500 WHERE UNWIRED ANSWERS 503/503 AND RULED THE HALF INSTALL WORSE. THE SAME SHAPE IS HERE AND IT IS SHARPER**, because the arm that comes alive is not a read. 202 is this contract's *"accepted, the batch runs on the worker"*, and an operator working an incident reads it as the nightly batch retriggered.

**THE PORT'S OWN DOCBLOCK ANTICIPATES HALF OF THIS AND NOT THE OTHER HALF, AND THE DIFFERENCE IS WORTH STATING PRECISELY RATHER THAN AS A DEFECT.** It says four setters *"would buy the ability to half-wire the operator console, which is not an ability anybody has asked for"*, and that *"this file answers that the same way whichever method is MISSING"*. **The second clause is TRUE and it is measured**: a member that throws is indistinguishable on the wire from no port at all. **What neither clause reaches is a member that returns a PLAUSIBLE value**, and the single setter does not refuse one: it makes a half wiring one object literal instead of two calls. **That is a gap in what the sentence covers rather than an error in what it says**, so nothing in `src/` is edited and the correction is executed beside the claim (`RI-14`).

**AND THE HARM IS ALREADY BOUNDED, BY THIS FILE, IN THIS FILE'S OWN WORDS.** `renderBatchRun` refuses a `started` outcome carrying a null job id, calling it *"a trigger that reports success and does no work, which is the failure RB-01 exists for arriving as a 202"*. Measured through the router: that stub is a **500**. **So the residue is exactly one shape, a stub that fabricates an id, and it is not detectable from inside this process at all.** A guard would have to ask the queue whether the job exists, and `apps/api` declares no queue.

### 7. The audience is an operator, and it changes the answer twice

**IT MAKES THE MUTE WIRE CHEAPER THAN IT WOULD BE ON A TRADER SURFACE.** [ADR-359](ADR-359.md) and [ADR-360](ADR-360.md) both found a refusal whose only honest channel was the log, and both were about surfaces a TRADER reaches, where nobody holding the response can read a log. **Here the only reader is an operator on the admin origin**, and an operator has the process log. **So a log-only channel is legitimate on this surface in a way it is not on the other two**, and this row does not ask for it to change.

**AND IT MAKES ONE THING MORE EXPENSIVE RATHER THAN LESS, WHICH IS THE BOOT.** The composition report is what `index.ts` prints at startup, and on the operator surface it names **four registered `/internal/*` routes and withholds none of them**. Every one of the four answers 500. **So a deployment that cannot serve a single operator row starts cleanly, reports four routes registered, and says nothing anywhere about the port that makes all four fail.** Nothing in the report, the startup line or any other channel names `setInternalOpsSource`, and the first person to learn is whoever makes a request during an incident.

**THAT IS THE ONE REFUSAL PATH THIS ROW FINDS SILENT TO THE ONLY PERSON WHO COULD ACT ON IT**, and it is silent at exactly the moment acting would be cheap. It is section 8's third question rather than a change made here, because a boot posture is an operational ruling and no code in this row assumes an answer.

### 8. Open questions, recorded as the founder's with options and no values

**NOTHING BELOW IS DECIDED HERE AND NO NUMBER IS CHOSEN.**

**OQ-1. Should a deployment whose operator port is unwired say so at boot?** [ADR-360](ADR-360.md)'s OQ-3 asked this of the admin surface and this row measures the operator surface's version: four routes registered, four answering 500, nothing said. Options: (a) leave it, and the wire is the only channel; (b) a startup line naming uncomposed ports beside the registered and withheld counts, which is additive and blocks nothing; (c) fail closed on the operator surface, which is narrower than ADR-360's version because the public surface withholds these rows anyway. **(b) is the cheapest and it is still a ruling, because a startup line that names ports is a list somebody maintains unless it is derived.**

**OQ-2. Should the operator surface's 500 carry more than five keys?** Section 4 measures that it carries the contract's five and section 2 rules the muteness correct on `problem`'s own docblock and API_CONTRACT section 2. **But that sentence was written about a TRADER surface**, and an operator origin behind an IP allowlist and hardware-key SSO is a different reader. Options: (a) leave it, and the operator correlates by `instance` against the process log; (b) rule that the operator surface may carry `detail`, which is an amendment to a frozen contract and needs its own ADR; (c) leave the document alone and make the LOG line name the port, which today says only *"unmapped error status, answering internal_error"* and carries the port name inside `err.message`. **(c) is the smallest and it is still not this row's, because `server.ts` is one deployable's transport and this port is one of fourteen behind it.**

**OQ-3. May a wiring slice install this port partially?** Section 5 measures that it can and that the batch row is where it costs. Options: (a) rule that it may not, and hold it with a case that installs each member alone and asserts a refusal, which requires the port to declare what "installed" means; (b) rule that it may, and require the batch row to be the LAST member wired; (c) leave it to the slice, which is the position today and is what section 5 measured. **This is a ruling about a slice that does not exist yet, and it is cheaper to take before that slice is written than after.**

**OQ-4. What does `runBatch` owe when it cannot prove a job exists?** The guard in `renderBatchRun` catches the honest stub and nothing catches a fabricated id. Options: (a) accept it, on the ground that a port implementation that lies is out of scope for the module that calls it; (b) require the wiring slice's implementation to read the job back inside the same transaction before returning, which is a contract on an unwritten component; (c) rule it at the point `@merit/queue` is admitted to this deployable, since the capability and the guard arrive together. **No option is taken and none is cheap to take silently.**
