## ADR-357: the wiring triple is honest arithmetic and `blocked` is the wrong name for what it counts, one of the fourteen holds a WORKING live default while thirteen refuse, and the count must not move because lowering it disarms the gate standing beside it (2026-09-06, status: proposed)

**[`wiring.test.ts`](../../apps/api/test/wiring.test.ts) asserts `{declared: 25, wired: 11, blocked: 14}`, and its own `BLOCKED` entry for `useTurnstileVerifier` opens with the word *"NOTHING. THIS PORT IS ALREADY LIVE AND THE ENTRY EXISTS TO SAY SO"*.** The row was dispatched on the suspicion that a live port is being counted as blocked. **It is, and the file has said so in prose since ADR-226.** What was missing is that nothing asserted it.

**THE RULING IS THAT THE TRIPLE IS HONEST AND THE VOCABULARY IS NOT.** `blocked` counts the ports [`start.ts`](../../apps/api/src/start.ts) does not call. It has never counted obstruction, and on this tree the two readings differ by exactly one. **The number is right, it must not move, and the repair is a second measurement plus the words.**

- **Origin:** [ALLOCATION](ALLOCATION.md) row `357`, branch `claude/a-live-port-counted-as-blocked`, session **552**.
- **THE DELIVERABLE IS A RULING, A GATE AND FOUR REPAIRS.** No port is wired, no port is unblocked, and no number in the triple moves. What lands is the ruling, the assertion that binds it, two drifted citations and two stale prose counts repaired beside their originals under `RI-14`.
- **MONEY PATH, `E2` READ OWED.** `useTurnstileVerifier` is the anti-bot control on `POST /auth/otp`, and a ruling about whether it is live is a ruling about whether the sign-in path is defended. Ships `proposed` with an **UNSIGNED** approval line. **Merging is not signing.**
- **NO MIGRATION WAS TAKEN OR EDITED.** `git diff --stat origin/main -- packages/db/migrations scripts/db` is **EMPTY**.
- **A DISPATCH PROMPT IS NOT A SOURCE.** The dispatch named five claims. **All five reproduce, to the line number.** What did not reproduce is a premise the dispatch did not state and this row found underneath them, which is section 8.

### 2. THE RULING

**RULED: THE TRIPLE IS HONEST AS ARITHMETIC AND MISLEADING AS VOCABULARY, AND THE FIX IS THE VOCABULARY AND A SECOND MEASUREMENT RATHER THAN THE ARITHMETIC.**

1. **`blocked: 14` is correct and does not move.** It counts what it has always counted.
2. **Of those fourteen, ONE holds a working live default and THIRTEEN refuse.** The one is `useTurnstileVerifier`.
3. **The dispatch's premise that "at least one of those 14 is not blocked" is TRUE**, and the entry's own wording is not what misleads. The entry is the most honest text in the file: it says `NOTHING`. **What misleads is the key name.**
4. **The three states the dispatch asked for are really two plus a shape.** A port either refuses a request or serves one. Thirteen refuse, in three syntactic shapes that are not three states. Section 3 keeps the shapes because they are what a reader must not mistake for each other.

### 3. The three states asked for, measured port by port

Derived by reading each declaring module for the module-scope binding the setter assigns to, not from any entry's prose.

| Port | Module-scope default | Serves or refuses |
|---|---|---|
| `setAdminReadSource` | `null` | refuses |
| `setAdminSessionSource` | `null` | refuses |
| `setInternalOpsSource` | `null` | refuses |
| `useAdminPayoutBackend` | `UNWIRED_ADMIN_PAYOUT_BACKEND` | refuses |
| `useAdminWalletBackend` | `UNWIRED_ADMIN_WALLET_BACKEND` | refuses |
| `useAdminWriteBackend` | `UNWIRED_ADMIN_WRITE_BACKEND` | refuses |
| `useCertificateRevokeBackend` | `UNWIRED_ADMIN_CERTIFICATE_BACKEND` | refuses |
| `useCheckoutBackend` | `UNWIRED_CHECKOUT_BACKEND` | refuses |
| `usePayoutBackend` | `UNWIRED_PAYOUT_BACKEND` | refuses |
| `useWithdrawalBackend` | `UNWIRED_WITHDRAWAL_BACKEND` | refuses |
| `useAffiliateDeps` | `productionAffiliateDeps` | refuses |
| `useKycDeps` | `productionKycDeps` | refuses |
| `useCheckoutAdapters` | `PRODUCTION_CHECKOUT_ADAPTERS` | refuses |
| **`useTurnstileVerifier`** | **`cloudflareTurnstileVerifier()`** | **SERVES** |

**THREE SHAPES OF REFUSAL AND WHY THE DISTINCTION IS KEPT.** Three hold `null`; seven hold an explicit `UNWIRED_*` stand-in; three hold a `production*` value that resolves nothing. **The third shape is the dangerous one**, because its NAME says production and its BEHAVIOUR says 503, which is precisely the confusion this row was dispatched into.

**AND THE THIRD SHAPE IS NOT HOMOGENEOUS EITHER, WHICH IS WHY THE CLASSIFICATION IS NOT A REGEX.** `productionAffiliateDeps` and `productionKycDeps` refuse by holding an `UNWIRED_*` member. **`PRODUCTION_CHECKOUT_ADAPTERS` ([`checkout.ts:1203`](../../apps/api/src/routes/checkout.ts)) names no `UNWIRED_` value at all** and refuses by being EMPTY: `adapterFor: () => undefined`, both URLs `''`, `enrichment: null`. A probe asking *"does the initializer name an `UNWIRED_` value"* classifies thirteen correctly and this one WRONGLY, and would have reported `useCheckoutAdapters` live. **That probe was written, run, and refused on its own result**, which is section 7's reason for splitting the measured half from the ruled half.

**WHY `useTurnstileVerifier` IS THE ONE.** [`cloudflareTurnstileVerifier`](../../apps/api/src/turnstile.ts) at `turnstile.ts:211` is a complete vendor adapter: it reads `MERIT_TURNSTILE_SECRET` from `process.env` PER CALL, posts to `TURNSTILE_SITEVERIFY_URL` with a 3 second timeout, and returns `passed` or `failed` on the answer. **It waits on no code, no adapter and no ruling. It waits on an environment variable.** The other thirteen wait on a thing somebody must build or decide.

**AND AN ABSENT SECRET IS NOT AN UNWIRED STATE.** With no secret the default answers `unconfigured`, which `routes/auth.ts` serves as 503 ([ADR-226](ADR-226.md)). **So the port is live or it refuses, and there is no third state for `start.ts` to install.** This is the difference from `useKycDeps` that the dispatch asked to be told apart: `productionKycDeps` carries `provider: null` and `returnUrl: null` and CANNOT serve under any environment, because the code that would serve does not exist. **A live default that refuses unconditionally and a live default that refuses only until configured are not the same fact.**

### 4. Why `blocked: 14` MUST NOT MOVE, which is mechanical rather than editorial

The tempting repair is `blocked: 13` with `useTurnstileVerifier` removed from the list. **It was tried and it is a gate weakening, measured rather than argued.**

Deleting the entry and running the file reddens **TWO** tests, not one:

```
AssertionError: expected [ 'useTurnstileVerifier' ] to strictly equal []
  wiring.test.ts:1661   expect(unaccounted).toStrictEqual([]);
AssertionError: expected { Object (declared, wired, ...) } to strictly equal { ... }
```

**The first is the regression this whole file exists for.** `unaccounted` requires every declared port `start.ts` does not call to carry a reason. A port that is live-by-default is still a port `start.ts` does not call, so removing its entry re-opens exactly the hole the file was written to close: **a port with no wiring and no recorded reason.**

**SO THE NUMBER CANNOT FALL WITHOUT DISARMING THE GATE BESIDE IT, AND A NUMBER LIKE THAT IS NOT ONE A SESSION MAY LOWER.** The dispatch's instruction not to move a number to make a point is met here by the tree refusing to let the number move at all.

### 5. What `declared: 25` and `wired: 11` actually count

- **`declared: 25`** counts `export function use*(` / `set*(` in `apps/api/src/routes` and `apps/api/src`. It is a count of SETTERS, and it is exact.
- **`wired: 11`** counts top-level calls to those setters in `start.ts`. **It counts INSTALLATION BY THE WIRING SLICE, and it does not count LIVENESS.**

**THE DISPATCH'S THIRD QUESTION IS THE SHARPEST AND THE ANSWER IS YES: a port with a working module-scope default is serving traffic without appearing in `wired`.** On this tree **eleven ports are installed by `start.ts` and twelve are live**, and the twelfth is `useTurnstileVerifier`.

**`wired` IS NEVERTHELESS THE RIGHT MEASUREMENT AND IS NOT CHANGED HERE**, for the reason the file already gives: raising it by calling a setter that installs what is already installed would report progress and change nothing a request sees. **The word is accurate for the thing it names.** What was missing was any measurement of the other thing, and section 7 adds it rather than redefining this one.

### 6. The entry's wording is NOT the defect, which is the finding that cuts against this row's own convenience

The dispatch offered this row a ruling it could have taken cheaply: that the entry's wording misleads and should be repaired. **It does not and it should not.** `useTurnstileVerifier`'s entry is the only one of the fourteen that states its own status in the first word, and the header block above `BLOCKED` already separates it from the other three no-ops in exactly the terms this ruling uses: *"Its module-scope default is the REAL Cloudflare verifier rather than a fail-closed stand-in, so the port is live with nothing installed."*

**THE FILE HAS BEEN RIGHT IN PROSE AND SILENT IN ASSERTION FOR FOUR WAVES.** That is the defect, and it is the same one [ADR-034](ADR-034.md) exists to end: a fact that only a paragraph carries goes stale without anything going red. Section 8 is the proof that it did.

### 7. What is bound mechanically, so this ruling fails on good news

Two new constants and three assertions in `wiring.test.ts`.

- **`DEFAULTS` (`:1615`)** records the initializer each of the fourteen module-scope variables carries, as text. The assertion reads all fourteen back off the declaring modules and compares. **A default that changes goes RED**, which is the check whose absence let this sit.
- **`LIVE_DEFAULT` (`:1647`)** records the RULING: the blocked ports whose default serves a request. One member.
- **The third assertion reports `{blocked: 14, refusing: 13, live: 1}`**, so the gap between the two readings is a number rather than a paragraph.

**THE INPUT IS MEASURED AND THE JUDGEMENT IS WRITTEN DOWN, AND THE SPLIT IS DELIBERATE.** Section 3 records why the regex that would have merged them is wrong. **A probe that reads the WORD is the failure `RI-35`'s register carries its own comments about**, and `PRODUCTION_CHECKOUT_ADAPTERS` is a live instance of it in this very file.

**THIS FAILS ON GOOD NEWS, WHICH IS [ADR-330](ADR-330.md)'s test.** The day a wiring slice installs one of the fourteen, `DEFAULTS` and `BLOCKED` disagree and the suite goes RED until both move. **Row `356` is concurrently working on `setAdminReadSource`, which is one of the fourteen**, so that conflict is expected and is the mechanism working: it makes the removal visible rather than silent. **No invariant number was minted**, on ADR-330's precedent: 35 of 35 before and after.

**AND THE DAY THE SECRET SHAPE CHANGES, THIS ROW'S OWN CLAIM GOES RED.** Seed 2 of section 11 replaced `cloudflareTurnstileVerifier()` with a refusing stand-in and the suite reddened at the sentence saying the port is live. **The ruling is falsifiable by the tree.**

### 9. Open questions, which are the founder's and are recorded as options rather than answered

1. **Should the reported key be RENAMED from `blocked`?** This entry does not rename it and states why: `{declared, wired, blocked}` is cited across the tree and `RI-15`/`RI-16` bind citations to line numbers, so a rename moves every citation for a gain that section 7 already delivers as a number. **Options: (a) leave `blocked` and keep `{blocked, refusing, live}` beside it, which is what shipped; (b) rename to `unwired`, which is what it counts, and repoint every citation; (c) report a four-member triple.** This entry took (a) as the smallest change that makes the reading unambiguous, and it is the founder's to overrule.
2. **Is `MERIT_TURNSTILE_SECRET` set in any deployment?** This session cannot see a deployment. **The ruling that the port is live is a ruling about the CODE, and whether it is live in fact is a deployment question this repository cannot answer.** If the secret is unset everywhere, the anti-bot control on `POST /auth/otp` is answering 503 in production and that is an operational finding rather than a wiring one. **It is not asserted here because nothing in the tree can assert it.**
3. **Does a port that is live without appearing in `wired` belong in `BLOCKED` at all?** Section 4 says it must, on the gate. **But that is an argument from the gate's current shape rather than from first principles**, and a founder may prefer a third list (`LIVE_WITHOUT_WIRING`) that `unaccounted` also honours. That is a larger change to the file's structure and is not taken here.

### 10. Where this entry is most likely wrong

- **The `RI-15` question from section 8 row 2 was MEASURED rather than left as an either/or, and the answer is a named hole in a live gate.** The bad citation was restored on this tree and `RI-15` was re-run: it **PASSED at 35 of 35**, and `CITATIONS_OWNED_ELSEWHERE` holds no entry for it, so the citation is unwaived and simply unbound. **The cause is `IDENTIFIER_GLUE` (`repo-invariants.mjs:2553`), which admits at most ONE linking word from the closed set `at|in|is|see`.** The text between the name and the pointer is *"at module scope ("*, which is three words, so no name binds and the citation falls to `RI-15`'s stated hole (1): resolution and range only. **THREE citations in `wiring.test.ts` are written in exactly that shape**, and *"at module scope"* is the phrase this file uses to make this precise claim. All three are correct as of this row; none of them is guarded. **Widening `IDENTIFIER_GLUE` is `RI-15`'s own row and is NOT taken here**, because a change to that grammar re-reads 225 citations across the tree and would be this row taking another row's object as a means.
- **`LIVE_DEFAULT` is a ruling and a ruling can be wrong.** If a fourteenth-hour reading finds another of the thirteen serves under some environment, the assertion goes red and this entry is the thing to correct. That is the intended failure.
- **Section 5's "twelve are live" counts the CODE.** A deployment missing the secret has eleven live and one refusing, and this entry does not know which.
