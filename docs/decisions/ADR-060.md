## ADR-060: `engine_eligible` contains the six funded gates and not R-38, and the reason it was unrulable is that no document ever enumerated them  (2026-08-18, status: proposed)

**A fixture may not pin `engine_eligible: true` today, and the recorded reason is that M01 declares R-38 a funded gate while declaring its input on `ExternalGates`, so "the engine has chosen a reading; M01 has not" ([fixtures README:228](../../packages/rules-engine/fixtures/README.md)). That reason was re-derived from source for this ruling and it does not survive intact. M01 states the exclusion FIVE times. What M01 has never done, anywhere, is enumerate the engine gates as a closed list, and the only closed list in the repository lives in [`types.ts:954`](../../packages/rules-engine/src/types.ts). The unpinnable direction is a missing enumeration, not a contradiction, and the two are unblocked by different rulings.**

- **Context:** `GS-080`'s registry row asserts "that `engineEligible` is unaffected" by a gate configured to zero, and `GS-055` declined to pin the flag at all. [`GS-064`](../../packages/rules-engine/fixtures/GS-064-breach-and-payout-eligibility-on-the-same-day.expected.json) is the one fixture in the directory that pins it, and it pins `false`. **The asymmetry is deliberate and the fixtures README states the reason in one sentence worth preserving verbatim: "a contested conjunction still has one uncontested value" ([README:152](../../packages/rules-engine/fixtures/README.md)).** This ruling must leave that sentence true.

  **Nothing here is a proposal to change behaviour.** The engine is not edited by this ADR and would not be edited by accepting it. What changes is which document a fixture author can derive an expectation FROM, which is the whole of `TR-01`.

### 1. What the engine does, quoted rather than described

`evaluateGates` returns a six-member record and conjoins exactly those six:

> ```ts
> const gates: EngineGateResults = {
>   tradedDays, winDays, buffer, consistency, cadenceGap: cadence.gate, minimumAmount,
> };
> return { kind: 'evaluated', gates, engineEligible: allGatesPass(gates) };
> ```
>
> [`gates.ts:258`](../../packages/rules-engine/src/payout/gates.ts) and [`gates.ts:267`](../../packages/rules-engine/src/payout/gates.ts)

> ```ts
> function allGatesPass(gates: EngineGateResults): boolean {
>   return gates.tradedDays.pass && gates.winDays.pass && gates.buffer.pass &&
>     gates.consistency.pass && gates.cadenceGap.pass && gates.minimumAmount.pass;
> }
> ```
>
> [`gates.ts:280`](../../packages/rules-engine/src/payout/gates.ts)

**There is no R-38 term.** R-38 is computed elsewhere and conjoined into the other operand:

> ```ts
> const noPayoutInFlight = { pass: !external.hasPayoutInFlight };
> ...
> const contextEligible =
>   accountActive.pass && kycVerified.pass && notFrozen.pass && reconClear.pass &&
>   noPayoutInFlight.pass;
> ...
> const eligible = state.engineEligible && contextEligible;
> ```
>
> [`evaluate.ts:136`](../../packages/rules-engine/src/payout/evaluate.ts), [`:146`](../../packages/rules-engine/src/payout/evaluate.ts), [`:160`](../../packages/rules-engine/src/payout/evaluate.ts)

**And the engine states its reading as a reading, in a header that names the rule numbers**: "The context gates (**R-38**, R-40), which are NEVER part of the replayed state" ([`types.ts:872`](../../packages/rules-engine/src/types.ts)), citing `INV-23` and `SD-06`. `hasPayoutInFlight` is declared at [`types.ts:905`](../../packages/rules-engine/src/types.ts) on the `ExternalGates` interface at [`types.ts:898`](../../packages/rules-engine/src/types.ts), whose own doc comment reads "Context, never replayed (INV-23). Every field is resolved by the CALLER."

**So the engine did not choose silently. It chose, cited two M01 clauses, and wrote the citation down.** That is materially different from the self-grading trap `TR-01` describes, and it is the first thing this ruling had to establish, because "the engine chose" is not evidence and "the engine chose against a citation" is a claim that can be checked.

### 2. The two readings, and what each costs

#### Reading A, EXCLUSION: R-38 is a context gate. `engineEligible` is the six funded gates.

Stated in M01 five times, none of them ambiguous:

| Site | Text |
|---|---|
| [M01:134](../plans/M01-rules-engine.md) | `INV-23`: "Context gates (frozen, recon, KYC, **in flight**) never enter the replayed state or its hash" |
| [M01:175](../plans/M01-rules-engine.md) | the interface sketch: `interface ExternalGates { // context, never replayed (INV-23)`, with `hasPayoutInFlight` inside it at [M01:178](../plans/M01-rules-engine.md) |
| [M01:214](../plans/M01-rules-engine.md) | the `RuleState` sketch: `engineEligible: boolean; // engine gates only (SD-06)` |
| [M01:253](../plans/M01-rules-engine.md) | `SD-06`: "Freeze, recon, KYC, and **in-flight** are not replayable: they were true on the day and may not be true now" |
| [M01:478](../plans/M01-rules-engine.md) | the sentence directly under the Group F heading: "`engineEligible` is the conjunction of the engine gates; the context gates are combined at read time (INV-23)" |

#### Reading B, INCLUSION: R-38 is a funded gate and `engineEligible` has seven terms.

Supported by two placement artifacts and one adversarial-section phrase:

| Site | Text |
|---|---|
| [M01:476](../plans/M01-rules-engine.md) to [:491](../plans/M01-rules-engine.md) | R-38 sits inside the `#### Group F: funded gates` span. Group G opens at [M01:492](../plans/M01-rules-engine.md) |
| [M01:341](../plans/M01-rules-engine.md) | `DO-9`: "Evaluate every engine gate, compute `engineEligible` ... \| **R-33 to R-41**" |
| [M01:802](../plans/M01-rules-engine.md) | `AS-01`'s counter: "G-NO-IN-FLIGHT (R-38) is **part of eligibility**" |

**Reading B is defeated by its own two placement citations, and the defeat is arithmetic rather than interpretive. `R-40` is in the same group and in the same range.** R-40 is [M01:489](../plans/M01-rules-engine.md), titled **"Context gates"**, and it is the row that enumerates account status, KYC, freeze and recon. R-41, the conjunction itself, is [M01:490](../plans/M01-rules-engine.md). **A group that contains the context-gate rule cannot be the list of engine gates, and a range "R-33 to R-41" that contains R-40 and R-41 cannot be the engine-gate enumeration either.** Under Reading B, `engineEligible` would have to contain the context gates it is defined in contradistinction to, and would contain itself.

**And Reading B has a consequence no document contemplates, which is what makes it not merely weaker but unavailable.** `engine_eligible` is a **stored column** ([`rule_states.md:24`](../architecture/data-model/rule_states.md), "the engine's verdict from **engine gates only**, replayable by construction") and it is inside the state hash ([M01:1246](../plans/M01-rules-engine.md) excludes "`engine_version` and every context gate" and nothing else). Under Reading B a stored, hashed column would depend on a caller-supplied boolean that is true today and false tomorrow. **A freeze applied last March would flip every stored row's verdict, and the replay self-audit would report a divergence on every account every night** — which is the exact sentence `SD-06` gives as its own reason ([M01:253](../plans/M01-rules-engine.md)) and the exact failure `FM-17` names. Reading B does not merely disagree with `INV-23`; it makes `INV-04`'s nightly comparison useless.

### 4. Recommendation, and the argument against it

**RECOMMENDED: Reading A. `engineEligible` is the conjunction of `R-33`, `R-34`, `R-35`, `R-36`, `R-37` and `R-39`. R-38 is a context gate, binds through `contextEligible`, and is part of `eligible` and not of `engineEligible`.**

**The six are derived from M01 and not transcribed from the engine, and the distinction is the whole safety of this ruling.** Group F is [M01:476](../plans/M01-rules-engine.md) to [:491](../plans/M01-rules-engine.md), which is `R-33` through `R-41`. Remove the two rows that are definitionally not engine gates — `R-38`, whose input `ExternalGates` declares, and `R-40`, which IS the context-gate rule — and remove `R-41`, which is the conjunction rather than a term in it. **Six rows remain.** They happen to be the six in [`types.ts:954`](../../packages/rules-engine/src/types.ts). **Agreement reached independently is what makes a fixture safe; agreement reached by transcription is what `TR-01` forbids**, and the derivation above touches no source file.

#### The argument against, in four parts, none of them rhetorical

**First, `AS-01` genuinely says "part of eligibility" and the ruling puts a distinction into it that its author did not write.** [M01:802](../plans/M01-rules-engine.md) is the counter to a live attack, and reading it as "part of `eligible`" rather than "part of `engineEligible`" is a reading. It is the right one — the sentence continues "backed by the SD-09 partial unique index so the engine is not the only line of defence", which is about enforcement location and not about conjunction membership — but a founder should see that this ruling narrows an adversarial-section sentence rather than merely citing it.

**Second, the ruling requires editing a SECOND frozen document to make the first coherent.** `M05:88`'s "the engine gate" becomes wrong. A ruling whose fold list crosses a plan boundary is heavier than one that does not, and the honest way to state that cost is that `M05` was frozen with a phrase that was already inconsistent with `SD-06`, which `M05` itself cites in the same cell.

**Third, and this is the sharpest one: THE RULING DOES NOT BY ITSELF MAKE `engine_eligible: true` PINNABLE.** `INV-15` reads "`engine_eligible == AND(every engine gate)`" ([M01:126](../plans/M01-rules-engine.md)) and **no document enumerates the engine gates**. Ruling `R-38` out narrows the set; it does not close it. **What actually blocked the fixture was the missing enumeration, and the R-38 question is one instance of it.** The fold list therefore has to put the closed six-member list into M01, and the temptation at that moment is to copy it from [`types.ts:954`](../../packages/rules-engine/src/types.ts) — which would ratify the engine exactly as pinning `true` would, one level up and harder to see. Section 4's derivation exists to be used instead.

**Fourth, `RE-P-15` does not exist.** `INV-15`'s named enforcement is a property ([M01:984](../plans/M01-rules-engine.md), "`engineEligible` equals the conjunction of `engineGates`, for every generated state") and a grep across `packages/` and `scripts/` returns nothing. So the invariant this ruling clarifies is currently enforced by no test at all, and a founder reading "the engine already does the right thing" should know that nothing checks it.
