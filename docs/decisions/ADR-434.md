### 3. The staleness, confirmed at source and re-derived rather than taken on report

> **WHAT HOLDS THE GREEN IS THIS LINE BREAK** and the register says so: the statement below is short enough that prettier leaves it on one line, so the next character after the name is a space, and a second name added to it would be reflowed into a list and flip the artifact with nobody having edited the check, the probe or the register.

**WHAT THE PROBE NOW DOES**, read at source and not from a sibling entry. `event-sink-caller` is registered at [`absence-claims.mjs:1146`](../../packages/tooling/checks/absence-claims.mjs). ### 4. The repair, and why the corrected sentences stay in the file

**THE FALSE SENTENCES ARE NOT DELETED.** They are quoted verbatim, as an indented block, under `IT READ`, followed by **THE FIRST OF THOSE IS FALSE SINCE ADR-431. THE SECOND WAS NEVER TRUE.** That is `RI-14`'s rule and it is quoted from the invariant's own words at [`repo-invariants.mjs:1887`](../../packages/tooling/checks/repo-invariants.mjs): *"A REFUTED CLAIM MAY STAY, AND MUST SAY SO. The corrected file deliberately QUOTES the false sentence rather than deleting it, because a false sentence deleted leaves nothing for the next reader to check."* A reader arriving at this paragraph can now see that the line break was once believed to hold the green, that it did not, and what did.

**WHAT REPLACES THE INFERENCE.** Three paragraphs: that the probe blanks specifier lists before it reads and therefore can tell; that the line break was never the mechanism, with the one-line case that proves it; and that the request the comment used to make of the next reader is **withdrawn**, because all seven publication shapes now read `absent` and every install shape still reads `present`. The FIRST reason for publishing the writer alone -- that it is the one export of this package that is an adapter into an append-only table -- is untouched, because it is about what the export is and nothing measured here bears on it.

**THE HELPER IS CITED BY SYMBOL AND NEVER BY LINE.** `BINDING_LIST` and `withoutBindingLists` are named in the comment without a line number, deliberately: a pointer into a live file is a pointer somebody has to repair, and [ADR-386](ADR-386.md) section 6 is the entry about what that costs.

**AND THE COMMENT NOW SAYS THAT NOTHING WATCHES IT**, which is section 5 written where the next reader will meet it rather than only here.

**IT IS A LIVE FILE AND NOT A DATED RECORD, WHICH THE DISPATCH ASKED THIS ROW TO SETTLE BEFORE RELYING ON IT.** [ADR-386:169](ADR-386.md) reads: *"THE PROPERTY IS THAT NO CITED LINE MOVES. Where one must, every pointer in a LIVE file is repaired and listed, and every pointer in a DATED RECORD is NAMED, because that one cannot be repaired by a commit."* **THE RULING PUTS LIVE FILES AND DATED RECORDS ON OPPOSITE SIDES OF THIS EXACT QUESTION**, and the reason it gives for the dated side -- section 6 clause 2, that repairing such a pointer *"would rewrite the record to say something it did not say"* -- is a property of a record with a date on it. `packages/ledger/src/index.ts` carries no date, no session heading and no signature; it is source, and it is compiled. **AND THE RULING IS ABOUT POINTERS RATHER THAN ABOUT CLAIMS**, so it does not reach this comment at all: what is stale here is a statement about a check's behaviour, not a citation to a line. Both readings give the same answer and the repair is taken.

**NO CITED LINE MOVED.** Derived rather than assumed: the only `path:NNN` pointers into this file anywhere in the tree are [`docs/sessions/2026-09-04-session-511.md:25`](../sessions/2026-09-04-session-511.md) at `:72` and [ADR-314:3](ADR-314.md) at `:77`, **both above the first line this row touches**, so neither lands on different text. **THREE DATED POINTERS BELOW THE EDIT ARE NAMED AND NOT REPAIRED**, per the ruling: [ADR-431:63](ADR-431.md) (`line 175`), [ADR-431:155](ADR-431.md) (`lines 148 to 174`) and [session 626:32](../sessions/2026-09-07-session-626.md) (`lines 148 to 174`). The paragraph they point at is the paragraph this row rewrote, which is the point of the ruling: those records said something true on their date and a commit cannot make them say it again.

### 5. "No gate reports this", derived leg by leg, and ADR-431's reason for it is wrong

THE ARGUMENT DOES NOT, AND THE DIFFERENCE MATTERS BECAUSE IT IS THE DIFFERENCE BETWEEN A FILE NOTHING LOOKS AT AND A FILE TWO LEGS OPEN.**

### 6. Whether that is a hole worth closing, and what closing it costs

**IT IS A HOLE, AND IT IS THE CLASS [ADR-429](ADR-429.md) SECTION 10 DESCRIBES FOR TESTS ARRIVING AT PROSE**: a thing that can silently stop being true, in a file a runner opens, with nothing in the run that could notice. **IT IS NOT CLOSED HERE**, and the price below is the argument for giving it a row rather than bolting a control onto a repair.

**CANDIDATE A: REGISTER THE BARREL AS AN ABSENCE-CLAIM SITE.** Cost: one entry in `packages/tooling/checks/absence-claims.mjs`. **REFUSED, AND THE REASON IS THAT IT BUYS ALMOST NOTHING.** The sentence is not an absence claim about an artifact; it is a claim about a probe. It would have to enter as `unbindable` with a reason, which leg 4 accepts and no other leg checks, so the only thing gained is leg 1: the sentence would have to keep existing, character for character. **A FALSE SENTENCE SATISFIES LEG 1 PERFECTLY.** It would have stood green through all 53 commits. And it would buy a liability: [ADR-431](ADR-431.md) section 8 measured leg 1 at one hand rewrap from a false red on **24 of its 33 anchors**.

**CANDIDATE B: A NEEDLE ON THE TWO NAMES, SO LEG 6 REACHES IT.** This is the one that works, and it is priced rather than argued. Derived over the base tree, counting register entries a green run would demand that do not exist today:

| configuration | new registrations forced | reaches the stale paragraph |
|---|---|---|
| shipped needles, `SWEEP_WINDOW` 2 (today) | **0** | no |
| shipped needles, `SWEEP_WINDOW` 3 | **3** | no |
| **+ a needle on `TRANSACTION_EVENT_WRITER` and `makeEventSink`, window 2** | **2** | **no** |
| **+ that needle, `SWEEP_WINDOW` 3** | **7** | **YES** |

**SO THE PRICE IS SEVEN REGISTER ENTRIES AND A GLOBAL WINDOW WIDENING**, in `packages/tooling/checks/absence-claims.mjs` plus whatever cases that file's suite would owe. Three of the seven are bought by the window alone against needles that already ship, and are therefore sentences the register was already meant to reach and has been missing.

**AND THE MEASUREMENT IS WHAT ARGUES AGAINST TAKING IT IN THIS ROW, RATHER THAN THE COST.** Three things, each of which is a reason the control needs its own counterfactual:

1. **IT FORCES REGISTRATION AND NOT TRUTH.** Leg 6's finding says *"no register entry binds it"*. Once bound, the sentence is checked by leg 1, which asks that it still exist, and by leg 2, which asks the ARTIFACT's probe -- and `event-sink-caller`'s probe was reporting `absent` correctly the whole time. **THE CONTROL WOULD HAVE NAMED THE SENTENCE IN 2026-09-07's REGISTER AND WOULD NEVER HAVE GONE RED AT IT.** What it buys is that a row reading the register meets the sentence, which is how [ADR-431](ADR-431.md) found it in the first place and is worth something, but it is not a gate on truth and must not be sold as one.
2. **ITS REACH IS A DISTANCE INSIDE A COMMENT.** The window has to be 3 rather than 2 because on the base tree the nearest occurrence of either name sat exactly **3 lines** from the marker. **ON THIS ROW'S OWN REPAIRED PARAGRAPH THAT DISTANCE IS ABOUT 20 LINES AND THE SAME CONTROL AT WINDOW 3 MISSES IT.** A control whose reach depends on how far a writer put a name from a word is leg 1's exposure arriving one leg over, and pricing it honestly means seeding it, which is a row's work.
3. **THE FILE IT LANDS IN IS HELD BY ROW 433 THIS WAVE.** Building it here would mean reaching into `absence-claims.mjs` for a register edit, which this fence forbids and which is the coupling the dispatch asked to hear about rather than to work around.

**CANDIDATE C: A CHECK THAT READS A COMMENT'S CLAIM ABOUT A CHECK.** **REFUSED WITHOUT A NUMBER**, on `RI-14`'s own reason at [`repo-invariants.mjs:1882`](../../packages/tooling/checks/repo-invariants.mjs): claims about behaviour *"are argued rather than looked up, and a check that pretended to read them would be a check somebody switches off."*

**AND THE OBSERVATION A LATER ROW SHOULD START FROM.** The falsifier for the first stale sentence **already existed in this tree, in the suite, on the base**: `packages/tooling/test/absence-claims.test.ts` holds [ADR-431](ADR-431.md)'s cases asserting that a publication reads `absent`, and it names the barrel by path at `:1448`. A green case asserting the opposite of a shipped comment sat beside it for 16 commits and nothing connects the two. **THE CHEAPEST HONEST CONTROL MAY NOT BE A SWEEP AT ALL BUT A BINDING FROM PROSE TO A NAMED CASE**, and that is a change to the register's shape, which is a row with a subject rather than a clause in this one.
