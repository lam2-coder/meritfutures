### 3. The narrower question, priced and refused: should the anchor be asked when the window fails

**[ADR-380](ADR-380.md) OFFERED THIS AS THE CHEAPER ROUTE, AND IT IS CHEAPER IN LINES AND NOT IN MEANING.** For a named citation `RI-15` today requires the window AND the anchor. Asking the anchor when the window fails makes the two a disjunction, and since the anchor's first leg cannot succeed where the window failed -- a cited range that DECLARES the name puts the name on the cited line, which is a window of zero -- **the rule collapses to the anchor alone and the window leg goes dead for every named citation.**

**IT WAS WRITTEN AND RUN, IN THREE SPELLINGS, AGAINST THE PRISTINE BASE.**

| Spelling | RI-15 findings, base | RI-15 findings, with the section 4 repair |
|---|---|---|
| today | 0 | 1 |
| anchor asked on any window failure | **1** | **1** |
| anchor asked only where the name IS in the file | **1** | **1** |
| enclosing declaration must BE the name | 0 | 1 |

**THE ONE FINDING IS THE SAME FINDING IN BOTH LOOSE SPELLINGS AND IT IS THE REGISTER REPORTING THE CHANGE:**

```
apps/api/src/admin-source/flags.ts: the register claims `detectors/fills.ts:505`
for `martingale` is a known finding and it is not one on this ref
```

**SO THE CHANGE'S ENTIRE EFFECT ON THIS TREE IS TO SILENCE ONE REGISTERED CITATION, AND THE MECHANISM WAS OPENED RATHER THAN COUNTED.** [`flags.ts:48`](../../apps/api/src/admin-source/flags.ts) writes three flag types against three pointers, `` `martingale` (`detectors/fills.ts:505`, `:810`, `:1059`) ``, and the reader binds the nearest name to the FIRST pointer, which is `RI-15`'s own miss (8). The register's own commentary calls that citation **TRUE**. The anchor clears it like this:

```

enclosing declaration                D01_FLAG_TYPE
subject in the sentence that matches it   flag_type
```

**`sameName` ADMITS CONTAINMENT FROM FOUR CHARACTERS UP, SO `flag_type` REACHES `D01_FLAG_TYPE`.** The sentence's `flag_type` is the `risk_flags` COLUMN. It says nothing whatever about `martingale`, and the same match clears a pointer at `:505`, `:810` or `:1059` indifferently. **That is the anchor being satisfied by a coincidental token, which its own docblock names as the entire reason it exists.**

**AND THE SECOND SPELLING SHOWS THE SIZE OF WHAT THE DISJUNCTION WOULD ADMIT.** With the section 4 repair in place, the anchor clears `wiring.test.ts:936` -- [ADR-380](ADR-380.md) predicted that and the prediction is correct -- because the cited line sits inside `interface PayoutTx` and the sentence writes `PayoutTx.subject`. **`interface PayoutTx` runs from `:557` to `:632`.** So the rule would admit **76 lines** where the window admits **5**, and it would admit them for a claim about one of its eight members.

**THE FOURTH SPELLING IS THE HONEST ONE AND IT MOVES NOTHING.** Requiring the enclosing declaration to BE the bound name changes no verdict on this tree in either direction. A leg that moves nothing is a leg this file has refused since `RI-05`.

**REFUSED.** The anchor is what the window could not supply, and it is not what the window could be replaced by.
