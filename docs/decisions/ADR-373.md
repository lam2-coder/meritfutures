**Three rows found the same defect one module at a time and each repaired only its own port.** [ADR-359](ADR-359.md) found that certificate revocation's docblock advertised one status and the wire answered another; [ADR-365](ADR-365.md) found it on the admin payout console and could not make the repair; [ADR-366](ADR-366.md) found it on the admin wallet and recorded it as a landmine. **This row asked how many of the rest are wrong. The answer is that FIVE of the twenty-one refusal classes disagree with their own router, that FOUR of the five are one defect with one repair, and that the fifth is wrong on the other side.**

### 2. THE RULING

Section 3.
2. **RULED: THAT RULING DOES NOT GENERALISE AND IT IS NOT INHERITED.** [ADR-364](ADR-364.md) refuted exactly this kind of unexamined generalisation last wave, so the ground is re-derived per module: each of the four handlers states the ADR-192 clause 2 argument in ITS OWN source, and section 4 is the argument that a fifth module carrying the same shape is ruled the OTHER way.
3. **RULED: `catalog.ts` IS THE FIFTH DISAGREEMENT AND THE HANDLER IS THE WRONG SIDE OF IT.** `CatalogUnwired` is caught by nothing anywhere in the deployable, so `server.ts`'s error handler answers `500 internal_error` on all three of its rows. **A catch is behaviour and this row changes none**, so the docblock is left standing, ANNOTATED with what the tree actually delivers, and the disagreement is pinned by an executed case that expires when the catch lands. Section 4.
4. **RULED: `internal.ts` AND `public-methods.ts` ARE NOT FINDINGS, AND SAYING SO IS PART OF THE RULING.** Both answer 500 on an unset port and both ARGUE for it in their own source. **The defect is not the status; it is the prose disagreeing with the wire.** Section 4.
5. **RULED: THE LOG LINE IS A CONTROL ON THREE MORE MODULES AND NOTHING WAS HOLDING ANY OF THEM.** ADR-359 held it for one. Section 5.
6. **RULED: THE CLASS CAN BE A DERIVED CONTROL, AND IT IS ONE NOW.** Section 6, with ten falsification seeds.

### 4. Which side is wrong, decided per module rather than inherited

**ADR-359 RULED THE 401 CORRECT AND THE DOCBLOCK WRONG, ON [ADR-192](ADR-192.md) CLAUSE 2. THAT RULING IS NOT ASSUMED TO CARRY, WHICH IS ADR-364's OWN LESSON.** What carries is the PREMISE, and the premise was checked in each file separately: all four handlers state the disclosure argument in their own comment, that whether this process holds a backend is a fact about the deployment and a caller who has not authenticated may not have it. **The four 401 legs are at `admin-certificates.ts:697`, `admin-payouts.ts:1058`, `admin-wallet.ts:1531` and `admin-writes.ts:946`; the four outer legs they were confused with are at `admin-certificates.ts:744`, `admin-payouts.ts:1125`, `admin-wallet.ts:1602` and `admin-writes.ts:992`.** So for these four the handler is right and the sentence was wrong.

**THE THREE PRIOR ROWS DISPOSED OF THE IDENTICAL SENTENCE THREE DIFFERENT WAYS, AND THAT IS ITSELF THE FINDING.** ADR-359 section 3 declined the edit on the ground that the sentence is about the CLASS and is true of the class. ADR-365 section 8 recorded it as OWED, wrote the repair, and reverted it because the insertion broke citations in a file that row did not hold. ADR-366 section 6 recorded it as a LANDMINE and did not open the file. **Three dispositions, one sentence, three consecutive waves. This row settles it against ADR-359, using ADR-359's own measurement**: that entry wrote that a reader who greps for the status *"will predict the wrong status for the deployment as it actually stands"*, and predicting the wrong status is what a docblock exists to stop.

**`catalog.ts` IS RULED THE OTHER WAY AND THE DIFFERENCE IS A DECISION VERSUS AN OMISSION.**

- The 401 in the admin four is a DECISION, argued in the handler's own source and resting on a merged ruling.
- The 500 in `catalog.ts` is an OMISSION. **There is no `instanceof CatalogUnwired` anywhere in the deployable.** The class escapes to `server.ts:226`, which answers `internal_error` and logs *"unmapped error status"* at `server.ts:232`. Nobody chose it.
- The docblock's own argument is the argument this tree acts on everywhere else: `economic-calendar.ts`, `verify.ts` and `certificates.ts` each raise a distinct class for a deployment nobody finished and each answers 503, on [ADR-240](ADR-240.md) section 4's standing ruling that an unfinished deployment is not a defect.
- **AND THE STATUS TABLE FORECLOSES THE CHEAP FIX.** `STATUS_CODE` in `server.ts` carries no `503`, so giving `CatalogUnwired` a `statusCode` would still answer 500. What is missing is a handler-level catch, which is what every other module in the table has.

**SO THE HANDLER IS THE WRONG SIDE AND THIS ROW DOES NOT CHANGE IT**, because the fence is comments and tests. It is a finding and an open question (`OQ-373-01`), pinned by an executed case rather than by a sentence. **THE DOCBLOCK IS ANNOTATED RATHER THAN RETIRED, AND THE DISTINCTION IS THE RULING.** Its argument stands word for word, because it is the argument this tree acts on everywhere else; what is added beside it is that the tree does not deliver it. **Nothing is retired here, so `RI-14` has no claim to keep**, which is the opposite disposition from the admin four one section up and follows from ruling 3 rather than from taste.

**`internal.ts` AND `public-methods.ts` ANSWER 500 AND ARE NOT FINDINGS, WHICH IS THE CONTROL CASE THAT KEEPS THIS ROW HONEST.** `public-methods.ts` says a 503 *"would invite a retry against a process that will never succeed"*; `internal.ts` weighs both precedents by name and takes the same side, because its rows include the manual batch trigger and every retry against an unwired process is another trigger that cannot run. **Both are measured answering 500 and both say so.** The defect this row is about is never a status; it is prose that disagrees with the wire.

### 5. Where the log is the only place the fact exists, and what was holding it

**ADR-359 measured that the unwired 401 is byte-identical to the document a genuinely anonymous caller receives**, deliberately, so `request.log.error` is the only channel that distinguishes *"this deployment installed no backend"* from *"your credentials were rejected"*. It held that line for `admin-certificates.ts` with four cases and measured that nothing executed had been holding it.

**THE OTHER THREE MODULES CARRY THE SAME LINE AND NOTHING WAS HOLDING ANY OF THEM.** Deleting `admin-writes.ts`'s left `admin-writes.test.ts` entirely green, which is seed 4. Three cases now hold all three: one log entry, carrying the error itself rather than a rewritten string, whose message names the refusing member and the setter that would install a backend.

**AN OPERATOR WITH VALID CREDENTIALS IS TOLD THEIR CREDENTIALS ARE WRONG ON FOUR ADMIN SURFACES, AND THE TRUE ANSWER IS READABLE ONLY IN A PROCESS LOG.** That is ADR-359's disclosure trade, and this row does not disturb it; it only makes the channel it depends on impossible to drop silently.

### 6. Whether it can be a derived control. It can, and it is

`apps/api/test/advertised-status.test.ts` derives both halves and compares them.

**ADVERTISED is parsed out of the source.** For each refusal class, the doc comment above it, then the FIRST PARAGRAPH THAT NAMES A STATUS, then every status that paragraph affirms with every status it DENIES dropped. **Both narrowings are measurements rather than conveniences.** Without the denial rule, *"Answered as 503, never 500"* promises two statuses and nine clean modules go red for saying exactly what they should. Without the paragraph rule, `account-reads.ts` promises a 500 in a clause about what would happen if a sibling class ESCAPED the catch, and `certificates.ts` promises a 200 and a 404 in a paragraph about which caller could reach which. **The summary paragraph alone would be narrower and it loses `catalog.ts`, whose status sentence is its second paragraph and is the sharpest finding here.**

**REACHABLE is driven.** No table of expected statuses is written down anywhere; the statuses are whatever the composed router returns.

**THE RULE IS A SUBSET AND NOT AN EQUALITY.** A module may reach statuses no docblock names, which is a 400 for a malformed body or a 404 for an address naming nothing. What it may not do is PROMISE a status no request to it can meet.

**BOTH EXCEPTIONS ARE ASSERTED TO BE REAL, SO BOTH FAIL ON GOOD NEWS.** The `catalog` entry asserts that the promised status is still unreachable and the met one still reached, so the day somebody adds the catch the case reddens and the entry must be deleted rather than inherited. The `checkout` entry asserts that its status is still unreachable to a bodyless probe and still promised. **An exception nothing re-checks is an exemption list.**

**TEN FALSIFICATION SEEDS, EVERY ONE WATCHED RED AND EVERY ONE RESTORED BYTE-IDENTICAL under `sha256sum -c`.**

**`RI-30` WENT RED ON THIS ROW'S OWN FIRST DRAFT, AT 34 OF 35, AND IT WAS RIGHT TO LOOK.** The reader strips the ` * ` rail from inside a docblock it has already located, and it was written as a `.replace()` over a block-comment opener, which is the shape that check refuses on the measurement in its own header. **NO CHECKER WAS EDITED.** `stripComments` is the wrong tool for this operation, since it would delete the very text the file reads, so the pattern moved to a named constant that says so. **That is the third consecutive wave in which an invariant caught the defect it was minted for inside the diff that introduced it.**

### 7. What the citation grammar cost this row, measured a THIRD time

**THE `catalog.ts` DOCBLOCK COULD NOT BE ANNOTATED UNDER THE FENCE AS DISPATCHED, AND THE OBSTACLE IS A CITATION.** `RI-15` and `RI-16` bind a citation to a line number within a two-line window, and `apps/api/test/wiring.test.ts:958` cited `catalog.ts:1211` for `readSize`. **A one-line insertion above it lands that pointer on a blank line and a two-line insertion lands it on a bare closing brace, and `RI-15` refuses both by a rule the window does not soften**, which is why the window alone does not save an insertion that would otherwise fit inside it. That measurement stands and is the interesting half.

**WHAT CHANGED IS THE FENCE AND NOT THE MEASUREMENT, AND THE CONTRADICTION WAS THE DISPATCH'S OWN.** The row granted citation-repair rights across `apps/**` for citations this diff breaks and in the same prompt forbade `apps/api/test/wiring.test.ts`; both cannot hold for a docblock sweep that shifts lines in the files that file cites. **The dispatcher resolved it mid-row in the narrowest form**: this row may edit `wiring.test.ts` ONLY to repair a citation its own diff broke. **That grant was used exactly once**, repointing `readSize` from `:1211` to `:1213`, a line number and nothing else. **No `BLOCKED` entry, no `DEFAULTS`, no `LIVE_DEFAULT`, no `UNPROVEN_RULING`, no triple and no sentence making a claim about a port was touched**, and `git diff` on that file is one digit pair.

**AND ONE POINTER IS NOW SILENTLY DRIFTED BY EXACTLY TWO, WHICH IS REPORTED RATHER THAN LEFT TO BE FOUND.** `ALLOCATION.md:278` cites `catalog.ts:1211` for `readSize` and `catalog.ts:1224` for `readCapSchedule`; both are two lines out after this row's insertion, `CITATION_WINDOW` is two, so `RI-16` is silent and the pointers are wrong anyway. **It is another row's cell and outside this fence.** ADR-365 section 8 recorded the identical shape on `admin-payouts.ts`, so this is its second occurrence and the first where the drift was created knowingly.

**THE FOUR ADMIN REPAIRS WERE SIZED BY THE SAME MECHANISM.** A full-length correction in `admin-payouts.ts` breaks three citations in `ALLOCATION.md` row `365`, which is another row's cell. The repair is therefore three lines where it would otherwise have been thirteen, and the argument lives here instead. **`admin-certificates.ts`, `admin-wallet.ts` and `admin-writes.ts` tolerate fourteen added lines with no citation damage at all**, and were held to the same three lines so that one defect found four times reads as one repair rather than four.

**THIS IS [ADR-361](ADR-361.md) SECTION 9's UNSTATED MAINTENANCE COST, MEASURED FOR THE THIRD TIME AND ON A THIRD FILE.** ADR-365 section 8 measured it second and called it overdue rather than open. **It is now shaping prose in a money-path module, and it forbade a correction outright until a fence was widened by hand to let one line of it through**, which is a different order of cost from the two that came before.

### 8. Open questions, recorded as the founder's with options and no values

**OQ-373-01. Does `catalog.ts` get the catch its own docblock argues for?** Measured: all three catalogue rows answer 500 on an unwired deployment, and the class is caught by nothing. **Options: (a)** give it a handler-level catch answering 503, which is what `economic-calendar.ts`, `verify.ts` and `certificates.ts` each do and what the docblock argues for; **(b)** rule the 500 correct on `internal.ts`'s reasoning and retire the docblock's status sentence instead, which makes the catalogue the third module to take that side; **(c)** leave both, which is the state on merge if nobody acts. **This row takes no option, because every one of them is a change to what a request meets.**

**OQ-373-02. Should a status a docblock promises be data rather than prose?** The control here reads English and section 6 records exactly how narrow the reading had to be to stay honest. **Options: (a)** leave it, and accept that the parser carries two measured narrowings; **(b)** have each module declare its refusal status as an exported constant the handler and the check both read, which removes the parsing entirely and is executable code rather than a comment; **(c)** widen the check to every error class rather than the two naming conventions, which reaches `InternalOpsError` and `MethodPageError` and costs the population its derivation.

**OQ-373-03. Is the citation cost now a blocker rather than a tax?** Section 7 measures that a correction to a money-adjacent module was forbidden by a pointer in a file the row could not open, and was unblocked only by widening a fence mid-row. **The next such collision will not have a dispatcher awake to widen it.** **Options: (a)** a fence that automatically reaches a row's citers; **(b)** a citation grammar that does not bind line numbers, which is `RI-15`'s own row and is now owed by four entries; **(c)** an accepted practice of appending corrections where no citation follows, which puts a correction far from what it corrects. **It is the same question ADR-365 section 12 called overdue, asked a third time with a harder example.**

### 9. Where this entry is most likely wrong

- **Section 4 rules the `catalog.ts` handler the wrong side, and a reviewer may hold the opposite.** The measurement is the same either way: the class is caught by nothing and the answer is 500. What differs is whether the absence of a catch is an omission or an unwritten decision. **If a reviewer rules the 500 correct, this row's finding becomes a docblock repair somebody else must make**, and section 7's obstacle applies to them too.
- **REACHABLE is measured with an empty body and no other header.** A status a module reaches only behind a well-formed request is invisible to it, and `checkout.ts` is the one place that bites today. **A second such module arriving would present as a false finding**, and the remedy is another named explanation rather than a widened rule.
- **The whole measurement is of an in-process server holding the shipped defaults.** It says nothing about a deployment that ran `start.ts`, and nothing about a PARTIAL install, which is precisely the state in which the admin four's outer leg becomes reachable. **Nothing in this tree goes red on a partial install**, which ADR-365 section 10 recorded as a landmine and which this row reproduces rather than closes.
- **The advertised parser reads English.** Section 6 defends two narrowings with seven sentences from this tree, and a docblock written in a shape none of the seven anticipates would be read wrong. The direction of that error is not uniformly safe.
