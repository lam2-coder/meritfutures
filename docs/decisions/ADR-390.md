### 2. THE RULING ON `RECORD_HEADING`'s SCOPE

> **A DOCUMENT WHOSE OWN TITLE DATES IT IS A RECORD END TO END. No later heading cancels that. A document whose title does NOT date it keeps the per-heading rule exactly as it stands.**

**IT IS NOT A NEW RULE. IT IS THE RULE THE CORPUS ALREADY KEEPS IN 1,076 OF 1,101 TITLE-DATED DOCUMENTS**, and it keeps it there by an accident of typography rather than by decision: those documents write their sections as `###`, so nothing ever reaches the level the recogniser reads. **The 25 that write sections as `##` lose their date at the first one.**

**AND IT IS THE PROPERTY THE SOURCE ALREADY CLAIMED IN WRITING.** [`scripts/corpus/gates.mjs`](../../scripts/corpus/gates.mjs) carried this comment beside the loop, and it is the sentence this ruling makes true:

> *"Levels 1 and 2 only. An ADR's `### 3.` inherits the dated `##` its file opens with, which is what makes a whole dated ruling a record rather than only its opening paragraph."*

**A whole dated ruling is exactly what it did not make a record, for 25 files.** The comment describes an intent that the code delivered only for documents whose authors happened to indent one level further.

**THE SECOND CLAUSE IS NOT A HEDGE AND [`docs/STATE.md`](../STATE.md) IS WHY IT IS THERE.** `RI-15`'s own header gives the reason the rule is heading-based rather than directory-based: it must reach *"INSIDE `docs/STATE.md`, which is a LIVE document that ACCUMULATES dated sections and which no directory rule can split."* That file's first heading is `# STATE`, which no date recogniser matches, so the per-heading read survives for it unchanged and its undated sections stay in scope. **A rule of "once dated, dated forever" would have swallowed the rest of `STATE.md` at its second heading, `# **FROZEN** (2026-08-14)`, and that is the failure this ruling deliberately does not take.**

**WHAT THE RULING DOES NOT DO.** It mints no invariant and spends no `CI-06` letter. It does not touch `RECORD_HEADING` itself, which is unchanged in both files. It does not re-level a single heading in a single record. And it does not reopen [ADR-388](ADR-388.md)'s repairability ruling, which section 8 of that entry states does not use this axis at all.

### 5. Why the rule and not the twenty-five headings

**[ADR-388](ADR-388.md) SECTION 15 ITEM 3 OFFERED TWO REMEDIES: THE RULE, OR THE FIFTEEN HEADINGS. THE HEADINGS ARE REFUSED, ON THREE GROUNDS AND NOT ON COST.**

### 6. `CI-06/table-row-width` assertion 3: a claimed body row must CLOSE

**IT IS A LEG AND NOT A NEW SLUG**, which is [ADR-388](ADR-388.md) section 9's ruling and this row agrees with it for its own reason: it is that gate's own subject, the letter series is closed at `w`, and the gate already carries two assertions of which only one is in its title. **The title is left alone on that precedent.** Assertion 1, the header-versus-delimiter check, has never been in it either.

**THE PREDICATE.** A body row of a claimed table must end with an unescaped pipe. `rowCells` strips a leading pipe and a trailing pipe *if present*, which is GFM's own rule and is correct for counting cells, **so a row that never closes carries the declared width and the cell-count assertion cannot express it.** The opening pipe is not asserted separately because it is structural: the run splitter claims only lines that start with one, so a row that does not open is not a row of that table to begin with.

**THE SCOPE IS BODY ROWS AND IT IS MEASURED RATHER THAN ASSUMED.** Over the whole of `docs/` on `3b664fcf`, **31,237 rows in claimed tables, of which 23,549 are body rows, and 0 rows of any of the three kinds fail to close.** Header rows: 0. Delimiter rows: 0. **Scoping the leg to body rows costs nothing today and keeps it aimed at the edit that produces the defect**, which is an append to a registry.

**THE REGISTER IS EMPTY AND THAT IS DERIVED, NOT ASSERTED.** The gate's own note, derived at reporting time on this branch's head: **0 body row(s) opening a row without closing it**, over **24,590 body rows in 3,857 tables**. `CI-06/table-row-width` carries a register keyed by (file, first cell) for ragged rows, at 17 entries across 7 files; **assertion 3 adds no entry to it and needs no exemption of any kind.**

**FOUR SEEDS, THREE RED AND ONE GREEN, EVERY ONE RESTORED BYTE-IDENTICAL AND VERIFIED WITH `sha256sum -c`.**

| Seed | What was placed | Result |
|---|---|---|
| **A** | The closing pipe removed from [`docs/sessions/README.md`](../sessions/README.md) line 141, restoring the exact defect [ADR-384](ADR-384.md) found and [ADR-388](ADR-388.md) repaired | **RED, 32 of 33**, naming that file, that line, and the first cell `241` |
| **B** | The same, on a body row of a different file, [`ALLOCATION.md`](ALLOCATION.md) line 271 | **RED, 32 of 33**, naming the row headed `279` |
| **C** | The closing pipe removed from the HEADER row of that same table | **GREEN, 33 of 33.** The leg is body-scoped on purpose and this is the control that says so |
| **D** | The closing pipe of the same body row replaced with an ESCAPED `\|`, which GFM reads as content | **RED, 32 of 33.** The predicate reads an UNESCAPED pipe, which is `rowCells`'s own grammar |

**SEED C's RESTORE IS THE ONE WORTH RECORDING.** Removing the pipe also removed the cell padding, and appending ` |` did not put the padding back, so `sha256sum -c` reported FAILED. **The line was then restored from the base blob by reading it and writing it, and the checksum matched.** `git checkout --` was not used, which is the rule, and the point of the rule is exactly this: a restore that is not verified is a restore that is assumed.
