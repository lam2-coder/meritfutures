## ADR-138: a Server Action has no path, so the refusal is TOTAL, and the first rendered document is what makes it reachable  (2026-08-27, status: proposed)

**[ADR-095](ADR-095.md) ruling 3 refuses two things and [ADR-098](ADR-098.md) closed one of them.** The ruling reads *"No Next.js route handler and no Server Action may serve `/api/v1`, any operator path, or any surface [API_CONTRACT](../architecture/API_CONTRACT.md) specifies"*, and [`RI-09`](../../packages/tooling/checks/repo-invariants.mjs) is the route handler half, by path. **The Server Action half has never had a mechanism, and until this session it did not need one: there was no `app/` directory in this repository and there never had been.** This entry rules the other half and [`RI-11`](../../packages/tooling/checks/ui-server-endpoints.mjs) is it.

- **Origin:** [P4](../plans/P4-portal-and-site.md), dispatched as session **250** on branch `claude/portal-app-shell`, whose objective is the portal's first rendered document. The number was reserved before dispatch; [ALLOCATION](ALLOCATION.md)'s `138` row is amended **in place** per [ADR-065](ADR-065.md) T3.

- **NOT MONEY PATH.** No migration, no `SD-nn`, no ledger, no engine, no payout, no auth. [ADR-003](ADR-003.md)'s strict regime does not bind this session. It is worth a founder read anyway for one reason, stated in section 4: **the refusal this entry takes is TOTAL where the ruling it implements is conditional**, and a total refusal of a framework feature is a thing the project lives with.

### 3. THE RULING

**RULING 1. THE SERVER ACTION DIRECTIVE IS REFUSED IN EVERY PACKAGE OF THIS WORKSPACE, WITH NO EXEMPTION, AND THE REFUSAL IS TOTAL RATHER THAN SCOPED TO THE OPERATOR SURFACE.**

**A Server Action has no path.** The framework posts it to the URL of whatever route the caller is already on and dispatches on a build-time hash carried in a request header. So the question [`RI-09`](../../packages/tooling/checks/repo-invariants.mjs) asks of a route handler, *does this path spell the operator surface*, **has no answer for an action in either direction**: the endpoint is real, it accepts a request body, it runs on the server with the deployable's own credentials, and nothing in the tree describes what it answers.

That leaves exactly one checkable question, which is whether one exists. **[ADR-095](ADR-095.md) ruling 3 is conditional and this implementation is not, and the difference is deliberate rather than an overreach**: a conditional refusal of an unconditional hole is a rule that can only be enforced by reading the body of every action and believing what it says, which is [ADR-042](ADR-042.md)'s *"prose is not a control"* wearing a type signature.

**RULING 2. A FRAMEWORK ROUTING CONFIGURATION MAY NOT SPELL THE API SURFACE.** No `next.config.*` and no `middleware.*`, at a deployable's root or under its `src/`, may carry a string literal containing [API_CONTRACT](../architecture/API_CONTRACT.md)'s base path, or beginning with an operator prefix. **Both lists are read out of [`apps/api/src/surface.ts`](../../apps/api/src/surface.ts)** and neither is copied, which is `RI-09`'s own rule: *"A second copy of `['/admin', '/internal']` in this file would drift the day the contract grows a third operator prefix, and it would drift SILENTLY."*

**RULING 3. THE MECHANISM IS `RI-11`, IN ITS OWN FILE, AND IT IS THE FIRST CHECK IN `CHECKS` THAT IS NOT WRITTEN IN [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs).** The array stays the one list every reader already knows: the runner, `pnpm run check:invariants`, [ALLOCATION](ALLOCATION.md)'s `RI-nn` table and the suite that walks every check all see `RI-11` without learning anything new. `RI-11` is the next free number and [ALLOCATION](ALLOCATION.md)'s table says so; its row lands in the commit that writes the check, per that table's own rule.

**RULING 4. `CI-07` IS NOT MOVED, RELAXED OR RE-RULED.** Section 7.

**RULING 5. [ADR-095](ADR-095.md) RULING 4'S CARVE-OUT IS UNTOUCHED AND IS NOT REACHED BY RULING 1.** That carve-out is [M09](../plans/M09-marketing-site.md)'s revalidation hop, permitted on `apps/site` *"as a cache-control hook and never as an API surface"*, on four named conditions. **It is a route handler, and a route handler is a path `RI-09` can read.** An implementation of it as a Server Action would be refused here, and that is the correct direction: [M09](../plans/M09-marketing-site.md) section 3.2's sequence has the API call the site over HTTP, which is a URL the API must be able to write down.

### 5. THE ALTERNATIVES, AND WHY EACH IS REFUSED

| Alternative | Refused because |
|---|---|
| **Refuse a Server Action only when it serves an operator path**, which is [ADR-095](ADR-095.md) ruling 3 read literally | **Unimplementable, and not for want of effort.** An action's endpoint is the current route's URL plus a hash; there is no path to test. The only remaining reading is "refuse an action whose BODY touches an operator concern", which needs a call-graph analysis of a `.tsx` file to a database accessor, and would still pass an action that reaches the same data through a helper. A control that can be defeated by extracting a function is a review convention |
| **An ESLint rule instead of an invariant** | It is the right instrument for a directive and it is the WRONG one today, **measured rather than assumed**: [`eslint.config.js`](../../eslint.config.js) attaches every `merit/*` rule to `apps/**/*.ts` and `packages/**/*.ts`, and a Server Action in the App Router is ordinarily `.tsx`. The seeded action in section 2 left `pnpm run lint` at exit 0. That glob is one line and it is in nobody's fence this session; section 6 carries it. **A control that exists today beats a wider one somebody else has to write first**, and the two are not exclusive |
| **Do nothing, on the ground that no Server Action exists yet** | This is the argument [ADR-073](ADR-073.md) exists to refuse. **Six sessions are writing route segments under `app/` concurrently with this one**, each holding a directory where a `.tsx` file and a directive are the shortest path to a working form. The refusal is worth a fraction as much next week |
| **Fold `RI-11` into [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) beside the other ten** | Refused on collision rather than on taste. Three sessions were live in that file's neighbours when this landed, and a ruling that needs its own argument reads better beside its own mechanism. The `CHECKS` array is unchanged as the single list, so nothing downstream learns a second place to look |
| **Refuse the directive in `apps/` only, exempting `packages/`** | A package is compiled into a deployable and the directive travels with it. `RI-09` exempts `packages/` because *"a package routes nothing on its own"*, which is true of a PATH and false of a directive: a directive in a shared component is an endpoint in every app that renders it |

### 7. `CI-07` GOES RED ON THIS BRANCH, IT WAS PREDICTED BEFORE IT WAS RUN, AND IT IS NOT MOVED

[ADR-095](ADR-095.md) section 6 re-ruled `CI-07`'s artifact to *"a `page`, `layout` or `route` file under `apps/*/src/app/`"*, and [STRATEGY section 4.1](../testing/STRATEGY.md)'s rule is that the day the artifact arrives *"the row is a finding until the stage is written"*. **Session 250 creates the first two.** The prediction was written down before the runner was invoked and the runner reproduced it exactly:

```
FAIL   CI-06/gate-inventory  (1)
       docs/testing/STRATEGY.md:190 CI-07: the artifact "a page, layout or route file under
       apps/*/src/app/" HAS ARRIVED (apps/portal/src/app/layout.tsx,
       apps/portal/src/app/page.tsx is an App Router file), so the row reopened on the
       commit that added it and the stage is not written
```

**Three ways out and only one is honest.**

| Way out | Available? |
|---|---|
| **Write the stage** | An implemented leg names a job in [`ci.yml`](../../.github/workflows/ci.yml), which has no build job today and is not in session 250's fence. **This is the repair and it is one commit for whoever holds that file** |
| **Re-rule the artifact one step further down the chain**, which is what [ADR-095](ADR-095.md) section 6 did | **Refused, and the reason is that [ADR-095](ADR-095.md)'s own reason has expired.** That entry could re-rule because the stage was genuinely unwritable: `next build` exited 1 with nothing to build. It exits 0 on this branch. A re-ruling today would be relaxing a register to keep it green, which [P4 section 11](../plans/P4-portal-and-site.md) rule 13 makes the same move as widening a fence |
| **Leave it a finding and say so** | **Taken.** The cell in [STRATEGY](../testing/STRATEGY.md) records the arrival, the date and the file, and keeps its waiting leg so the gate keeps reporting |

**`VG-2`'s chain does not expire here and `VG-10`'s does not either.** [ADR-080](ADR-080.md)'s rule is that a chain names its next LINK and expires when that link acquires an implemented leg. `CI-07` acquires none in this commit, so both rows are untouched, for the reason [ADR-095](ADR-095.md) section 7 gives about the analogous day. `VG-10` is additionally conjunctive and no bucket exists.

**`pnpm run verify` therefore exits 1 on this branch, on this finding alone.** Every other leg is green and the pull request lists them. A gate that fails on good news is the control working, and [ADR-073](ADR-073.md) section 8 calls this row *"the one an implementer is most likely to leave out, because it is the only one that fails on good news"*.

### 8. Founder approval

**One checkable clause, and it carries the direction it fails in.**

> **A file under `apps/portal/src/` whose first line is the Server Action directive, plus a `rewrites()` entry in [`apps/portal/next.config.mjs`](../../apps/portal/next.config.mjs) whose `source` is `/api/v1/admin/payouts`, takes `node packages/tooling/checks/repo-invariants.mjs` to exit 1 naming BOTH, while `pnpm run lint`, `tsc --noEmit` and `node scripts/corpus/gates.mjs check` stay exactly as they are on the clean tree.**

**Executed, both directions, and the outputs are pasted in the pull request.** The check was additionally watched: refusing prose that merely discusses the directive; reporting `/ops` only while `OPERATOR_PREFIXES` in [`apps/api/src/surface.ts`](../../apps/api/src/surface.ts) actually carries it, which proves the vocabulary is read rather than copied; and THROWING rather than passing when that list parses to nothing.

**The direction it fails in.** If the clause is wrong, this entry has built a control for a hole that was already shut, and the cost is a check that can never fire. **If it is right, which is what the run says, then the three lines in section 2 are a live operator endpoint on a public origin that every gate in this repository reports as clean**, and the failure is silent in exactly [ADR-095](ADR-095.md)'s words: the app builds, the route serves, every gate stays green, and the first evidence is an incident.

**What a founder read adds and this entry cannot.** Every fact above is a command's output, produced in this session rather than recalled. **Ruling 1 is not.** It refuses a framework feature outright, for both UI applications, for as long as the framework is admitted, on the argument that the conditional version is unimplementable. **Whether an unimplementable rule is better refused wholesale than left as a review convention is the judgement**, and section 5's first row is the whole of the case. It is the same trade [ADR-083](ADR-083.md) took when it made the API its own deployable rather than a habit inside the portal, and it is being taken here at a much smaller scale and for the identical reason.

**Approval line: UNSIGNED.**
