## ADR-121: "shipped source" for `RI-10` means the directories the node loader loads, and `scripts/` is one of them  (2026-08-27, status: proposed)

**[`RI-10`](../../packages/tooling/checks/repo-invariants.mjs) asserts that every relative import in shipped source names a file that exists, and it was scoped to `src/` under `apps/` and `packages/` on one stated sentence: *"Only `src/` is loaded by the runtime."*** That sentence was a considered decision rather than an oversight, and it is now visibly incomplete. `scripts/demo/` is loaded by the node loader too, and [`nightly.yml`](../../.github/workflows/nightly.yml) runs it as `CI-09`'s replay self-audit leg.

**The cost of the omission was measured before anything was ruled.** On `origin/main` at `421e52e`, `scripts/demo/` carried **19 broken specifiers across 5 non-test files**, `node --experimental-strip-types scripts/demo/main.ts` died with `ERR_MODULE_NOT_FOUND` on its own first relative import, and **every gate in this repository was green**, `RI-10` included, because `RI-10` was not looking there.

Rewriting the specifiers is transcription and needs no entry. **Widening a scope that was chosen on purpose is a ruling**, and that is what this one records.

- **Origin:** session **233**, `claude/scripts-specifier-sweep`. The number was **RESERVED BEFORE DISPATCH and CONDITIONAL** ([ALLOCATION](ALLOCATION.md)): reserved against the widening, not against the sweep. **Not a money path by subject.**

- **Context:** [ADR-119](ADR-119.md) section 6 left `CI-09`'s replay self-audit leg owed a workflow job; [session 231](../sessions/2026-08-26-session-231.md) landed it, and its own comment recorded the defect this entry closes: *"`scripts/demo/` carries 16 specifiers naming `.js` files that are `.ts` ... `RI-10` does not catch it because `RI-10` is scoped to `src/` and `scripts/` is not `src/`."* That comment reported the defect rather than repairing it, correctly, because it was written in a workflow file.

### 2. THE RULING

> **1. `RI-10`'s SCOPE IS THE DIRECTORIES THE NODE LOADER LOADS, AND THAT IS TWO POSITIVE TERMS: `src/` UNDER `apps/` OR `packages/`, AND EVERYTHING UNDER `scripts/`.** The earlier line was drawn at `src/` because `src/` is where the deployables live by [ADR-083](ADR-083.md), and on the day it was written that was the whole of the code the runtime loaded. `scripts/demo` became a second such place when [ADR-119](ADR-119.md) gave it a `BatchPorts` world and `nightly.yml` gave that world a job. **The scope did not become wrong; the tree grew past it.**
>
> **2. "SHIPPED SOURCE" MEANS *LOADED BY `node --experimental-strip-types`*, AND IT HAS NEVER MEANT *PUBLISHED*.** This is the clause a later session will need. `scripts/demo` ships to nobody and is covered anyway, because coverage follows the loader and not the distribution. The corollary binds in the other direction too: a future TypeScript file that no loader reaches is out of scope no matter where it sits, and putting it in `scripts/` does not admit it by itself.
>
> **3. THE `test/` SUBTRACTION IS THE OLD RULING PRESERVED, NOT A NEW EXCEPTION.** `RI-10`'s `covers` line already ruled tests out of scope, for two reasons that this widening does not touch: Vitest resolves the tolerant way, so a `.js` specifier in a test is not a runtime defect, and rule-test fixtures carry synthetic specifiers as DATA that no regex can tell from a statement. Under `src/` the subtraction held **for free**, because nothing under `src/` is a test. Under `scripts/` it has to be **written down**, because `scripts/demo/test/` is a sibling of the source rather than a sibling of `src/`. Writing down a rule that was previously free is not weakening it.
>
> **4. THE SUBTRACTION IS A DIRECTORY SEGMENT AND MAY NEVER BECOME A LIST OF NAMES.** `runtimeLoaded` subtracts the segment `test/` and names no package, no file and no area. **The day this check needs a second name in that subtraction is the day it is scoped wrong again**, and finding 9 is why that sentence is in the ruling rather than in a comment.
>
> **5. THE `src/` CLAUSE STAYS, AND REFUSING TO SIMPLIFY IT IS A DECISION.** Section 3.

---

### 3. Why the `src/` clause survives, which is the half that looks like dead weight

The obvious simplification is to delete the `src/` term and scan every non-`test/` TypeScript file under the three areas. One rule instead of two. Measured on this tree it finds **the same 19 findings and nothing else** (finding 8), so it costs nothing today.

**It costs something tomorrow, and the cost is already sitting on disk.** The two files it newly admits are `apps/portal/e2e/slop-score.spec.ts` and `apps/site/e2e/slop-score.spec.ts`. They are Playwright specs. They are tests. Ruling 3 puts tests out of scope, and Playwright, like Vitest, resolves the tolerant way, so a finding in either would be a false positive **against this entry's own ruling**.

Keeping them out under the simplified rule costs a second name in the subtraction: `test` **and** `e2e`. That is a subtraction list that grows by name, which is exactly what finding 9 says goes wrong. **The simplification does not remove an exception, it moves one from the positive side of the rule to the negative side, where it is harder to see and easier to extend.**

So the shape is: two positive terms, one subtraction, and the subtraction never grows.

---

### 4. `nightly.yml`'s line does NOT move, and the reason is not the one anybody expected

`nightly.yml` carried a standing instruction: *"WHEN THAT SWEEP LANDS, THIS LINE SHOULD MOVE TO THE `.ts` ENTRY."* This session is that sweep. **The line does not move.**

The instruction's premise was that the `.js` specifiers were the reason `CI-09`'s replay leg ran the `.mjs` wrapper rather than `seed-world.ts`. **Measured after the sweep, that premise was wrong.** `node --experimental-strip-types scripts/demo/seed-world.ts` now exits **0** and writes **zero bytes**: the file exports `main` and never invokes it. `seed-world.mjs` is what registers the resolve hook, wires `argv` and stdio, calls `main` and returns its exit code. Its own header said so all along, and `run.mjs` says it too: the wrapper is `.mjs` because *"the hook has to be registered BEFORE the first import that needs it, and an import is hoisted above every statement in its own module."*

**Moving the line would have traded a self-audit that reports for a module-graph load that cannot, and it would have gone GREEN doing it.** That is `FM-17`'s shape exactly, and `seed-world.ts`'s own error handling names it: *"an audit that declines to report must never look like one that found nothing."*

What changed in the file is the **comment only**: the `run:` line is byte-identical. The comment now records the measurement, because the sentence it used to carry (*"dies with ERR_MODULE_NOT_FOUND on this tree"*, *"16 specifiers"*) is false after this branch, and a stale true-sounding comment is the drift [ADR-034](ADR-034.md) exists to end.

### 5. The approval line

Executed rather than described, and it is two commands because the widening and the sweep are two claims:

```
node --experimental-strip-types scripts/demo/main.ts   # exit 0, where it died with ERR_MODULE_NOT_FOUND
node packages/tooling/checks/repo-invariants.mjs RI-10 # PASS on the swept tree
```

**And the check was watched FAILING before it was believed passing**, which is finding 10's lesson made procedural. Seeded live on the working tree, then restored:

- `scripts/demo/main.ts` made to name `./render.js` where `render.ts` is: **`FAIL RI-10 (1)`**, naming the file and the target.
- The same defect seeded inside `scripts/demo/test/`: **`PASS`**, because ruling 3 holds.

Both are test rows now, alongside a third that seeds a `scripts/` specifier naming a **genuine** `.js` file and demands silence. The seeded-violation row was confirmed to fail when the scope is reverted to `apps` and `packages`, so it is load-bearing rather than decorative.

### 6. Alternatives considered

- **Leave `RI-10` at `src/` and fix only the specifiers.** **Rejected.** It repairs the instance and leaves the class: the next file added to `scripts/demo` regains the defect silently, and the only symptom is a nightly job dying at startup.
- **Drop the `src/` clause and scan every non-`test/` TypeScript file.** **Rejected on measurement**, section 3. Same findings today, an `e2e` exception tomorrow.
- **Scope to `scripts/demo` specifically.** **Rejected as the exact shape finding 9 warns about**, one directory further down: a check that names the one directory that broke will be silent about the second one.
- **Extend the scope to `.mjs` files as well.** **Not reached, and deliberately so.** `RI-10` has never read `.mjs`, and the first thing a widening would meet is [`scripts/ci/falsify-ci.mjs`](../../scripts/ci/falsify-ci.mjs), whose seeded fixtures carry `import ... from './scoped-db.js'` **inside string literals**. That is the precise trap `RI-10`'s own second draft fell into. A later entry may take it; it needs a specifier reader that understands string context, which is a different piece of work from a scope line.
- **Add an "inspected zero files" guard, as `RI-09` carries.** **Not reached.** It would not buy what it looks like it buys here: `apps/` and `packages/` keep the count non-zero, so a `scripts/` that vanished or moved would still pass the guard. A guard that cannot fail on the thing it is aimed at is furniture. Stated as a known limit rather than built badly.
- **Move `nightly.yml`'s line to the `.ts` entry, as instructed.** **Rejected on measurement**, section 4. The instruction was written against a premise that the sweep itself disproved.

---

### 7. Consequences

- **`RI-10` now covers `scripts/`**, so a specifier naming a file that is not there turns `CI-01` red rather than waiting for a nightly job to die at startup.
- **`node --experimental-strip-types scripts/demo/main.ts` loads**, which it has not done since the directory was written. That says the module graph loads and says nothing about whether it behaves, which is what `RI-10`'s `covers` line has always claimed for a green result.
- **The `nightly.yml` standing instruction is retired and replaced with the measurement that retired it.** No workflow behaviour changes.
- **A latent finding is written down rather than fixed:** `.mjs` files are read by no specifier check in this repository, and `scripts/` is now the area where that gap is most visible, because it is the area whose executables are `.mjs` by design. Section 6 names what closing it would take.
- **`scripts/demo/test/` is covered by nothing**, by ruling 3, and that is the same posture every other test directory has. If a future session wants tests covered, it needs a different check and a different entry, not a wider `RI-10`.
