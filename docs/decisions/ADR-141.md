## ADR-141: a trader-scoped response that names a catalogue row is TWO reads in one direction, and the compiler already refuses the version of that mistake everybody looks for  (2026-08-27, status: proposed)

**[ALLOCATION](ALLOCATION.md) reserved this number CONDITIONALLY, against the case that the crossing between `firm` and `owned` "needs stating". It fires, and it fires for a reason the reservation did not anticipate: the blunt leak is a COMPILE ERROR, so the thing that needed stating is not the one the row was reserved against.** `GET /purchases` is the first request handler in `apps/api` that composes one response out of both doors [ADR-102](ADR-102.md) opened. This entry rules what that composition is allowed to look like, records the four measurements that decide it, and reports three contract-versus-schema findings the route surfaced and did not repair.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `141`, session **253**, dispatched as `claude/routes-catalog`. **NOT money path by content**; `purchases` is money-adjacent and carries four `bigint` cent columns to the wire, so `INV-02` is asserted at the boundary rather than assumed.

- **Context:** it runs after [ADR-106](ADR-106.md), which closed the scope vocabulary at five and made `ScopedTableKey` and `FirmTableKey` stop partitioning `TableKey`; after [ADR-112](ADR-112.md), which gave the accessor an ADDRESS; and after [ADR-120](ADR-120.md), which admitted `apps/api` to `DB_ADMITTED` and built the two doors this entry uses. It needs no widening of `SystemReason` or `SqlExecutorReason` and takes none.

### 2. THE RULING

> **1. A TRADER-SCOPED RESPONSE THAT NAMES A CATALOGUE ROW READS THE SCOPED SIDE FIRST, AND THE FIRM READ TAKES THE SCOPED RESULT AS ITS ARGUMENT.** The set of catalogue rows a response may name is derived from rows the tenancy predicate already returned, and from nothing else. In [`catalog.ts`](../../apps/api/src/routes/catalog.ts) that is `plansOfVersions(planVersionIds)`: it can annotate what the scoped read returned and it has no shape in which to widen it. **A firm method that returns rows a scoped read did not ask about, on a trader surface, is refused by this clause even where no type objects.**
>
> **2. THE TWO HALVES ARE TWO INTERFACES, AND THAT IS A SECOND GUARD RATHER THAN THE ONLY ONE.** `CatalogFirmReads` and `CatalogScopedReads` are separate, so a handler holding the firm half has no method that reaches a purchase. **Finding 2 is why this is not load bearing on its own**: the accessor refuses `firmTx.rows('purchases')` at compile time already. The split is kept because it shuts the door one layer earlier, where a reviewer reads a port rather than a key type.
>
> **3. THE RESPONSE IS NOT A SNAPSHOT AND THE FIELDS IT CROSSES WITH MUST BE IMMUTABLE ONES.** `ApiDb` hands each unit of work to `transaction()`, so the scoped read COMMITS before the firm read opens. `GET /purchases` survives that on exactly `plans.code` and `plan_versions.version`, and it survives by finding 8 -- a trigger in another package -- rather than by anything the handler does. **A later slice crossing on a MOVABLE catalogue field does not inherit this argument and owes its own**, and the two candidates are named: `status` and `retired_at` are the two `plan_versions` columns `0028` deliberately leaves movable.
>
> **4. NEITHER `SystemReason` NOR `SqlExecutorReason` IS WIDENED, AND THE COST OF THAT IS PAID IN MEMORY AND STATED.** `GET /purchases` reads EVERY purchase of the caller and applies order, cursor and limit in the handler, because finding 5 leaves no other shape. Each page is `O(all of this identity's purchases)`. **Nothing here is a tenancy control**: the accessor narrowed the set before the handler saw a row, so the paging cannot leak and can only be slow. It is bounded in practice by `limits.max_accounts_per_entity` and by nothing the database enforces. **The keyset predicate is owed to `packages/db` as a ruling, not to this file as a workaround.**
>
> **5. A CATALOGUE ROW WHOSE SHAPE THE CONTRACT CANNOT DESCRIBE IS A REFUSAL, NOT AN OMISSION.** Two plan versions on sale for one plan (finding 3), a `plans.code` outside section 4's closed set, a cap schedule not starting at ordinal 1, a version with no `published_at`: each raises and becomes a `500`. **The alternative is dropping the row, and on `GET /plans` that publishes a pricing page missing a plan that is still purchasable**, which is a worse failure than a loud one and a silent one besides.
>
> **6. THE ALLOWLIST IS THE ONLY THING WITHHOLDING FIRM-INTERNAL TEXT FROM A PUBLIC READ, AND NO SCOPE CLASS WAS EVER GOING TO HELP.** `simulation_waiver_reason` is free text an operator wrote about Merit's own publish decision, on a table `GET /plans/:planId/versions/:version` serves to anybody with a socket. It is firm-internal rather than identity-shaped, so it is correctly `firm` and correctly invisible to every scope predicate. [API_CONTRACT section 1](../architecture/API_CONTRACT.md)'s response-shape policy is the whole control, which is [ADR-106](ADR-106.md) section 4's *"a scoped read is a FILTER and not a PROJECTION"* arriving from the other side.

### 3. Clause 1, and why the direction is the ruling when the type is not

**The reservation was written against the fear that a `plans` read might return something identity-specific.** Finding 6 went looking and it does not: the three `ALTER`-added columns on `plan_versions` reach a simulation run, a boolean and a text field, and none reaches `identities`. So the classification is correct and the [ADR-102](ADR-102.md) section 7 blind spot does not bite here.

**And finding 2 says the reciprocal fear is also unfounded.** `firmDb()` cannot read a purchase. The key types refuse it, at a call site in a different package, with an error naming `FirmTableKey`. Anybody arriving at this file expecting to find a convention holding the line finds a compiler instead.

**WHAT IS ACTUALLY LEFT IS TWO THINGS AND THEY ARE SMALLER AND HARDER TO SEE.**

**(a) Which identity the scoped door is opened with.** `ApiDb.scoped(identityId, fn)` takes a `string`. `session.identityId`, a path parameter and a query parameter are the same type, and [`db.ts`](../../apps/api/src/db.ts)'s guard checks that the value is a UUID rather than that it is the caller's. The control is that there is exactly ONE call site and it is inside `withSessionContext`, and that is a property of a file rather than of a signature.

**(b) Whether the firm read was keyed by the scoped result.** Both reads are legal on their own. A handler that read the whole catalogue and then joined in memory would compile, pass every type check, and return a correct response; it would also mean the SIZE of the firm read stopped being a function of what the caller owns. That is not a leak today and it is the shape a leak grows out of, because the next hand adds a filter to the wrong side of the join. **`plansOfVersions(ids)` takes the ids as a parameter so that the wrong side has nowhere to put one.**

### 4. Three contract-versus-schema findings, reported and not repaired

**All three edit an `approved` document to fix, which is an ADR against [API_CONTRACT](../architecture/API_CONTRACT.md) rather than this one.** The route renders each faithfully and says so at the site.

| # | Finding | Where |
|---|---|---|
| **F-1** | **`payout_cap_cents` FLATTENS A SCHEDULE THE SCHEMA RESERVED AS AN ARRAY.** [`API_CONTRACT:272`](../architecture/API_CONTRACT.md) declares a scalar; [`0004:168`](../../packages/db/migrations/0004_catalog.sql) declares `payout_cap_schedule_cents jsonb` and DATA_MODEL section 12 rows the array as buying *"progressive cap release (M14)"*. **The endpoint cannot express a second rung**, so the day M14 publishes one this response is WRONG rather than incomplete. The route reports the rung at `from_ordinal = 1`, selected by ordinal and never by position, and refuses a schedule that does not start there | `renderSize` / `capAtFirstOrdinal` |
| **F-2** | **`min_payout_cents` IS NOT A COLUMN OF `plan_version_sizes` AND IS NOT PER-SIZE.** It is `plan_versions.rules.phase_funded.min_payout_cents` (DATA_MODEL section 11), a per-VERSION value, and section 4 places it one level below where it lives. Every size of one version therefore carries the same number, which is faithful rather than wrong | `minPayoutCentsOf` |
| **F-3** | **`PlanSize` AND `PlanRules` ARE NAMED IN API_CONTRACT AND DECLARED NOWHERE IN IT.** [`:288`](../architecture/API_CONTRACT.md) writes `sizes: PlanSize[]` and [`:286`](../architecture/API_CONTRACT.md) writes `rules: PlanRules`; `grep -n "type PlanSize\|type PlanRules" docs/architecture/API_CONTRACT.md` returns nothing. Read as the document supports it, both size shapes are one shape and `rules` is the stored jsonb verbatim, which is what the route does | `PlanSizeView`, `PlanVersionResponse.rules` |

**A FOURTH IS RECORDED HERE BECAUSE IT IS A SCHEMA FACT RATHER THAN A CONTRACT ONE.** `plan_versions_published_has_timestamp` and `plan_versions_retired_has_timestamp` ([`0004:106`](../../packages/db/migrations/0004_catalog.sql), [`:109`](../../packages/db/migrations/0004_catalog.sql)) are independent, so `retired` does NOT imply `published_at IS NOT NULL`: a draft retired without ever being published is storable, and section 4 declares `published_at: string` with no null. The route refuses one rather than inventing a date.

### 5. What is FORECLOSED

1. **`GET /purchases` will never read `purchases` through `firmDb()`**, and that is a compile error rather than a rule (finding 2).
2. **A route file in `apps/api` will not import `@merit/db`.** [`db.ts`](../../apps/api/src/db.ts) stays the one file that names it, and the table keys travel as plain strings the accessor's own key types check.
3. **A cursor will not be implemented by widening `SqlExecutorReason` to run raw SQL from a request handler.** Clause 4 makes the in-memory page the ruled position until `packages/db` grows a keyset predicate, and the day it does, this handler loses code rather than gaining it.
4. **A public catalogue read will not resolve a session.** The two `Auth: none` routes are bare handlers, so a stale cookie cannot turn a cacheable read into a `503` and cannot cost an auth transaction. That is `public-methods.ts`' shape and this entry makes it the rule for the class rather than a choice one file made twice.
5. **A `plans` response will not name a plan the contract's `code` union cannot spell** (clause 5), which means a fourth plan code is a schema change AND a contract change, in that order.

### 6. Alternatives considered

**Serve `plan` on a purchase from the purchase row alone.** Refused because there is nothing to serve: `purchases` carries `plan_version_id` and no code and no version number ([`0006:105`](../../packages/db/migrations/0006_commerce.sql)). The crossing is not a design choice, it is what section 5's shape requires.

**Denormalise `code` and `version` onto `purchases` at checkout, so the read crosses nothing.** It removes the crossing and buys the classic defect back: two copies of a fact, one of them stale the day a version is retired. It is also a migration, and `0048` is not this session's.

**Register the three catalogue tables `derived` through something, so a trader-scoped read reaches them in one door.** Refused by `scope.ts` in advance and in writing, at [`:449`](../../packages/db/src/scope.ts): *"A `derived` rule through `plan_versions` is not a milder mistake, it THROWS ... a firm parent makes the whole chain firm rather than making the child derivable."*

**Take the ADR-141 reservation and record NOTHING, on the ground that the compiler already refuses the leak.** This was the closest call in the entry. It is refused because finding 2 is exactly the kind of fact a later session assumes rather than measures, and because what the compiler refuses and what clause 1 refuses are different sets: the compiler stops an unscoped purchase read, and clause 1 stops a scoped one annotated from an unbounded firm read. **An entry that says "the type system has this" is worth more than no entry, because the next slice that needs the other half will read it.**

### 7. Consequences

- **Three of API_CONTRACT's endpoints exist that did not.** `apps/api` composes **26** routes across **9** modules, up from 23 across 8.
- **`ADR-141` is `proposed` and the route is merged behind it**, on this estate's ordinary order: the code carries the ruling's reasoning at the site and the entry carries the citations.
- **Findings F-1, F-2, F-3 and the `published_at` one are OPEN** and each needs an [API_CONTRACT](../architecture/API_CONTRACT.md) amendment or a schema change. None blocks the routes.
- **The keyset predicate is owed to `packages/db`.** Clause 4 is the position until it lands.
- **The dispatch's own citations did not all reproduce, and that is recorded rather than smoothed over.** See section 9.

### 8. Approval clause: the seeds, and what each must turn red

Each was run, watched failing, and restored; `git status --porcelain` reported clean after every one.

> **1. THE LEAK ITSELF.** Replace `db.scoped(identityId, ...)` with `db.firm(...)` in `databaseCatalogReads`. **`pnpm -r --filter @merit/api run typecheck` must report `TS2345` naming `FirmTableKey`, twice**, and `pnpm vitest run apps/api/test/catalog.test.ts` must go **RED on five cases**, among them *"a purchases read scoped to A returns ZERO of Bs rows"*. Observed: exactly that, `5 failed | 25 passed`.
>
> **2. THE ALLOWLIST.** Spread the raw row into `renderPlanVersion`'s return. **Two cases must go RED**, one of them *"the firm-internal ALTER columns never reach the wire"*. Observed: `2 failed | 28 passed`.
>
> **3. THE CAP RUNG READ BY POSITION.** Make `capAtFirstOrdinal` take the first element instead of the lowest ordinal. **One case must go RED.** Observed: `1 failed | 29 passed`.
>
> **4. AGAINST A REAL POSTGRESQL, WHICH IS THE HALF A FAKE CANNOT DO.** A PostgreSQL 16 cluster with all **47** migrations applied and a two-identity fixture, `apps/api` started against it with `MERIT_API_SURFACE=public`, hit over a socket. **Alice's `GET /purchases` must return exactly her two rows and Bob's exactly his one, in both directions**; **Bob replaying Alice's `next_cursor` must reach only Bob's own row**; and `plan_versions.simulation_waiver_reason`, seeded with real operator text, **must not appear in the version response**. Observed: all four. This is the assertion `db-recorder.ts` says it must never make, made where it can be made honestly.
