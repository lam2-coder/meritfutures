## ADR-303: the catalogue door returns the row `schema.ts` declares, and every refusal it had it still has  (2026-09-03, status: proposed)

**Row `303` builds [ADR-299](ADR-299.md) ruling 1.** `catalogRows`, `catalogRowsWhere` and `catalogRowAt` on `ScopedTx` return `CatalogRow<K>`, derived from `TABLES[K]` and therefore from `schema.ts`, instead of `unknown`. **The `unknown` was inherited rather than ruled** and the door has never had a production caller, so this is the last moment its shape can be chosen by the row that needs it.

**THE STOP CONDITION WAS TWO-SIDED AND THE SECOND SIDE IS THE ONE THAT WAS AT RISK.** A typed return that cost one refusal would be a regression wearing a type. **The refusal inventory of [`catalog-read.test.ts`](../../packages/db/test/catalog-read.test.ts) was derived from the file BEFORE the first edit, re-derived from it after, and compared as sets: the after set is a STRICT SUPERSET and nothing was lost.** Section 3 states the derivation so it can be re-run rather than believed.

**NO TEST WAS DELETED, SKIPPED, RELAXED, RENAMED OR RETARGETED.** Twenty cases existed and twenty pass unchanged; **three were added** and none of the three replaces one above it. The guard order inside all three verbs is untouched: `refuseUncatalogued` is still the first statement of each, and `refuseUnaddressed` still runs before `catalogRowAt` builds anything.

**AND THE TYPE HALF IS CHECKED BY `tsc` RATHER THAN ASSERTED IN PROSE.** `packages/db/tsconfig.json` includes `test/**/*.ts`, so the type cases in the suite are compiled by `pnpm run typecheck` and a case that stops holding is a `TS2344` in this package. **Three of them were watched RED** before being written back.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `303`, session **496**, branch `claude/the-door-has-no-caller`, off `6f0efab`.

### 4. The type half, and why it is compiled rather than run

**VITEST CANNOT SEE ANY OF IT AND THE FILE SAYS SO.** [`catalog-read.test.ts`](../../packages/db/test/catalog-read.test.ts)'s own header already records the general form of this: the compile-time half of a refusal is watched failing to compile, because vitest "runs transpiled code and a type error is simply gone by then". **What is new is that this package's `tsconfig.json` includes `test/**/*.ts`**, so `pnpm run typecheck` compiles the suite and a type case can live beside the runtime ones rather than in `scripts/ci/`.

**THE CASES, AND THE ONES WATCHED RED.**

| Case | Asserts | Watched RED |
| --- | --- | --- |
| `TheRowIsTheDeclaredRow` | `sizeCents` is `bigint`; `priceCents` is `bigint`; `profitTargetCents` keeps its `null`; an invented key is not `keyof` the row; the row is neither `unknown` nor `any` | **YES**, on `sizeCents` retyped to `string`: `TS2344` |
| `TheBlobIsStillUnknown` | `payoutCapScheduleCents` is `unknown` on the typed row | **YES**, on `string`: `TS2344` |
| `TheScopedVerbsStillReturnUnknown` | `rows`, `rowsWhere`, `rowAt` and `lockAt` still return `unknown` | **YES**, on `string[]`: `TS2344` |
| `TheAddressedReadCanBeAbsent` | `undefined` is in `catalogRowAt`'s return | Not seeded; it is an `extends` over a type the same diff wrote |
| `theVerbsHandBackDeclaredRows` | All three verbs assign to declared row types at a call site, and `one?.sizeCents` is a `bigint` without a cast | Not seeded; `unknown` refuses every assignment in it, which is the pre-change state |

**`Same<A, B>` IS THE CONDITIONAL-IDENTITY FORM AND NOT MUTUAL ASSIGNABILITY, AND THAT IS NOT FASTIDIOUSNESS.** `any` is assignable in both directions, so a two-sided `extends` check would pass silently on a return type that had decayed to `any`. The failure this section exists to catch is a return that has stopped being a row, and `any` is one of the two ways it could stop. **The other is `unknown`, and both are asserted absent by name.**

**THE CASES ARE BOUND TO A VALUE RATHER THAN LEFT AS FREE ALIASES.** A type alias nothing references is an ESLint error in this repository, and prefixing each name with `_` to buy silence would leave the cases invisible to a reader running the suite. `ADR_303_TYPE_CASES` is a tuple of `true` typed by the four aliases, and one runtime case asserts it holds no `false`. **A case that stops holding fails `pnpm run typecheck` and that runtime line never runs.**

### 10. Where this entry is most likely wrong

**THE STRONGEST OBJECTION IS [ADR-299](ADR-299.md) SECTION 12's AND IT IS NOT ANSWERED HERE.** Every money defect this area has actually produced is inside the `jsonb`: the rounded cap, the refused string. **Not one is a mistyped property key**, which is the failure this row buys a compiler against. A reviewer may hold that the row-level reads were fine and the door should have been left alone. The defence is unchanged: the absence of a failure in a surface with no callers is not evidence, and this was the last moment the shape could be chosen by the row that needs it. **What this row adds to that defence is a measurement rather than an argument: the change cost zero refusals and three commands' worth of citation repair.**

**THE SECOND IS THAT `$inferSelect` IS DRIZZLE'S NAME AND NOT MERIT'S.** `CatalogRow` is one line and it depends on a property of the ORM's table type.
