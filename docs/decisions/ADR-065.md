## ADR-065: one key, one row, and the letter registry has run out of alphabet  (2026-08-20, status: proposed)

**This rules the shape of [ALLOCATION](ALLOCATION.md), the registry every other number in this corpus is drawn from.** It is not a cleanup ruling with a cleanup attached: three of its five sections rule on defects that the cleanup cannot reach, and one of them says the naming scheme this registry was built on is finished.

- **Context:** **Twenty keys head two rows each.** Thirteen in the ADR table, two in the migration table, five in the letter table. **Eighteen of the twenty are on `CI-06u`'s register** as accepted duplicates; the other two, `r` and `u`, are invisible to every gate in the runner for a reason that is itself the second finding.

  **Four blank lines sit inside the letter table**, at `:164`, `:167`, `:170` and `:173`. `markdownTables()` builds a table from a **maximal run of consecutive pipe lines** and keeps the run only if it carries a delimiter row. So the letter table is **five runs, and only the first carries the delimiter**. The other four hold **nine rows that no table gate reads** and that render as prose in every viewer. `CI-06p`, `CI-06f`, `CI-06h` and `CI-06u` all read this file, and all four are blind to those nine rows.

  [WAVE-01 section 4](../plans/WAVE-01-post-freeze-parallel-sessions.md)'s **R1** planned this work as session 70, **last and alone**, and **it never ran**: there is no session-70 log. Its decision rule survives and is section 1 below. Its enumeration does not: it named `039` to `046` and `0033`/`0034`, and the register has since grown `050`, `054`, `055`, `057` and `059`.

---

### 1. T1, the shape: one key, one row

**A key heads exactly one row of its table.** R1 stated the tiebreak and it is adopted unchanged: *the row recording the merge is the durable fact and the branch row is the claim it superseded; keep one row carrying both, and do not silently drop the branch row's reasoning where it says something the merge row does not.*

**The branch rows are not redundant and that is why this is a merge rather than a delete.** On `039` through `043` the merged row carries the PR number and **the branch row carries the plan link** -- `FOLD-01`, `FOLD-02`, the `S-E` session -- which the merged row dropped. Keeping only the merge row would lose the one clause a reader actually navigates by.

### 2. T2, the parser's contract: no blank line inside a table

**A blank line inside a markdown table does not divide it visually and does divide it mechanically.** Every gate that reads a table in this corpus reads it through `markdownTables()`, and a run without a delimiter row is discarded silently -- not reported, not counted, not skipped-with-a-note. **Nine rows have been outside every gate's reach for as long as the blanks have been there**, and two duplicate claims hid in them.

**The rule is that a table is one run of pipe lines.** If a table wants a visual break, the break belongs in a cell or in prose between two tables that each carry their own header and delimiter.

**This is not a lint preference; it is the difference between a registry and a rendering.** `CI-06v` is reserved for the executable form of it ([WAVE-03](../plans/WAVE-03-duplicate-registry-keys.md) session S7) and this ADR is the ruling that gate implements.

### 3. T3, the cause: a landed reservation is an amendment, not a new row

**Fifteen of the twenty duplicates are one shape**, and it is the shape [ADR-034](ADR-034.md) deleted growing back one level up. ADR-034 removed a `State` column because a state written beside a fact drifts from it. **The State column came back as a second row**: a reservation row saying *reserved, unwritten*, and later a second row saying *merged, here is the link*, both heading the same number.

> **When a reserved number's artifact lands, the reservation row is AMENDED IN PLACE.** The row gains the link and loses the word *reserved*. A second row is never added.

**And the reason the second row kept getting added is stated here because it is a real constraint rather than carelessness.** `CI-06a` fails on a link to a document that does not exist, so a reservation **cannot** carry its own link. The author who later lands the file finds an unlinked row, cannot tell whether editing it is theirs to do, and appends. **The remedy is in this rule, not in a gate**: the row is the reservation's, and the session that lands the artifact is the session that links it.

**Seven rows are linked by this ruling's application**: `055`, `056`, `057`, `059`, `060`, `061` and the ADR-049 row's provenance clause.

### 4. The `u` collision, and the displaced gate gets no letter

**Two different gates claim `u`, and there is a third claimant that is not a third gate.**

| Claimant | What it is | Ruling |
|---|---|---|
| `:172`, `claude/test-2r6zai` | **`CI-06u`, the table-key gate. Shipped in PR #112 and on `main` today** | **Keeps `u`** |
| `:174`, [session 75](../sessions/2026-08-19-session-75.md) | `CI-06u`, [ADR-059](ADR-059.md)'s **M01-column gate**. Reserved, unwritten | **Displaced. No letter** |
| [PR #114](https://github.com/lam2-coder/meritfutures/pull/114) | A **different implementation of the same gate**, branched before #112 merged | **Not a separate claim.** See 4.1 |

**The shipped artifact keeps the letter.** [ADR-034](ADR-034.md)'s tiebreak renumbers the branch citing the number least, and one of these two is a gate that runs on every pull request while the other is a sentence.

**THE DISPLACED GATE IS DELIBERATELY LEFT WITH NO LETTER, AND THAT IS A RULING RATHER THAN AN OVERSIGHT.** ADR-034 rules that the claim precedes the artifact, so the ordinary remedy is to reserve it the next free letter. **Section 5 is why that is not available**, and giving it one anyway would be this ADR spending the registry's last allocation on an unwritten gate in the same document that rules the registry is out of room. It is recorded as unlettered and it is not lost: [ADR-059](ADR-059.md) still specifies it.

#### 4.1 PR #114, and the recommendation is neither "merge it" nor "close it"

**It is a different design for one letter, and the review desk was right to route it here rather than close it as a duplicate.** Both surveys ran independently and **both found the same two worst defects** -- `G-ELIGIBLE` defined twice with contradictory predicates on the payout path, and `M05`'s `INV-M5-17/18/19` each meaning two things. That corroboration is worth more than either gate.

|  | **#112, merged** | **#114, open** |
|---|---|---|
| Scope | by first-column **header**: `DIMENSION_HEADERS`, six hand-argued entries | by first-cell **shape**: is it a corpus identifier or a document link |
| Survivors | 106, **registered** per `(file, key)` | 78, **ratcheted** per file |
| Decay | register shrinks only | count may shrink, never grow |

**Each catches what the other cannot, and that is the finding rather than the tiebreak.** #112 catches `STATE.md`'s P1 table, where `**CI-06, corpus integrity**` heads four rows saying `22` and `Eleven`; #114 cannot, because a duplicated **label** is not an identifier and #114's own body says so. #114 needs no exemption list, while #112's own comment concedes that *"the cheapest way to make this gate quiet is to widen `DIMENSION_HEADERS` until it stops matching anything."*

**And one asymmetry decides the direction.** #112's register currently exempts `g-eligible` -- **a live money-path contradiction, two definitions with opposite identity clauses both citing [ADR-041](ADR-041.md)** -- because a file-level entry was the only tool it had. #114's scope would still fire on it. **A defect parked in an exemption list is a defect the ratchet has stopped ratcheting on.**

> **RECOMMENDED: adopt #114's SCOPE RULE into the shipped gate and keep #112's register for the label class only.** They are complementary rather than exclusive. Scoping by first-cell shape removes the false positives that forced the six `DIMENSION_HEADERS` entries, which lets the register shrink to the one class neither scope can express. **Do not merge #114 as it stands**: `mergeable_state` is `dirty`, it branched before #112, and a keep-both merge yields **two gates with `id: 'CI-06u'` in one runner**, which `CI-06p` cannot see because it builds `implemented` as a `Set` and two identical ids collapse to one member. That is `OI-11` at the runner level, and `CI-06w` is reserved for exactly that class.

**This is a recommendation and not a ruling**, because it is an implementation decision in the gates lane and this session holds no part of that fence.

### 5. `CI-06<letter>` was the wrong shape for an open-ended registry, and it is now empty

**Measured rather than asserted, on this tree:** `a` through `w` are claimed. [`nextFreeLetter()`](../../scripts/corpus/falsify.mjs) scans `a` to `x` only and throws `seed anchor exhausted` when all are claimed. **`x` is the only free letter, and it is not free.** The `CI-06p` seed takes `nextFreeLetter()` and writes a row claiming **two past it**, so one seed consumes `free`, `free+1` and `free+2`. With `free = x` that is `x`, `y`, `z`.

> **There are zero allocatable letters. The next gate to claim one breaks the falsification harness for `CI-06p`**, which is the gate that guards this very table.

**`x` is therefore reserved to the harness and no row may claim it.** That is the operative rule this ADR adds today.

**The scheme's three failure modes have all now been observed, which is the argument that this is structural rather than bad luck:**

| Failure | Where it happened |
|---|---|
| **Exhaustion** | `a` to `w` claimed in about one week |
| **Collision** | `u` claimed twice, section 4, because a one-character namespace makes claims cheap and near-simultaneous |
| **Opacity** | `CI-06o` names nothing. A reader must consult a registry to learn what a gate checks, **which is the only reason the letter table exists**, and it is the table this ADR is repairing |

**The ruling: the successor identifier is a slug, not a letter.** `CI-06/model-ban` rather than `CI-06o`. A slug is self-describing, so no registry row is needed to decode it; it is unbounded, so it cannot exhaust; and two gates collide only when they claim the same **subject**, which is a real conflict worth surfacing rather than an accident of alphabet.

**This ADR does not perform that migration and must not.** It touches every gate id, `STRATEGY` section 4.4, `nextFreeLetter()`, `CI-06p`'s parser and every citation in the corpus. **It is named here as its own session with a stated precondition**: it must land before any twenty-fourth gate is written, because there is no letter for one.

### 6. What this amends

| Where | From | To |
|---|---|---|
| [ALLOCATION](ALLOCATION.md), all three tables | Twenty keys heading two rows | One row per key, merged per section 1 |
| ALLOCATION's letter table | Five runs split by four blank lines, nine rows unread | One run, no blank lines |
| [`gates.mjs`](../../scripts/corpus/gates.mjs)'s `CI06U_REGISTER` | `docs/decisions/ALLOCATION.md` with eighteen keys | **The entry is removed entirely** |
| `gates.mjs`'s register comment on `r` | "the two rows are byte-identical but for one link, so the dedupe reached it" | **False.** The two rows differ by a clause, and `r` is absent because the two rows sit in **different unparsed fragments** and were never compared |

- **Alternatives considered.**

  - **Delete the branch rows.** Rejected: on `039` to `043` the branch row carries the plan link the merge row does not, so a delete loses the clause a reader navigates by.
  - **Keep the blank lines and teach `markdownTables()` to bridge them.** Rejected, and it is the tempting one. A parser that bridges blanks makes two adjacent tables in one section into one table, which is a false-positive generator on every document that has them. **The document is wrong here, not the parser.**
  - **Give the displaced M01-column gate the letter `x`.** Rejected in section 5: it is the harness's headroom, and spending it on an unwritten gate inside the ADR that rules the registry is exhausted would be the clearest possible instance of the problem.
  - **Extend `nextFreeLetter()` to `z` to buy three more.** Rejected. It buys one gate and one week, removes the harness's headroom, and the exhaustion is the symptom rather than the defect.
  - **A second letter, `CI-06aa`.** Rejected: it keeps every failure mode in section 5 and adds ambiguity about whether `aa` sorts after `z`.

- **Consequences:**

  - **`0034` keeps its history and loses its second row, and this is the one merge that needed checking rather than sweeping.** It is a **real historical collision**: [ADR-047](ADR-047.md) claimed it for `rule_states`' calendar revision and `ADR-046` claimed it for the reversible contact addresses, wrote the file and merged. **Nothing is erased, because the history lives in two other places that both stay**: the `### 0034 was claimed twice` heading, and the `0035` row where ADR-047's subject actually landed as [`0035_rule_states_calendar_revision.sql`](../../packages/db/migrations/0035_rule_states_calendar_revision.sql). The surviving row names the file on disk and points at both.
  - **`046` is a SECOND collision of that kind and no record named it as one.** Its two rows carry **different subjects**: `OQ-P2-01`'s `CalendarSlice` ruling and `OQ-M10-06`'s reversible contact addresses. The first was renumbered to [ADR-049](ADR-049.md) and the `049` row already says "written as `046` and moved here". **The register filed `046` with the fifteen reservation-plus-merge pairs, and it is not one of them.** Its first claimant's provenance is carried into the `049` row rather than deleted.
  - **`CI-06u`'s register loses its largest entry**, eighteen keys of twenty-two per its own count, and the gate then reads this file with no exemption at all. That is the ratchet doing what it was built for.
  - **`CI-06v` and `CI-06w` are unaffected.** Both are reserved against WAVE-03 sessions and neither is written; section 5 does not retract a reservation that already exists, it stops new ones.
  - **The letter migration is owed and unscheduled.** Section 5 rules the direction and names the precondition. Until it lands, **no twenty-fourth gate can be written**, and that is a real constraint on the gates lane rather than a note.

- **Founder approval: PENDING.** This rules the shape of the registry every number in the corpus is drawn from, retires the naming scheme twenty-three gates already use, and leaves a specified gate deliberately unlettered. It is not taken on a session's authority ([E2](../../MERIT_BUILD_MASTER_PROMPT.md)). **Recommended for acceptance.**
