## ADR-253: a table the registry cannot name, and the ruling ADR-106 said was owed turns out to be a REFUSAL (2026-08-29, status: proposed)

**Row `253` sent one session at `useAffiliateDeps`' two obstructions, both of which the entry called registry-shaped, and asked for a ruling on each before any DDL. Neither is what it was called. The first is not one registration away, it is a SEVENTH SCOPE CLASS away, and the class that would make it compile today is a lie that every mechanical check in this repository accepts. The second is not registry-shaped at all: no table is owed, and the reason is arithmetic over a UNIQUE index rather than a preference about modelling.**

**NOTHING IS REGISTERED. `packages/db/src/scope.ts` and `packages/db/src/schema.ts` are not edited.** Row `253` granted two registrations and its own escape clause, in its own words: *"IF NO MEMBER OF THE CLOSED CLASS SET HONESTLY FITS, SAY SO AND LEAVE THE PORT BLOCKED."* That clause fires on the first obstruction and the second turns out not to need a table.

**NO MIGRATION NUMBER IS SPENT.** `0074` was the next free number when this branch was cut and was reserved conditionally; the condition did not fire and it returns to the pool, which is row `241`'s move one wave earlier and for the same reason.

**WHAT IS BUILT IS A CONTROL, AND IT IS THE ONLY THING HERE THAT CHANGES WHAT CI REFUSES.** Section 4. The mistake this session was most likely to make is the mistake the tree could not catch, so the mistake is what got a gate.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `253`, session **443**, dispatched as `claude/the-commission-with-no-owner`. The row is **CONDITIONAL** on ruling, and both conditions are ruled.

- **REVENUE PATH BY SUBJECT AND NOT BY DIFF.** `affiliate_commissions.amount_cents` is integer cents and signed, and a wrong tenancy rule on it shows one affiliate what another is owed. **No executable money line lands here**: no migration, no DDL, no ledger account, no arithmetic over cents, and no float anywhere. What changes under `apps/api/src` is the text of four refusals, each of which continues to refuse. The row does not claim an `E2` read and none is owed.

- **WHAT IS MEASURED, WHAT IS DERIVED, AND WHAT IS JUDGED.** That the table is created by `0012` and declared nowhere, that it declares zero columns against `identities(id)` and exactly three foreign keys, that `firm` compiles and passes `tsc` and passes the suite's own firm assertion, that no relation registered `firm` today has a required edge to an identity-reaching parent, that `affiliate_clicks.click_token` is UNIQUE and defaulted per row, that no migration declares a `campaign` column, and that nothing under `apps/api/src` writes an `affiliate_clicks` row, is **MEASURED**, by executing it. That a chain through `attributions` does not terminate is **DERIVED** from `scoped-db.test.ts`'s own stated rule at the class each hop carries. What is **JUDGED** is that `firm` is FALSE here rather than merely unproven (section 2 clause 6), that an issued link is not an object this schema models (section 3), and that a seventh class is a slice with its own row rather than this one's to write (section 6).

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every citation the row carried was re-derived. **One did not survive and one clause of the row is wider than the tree supports**; section 7 carries both.

### 2. The first ruling: no member of the closed six honestly fits, and the registration is REFUSED

[`packages/db/test/affiliate-commissions-unregistrable.test.ts`](../../packages/db/test/affiliate-commissions-unregistrable.test.ts) is the enumeration, executed. It reads the migrations rather than `schema.ts`, because the subject of every claim is a table `schema.ts` does not contain.

> **1. `root` IS `identities`' ALONE.** Asserted where it lives, over the registry, rather than asserted about this table.
>
> **2. `owned`, `pair` AND `either` ARE REFUSED BY ONE MEASUREMENT.** The row declares **zero** columns against `identities(id)` and zero against `accounts(id)`. `owned` names one identity column, `pair` names two, `either` names one beside an account edge. There is nothing for any of the three to name, and this is the DDL answering rather than a judgement, which is `reserve_coverage_snapshots`' and `operators`' ground.
>
> **3. THE ROW DECLARES THREE EDGES AND EVERY ONE REFUSES `derived`.** The set is asserted by NAME, so a fourth edge added tomorrow re-opens this enumeration in the diff instead of being silently outgrown.
>
> **4. `attribution_id` IS THE EDGE `scope.ts` ALREADY ARGUES WITH, AND THE ARGUMENT HOLDS.** It is `uuid NOT NULL REFERENCES attributions(id)`, `attributions` is registered `pair`, and `scoped-db.test.ts`'s own rule is that a chain terminates at `owned` or at `root`. `pair` is neither. **The parent is not a table with no identity on it: it carries TWO**, `buyer_identity_id` and `affiliate_identity_id`, both `NOT NULL`, and that distinction is what makes the seventh class a real question rather than a dead end. See section 6.
>
> **5. `paid_in_statement_id` IS THE PLAUSIBLE MISTAKE, BECAUSE THE CHAIN THROUGH IT WOULD ACTUALLY TERMINATE.** `affiliate_statements` is `derived` via `affiliates`, which is `owned`, so the walk ends at an identity and the mechanical check passes. **It is refused on nullability and on population.** [ADR-101](ADR-101.md) clause 2 refuses a nullable edge because the rows reaching nobody are a subset returned in silence, and here that subset is named: `status` admits four members and `affiliate_commissions_paid_has_statement` binds a statement only to `paid`, so a hop through this column returns the paid rows and **drops every `accrued`, `payable` and `clawed_back` row**. Those are the rows an affiliate arguing about money is arguing about. This is `payment_disputes`' `ledger_transaction_id` trap, in this migration set, on the settlement half instead of the dispute half.
>
> **6. `clawback_of` IS A SELF EDGE AND IS NULL ON EVERY ACCRUAL.** A self-reference has no terminus, and `affiliate_commissions_clawback_sign` makes the null the normal case. Refused twice, neither refusal needing a judgement.
>
> **7. `firm` IS THE SIXTH, IT IS AVAILABLE, AND IT IS THE ONE THAT MATTERS.** The predicate `scoped-db.test.ts` reads at *"no firm table carries a column referencing identities, so the class is not hiding one"* **PASSES** on this table. So a `firm` rule here compiles, satisfies the totality clause, satisfies that assertion, and makes the row readable through `firmDb()` -- **which takes no reason at all**, on [ADR-102](ADR-102.md) clause 5's ground that no identity is at risk. **Here one is.** A commission is what Merit owes a named affiliate; `affiliates.balance_cents` is signed money two hops out and is `owned`; and `affiliate_statements`' own registration says in its own words that the line items behind a statement's `total_cents` are this table. **`firm` is not unproven here. It is false**, and it is false in the direction row `253` named: a wrong tenancy answer behind a door that RETURNS ROWS rather than behind one that refuses.

**SO THE ANSWER TO ADR-106's OPEN QUESTION IS A REFUSAL RATHER THAN A CLASS.** `scope.ts` has said since [ADR-106](ADR-106.md) that *"registering this table needs a ruling about what a row derived from a two-party row belongs to, and ADR-106 does not make it."* That ruling is made here and it is: **not with this vocabulary.** The port stays blocked on `stats`, `UNWIRED_AFFILIATE_BACKEND` continues to refuse it, and the refusal now says the table is a class away rather than a registration away.

### 3. The second ruling: an issued link is not a row, and the refusal is arithmetic

[`apps/api/test/affiliate-issued-link.test.ts`](../../apps/api/test/affiliate-issued-link.test.ts) is the evidence.

> **1. THE TOKEN A BUYER PRESENTS NAMES A CLICK, AND THE INDEX IS WHAT SAYS SO.** `CheckoutRequest.affiliate_click_token` is resolved by `tx.clickByToken` inside the checkout transaction, `affiliate_clicks.click_token` is `uuid NOT NULL DEFAULT gen_random_uuid()`, and `affiliate_clicks_token_uq` is UNIQUE over it. `resolveAttribution` leans on exactly that in its own docblock, where it says the index *"makes a token name exactly one row"* and is therefore why it does not sort.
>
> **2. ONE ISSUED LINK IS CLICKED MANY TIMES, AND A UNIQUE COLUMN HOLDS A VALUE ONCE.** So the handle an affiliate is ISSUED and the token a buyer PRESENTS are two objects, and `CreateLinkResponse.click_token` is not an `affiliate_clicks.click_token`. **This is arithmetic and not taste.** The module header already refused a write at issue time on the `clicks_30d` denominator; **this refusal is independent of how clicks are counted and survives any change to that count**, which is why both are now written down.
>
> **3. AND NO LINK ROW IS OWED, WHICH IS THE PART THAT IS A RULING.** Three measurements carry it. **`affiliate_clicks` already holds every attribute a link object would carry, at CLICK grain**: `affiliate_id uuid NOT NULL` and `landing_path text NULL` are on the click row, so `0005` put a link's properties on the click rather than on a link. **`affiliates.code citext NOT NULL UNIQUE` is already a unique public handle**, so a URL has something to name without a new row existing to be named. **And nothing under `apps/api/src` writes an `affiliate_clicks` row at all**, measured over source with comments stripped, so a link table's only reader would be a click handler that does not exist, which is the primitive-before-a-caller [ADR-120](ADR-120.md) clause 3 refuses.
>
> **4. WHAT `issueLink` OWES IS AN ADAPTER AND A BASE URL.** Neither is DDL and neither is a scope rule. That moves it into the position `affiliate`, `requiredDisclosure`, `submitCreative` and `statements` already occupy: **five of the six methods are an adapter somebody can write, and one is not.**
>
> **5. `campaign` IS RULED AND NOT TAKEN.** It reaches no column, measured: the only occurrences of the word in the migration set are three lines of prose in `0025_reserved_sequence.sql`, and the case asserts each is a comment. **Where it belongs is beside `landing_path` on `affiliate_clicks`, at click grain**, because that is where this schema already keeps what a link was. **The column is not taken here**, because nothing reads it and the slice that ingests clicks is the one that should meet it.

**WHAT THIS RULING DOES NOT DO IS EDIT THE CONTRACT.** [API_CONTRACT](../architecture/API_CONTRACT.md) section 7 names the response field `click_token` and M08's own table says `POST /affiliate/links` *"Issues a click token"*. **Those sentences are what make this endpoint look like it must write a click row**, and section 3 clause 2 measures that it cannot. API_CONTRACT is a frozen document and is outside this fence, so **the collision is REPORTED and not repaired**: the field is a link handle wearing a click token's name. Renaming it is a contract change and needs an entry that is allowed to make one.

### 4. The control, and it is the only thing here that changes what CI refuses

**A `firm` RULE CARRIES A REASON AND NO COLUMNS, SO THE REGISTRY HOLDS NOTHING TO CHECK A FIRM CLAIM AGAINST. THE MIGRATIONS DO.**

> **A FIRM ROW IS ONE NO IDENTITY OWNS, AND A REQUIRED EDGE TO AN IDENTITY-REACHING PARENT IS AN IDENTITY OWNING IT.** The new case is *"no firm relation has a required edge to a relation that reaches an identity"*. It walks every relation registered `firm`, reads its `CREATE TABLE` body out of the migrations, and refuses any `NOT NULL` foreign key whose parent is registered `root`, `owned`, `derived`, `pair` or `either`.

**`NOT NULL` AND NOT EVERY EDGE, AND THE NARROWING IS THE RULING.** A nullable edge leaves rows that reach nobody, so a table carrying one genuinely may hold rows no identity owns, and `either` is the class built for the case where that is the ROW's property. **A required edge admits no such row**: every row of the child reaches the parent, so if the parent reaches an identity then so does every row here.

**IT IS GREEN OVER EVERY FIRM RELATION ON THIS TREE, WITH ZERO VIOLATIONS**, and the view among them is skipped for `scoped-db.test.ts`'s stated reason: a view has no `CREATE TABLE` body, and the class question about a view is asked of the relation it projects.

**AND IT WAS WATCHED FAILING, ON THE REAL MISTAKE RATHER THAN ON A SYNTHETIC ONE.** The seed is the registration this session was dispatched to consider: `affiliateCommissions` declared in `schema.ts` faithfully to `0012`, added to `TABLES`, registered `class: 'firm'`, and added to `scoped-db.test.ts`'s `SQL_NAME` map, which a session making this mistake is forced to do because omitting it is a compile error.

> **UNDER THE SEED, `pnpm run typecheck` EXITS 0.** The mistake COMPILES.
>
> **UNDER THE SEED, `scoped-db.test.ts`'s OWN FIRM ASSERTION STAYS GREEN**, and so does *"every derivation chain ends at an identity"*, which has no chain to walk on a firm rule.
>
> **THE NEW CASE GOES RED** with exactly one violation: `affiliate_commissions.attribution_id NOT NULL -> attributions (pair)`.
>
> **THE ONLY OTHER TENANCY-RELEVANT RED IS A HAND-MAINTAINED COUNT.** `scoped-db.test.ts`'s totality case fails at `expected 115 to be 114`, which is an arity a session taking this registration would update in the same commit and which asserts nothing about tenancy. **So before this entry, the whole of what stood between this tree and a false firm registration was a number somebody would have edited.**

**WHAT IT WOULD HAVE CAUGHT ON `origin/main` IS NOTHING, AND THAT IS REPORTED RATHER THAN DRESSED UP.** It finds no defect. It is written because the mistake it refuses is the one available RIGHT NOW to the next session that opens `scope.ts` on this table, and because [ADR-042](ADR-042.md) already ruled that prose is not a control. Section 2 clause 7 was a paragraph until this case existed.

### 5. The repair, and it was wider than the row said

**ROW `253` GRANTED ONE REPAIR AND NAMED ONE SITE. THE SENTENCE WAS AT TWO.**

`STATEMENTS_UNREACHABLE` served a caller the retired claim that `affiliate_statements` *"is not in `packages/db/src/schema.ts` at all"*. It is, and it is registered `derived` through `affiliates`. The wiring entry registered that site as outside its own fence and row `253` brought it inside this one. **What no entry had named is that the module HEADER carries the same retired sentence a second time**, in finding 1, where it is read by every session that opens the file to write an adapter.

Both are repaired. The constant is renamed `STATEMENTS_READABLE` and now names the class that makes the read possible, so the refusal says *no adapter yet* instead of *no table ever*, which is the difference between sending a later session to `apps/api` and sending it to `packages/db` for work already done. `COMMISSIONS_UNREACHABLE` and `LINK_HAS_NO_TABLE` are rewritten to carry sections 2 and 3.

**THE REPAIR IS ASSERTED OVER WHAT A CALLER IS SERVED AND NOT OVER THE FILE**, and the difference is deliberate. The repair leaves a docblock QUOTING the retired sentence so a later reader can see what was corrected, which is `RI-14`'s rule; an assertion over source text would forbid that idiom and could be satisfied by deleting the record instead of the defect. **All six methods are called and their messages read**, so a seventh site of the same sentence would fail this case rather than hide behind the one the row named.

**WATCHED RED BEFORE GREEN ON UNMODIFIED SHIPPED SOURCE.** With the repair stashed and `apps/api/src/routes/affiliate.ts` byte-identical to `origin/main`, two cases fail; with it restored, twelve pass. The file was verified byte-identical by `sha256sum` after the restore, and `git status` was empty of it.

### 6. What is NOT done, and the seventh class stated so nobody re-derives it

**THE PORT IS NOT WIRED AND THE WIRED COUNT DOES NOT MOVE.** `useAffiliateDeps` already holds `productionAffiliateDeps` at module scope, so calling the setter installs what is installed, which is not a wiring on `wiring.test.ts`'s own stated rule. **The entry is NARROWED rather than shrunk**: from two obstructions to one, with the discharged one kept in place and saying what was ruled, on `RI-14`'s rule that a false sentence removed leaves nothing for the next reader to check.

**THE SEVENTH CLASS IS NAMED HERE AND DELIBERATELY NOT WRITTEN.** It would be a rule that derives through a `pair` parent and NAMES which of the two columns the child belongs to. **The argument FOR it is real and is recorded rather than buried**, because a later session should meet it rather than rediscover it: [ADR-106](ADR-106.md) excludes `pair` from `ScopedTableKey` because every row a disjunction returns carries the OTHER party's identity uuid out of a `NOT NULL` column, and **one hop out that ground is ABSENT rather than outweighed**. A commission row carries no identity column at all; what it carries is `attribution_id`, an opaque uuid addressing a row the scoped accessor cannot read. That is the same move [ADR-191](ADR-191.md) used to admit `either` to a key set `pair` is excluded from, and the same move [ADR-230](ADR-230.md) used to admit a write.

**IT IS NOT TAKEN HERE FOR TWO REASONS AND NEITHER IS THAT THE ARGUMENT FAILS.**

> **THE FENCE.** Row `253` fences `scope.ts` to *"those registrations only"*. A class is not a registration: it changes the `ScopeClass` union, `scopePredicate`, `ScopedTableKey` and the suite's totality assertions. **Taking it would be widening a fence to finish**, which the row forbids in the same breath as it grants the work.
>
> **THE PRECEDENT.** [ADR-191](ADR-191.md) added the sixth class and it was a session's whole output, with a dispatched row of its own. **A class is a slice**, and one taken as a side effect of a registration is the shape this registry exists to refuse.

**AND WHERE THAT ARGUMENT IS MOST LIKELY WRONG IS NAMED.** The claim that the disclosure ground is absent rests on `attribution_id` being opaque to its holder. **An affiliate who can read commission rows learns HOW MANY attributions they have and can address each one**, and if any door ever resolves an `attributions` row from its id for a party, the uuid stops being opaque and ADR-106's ground returns one hop out. Nothing does that today. **A class written on this ground therefore has a standing condition attached to it**, and that is a reason for the class to be argued in its own entry rather than smuggled into a registration.

**AND ONE CLAUSE OF THE ROW IS WIDER THAN THE TREE SUPPORTS.** It describes `reserve_coverage_snapshots`' citation of *"`affiliate_commissions`' refusal in a second dress"* as **"a `derived` chain that terminates at a table with no identity on it"**. **That is true of `reserve_coverage_snapshots` and false of `affiliate_commissions`.** The reserve chain ends at `treasury_balances`, which is `firm` and has no identity on it; the commission chain ends at `attributions`, which has **two**. - **Approval:** `___________________________` (UNSIGNED. **Merging is not signing.**)

  **What a founder read adds and this entry cannot.**

  **THE FIRST IS WHETHER THE SEVENTH CLASS SHOULD BE BUILT AT ALL, AND THIS ENTRY DELIBERATELY LEAVES IT OPEN.** Section 6 states the argument for it and two reasons this session is not the one to take it, and neither reason is that the argument fails. **If you would rather `affiliate_commissions` stayed permanently unreadable**, that is a smaller and safer world and it costs `GET /affiliate/stats` every money figure it has: `earned_cents_lifetime`, `payable_cents` and `paid_cents_lifetime` are all sums over this table, so refusing the class refuses the affiliate panel rather than deferring it. **If you would rather it were built**, it needs a row of its own, and section 6's standing condition on `attribution_id`'s opacity should be in that row rather than in this one.

  **THE SECOND IS THAT THIS ENTRY RULES A CONTRACT FIELD MISNAMED AND DOES NOT CHANGE IT.** Section 3 concludes that `CreateLinkResponse.click_token` cannot be an `affiliate_clicks.click_token`, which makes the name wrong in a FROZEN document that this fence does not contain. **A field named for the wrong object is how the next session writes the wrong adapter**, and the arithmetic behind the finding is not in doubt. Whether it is repaired by renaming the field or by leaving the name and documenting the two objects is yours, and either way it needs an entry allowed to touch API_CONTRACT.

  **THE THIRD IS WHETHER RULING THAT NO LINK ROW IS OWED IS A DECISION THIS SESSION SHOULD HAVE MADE.** Row `253` granted the issued-link table explicitly and this entry declines to take it. **The three measurements in section 3 clause 3 are facts about today's tree and the ruling on top of them is a judgement about the design**, and a founder who intends per-link reporting later would want the row now rather than after clicks are being ingested against a schema that cannot attribute them to a link. **Nothing in the approved corpus asks a per-link question today** -- `GET /affiliate/stats` is affiliate-grained throughout -- which is what the judgement rests on, and it is a claim about what the corpus asks rather than about what the business will want.

  **WHERE THIS ENTRY IS MOST LIKELY WRONG, named rather than left for a reader to find.** **Section 2 clause 7 calls `firm` FALSE, and that is the one judgement here with no mechanical backing available to it.** The control in section 4 does not check that a firm rule is true; it checks a NECESSARY condition, that no required edge reaches an identity, and a table could satisfy it and still be wrongly firm. **So the gate makes THIS mistake unavailable and does not make the class honest in general**, and any entry that reads section 4 as validating firm rules is reading it too widely.
