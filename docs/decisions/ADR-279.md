## ADR-279: a stripper that eats the file, and the count in the row was seven where the tree holds twenty-nine (2026-08-30, status: proposed)

**[ADR-277](ADR-277.md) section 7 finding 1 reported that the tree's standing comment stripper is a block-comment regex followed by a line-comment regex, and that a block-comment OPENER written inside a LINE comment opens a phantom block that runs to the next real closer. Row `279` re-stated it and said the durable repair was one scanner in `packages/tooling` plus a check. Both are right. THE PART BOTH GOT WRONG IS THE SIZE: the row counted seven copies and five naive, and this session measured TWENTY-NINE files and TWENTY-SEVEN of them a comment regex, by running the new check's own legs over `origin/main`.**

**THE FINDING WAS WATCHED RATHER THAN QUOTED.** A `new Date().getHours()` placed inside the phantom span of [`apps/worker/src/index.ts`](../../apps/worker/src/index.ts) was seeded on the real tree, `RI-28` was run, and it reported **PASS, 28 of 28**. The same seed placed 447 characters later, past the last phantom closer, reported **FAIL `RI-28` (1)**. Both restores are `sha256sum -c` byte-identical.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `279`, session **470**, branch `claude/a-stripper-that-eats-the-file`. **NO MIGRATION NUMBER IS TAKEN OR RESERVED** and `packages/db/**` is untouched. **`RI-30` was RESERVED TO THE ROW and is taken**, and its register row was written in the same commit as the check.

- **NOT THE MONEY PATH.** No `src/` line moves in any deployable, no migration, no schema, no value, no grant. Every code change is either in `packages/tooling/**` or is one import replacing one comment stripper inside a test file. `E2` is not claimed and not discharged.

### 1. The defect, measured on this tree

The idiom, as five files wrote it character for character:

```js
source.replace(/\/\*[\s\S]*?\*\//g, ' ').replace(/\/\/[^\n]*/g, ' ')
```

The block pass runs FIRST. It cannot know that a `/*` sits inside a line comment, because line comments have not been removed yet, and removing them first only inverts the problem. So a header that quotes a glob opens a block that ends at the next real `*/`.

[`apps/worker/src/index.ts`](../../apps/worker/src/index.ts) carries the opener at line 64, inside prose reading `` `src/provisioning/**` ``, and the closer at line 1,101, inside prose reading `` `apps/*/src` ``. Between them sit **571 lines of real code**, including the export list the barrel exists to be.

| Reading of the barrel | Characters |
| --- | --- |
| The file | 55,728 |
| Under the two-replacement idiom | 2,753 |
| Under the scanner | 15,987 |

**THE DIRECTION IS THE WHOLE POINT.** A PRESENCE assertion over an emptied file goes red and somebody looks at it. An ABSENCE check over an emptied file goes GREEN and nobody ever does. `RI-28` is an absence check, and so were most of the suites carrying a copy. That is [ADR-274](ADR-274.md)'s own warned defect class landing inside the check ADR-274 shipped.

### 4. `RI-28` reads its files TWICE now, and blanking alone was a weakening

**WITH THE SCANNER AND NOTHING ELSE, `RI-28` WENT RED**, on [`scripts/ci/falsify-ci.mjs:539`](../../scripts/ci/falsify-ci.mjs), for `value.toLocaleString()`. That is not a call: it is the TEXT of the `CI-02/RE-D-02` seed, held inside a template literal, and the file's entire job is to hold the text of seeded violations. The old stripper had been hiding it by deleting 45,000 characters of that file by accident.

**SO THE THREE CALL LEGS READ THE TEXT WITH STRING LITERALS BLANKED.** A spelling written inside a literal is a quotation, exactly as a spelling written inside a comment is, which is `RI-25`'s seed applied one step further.

**AND BLANKING ALL FOUR LEGS WAS A WEAKENING, WHICH THE CHECK'S OWN SUITE SAID BEFORE THIS ENTRY DID.** The fourth leg matches `process.env['TZ']`, and that key is a STRING: blanking deletes the evidence. `repo-invariants.test.ts`'s seeded case for it went red with *"expected '' to contain 'asks for the process\\'s'"*. The leg now reads the text that still holds literals, which is stated per entry in `LOCAL_CLOCK_READS` rather than in a comment.

**ONE `lineAt` SERVES BOTH READINGS BECAUSE BLANKING IS CHARACTER FOR CHARACTER**, quotes and newlines kept. That is not an assumption: [`strip-comments.test.ts`](../../packages/tooling/test/strip-comments.test.ts) asserts it over **every JavaScript-family file in the workspace**, both length and every newline position.

**A SECOND FINDING CHANGED AND IT IS SMALLER**: `RI-28` used to report a line number that was not the line. The idiom collapses a whole block comment to one space, so counting newlines in the stripped text is counting a different file. The seed on line 1,124 of the barrel was reported as `apps/worker/src/index.ts:143`. The scanner keeps newlines inside block comments and the number is now true.

### 5. The scanner, and two defects in the version ADR-277 wrote

[`packages/tooling/checks/strip-comments.mjs`](../../packages/tooling/checks/strip-comments.mjs) is the one home. Its algorithm is [ADR-277](ADR-277.md)'s, from [`trading-day-coverage.test.ts`](../../apps/worker/test/trading-day-coverage.test.ts), where seed 13 proved it. **THE WORK WAS NEVER THE ALGORITHM AND THE ROW SAID SO.** Two things did change, and both were found by running the old scanner against the new one over all 704 source files rather than by reading it.

**FIRST: A NESTED TEMPLATE LITERAL INVERTED ITS STATE.** [`external-gates.ts`](../../packages/rules-engine/src/external-gates.ts) carries `` `${xs.map((one) => `\`${one}\``).join(', ')}` ``: a substitution that opens a SECOND template. The ADR-277 scanner treats `${...}` as literal content, so it closed the outer template on the inner backtick and read everything after it with its states swapped, leaving real docblocks unstripped. Three files on this tree hit it: that one, `repo-invariants.mjs` and `falsify-ci.mjs`. The home models `${...}` as CODE, which is also what makes `literals: 'blank'` honest: `` `${at.getHours()}` `` survives blanking and is still a finding.

**SECOND, AND IT IS THE ONE WORTH READING: A REGULAR EXPRESSION LITERAL WAS BEING READ AS A COMMENT.** `/\/\*[\s\S]*?\*\//g` ends in `\//g`, which contains `//`. Every stripper this tree has ever had, the ADR-277 scanner included, saw that and deleted the rest of the line.

**THAT IS THE WORST POSSIBLE PLACE FOR THAT BLIND SPOT.** The files carrying such a regex are precisely the files that strip comments, which is precisely what `RI-30` reads. The check that hunts the idiom was blind to the idiom, and it was blind on **11 files**. `RI-30`'s first working run reported 40 findings once the scanner learned regex literals and reported a fraction of that before.

Whether a `/` opens a regex or divides is not decidable from characters alone. The home uses the standard heuristic, states that it is one, and excludes `<` and `>` from the "could end a value" set so that `</div>` in a `.tsx` file does not open one.

### 6. `RI-30`, and the sentinel the row insisted on

**Title, live from `CHECKS`: *"One comment stripper, in packages/tooling, and every parser imports it"*.**

**LEG 1 IS THE NAME**, exactly `stripComments`, with a trailing `[(=<:]`. That last part is not tidiness: this check's own source carries `function stripComments\s*\(` inside a regex literal, which the scanner now correctly treats as code, and a name leg without it reported the check as its own violator.

**LEG 2 IS THE IDIOM AND IS NAME-BLIND**: a `.replace()` over a JavaScript line-comment regex, or over a block-comment regex that is not SQL's. Twenty-one of the twenty-nine copies had no name to catch, so leg 1 alone would have found eight of twenty-nine.

**THE LANGUAGE TEST IS NOT A FENCE.** Five SQL strippers and one YAML stripper stand in this tree. They are out of SUBJECT: SQL's comment grammar is `--` plus `''` doubling, YAML's is `#`, and this home is a JavaScript scanner that would strip either one wrongly. A block strip written in the same expression as a `--` strip is SQL, and that is how they are told apart. Section 7 names all of them.

**FOUR SENTINELS THROW, AND THE ROW IS WHY**: *"An absence check over an empty scope reports PASS in silence. This whole row is that defect."* Zero files walked; a missing home; a home exporting no `stripComments`; and **an importer set that does not reach outside `packages/tooling`**, which is the revert detector: with nothing importing the home, both legs are satisfied by a tree that has quietly gone back to 29 copies under other names.

**THEY ARE UNCONDITIONAL RATHER THAN SILENT ON A FOREIGN TREE**, which is a departure from `RI-25`'s precedent and is deliberate: a conditional sentinel is a sentinel with a way out. The cost is that the synthetic fixture in [`repo-invariants.test.ts`](../../packages/tooling/test/repo-invariants.test.ts) now carries the estate, three small files.

**ONE FILE IS ADMITTED AND THE ADMISSION IS ASSERTED RATHER THAN TRUSTED.** `strip-comments.test.ts` reproduces the naive idiom verbatim, because every case in it is a comparison against the thing being repaired and a repair with no record of what it repaired is a repair the next session undoes. The check THROWS if that file stops existing or stops carrying the idiom, so the exception cannot quietly widen into a hole.

**WATCHED RED ON THE REAL TREE.**

| Seed | Result |
| --- | --- |
| The idiom returned to [`referrals.test.ts`](../../apps/portal/test/referrals.test.ts) | **FAIL (2)**, naming both replacements |
| A second `stripComments` declared in [`trading-day-coverage.test.ts`](../../apps/worker/test/trading-day-coverage.test.ts) | **FAIL (1)** |

Restores are `sha256sum -c` byte-identical over all five files touched. The home-missing and no-export sentinels are not watchable on the real tree, because `repo-invariants.mjs` imports the home at module load and dies first with `ERR_MODULE_NOT_FOUND`; they are reachable and load-bearing for the synthetic trees the suite builds, and that is stated rather than dressed up as a watched RED.
