## ADR-117: `RI-08` guards every package against an EMPTY admission list, because the two ADR-096 named were five before this session opened  (2026-08-26, status: proposed)

**[ADR-096](ADR-096.md) section 9 named `RI-08`, measured the hole it closes, and assigned it to `P4-e`. `P4-e` landed without it.** [ADR-095](ADR-095.md)'s `F4` names the same gap from the framework side and its section 9 item 5b is the two entries noticing each other on one day. **Three entries have cited this hole and none closed it.** This entry writes it, and it rules ONE thing ADR-096 did not have the evidence to rule: **the scope.** ADR-096 scopes the check to `apps/site`, widens itself one sentence later to `packages/queue`, and calls the wider version *"the better version of it"*. **Five manifests now state the accessor's absence as a design property, and ZERO packages in this workspace declare it.** So the check guards **every workspace package** against an **admission list that is empty**, which is the same shape [ADR-084](ADR-084.md) section 5 gave `SystemReason` and `pnpm-workspace.yaml` gives `onlyBuiltDependencies`. **No migration, no application code, no manifest edited.**

- **Origin:** [ADR-096](ADR-096.md) section 9, dispatched as session **229**. The invariant NUMBER was allocated by ADR-096 itself; this entry allocates nothing and rules the shape.

- **NOT MONEY PATH BY FILE, AND THE HOLE IT CLOSES IS A MONEY-PATH HOLE.** No ledger, no payout, no engine, no auth, and the diff is one check and its tests. What it guards is the [ADR-008](ADR-008.md) BOLA blast radius `scopedDb` exists to bound, approached from the manifest rather than from the type.

### 2. THE RULING

1. **`RI-08` reads MANIFESTS, over EVERY workspace package except the accessor's own**, in all four dependency fields, and refuses any entry that resolves to the accessor package. It is exported in `CHECKS` and runs at `CI-01` with the other nine.

2. **The accessor is read out of [`packages/db/package.json`](../../packages/db/package.json)'s own `name`, never written into the check.** `RI-09`'s relationship to [`surface.ts`](../../apps/api/src/surface.ts), one register over: parse the source of truth and implement the comparison.

3. **`DB_ADMITTED` is the admission list and it is EMPTY.** A package reaches the trader database by being written into that list, in the file whose whole subject is which packages may. Adding a name is the decision; the empty list is the control.

4. **`apps/api` is NOT pre-admitted**, though [ADR-109](ADR-109.md) says it is the name that will need the accessor first: *"Whether `apps/api` gets `@merit/db`. It does not here. The wiring is a session with a migration-adjacent read of its own."* **A list that admits a member against a need nobody has stated yet is a list joining itself.**

5. **Three readings of "resolves to the accessor", each named in the finding it produces:** the dependency KEY, a `workspace:`/`npm:` ALIAS whose target is parsed out, and a `link:`/`file:`/`portal:` PATH that resolves to the accessor's directory.

6. **Two conditions make the check THROW rather than pass:** an admission naming a package that does not exist, and an admission list that covers every package. **The second is "never weaken a gate to pass it" made mechanical.**

### 4. Why an EMPTY ADMISSION LIST, which is this workspace's own idiom in three places

**A deny list of two names says which packages are forbidden. An empty admission list says the capability is not available**, and the difference is what happens to the sixth package nobody has written yet.

| Precedent | The line | What it buys |
|---|---|---|
| [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml) | `onlyBuiltDependencies: []`, *"an empty list means every one of them is an explicit admission decision rather than a default"* | a build script arrives as a diff, not a default |
| [`.npmrc`](../../.npmrc) | *"every one of these settings exists to make a dependency arrive as a decision rather than as a side effect"* | `VG-12`'s human leg |
| [ADR-084](ADR-084.md) section 5 | `SystemReason` closed at two, so that *"forgot to scope" becomes "wrote the word system"* | a diff a reviewer reads |

**ADR-096 section 4 states the cost this entry is answering, against itself:** the ruling *"turns it into 'added one line to a `package.json`', which is also a diff a reviewer reads and is SHORTER, less obviously about the database, and reviewed by whoever reviews manifests rather than by whoever reviews queries."*

**With `DB_ADMITTED` empty, that one line turns `CI-01` red, and making it green again costs a SECOND diff, in the checks file, whose subject is which packages may reach the trader database.** The quiet line becomes a loud one, and the reviewer it reaches is the one ADR-084's design was written for. **That is the whole of what this entry buys and it is stated no wider than that.**

### 5. What the manifest gate ACTUALLY gates, measured in both directions rather than reasoned

The dispatch's premise, and ADR-096's, is that the dependency FIELD is where the capability is acquired. **It is, and the measurement is worth recording because one file in this tree says the opposite.**

[`.npmrc`](../../.npmrc) sets `node-linker=isolated` and states that the default is *"load-bearing here rather than incidental"*, so an undeclared specifier does not resolve at RUN time. **It does not resolve at BUILD time either.** Seeded into `apps/site/src` and again into `apps/api/src`, one file each, no manifest line, and no `paths` mapping anywhere in the tree:

```
$ printf "import { systemDb } from '@merit/db';\n" > apps/site/src/__seed__db.ts
$ (cd apps/site && pnpm exec tsc --noEmit)
src/__seed__db.ts(1,26): error TS2307: Cannot find module '@merit/db' or its
  corresponding type declarations.

$ (cd apps/api && pnpm exec tsc --noEmit)
src/__seed__db.ts(1,26): error TS2307: Cannot find module '@merit/db' or its
  corresponding type declarations.
```

**So the manifest field is not merely where the dependency is recorded; it is the only place the capability can be acquired.** That is what makes a manifest check the whole control rather than half of one, and it is why this entry does NOT add a source-import half to `RI-08`. **[ADR-096 section 9](ADR-096.md) predicted this exact result for `apps/site` and it reproduces; both seeds were removed and `git status --porcelain` reports clean.**

**IT ALSO CONTRADICTS A LINE IN THE TREE, AND THE CONTRADICTION IS REPORTED RATHER THAN TAKEN.** [`apps/api/package.json:15`](../../apps/api/package.json) states that `node-linker=isolated` *"makes an undeclared import unresolvable at run time while `tsc` resolves it happily through the workspace, so the declaration is what separates a route that type-checks from one that starts."* **`tsc` does not resolve it happily; it reports `TS2307`.** The sentence's CONCLUSION survives, because the declaration still separates the two; its stated reason does not. **That file is outside this session's fence and is unedited.** Section 7 rows it.
