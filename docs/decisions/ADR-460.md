### 3. Where the call goes, and why not the other five blanks

`:2211` is the blank between the two registry-drift refusals and the table resolution:

```
2210   }
2211   refuseTermInValues(key, values);
2212   const table = TABLES[key] as PgTable;
```

**IT IS THE EARLIEST OF THE SIX AT WHICH THE GUARD CAN RUN, AND EARLIEST IS THE PROPERTY WORTH HAVING.** Everything above it tests the REGISTRY (`rule.class`, `rule.traversal`) and nothing above it reads `values`. Everything below it either reads `values`, resolves a column, or issues the parent-proof `SELECT`. **A refusal that is going to happen should happen before a read inside the caller's transaction**, which is what the other four blanks and the priced `:2282` all give up.

**THE OTHER FIVE WERE CONSIDERED AND ARE WORSE FOR ONE REASON EACH.** `:2220` and `:2243` sit below `propertyForColumn` and below the SQL-spelling refusal, so the guard would run after two checks that inspect the caller's keys. `:2252` and `:2266` sit below the parent read or immediately above it. `:2281` is the blank directly above the `return`, which is where the priced expression shape would have landed and carries its ordering exactly.

**AND `:2211` IS THE SPELLING THE FILE ALREADY USES**, which is why consuming a blank line costs nothing in readability here. `refuseTermInValues` sits at [`scoped-db.ts:524`](../../packages/db/src/scoped-db.ts) with `const table = TABLES[key] as PgTable;` on the next line and no blank between them. **The edited region is that pair, character for character.**
