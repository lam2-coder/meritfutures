### 3. The shape ruling: what counts as a throw "of its own"

The dispatch required this decided in the entry rather than left to the implementation. There are three questions and each gets an answer and a reason.

**QUESTION ONE: A THROW INSIDE A CALLBACK. It counts, and the wider reading is FORCED by the polarity rather than chosen.** Legs 1 and 2 already read a throw narrowly, per-frame, and the header says why: _"a nested callback that throws pushes its own frame and does not make its parent a refusal"_. That narrowness is what keeps leg 1 off `properties(names)`, whose `.map` callback throws. **Leg 3 points the other way and the same attribution flips sign with it.** Leg 1 reports a function that DOES throw, so attributing a callback's throw to the parent would MANUFACTURE reports; leg 3 reports one that does NOT, so the same attribution SUPPRESSES them. A guard spelled `rows.forEach((r) => { if (bad(r)) throw ... })` is a refusal, and a leg 3 reading only the outer frame would call it empty and be wrong. **So the rule now carries two fields, `throws` for the narrow per-frame reading legs 1 and 2 keep, and `throwsWithin` set on every open frame for leg 3.** A wider reading here can only ever suppress a report, never invent one, which is the safe direction for a leg whose failure mode is calling a real guard empty.

**QUESTION TWO: DELEGATION. A `refuse` function that throws nowhere but calls another `refuse[A-Z]` function is NOT reported, and the test is the convention itself.** `refuseBoth(key, values)` whose whole body is `refuseTenancyColumn(key, values); refuseTermInValues(key, values);` refuses two things and throws none. It is not empty in any sense the guard set cares about, because **every name it delegates to is a name legs A and D of `write-guard-set.mjs` already read**, so the completeness check still sees the whole refusal. Delegation through a member call, `guards.refuseUncatalogued(key)`, counts the same way and for the same reason.

**AND THE COROLLARY IS THE POINT OF THE WHOLE RULE, NOT AN AFTERTHOUGHT.** A `refuse` function delegating to a helper the convention does NOT cover is reported, **and so is the helper**, by leg 1 or leg 2. Both halves of `refuseCurrency(...) { checkCurrency(values); }` plus a throwing `checkCurrency` are reported in one pass, which is cased in the suite. **The composite is only as visible as its least visible part.**

**A CALL TO ITSELF IS NOT DELEGATION.** `function refuseLoop(v) { if (v !== '') refuseLoop(''); }` refuses nothing and would satisfy a naive delegation test by naming itself. The check excludes the function's own name, which costs one comparison.

**QUESTION THREE: `async`. Leg 3 covers it, and covering it does NOT decide [ADR-459](ADR-459.md) section 9 item 5.** That item asks whether a guard-SHAPED async function must be renamed, and it is held open by `pairInsertStatement` occupying the signature as a builder. **Leg 3 asks a different question**: it takes a name the author has ALREADY chosen and asks whether a throw backs it, and the `async` keyword changes nothing about that. Excluding `async` here would have been an exemption bought against a shape that does not exist on this tree, which is precisely the move this rule's own header refuses. **The question it DOES force is named and left, in section 9 item 3.** `pairInsertStatement` is not `refuse`-named and is untouched.

### 6. The hole leg 3 leaves, measured on the running rule and not repaired

**MUTUAL RECURSION BETWEEN TWO CONFORMING NAMES EVADES LEG 3 ENTIRELY.** This was seeded and run, not reasoned about:

```ts
export function refusePing(key: string): void {
  refusePong(key);
}
export function refusePong(key: string): void {

}
```

`npx eslint` on that file produced **no output at all**. Both functions refuse nothing, both carry a name `write-guard-set.mjs` reads as a guard, and each satisfies the delegation test by pointing at the other. **The self-call exclusion catches the one-node case and does not reach the two-node case**, because closing it means following the delegate to ask whether IT throws, which is a call graph across files and a different instrument from a per-frame visitor.

**IT IS LEFT OPEN DELIBERATELY AND THE ARGUMENT FOR LEAVING IT IS NOT "IT IS HARD".** Every guard on the tree today throws directly, so the hole is reachable only by writing two new empty guards that call each other, which is a shape nobody writes by accident. The alternative, dropping the delegation route entirely, would close this hole and open a worse one: it would report `refuseBoth` and every real composite guard, which is leg 3 calling a genuine refusal empty, the exact failure section 3 is built to avoid. **A rule that is silent on a contrived shape is better than one that is red on an idiomatic one.** It is priced in section 9.
