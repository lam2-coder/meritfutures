## ADR-256: the card that was ruled and not built is built, its refusals are state-independent so a revocation cannot become a failure, and the two ports it unblocks are one SLICE from wireable rather than one VARIABLE from wired (2026-08-30, status: proposed)

**[ADR-249](ADR-249.md) ruled the renderer's home, its timing, its storage and its address, deliberately landed no renderer, and left `useCertificateImageSource` and `useCertificateBackend` naming one absent artefact between them. This entry lands it. `renderCertificateCard` ([`apps/api/src/certificate-card.ts`](../../apps/api/src/certificate-card.ts)) is a pure function from one value to `image/png` bytes, and every clause of ADR-249 is TRANSCRIBED rather than re-decided.**

**THE ROW'S NAMED TRAP IS THE THING THE DESIGN IS ORGANISED AROUND, AND IT IS SHUT STRUCTURALLY RATHER THAN BY REMEMBERING IT.** `imageHandler` ([`certificates.ts:1130`](../../apps/api/src/routes/certificates.ts)) throws when a non-deferred lookup carries no card, in words that name the invariant, so **a renderer that answers nothing for a revoked row turns the revocation INTO the failure**. Every refusal this module makes is therefore state-independent: all five published sentences and the disclosure are checked on EVERY render, including the four sentences the card in hand will not draw, and the layout is FIXED so an issued card and a revoked card draw the same blocks at the same pixels and differ only in what those blocks say.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `256`, session **447**, dispatched as `claude/the-card-that-was-ruled-and-not-built`. The row is **RESERVED, REQUIRED**, and it is taken.

- **NOT THE MONEY PATH.** No ledger account, no balance, no payout. `E2` is not owed. **NO MIGRATION IS RESERVED, TAKEN OR SPENT**, which is [ADR-249](ADR-249.md) section 4's ruling applied rather than re-derived: every value the card draws is already a column. **The next free number is still `0075`.** Ships `proposed` with an **UNSIGNED** approval line.

- **WHAT IS MEASURED, WHAT IS DERIVED, AND WHAT IS JUDGED.** That the bytes are a PNG the route's own `assertPng` accepts, that the chunk stream is well formed and every CRC verifies against an independently written reader, that all four revocation classes RENDER, that retuning one class's sentence moves exactly that class's card and no other, that a misconfigured sentence this card will not draw still fails this card, that the module's source reaches no clock and no world, that every drawn value changes the bytes, that every field of the input changes the version, and that the route serves a revoked card end to end at 200, is **MEASURED**, by executing it. That the renderer belongs behind the port, renders on fetch, stores nothing and needs no address column is **DERIVED** from [ADR-249](ADR-249.md) at the clause each claim names. What is **JUDGED** is where the module lives (section 2), that a revocation is drawn in weight and never in a hue (section 6), and that neither port is wireable yet (section 7).

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every clause the row quotes was re-read in [ADR-249](ADR-249.md) itself and every line citation was opened before anything was built on it: section 1.

### 2. Where the module lives, which the row asked to be declared

**`apps/api/src/certificate-card.ts`. NOT under `routes/`, and NOT a workspace package.** Both halves are arguments rather than conveniences.

> **1. IT IS NOT A ROUTE AND IT IS NOT UNDER `routes/`.** Every file in that directory is a surface: it registers a path, reads a request or projects a response. This module has no idea an HTTP request exists. **`routes/certificates.ts` does not import it and the suite asserts that on the IMPORT STATEMENTS rather than on a mention**, which is what keeps `assertPng` there a VALIDATOR at the boundary instead of a producer checking its own work.
>
> **2. IT IS NOT A WORKSPACE PACKAGE, AND `apps/api/package.json` IS WHY.** That manifest records what a workspace dependency MEANS in this tree: the declaration *"is THE ONLY PLACE THE CAPABILITY CAN BE ACQUIRED"*, which is what makes `RI-08`'s manifest check the whole control rather than half of one. **A package is therefore a claim that more than one deployable renders cards, and exactly one thing in this estate needs card bytes.** [ADR-249](ADR-249.md) clause 1 rules that where the bytes are produced is a DEPLOYMENT shape; a package boundary would look like this session deciding it.
>
> **3. AND THE PORT IS KEPT OPEN BY THE MODULE IMPORTING NOTHING FROM THIS DEPLOYABLE.** Its only imports are `node:crypto` and `node:zlib`, asserted as an exact list rather than as a denylist. **So the day a render service exists this file MOVES and no caller is rewritten**, which is the deployment freedom clause 1 refused to spend and this entry does not spend either.

**THE ALTERNATIVE, NAMED WITH ITS COST.** A `packages/certificate-card` would be reachable by `apps/worker`, and that is the exact reachability [ADR-249](ADR-249.md) section 2.1 narrowed [ADR-246](ADR-246.md) to remove: *"an issuer runs once per certificate, and a thing that runs once per certificate cannot re-render on fetch."* Making the renderer easy for the issuer to call is making the rejected design easy to build.

### 3. The trap, and the four things that shut it

**A REVOKED CERTIFICATE MUST RENDER. WHAT CHANGES IS WHAT IT SAYS.** `INV-M11-08` makes the re-render the only path by which a revocation reaches a circulating image, so a renderer that fails on a revoked row converts the revocation into a 500 on exactly the fetch that matters. Four properties stand between this module and that.

> **4. EVERY COPY REFUSAL IS CHECKED ON EVERY RENDER, INCLUDING THE FOUR SENTENCES THIS CARD WILL NOT DRAW.** This is [`routes/verify.ts`](../../apps/api/src/routes/verify.ts)' own rule transcribed: *"Every sentence is checked on every path, because a sentence missing only for the result it describes is a hit-versus-miss oracle built out of the configuration error."* **Here it buys something further than an oracle.** A check that ran only on the sentence being drawn would let a deployment ship a broken `fact_untrue` string and discover it on the first card that had to publish a revocation. Checked this way, that deployment fails its very first fetch of ANY card.
>
> **5. THE LAYOUT IS FIXED AND NO BLOCK MOVES WITH THE STATE.** The published sentence gets a three-line box whether it uses one line or three; the state line is drawn for `issued` and for `revoked` at the same pixel; the claim block reserves five slots whether the card has four rows or five, and the renderer REFUSES a claim block that grows past its reservation rather than pushing everything below it down. **A layout that can move with the state is a layout in which a long revocation sentence is the thing that overflows.**
>
> **6. A DEFERRED ROW CANNOT BE HANDED TO THIS FUNCTION AT ALL.** `CARD_STATES` is two members and the input has no field a deferral could arrive in, which is [ADR-168](ADR-168.md) foreclosure 4 obtained structurally, the same way `projectCertificate` obtains it. `imageHandler` throws when a lookup hands it a card for a deferred code; nothing here can build one.
>
> **7. A CHARACTER THE TYPEFACE CANNOT DRAW IS REFUSED IN CONFIGURED COPY AND REPLACED IN A ROW VALUE, AND THE ASYMMETRY IS THE TRAP AGAIN.** Copy is refused because the refusal is state-independent and reaches every card at once, and because Merit's published wording is not silently altered on a public artefact carrying its claim. **A row value is drawn anyway**, through a replacement box, because refusing an unexpected byte in `plan_code` would turn one odd row into a revocation that never renders. An over-long row value is truncated with a visible marker for the same reason.

**AND THE ROUTE HALF IS EXECUTED RATHER THAN ARGUED.** [`certificate-card.test.ts`](../../apps/api/test/certificate-card.test.ts) wires a `CertificateImageSource` that renders a revoked card, injects the real request, and asserts 200 with `image/png` and the exact bytes. [`certificate-card-home.test.ts`](../../apps/api/test/certificate-card-home.test.ts) already asserts the FAILURE beside it, a `revoked` lookup with a null card answering 500, so the pair now covers both directions of the invariant.

### 4. The second trap: no key, no origin, no variable, no world

**THIS MODULE READS NO ENVIRONMENT VARIABLE, NAMES NO ORIGIN, NO BUCKET AND NO HOSTNAME, AND HOLDS NO KEY.** [ADR-240](ADR-240.md) ruled a URL signing key *"not even a secret this deployable could use"* and [ADR-249](ADR-249.md) section 3 ruled the address derived rather than signed. **Nothing here asks either ruling to move**, and the design does not need them to: the renderer is handed a value and returns bytes, so it has no address to sign and no place to put a signature.

**THE COPY IS CONFIGURATION AND ARRIVES AS AN ARGUMENT.** `INV-M11-04`'s disclosure and `INV-M11-07`'s four published sentences are already named in this estate, at `VERIFY_PRESENTATION_VARS` and `VERIFY_DISCLOSURE_VAR` in [`routes/verify.ts`](../../apps/api/src/routes/verify.ts), and this module takes them as `CertificateCardCopy` rather than reading an environment of its own. **`AS-M11-05` is why that matters more than tidiness**: `account_enforced` means the claim STANDS, and a second copy of Merit's revocation wording maintained inside a renderer is the sentence that goes stale while the verify page moves. The suite asserts the two key sets are identical.

**AND THE CLASS SELECTS THE SENTENCE, WHICH IS `INV-M11-07` IN ITS OWN WORDS.** The caller hands over all five and the renderer picks by `revocation_class`, so a caller cannot pass a sentence that does not match the class. [ADR-012](ADR-012.md)'s grep over this branch's diff plus both new files returns **nothing**: no hostname, no bucket, no key and no secret is written into this repository.

### 5. Clause 8's condition, made structural rather than promised

[ADR-249](ADR-249.md) clause 8 rules `FM-M11-05`'s `row_version` DERIVED: a digest over the value handed to the template IS the version. **Its own founder block names the condition that reasoning rests on**, that it *"holds only while the template draws NOTHING the digest did not see"*, and that *"a renderer that reaches for the clock, for a plan-version lookup, or for a logo it fetches, has a rendering input the row does not carry"*.

> **8. THE TEMPLATE TAKES ONE ARGUMENT AND THE DIGEST IS TAKEN OVER THAT ARGUMENT.** `renderCertificateCard(input)` is the whole signature, every function under it takes what it is given, and the module imports a hash and a deflate and nothing else. **The suite sweeps the module's own source, comments stripped, for `Date`, `process.env`, `fetch(`, `readFile`, `Math.random`, `randomBytes`, `performance`, `node:fs` and `node:http`, and asserts the import list is exactly two entries**, which is the half a denylist cannot give.
>
> **9. AND THE OTHER DIRECTION IS EXECUTED FIELD BY FIELD.** Every DRAWN value is asserted to change the bytes, so a value this entry claims is rendered and is not fails with its own name; every field of the input is asserted to change the VERSION; and `CARD_INPUT_KEYS` is asserted TOTAL over the input's keys, so a field added and forgotten in the canonical form fails rather than becoming a rendering input the version cannot see.
>
> **10. THE CONFIGURED COPY IS INSIDE THE DIGEST AND THAT IS DELIBERATE.** A deployment that retunes the disclosure has changed what every card says, so every cached card must miss. **A version taken over the row alone would keep serving the sentence a deployment has just replaced until somebody remembered to invalidate**, which is `INV-M9-04`'s *"an invalidation that is fire-and-forget is a cache that is USUALLY RIGHT"* arriving one table later. The cost is named: the four sentences a given card does not draw are in its version, so retuning `fact_untrue` misses the cache for issued cards that look identical. **That is a cache miss and the alternative is a wrong card.**

  **What a founder read adds and this entry cannot.**

  **THE FIRST IS THAT THIS FILE IS NOW THE DISCLOSURE BOUNDARY FOR A PUBLIC ARTEFACT AND IT IS THE ONLY ONE.** [`certificates.ts`](../../apps/api/src/routes/certificates.ts)' own header says so: the response-shape allowlist is a projection over named fields and nothing chooses fields inside a PNG, so on the image row the boundary is in the renderer. **What stands in for the allowlist here is that the input type has a field for exactly what the card draws and no field for anything else**, which is `CertificateRow`'s discipline copied, and the suite asserts the key list is total. `identity_id`, `revoked_reason` and the rest have nowhere to arrive from. **That is a structural control and it is not a review**: nobody has looked at a rendered card beside `INV-M11-01` and confirmed the disclosure is the right disclosure. Rendering one of each kind is two calls to `renderCertificateCard`, and that reading is the one this entry cannot do for you.

  **THE SECOND IS THE TYPEFACE, WHICH IS NINETY LINES OF HAND-WRITTEN DATA THAT NOTHING VERIFIES.** The module refuses a malformed glyph at load, so a short row or a stray character cannot ship. **Nothing asserts that the glyph for `A` looks like an A.** A transposed pair would draw a wrong character into a plan code or a certificate token on a public surface, every test in this suite would pass, and the failure would be discovered by a trader reading their own card. The cheapest control is a human looking at one rendered alphabet once, and this entry can only say that it has not happened.

  **THE THIRD IS THAT AN UNDRAWABLE CHARACTER IN THE CONFIGURED COPY TAKES EVERY CARD DOWN.** Section 3 clause 7 argues that this is the right direction, because the alternative silently alters Merit's published wording, and because a state-dependent refusal is the trap. **The cost is a real foot-gun**: a typographic apostrophe or a curly quote pasted into `MERIT_VERIFY_DISCLOSURE` fails every card fetch with a 500, and neither character is banned anywhere in this corpus. **Appendix F bans em-dashes in Merit prose, which reduces the likelihood and does not remove it.** The two ways out are widening the typeface and normalising the copy, and both are decisions about what Merit's published wording may contain rather than about a renderer.

  **THE FOURTH IS THAT THE RATE LIMIT IS NOW OVERDUE RATHER THAN OWED.** [ADR-249](ADR-249.md) section 2.2 accepted, in writing, that render-on-fetch is compute an attacker can drive, and named the missing rate limit as the control. **That acceptance was cheap while the render did not exist.** It is not cheap now: a PNG encode on an unauthenticated public path is live the moment the adapter lands, and the adapter is a small slice. **The ordering question is a founder's**, and the honest statement is that wiring the image port before the rate limit exists puts `FM-M11-05` on a surface anybody can drive.

  **WHERE THIS ENTRY IS MOST LIKELY WRONG, named rather than left for a reader to find.** **The layout, the dimensions and the wording of every label on the card are this session's and no approved document reviews them.** Section 6 names the three decisions honestly, but the honest reading is wider than that: `EVALUATION PASS`, `PAYOUT`, `PLAN`, `SIZE`, `TRADING DAY`, `ISSUED` and `CLAIM SCHEMA` are all strings this session chose, and they are on a public artefact carrying Merit's name. **They are drawn from columns rather than invented as facts, which is the half that matters and is asserted; what they are CALLED is not ruled anywhere.** The second seeded defect is the pattern to be suspicious of here: an assertion that a value is drawn is not an assertion that it is drawn correctly, and the difference is exactly where a suite stops being able to help.
