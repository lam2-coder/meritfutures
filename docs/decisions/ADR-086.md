## ADR-086: The job interface is five methods, the transaction is the first argument, and one primitive is foreclosed on purpose  (2026-08-24, status: proposed)

**[ADR-006](ADR-006.md) is `accepted`, it chose pg-boss on 2026-08-13, and it closed with a sentence that is a specification rather than a hope: *"The job interface stays narrow enough that a later move to BullMQ is a contained change, and that narrowness is now a review criterion on M2 and M5, not an aspiration."* A criterion with no artifact is a sentence, and this entry is the first artifact it has ever been applied to.**

- **Context:** [P3's build plan](../plans/P3-ledger-billing-identity.md) section 3 recorded that *"nothing in this tree enqueues anything"*, so the criterion had never graded anything. Re-measured here at `01bb681` rather than inherited: `git grep -li pg-boss` over `apps/**` and `packages/**` returns [`apps/worker/src/index.ts`](../../apps/worker/src/index.ts) and [`packages/db/src/client.ts`](../../packages/db/src/client.ts), **both of them comments about a queue that did not exist**, and `git grep -li enqueue` over the `.ts` files returns the second of those two, also a comment.

---

## 1. What this entry decides, and what ADR-006 already decided

**ADR-006 decided the vendor and this entry does not revisit it.** pg-boss stands, its reasons stand, and its two alternatives were weighed there. What was left open is the thing ADR-006 named as a review criterion and could not itself write: **the surface**. Which primitives the interface exposes, which it refuses, and which one it admits knowing that admitting it is what makes the escape hatch expensive.

**Three things are ruled here:**

1. **The interface is five methods**, and the count is mechanical rather than described.
2. **`enqueue` takes the caller's open transaction as its first argument**, with no overload that omits it. This is the one primitive on the surface a Redis-backed queue cannot honour, and it is admitted deliberately.
3. **The queue does not install its own schema.** `migrate` is off, so the job store arrives as a reviewed migration or it does not arrive.

---

## 2. The surface, and the admission test applied one method at a time

**The test each method had to pass: could a BullMQ adapter implement this?** A method that fails it is a method that makes ADR-006's *"contained change"* cost something, and this table is where that cost is named at the boundary rather than discovered at the move.

**Two different kinds of claim are in this table and they are marked as such.** The pg-boss column is **measured on this tree** against `pg-boss@12.28.0`: every row was executed by [`test/pg-boss-queue.test.ts`](../../packages/queue/test/pg-boss-queue.test.ts) with the emitted SQL captured. The BullMQ column is **read from that library's public API and is not measured here**, because BullMQ is not in this workspace and admitting it to check would be a VG-12 admission spent on a comparison.

| Method | pg-boss, measured | BullMQ, from its API | Verdict |
|---|---|---|---|
| `declareQueue(queue)` | `SELECT pgboss.create_queue('<name>', ...)` under an advisory lock. **Required**: `send` to an undeclared queue throws `Queue <name> does not exist` | Queues are implicit; a `Queue` is created on first `add`. The adapter implements this as a **no-op** | **Expressible.** The narrower interface is the one that HAS this method: pg-boss cannot invent it, and Redis can ignore it |
| `enqueue(tx, request)` | `INSERT INTO pgboss.<table>` executed on the executor passed as `SendOptions.db` | `queue.add(name, data, opts)`, on Redis, with **no way to join a Postgres transaction** | **NOT expressible.** Section 3. This is the foreclosure |
| `consume(queue, handler)` | `boss.work(name, handler)`, handler receives an array even at the default `batchSize: 1` | `new Worker(name, processor)`, processor receives one job | **Expressible.** The interface hands one job per call, which is the shape both can serve; the batch is the adapter's business |
| `start()` | opens polling, maintenance and the queue cache | `Worker` starts on construction; the method is a no-op or a `waitUntilReady` | **Expressible** |
| `stop()` | `boss.stop()` | `worker.close()` / `queue.close()` | **Expressible** |

**Four of five are expressible and the fifth is the point.** That is the shape ADR-006 asked for: an interface where the move to Redis costs exactly one named thing rather than an audit.

### 2.1 The request fields, tested the same way

`key` is a deduplication id (`singletonKey` here, `jobId` there). `notBefore` is a delay (`startAfter` here, `delay` there). `retryLimit` and `retryDelaySeconds` are an attempt count and a backoff (`attempts`, `backoff` there). **All four are expressible on both**, and none of them adopts the vendor's spelling, which is what stops the vendor's name from leaking into every call site through its option names.

## 3. The foreclosure, stated in the direction it will be paid in

**ADR-006's central consequence is that *"enqueue participates in the same transaction as the state change that caused it, which removes a whole class of saga bugs ('committed the purchase, lost the provisioning job')."* A transaction is per-connection.** So the interface has to make the connection the caller's to supply, and it does: `enqueue(tx, request)`.

**pg-boss supports this directly and it is not an accident of its implementation.** `SendOptions` extends `ConnectionOptions`, which carries `db?: IDatabase`; `Manager.createJob` reads `const db = wrapper || this.db` and runs the insert on it. One property, and it is the whole ruling.

**WHAT THIS FORECLOSES.** A BullMQ adapter could implement the other four methods and would have to implement this one by **accepting the transaction and ignoring it**, which is the bug wearing the type that was supposed to prevent it. So the move ADR-006 kept available is available for the *shape* of the code and not for the *guarantee*: after it, `INV-M3-13`'s wallet leg committing in one transaction with the purchase, and P3's *"saga compensation green"* done-clause, are properties nothing enforces. **That is a decision to take with this sentence in front of you, and the cost of writing it here is one paragraph.**

**THE NON-TRANSACTIONAL ENQUEUE IS THE AWKWARD ONE TO WRITE, which is what the brief asked the shape to do.** There is no `enqueueNow`, no optional transaction and no ambient default. A caller with no state change to join opens a transaction around the single insert, which is one line and is correct. A caller who wants the unsafe form has to construct a `JobTransaction` by hand out of something that is not a transaction, and that is a diff a reviewer reads.

**WHAT THE TYPE CANNOT DO, said rather than implied.** `JobTransaction` is structural: anything with an `executeSql` satisfies it, including a pool. The type says *"give the queue something that runs SQL"*; it cannot say *"and be inside a transaction"*, because that is a fact about a connection at a moment and no TypeScript type observes a moment. This closes the accidental door and not the deliberate one, which is the limit [`no-raw-db-client`](../../packages/eslint-plugin-merit/rules/no-raw-db-client.js) states about itself in the same words.

### 3.1 The other direction, because the brief asked for it

**What BullMQ offers that pg-boss does not, and that this interface therefore gives up nothing by refusing:** higher throughput, per-queue rate limiting, sandboxed processors and mature dashboards. ADR-006 already weighed those and found that *"at v1 scale ... the throughput advantage buys nothing we need"*. **Nothing Redis-only is admitted here**, so the move is asymmetric on purpose: everything on this surface survives it except the one thing named above.

## 4. What is refused, and each refusal is cheaper now than at the move

**A primitive admitted before a caller exists is a primitive nobody can remove.** Each of these is available from pg-boss today and each is left out.

| Refused | What it is | Why not |
|---|---|---|
| `sendThrottled` / `sendDebounced` | a singleton over a **time window** (`singletonSeconds`, `singletonNextSlot`) | Postgres-side arithmetic over the job table. Redis has rate limiting, not this. A caller needing it should ask for it by name |
| `priority`, `minPriority`, `maxPriority` | priority fetch | Expressible on both, and refused on narrowness alone: no caller exists, and a priority admitted now is a scheduling policy nobody decided |
| `flow` / `dependsOn` | a job graph resolved in the store | Both have a form of it. The provisioning saga's compensation is **our** orchestration and putting it in the queue would move a money-path decision into a vendor |
| `deadLetter` routing | a queue jobs fall into after exhausting retries | Expressible on both; refused until the operator surface that would read it exists |
| `findJobs`, `getQueueStats` | querying the job store | **The one that would hurt most.** A job store in Postgres is queryable with SQL, and a report built on that query is a report that cannot be ported. This is the archetype of the primitive that makes a contained change expensive |
| `schedule` (cron in the job store) | pg-boss's own scheduler | `CRON_INVENTORY` is not this session's fence and the scheduled jobs are not this session's work. What lands is the interface and its adapter, not a job |

## 5. The queue does not install its own schema

**pg-boss defaults `migrate` to TRUE.** Its own `dist/attorney.js` reads `config.migrate = ('migrate' in config) ? config.migrate : true` (quoted from the installed package, which is not linkable from here because it is not in this repository), so the stock configuration runs DDL against the money database at `start()`, from a library, outside the migration set.

**That is refused.** [ADR-008](ADR-008.md) makes migrations *"plain SQL files that can be reviewed line by line"* and constitution E2 makes them sacred once merged. A queue that installs its own schema at boot puts tables inside the PITR boundary that protects the ledger with **no review, no migration number and no diff**, and the day it silently migrates itself on a version bump is the day that boundary contains something nobody read.

**So `migrate: false`, and `start()` against a database with no pg-boss schema FAILS with `pg-boss is not installed`, emitting no DDL.** Both halves are asserted, and the assertion was watched failing: flipping the flag makes the case report `expected [ 'CREATE SCHEMA IF' ] to deeply equal []`, naming the schema it was about to create.

**THE MIGRATION THAT WOULD INSTALL IT DOES NOT EXIST AND THIS SESSION CANNOT WRITE IT.** `packages/db/migrations/**` is outside the fence and migration numbers are allocated in [ALLOCATION](ALLOCATION.md) (`0047` is [session 148](../sessions/README.md)'s). pg-boss emits its own DDL through `getConstructionPlans(schema)`, so the migration is a transcription rather than a design, and it is named here as owed rather than left for a session to discover at its first `start()`.

## 6. The finding: `packages/db` cannot supply the executor, and this session did not add a second pool

**[ADR-084](ADR-084.md) section 2 ruled where this queue runs, in those words: *"Session 147 builds the queue on this pool."* It runs there by construction and it cannot run there yet, and both halves are true at once.**

**BY CONSTRUCTION**: [`packages/queue`](../../packages/queue/src/index.ts) declares no `pg`, no `drizzle-orm` and no `@merit/db`; it never calls `new Pool`, never reads `DATABASE_URL`, and takes both its connection and its transaction as arguments. **It cannot open a second pool even by mistake**, which is the property ADR-084 spent 14 packages to keep available.

**AND IT CANNOT RUN THERE YET.** Measured rather than read, by importing the package and printing its surface:

```
@merit/db value exports (8): SCOPE_RULES, TABLES, TABLE_KEYS, closeClient,
                             schema, scopePredicate, scopedDb, systemDb
scopedDb(identity) -> __brand, identityId, rows
systemDb(reason)   -> __brand, reason, rows
either has executeSql: false
```

**Nothing on that surface runs a transaction and nothing yields a SQL executor.** `closeClient` is the only export whose name is about the connection and it closes the pool rather than lending it; `client()` is deliberately unexported and [ADR-084](ADR-084.md) section 9 rules it so permanently, on the ground that exporting it *"would leave the ESLint rule as the only thing between an app and an unscoped query"*.

**So the dispatching brief's stop condition is met by reporting rather than by reaching.** The instruction was that if the queue cannot share `packages/db`'s pool, *"that is the finding and you stop and report rather than adding a second pool."* **No second pool was added.** What lands is the interface, the adapter and the suite that proves the enqueue joins the transaction it is given; the wiring waits on one export from a package this fence does not hold.

### 6.1 What that export has to be, stated and NOT ruled

**This is a real design question and it belongs to the session that holds `packages/db`, not to this one.** It is written down so that session inherits it instead of re-deriving it.

`packages/db` needs to publish a way to run a function inside a transaction and hand it something with `executeSql`. **The tension is that ADR-084 section 9's whole argument is that reaching the database and choosing a scope are the same act**, and a bare transaction runner is a third accessor that is neither scoped nor branded, which is exactly the hole VG-4 exists to keep shut. **Three shapes are visible and none is ruled here:** the runner could be branded like `ScopedDb` and `SystemDb` are; it could hang off the scoped accessor so a transaction is always opened *for an identity*; or it could take a closed reason vocabulary the way `systemDb` does. **No `OI-nn` is minted for it**, because the `OI` table is not in this fence and a number claimed from outside its allocation site is how `OI-27` happened. It is carried in [STATE](../STATE.md) and in [session 147](../sessions/2026-08-24-session-147.md)'s log instead.

## 8. Consequences

- **`packages/queue` is a library and the split is load-bearing.** [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml): *"apps/\* are DEPLOYABLES and packages/\* are LIBRARIES."* Both `apps/api` and `apps/worker` will enqueue, and `RI-04` reports an app depending on an app in its own words: *"a deployable that imports a deployable is one deployable."*
- **The vendor is named in exactly one module, and that is asserted rather than intended.** [`test/surface.test.ts`](../../packages/queue/test/surface.test.ts) walks `apps/**` and `packages/**` for the import specifier and for the manifest key, in both cases requiring one result. **"A contained change" is a fact about a file count and it decays silently**: the second import always arrives in a session with a deadline, and nothing else in this repository would notice.
- **The interface is polled, not notified.** pg-boss's LISTEN/NOTIFY path needs a pg-boss-owned pool or an adapter implementing `listen`, and `JobTransaction` has one method which is not `listen`. **That is the same decision as `migrate` seen from the other side**: this package is handed a connection rather than owning one, so it polls, and polling latency is a real cost stated here rather than left to be derived.
- **Nothing is scheduled and no job exists.** `CRON_INVENTORY` is outside this fence. [`apps/worker`](../../apps/worker/src/index.ts) is retensed to say so and imports nothing: `apps/worker/package.json` is outside the fence too, and under `node-linker=isolated` an undeclared import does not resolve.
- **A sixth method does not compile silently.** `JOB_QUEUE_METHODS` is checked in both directions: `satisfies` rejects a name that is not a method, and `EveryJobQueueMethodIsListed` rejects a method that is not a name.
- **The suite needs no database and runs in the `unit` project on every push.** [`CI-04`](../testing/STRATEGY.md)'s second leg is still a dated condition ([ADR-085](ADR-085.md)), so a suite that needed a live Postgres would be a suite that has never run. The model in [`test/fake-database.ts`](../../packages/queue/test/fake-database.ts) is named as a model: it knows which connection a statement went to and whether that connection committed, which is the whole of what *"a transaction is per-connection"* asserts, and nothing else.
- **No `SD-nn`, no migration number, no `CI-06` letter, no `OI-nn`, and no new gate.** The validating half is a vitest suite because the property is a runtime one; the two compile-time refusals ADR-084 put in `falsify-ci.mjs` have no analogue here, and that file is outside this fence.
- **Two expectations in the suite were WRONG on first run and pg-boss corrected them**, which is the reason the suite reads pg-boss's output rather than the adapter's intent: `startAfter` crosses the wire as an ISO-8601 string because pg-boss `JSON.stringify`s the job, and `declareQueue` calls the schema's `create_queue` function rather than inserting a row. **A suite that had taken its expectation from `pg-boss-queue.ts` would have agreed with itself about both.** [ADR-084](ADR-084.md) section 7 is the precedent and it cost that session its whole first draft.

## 10. Approval

- **Founder approval: UNSIGNED as of 2026-08-24. MONEY PATH**, and [E2](../../MERIT_BUILD_MASTER_PROMPT.md) reserves the line-by-line read for exactly this class.

  **THE ONE CLAUSE TO CHECK BEFORE SIGNING**, carrying the direction it could fail in and not only the one it was written for:

  > `pnpm exec vitest run packages/queue` passes at **14 assertions over 2 files**, and its `rolls back with the transaction` case is watched **FAILING** when `db: tx` is deleted from [`pg-boss-queue.ts`](../../packages/queue/src/pg-boss-queue.ts)'s `send`, reporting `expected [ { ...(2) } ] to have a length of +0 but got 1` -- **one job insert durable after a rollback**, which is *"committed the purchase, lost the provisioning job"* reproduced; `commits with the transaction` stands beside it so the rollback case cannot pass against an enqueue that writes nothing at all; and [`surface.test.ts`](../../packages/queue/test/surface.test.ts) reports **exactly one module and exactly one manifest** naming `pg-boss` across `apps/**` and `packages/**`, watched **FAILING** on a second import and on a sixth method.

  **The failure direction is inside the clause because it is the one that passes silently.** An enqueue that reaches its own connection still returns a job id, still inserts a row, and still looks correct at every call site; what it stops doing is disappearing when the purchase it belonged to disappears. **A suite that asserted only "the job was created" would be green against it**, which is why the assertion is about the connection the insert landed on and about what survived a rollback, and why both directions are asserted rather than one.

  **What it costs if wrong.** ADR-006's *"contained change"* becomes a rewrite, the criterion it made a review item was never applied to the artifact it was about, and P3's *"saga compensation green"* done-clause rests on a guarantee nothing enforces. That is the whole class of bug ADR-006 was accepted to remove, reintroduced at the one seam it was accepted to close.

  **WHAT THE CLAUSE DOES NOT BUY, stated so the signature does not read wider than it is.** The suite proves the adapter's translation and the connection the insert lands on, **with a model of a database and not a database**. It does not prove that `packages/db`'s eventual transaction runner opens a real transaction, that `BEGIN` and `COMMIT` bracket the insert on a live connection, or that a pg-boss version bump keeps `SendOptions.db` meaning what it means today. The first two arrive with the executor of section 6.1; the third is what `CI-04`'s second leg is for. **And the design choices here are not verified by any of it**: five methods rather than six, the six refusals in section 4, and a foreclosure taken deliberately are a founder's read and not a runner's.
