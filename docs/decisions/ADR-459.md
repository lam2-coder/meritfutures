### 3. Why the priced rule is refused, stated as the arithmetic rather than as an opinion

The priced rule is _"no function in `scoped-db.ts` may `throw` outside a function matching the convention"_. Applied to the tree it would ship on:

**IT WOULD BE RED ON 68 SITES ACROSS 24 FUNCTIONS, ON DAY ONE.** That is not a rule with a rough edge. **It is a rule whose finding is the file.**

**AND THE 68 ARE NOT REPAIRABLE INTO IT, WHICH IS THE PART THAT DECIDES THIS.** A rule that is red on code that ought to change is a rule you land after changing the code. These 68 ought not to change. A schema-drift assertion at `:2725` is not a write guard and would be actively worse named `refuseAffiliatesDrift`, because it does not refuse a caller's input: it reports that the database no longer matches the code. A `throw cause` at `:2126` is a rethrow whose entire job is to preserve a cause the transaction needs. Renaming 24 functions to `refuse` something would destroy the very signal the convention carries, which is that a `refuse` name means _this is a rule about what callers may write_.

**SO THE ONLY WAY TO LAND THE PRICED RULE IS AN EXEMPTION LIST OF 24 NAMES**, and [ADR-458](ADR-458.md) section 5 already ruled on that shape one document earlier, about an allowlist inside a rule: it is _"a list a rule change can widen without a reviewer reading the word"_. **A 24-name exemption is worse than that. It is the rule's negation, shipped underneath it, and it would make the control read as complete coverage while covering 13 sites out of 81.** This row will not write it, and it will not weaken the rule's predicate until the exemption list is empty either, because that is the same act performed more quietly.

**THE REFUSAL IS OF THE SHAPE AND NOT OF THE SUBJECT, AND [ADR-450](ADR-450.md)'s PRECEDENT IS TAKEN ONLY THAT FAR.** The hole [ADR-458](ADR-458.md) section 5 names is real, this row confirmed it independently, and refusing to close it because one proposed instrument does not work would be answering a measurement with a shrug. Section 4 is the instrument that does work.

### 4. What is built, and why the predicate is the shape and not the throw

[`merit/refusal-naming`](../../packages/eslint-plugin-merit/rules/refusal-naming.js), attached in [`eslint.config.js`](../../eslint.config.js) over `packages/db/src/**/*.ts`. Two legs.

**LEG 1, THE SHAPE, AND IT IS THE ONE THAT ANSWERS THE MOTIVATING SENTENCE LITERALLY.** A **named** function that throws and **returns nothing** must match `refuse[A-Z]`. "Returns nothing" is an explicit `void` or `never` annotation, or, where there is no annotation, a body with no value-returning `return` of its own. **That second branch is not decoration: it closes the one-character evasion of deleting the return type**, and it is watched closing it in the suite. [ADR-458](ADR-458.md) section 5's own example, _"a refusal written as a helper called `checkCurrency`"_, is caught by leg 1 under any name at all, with no vocabulary guessing anywhere in the predicate.

**LEG 2, THE VOCABULARY, AND IT EXISTS BECAUSE TWO OF THE NINE GUARDS ARE NOT VOID.** `refuseNullBound` at `:771` returns `unknown` and `refuseGeneratedColumn` at `:4685` returns the values it cleared, and `scoped-db.ts` says at its own site that the second shape is **forced by a citation constraint rather than chosen**. Leg 1 cannot see either, because they return a value their caller uses. Leg 2 reaches them: a function that throws and calls itself `assertFoo`, `checkFoo`, `validateFoo` or any of thirteen refusal verbs is a refusal wearing the wrong name, whatever it returns. **This matters more than it looks, because [ADR-458](ADR-458.md) section 11 item 1 prices the NEXT guard as expression-shaped**, so the shape leg 1 cannot see is the shape the next guard is expected to have.

**LEG 2 IS A HEURISTIC AND LEG 1 IS NOT, AND THAT ASYMMETRY IS DECLARED RATHER THAN BLURRED.** Section 8 item 1 prices the hole it leaves.

**THE GLOB IS WIDER THAN THE PRICE AND IT WAS MEASURED BEFORE IT WAS CHOSEN.** [ADR-458](ADR-458.md) priced the rule over `scoped-db.ts` alone. The attachment is `packages/db/src/**/*.ts`, which is all six `.ts` files of the accessor's package: between them they hold **seven named functions that return nothing and throw, and all seven already conform**, so widening costs no exemption. What it buys is one evasion closed, which is **a guard extracted to a sibling file**, somewhere legs A and D of `write-guard-set.mjs` do not read either.

**IT BELONGS IN ESLint AND NOT AS A FIFTH LEG OF `write-guard-set.mjs`, AND THE FENCE IS ONLY THE SECOND REASON.** The first is that the two controls assert different kinds of thing. `write-guard-set.mjs` asserts a relation BETWEEN named things, the matrix of which builder calls which guard, and it is a bespoke runner because no lint rule has that vocabulary. This rule asserts a property of ONE function at a time, decidable from that function's own syntax, which is what a lint rule is. Putting it in the checker would also point it only at `scoped-db.ts`, since that is the file the checker reads, and would give up the sibling-file coverage for nothing. **The second reason is that `write-guard-set.mjs` is owned by PR #742 and out of this fence**, and section 9 records what would have been added there had it not been.

**IT TAKES NO OPTIONS.** `schema: []`. The convention is a ruling recorded in [ADR-458](ADR-458.md) and read by a checker, and an options bag is where a later session widens the pattern without a reviewer reading the word.

### 7. What this check cannot do, stated here rather than discovered later

**IT READS SHAPE AND VOCABULARY, NOT BEHAVIOUR, AND THAT IS THE SAME KIND OF LIMIT [ADR-458](ADR-458.md) DECLARED ABOUT ITSELF.** An expression-shaped guard named `clearedValues`, which is neither void nor spelled with a refusal verb, is invisible to both legs. **That is the one place this rule is weaker than its subject deserves**, and it is exactly the shape [ADR-458](ADR-458.md) section 11 item 1 prices as the next guard. Section 8 item 1 prices what would close it. **A reader who takes this rule as complete coverage of "a fourth rule arrives under the wrong name" is reading it more strongly than it reads itself.**

**`async` IS EXCLUDED AND IT IS NOT AN EXEMPTION BOUGHT TO PASS, THOUGH IT IS THE PLACE A READER SHOULD LOOK HARDEST.** `pairInsertStatement` returns `Promise<void>` and throws 8 times, and it is the single function in the tree that leg 1 would flag if `Promise<void>` counted as returning nothing. **It is not a guard: it is a write BUILDER, async because it performs the insert**, so its observable effect is the write, and its 8 inline throws are already pinned at 8 by leg C of `write-guard-set.mjs`. Demanding it be renamed `refuse` something would demand a builder pretend to be a guard. **The cost is real and is stated rather than buried: an async guard, if one is ever written, is invisible to leg 1.** No guard in this tree is async and none has ever needed to be.

**AN ANONYMOUS FUNCTION IS SKIPPED, AND NOTHING THAT COULD BE A SHARED GUARD IS LOST BY IT.** A `.forEach` callback that throws satisfies leg 1's shape test and is skipped only because it has no name to hold to a naming convention. **A guard must be reachable by name to be called from a builder at all**, so the skip cannot hide one. Inline refusal is leg C's half of the hole and not this rule's. The suite carries that `forEach` case explicitly, as the case that would start firing if the exclusion were ever dropped.

**IT DOES NOT ASSERT THAT A `refuse`-NAMED FUNCTION ACTUALLY REFUSES.** The converse property, that every `refuse[A-Z]` declaration throws, is true 9 times out of 9 today and is **not** enforced here. It is a different hole (a guard that quietly stopped guarding) from the one this row was given, and section 8 item 3 prices it rather than smuggling it in.

**IT IS COUPLED TO NAMES AND SHAPES, NOT TO LINE NUMBERS OR ORDERING.** Reformatting the file, reordering the guards or moving one within its builder leaves it green. What turns it red is a refusal declared under a name the convention does not cover, which is the change it exists to see.
