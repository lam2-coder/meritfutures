## ADR-445: the property is TRUE of every INSERT this tree builds, STRUCTURALLY, and FALSE of every UPDATE, and only building the statements could tell them apart (2026-09-07, status: proposed)

**Row 445 of the 435s wave. Branch `claude/no-statement-writes-generated`, off `origin/main` at `89b02405`, session 640.**

**THE ARTIFACT IS BUILT AND IT IS NOT A GREP.** [`packages/tooling/checks/generated-column-writes.mjs`](../../packages/tooling/checks/generated-column-writes.mjs) folds the generated-column set out of the DDL on every run, then CALLS THE ACCESSOR through a driverless Drizzle handle and reads the column list off the statement the accessor sends. That is [ADR-435](ADR-435.md)'s own move one layer down: *"it is not an approximation of the run, it is the run"*.

**AND THE PROPERTY SPLIT IN TWO UNDER THE FIRST STATEMENT IT BUILT.** An INSERT cannot name a generated column whatever a caller hands it, because Drizzle's insert dialect takes its column list from the TABLE. An UPDATE names whatever a caller hands it, because Drizzle's `.set()` maps over THE CALLER'S KEYS. **5 built UPDATEs in this tree write a stored generated column today**, derived in section 6, and no type refuses them: [`WriteValues`](../../packages/db/src/scoped-db.ts) is `Readonly<Record<string, unknown>>` at line 507 and the accessor's `updateAt` types the ADDRESS against the table's columns and the VALUES against nothing.

**THE COMMISSION'S PREMISE IS THEREFORE HALF WRONG AND THE HALF THAT IS WRONG IS THE LOAD-BEARING ONE.** The dispatch reads *"`$inferInsert` omitting a column is a type fact and a raw `sql` fragment is not bound by it"*. **The accessor does not use `$inferInsert` anywhere on the write path.** Section 5. The type system was never the thing holding the insert half; Drizzle's dialect is, and it holds it against every input.

### 5. The insert half: TRUE, and true STRUCTURALLY rather than by discipline

**THE VALUES OBJECT THE CHECK HANDS THE BUILDER NAMES EVERY COLUMN THE TABLE DECLARES.** That is not an overreach, it is the only question worth asking, and the reason is a type:

    export type WriteValues = Readonly<Record<string, unknown>>;   scoped-db.ts:507

**NOTHING ON THE WRITE PATH IS TYPED AGAINST `$inferInsert`.** `insert`, `insertUnder`, `insertAsParty` and `updateAt` all take `WriteValues`, and `updateAt`'s third parameter is that type while its SECOND is `NamesAColumn<K, A>`: the accessor types the address against the table's columns and the values against nothing at all. So the dispatch's premise, that the type fact holds the insert half and a raw fragment escapes it, does not describe this accessor.

**WHAT HOLDS IT IS DRIZZLE'S DIALECT.** An insert's column list is built from the TABLE's columns minus those that report `shouldDisableInsert()`, and a value for a column not in that list is discarded before a column list exists. **116 of 116 registry keys build an INSERT and none names a member of the set**, with **4** of them on a table that carries one. The leg is falsified in the suite on the real accessor and the real registry, by handing it a set that names `identities.created_at`: the built INSERT names it and the finding is raised.
