### 2. The transcript: ten questions on a PostgreSQL this row started

**PostgreSQL 16.13 (Ubuntu 16.13-0ubuntu0.24.04.1), started in this container**, and a table modelling what `schema.ts` actually declares: an `ALWAYS` identity `id` of the shape all 20 identity columns have, and a `STORED` generated column of the shape `reconciliations.delta_cents` has.

```sql
CREATE TABLE gen_probe (
  id           bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  amount_cents bigint NOT NULL,
  qty          bigint NOT NULL,
  total_cents  bigint GENERATED ALWAYS AS (amount_cents * qty) STORED
);
```

**THE FOUR HALVES, ASKED WITH `\set VERBOSITY verbose` SO THE CODE READ IS THE SERVER'S.**

| # | Statement | SQLSTATE | Message and `DETAIL` | Raised at |
| --- | --- | --- | --- | --- |
| Q1 | `INSERT ... (amount_cents, qty, total_cents) VALUES (500, 2, 1000)` | **`428C9`** | *cannot insert a non-DEFAULT value into column "total_cents"*, `DETAIL: Column "total_cents" is a generated column.` | `rewriteTargetListIU`, `rewriteHandler.c:942` |
| Q2 | `UPDATE ... SET total_cents = 1` | **`428C9`** | *column "total_cents" can only be updated to DEFAULT*, same `DETAIL` | `rewriteHandler.c:977` |
| Q3 | `INSERT ... (id, amount_cents, qty) VALUES (99, 500, 2)` | **`428C9`** | *cannot insert a non-DEFAULT value into column "id"*, `DETAIL: Column "id" is an identity column defined as GENERATED ALWAYS.` plus `HINT: Use OVERRIDING SYSTEM VALUE to override.` | `rewriteHandler.c:903` |
| Q4 | `UPDATE ... SET id = 99` | **`428C9`** | *column "id" can only be updated to DEFAULT*, same `DETAIL` | `rewriteHandler.c:969` |
| Q5 | `INSERT` naming BOTH kinds | **`428C9`** | the identity message; the identity check runs first | `rewriteHandler.c:903` |
| Q6 | `UPDATE` naming BOTH kinds | **`428C9`** | the identity message | `rewriteHandler.c:969` |
| Q7 | `SELECT FROM WHERE;`, the control | **`42601`** | *syntax error at or near "WHERE"* | `scanner_yyerror`, `scan.l:1244` |

**`42601` IS `syntax_error` AND ONLY A PARSE FAILURE PRODUCES IT.** `428C9` is `generated_always`. **The two refusals are raised by the SAME FUNCTION**, `rewriteTargetListIU`, at four adjacent sites in `rewriteHandler.c`, which is the mechanical reason they cannot carry different codes and the reason the docblocks' claim was never going to survive a database.

**THE THREE QUESTIONS THAT FIND WHAT DOES SEPARATE THEM.**

| # | Statement | Result |
| --- | --- | --- |
| Q8 | `INSERT ... (id, ...) OVERRIDING SYSTEM VALUE VALUES (99, ...)` on the ALWAYS identity | **ACCEPTED**, `INSERT 0 1` |
| Q9 | `INSERT ... (total_cents) OVERRIDING SYSTEM VALUE VALUES (...)` on the STORED generated column | **REFUSED, `428C9`**, identical message to Q1 |
| Q10 | `GENERATED BY DEFAULT AS IDENTITY` in a second table, `INSERT` and `UPDATE` naming it | **BOTH ACCEPTED** |

**SO THE DISTINCTION IS REAL AND IT IS NOT THE SQLSTATE.** It is two things: the `DETAIL` line, which names *a generated column* on one half and *an identity column defined as GENERATED ALWAYS* on the other, and `OVERRIDING SYSTEM VALUE`, which **lifts the identity refusal and leaves the generated one standing**. That is what the rewritten docblocks now say, and it is a stronger support for the sentence they open with, *"two different refusals"*, than the false one it replaces.

**`Q10` IS WHY THE WORD `always` IN THE REGISTRY FIGURES IS LOAD-BEARING.** A `BY DEFAULT` identity column is refused by nothing. All 20 identity columns in this registry are `always`, so `databaseWrites` is right to treat `generatedIdentity` as a refusal on this tree; **on a tree that grew one `BY DEFAULT` column the predicate would be over-broad**, and the figure that is currently a reassurance would become the defect. Recorded, not acted on: no such column exists and inventing a guard for one would be pricing a hazard this registry does not have.

**`Q8` AND `Q9` REPRODUCE [ADR-454](ADR-454.md)'s `Q10` INDEPENDENTLY**, on a different cluster in a different container, without that row's table being read first. **Rows 452, 454 and 456 have now measured this on three separate databases and agree.** There is no disagreement to report, and had there been one this section would carry it rather than the ADRs.
