## ADR-144: an admin route is an ordinary route module, and the surface that serves it is selected by the partition that already exists  (2026-08-27, status: proposed)

**No route in this repository had ever been written against the admin origin, so the first one rules how the surface is selected and every admin route after it follows.** This entry is that ruling. It rules that the answer is NOTHING NEW: [ADR-083](ADR-083.md) already partitions the contract over path prefixes, [`surface.ts`](../../apps/api/src/surface.ts) already holds `/admin` among them, and [`registry.ts`](../../apps/api/src/registry.ts) already composes every file in the routes directory, so an admin route is an ordinary route module and [`start.ts`](../../apps/api/src/start.ts) is untouched. It also rules that a READ route still checks a role, that the door an admin read takes is `systemDb('operator-console')` and needs no widening, and that money on the operator surface is swept by name rather than remembered.

- **Origin:** session **256**, [`claude/routes-admin-reads`](../../apps/api/src/routes/admin-reads.ts). The number was **RESERVED REQUIRED before dispatch** and this session chose nothing; the reservation row in [ALLOCATION](ALLOCATION.md) is amended in place under [ADR-065](ADR-065.md) T3 rather than joined by a second row.

- **Not money by content, and sensitive by what it reads.** No migration, no `SD-nn`, no `packages/db` import, no dependency and no gate change. It moves nothing. It reports open liability, the eligibility forecast and the identity graph, which is the read surface [M06](../plans/M06-admin-ops-console.md) `AS-M6-05` calls "nearly as valuable as its write surface".

### 2. THE RULING

> **1. An admin route is an ORDINARY ROUTE MODULE under `apps/api/src/routes/`, and the surface that serves it is selected by the path-prefix partition [ADR-083](ADR-083.md) built and by nothing else.** There is no admin router, no second `buildServer`, no `MERIT_API_SURFACE` branch inside a handler and no edit to `start.ts`. A module whose paths begin `/admin` is registered by the operator deployment and withheld by the public one, and the public deployment's 404 stays the router's.
>
> **2. A READ ROUTE STILL CHECKS A ROLE.** Every endpoint declares the roles it admits, as data, from the closed set `owner | ops | readonly`, and the guard is a membership test over that set. A caller with no operator session is **401**; a session that is not an operator's is **403**; a role string outside the set is **403** and is never defaulted to the least privileged.
>
> **3. The role vocabulary, the operator principal, the operator cookie and the admin problem documents live in `admin-reads.ts` and are EXPORTED.** The concurrent writes module imports them. When a third admin module arrives, they lift to `apps/api/src/admin-auth.ts`.
>
> **4. An admin read reaches rows across identities, so its door is `systemDb('operator-console')`.** The reason needs NO WIDENING and `SqlExecutorReason` is not touched. The data source is a PORT and nothing in this tree wires it, because what is missing is a SHAPE and not an authority.
>
> **5. Every response member whose name ends `_cents` or `_bp` is a safe integer, and every member whose name ends `_day` or `_on` is a `YYYY-MM-DD` trading day**, asserted by a walk over the NAME rather than by a list of fields.
>
> **6. `ADMIN_ORIGIN` stays a placeholder and no host is written**, and that is asserted mechanically rather than remembered.

### 3. Clause 1: the strongest answer available was the one that adds nothing

**Three mechanisms were candidates and two of them are worse than the one that already exists.**

| Candidate | Why it was refused |
|---|---|
| **A second server built from an admin-only module list** | It reopens the question [ADR-083](ADR-083.md) closed. Two `buildServer` call sites are two error handlers, two not-found handlers and two chances for the operator process to answer a public shape. The composition report that names what was registered and what was withheld would then describe half a deployment |
| **A `MERIT_API_SURFACE` check inside each admin handler** | This is the exact degradation [P1](../plans/P1-monorepo-scaffold.md) section 2.1 names, "it silently converts a security control into a URL convention". A handler that runs and then refuses can be reordered, wrapped, or bypassed by a later middleware; a route that was never registered cannot answer anything at all |
| **A `routes/admin/` subdirectory with its own discovery** | `discoverRouteModules` reads ONE directory and has no exclusion list, deliberately: [ADR-100](ADR-100.md)'s rule is that the module list is a directory listing. A second directory is a second list, and the first thing a second list does is disagree with the first |

**The chosen answer is the one that required no code at all, and that is the argument for it.** `classifyPath('/admin/liability')` already returned `operator` before this session existed. Writing a file whose paths begin `/admin` is the whole of what an admin route has to do, and the property is now measured rather than assumed: with the seven registered, `MERIT_API_SURFACE=public` reports **seven withheld** and answers 404 on every one of them.

**THE ONE THING A LATER ADMIN MODULE MUST NOT DO is prefix its own paths with the base path.** `assertContractPath` refuses that at startup, and its message says why: `/api/v1/admin/x` matches neither operator prefix, so it would classify an operator route as public with nothing reporting it.

### 4. Clause 2: what `readonly` costs if nothing checks it

**API_CONTRACT gives all three roles the read surface, so a guard on these seven admits all three, and that is exactly the shape in which a guard rots.** A check that has never refused anybody is indistinguishable from a check that cannot, and the whole content of the word `readonly` is that some other role is not it. So the guard is written to refuse in three directions and all three are exercised:

| Caller | Answer | Why that one |
|---|---|---|
| No operator cookie | **401** | Section 2: 403 is "authenticated but not permitted". Answering it to an anonymous caller confirms the endpoint exists and that the only thing missing is a factor. [`auth.ts`](../../apps/api/src/routes/auth.ts) states the same order for the same reason |
| A session that is not an operator's | **403**, `required_factor: 'admin_sso'` | [API_CONTRACT](../architecture/API_CONTRACT.md) section 12's row "Trader session calls any `/admin/*`". That row names no origin and the row BELOW it says "from the public origin", which is the discriminator: on the public deployment the route is withheld and the answer is 404, and on the operator deployment a real session that is not an operator's is authenticated-but-not-permitted |
| A principal whose role is outside the closed set | **403** | Never defaulted. [`roles.ts`](../../apps/admin/src/roles.ts) states it in the same words: "a string that quietly becomes `readonly` is a typo that granted a session" |
| `readonly`, `ops`, `owner` | **200** | Section 8. `INV-M6-09` is about MUTATION and no route here mutates, so narrowing one would be this module inventing a control the contract does not carry |

**The role arrives as a `string` and not as the closed union, deliberately.** It crosses a boundary with an identity provider, which hands over text. Typing it as the union at the port would move the refusal to a cast somebody writes once and nobody watches.

**The set is written twice and bound by an assertion rather than by an import.** `RI-04` refuses a deployable that imports a deployable, so `apps/api` cannot import `apps/admin`. The suite reads [API_CONTRACT](../architecture/API_CONTRACT.md) section 8's own line and asserts both transcriptions against it, which is stronger than binding them to each other: the primary source is what either of them could drift from.

### 5. Clause 4: the reason fits, and the thing that does not fit is the SHAPE

**This is the finding of the session and it is stated in the direction that was surprising.** The dispatching brief expected the pressure to fall on `SystemReason`, and it does not. `'operator-console'` was accepted by [ADR-102](ADR-102.md) for exactly this dashboard, so an admin read needs no new member and none is proposed.

**What the accessor does not offer is a query shape.** Its whole read vocabulary is `rows(key)`, `rowsWhere(key, filter)` and `rowAt(key, address)`, where a filter is a TYPED EQUALITY over declared columns ([ADR-112](ADR-112.md)). None of the seven bodies is a projection of one table:

| Body | What it needs | What the accessor offers |
|---|---|---|
| `LiabilityResponse` | six aggregates over the whole book, per plan and per PSP | no aggregate |
| `AdminAccountSearchItem` | accounts joined to identities, to open flag counts and to reconciliation state | no join |
| `IdentityGraph` | a walk over link edges with an aggregate at the end | neither |

**The only way to write a live adapter today would be `sqlExecutor`, whose vocabulary has one member and it is not this.** Widening that to smuggle in the SQL the accessor deliberately withholds is the move this entry refuses. So the port is declared, the routes are real, and the adapter is OWED to a slice that holds `packages/db`. That is [ADR-110](ADR-110.md)'s shape one route over, and this entry takes it for the same reason: a port with nothing behind it is honest, and a widened vocabulary is permanent.

**An unwired port is a 500 and never a 404 or a 503**, also [ADR-110](ADR-110.md)'s. "No such account" and "try again shortly" are both this file describing an operational gap as a fact about the estate.

### 6. Clause 5: the sweep reads the NAME, which is what makes it hold for fields nobody has added

[API_CONTRACT](../architecture/API_CONTRACT.md) section 1: "`*_cents` are JSON integers. `*_bp` are JSON integers. No floats, no formatted strings". `GET /admin/liability` reports the books of the firm, so a float there is a float on the books rather than a rounding in a client.

**A per-field check would be a list, and a list goes stale the first time a field is added.** The walk covers every field this contract will ever declare, including the ones inside the untyped drill-down and inside an identity edge's open `evidence` bag.

**Two calibrations are recorded because both were wrong on the first pass and were caught by execution rather than by reading.**

1. **`cusum.statistic` and `cusum.threshold` are floats and are correctly left alone.** They carry neither suffix, so they need no exemption. A CUSUM statistic is a standardised deviation and not an amount of money; rounding it would be the calibration defect [M06](../plans/M06-admin-ops-console.md) `FM-M6-07` names rather than a fix.
2. **A CONTAINER NAMED FOR A DAY IS NOT A DAY.** `eligible_next_7d.by_day` is an ARRAY whose elements each carry a `trading_day`, and a name-only rule refused the shape the contract declares. The rule is type directed: an object or array under a day-shaped name is walked, and anything else must be a `YYYY-MM-DD` string. **This was watched refusing a valid `LiabilityResponse` before it was fixed**, which is the only reason it is right now.

**What it deliberately does not check is `*_at`.** A hand-written RFC 3339 regex either under-checks or refuses legal values, nothing in this fence is load-bearing on that shape, and a gate that fails on correct input is a gate that gets switched off.

### 7. What this FORECLOSES

**Named because an entry that records only the winner leaves the next reader unable to tell whether an alternative was considered or never seen.**

| Foreclosed | What it costs to reopen |
|---|---|
| **A second deployable for the admin API** | [ADR-083](ADR-083.md)'s second-transcription argument, unchanged: it would be a second copy of the error model, the idempotency rule and the pagination rule |
| **Per-handler surface checks** | Reopening it means the public deployment's 404 stops being structural and becomes a check somebody has to keep getting right, on every route, forever |
| **A fourth admin role** | It is a change to API_CONTRACT section 8 and therefore an ADR, not a value a request may carry and not a string an identity provider may invent |
| **Widening `SystemReason` or `SqlExecutorReason` for an admin read** | Both are refused here with the reason stated: the first needs no widening and the second would be a door out of the accessor opened for a dashboard |
| **A default for an unrecognised role** | The refusal is the whole value of a closed set. Reopening it means a typo grants a session |
| **`apps/api` importing `apps/admin`** | `RI-04`. The two transcriptions are bound to the contract instead |

**What stays open, deliberately.** The response projections are hand-written allowlists rather than zod schemas, because [ADR-083](ADR-083.md) ruling 3 names the zod type provider as what will generate the OpenAPI document and no route in this tree uses it yet. Converting these seven is a re-declaration and not a rewrite, and inventing the pattern here with no generator to feed would be guessing at the shape of a thing that does not exist.

### 9. What was watched, in both directions

**The surface boundary, RUN rather than asserted.** The API was started on each surface in turn and every one of the seven was curled with the sources wired:

```
MERIT_API_SURFACE=public    -> merit api: 23 route(s) registered, 7 withheld from this surface
  /admin/liability, /admin/eligible-forecast, /admin/accounts, /admin/accounts/:accountId,
  /admin/identities/:identityId/graph, /admin/flags, /admin/evidence/:accountId  -> 404 on all seven
  /health -> 200

MERIT_API_SURFACE=operator  -> merit api-admin: 8 route(s) registered, 22 withheld from this surface
  the same seven                                                                 -> 401 on all seven
  /health -> 200
```

**404 on one surface and 401 on the other, from the same file, is the whole ruling in two status codes.** The public deployment has nothing at the path. The operator deployment has a route, and it refuses an anonymous caller.

**The guard, RUN against a wired principal source on the operator surface:**

```
(no cookie at all)  -> 401 unauthenticated
tok-trader          -> 403 forbidden   "This session is not an operator session."
tok-norole          -> 403 forbidden   "This session carries no admin role."
tok-readonly        -> 200
tok-ops             -> 200
tok-owner           -> 200
```

**[ADR-012](ADR-012.md), swept over the whole diff.** Every added line was searched for a host-shaped token and for a scheme:

```
git diff origin/main -U0 | grep '^+' | grep -oiE '\b[a-z0-9-]+\.(com|net|org|io|dev|app|xyz|cloud|...)\b'
  -> ZERO.
every scheme-bearing literal added -> https://storage.example.invalid/pack-1
```

`.invalid` is reserved by RFC 2606, resolves nowhere by definition, and can never be somebody's host. **The rule is now mechanical as well**: the suite reads the module and its own source as text and asserts neither carries a host-shaped token, with the needles assembled rather than spelled so the test is not the first thing it has to fail on.

**Three citations in the dispatching brief, checked at source:**

| Cited | Found | Consequence |
|---|---|---|
| `API_CONTRACT:516` for the roles line | the `Roles:` line is at **`API_CONTRACT:622`** | none: the line says what the brief said it says, and the suite parses it by CONTENT rather than by line so this cannot drift again |
| `M06:329` for the `D5` rule | the suite row the brief quotes is at **`M06:452`**. The same stale citation appears in [FOLD-04](../plans/FOLD-04-impersonation-and-admin-parity.md), so the drift predates this session | none for this ruling. **The brief's gloss is also imprecise**: `D5` is [API_CONTRACT](../architecture/API_CONTRACT.md) section 12's **negative-authz matrix**, which is not the same table as `M06` section 11.2's admin parity matrix. It is a matrix and not a test identifier either way, which is the half that mattered |
| the paths `/admin/identities/:identity`, `/admin/accounts/:account`, `/admin/evidence/:account` | the contract writes **`/admin/identities/:identityId/graph`**, **`/admin/accounts/:accountId`** and **`/admin/evidence/:accountId`** | **the contract's spellings are what shipped.** The graph suffix is the one that would have mattered: a route at `/admin/identities/:identityId` serves a path section 8 does not declare |

**Everything else run: `pnpm run verify` exit 0** on every merge of `main`, `repo-invariants` and `gates.mjs generate && check` both whole. **Those two totals are the TREE's rather than this ruling's and they moved while this branch was open**: 11 of 11 invariants and 33 of 33 gates on the current head where they were 10 and 32 when the session began, because `main` added one of each. **This entry adds no gate, no invariant and no `falsify` case.**

### 10. The approval line

- **Founder approval: NOT GIVEN. `status: proposed`, and this line stays UNSIGNED.**

  **What a founder read adds and this entry cannot.** Clause 1 is the load-bearing one and it is a ruling every admin route in this system inherits. It is argued from three documents and measured in two status codes, which is the strongest form the evidence takes here; what it cannot supply is whether the operator surface should be one deployment of this codebase at all, and that question was answered by [ADR-083](ADR-083.md) and is not reopened.

  **The clause this entry is least comfortable with is clause 2 as applied**, and it is named rather than absorbed: all seven endpoints admit all three roles, because the contract does, so the guard on THESE routes has never refused a legitimate operator. What makes it a control rather than a decoration is the three refusals in section 9 and a role set that is closed. **A reviewer who wants one thing checked should check that a later admin read does not quietly become the first one that skips the declaration.**

  **One checkable clause, written in the direction that would be FALSE if the ruling were wrong:** *every path this module declares classifies as `operator`, the public deployment registers none of them and answers 404 on each, the operator deployment registers all of them, and no member of the diff names a host.*

  ```
  # 1. The partition, from the composition report of two real processes.
  MERIT_API_SURFACE=public   PORT=... node --experimental-strip-types src/start.ts
  MERIT_API_SURFACE=operator PORT=... node --experimental-strip-types src/start.ts
  #    -> 7 withheld / 404 on the public surface, 8 registered / 401 on the operator surface.

  # 2. The role guard is not vacuous.
  curl -H 'Cookie: merit_admin_session=tok-norole'  .../api/v1/admin/liability   # -> 403
  curl -H 'Cookie: merit_admin_session=tok-readonly' .../api/v1/admin/liability  # -> 200

  # 3. Nothing outside the fence moved.
  git diff origin/main --stat -- packages/ pnpm-lock.yaml pnpm-workspace.yaml apps/api/package.json
  #    -> empty.
  ```

  **Cost if wrong:** clause 1 failing means the operator surface is selected by something a later session can reorder away, and the public deployment's 404 for `/admin/*` becomes a permission check that has to keep being right on every route forever, which is the failure [P1](../plans/P1-monorepo-scaffold.md) section 2.1 names as invisible for months and a re-platform to undo. Clause 2 failing means `readonly` is a word in a contract and not a boundary in a process, which is `INV-M6-09` reduced to documentation. Clause 6 failing once is unrecoverable: a domain written into a public artifact is in the git history and in whatever mirrored it, and [ADR-012](ADR-012.md)'s whole thesis is that the admin apex is worth protecting because it is not guessable.
