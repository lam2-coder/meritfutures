### 4. The `always` gate, and why the prescribed clause would have refused a legal write

[ADR-451](ADR-451.md):117 and the dispatch both prescribe `column.generatedIdentity === undefined`. **That is not what landed, and the reason is a property of PostgreSQL rather than a preference.**

`GeneratedIdentityConfig` in `drizzle-orm@0.45.2` is `{ sequenceName?, sequenceOptions?, type: 'always' | 'byDefault' }`. **PostgreSQL refuses a write naming a `GENERATED ALWAYS AS IDENTITY` column and ACCEPTS one naming a `GENERATED BY DEFAULT AS IDENTITY` column.** A guard keyed on the property's mere presence would therefore refuse a statement the database allows.

**THAT IS THE EXACT SHAPE OF THE DEFECT THIS CHAIN JUST SPENT A ROW REMOVING.** [ADR-448](ADR-448.md) section 8 item 1 was four test cases asserting a write PostgreSQL refuses; [ADR-451](ADR-451.md) corrected all four. Refusing a write PostgreSQL accepts is the same error pointed the other way, and it would sit in shipped source on the money path rather than in a test.

**IT CHANGES NO NUMBER TODAY.** All 20 are `always`, so the two spellings are indistinguishable on this estate. The gate is what makes the guard still correct on the day somebody adds the first `byDefault` column, and the reasoning is written at the clause rather than left in this file.

### 8. The corpus says `42601` and a real PostgreSQL says `428C9`

**THIS IS THE LARGEST THING THIS ROW FOUND AND IT IS NOT THIS ROW'S SUBJECT.** [ADR-448](ADR-448.md) section 8 item 2 says *"`428C9`, not `42601`"*, which reads as a contrast between the identity half and the stored half. **The stored half's number is also `428C9`.**

A throwaway PostgreSQL **16.13** cluster was initialised in this container, given a table carrying both column kinds, and asked all four questions. `VERBOSITY verbose` prints the SQLSTATE.

| Statement | SQLSTATE | Message |
| --- | --- | --- |
| `UPDATE t SET delta_cents = 99` (STORED GENERATED) | **`428C9`** | *column "delta_cents" can only be updated to DEFAULT* |
| `UPDATE t SET id = 99` (ALWAYS IDENTITY) | **`428C9`** | *column "id" can only be updated to DEFAULT* |
| `INSERT ... (delta_cents) VALUES ...` (STORED GENERATED) | **`428C9`** | *cannot insert a non-DEFAULT value into column "delta_cents"* |
| `INSERT ... (id) VALUES ...` (ALWAYS IDENTITY) | **`428C9`** | *cannot insert a non-DEFAULT value into column "id"*, with the `OVERRIDING SYSTEM VALUE` hint |
| `INSERT ... OVERRIDING SYSTEM VALUE` | none | accepted, which is why the identity half is the one with an override |
| `UPDATE t SET delta_cents = DEFAULT` | none | accepted, which is what "can only be updated to DEFAULT" means |
| `UPDATE t SET our_cents = 11 WHERE id = 1` | none | **the address path, accepted** |

**`42601` IS `syntax_error` AND IS NOT WHAT ANY OF THESE RETURN.** `428C9` is `ERRCODE_GENERATED_ALWAYS` and PostgreSQL uses it for both features, which is consistent with both errors being raised from `rewriteTargetListIU` in `rewriteHandler.c`.
