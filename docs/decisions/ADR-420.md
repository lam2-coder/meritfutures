**THE ROW WAS DISPATCHED AT A QUESTION FOUR ENTRIES CALLED UNRULED WITHOUT WRITING DOWN WHAT THE CHOICES WERE.** [ADR-407](ADR-407.md) section 11 item 1 states it, and [ADR-411](ADR-411.md), [ADR-413](ADR-413.md) and [ADR-416](ADR-416.md) each carry it forward unchanged: *"`LiabilityGapCause` is closed at three kinds of absence, and none of them is a producer this deployment did not install"*. **IT IS READ AT SOURCE HERE AND THE QUESTION IT ASKS TURNS OUT TO BE THE SMALLEST OF THREE**, and the only one of the three that needs no vocabulary at all.

### 3. THE QUESTION, STATED PRECISELY, WHICH IS THE THING FOUR ENTRIES DID NOT DO

The question as inherited is *"what `LiabilityGapCause` does an unwired producer get"*. **THAT PHRASING CONTAINS ITS OWN ANSWER AND IT IS THE WRONG ONE**, because it presupposes that an unwired producer produces a `gaps` entry. Unfolded against the tree, a deployment where a producer is declared and nothing installs it has to answer three separate questions and only the third is about a vocabulary:

1. **AT WHAT GRANULARITY IS THE ABSENCE?** The whole method, or one figure on an otherwise served response.
2. **WHAT DOES THE METHOD RETURN?** A synchronous named refusal, or a 200 carrying `eligible_next_7d: null` and a `gaps` entry.
3. **IF A `gaps` ENTRY, UNDER WHICH `cause`?**

**AND THE SECOND HALF OF THE DISPATCH'S QUESTION, WHAT THE READER SEES, HAS A MEASURED ANSWER TODAY AND IT IS NOTHING.** Derived rather than inherited: `gapCauseRemedy` in [`apps/admin/src/liability-read.ts`](../../apps/admin/src/liability-read.ts) has **NO PRODUCTION CALLER**. A census over `apps/**` and `packages/**` returns the declaration, the package index re-export, and two test files. `WIRE_GAP_CAUSES` has one production use and it is `readGap` REFUSING a cause it cannot branch on, not a render. That file's own header states the reason and it reproduces: *"NO `gaps` ENTRY CAN REACH A FIGURE THIS PAGE RENDERS TODAY"*. So the cause an API row agonises over is parsed, validated, carried, and shown to nobody.

### 5. THE LAYER RULE, DERIVED FROM THREE INSTANCES AND ONE DELIBERATE OMISSION

**THIS TREE ANSWERS DEPLOYMENT INCOMPLETENESS WITH A NAMED THROW AT THE LAYER WHOSE SUPPLIER IS MISSING, AND NEVER WITH A MEMBER OF AN ABSENCE VOCABULARY.** The fourth instance is the one that decides it, and it is inside this fence: [`eligible-next-7d.ts`](../../apps/api/src/admin-source/eligible-next-7d.ts) declares `EligibleFoldRefusalCause`, a closed vocabulary of four, beside `EligibleFoldRefused` carrying `cause`, `awaiting` and `detail` in `LiabilityGap`'s exact idiom. **THE UNWIRED PORT IS NOT ONE OF THE FOUR.** `UNWIRED_ELIGIBLE_FOLD_IO` THROWS `EligibleFoldUnwired` rather than returning `{ kind: 'refused' }`, on a file that had every reason to add a fifth member and did not.

**AND THE VOCABULARY'S OWN RULE SAYS WHY.** `LiabilityGapCause`'s declaration takes `SystemReason`'s rule from [ADR-165](ADR-165.md), that it *"DOES NOT NAME SERVICES, IT NAMES KINDS OF ACCESS"*, and adds that each member is *"A DIFFERENT ACT BY WHOEVER READS THE PANEL"*. `GAP_CAUSE_REMEDY` is that sentence made total: a map from cause to what the reader DOES. **AN UNINSTALLED PRODUCER AFFORDS THE PANEL'S READER NO ACT.** The remedy is a deploy, taken by somebody who is not looking at the panel. A fourth member would carry a remedy string reading "there is nothing you can do", which is the bare null the vocabulary exists to refuse, spelled.

**THE PORT IS ALSO NOT A DEPLOYMENT SETTING, WHICH REMOVES THE LAST REASON TO WANT THE MEMBER.** `readEligibleNext7d(tx, calendarTx, io, asOf)` takes `io` as a REQUIRED positional parameter with NO default. A deployment supplies a real port or names `UNWIRED_ELIGIBLE_FOLD_IO` deliberately. There is no configuration under which a caller silently ends up unwired, so there is no state for a wire cause to describe.

**RULING. `LiabilityGapCause` DOES NOT GAIN A MEMBER FOR AN UNWIRED PRODUCER, AND `readLiability` ON SUCH A DEPLOYMENT ANSWERS `AdminSourceNotComposed('readLiability')`, WHICH IS WHAT IT ALREADY ANSWERS.** [ADR-407](ADR-407.md) section 11 item 1 is therefore not a blocker in front of this method. It dissolves. **This ruling is takeable from this fence precisely because it edits none of the forbidden files**: a ruling that a vocabulary stays closed needs no diff on the file that declares it.

### 6. THE TWO HOLES THAT ARE REAL, WHICH NO ENTRY HAS NAMED

**`toWireEligibleNext7d` TAKES THE `folded` ARM ALONE.** Its parameter is `EligibleNext7dFigure` and not `EligibleNext7dOutcome`, so **NO FUNCTION IN THIS TREE MAPS A FOLD REFUSAL ONTO A `gaps` ENTRY.** The mapping is unwritten, and when somebody writes it they will find it is not total. Every `awaiting` below was derived by EXECUTING the arm, not read off the source:

| Fold cause | `awaiting` | Honest `LiabilityGapCause` for THIS field |
|---|---|---|
| `calendar_uncovered` | `null` | `estate_uncovered` |
| `horizon_exhausted` | `null` | `insufficient_history` |
| `no_folded_state` | **`'a nightly runNightlyBatch run against this database'`** | **NONE** |
| `projection_refused` | `null` | **NONE** |

**HOLE 1, AND IT IS A CONTRADICTION BETWEEN TWO LIVE RULINGS RATHER THAN A GAP IN A VOCABULARY.** `assertLiabilityGapsPaired` makes `awaiting` non-null EXACTLY when the cause is `awaiting_dependency`. `no_folded_state` carries an `awaiting`, so carrying it to the wire FORCES `awaiting_dependency`, and [ADR-203](ADR-203.md) ruling 8 with [ADR-204](ADR-204.md) ruling 9 exclude that cause for this field. Dropping the `awaiting` to fit is deleting the one thing an operator could act on, on the morning the fold's own comment says *"the firm owes nothing on the morning it may owe the most"*.

**HOLE 2. `projection_refused` IS AN ASSEMBLY DEFECT AND THE VOCABULARY HAS NO KIND FOR ONE.** Its own detail says so: *"a horizon this assembly built wrongly rather than a day the estate has no opinion about"*. `awaiting` is null, so `awaiting_dependency` is closed to it by the validator, and the other two describe the estate. The remedy is to page an engineer.

**BOTH ARE REACHABLE WITH `B5` FULLY SPENT AND EVERY PORT WIRED**, which is what makes them worse than the one that was carried for four entries. An unrun nightly batch is an ordinary Tuesday.

### 7. WHERE THIS ROW WAS TEMPTED TO WIDEN A DEFINITION AND REFUSED

**IT COULD HAVE RULED HOLE 1 BY READING `awaiting_dependency` AS "A RUN IS OUTSTANDING".** The member's own gloss is *"a named deliverable is outstanding"*, and a nightly batch run is nameable, which is exactly the widening that would type-check, pass `assertLiabilityGapsPaired`, pass 33 gates and contradict a ruling in three copies. **It is refused, and the reason it is refused is that the field's causes were fixed by a ruling and not by the type**, which is [ADR-407](ADR-407.md) section 6's ground re-derived rather than inherited.

**IT COULD ALSO HAVE COMPOSED A REFUSAL-TO-GAP MAPPER IN FENCE.** `eligible-next-7d.ts` is this row's file and a `toWireRefusal` would have landed green. It would have required choosing a cause for the two holes, which is the ruling this row says is a founder's, so writing it would have been ruling by implementation. **The absence of that function is now asserted rather than merely true.**
