### 7. Whether that is worth closing, what closing it costs, and the recommendation

**IT IS WORTH CLOSING. IT IS NOT CLOSED HERE AND IT SHOULD NOT BE BOLTED ONTO A REPAIR.** A control that arrives in the same diff as the defect it would have caught has no counterfactual, which is this tree's standing rule for a new check and the reason [ADR-433](ADR-433.md) is a row of its own. **What follows is a price and a recommendation, not a design.**

#### 7.1 Three candidate controls, priced

**(a) TWO NEW `RI-35` REGISTER ENTRIES, ON `provisioning-ports-workspace-import`'s SHAPE.** Cost: roughly sixteen lines each at `absence-claims.mjs:761-776`'s size, in a file held by row 435 this wave. **REJECTED, and section 6.3 is why: the shape does not reach the defect.** A denylist entry goes red when a NAMED specifier appears and is silent when any other import does. It would have been green through both [ADR-426](ADR-426.md) and [ADR-430](ADR-430.md). **This is the cheapest option and it buys nothing, which is worth writing down so the next row does not reach for it.**

**(b) A GENERAL INVARIANT THAT READS ANY HEADER'S IMPORT CLAIM AND CHECKS IT.** **REJECTED, AND `RI-14`'s OWN DESIGN NOTE RULES IT OUT IN ADVANCE.** [`repo-invariants.mjs:1879-1884`](../../packages/tooling/checks/repo-invariants.mjs): *"It reads ONE shape: a claim that a NAMED thing does not exist. Not "is blocked", not "has no driver" ... those are claims about behaviour and about vocabularies, they are argued rather than looked up, and a check that pretended to read them would be a check somebody switches off."* The six claiming headers in section 5 spell their claim six different ways and two of the spellings are universals. **Recognising them is natural-language classification, and the failure mode is not a false positive but a check nobody trusts.**

**(c) A REGISTRY: one row per claiming header, holding the file, the exact claim sentence, and the import list that sentence asserts, checked mechanically.** **THIS IS THE ONE THAT CLOSES IT.** Its cost, stated honestly:

| what it needs | size |
| --- | --- |
| one new `RI-nn`, minted with a reserved number | one entry, plus its `covers` text, which in this tree runs to a screen |
| the registry itself | **six rows today**, section 5's table, each carrying a verbatim sentence and an expected import list |
| a seeded counterfactual per row, watched failing | six seeds, restored byte-identical, which is this tree's standing discipline for a new check |
| the pin that keeps the registry honest | an assertion that every `ports.ts` under `apps/worker/src` making an import claim HAS a row, or the registry becomes the thing that goes stale |
| fence | `packages/tooling/checks/**`, held by row 435 this wave, so it cannot be taken until that row lands |

**Comparable in size to [ADR-433](ADR-433.md)'s widening row.** Not to this one, which is comment text.

#### 7.2 The argument each way, with the measurement that settles it

**FOR.** The counterfactual is concrete and it is the reason to believe (c) works: **a registry row is CODE, and [ADR-426](ADR-426.md) would have had to edit it in the same commit that added the import, or watch a red run.** A header sentence one hundred and fourteen lines above the import is neither code nor adjacent, and section 3.2 shows an author who KNEW the idiom, APPLIED it correctly to a deleted type in that very diff, and did not carry it to the top of the file. **This is the third row in five to repair a false self-description**: [ADR-432](ADR-432.md) corrected its own, [ADR-434](ADR-434.md) corrected two on the ledger barrel, and this one corrects two more. **A defect class that produces a repair row every other wave is paying for a control.**
