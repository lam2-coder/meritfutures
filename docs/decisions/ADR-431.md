### 3. The premise, re-derived at source, and the part of it that is wrong

The dispatch said `RI-35`'s probe fires on a prettier reflow, that [ADR-415](ADR-415.md) raised it, and that leg 1's verbatim single-line anchor is *probably where the reflow sensitivity comes from*. **THE FIRST TWO ARE RIGHT AND THE THIRD IS WRONG, AND THE THIRD IS WRONG IN A WAY THE FILE ITSELF ALREADY SAYS.**

[ADR-415](ADR-415.md) section 6 is about the PROBE and never about leg 1. Its sentence is that `event-sink-caller`'s *"proxy for a value position is `TRANSACTION_EVENT_WRITER` followed by `.`, `,` or `)`, and a name inside a re-export SPECIFIER LIST is followed by a comma while being a binding position and not a value position at all"*. That is one mechanism. Leg 1 is a different one, and `absence-claims.mjs`'s own docblock on the `claim` field states the design: *"a VERBATIM substring of a single line of `site`. Single-line on purpose: a multi-line anchor breaks the first time prettier reflows a comment and would make leg 1 fire on formatting rather than on drift."* **LEG 1 WAS BUILT AGAINST THE REFLOW THE DISPATCH SUSPECTED IT OF.** Section 8 measures what it is still exposed to, which is real and is not this.

**A SIBLING'S SUMMARY IS NOT PRIMARY SOURCE AND THIS ROW READ BOTH.** [ADR-419](ADR-419.md)'s rewrites of five `sweptBy` strings and [ADR-417](ADR-417.md)'s deletion of eleven derived integers were read before anything in this file was changed; leg 7 and the `census` shape they produced are untouched here.

### 4. The defect, demonstrated before it was repaired

**A DEFECT NOBODY CAN SHOW FIRING IS A DEFECT NOBODY CAN SHOW FIXED**, so every red below was produced in a throwaway `git worktree` at `d915dc14`, driven by the SHIPPED `ri35.run` against that worktree as its root, with the working tree never carrying the seed. The worktree was `git checkout -- .` clean between every case and after the last.

**The control first:** `ri35.run` over the pristine worktree reports **0 findings**.

#### 4.1 The verbatim red

Changing `packages/ledger/src/index.ts` line 175 from `export { TRANSACTION_EVENT_WRITER } from './events.ts';` to the same export written across three lines, **with the same binding published from the same module and nothing else in the tree touched**, produces:

> `apps/api/src/events.ts` says "`makeEventSink` is called by NO file" AND an INSTALL of the event producer: a call to `makeEventSink` or a use of `TRANSACTION_EVENT_WRITER` in a value position, under any `src/`, past the module that declares both. [...] EXISTS. The sentence is false and this is the check going red at it rather than a later session reading it and being sent to do work already done. Repair the sentence, then move its register entry to `retired` so the quote kept beside the correction stays bound.

**THE SENTENCE IT NAMES IS TRUE.** Nothing installs the sink. The check has reported an artifact into existence off a line break.

#### 4.2 And prettier produces it, with the exported surface held identical

The form above is one prettier would COLLAPSE, so on its own it is a hand reflow that `format:check` would catch. **THE FORMATTER REACHES THE SAME RED BY ITSELF.** Three names already exported from the same module in the block above were moved onto the writer's statement, leaving `packages/ledger/src/index.ts` exporting **exactly the same set of bindings from exactly the same module**. `prettier --write` then split the statement into a list of four, `trailingComma: "all"` put a comma after the writer, and `ri35.run` reported the same single finding. **The red survives `format:check`, because prettier wrote it.**

#### 4.3 The line break was never the trigger, which is where this row parts company with ADR-415

[ADR-415](ADR-415.md) section 6 says *"WHAT HOLDS THE GREEN TODAY IS A LINE BREAK"*, and `packages/ledger/src/index.ts` carries a comment saying the same in its own words and asking the next reader not to add a second name to one export statement. **MEASURED, THAT ACCOUNT IS HALF WRONG.**

| spelling of the same publication | old probe |
|---|---|
| `export { TRANSACTION_EVENT_WRITER } from './events.ts';` | `absent` |
| the same name alone, wrapped, with `trailingComma: "all"`'s comma | **`present`** |
| `export { TRANSACTION_EVENT_WRITER, makeEventSink } from './events.ts';`, ONE line, no reflow at all | **`present`** |
| `export { makeEventSink, TRANSACTION_EVENT_WRITER } from './events.ts';`, ONE line, writer LAST | `absent` |

**THE COMMA THE PROXY READS IS THE SEPARATOR, AND THE SEPARATOR ARRIVES WITH THE SECOND NAME WHETHER OR NOT THE STATEMENT WRAPS.** What held the green was that the list had exactly ONE name. A list ending in the writer stays green however it is wrapped, because a brace follows the name. Prettier is one route in, through the trailing comma on a wrapped list, and it is not the mechanism.

**THIS ROW GOT THAT WRONG ONCE, IN ITS OWN TEST FILE, AND THE MEASUREMENT CAUGHT IT.** The one-line case was first written with the writer LAST in the list, where no comma follows it; run against the old check it PASSED, and a case that passes on both behaviours binds nothing. It is corrected, the correction is in the fixture's own comment, and it is the reason row 4 of the table above exists.

### 5. The repair, and the two alternatives priced rather than dismissed

The two caller probes now blank every `import` and `export` SPECIFIER LIST before reading a line, on source whose comments `stripComments` has already removed. A name in a specifier list is a binding position by TypeScript's own grammar and never a value position, which is the whole of the argument.

| candidate | verdict | why |
|---|---|---|
| exclude the barrel by path | **REFUSED** | a second exclusion, and it blinds the probe to a real install written in a barrel. It is also the repair [ADR-415](ADR-415.md) already priced and refused |
| drop the punctuation proxy, treat any surviving occurrence as a value | **REFUSED, AND THE REFUSAL IS MEASURED** | after comments and specifier lists are gone an identifier really is a value or a declaration, so this is tempting. Derived over the shipped scope: it reports `present` on **five files under `apps/worker/src`** whose refusal STRINGS name `TRANSACTION_EVENT_WRITER` in order to say this deployable installs none, and `stripComments` cannot remove a string literal. That is the same false red through a wider door |
| blank the specifier list, keep the proxy | **TAKEN** | excludes no file by path, parses nothing, and is therefore neither of the two widenings ADR-415 was forbidden |

**THE SPAN BLANKED IS THE BRACE AND NEVER THE LINE**, and that is load-bearing rather than tidy. An import and an install written as ONE statement is a line the shipped tree does not carry today and is exactly the line a line-scoped repair loses. The per-line `reexport` heuristic that `replay-audit-src-caller` already carries three artifacts away discards any line containing `from '` or `export {`, which is **5,166 whole lines** of the stripped shipped scope; the brace-scoped helper removes **77,651 characters** and no line's non-specifier content.

**THE REGEX WAS VALIDATED BEFORE IT WAS TRUSTED.** Over the shipped scope it matches **1,393 spans**, longest **2,235 characters** (a real named-import list in `packages/db/src/scope.ts`), and **ZERO** of them contain a statement keyword, an arrow or a semicolon inside the braces. It cannot match `export default function f(a) {`, `export const x = {`, `export type X = {`, `export class C {` or `export interface I {`, because the only things admitted between the keyword and the brace are an optional `type` and an optional default binding followed by a comma.

**NO VERDICT ON THE REAL TREE MOVED.** All four caller probes, before and after: `worker-queue-door-caller` **`present`** both sides, `event-sink-caller` **`absent`** both sides, `provisioning-saga-caller` **`absent`** both sides, `replay-audit-src-caller` **`absent`** both sides. `RI-35` is green over the tree before and after, and every reflow in section 4 is green after.

### 6. WHAT THE REPAIR NO LONGER CATCHES

**ONE THING, AND IT IS AN ACCIDENT RATHER THAN AN INTENT.** A file that imports the name in a MULTI-NAME list and then installs it in a shape the proxy does not recognise used to read `present` off the import's own comma. It now reads `absent`.

**THAT BACKSTOP WAS NEVER AIMED AND IT WAS ALREADY HALF GONE.** The proxy reads `.`, `,` and `)` and nothing else, so `const sink = TRANSACTION_EVENT_WRITER;` in a file whose import is on a statement of its own was missed BEFORE this repair; the same assignment behind a two-name import was caught only because the import had a comma in it. **The hole predates the repair and what this narrows is the accident, not the intent.** Closing the hole properly means widening the value-position class, which is a change to what the probe asserts and not a repair to how it reads formatting; it is named in section 10 and not taken.

**EVERY INSTALL THE PROBES WERE WRITTEN TO CATCH IS UNTOUCHED**: a call of the factory, the name in an argument position, the name under a member access, and `LIVE_QUEUE` handed to a factory, which is the shape [ADR-338](ADR-338.md) found the wiring actually took. Section 7 binds all of them.

Against the repaired check: `92 passed`.

**FOUR CASES STOP THIS BEING A QUIET WEAKENING, AND THEY ARE THE MORE IMPORTANT HALF.** A real install reached through a multi-name import list; the same through a member access behind one; an install sharing a line with its own import; and `checkAbsenceClaims` itself going RED at the claim site with the sentence named, so the repair is watched where a reader meets it rather than only at the probe.

### 8. Leg 1's own formatting sensitivity: found, demonstrated, and REFUSED with the measurement

**THE DISPATCH'S SUSPECT IS GUILTY OF SOMETHING ELSE.** Leg 1 does break on a rewrap, and it was watched breaking: splitting the anchor line of `apps/api/src/events.ts` through the middle of the registered substring, **with the words identical and prettier reporting the file clean**, gives

> `apps/api/src/events.ts` carries the registered claim "`makeEventSink` is called by NO file" 0 times. The sentence moved, was reworded or was deleted [...]

and rewrapping the same paragraph at a point OUTSIDE the anchor leaves leg 1 green. **THE EXPOSURE IS WIDE**: 29 of 33 anchors sit on comment lines, **24 of 33 cover 80% or more of their line**, and the median line carries **5 characters** the anchor does not.

**AND THE FORMATTER DOES NOT DO IT.** `prettier --write` over the whole `format` glob in the worktree changed **ZERO files** and left `RI-35` at 0 findings. `.md` and `.sql` are not in prettier's scope at all, and prettier does not rewrap comment prose in the JavaScript family. **Leg 1's exposure is to a HAND rewrap.**

**THE REPAIR IS REFUSED AND HERE IS THE PRICE.** Whitespace normalisation, the dispatch's first candidate, was measured and repairs **nothing**: **0 of 33** anchors carry leading, trailing or internal multi-space whitespace, so there is no whitespace in this register for a formatter to move. The only repair with teeth is comparing across line boundaries, and it costs the property the register is built on: leg 1's contract is a verbatim substring of ONE line, legs 2 and 3 assert about the site it identifies, and a whole-file normalisation that strips comment markers can match a sentence assembled from a comment and the code under it, binding the register to a coincidence.

**THE DECIDING ARGUMENT IS WHAT EACH FALSE RED TELLS ITS READER TO DO.** A leg 1 break says the sentence moved and the register did not move with it, and the correct response is to move the anchor, which is cheap and is what the finding already instructs. **THE PROBE'S FALSE POSITIVE ARRIVES WITH INSTRUCTIONS THAT ARE ACTIVELY WRONG**: it says *"Repair the sentence, then move its register entry to `retired`"*, and a row that follows it retires a TRUE absence claim and blinds the register permanently, at the direction of a check that reported an artifact into existence off a comma. That asymmetry is why one is repaired here and the other is named.

### 12. Approval

**Status `proposed`. The approval line below is UNSIGNED and merging is not signing.** [ADR-415](ADR-415.md), whose section 6 this row answers, is itself `proposed` and unsigned on this row's base, as is [ADR-410](ADR-410.md), which owed the registration in the first place.

- **What a founder read adds and this entry cannot.**

  **THE FIRST DECISION IS WHETHER A REPAIR THAT MAKES A CHECK EASIER TO SATISFY IS EVER SAFE, AND THIS ROW SAYS THE QUESTION IS BADLY PUT.** Every repair to a false positive makes a check easier to satisfy; that is what repairing a false positive IS. What separates it from weakening a gate is whether the thing it stops reporting was ever true, and the only honest way to settle that is to say what the repair no longer catches and then go looking for it. Section 6 names one loss, section 7 seeds four cases against it, and section 5 records a candidate repair that was REFUSED because the measurement said it would cost five true sentences. **A founder pricing this programme should note that the refusal cost one script and produced a number, and that the row could not have argued it from reasoning.**

  **THE SECOND IS WHETHER A CHECK MAY INSTRUCT A READER TO WEAKEN THE REGISTER.** Section 8's deciding argument is not that the probe's false red was more frequent than leg 1's, because it was not; it is that the probe's finding text tells the reader to retire a TRUE claim, and a reader who complies has permanently blinded the register at the direction of the check. **A founder should decide whether a finding that recommends a register edit needs a different shape from one that recommends a code edit**, because this register has several of the first kind and nothing distinguishes them.

  **THE THIRD IS THE ONE WITH A COST ALREADY PAID.** Two entries in three waves have now recorded that the correctness of a repository invariant rested on a formatter's line-width heuristic, and BOTH accounts of the mechanism were wrong: [ADR-415](ADR-415.md) said the line break held the green, `packages/ledger/src/index.ts` says so in a comment to this day, and section 4.3 shows a one-line edit that fires with no reflow and a wrapped edit that does not fire at all. **The estate has been carrying a precise-sounding explanation that nobody executed.** A founder should decide whether a registered false positive is allowed to stand on a description at all, or whether registering one should cost the case that fires it, which is what this row's fixtures would have forced two waves ago.

  **AND THE FOURTH IS THE ONE THIS ROW WOULD KEEP IF IT KEPT ONE.** Leg 1 is one hand rewrap away from a false red on 24 of its 33 anchors, and this row refused to repair it because prettier does not do it and the failure is self-announcing. **That is a judgement about who edits this tree, not a property of the check.** It was correct on the day it was measured. A founder should decide whether an anchor that covers 95% of its line is a design or a liability, because the answer this row gave assumes the next reader is careful, and this register exists precisely because that assumption failed four times.
