## ADR-154: tier 1's boundary is an ARTIFACT and tier 2 has none, so the simulator implements `streamLive` and the shared thing becomes the TYPE  (2026-08-27, status: proposed)

**[`154`](ALLOCATION.md) was reserved CONDITIONALLY, for the case where planning `P6` met a contradiction between what [ADR-020](ADR-020.md) rules and what the tree can express. It met one on the first stated content.** ADR-020 rules that the real feed plugs in *"exactly as the batch pipeline already does"*. **The batch pipeline's mechanism is a FILE**, and [M02 section 3.5](../plans/M02-rithmic-bridge.md)'s `streamLive` hands its consumer objects. There is no file, no ingest directory and no parser in tier 2, so the sentence names a mechanism with no tier-2 instance, and each of the two readings that remain is refused by a landed document.

**The sentence [ADR-020](ADR-020.md) itself links to is one of the two that this ruling edits.** Its tier 2 clause links the words *"platform adapter"* to [GLOSSARY:298](../GLOSSARY.md), whose body enumerates five operations and ends *"v1 ships one implementation (Rithmic)."* **Both of those clauses are false the moment tier 2 ships**, and neither is false today.

- **Origin:** [P6](../plans/P6-live-tier.md), planned as session **265** on branch `claude/p6-planning`. The number was **RESERVED BEFORE DISPATCH and CONDITIONAL** ([ALLOCATION](ALLOCATION.md)), so none was chosen here; the `154` row is amended **in place** per [ADR-065](ADR-065.md) T3.

- **NOT MONEY PATH BY FILE.** No migration, no `SD-nn`, no ledger, no engine, no payout, no auth. [ADR-003](ADR-003.md)'s strict regime does not bind. **It is worth a founder read anyway, and section 6 says why**: the thing being moved is the boundary that makes *"the stream never feeds a money decision"* a compiler fact rather than a reviewer's memory.

### 2. THE RULING

> **1. THE SIMULATOR IMPLEMENTS `streamLive`, AND `streamLive` JOINS `PlatformAdapter`.** Finding 6's argument is about a PARSER, and it is correct about one: in file mode the parser is the thing both sources must traverse and a simulator implementing `ingestEOD` would skip it. **In tier 2 there is nothing to skip.** Absorbing the mechanism difference is the adapter's entire job here ([M02 section 3.5](../plans/M02-rithmic-bridge.md): *"The adapter absorbs the difference, exactly as it already absorbs report shape, so the consumer sees one stream either way"*), so between the wire and the tick there is the adapter and nothing else. **A rule read past its own stated reason is a rule nobody can apply**, and finding 7 shows the reason is cited to a file-mode scenario.
>
> **2. THE SHARED THING MOVES FROM THE ARTIFACT TO THE TYPE, AND `LiveAccountTick` WAS ALREADY BUILT TO BE IT.** Findings 11 and 12. `indicative: true` as a required literal, a per-account-per-day `sequence` so a lost tick is distinguishable from a quiet market, and `Cents` as `bigint`. **In tier 1 the thing both sources produce is a CSV file; in tier 2 it is this type**, and the discipline `INV-M2-11` names survives in the only form tier 2 can carry it.
>
> **3. IT REACHES `streamLive` AND NO OTHER OPERATION, AND THAT REFUSAL IS THE LOAD-BEARING HALF.** `provision`, `entitle`, `ingestFills`, `ingestEOD` and `reconcile` are still not implemented by the simulator, for finding 6's reason, which is undisturbed for all five. **The argument "the simulator implements one method, so it may implement the others" is foreclosed here in advance**, because it is the argument that will be available and it is wrong for exactly the reason clause 1 gives: those five have a parser and this one does not.
>
> **4. `GS-084`'s PROPERTY HAS NO TIER-2 ANALOGUE AND `P6` MUST NOT CLAIM ONE. What replaces it is a CONFORMANCE assertion over every implementation.** "No downstream code branches on source" is purchasable only where both sources write into one directory. With two implementations of one method there is nothing to branch on and nothing proved by saying so. **The assertion worth running is that every `streamLive` implementation emits ticks satisfying the same stated invariants** (monotone `sequence` per account and trading day, `indicative: true`, `atUtc` inside the session bounds), run over each implementation rather than asserted of the interface. Finding 10 is the corpus already accepting the shape.
>
> **5. THE INTERFACE'S OPERATION LIST IS AUTHORITATIVE IN [OVERVIEW section 3](../architecture/OVERVIEW.md) AND THE THREE SITES MOVE IN ONE CHANGE.** Finding 2's test reads OVERVIEW by name, so the row, the [GLOSSARY](../GLOSSARY.md) entry and the test are one edit or they are a contradiction that type-checks. **Both documents are `approved`, which is why this is an entry rather than a commit.** [GLOSSARY:299](../GLOSSARY.md)'s *"v1 ships one implementation (Rithmic)"* is amended in the same change: v1 ships one VENDOR implementation and a simulator that implements the streaming operation only.
>
> **6. THIS ENTRY DESIGNS NEITHER THE CACHE, NOR THE CONTAINER, NOR THE SOCKET.** [P6](../plans/P6-live-tier.md) section 10 items 1 and 2 carry them, each needs a migration or an architecture amendment, and **a ruling that took them here would be designing storage from a planning session**, which is [ADR-124](ADR-124.md)'s refusal one phase over.

### 4. THE ALTERNATIVES, AND WHY EACH IS REFUSED

| Alternative | Refused because |
|---|---|
| **The simulator does NOT implement `streamLive`, and the live consumer is written against `streamRun` in development and a vendor adapter in production** | **Two code paths for the surface a funded trader watches all session**, which is the exact failure `GS-084` exists to prevent for tier 1 and which [M02](../plans/M02-rithmic-bridge.md) `FM-M2-12` names by hand: *"Simulator and vendor diverge: every test passes and production breaks."* It also strands finding 10, whose `V-M2-16` conformance case has no interface to conform to |
| **Invent a tier-2 artifact so the file-mode seam reproduces**, for example a tick file the simulator writes and an adapter tails | **It is a parser built to justify a rule rather than to do work**, and it makes the polled mechanism finding 12 already handles into a second writer of a format nobody consumes. It also puts a disk between a live feed and a dashboard, which is latency added to buy a property the type already carries |
| **Leave the contradiction and let whoever builds `P6-a` choose** | This is the shape [ADR-072](ADR-072.md) and [ADR-125](ADR-125.md) both found the cost of: a decision made inside a slice is a decision nobody can cite. **The two readings are refused by two different documents and a session that picks one is silently overruling one of them** |
| **Rule that `INV-M2-11` simply does not reach tier 2, and delete rule 4's claim** | **It is the cheapest edit and it loses the thing rule 4 was reaching for.** The discipline is worth keeping and clause 2 is the form in which tier 2 can keep it; deleting the claim would leave tier 2 with no stated equivalence property at all |
| **Widen `PlatformAdapter` with a second interface instead**, for example `LiveAdapter` | **A second interface is a second place a vendor specific can leak**, which is the sentence finding 2's test exists to defend. It also contradicts [M02 section 3.5](../plans/M02-rithmic-bridge.md)'s own words: *"the adapter interface gains **one method**"* |

### 6. Founder approval

**One checkable clause, and it carries the direction it fails in.**

> **Three sites enumerate `PlatformAdapter`'s operations and all three say FIVE with `streamLive` absent** ([`packages/rithmic/src/index.ts`](../../packages/rithmic/src/index.ts), [OVERVIEW section 3](../architecture/OVERVIEW.md)'s `packages/rithmic` row, and [GLOSSARY:299](../GLOSSARY.md)), **[`adapter.test.ts`](../../packages/rithmic/test/adapter.test.ts) asserts that key set exactly and cites OVERVIEW as its authority, and [`stream.ts`](../../packages/rithmic/src/simulator/stream.ts) already exports a producer of `LiveAccountTick`, the type [M02 section 3.5](../plans/M02-rithmic-bridge.md)'s `streamLive` signature names.**

**Executed, and the outputs are in the pull request.** Every citation in section 1 was read at its file before this entry was written, and the two greps the dispatch warned had been got wrong twice were replaced by building the server and by running the build.

**The direction it fails in.** If the clause is wrong and `streamLive` is already on the interface somewhere, this entry rules on a contradiction that does not exist and the cost is an entry nobody needs. **If it is right, which is what the files say, then `P6`'s first stated content cannot be started by any session without either overruling a package header or shipping two code paths for the live feed**, and the session that meets it will make that choice inside a slice where nobody can cite it.

**What a founder read adds and this entry cannot.** Every fact in section 1 is a file's own words. **Clause 1 is not.** It reads a landed refusal past its stated reason and concludes the reason does not reach tier 2. That is a judgement about how narrowly a written rule binds, **and the failure mode of getting it wrong is that a simulator becomes a mock at a boundary somebody later discovers was real.** Section 4's second row is the alternative that keeps the artifact, and it is refused for a reason of taste as much as of cost, which is exactly the kind of reason a founder should get to overrule.

**Approval line: UNSIGNED.**
