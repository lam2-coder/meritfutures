### 3. `psp_clearing`, and the sentence one line above the one two entries read

**The tree states this code's nature TWICE and both statements are asset-shaped.**

> [`checkout.ts:1681-1682`](../../apps/api/src/routes/checkout.ts): crediting a clearing account *"would book a receivable from a processor that was never asked for money"*.

That is the sentence [ADR-177](ADR-177.md) section 4 and [ADR-181](ADR-181.md) section 2 each quote. **A receivable is an asset.** [ADR-177](ADR-177.md) is right that the sentence's VERB is backwards for one, because crediting an asset reduces a receivable rather than booking one, so it cannot be read as a sign-checked derivation. **It is not being read as one.** What is read is the noun, and the noun is a class word.

> [`checkout.ts:1679`](../../apps/api/src/routes/checkout.ts): *"There is no processor in this transaction, so there is nothing in clearing."*

**No entry has quoted this one, and it is the load-bearing evidence.** An account that holds something when a processor IS present is an account holding Merit's money at a third party. That is cash at a third party, which is an asset. **And it is, word for word, the reading [ADR-181](ADR-181.md) section 8 named as the coherent alternative NOT written in this tree**: *"`psp_clearing` means funds held at a payment provider for onward payment rather than a receivable from a processor, in which case shape (iii) is right."* It is written in this tree, in shipped source, one line above the sentence that entry read instead.

**SO THE TWO READINGS DO NOT COMPETE ON CLASS, WHICH IS THE FINDING.** A receivable from a processor and funds held at a processor for onward payment are both assets. [ADR-181](ADR-181.md) offered the second as the thing that would overturn its refusal of shape (iii); it does not, because shape (iii) needs a firm-scoped `liability` and neither reading produces one. **The alternative the founder was asked to weigh reaches the same answer as the reading that was already on the table.**

**What would make `psp_clearing` a `liability`, stated so a reader can see what is missing.** A reading under which Merit holds, at a processor, money it owes onward to somebody else. **No file in this tree states one.** [M03](../plans/M03-billing-checkout.md) section 3.4, quoted at [`checkout.ts:1680`](../../apps/api/src/routes/checkout.ts), is about a purchase with *"no third party"*: the processor path collects Merit's own product revenue, and money Merit has collected for itself is not money Merit owes.

**The `post.test.ts` transfers are still not evidence and this entry does not use them**, for [ADR-177](ADR-177.md)'s stated reason: `psp_clearing` is debited against `firm_treasury` in one case and credited against it in another, which is a fixture exercising the posting machinery in both directions.

**What has changed is the ground for DISCOUNTING the evidence that exists.** [`0052:114-116`](../../packages/db/migrations/0052_chart_of_accounts.sql) reads:

> GLOSSARY calls the reserve *"funds set aside"*, which is asset-shaped prose of exactly the kind that turned out to be **wrong** for firm_treasury one row up.

**[ADR-180](ADR-180.md) ruled that the asset-shaped prose about `firm_treasury` was RIGHT and the three postings backwards.** The precedent `0052` used to distrust GLOSSARY's sentence now runs the other way. (That sentence carries a second defect [ADR-180](ADR-180.md)'s [ALLOCATION](ALLOCATION.md) row already registers: `0052` writes *"wrong"* where [ADR-177](ADR-177.md) section 4 writes *"contradicted"*, so the migration names a loser the entry it transcribes refused to name. It is not repaired here; `0052` is unamendable.)

**The evidence for `asset`, weakest last.**

- **[GLOSSARY:241](../GLOSSARY.md)**: the reserve is *"Funds set aside to cover projected payouts. Held and reported separately from operating funds."* **Funds are cash and a thing held is a thing held.** "Separately from operating funds" separates two pots of the same substance.
- **The anchor is a cash balance.** `SD-M5-03` ties the figure to `treasury_balances`, whose `source` is CHECKed to `('provider_api','manual_attestation')` ([`0009:147`](../../packages/db/migrations/0009_ledger.sql)). **A payment rail reports exactly one number about Merit: how much of Merit's money it is holding.** That is [`0053`](../../packages/db/migrations/0053_firm_treasury_kind.sql) ground (a) applied to the other code, and it is stated at the same strength there: `account_code` is bare `text` with no key into the chart, so this is an argument from the table's SUBJECT and not from a join.
- **[ADR-011](../decisions/ADR-011.md) and [M05:417](../plans/M05-payout-system.md)**: *"The payout wallet is funded weekly, manually."* **A thing you FUND is a thing you HOLD**, and `FM-M5-06` ([M05:376](../plans/M05-payout-system.md)) is *"Payout wallet cannot cover approved payouts"*, which is a statement about a balance running out rather than an obligation growing.

**THE COMPETING READING IS `equity` AND IT IS NAMED RATHER THAN IGNORED.** In classical accounting a "reserve" is frequently an appropriation of retained earnings, which is equity, and a reader who brings that vocabulary to the code name reaches it immediately. **It is refused on the anchor**: an equity appropriation has no rail balance and no provider API to report it, and `treasury_balances.source` says the number comes from one.

**AND UNLIKE `firm_treasury` THERE IS NOTHING ON THE OTHER SIDE.** [ADR-180](ADR-180.md) had to choose between two unanimous and opposite halves. Here there is one direction of evidence and no posting anywhere in the corpus contradicting it. **That is a WEAKER body of evidence and a STRONGER epistemic position at the same time**, and both halves of that sentence are true.

### 5. THE RULING

> **1. `psp_clearing` IS AN `asset`.** Section 3. Both statements of its nature in shipped source are asset-shaped, and the second of them is the reading [ADR-181](ADR-181.md) section 8 put to the founder as the alternative.
>
> **2. `reserve` IS AN `asset`.** Section 4. [ADR-177](ADR-177.md)'s two grounds for refusing it still hold and are not overturned; what is overturned is `0052`'s ground for discounting the prose that remains, and [ADR-180](ADR-180.md) is what overturned it.
>
> **3. THE `ELSE true` CLOSES, AND IT CLOSES TO `ELSE false`.** With all seven codes armed and `ledger_accounts_code_is_declared` closing `code` at those seven, the ELSE arm is unreachable today under either word. **What separates them is the day the vocabulary widens.** Under `ELSE true` an eighth code inserts with any kind and nothing says so, which is the silence `0052` installed deliberately in order to store an open question. **There is no open question left to store.** Under `ELSE false` an eighth code is REFUSED until its kind is ruled in the migration that mints it, which is [`0009:46`](../../packages/db/migrations/0009_ledger.sql)'s rule one column over: *"A class appearing first in a migration is a class nobody defined"*, and a code with a declared name and no ruled kind is a class half defined. **Deleting the ELSE is NOT the same closure and is strictly worse**: a CASE with no ELSE returns NULL for an unmatched code and a CHECK PASSES on NULL, so the constraint would behave exactly as `ELSE true` did while appearing to say something else.
>
> **4. NO ROW IS SEEDED, AND THAT IS A DECISION RATHER THAN A LIMIT.** Both codes are firm-scoped ([`accounts.ts:52-55`](../../packages/ledger/src/accounts.ts)), so `0052` header item 4's stated rule, that the seedable set is the firm codes with a settled kind, would now admit them. **The rule is followed and its ARGUMENT is not.** `0052` seeded `fees_revenue` and `0053` seeded `firm_treasury` because a posting the corpus states resolves against each. Nothing posts against either of these two, so a row would be a chart entry no posting resolves and a `readChart` cost with no reader ([`chart.ts:12-16`](../../packages/ledger/src/chart.ts) prices that read). **And one of the two carries a hazard the other does not**: `SD-M5-03` anchors the reserve figure outside this ledger *because "computing it from our own ledger makes it a number that agrees with itself"*, and a `reserve` ROW is the first object in this tree a later reader could sum and mistake for that figure. **Ruling the kind creates no such object; seeding one would.**
>
> **5. NO CODE IS MINTED, NO NAME IS MINTED, AND NO DOCUMENT IS AMENDED.** The vocabulary stays closed at seven and [M05](../plans/M05-payout-system.md) section 2.1 stands as [ADR-180](ADR-180.md) and [ADR-181](ADR-181.md) left it. This entry rules a `kind` and nothing about a posting.
