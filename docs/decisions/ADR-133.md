## ADR-133: the fixture backlog is DERIVED and not SUBTRACTED, and a summary table row is inside ADR-034's scope even though the gate excludes it  (2026-08-27, status: proposed)

**[ADR-034](ADR-034.md) ruled that no document states a quantity a script can derive unless the number sits in a generated span the script rewrites. [WAVE-04 section 6](../plans/WAVE-04-fixture-backlog-and-gate-inventory.md) opened `OI-25` because the fixture backlog is arrived at BY SUBTRACTION: a population somebody counted once, written above the rows it counts, owed an edit by every session that moves a row.** This entry closes that with a query. It is written rather than skipped because three things had to be decided that no existing ruling decides, and because the first run of the mechanism found a count that had already drifted by forty in the document whose entire subject is derived counts.

- **Origin:** `OI-25`, [WAVE-04 section 6](../plans/WAVE-04-fixture-backlog-and-gate-inventory.md), session **245**. The number was **RESERVED BEFORE DISPATCH and CONDITIONAL** ([ALLOCATION](ALLOCATION.md) row 133): *"[ADR-076](ADR-076.md) was expected to close this and did not, which is itself evidence the shape needs stating."* **The condition is met and section 3 is the proof.**

- **NOT MONEY PATH, by position and by subject.** Nothing here reads or writes a money field, and no file under `packages/db`, `packages/rules-engine/src`, `apps/worker/src/batch` or `apps/api/src` is touched.

- **What it does NOT rule.** It takes no view on any scenario row's disposition. Sessions **237**, **248** and **249** own the rows behind `no-fixture-format`, `format-cannot-express` and the three small terms respectively; this entry owns the mechanism and not one row. That split is what makes every conflict in [section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) an append rather than a revision.

---

### 1. The decision, in four clauses

1. **The counts of [section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) are generated spans and may not be stated.** Every cell of both summary tables, and the row total in the document's opening sentence, is a `gen` span whose query is [`scripts/corpus/fixture-backlog.mjs`](../../scripts/corpus/fixture-backlog.mjs) reading the rows below. `node scripts/corpus/gates.mjs generate` writes them and a hand edit is a `CI-06g` finding on the next run.

2. **The closed vocabularies stay declared in [`gates.mjs`](../../scripts/corpus/gates.mjs) and are READ from there as text, never re-declared.** [ADR-074](ADR-074.md) section 2 is why they are written rather than derived from use; a second copy of a closed set is the duplicate-key class, and it would fail in the worst direction, producing a summary table missing a row while every count in it stayed arithmetically correct. Reading another script's source for a declaration is [`falsify.mjs`](../../scripts/corpus/falsify.mjs)'s own idiom, which reads the gate ids and `RETIRED_REGISTER` out of the runner the same way and throws when its anchor is not found.

3. **The derivation asserts the partition CLOSES, in both directions, and refuses to answer when it does not.** Summing the buckets proves nothing on its own. Comparing that sum to the row count is what makes a row impossible to lose: an undeclared status, a misspelt blocker or a row whose cells shifted each drop a row out of every bucket, and each is reported as an arithmetic gap naming the rows responsible rather than as a summary that is quietly short by one. **A derived count that omits a row is worse than the stated number it replaces, because it reads as machine output.**

4. **`CI-06/fixture-inventory` assertion 5 is NOT retired, and what it asserts changes.** It compared a hand-maintained summary against the rows, which is what made the summary trustworthy while it was still typed. Nobody types the number now, so it catches no typist. It cross-checks **two independent readers of the same rows**, the derivation script and the runner's own loop, which is the arrangement `sql_tables` and `tables` have carried since the reconciliation. That is precisely what a span alone does not buy, and [ADR-034](ADR-034.md) says so in its own terms: *"a generated span can still be generated from the wrong query, and CI-06g cannot tell a right query from a wrong one."*

### 2. THE FINDING, AND IT IS WORTH MORE THAN THE SPAN: three reasons `CI-06/derivable-counts` cannot see this number, and only one of them is a property of the number

The dispatch asked whether `CI-06/derivable-counts`, which landed in #309 to enforce [ADR-034](ADR-034.md), already caught the backlog. **It did not, and it could not have, and the three reasons apply in this order.** Each was measured against the tree rather than read off the source.

| # | Reason | Measured | Is it a hole? |
|---|---|---|---|
| **1** | **There is no vocabulary entry for this population.** The gate matches a cardinal only when a `DERIVABLE_NOUNS` entry governs it, and the vocabulary is eight populations: ADRs, triggers, migrations, tables, gates, edge cases, golden scenarios, schema deltas. *"How many registered scenarios are blocked"* is not among them, and before this session no `SPAN_QUERIES` key derived it | The gate's own run note prints the whole vocabulary on every run | **No.** The gate's `covers` line states this limit in terms: *"the vocabulary is a recorded reading and not a derivation. A derivable population with no entry is unpoliced, and the remedy is another argued entry rather than a looser match"* |
| **2** | **The recogniser is VALUE-ANCHORED, so a cardinal must equal what its bound query returns on this tree.** The eight queries return 122, 18, 47, 111, 32, 157, 316 and 117. Not one of the ten backlog counts is any of those values, so even with a noun in front of it every one of them fails the match before the exclusions are reached | Same run note, same line | **No.** It is the property the gate was chosen for: the alternatives were measured with the same reader and gave 206 and five findings in live prose, all false |
| **3** | **A summary table row is excluded BY SHAPE, and its stated justification does not cover a summary row** | Section 2.1 below | **YES, and this is the finding** |

#### 2.1 The measurement, because a claim about a gate should be run rather than read

A probe file was added under `docs/` in a copy of this tree, with a heading carrying **no date and no session number**, so the record-heading exclusion could not fire. It states one number, at a value the runner derives, governed by a noun already in the vocabulary, twice: once as a prose sentence and once as a summary table row whose number is a population over the document's own rows.

```
The corpus registers 316 golden scenarios.

| Term | Rows | |
|---|---|---|
| **registered** | 316 golden scenarios | a summary row |
```

**One finding, on the prose line, and silence on the table row.** The run note's table-row counter moved from 13 to 14 and the finding count was 1:

```
note: ... 158 site(s) under a dated or session heading and 14 in a table row,
      both out of scope by shape; 1 in scope
FAIL  CI-06/derivable-counts  (1)
      docs/zz-exclusion-probe.md:9: "316 golden scenarios" states a count this runner derives
```

**Identical text, identical value, identical noun, and the shape decides.** The exclusion's stated argument is that *"a TABLE ROW is a per-row datum where `ADR-034`'s subject is a prose sentence, and a registry row is a per-row datum whose number belongs to that row rather than to the document."* **That is true of a DATA row and false of a SUMMARY row.** `GS-001`'s row states a fact about `GS-001`. The `no-fixture-format` row states a fact about the document, computed over the document's own rows, restated above them, and maintained by hand. It is `ADR-034`'s subject exactly, and it is invisible because it begins with a pipe.

**A live instance is already in the tree and it is not a probe.** [ALLOCATION](ALLOCATION.md) row 125, session **237**'s own reservation, reads *"227 blocked scenarios move or do not move on this one term"*. As of this entry the runner derives 227 for `fixture_blocker_no_fixture_format`, and the noun `blocked scenarios` is one an argued vocabulary entry would carry. **It is a hand-maintained population count sitting in a table row, and it will be wrong the moment session 237 lands.** It is left standing rather than repaired here: that row is 237's reservation and not this session's, and it is named so the class has an instance somebody can point at.

#### 2.2 What is ruled about it, and what is deliberately left owed

**This entry rules that a summary table row is inside [ADR-034](ADR-034.md)'s scope**, so a session writing one owes it a span or a pointer at a script, whether or not any gate can see it. It **does not narrow the exclusion**, and that is a decision rather than an omission:

- The narrowing is an edit to `DERIVABLE_NOUNS` and to the exclusion in [`gates.mjs`](../../scripts/corpus/gates.mjs), and sessions **243** and **244** are live in that file. The dispatch fence asks for a new script rather than a gate change, and the two functional lines this session did need there are declared in the pull request rather than slipped in.
- **It is not free, and the false positives are already visible.** Now that `fixture_status_written` derives 43, a noun entry for `written` would fire on section 39's own sentence *"43 are written"* in the M1 partition paragraph, where 43 is a SUBSET that happens to equal the whole population. Value-anchoring cannot tell those apart, which is the class the gate's design notes already worry about. **An argued entry per population is the remedy, and arguing them is a session rather than a line.**
- **It is `OI-26`-shaped rather than `OI-25`-shaped**: it is a gate that does not exist, not a count that is stated.

**Recorded as owed, named so the next reader does not re-derive it:** `CI-06/derivable-counts` reaches a summary table row for no population, and the exclusion that stops it is argued over a data row.

### 3. Why this is not a transcription, which is what the reservation asked

| # | What had to be decided | Why no existing ruling decides it |
|---|---|---|
| **1** | **Whether a landed gate's assertion survives the repair, and what it then asserts.** `CI-06/fixture-inventory` assertion 5 exists to compare a hand-maintained summary against the rows. A session could reasonably have deleted it as redundant once nobody types the number | Clause 4 keeps it and repoints it. Its header bullet and its finding text BOTH said the summary was hand-maintained and unreachable by `CI-06g`, and both are now false. **A gate whose covers line says something untrue is the defect this corpus hunts**, so the texts move in the same commit as the spans |
| **2** | **Whether [ADR-034](ADR-034.md) reaches a summary table row.** The ruling's subject is *"a document"* and the gate enforcing it declares a table row out of scope, with an argument that holds for a data row | Section 2 above. Somebody has to say which of the two is the ruling and which is the reader, and until it is said the next summary table inherits the gate's answer by default |
| **3** | **Who owns a count that has ALREADY drifted when the derivation lands.** [ADR-034](ADR-034.md) and the gate both say a drifted number is the case where a gate *"would be asking a reader to adjudicate"*, and the gate declines to fire there on purpose | Section 4. This session let `generate` rewrite 276 to 316 with nobody adjudicating, on the ground that the derivation IS the adjudication once it exists. That is a rule about the moment a span is installed, and it is stated here rather than left as something one session happened to do |

### 4. The receipt: 276 against 316, and the mechanism found it on its first run

The document's opening sentence read *"[Section 33.4] is the same idea at three rows; this is it at 276."* **It has 316 rows.** The number was **wrong by forty**, in [section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) itself, whose own next paragraph reads *"EVERY COUNT ABOVE WAS RECOMPUTED BY READING THE TREE AND NOT BY ADJUSTING THE PREVIOUS ONE."*

**It survived every control in the tree, and each one for a reason it states about itself:**

| Control | Why it was silent |
|---|---|
| `CI-06g` | The number was not in a span, and that gate checks the spans that EXIST |
| `CI-06/derivable-counts` | Reasons 1, 2 and 3 of section 2, in that order. Additionally its own **stated** false negative: *"A COUNT THAT HAS ALREADY DRIFTED IS INVISIBLE HERE"* |
| `CI-06/fixture-inventory` assertion 5 | It reads a row whose first cell is a vocabulary term. This number is in a prose sentence and is not the count of any one term |
| 32 green gates and every reader since | It is a small number in an opening sentence, and nothing re-ran the query |

**The repair took no judgement and that is the whole point.** Installing the span and running the generator printed one line:

```
docs/testing/golden-scenarios/39-fixture-status-and-blockers.md: fixture_backlog_rows 276 -> 316
```

### 5. Falsified rather than asserted, which is this phase's definition of done

The derivation was perturbed in a copy of the tree, never in the working tree, so no generated span was ever reverted by hand.

| Perturbation | Expected | Observed |
|---|---|---|
| One row's blocker moves from `no-fixture-format` to `format-cannot-express` | Two spans move by exactly one, in opposite directions; the blocked total does not move | `fixture_blocker_no_fixture_format 227 -> 226`, `fixture_blocker_format_cannot_express 16 -> 17`, and nothing else rewritten. **32 of 32 gates over the perturbed copy** |
| The same row put back | Exactly the baseline returns | `227 -> 226` and `16 -> 17` reversed, and no third span moved |
| One row moves from `blocked` / `no-fixture-format` to `covered-elsewhere` with its blocker cleared | Three spans move by exactly one; the row total does not move | `fixture_status_covered_elsewhere 9 -> 10`, `fixture_status_blocked 264 -> 263`, `fixture_blocker_no_fixture_format 227 -> 226`. `fixture_backlog_rows` unchanged |
| **NEGATIVE CONTROL.** A blocker term nobody declared (`no-fixture-fromat`) | The derivation REFUSES rather than returning 226 and looking clean | `the blocker partition does not close. 264 blocked row(s) and 263 counted, so 1 name a term outside the closed vocabulary ...: GS-036 (line 105) reads "no-fixture-fromat"`. The runner reports `ERROR CI-06g`, exit 1, and `CI-06/fixture-inventory` independently reports two findings |
| **NEGATIVE CONTROL.** The runner's `FIXTURE_BLOCKERS` declaration renamed | The derivation REFUSES rather than deriving over an empty vocabulary | `no top-level` `const FIXTURE_BLOCKERS = [...]` `declaration ...` |

**The two negative controls are the half that matters.** A derivation that classified an unreadable row as nothing would return a smaller backlog on every malformed row and read exactly like a clean tree, which is the failure mode the stated number at least could not have.

- **Consequences:** [Section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) carries generated spans where it carried numbers, and two paragraphs recording what the mechanism is now. [`fixture-backlog.mjs`](../../scripts/corpus/fixture-backlog.mjs) joins `scripts/corpus/`. [`gates.mjs`](../../scripts/corpus/gates.mjs) gains one line reaching the queries and one making `fixtureSummaryCounts` see through a span, and three text edits where its own prose became false. **Sessions 237, 248 and 249 move rows into a document whose summary is now machine output**, so their diffs show dispositions and nothing else, and the derived counts are the first real check on whether the backlog moved by the amount their rows imply. `OI-25` closes.
- **Alternatives considered:** **make the two summary TABLES whole generated spans**, on [ADR-088](ADR-088.md)'s registry-table precedent (rejected: the third column is editorial prose per term, and moving it into a runner would put document prose in a script AND force sessions 237, 248 and 249 to edit this session's file to change a disposition, which is the cross-fence edit the four-way split exists to prevent); **delete the numbers and point at the script**, which [ADR-034](ADR-034.md) permits (rejected: `CI-06/fixture-inventory` assertion 5 reads those cells, so deleting them would retire a landed assertion to avoid writing eleven span names); **re-declare the two closed vocabularies in the new script** (rejected under clause 2: two declarations of one closed set, failing silently in the direction where a new term produces a summary missing a row); **narrow the table-row exclusion in `CI-06/derivable-counts` in this session** (rejected in section 2.2: two sessions are live in that file, and the false positives are already visible in section 39's own M1 partition paragraph); **one query per span key rather than re-deriving the whole backlog eleven times** (rejected: a per-key query cannot assert the partition closes, and closure is clause 3).
