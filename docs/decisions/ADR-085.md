## ADR-085: `CI-04`'s artifact was never the Neon branch, and two `VG` chains expire the moment it says so  (2026-08-24, status: accepted)

**[STRATEGY](../testing/STRATEGY.md) section 4.1 has recorded `CI-04` as waiting on *"a Neon branch provisioned for CI"* since 2026-08-20. The branch was never the blocker.** The `integration` Vitest project was declared at [`vitest.config.ts`](../../vitest.config.ts) and selected by **no workflow**: `ci.yml` ran `--project unit --project property`, `golden.yml` ran `--project golden`. **A project nothing selects is a suite that has never run**, and its two assertions need no database at all.

- **Context:** [ADR-073](ADR-073.md) gave every 4.1 row a disposition and [ADR-080](ADR-080.md) extended the rule to section 4.2's twelve. This entry applies both, and the second application is not a formality: giving `CI-04` an implemented leg **expires two chained `VG` legs on the same commit**, which is exactly the transition ADR-080 (d) rules and nothing was checking.

  **Two claims this session was handed did not survive measurement**, and both changed the work. They are section 4.

- **Decision:** two rulings, one new gate, and no database.

---

## 1. Ruling 1: `CI-04`'s implemented leg is the project being SELECTED

`CI-04` takes **[`CI-09`](../testing/STRATEGY.md)'s shape: one implemented leg plus one dated condition.** `CI-06/gate-inventory` already reads that as `partialRows`, so the shape needs no new rule.

**What the implemented leg buys today is measured rather than asserted.** The `integration` project holds one file and **two assertions, neither of which has ever run in CI**:

| Assertion | |
|---|---|
| migration filenames are uniquely numbered | a duplicate number is an ordering nobody can reason about, and `E2` makes a merged migration unrenumberable |
| every number below the highest is on disk or reserved in [ALLOCATION](ALLOCATION.md) | a hole the table does not explain |

**They land immediately before session 148 carries `0047`.** That is the whole value of the leg and it is why the leg is worth taking now rather than with the database.

**The database is the SECOND leg and keeps its dated condition, unchanged.** [STRATEGY](../testing/STRATEGY.md) section 4.1's Integration row rules it *"A Neon branch per CI run, torn down at job end"* and **rejects by name both substitutes a session would reach for**: *Testcontainers*, because *"it tests a Postgres that is not the one production runs"*, and a shared CI database. **A service container is therefore not available to this session**, and the condition is not weakened to make the row close.

## 2. Ruling 2: `VG-3` and `VG-6` expire, and take `Waiting` rather than `FINDING`

[ADR-080](ADR-080.md) (d)'s second clause makes a chained leg available **only while the row it names is not implemented**. Both rows read *"Chained, 2026-08-22, on `CI-04`"*. Ruling 1 implements `CI-04`. **Both chains expire on this commit.**

**They take a condition rather than a finding, because an honest one exists.** ADR-080's own `VG-5` test is *stage runs, subject present, implementation absent*, and it separates them:

- **`VG-5`'s subject is PRESENT** ([API_CONTRACT](../architecture/API_CONTRACT.md) section 12's matrix exists), which is why `VG-5` is a `FINDING`.
- **`VG-3`'s and `VG-6`'s subject is an endpoint that SERVES**, and [`apps/api`](../../apps/api) registers no route. `fastify` is absent from both `pnpm-workspace.yaml`'s catalog and `pnpm-lock.yaml`, measured at zero occurrences.

> **`VG-3` and `VG-6`: Waiting, 2026-08-24. Artifact: `fastify` present in the lockfile.**

**The lockfile key rather than "a route in `apps/api`"**, because [ADR-073](ADR-073.md) wants a path or a manifest key and `CI-08`'s row is the precedent: the dependency is the checkable half and it fires early on purpose.

**`VG-3`'s review half is `E2` and is deliberately NOT dressed as a `(c)` discharge.** That is [ADR-080](ADR-080.md) section 5's `VG-7` lesson: a line stating the control, where `CRON_INVENTORY` rows the work.

## 3. The gate: `CI-06/vg-inventory`, unlettered

`CI-06/gate-inventory`'s sibling one table down. Five dispositions instead of three, ADR-080 instead of ADR-073.

**The assertion it exists for is CHAIN EXPIRY.** A chained leg is a claim about **another table**, so it goes stale with no edit to the row that carries it, and section 4.2 would report twelve well-formed rows **identically** whether the rule discriminates or has stopped reading. That is the `VG-5` shape one table up.

**It is UNLETTERED, and that is forced rather than stylistic.** See section 4.

**Wired is strictly stronger than 4.1's `(a)`** ([ADR-080](ADR-080.md) section 3): the step or the rule must resolve, not just the job.

## 4. Two claims that did not survive measurement, and one of them is a false citation

**`x` IS NOT FREE, AND THE CITATION OFFERED FOR IT DOES NOT RESOLVE.** The session was told the rule lives at `ALLOCATION.md:186`. **It does not.** That span rules `CI-06k` folklore-rejected by [ADR-036](ADR-036.md), a different letter, and **`x` appears nowhere in [ALLOCATION](ALLOCATION.md) as a constraint**.

**The rule is real and lives in one place only**, [`scripts/corpus/falsify.mjs`](../../scripts/corpus/falsify.mjs)'s `nextFreeLetter()`, whose loop scans `a` to `x` and whose comment says why:

> *"Stops at `x` rather than `z` because every seed below needs two letters of headroom above the one it names. A harness that silently wrapped past `z` would plant nothing and report a tidy `did not fire`."*

Letters are claimed through `w`, so **a lettered gate here throws `seed anchor exhausted` and takes `pnpm run falsify` down with it.** [ADR-082](ADR-082.md)`:124`'s *"`x` stays unclaimed"* records that ADR-082 took no letter; **it does not release one.**

**So this entry writes the rule into [ALLOCATION](ALLOCATION.md) rather than citing a harness comment.** A constraint enforced only by a comment inside a script is the shape this corpus keeps getting bitten by, and **a false `file:line` inside a signed entry is what session 149 spent a session repairing across seven ADRs.**

**A SERVICE CONTAINER FOR `CI-04` IS ALREADY REFUSED**, section 1. The session did not have to decide it; STRATEGY had.

  **EVERY CONJUNCT WAS EXECUTED ON THE MERGED RESULT, NOT INHERITED FROM THE BRANCH.** `gates.mjs check` is **29 of 29** and `CI-06/vg-inventory` reports its own tally: *12 VG rows; 3 wired, 2 chained, 4 waiting legs over 3 artifacts, 4 discharged outside Actions, 2 explicit FINDINGs*. `node scripts/ci/falsify-ci.mjs CI-04` reports **2 of 2 watched failing on the violation aimed at them**, each found by its own assertion text rather than by a bare non-zero exit: `CI-04/duplicate-migration-number` on *"migration filenames are uniquely numbered"* and `CI-04/unexplained-hole` on *"every number below the highest is on disk or reserved in ALLOCATION"*.

A substring probe would have reported the artifact arrived on a package that is not it, passing in exactly the same way as one that works, and `gates.mjs`'s own `@vitest/browser-playwright` case is why that was checked rather than assumed.

  **Both of the brief's premises were refuted by this session and the corrections are the entry's.** `x` is not a free letter: `nextFreeLetter` in [`falsify.mjs`](../../scripts/corpus/falsify.mjs) scans `a` to `x` and its own comment states that every seed needs two letters of headroom, so a lettered gate would exhaust the seed anchor. The gate is unlettered. And a service container was already refused by [STRATEGY](../testing/STRATEGY.md)'s *"A Neon branch per CI run"*, which rejects Testcontainers and a shared CI database by name. **The dispatching brief asserted both the other way and both were wrong.**

  **THE ONE CLAUSE TO CHECK BEFORE SIGNING**, carrying the directions it could fail in and not only the one it was written for:

  > [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) selects the `integration` project in exactly one job; `node scripts/ci/falsify-ci.mjs CI-04` reports that job **failing on both seeds, naming the test**; `node scripts/corpus/gates.mjs check` is **29 of 29** with `CI-06/vg-inventory` reporting `VG-3` and `VG-6` as **waiting** rather than chained; and the same gate is watched **FAILING** when a chained leg is repointed at `CI-01` and when a real `fastify` key is seeded into the lockfile, **while `fastify-plugin` seeded into the lockfile does NOT reopen the row.**

  **The near-miss is inside the clause rather than beside it**, because it is the direction the probe fails in silently. `fastify-plugin` contains `fastify`, and a substring probe reports the artifact **arrived** on a package that is not it, passing in exactly the same way as one that works. That is `gates.mjs`'s own `@vitest/browser-playwright` case.

  **What it costs if wrong.** A stage that runs a suite nobody has watched fail, and a section 4.2 gate that reports twelve well-formed rows identically whether the chain-expiry rule discriminates or has stopped reading, which is the `VG-5` shape one table down.
