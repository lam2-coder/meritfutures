### 2. RULING 1: the comment is false in every clause, and the half nobody re-derived is the load-bearing one

**THE CHEAP HALF FIRST.** *"`prior` needs the codec"* was true when it was written and `ADR-250` discharged it. That is the defect the row anticipated and it is real.

**THE HALF THAT MATTERS IS THAT `prior` NEVER NEEDED ANYTHING ELSE**, and the reason a successor could easily conclude otherwise is that [ADR-250](ADR-250.md) section 7 says the opposite about a NEIGHBOURING port, correctly and in the same paragraph:

> `storedRuleStates` STILL REFUSES, AND ITS REASON IS NARROWED RATHER THAN DELETED. That reason named the codec ... **It is not.** A `RuleStateRow` is twenty-odd columns read back and rebuilt: `contextGates` has its own stored shape, `calendarRevisionId` crosses a `bigint` column into a `number | null` field ... **One `jsonb` leaf decoded is not a row rebuilt.**

**Every one of those three examples is a field a `RuleState` does not have.** `AccountDay.prior` is a `RuleState` ([`ports.ts:57`](../../apps/worker/src/batch/ports.ts)), not a `RuleStateRow`:

| Field | `RuleStateRow` | `RuleState` | Why |
|---|---|---|---|
| `contextGates` | **YES** | no | `INV-23`: context gates never enter the replayed state |
| `stateHash` | **YES** | no | `SD-08` is computed FROM a state; a state does not carry its own hash |
| `calendarRevisionId` | **YES** | no | [ADR-047](ADR-047.md)'s stamp on the ROW, and `0035`'s column |
| `accountId` | **YES** | no | The fold is per account by construction |

**SO `prior` IS A STRICTLY SMALLER READ THAN THE PORT THAT STILL REFUSES**, and the codec was the entire remainder. `ADR-250`'s paragraph is true of its own subject and reads, to anyone who does not open both interfaces, as though it were true of this one. **That is the shape this estate keeps finding: a sentence that verifies, doing a job it was not written for.**

### 10. Where this entry is most likely wrong

**NO DATABASE WAS REACHABLE FROM THIS SESSION AND THE WHOLE OF SECTION 3 IS READ THROUGH A RECORDER.** What is proved is which key was named, which filter was applied and what the mapping produced. What is NOT proved is the driver's own behaviour: that `date` comes back as `'YYYY-MM-DD'`, that `bytea` comes back as a `Uint8Array`, that `bigint` columns come back as `bigint` under drizzle's `{ mode: 'bigint' }`, and that `jsonb` comes back already parsed. **Those are the same four assumptions `adapter.ts`'s four shipped ports already make**, they are `packages/db`'s to prove, and a case here claiming them would be agreeing with its own fake. **The first live run against Postgres is where they are settled**, and the boundary readers are written so that each one fails by name rather than by `undefined` if any is wrong.

**THE PRIOR IS READ BY SCANNING THE ACCOUNT'S WHOLE `rule_states` HISTORY, AND THAT IS THE SAME TRADE `accountsWithStoredState` ALREADY DECLARES AND CALLS WRONG.** One account's rows is a few hundred at most and the maximum is taken in this process, because the accessor publishes no ordered or limited read. `rule_states_account_day_desc_idx` exists precisely for this query and nothing here uses it. **The repair is a read on `packages/db` rather than a filter here**, it is owed before the fold runs nightly rather than before this file lands, and it is the same sentence that file already carries one port up.

**AND THE `null` ARM IS NOW REACHABLE IN A WAY IT WAS NOT, WHICH IS A BEHAVIOUR CHANGE A FOUNDER SHOULD SEE.** Before this diff every account with a live mark threw. Now an account whose mark is superseded, or whose mark row vanishes between the partition read and this call, is counted `absent` and the batch **completes with a zero exit status**.
