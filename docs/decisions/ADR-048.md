## ADR-048: CI-03's polarity is derived per fixture from the rules it cites  (2026-08-16, status: accepted)

**[P2 section 3](../plans/P2-rules-engine.md) is the analysis and this ADR records the ruling. `OQ-P2-03`, closed.**

- **Context:** **CI-03 is green today while asserting that every golden fixture does NOT match**, and that is correct rather than broken. TR-02 puts the fixture before the function, so every fixture is in the window where it must fail; STRATEGY section 1 is equally clear that a permanently red required stage is worse than a smaller one nobody clicks through. So the stage **asserts the failure instead of suffering it**, and the direction is read off the engine rather than set by a flag in a fixture.

  **The mechanism cannot survive P2.** [`engineIsIdentityStub()`](../../packages/golden-loader/src/run.ts) folds one probe day and tests reference equality on the returned state. It is **global and all-or-nothing**, so the moment the first rule lands, polarity flips to `direct` **for every fixture at once** — including fixtures for rules not yet written — and the stage is red for the rest of P2. The design was right for the scaffold, where the engine was one step from nothing to something. **M01 is fifty rules across eight groups and cannot land in one commit under [ADR-003](ADR-003.md).**

  **Two of the three ways out are already closed.** Landing all fifty rules in one session is closed by ADR-003. A per-fixture `pending` flag is closed explicitly and by name: the loader calls it *"the escape hatch a future session reaches for at 11pm when one scenario will not go green"*, and TR-03 forbids it.

### The ruling

> **Polarity is derived PER FIXTURE, from the rules the fixture already cites.** The engine exports the set of rule identifiers it implements. If every rule a fixture's `source` cites is in that set, the fixture is `direct` and must match; otherwise it is `inverted` and must fail.

**No fixture is edited and no flag is introduced**, which is the property the present design has and must keep. The direction is still read off the engine — **per rule instead of per repository**.

### This is more honest and it is also more places to be wrong, and the second half is why it is safe

The global probe has one failure mode and this has four. Naming them is the point; **the ruling rests on the claim that every one of them fails LOUDLY, in a direction somebody sees.**

| # | The way it can be wrong | Which direction it fails in |
|---|---|---|
| **1** | A fixture cites rules that ARE implemented but its expected end state also depends on one it did not cite | Flips to `direct` **too early** and the fixture is **red**. Loud |
| **2** | A rule is implemented and not added to the declared set | Its fixtures stay `inverted` and **MATCH**, which under inversion **is the failure condition**. Loud |
| **3** | A rule id is added to the declared set without the rule being implemented | Caught by the cross-check below, before any fixture is consulted. Loud |
| **4** | A fixture cites **no rule at all**, so "every cited rule is implemented" is **vacuously true** and it flips to `direct` on an empty engine | **This is the dangerous one, and it is closed by a prerequisite rather than by care.** See below |

**The symmetry is the argument.** A fixture that flips too early is red; a fixture that flips too late matches while inverted, and matching while inverted is itself the failure. **There is no quiet direction.** That is not true of a `pending` flag, whose whole purpose is to be quiet, and it is why this is a different object from the one TR-03 forbids.

### Case 4 is the vacuity class, and it needs the citation rule to land FIRST

**An empty cited set makes the polarity test vacuously true.** "Every rule this fixture cites is implemented" is trivially satisfied by a fixture that cites nothing, so such a fixture flips to `direct` against an engine that implements nothing and fails for a reason that has nothing to do with its subject.

This corpus has now found the same defect in five costumes: `array_length` on an empty array returning `NULL` and the `CHECK` passing ([ADR-035](ADR-035.md), seven constraints), `{}` accepted as a `trading_calendar_revisions` prior image ([ADR-042](ADR-042.md) F-2), an allowlist decaying by keeping a stale entry (`CI-06l`), a calendar fixture emptied to zero sessions passing every downstream loop (`CI-06m`), and this. **The empty case is never the safe default: it is the one value that skips the assertion entirely.**

> **So the ruling has a stated prerequisite.** [P2 section 2](../plans/P2-rules-engine.md)'s mechanical traceability tier — `source:` becoming a **resolvable citation of at least one `R-nn`, `CV-nn` or `INV-nn` that exists in M01**, enforced by a new `L-nn` loader rule watched failing on its own seeded violation — **lands before or with the polarity change, never after it.** Without it the empty set is reachable and case 4 is open.

### The self-declaration cross-check

A session could add a rule id to the declared set without implementing the rule. **M01 already requires one unit test per rule**, fifty of them in the `RE-U-nnn` series, each asserting its operator at the boundary on both sides.

**The declared set is cross-checked against the PASSING `RE-U-nn` set, and a declared rule with no passing unit test fails the stage.** The declaration is therefore not self-certifying: it is checked against an artifact written under the same writer/reviewer split that produced the fixtures.

### What proves the flip actually happened

**The measurement already exists and does not change.** [`coverage.ts`](../../packages/golden-loader/src/coverage.ts) corrupts every loaded fixture and re-runs the stage's own assertion. Under inversion the corruption **still passes**, and the report says the stage is blind. **When a group flips, that measurement becomes false for those fixtures on its own** — nobody has to remember to update it.

The only change is **reporting it per rule group**, so the coverage block shows the flip advancing group by group. **The mechanism is unchanged, which is the point**: [ADR-038](ADR-038.md) exists to keep a CI stage honest about what it currently proves, and a stage whose meaning changes eight times during P2 needs its self-report to change with it automatically rather than by edit.

- **Consequences:** [`packages/rules-engine`](../../packages/rules-engine/README.md) exports the set of rule identifiers it implements, and that export is part of its public contract. The golden loader derives polarity per fixture from it; `engineIsIdentityStub()` is superseded and its probe is retired **with its header's warning carried forward**, because the case it names — an engine that returns its input by reference and emits nothing — is still worth a comment where the new derivation lives. **A new `L-nn` rule requires a resolvable citation on every fixture and is a prerequisite of this change, not a companion to it.** The `RE-U-nn` cross-check becomes a stage requirement. `coverage.ts` reports polarity per rule group. **[STRATEGY](../testing/STRATEGY.md)'s CI-03 row is amended to say what a green CI-03 means during P2**, which is that every fixture whose rules are declared matched and every fixture whose rules are not declared failed, rather than the single sentence it carries today.

- **Alternatives considered:** **All fifty rules in one session** (rejected: ADR-003, and a fifty-rule money-path diff is not reviewable); **a per-fixture `pending` flag** (rejected by name in the loader's own source and by TR-03: it is the quiet direction, and its whole purpose is to let one fixture stop asserting without anybody deciding to); **keeping the global probe and accepting a red stage for the rest of P2** (rejected: STRATEGY section 1 says a permanently red required stage is worse than a smaller one, and a stage everybody has learned to ignore is not a gate); **deriving polarity from the fixture's rule GROUP rather than its cited rules** (rejected: the group is not written on the fixture and would become a second hand-maintained mapping, which is ADR-034's class; the citation is already there and is about to be made resolvable anyway); **inferring the implemented set by reflection over exported function names** (rejected: it infers a rule is implemented from a symbol existing, which is exactly the self-certification the `RE-U-nn` cross-check exists to refuse).
