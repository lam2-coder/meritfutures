## ADR-202: the required `cusum` object yields to the absence ruling, because a shape may not promise a value a ruling forbids producing  (2026-08-28, status: proposed)

One rule says the field renders ABSENT until the calibration lands and no statistic is manufactured; the other declares a non-optional object of two numbers and a boolean in three places, so the field can hold no absence. The set of values `readLiability` may return for that field is therefore empty and `GET /admin/liability` has no response it may serve. **The SHAPE yields.** The ruling is not a preference between two defensible answers: section 3 enumerates everything the required object can hold today and shows, without data, that every one of them is `FM-M6-07`'s failure in one of its two directions, so the required side can be satisfied only by a non-control. ### 2. The conjunction that has no member, stated so a reader can check it

Let **V** be the set of values `readLiability` may return for `per_plan[].cusum` on a response `GET /admin/liability` actually serves. That endpoint is registered: session 374 measured it on `CompositionReport.registered` over a real `compose()`.

**Rule B constrains V from above.** The declaration at `API_CONTRACT:907` is a non-optional property whose type is a single object literal. No arm of it is `null`, no arm is `undefined`, and the property carries no `?`. So

> **V is a subset of { every object of the form `{ statistic: number, threshold: number, alarm: boolean }` }**, and therefore `null` is not in V and an omitted key is not in V.

**Rule A constrains V from above too.** `ADR-167:80` renders the field ABSENT until `DEP-M6-05` lands and *"does not manufacture one"*. `DEP-M6-05` has not landed: [`M06:557`](../plans/M06-admin-ops-console.md) puts it in **Wave 4**. So

> **V is a subset of { absent }.**

**Intersect them.** No object of rule B's form is the value "absent", and "absent" is not an object of that form. The two supersets are disjoint, so

> **V is EMPTY.**

**A field whose admissible value set is empty is a response that cannot be served.** That is the whole of `B3` in one line, and neither rule is defective in reaching it: rule A is right that an uncalibrated statistic must not be published, and rule B is right that a client reading an authoritative liability panel should not have to null-check the fields it renders. **The gap is that nobody wrote them in the same room.** Rule B was frozen into an approved contract before rule A existed, and rule A's own last clause handed the absent wire shape to `P7-b`, which had already closed (section 10, finding 2).

**The emptiness is not theoretical and the tree has already paid for it in code.** [`apps/api/src/routes/admin-breaker.ts:242`](../../apps/api/src/routes/admin-breaker.ts) carries the comment *"`plan.cusum` IS READ AND DELIBERATELY NOT CARRIED"*: that module takes a `LiabilityResponse` from the source, reads the object rule B forces it to contain, and refuses to put it on its own wire. **A line of code exists whose only job is to discard a value the type system requires somebody to have invented.** That is what an empty conjunction looks like when a deployable has to compile anyway.

### 3. Every value the required object can hold today fails `FM-M6-07`, and one proof needs no data

**This is the section the dispatch asks to be checkable arithmetically**, on the standard [ADR-201](ADR-201.md) set when it proved two of three readings of `avg_30d_cents` were not controls at all. The test is [`M06:282`](../plans/M06-admin-ops-console.md), `FM-M6-07`, verbatim:

> **CUSUM miscalibrated** | Either constant alarms, which become noise, or none, which is the same as no chart | `mu_0` and `sigma` estimated from the simulation harness before launch, then refreshed monthly from realized data | Calibration is a tracked deliverable with a named owner, **not a constant someone picked**

The recurrence is [`M06:97`](../plans/M06-admin-ops-console.md), `P-M6-06`, restated identically at [`GLOSSARY:260`](../GLOSSARY.md):

> `S_t = max(0, S_(t-1) + (x_t - mu_0 - 0.5*sigma))`, alarming at 4 to 5 sigma

Let `x_t` be a plan's pass rate on trading day `t`, in integer basis points by `ADR-167` clause 4, so `0 <= x_t <= 10000`. Let `k` be the slack `0.5*sigma` and `h` the alarm point. **Rule B's object must carry three values today. Every way of filling it falls in exactly one of three classes, and the classes are exhaustive because `mu_0` and `sigma` either have real values or do not.**

| Class | What the object holds | Verdict |
|---|---|---|
| **1.** the only object needing no invented number: zeros | `mu_0 = 0`, `k = 0`, and `h` either `0` or a placeholder | **PROVABLY NOT A CONTROL, both halves, with no data** |
| **2.** an invented `mu_0` and `sigma` | any pair somebody picks | **PROVABLY NOT A CONTROL, and `FM-M6-07` names the act itself** |
| **3.** a calibrated `mu_0` and `sigma` | the real pair | **NOT AVAILABLE.** `M06:557` is Wave 4 |

**Class 1 is refuted twice and neither refutation needs a row.** Take `mu_0 = 0` and `k = 0`, the only assignment that invents nothing. The recurrence collapses to `S_t = max(0, S_(t-1) + x_t)`, and because `x_t >= 0` for every possible history, `S_t >= S_(t-1)` for every `t`: **the statistic is non-decreasing and unbounded.** Against `h = 0` it passes the alarm point on the first day any plan records a single passing account and **can never come back below it**, so `alarm` is true from that day forever, on every plan, whatever happens. That is *"constant alarms, which become noise"* proved from the sign of `x_t` alone. Take instead `statistic` pinned at the literal `0` as a placeholder, with any `h > 0`: then `alarm` is false on every plan on every day for all time, which is *"none, which is the same as no chart"* -- and it is the worse half, because a panel rendering `alarm: false` is not silent. **It is an affirmative statement that the plan is not being beaten, made by a chart that never looked.**

**Class 2 is refuted twice as well, and the second refutation needs no data either.**

**(a) The sign of one invented difference decides the entire chart.** With an invented pair the increment is `d_t = x_t - mu_0 - k`. If `mu_0 + k` sits below the plan's true mean pass rate, `d_t` has positive mean, `S_t` drifts up without bound, crosses any finite `h`, and stays above it: constant alarms. If `mu_0 + k` sits above the true mean by more than the series' own spread, `S_t` is held at the `max(0, ...)` floor and never accumulates: no alarm ever, on any plan, however hard it is being beaten. **The number that decides which of those two happens is exactly the number `DEP-M6-05` exists to supply**, and `FM-M6-07`'s control column already names an invented one by its proper name: *"not a constant someone picked."* Inventing the pair is not a weaker version of calibrating it; it is the failure mode, written down in advance, in the corpus's own risk register.

**(b) `threshold` and `alarm` are undetermined EVEN GIVEN a perfect calibration, and this needs no data at all.** `M06:97` and `GLOSSARY:260` both state the alarm point as a **RANGE**, *"alarming at 4 to 5 sigma"*, and searched exhaustively over `M06`, the `GLOSSARY`, `INFRA` and the constitution, no document narrows it to one multiple. So two producers, both faithful to every word of the corpus, emit `threshold = 4*sigma` and `threshold = 5*sigma`, and **return different `alarm` booleans on identical rows** for every statistic landing in `[4*sigma, 5*sigma)`. **A non-optional boolean on an approved contract whose value the corpus does not determine is a producer's choice wearing a contract field's name**, and the operator reading the panel cannot tell which choice was made.

**The elimination is total, and that is what separates `B3` from `B2`.** `ADR-201` eliminated two of three readings of `avg_30d_cents` and one survived, so a definition closed the gap. **Here two of three classes are available and both are eliminated, and the survivor is not available.** The intersection of "what rule B admits" with "what `FM-M6-07` admits" is empty for as long as `DEP-M6-05` is unlanded. **So rule B can be satisfied today only by publishing a non-control**, and that is the fact which decides section 4 rather than a preference between two reasonable shapes.

### 4. WHICH ONE YIELDS, and the principle that makes it one decision

**RULING 1. The SHAPE yields. `ADR-167` clause 5 stands unmoved, unnarrowed and uncited-against.**

**The argument is what each rule exists to protect, and the two protections are not symmetric.**

**Rule A protects the operator from a number that means nothing.** Its ground is `FM-M6-07` and, one level up, `AS-M6-02`'s mechanism, which `ADR-201` states in its own words for the neighbouring control: a control that cries wolf gets overridden, and the overriding is what the incident later runs into. **That protection is unconditional.** It does not depend on which surface carries the figure, on who is reading, or on what shape the reading arrives in. Section 3 is the proof that it is live today rather than a caution.

**Rule B protects the client from a missing field.** A non-optional property is a promise that a value exists, so every reader may render it without a null check; [`ADR-111.md:39`](ADR-111.md) clause 3 gives the general form of why that promise is worth keeping -- *"widening an authenticated route to public later is a decision somebody makes; narrowing a public route later is a break for every caller that found it"* -- and narrowing a response is the same direction of mistake. **But that protection is CONDITIONAL on the field carrying a true value.** A required field whose only producible value is fabricated does not spare the client anything; it obliges the client to render a fabrication and calls that reliability.

**RULING 2. The principle, and it is one principle rather than two concessions: a shape may not promise a value a ruling forbids producing.** Where a rule about the TRUTH of a figure meets a rule about the PRESENCE of a field, presence yields, because presence is worth having only for a figure that is true. The reverse trade buys the client a field it can parse without a null check and hands the operator a number nobody estimated, on the panel `AS-M6-04` is the registered scenario for getting wrong.

**Splitting the difference was available and it is refused by name.** The reasonable-looking answer is that clause 5 relaxes just far enough to emit a zeroed object while the shape stays exactly as declared. **That answer is class 1 of section 3**, which is proved to be a non-control in both directions, so it does not weaken two rules a little; it weakens one rule into uselessness and leaves the other intact while producing an alarm that is wrong every day. There is no third position between "the field carries a value" and "the field carries an absence", so a compromise here can only be a fabricated value with a caveat in a comment, and a caveat in a comment is not on the wire.

**And this trade is not new to the corpus. It has been made twice already, on this exact figure, on both surfaces whose shape nobody fixed in advance.**

| Surface | What it carries today | Where |
|---|---|---|
| `GET /admin/cusum`, the projection of this very field | `readonly cusum: null`, with a `ProjectionGap` on the body naming `DEP-M6-05` and quoting `FM-M6-07` | [`admin-breaker.ts:147`](../../apps/api/src/routes/admin-breaker.ts) and `:186` |
| the weekly loss-ratio and CUSUM digest | the line `absent: blocked on ... (ADR-167 clause 5, FM-M6-07)` | [`produce.ts:203`](../../apps/worker/src/digests/produce.ts) |
| the producer both of those read from | `cusumOf(series, params)` returns `CusumFold \| null`, and returns `null` while the parameters are `null` | [`evaluate.ts:668`](../../apps/worker/src/breaker/evaluate.ts) |

**So the required object is required in exactly one layer, and both of its neighbours already speak `null`.** The evaluator that produces the statistic returns `null` today; the renderers that draw it render an absence today; the wire type between them is the only thing in the chain that cannot say so. **Ruling that the shape yields does not weaken it. It brings the last surface into line with the answer the tree already gives on every other one**, and it removes the line of code at `admin-breaker.ts:242` whose only job is to throw away a value the type forced somebody to invent.

### 5. The form the yield takes, and the three forms refused

**RULING 3. `per_plan[].cusum` becomes `{ statistic: number; threshold: number; alarm: boolean } | null`, in all three declarations, and `null` means ABSENT, blocked on `DEP-M6-05`.** The key is always present. The object, when present, is unchanged in every member and every type, so `ADR-167` clause 4's integer basis points and the *"neither cents nor basis points"* note at [`API_CONTRACT:983`](../architecture/API_CONTRACT.md) both stand exactly as written.

**`null` rather than the three alternatives, each refused on a source rather than on taste.**

| Refused | Why |
|---|---|
| **`cusum?: {...}`, an omitted key** | An omitted key makes *"absent, blocked on `DEP-M6-05`"* and *"this deployment did not fill the field"* the same response, and a client cannot tell them apart. That is [ADR-198](ADR-198.md) clause 2's reasoning one type over: *"encoding an absence as a number would make 'no figure' and 'zero cents' the same row forever."* `null` is a value the response asserts; a missing key is a value the response withholds |
| **the three MEMBERS nullable** | It makes one fact into three independent absences and admits `{ statistic: 5, threshold: null, alarm: true }`, which is a partially calibrated chart and a shape nothing in the corpus describes. The absence is a property of the CALIBRATION, not of the members: `UNCALIBRATED_CUSUM` at [`evaluate.ts:553`](../../apps/worker/src/breaker/evaluate.ts) has all three parameters null together and one `blockedOn` beside them |
| **an inline gap object, `{ absent: true, blocked_on: ... }`** | Two reasons, one measured. `assertContractScalars` refuses any key ending `_on` or `_day` that is not a trading day, which [`admin-breaker.ts:103`](../../apps/api/src/routes/admin-breaker.ts) records and which session 320 watched turn every 200 into a 500. And the reason for the absence is identical for every plan on every day, so a per-row copy of it is the same sentence repeated once per plan; `CUSUM_GAPS` at [`admin-breaker.ts:186`](../../apps/api/src/routes/admin-breaker.ts) already carries it **once**, on the body, which is where a fact about the deployment belongs |

**The nullable form is also the shape that does not have to be changed back, and that is an argument rather than a convenience.** When `DEP-M6-05` lands, `cusumOf` returns a fold instead of `null` and nothing about the wire type moves: the `null` simply stops occurring for calibrated plans. It also stays the honest answer afterwards for a plan whose series is too short to have a statistic, which is `INV-M6-07`'s *"a ratio computed on three transactions is not a ratio"* arriving on this figure. **This entry does not rule the small-sample case** (section 8): it notes that the shape it rules can carry the answer whichever way that one goes, and the required shape cannot carry either.
