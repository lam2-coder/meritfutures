## ADR-426: `ADR-303` limit 4 is SPENT for one verb on one handle, and the proof is a hand-written mapping deleted in the same commit (2026-09-07, status: proposed)

**Row 426 of the 422s wave. Branch `claude/limit-4-mapping-deleted-retry`, off `claude/wave-422s` at `bfd6c400`, session 621.**

**[ADR-421](ADR-421.md) SECTION 9 PRICED THIS ROW AND THIS ROW PAYS THE PRICE.** That entry narrowed all four verbs on all six handles, measured **zero consumer errors**, and refused on the ground that zero errors is zero readers: every reader reads a PORT that re-states the `unknown`, so a narrowing no port follows deletes no mapping. **WHAT DID NOT MOVE IS EVERY REFUSAL, AND THAT IS RULED RATHER THAN PREFERRED.** `ADR-299` section 5.1 item 5, quoted in `packages/db/test/catalog-read.test.ts` and now in three more places: **a type derived from a TRANSCRIPTION does not retire a runtime check.** `ADR-112` foreclosure 4 records that no check in this tree compares a `schema.ts` column type against the DDL. So the narrowing buys the guard for a column's EXISTENCE and buys nothing about its VALUE, and not one `throw` in `rows.ts` was deleted with the mapping.

### 4. What was changed, in four moves

**MOVE 1: THE ACCESSOR, FOR ONE VERB ON ONE HANDLE.** `DeclaredRow<K extends TableKey> = (typeof TABLES)[K]['$inferSelect']` is declared in `packages/db/src/scoped-db.ts` and exported from `packages/db/src/index.ts`. `CatalogRow` is REDEFINED IN TERMS OF IT rather than left beside it, because two spellings of one expression is the `FM-16` shape limit 4 itself describes. `SystemTx.rowsWhere` returns `Promise<DeclaredRow<K>[]>`; the `as unknown[]` in its implementation MOVED to `as DeclaredRow<K>[]` and no cast appeared.

**THE KEY VOCABULARY IS UNTOUCHED AND THAT IS THE HALF [ADR-424](ADR-424.md) WATCHES.** That entry's section 7 binds `SystemTx` to every admin-source handle and says a `SystemTx` whose `rows` KEY VOCABULARY narrows stops satisfying `LiabilityTx` and `AdminSourceTx`. `K extends TableKey` is what it always was. **A RETURN that narrows is assignable to every port that declared `Promise<unknown[]>`**, so no consumer is asked to move, and section 6 is that claim measured rather than argued.

**MOVE 2: THE DOOR.** `apps/worker/src/db.ts` re-exports `DeclaredRow`. **It is there for the reason `atLeast`, `atMost` and `isNull` are there**, which is `ADR-165`'s ONE FILE PER PACKAGE: the alternative is a `ports.ts` importing `@merit/db` and `test/db.test.ts`'s *"exactly one file under src imports the accessor"* becoming a two-element list, which `ADR-333` already declined to loosen. **It is not a second door in `ADR-165` clause 2's sense, because a TYPE REACHES NO TABLE**, and [ADR-424](ADR-424.md) finding 9 already ruled the general case: *"a type-only witness needs NO door, and `ADR-171` clause 1 is untouched by one"*. No value of the type is constructed anywhere.

**MOVE 3: THE PORT.** `DigestReadTx.rowsWhere` is generic over `K extends DigestReadTable` and returns `Promise<DeclaredRow<K>[]>`. The union is unchanged and is still two members, so the port reaches no table it could not reach before. `export type DigestRow` is **DELETED**.

**MOVE 4: THE MAPPING.** `record()` is **DELETED** from `digests/rows.ts` and from both callers. The seven column readers became generic over the row (`<R extends object>(row: R, key: keyof R & string, ...)`), so **`tsc` now checks every column NAME against `schema.ts`** where a string used to pass unchecked. `readAlarmSchedule`, `foldWindows`, `readProducerSchedule` and `nextAttempt` take typed rows instead of `unknown`.
