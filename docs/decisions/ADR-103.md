## ADR-103: column TYPE and NULLABILITY are COMPARED, so `ALTER COLUMN` stops standing in for a comparison that did not exist  (2026-08-25, status: proposed)

**[ADR-084](ADR-084.md) made [`schema.ts`](../../packages/db/src/schema.ts) a transcription of the migrations and built the assertion that checks it. [ADR-094](ADR-094.md) made that assertion read a table's WHOLE history rather than its `CREATE TABLE`. Both compare NAMES, and the name set is all either of them reads.** A column transcribed `text()` where the DDL says `bytea`, or `.notNull()` where the DDL says nullable, agrees on names, is invisible to every scope-rule assertion, and is GREEN on all 99 registered tables. **ADR-094 section 3 named that gap, priced closing it as its own session, and left `ALTER COLUMN` refusing two tables as a STATED PROXY in its place. This entry is that session, and the proxy is replaced by the thing it stood for rather than deleted.**

- **Origin:** [P3 wave 3](../plans/P3-wave3-modules.md) section 9's `P3-g` row and section 15's prompt, session **214**. **The specification is [ADR-094](ADR-094.md) section 3 and this entry did not write a new one.** ADR-094 wrote *"seven already-merged money-path files"*; the registry is at **99** and the comparison lands on every one of them.

- **Context:** [`scoped-db.test.ts`](../../packages/db/test/scoped-db.test.ts) held, before this entry, one per-table assertion holding `sqlNames(key)` equal to the folded column-NAME set, plus [ADR-101](ADR-101.md)'s clauses, which read exactly two things out of a column DEFINITION -- `REFERENCES identities(id)` and `NOT NULL` -- **and only on the ONE column a scope rule names**. Nothing read a type at all. Every session since [session 206](../sessions/2026-08-25-session-206.md) has been required to disclaim it and none could close it, because it was nobody's slice.

---

### 1. Why the axis is not cosmetic

**`bytea` versus `text` is [ADR-046](ADR-046.md)'s seal.** `contact_channels.value_hash` is a DIGEST and `contact_channels.value_ciphertext` is envelope-encrypted under a key that is not present in this database. A digest transcribed as `text` is a digest the application layer reads as a string, and the transcription is what the application layer sees.

**Money is integer cents, so the integer WIDTH is the balance.** `purchases.list_price_cents` is `bigint`; transcribed `integer` it compiles, satisfies the name comparison, and silently caps at 2,147,483,647 cents.

**A closed vocabulary read as an open one is [ADR-041](ADR-041.md)'s three members lost.** `identities.status` is the `identity_status` enum and that entry refused to add a fourth member to it; transcribed `text()` the refusal has nothing to hold.

**NULLABILITY is the axis two merged migrations already MOVED**, which is the whole reason `ALTER COLUMN` was refused rather than folded.

**THAT IS THE ANSWER THE SLICE WAS DISPATCHED TO MEASURE AND IT IS THE OPPOSITE OF THE ONE IT WAS PRICED FOR.** [P3 wave 3](../plans/P3-wave3-modules.md) section 12 row 1 says *"`P3-g`'s cost is unmeasured by construction"* and ADR-094 predicted the comparison *"would turn the suite red on whatever it finds"*. **It finds nothing.** The transcription of 99 tables, written by nine sessions across two days with no mechanical check on this axis at all, is correct on every column. **No row of [`schema.ts`](../../packages/db/src/schema.ts) is edited by this entry, and the file is untouched.**

**A GREEN RESULT FROM A NEW COMPARISON IS THE RESULT MOST LIKELY TO BE VACUOUS, AND SECTION 5 IS WHY THIS ONE IS NOT.**

**Two spellings are one type and the table saying so is closed at two entries.** `timestamptz` is what the migrations write; `timestamp with time zone` is what drizzle-orm renders. Nothing else in this tree needs an alias, measured rather than assumed: `bytea`, `citext`, `jsonb`, `char(n)`, `numeric`, `inet`, `text[]`, `bigint[]`, `uuid[]` and all thirteen enums spell identically on both sides. **An entry in that table makes two DIFFERENT spellings compare EQUAL, so it is the one edit that can make this comparison agree with a wrong transcription**, and it is written with that stated against it.

### 3. The ruling

> **1. A TRANSCRIPTION STATES A COLUMN'S TYPE AND ITS NULLABILITY, AND BOTH ARE COMPARED AGAINST THE MIGRATION SET AS OF THE LAST MIGRATION.** Per registered table, for every column: the type drizzle-orm renders equals the type the folded DDL declares, and `.notNull()` equals what the folded DDL declares, where a `PRIMARY KEY` declares it without the words.
>
> **2. [ADR-094](ADR-094.md) SECTION 3's `ALTER COLUMN` CLAUSE IS SUPERSEDED, AND ONLY THAT CLAUSE.** The fold's vocabulary gains a SECOND member: `ALTER COLUMN <name> DROP NOT NULL` is folded. `DROP COLUMN` and `RENAME` stay REFUSED and the default stays FAIL. ADR-094's ruling items 1 and 2, and its foreclosures 1, 2, 3, 5, 6 and 7, are untouched.
>
> **3. THE `ALTER COLUMN` SUB-VOCABULARY IS ITSELF CLOSED AT ONE SHAPE WITH A DEFAULT OF FAIL.** `SET DATA TYPE`, `SET NOT NULL`, `SET DEFAULT`, `DROP DEFAULT` and every other `ALTER COLUMN` shape are REFUSED, and a statement mixing any of them into a recognised one is refused whole rather than part-folded.

**THE ORDER IS THE RULING AND NOT AN IMPLEMENTATION DETAIL.** ADR-094 refused `ALTER COLUMN` on a stated argument -- *"deleting the refusal before writing the comparison would be trading a real control for nothing"* -- so the comparison LANDED FIRST, in its own commit, watched failing on four seeded transcriptions, and the vocabulary widened after it. **Clause 2 is available only because clause 1 exists, and reversing the two would be the trade ADR-094 refused.**

**Clause 3 is ADR-094 item 3's own discipline applied to the widening it permits.** `SET DATA TYPE`, `SET NOT NULL` and both `DEFAULT` shapes have **ZERO instances in 47 migrations**, so a rule for them would be written against nothing. **The three statements that exist are all `DROP NOT NULL`**, on two tables:

```
0029  ALTER TABLE otp_challenges  ALTER COLUMN email_normalized DROP NOT NULL;
0032  ALTER TABLE trading_calendar ALTER COLUMN session_open_at  DROP NOT NULL;
0032  ALTER TABLE trading_calendar ALTER COLUMN session_close_at DROP NOT NULL;
```

### 4. What the comparison COVERS, and what it CANNOT SEE

**Stated precisely, on [ADR-101](ADR-101.md)'s and [ADR-102](ADR-102.md)'s precedent that partial coverage stated precisely is worth more than full coverage claimed.**

**COVERED: 99 of 111 tables, 1,183 columns, two axes each.**

**NOT COVERED, and each is a real thing [`schema.ts`](../../packages/db/src/schema.ts) transcribes:**

| Unchecked | Where it lives | Why it is not here |
|---|---|---|
| **`DEFAULT`** | **335 `.default*()` calls** in the transcription | A default is applied by the DATABASE on insert, so a wrong one in `schema.ts` misleads a reader rather than changing a row -- until [ADR-102](ADR-102.md)'s `insert` builds a statement from it. **The cheapest next comparison and the one with a caller already written** |
| **`CHECK`** | Every money invariant in the tree | `schema.ts` transcribes no CHECK at all, so there is no second statement to compare. A comparison would have to hold that the transcription states NONE, which is what it does |
| **`UNIQUE`, `PRIMARY KEY`, indexes, triggers** | The DDL | Read only where an existing assertion needs them: `primary` in the hop check, and `PRIMARY KEY` as an implied `NOT NULL` here |
| **Inline `REFERENCES`** | 99 tables | Compared only on the columns a scope rule names ([ADR-101](ADR-101.md) clauses). The file's own header states the rule it follows and nothing checks it |
| **Column ORDER** | Both sides | Both readers sort or key by name |
| **`COLLATE`, generated identity, storage** | The DDL | Zero relevance to either axis and stripped by the type reader, whose refusal to swallow them is asserted |

**THE 12 UNREGISTERED TABLES ARE NOT COVERED AND THAT IS UNCHANGED BY THIS ENTRY.** They are unregistered, therefore unreachable through either accessor, therefore safe ([ADR-092](ADR-092.md) section 9). **`otp_challenges` and `trading_calendar` are two of them and clause 2 is what makes them REGISTRABLE**, which is the point of the widening rather than a side effect: session 215 registers `otp_challenges` under it and `POST /auth/otp` is the only endpoint in the contract that runs before an identity exists.

### 5. How a vacuous comparison is refused, which is this entry's real risk

**A GREEN NEW COMPARISON HAS ONE SILENT FAILURE DIRECTION AND IT IS NOT THE OBVIOUS ONE.** Both sides of every per-table assertion are READERS: `getSQLType()` on the transcription and a text reader on the DDL. **Two readers that degrade in the same direction agree**, and that is [ADR-084](ADR-084.md) section 7's failure and [ADR-094](ADR-094.md)'s seed B. Three assertions stand there, and all three were watched being the only thing that fired:

1. **Fourteen SENTINEL columns written out as LITERALS**, checked against BOTH readers. Two [ADR-046](ADR-046.md) digests, two money columns, a closed enum, a `citext` login, and one of each remaining spelling. `contact_channels.value_ciphertext` is `ALTER`-added in [`0034`](../../packages/db/migrations/0034_reversible_contact_addresses.sql), so these rows also prove the comparison reads the FOLD and not the `CREATE`.
2. **The type reader is asserted NON-DEGENERATE**: it returns a non-empty type for every one of the 1,183 columns, it is asserted not to have swallowed constraint text with it, and the number of columns it visits is compared against the number the transcription declares.
3. **The reader's OUTPUT VOCABULARY is asserted to span sixteen spellings**, so a reader that collapsed onto one is red.

**Watched, on the tree, restored after each:**

| Seeded | Result |
|---|---|
| `contact_channels.value_hash` transcribed `text()` instead of `bytea` | **2 failed / 225 passed.** *"contact_channels.value_hash is transcribed as a different TYPE ... expected 'text' to be 'bytea'"* |
| `contact_channels.value_ciphertext` given `.notNull()` against `bytea NULL` -- **the plan's own candidate clause** | **2 failed / 225 passed.** *"is transcribed as NOT NULL and the migration set declares it nullable"* |
| `purchases.list_price_cents` transcribed `integer()` instead of `bigint` | **2 failed / 225 passed**, the column named |
| **The silent one, ADR-094's seed B written for this comparison**: the per-table assertion made to compare the DDL WITH ITSELF, with `value_hash` still seeded as `text` | **1 failed / 226 passed. All 99 per-table comparisons stayed GREEN and the SENTINEL test was the only red.** That is what the sentinels are for, watched being it |
| The same self-comparison PLUS a type reader collapsed to return `'text'` for everything | **2 failed.** *"no registered column reads as bigint"*, by name |

**`git status --porcelain` was empty after each restore and before this entry was written.**

### 6. How the widened fold is refused, on tables nothing has registered

**THE SECOND MEMBER HAS NO EXERCISE IN THE REGISTRY AND SAYING SO IS PART OF THE RULING.** `otp_challenges` and `trading_calendar` are the only two tables carrying an `ALTER COLUMN`, neither is registered, so `foldTable(...).relaxed` is EMPTY on all 99 registered tables. **A vocabulary member no assertion runs is a vocabulary member nobody has checked**, which is ADR-094's own seed-B argument about a fold that folds nothing.

**So the suite folds those two tables BY NAME, registers neither, and watches the relaxation happen**: the column is asserted `NOT NULL` at its `CREATE`, nullable after the fold, and its TYPE unchanged. A second assertion re-derives every `ALTER COLUMN` statement in the migration set and holds that the carriers are exactly those two tables and the count exactly three, **so a fourth statement anywhere -- including on an unregistered table, which the refusal assertion cannot see -- turns the suite red and the next session reads this ruling before writing a regex.**

**Five statement shapes and two mutations watched, each seeded as a migration file and removed:**

| Seeded | Result |
|---|---|
| `ALTER COLUMN kind SET DATA TYPE citext` on a registered table | **REFUSED**, red on both the refusal assertion and the closure assertion, the statement quoted |
| `ALTER COLUMN kind DROP NOT NULL` on a registered table whose transcription says `.notNull()` | **RED on the type-and-nullability comparison**, naming `contact_channels.kind`. **This is the ordering executed: the widened fold reaches the new comparison and the comparison is what refuses** |
| `DROP NOT NULL` against a `PRIMARY KEY` column | **THROWS.** PostgreSQL refuses that statement, so a fold applying it replays a history that cannot have run |
| `DROP NOT NULL` against an already-nullable column | **THROWS.** A relaxation that applies nothing is a fold agreeing with a transcription it never checked |
| `ALTER COLUMN` naming a column not on the table | **THROWS**, on `ADD COLUMN`'s own mis-parse rule |
| `withoutNotNull` mutated to return the definition unchanged | **1 failed / 228 passed**, *"otp_challenges.email_normalized after the fold: expected true to be false"* |
| `foldTableDefs` mutated back to SKIPPING `ALTER COLUMN`, as it did before this entry | **1 failed / 228 passed**, the same assertion by name |

**ONE READER, NOT TWO.** `droppedNotNulls` is read by `foldTable`, which records the relaxation, and by `foldTableDefs`, which applies it. Two readers of one statement that could disagree is [ADR-092](ADR-092.md) section 5's measured hazard and it is not reintroduced here.

### 7. What this FORECLOSES

1. **A PER-COLUMN EXEMPTION IS FORECLOSED, on [ADR-094](ADR-094.md) foreclosure 1's exact argument.** There is no allowlist, no `skip`, no `// type differs, see ADR-NNN`. A registered table has every column compared on both axes or it is not registered.
2. **WIDENING THE TYPE ALIAS TABLE TO MAKE A COMPARISON PASS IS FORECLOSED.** Every entry must be a spelling PostgreSQL itself treats as one type. **An alias makes two different spellings compare EQUAL, so it is the only edit in this mechanism that can make the comparison agree with a wrong transcription**, and adding one is an ADR rather than a commit.
3. **WIDENING THE `ALTER COLUMN` SUB-VOCABULARY BY ADDING A REGEX IS FORECLOSED**, on [ADR-094](ADR-094.md) foreclosure 4. The default is FAIL. `SET DATA TYPE` in particular is a change to the axis this entry compares and it will arrive with rows already in the table; **it gets its own entry.**
4. **FOLDING `DROP COLUMN` OR `RENAME` STAYS FORECLOSED.** Zero instances in 47 migrations, and [ADR-094](ADR-094.md) foreclosure 3 stands unamended.
5. **`drizzle-kit generate` STAYS FORECLOSED.** Reading the SQL to assert against it is not generating a schema from it; nothing is emitted and nothing is written back.
6. **DERIVING THE SENTINEL LIST IS FORECLOSED.** Computing those fourteen rows from either reader would make them agree with the thing they exist to check, which is [ADR-084](ADR-084.md) section 7's failure and is the whole reason they are literals.
7. **"THE COMPARISON FOUND NOTHING, SO THE AXIS WAS NEVER AT RISK" IS FORECLOSED.** Nine sessions transcribed 99 tables with nothing checking this axis and got it right. **The next one has no such record and neither does the one after it**, and four seeded transcriptions that every other check in this package accepted are the evidence.

### 9. Consequences

- **The suite gains 104 assertions**: 99 per-table comparisons, three that stand where the vacuity is, and two on the widened fold. [`scoped-db.test.ts`](../../packages/db/test/scoped-db.test.ts) **125 to 229**; the full suite **112 files / 1,718 passed / 1 skipped** to **112 files / 1,822 passed / 1 skipped**. **A registration that fails to add its per-table comparison shows as a count that did not move**, which is [ADR-094](ADR-094.md)'s consequence 6 extended to the second axis.
- **`otp_challenges` and `trading_calendar` become REGISTRABLE and neither is registered here.** Session 215 is unblocked on the first.
- **A wrong type or a wrong nullability is now a RED SUITE rather than a wrong answer at runtime**, on every registered table, and on every table registered after this.
- **The nullability [ADR-101](ADR-101.md) clause 3 checks is now folded for drifted tables too.** That clause reads `foldTableDefs`, which now applies `DROP NOT NULL`, so an `owned` rule on a relaxed column gets the post-`ALTER` answer. **No registered table is affected today** and the correctness arrives before the table that needs it.
- **[`schema.ts`](../../packages/db/src/schema.ts)'s HEADER NOW CONTAINS A SENTENCE THAT IS FALSE ABOUT THIS TREE, AND IT IS REPORTED RATHER THAN REPAIRED.** It reads *"`ADD COLUMN` is folded, and `DROP COLUMN`, `ALTER COLUMN` and `RENAME` stay offenders that turn the suite red"*. **`P3-g`'s fence admits that file for ONLY the rows the comparison finds wrong and the comparison found none**, so touching it would be widening a fence to finish. **Session 215 holds `schema.ts` next, registers `otp_challenges` under exactly this widened fold, and the same header's TEN-of-ninety-nine drifted-table count moves in that same session.** The repair belongs there.

### 10. Alternatives considered

- **Compare types and leave `ALTER COLUMN` refused.** Rejected on the plan's own instruction and on ADR-094's argument read forward: the refusal was a proxy for a missing comparison, so once the comparison exists the refusal costs two tables and buys nothing. **Keeping it would leave `POST /auth/otp` blocked on a control that no longer stands for anything.**
- **Fold every `ALTER COLUMN` shape.** Rejected on measurement, not caution: four of the five shapes have zero instances, and `SET DATA TYPE` in particular changes the axis this entry compares. **A vocabulary written for statements nobody has written is a vocabulary nobody has checked**, which is ADR-094's own line.
- **Compare types against a live database's catalog instead of the SQL text.** Rejected. `CI-04` has no database ([P4](../plans/P4-portal-and-site.md) section 5.2: the `integration` job runs on bare `ubuntu-latest` with no `services:` block), so the check would not run in CI, and *"a check that cannot run is not a check that passed"* is already this repo's line in [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs).
- **Generate the sentinel rows from the DDL so the list never goes stale.** Rejected on [ADR-084](ADR-084.md) section 7. A generated expectation compares a reader with itself, which is the exact failure the sentinels exist to catch, and the staleness they can suffer is LOUD: a column that moves makes them red.
- **Repair `schema.ts`'s header in this session.** Rejected on the fence. The fence admits that file for the rows the comparison finds wrong, the comparison found none, and **never widen a fence to finish** is the standing rule. Section 9 names the sentence and the session that owns it.
- **Report the comparison and stop without widening the fold.** Rejected because the plan's row and its prompt both name the widening, the comparison landed first in its own commit, and **stopping would leave session 215 blocked on a proxy for a comparison that now exists.**
