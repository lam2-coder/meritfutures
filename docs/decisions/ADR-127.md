### 3. THE RULING

**RULING 1. `@stryker-mutator/core@10.0.0` and `@stryker-mutator/vitest-runner@10.0.0`**, two catalog entries, exact, declared as `devDependencies` of `packages/rules-engine` and of **no other manifest, the repository root included**. That placement is the scope executed rather than described: under [`.npmrc`](../../.npmrc)'s `node-linker=isolated` an undeclared import does not resolve, so a root declaration would make `stryker run` work from anywhere and a package declaration makes it work in the one package [STRATEGY section 2](../testing/STRATEGY.md) rules it onto.

**RULING 2. `@stryker-mutator/typescript-checker` is REFUSED**, which is the third package the tool's own quick start suggests. It type-checks every mutant against the project's `tsconfig`, and what it buys is the elimination of mutants that would not compile. Vitest runs `.ts` through esbuild, which **strips** types rather than checking them, so a non-compiling mutant here fails its tests like any other and scores as killed. The checker would make the score marginally more precise and the run an order of magnitude longer, and section 2's ask is a **trend**.

**RULING 3. The scope is every `.ts` file under `packages/rules-engine/src/` and the config lives INSIDE that package.** [STRATEGY section 2](../testing/STRATEGY.md) verbatim: *"Stryker, nightly, on `packages/rules-engine` only"*, whose rejected alternative it states in the same row, *"Repo-wide mutation testing (runtime cost with no proportionate signal on UI code). The engine is the one package where a surviving mutant is genuinely alarming, and restricting it there is what makes the number worth reading."* [`playwright.config.ts`](../../playwright.config.ts), [`vitest.config.ts`](../../vitest.config.ts) and [`eslint.config.js`](../../eslint.config.js) all sit at the root because they are repository-wide gates; this one is ruled onto one package, so it sits in the package. A root config with a `packages/rules-engine` glob would express the same scope today and would be one careless glob edit away from the workspace-wide run that row rejects by name.

**RULING 4. NO THRESHOLD IS WRITTEN AT ALL, and that is the ruling rather than a way past `RI-02`.** Section 4.

**RULING 5. The leg fails on three things and the mutation score is not one of them.** The initial test run failing, the runner crashing, and **zero mutants**. Section 5.

**RULING 6. One `pnpm` override, path scoped, because the admission failed `CI-05` before it passed anything.** Section 6.

### 4. The threshold that is not written, which is `OQ-TS-02` HONOURED rather than answered

**[ADR-073](ADR-073.md) section 6 measured this trap seven days ago and handed the founder a sharper question than the one `OQ-TS-02` asks.** Its table, reproduced here from the dirty side rather than quoted:

| Spelling | `RI-02` |
|---|---|
| `stryker.conf.mjs`, a JavaScript object literal | **MATCH.** A finding at `CI-01`, which blocks merge |
| `stryker.conf.json`, the same values in JSON | **No match.** The quote between the key and the colon defeats the needle |

**Reproduced on this branch:** with the block present in `.mjs`, `node packages/tooling/checks/repo-invariants.mjs` reports `FAIL RI-02`, `reads as a Vitest coverage thresholds block`. `RI-02`'s own `covers` line says it is *"a SPELLING check in both directions"* and that *"a scanned file that merely names one of these keys, in a comment or a string, is a finding"*, so this is the stated limitation firing rather than a defect.

**THE OBVIOUS MOVE IS TO WRITE THE CONFIG IN JSON, AND IT IS REFUSED.** That writes the identical value in a spelling the needle cannot see. It is the same shape as the `.gitleaksignore` fingerprint [session 232](../sessions/2026-08-27-session-232.md) refused and for the same reason: it buys green by keeping the thing that should not be there. ADR-073 said so first, in the sentence this ruling turns on: *"the tree already forbids one spelling of a Stryker threshold and permits the other, and neither outcome is a ruling anybody made."*

**THE SECOND MOVE IS TO NARROW `RI-02` SO ITS VOCABULARY STOPS REACHING A MUTATION THRESHOLD, AND IT IS REFUSED TOO, BECAUSE IT IS NOT THIS SESSION'S TO TAKE.** ADR-073 handed that question to the founder in as many words: whether `RI-02`'s vocabulary should reach a mutation threshold at all, *"given that its argument (line coverage measures how much code was executed, which is the one quality signal generated tests inflate for free) is an argument about coverage and not about mutation score, which is the one metric generated tests do not inflate for free."* A session that edited the needle would be answering `OQ-TS-02`'s second half on its own authority, one file over from the gate it was making quieter.

**SO THE THIRD MOVE IS THE ONE TAKEN, AND IT IS NOT A DODGE: THE CONFIG WRITES NO THRESHOLD BECAUSE THERE IS NO THRESHOLD.** [STRATEGY section 2](../testing/STRATEGY.md) rules the score *"reported as a trend rather than a threshold"*, and `OQ-TS-02` proposes *"trend only, reported nightly. A threshold on a young codebase produces tests written to kill mutants rather than to pin behavior, which is `TR-01` inverted."* A config carrying **no** such block is the literal expression of that ruling, and `RI-02` then passes because there is genuinely nothing for it to find rather than because the value was spelled around. **The difference between this and the JSON file is the difference between not having one and having one the gate cannot see**, and only one of those two is what STRATEGY asked for.

**WHAT THAT COSTS, AND THE COST IS PAID RATHER THAN ABSORBED.** Omitting the block means the leg's central property, that no score fails it, rests on a Stryker **default** instead of on a line in this repository, and a future major that changed the default would turn a trend into a nightly failure with nothing in this tree noticing. **So the default is ASSERTED**: [`stryker.conf.mjs`](../../packages/rules-engine/stryker.conf.mjs) reads `mutationScoreThresholds` out of the shipped JSON schema of the installed `@stryker-mutator/core` and **throws before the run starts** if the breaking default is anything but `null`. That is a check that runs on every nightly and on every local invocation, and it is the corpus's own standing preference applied: prefer a mechanical assertion over a sentence, whenever the error is checkable.

`high` and `low` fall back to `80` and `60`, which are the numbers the block would have carried, and they colour a report a human reads. They fail nothing and they never did.

**THE TWO PLACES THAT WOULD HAVE ROUTED AROUND IT WERE BOTH TRIED AND BOTH BROKE THE RUN**, which is why this finding is a finding rather than a config line:

| Sandbox location | Result |
|---|---|
| **`node_modules/.stryker-tmp`**, the one directory name every walker here skips | **Breaks the run.** Vitest excludes `**/node_modules/**` by default, so with the sandbox under that path every test file is excluded and the dry run reports `No tests were found` |
