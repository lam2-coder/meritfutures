### 1. The coverage, measured as a number rather than described as a list of legs

**A `covers` LINE NAMES LEGS. IT DOES NOT SAY WHAT FRACTION OF A WRONG LINE NUMBER EACH CHECK WOULD ACTUALLY REPORT, AND THAT IS THE ONLY QUESTION A READER OF A CITATION HAS.** So it was measured directly.

**THE METHOD IS A PERTURBATION AND IT NEEDED NO SEED.** For every single-line citation in each check's real scope, the cited line was replaced in turn by **every other line of the file it resolves to**, and the check's own legs were run on each. The result is an **in-file detection rate**: the share of wrong line numbers that check would report. A pointer past the end of the file is excluded from the denominator on purpose, because it is not how a citation drifts; a citation drifts to another line of the same file.

**THE READER IS THE CHECKS' OWN**, imported from an export-added copy of `repo-invariants.mjs` placed in its own directory so `REPO_ROOT` resolved, and deleted afterwards. **The copy re-enters a documented import cycle and had to be loaded second**, which that file's own header predicts in terms.

**AND THE RE-IMPLEMENTATION WAS HELD TO AN ORACLE BEFORE ANY OF IT WAS BELIEVED.** The verdict function run at each citation's TRUE line returns **0 findings for `RI-15` and 0 for `RI-16`**, which is what both checks return on this tree.

| Files or documents read | 753 source files | 1,324 documents |
| Citations in scope | **390** | **1,373** |

**THE TWO NUMBERS THAT MATTER ARE IN THE LAST ROW AND THEY ARE NOT THE SAME KIND OF FACT.**

**`RI-15` catches a little under half of all wrong line numbers**, and where no name binds it catches one only when the wrong line happens to be **blank or a bare closing bracket**, which is the vacancy leg doing the whole job. That is a real control with a stated price.

**`RI-16` catches five percent, and for 1,189 of its 1,259 perturbable citations it catches NOTHING.** Any line number in the file passes. What that check asserts about the overwhelming majority of the corpus's live pointers is **that the file exists and is long enough**, and nothing else.

### 12. Where this entry is most likely wrong

- **The detection rate is a model of drift and drift is not uniform.** A pointer that drifts usually moves a few lines, not to a uniformly random line of the file. **A near-neighbour model would give `RI-15` a LOWER rate than 44.2 percent**, because the vacancy leg is what earns most of it and a small drift rarely lands on a blank line. It would leave `RI-16`'s 94.4 percent exactly where it is, since that figure is zero detection at every distance. **So the headline number is if anything generous to `RI-15` and exact for `RI-16`.**
- **The oracle proves the re-implementation agrees on THIS tree, which is where both checks return nothing.** Two functions that both return zero agree cheaply. The eleven red seeds are what show the legs are individually reachable, and the oracle is a floor rather than a proof.
- **Section 5's cause is established on one file's insertion points and one reading of the guard.** Every unbound point measured carries a negation word in the leaked window and every bound one does not, and seed 13 closes the loop by removing the leak and watching the case turn. **The pairing state may still cost bindings somewhere this row did not look**; what is refuted is that it is the cause of the effect [ADR-377](ADR-377.md) measured.
- **The 983 insertion points are three files chosen for being in scope and unlike each other, not a sample of the corpus.** The 6.3 percent is a rate over those three and the spread across them is 3.3 to 9.0 percent.
- **Section 8 answers a question that a founder may think is not settled by a structural argument.** The claim is that an exemption mechanism inside the file being checked cannot obey the shrinks-only rule. **A founder who reads the specimens as movable to fixtures is reading option (c) of [ADR-377](ADR-377.md) section 14, which this row did not price.**
