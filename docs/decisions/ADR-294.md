## ADR-294: a crashed check is not a lower count. The runner reports PASS, FAIL and ERROR as three outcomes, keeps the denominator, and refuses to print the sentence that reads as a measurement (2026-08-30, status: proposed)

**Sessions 480 and 481 hit the same thing on the same afternoon, neither having been asked to look for it: with `node_modules` absent, [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) printed `29 of 30 invariants hold.` while `RI-18` was CRASHING on a missing `typescript` module.** The check never ran. The runner counted it anyway, on the side of the sentence that says everything is fine, and then printed a number that looks exactly like a measurement.

**THIS FILE'S OWN HEADER ALREADY RULED THE OPPOSITE, TWICE.** Rule 2 says *"A CHECK THAT CANNOT RUN IS NOT A CHECK THAT PASSED"*, and rule 1 says a check never reports on something it did not look at. Both rules governed the CHECKS and neither governed the REPORT, so the runner was free to say about thirty checks what no single check is allowed to say about itself.

**THE DIRECTION OF THE ERROR IS THE WHOLE POINT.** A session reading `29 of 30 invariants hold.` cannot tell a real violation from a broken runner, and the arithmetic quietly puts the unmeasured check on the held side. That is [CLAUDE.md](../../CLAUDE.md)'s recorded caution exactly: the reconciliation session's worst errors were failures to check a claim against a primary source, and the remedy is a mechanical assertion rather than a bigger model. **The report WAS the primary source, and it was lying by arithmetic.**

- **Origin:** [ALLOCATION](ALLOCATION.md) row `294`, session **485**, branch `claude/a-crashed-check-is-not-a-lower-count`. **NON-MONEY. TOOLING ONLY.** `apps/**`, `packages/db/**` and `.github/workflows/**` are untouched and were not read for edit.

- **THE FIX IS IN THE RUNNER AND NOT IN `RI-18`.** No invariant was weakened, deleted, renumbered or made conditional. `RI-18` throws today for exactly the reason it always did, and it is now REPORTED as throwing.

- **`RI-35`, RESERVED TO THIS ROW BY NAME, IS LEFT FREE.** Section 6 enumerates the three invariants this session considered minting and shows each is either untrue of this tree or unenforceable without weakening something. `RI-32`, `RI-33` and `RI-34` were not touched.

- **THE COUNT IS UNCHANGED AT THIRTY.** `30 of 30 invariants hold.` on a tree with its dependencies installed, before this change and after it.

### 1. What the runner did

The tally was ONE counter. A check that returned findings and a check that threw both did `failed++`, and the summary printed the difference:

```js

      console.log(`ERROR  ${check.id}  ${check.title}`);
      console.log(`       ${err instanceof Error ? err.message : String(err)}`);
      failed++;
      continue;

...

```

**Two things are true about that code and only one of them was ever noticed.** The exit code was ALREADY non-zero on a crash, which is why CI stayed honest and why this defect survived: the gate went red, the transcript said `29 of 30`, and only a human reading both at once could see them disagree. **What was wrong was the REPORT**, and a report nobody can trust is not repaired by an exit code somebody else reads.

**`ERROR` was already printed as its own word.** The line said `ERROR`, and then the arithmetic said `29 of 30 invariants hold`, and the arithmetic is the part a session quotes.

### 4. The ruling

**A check whose body throws is an ERROR, which is a third outcome and not a heavier FAIL.**

| | Meaning | Counted in | Exit |
|---|---|---|---|
| **PASS** | The check ran and found nothing | `passed` | `EXIT.OK`, 0 |
| **FAIL** | The check ran and found something | `failed` | `EXIT.VIOLATED`, 1 |
| **ERROR** | The check DID NOT RUN | `errored` | `EXIT.CRASHED`, 3 |
| usage | No such check id | none | `EXIT.USAGE`, 2 |

**FOUR PROPERTIES, EACH DECIDED RATHER THAN INHERITED.**

**(1) THE DENOMINATOR DOES NOT MOVE.** It is how many checks there were, so a crash cannot shrink it. Thirty checks producing twenty-nine passes, no fails and one crash is not `29 of 30`, and it is emphatically not `29 of 29`. Subtracting a crashed check from the total is the one repair that would have made the number arithmetically true and it is refused: it converts a broken runner into a smaller clean one, which is the same lie with better manners.

**(2) THE HELD SENTENCE IS NOT PRINTED ON A RUN THAT CRASHED.** `N of N invariants hold.` is a claim about a completed measurement. A run holding an ERROR did not complete one, so it prints the three-way tally and says in words that it did not measure the tree. **This is the load-bearing half of the fix**, because the exit code was already non-zero and the sentence was still being quoted.

**(3) A CRASH GETS ITS OWN EXIT CODE, AND IT DOMINATES.** `2` was already taken by usage, so a crash is `3`. It is not folded into `1` because *"this tree breaks an invariant"* and *"this run did not measure the tree"* are different facts wanting different responses, and a shell that can only see a number should be able to tell them apart. On a run producing both, the crash wins: findings you can read are the smaller news when a check went unread. **Nothing in the tree reads these codes for anything but zero versus non-zero** (`falsify-ci.mjs` compares `status === 0`, `package.json`'s `check:invariants` and `ci.yml` let the shell decide), so nothing had to change to accept a third code, and the distinction is there for the next reader rather than for a caller that exists today.

**(4) A RUN WITH NO CRASH SAYS EXACTLY WHAT IT ALWAYS SAID.** `30 of 30 invariants hold.` is byte for byte the old line, and a violated run keeps its old sentence and its old exit code 1. The blast radius is one branch of one report, and a suite case asserts the unchanged half so it cannot drift as a side effect of a later change to the crashed half.

**THE OUTCOME IS DECIDED IN THE RUNNER AND NOT INSIDE ANY CHECK, WHICH IS WHAT MAKES IT HOLD FOR AN IMPORTED ONE.** `ri11` lives in [`ui-server-endpoints.mjs`](../../packages/tooling/checks/ui-server-endpoints.mjs) and `ri18` in [`response-shape-copies.mjs`](../../packages/tooling/checks/response-shape-copies.mjs); both are members of the same `CHECKS` array and both throw across a module boundary into the same `try`. A case in the suite runs `ri11` against a tree that holds none of its inputs and watches it come back ERROR, so the property is asserted on a genuinely imported check rather than on a fixture that resembles one.

**THE RUNNER STREAMS.** `runChecks` takes an `emit` rather than calling `console.log`, so the suite reads the transcript this file actually prints instead of a second copy of the wording, and a long run still prints line by line instead of going quiet until the last check returns. A buffered transcript would have lost the partial output of a run that hangs, which is the one case where a transcript is worth most.

### 6. `RI-35` is left free, and here is what was considered

The row reserved `RI-35` to this session if the work needed one. **It does not, and the three candidates are named rather than left as a gap somebody re-opens.**

### 7. What this does not catch, stated rather than discovered later

**(1) A MODULE THAT THROWS WHILE IT IS BEING IMPORTED.** Every check in `CHECKS` is imported before any check runs, so a top-level failure kills the process before the first `try`. Node exits non-zero with a stack trace and NO summary line, so it cannot be mistaken for a count, which is the property that matters here. **It is also the reason `RI-18` loads `typescript` lazily**, and that reason is now written in two places rather than one.

**(2) `scripts/corpus/gates.mjs` CARRIES THE SAME DEFECT AND IS OUT OF FENCE.** Its `main` folds a thrown gate into the same `failed` counter and prints `N of N gates pass.`, so a gate that crashes is reported as a gate that did not pass, in the runner that guards the corpus. **It is reported here and not repaired here**, because this row's fence does not reach `scripts/` and widening a fence to fix a thing you found is how a one-file change becomes a wave. It is owed a row of its own, and the fix is this one transposed.

**(3) A CHECK THAT RETURNS `[]` WITHOUT LOOKING.** The report can only distinguish a check that threw from a check that returned. A check that silently reads nothing and reports PASS is invisible to this file and is what the SENTINEL idiom inside the checks exists for. **Nothing here reduces the need for one.**

**(4) A CRASH IN THE `list` PATH OR IN MODULE-LEVEL FIXTURE CONSTRUCTION.** Same as (1): outside the loop, so outside the tally.

### 10. Approval

**Status `proposed`. The approval line below is UNSIGNED and merging is not signing.**

- **Decision:** `repo-invariants.mjs` reports three outcomes rather than two. A check whose body throws is an **ERROR**: it is counted in its own tally, it is **not subtracted from the denominator**, it sets exit code **3** (`EXIT.CRASHED`, distinct from `1` for a violation and `2` for a usage error, and dominating a violation in the same run), and it **suppresses the `N of N invariants hold.` sentence entirely**, which is replaced by a three-way tally and a statement that the run did not measure the tree. A run with no crash prints and exits exactly as before. The behaviour is decided in the runner, so it holds for `ri11` and `ri18`, the two checks that live in other files.
