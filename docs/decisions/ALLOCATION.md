# Number allocation

TABLE: `CI-06f` and `CI-06h` call one shared parser over the first cell of every
row. A table split into a file per row is not a table, which is the same reason
`DELTA_MANIFEST` stays single under [ADR-043](ADR-043.md).

**Gaplessness is asserted over allocated plus reserved**, so a branch holding a reserved number shows a hole in this file and passes. A branch inventing an unreserved number fails.

### `044` collided with an open sibling pull request, and this branch moved

**This session claimed `044`, wrote the ADR, the migration that cites it, its probe and eleven documents, and then found `044` already claimed by PR #25.** `main` ends at `043`, this branch is not behind `main`, and **twelve of twelve gates passed against that claim**, because `CI-06f` reads one ref and PR #25's branch is not it. **That is `CI-06f`'s declared coverage gap met in the wild for the second time in three days**, after [FOLD-02](../plans/FOLD-02-enforcement-window-and-suspension.md)'s plan hit it on `038`, and the cross-ref job that would close it is still not written.

**The remedy was a manual step this session skipped and the FOLD-02 session did not.** That session's record says "every remote branch was checked"; this one checked `main`, found `043`, and took `044`. **The table cannot do that step for you**: it is single-ref by construction, it says so in its own words two paragraphs down, and a claim made without reading the siblings is a claim made against a table that was never asked the question.

**It is resolved here rather than at merge**, which is FOLD-02's precedent rather than PR #4 and PR #5's: the founder assigned at merge once, [ADR-034](ADR-034.md) exists because that was expensive, and the branch that discovers a collision is the only one that can act on it. **This branch moved even though [ADR-034](ADR-034.md)'s tiebreak points the other way**, and the reasoning is worth the two lines it costs: the tiebreak renumbers the branch whose number is cited least, and this branch cites it forty-one times against PR #25's twenty-one, **including inside a migration**. But the tiebreak decides which branch *should* move, and only one branch *can*. **PR #25 is open, complete and waiting for a founder who would otherwise resolve a numbering conflict in a frozen registry by hand**; this session was still writing. The number cited inside a migration is the one that matters, and `0033` is unmerged, so the citation is a `sed` rather than a supersession.


**The State column is the one part of this table no gate can check**, and the `035` row is the proof: a reservation becomes an allocation at merge, and **a runner reading one ref cannot tell the two apart**, because the branch holding a reservation and the `main` that has absorbed it both show the heading present and the row claimed. `CI-06f` reads the Numbers column, which is the load-bearing half. The State column is prose for a reader, it drifts like all prose, and [ADR-036](ADR-036.md) records that rather than implying the whole row is enforced.

**The count is now four, and the correction this session was commissioned to make had already been made.** The session brief named the `036` row as still reading `reserved, unmerged` after the pull request that merged it. It does not: `036` was corrected in the same fold that landed [ADR-037](ADR-037.md) and [ADR-038](ADR-038.md), and the row records its own repair. **The staleness had moved on to `037` and `038`**, which PR #15 merged and which still claimed to be reserved on a branch that no longer exists. That is the third and fourth instance, it was found by reading `git log` against the table rather than by reading the table, and **a brief written against this column was wrong about it inside two days**, which is the same evidence one layer out. The remedy is not more care. It is that **the State column is not a fact and is not read as one**; what a gate can check is the Numbers column, and what a reader should check is the ref.

### `0034` was claimed twice IN THIS TABLE, and twelve gates read it and passed

**Two rows above both claim `0034`.** [ADR-047](ADR-047.md) claimed it for `rule_states`' calendar revision; `ADR-046` claimed it for the reversible contact addresses, wrote the file, and merged in PR #41. **The number is spent, so this migration is `0035`** and the row above records the move.

**This one was not the two-ref gap.** The ADR-044 collision two headings up was invisible because `CI-06f` reads one ref and the colliding claim lived on another. **This collision was in one file, on one ref, in adjacent rows, and every gate still passed** — because `allocated()` in [`gates.mjs`](../../scripts/corpus/gates.mjs) accumulates claims into a `Set`. Two rows claiming `0034` produce one member. Gaplessness holds, "every number on disk is claimed" holds, and **a table whose entire purpose is to make a duplicate claim visible cannot see one.**

**That is worth more than the collision it let through**, because the ADR remedy does not exist on this registry: [ADR-034](ADR-034.md) renumbers the branch citing the number least, and a merged migration cannot be renumbered at all (constitution E2). **Here the recovery was free only because the second file was still unwritten.**

The check is a handful of lines against a `Set` that already exists, and it is **not written in this session, for a stated reason**: the tables are full of duplicate rows today. The ADR table above claims `039` through `046` **twice each**, a stale branch reservation beside its merged allocation, and this table claims `0033` twice as well as `0034`. So the assertion fails on arrival and what it needs first is a cleanup of the historical record, which is a session and a decision about which of each pair survives rather than a gate. It is [`OI-11`](../STATE.md), raised by the branch that met it, and it is the same shape as `OI-10`: **a duplicate that a gate reading for presence cannot see.**

### `ADR-046` was allocated twice IN ONE FILE, and the gate that checks for it could not run

**`docs/decisions/ADR-046.md` carried two `## ADR-046` headings** for two unrelated rulings: `OQ-P2-01`'s `CalendarSlice` ruling and `OQ-M10-06`'s reversible contact addresses. It was created by merging PR #40 and PR #41, neither of which had checked that the other claimed the number.

**This was not the two-ref gap and it was not a missing assertion either.** `CI-06f` has carried `if (seen.has(n)) findings.push("ADR-nnn appears more than once")` since it was written. **It could never fire**: `adrEntries()` in [`gates.mjs`](../../scripts/corpus/gates.mjs) read each file with a **non-global** `exec`, returning at most one entry per file, so two headings produced one entry and `seen` never collided. Fifteen gates passed over the duplicate.

**`ADR-049` is the one that moved, on a count rather than a guess**: 25 citing lines in 6 files against 70 in 20. And decisively, **37 of the other ruling's citations sit inside [`0034`](../../packages/db/migrations/0034_reversible_contact_addresses.sql), a merged migration constitution E2 forbids editing**, so that ruling was not renumberable at all. [ADR-034](ADR-034.md)'s tiebreak and E2 agree here, which they will not always do: **on this registry the ADR remedy and the migration rule can point in opposite directions**, and when they do, E2 wins because it is the one that cannot be complied with retroactively.

**The parser was tightened only after a seed was watched not firing.** `CI-06f/duplicate-heading` in [`falsify.mjs`](../../scripts/corpus/falsify.mjs) reported `DID NOT FAIL` against the non-global parser and `in scope, failed` after it, in that order, because tightening a parser without one is how 109 phantom anchors happened.
