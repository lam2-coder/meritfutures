# Number allocation

The three allocation registries, kept in one document because each is read AS A
TABLE: `CI-06f`, `CI-06h` and `CI-06p` call one shared parser over the first cell of
every row. A table split into a file per row is not a table, which is the same reason
`DELTA_MANIFEST` stays single under [ADR-043](ADR-043.md).

**Every table here carries two columns and no third.** The number, and who took it.
The State column that used to sit beside them is deleted, on [ADR-034](ADR-034.md)'s
own remedy, and the ruling is [below](#the-state-column-is-deleted-on-adr-034s-own-remedy).

## Number allocation, and why this table exists

**An ADR number is claimed here before it is written.** Two branches forking from the same `main` both read the registry, both find the same maximum, and both take the next integer. Neither is wrong locally; the corpus is broken the moment the second merges. **[ADR-034](ADR-034.md) rules the allocation, and [CI-06f](../testing/STRATEGY.md) enforces it.**

**Gaplessness is asserted over allocated plus reserved**, so a branch holding a reserved number shows a hole in this file and passes. A branch inventing an unreserved number fails.

**`053`, `054` and `055` were assigned to three parallel sessions within an hour of each other and none of them was reserved here at the time, so gaplessness was broken at every intermediate state and the first of the three to reach a commit paid for all of it.** The session holding `055` found `CI-06f` reporting `053` and `054` as holes, could not invent their subjects, and had to stop and ask. **That is a defect in how numbers are handed out, not in the gate**: `CI-06f` did exactly what [ADR-034](ADR-034.md) built it to do, which is refuse a sequence nobody can account for. ### `044` collided with an open sibling pull request, and this branch moved

**This session claimed `044`, wrote the ADR, the migration that cites it, its probe and eleven documents, and then found `044` already claimed by PR #25.** `main` ends at `043`, this branch is not behind `main`, and **twelve of twelve gates passed against that claim**, because `CI-06f` reads one ref and PR #25's branch is not it. **That is `CI-06f`'s declared coverage gap met in the wild for the second time in three days**, after [FOLD-02](../plans/FOLD-02-enforcement-window-and-suspension.md)'s plan hit it on `038`, and the cross-ref job that would close it is still not written.

**The remedy was a manual step this session skipped and the FOLD-02 session did not.** That session's record says "every remote branch was checked"; this one checked `main`, found `043`, and took `044`. **The table cannot do that step for you**: it is single-ref by construction, it says so in its own words two paragraphs down, and a claim made without reading the siblings is a claim made against a table that was never asked the question.

**It is resolved here rather than at merge**, which is FOLD-02's precedent rather than PR #4 and PR #5's: the founder assigned at merge once, [ADR-034](ADR-034.md) exists because that was expensive, and the branch that discovers a collision is the only one that can act on it. **This branch moved even though [ADR-034](ADR-034.md)'s tiebreak points the other way**, and the reasoning is worth the two lines it costs: the tiebreak renumbers the branch whose number is cited least, and this branch cites it forty-one times against PR #25's twenty-one, **including inside a migration**. But the tiebreak decides which branch *should* move, and only one branch *can*. **PR #25 is open, complete and waiting for a founder who would otherwise resolve a numbering conflict in a frozen registry by hand**; this session was still writing. The number cited inside a migration is the one that matters, and `0033` is unmerged, so the citation is a `sed` rather than a supersession.

### The State column is deleted, on ADR-034's own remedy

**A third column used to sit beside these two and say `allocated` or `reserved, unmerged`. It was wrong eleven times in nine days**, and the rows recorded it against themselves, one repair at a time: `035` four commits after PR #9 merged it, `036` after PR #13, `037` and `038` after PR #15, `039` through `043` after PR #17 and PR #18, and `045` with the migration table's `0033` after PR #29. **[ADR-036](ADR-036.md) already ruled the column prose no gate can check**, [STRATEGY](../testing/STRATEGY.md) already declared it as a coverage gap, and the column went on rotting anyway, because a declared gap is a description of a defect rather than a fix for one.

**[ADR-034](ADR-034.md)'s remedy has exactly two branches: generate the value, or delete it and point at the source.** There is no third, and in particular hand-repairing the column is not one, because that is what was being done, eleven times. This file already applied the remedy once, to the next-free-number sentence in the migration section below. Applied to the column, it splits the old cell in two:

| What the cell claimed | Disposition |
|---|---|
| **Is the artifact in this tree?** `docs/decisions/ADR-045.md` exists here, `0035_rule_states_calendar_revision.sql` exists here | **DERIVED, at check time, from the tree.** `CI-06f` and `CI-06h` already compute exactly this set to assert gaplessness against these tables; `node scripts/corpus/gates.mjs allocation` prints it per row. A derivation that runs is worth more than a cell that agreed with the tree on the day somebody typed it |
| **Has the branch that claimed it merged?** `allocated` against `reserved, unmerged` | **DELETED.** A runner reading one ref cannot tell a reservation from an allocation: the branch holding a reservation and the `main` that has absorbed it both show the number claimed. It is the two-ref problem [ADR-036](ADR-036.md) records, it is not closed here, and a claim no reader and no runner can check is not written down |

**Why the Claimed by column stays while the State column goes, which is the whole distinction.** A claimant is a historical fact and merging cannot falsify it: `merged to main (PR #17)` is true today and true forever, and a branch name records who to ask. **`reserved, unmerged` is false the instant the pull request merges, and nothing in the tree tells the row to change.** The volatile column is the one that was deleted, and it is the only one that ever drifted.

**What a reader loses, stated rather than glossed.** The table no longer says which claims are live. That was never a fact it held: it held a fact somebody entered, and the eleven instances are the measurement of how long that fact survived. What answers the question now is `git ls-remote`, which is the manual step the `044` collision above exists to teach, and `node scripts/corpus/gates.mjs allocation`, which answers the half a single ref can honestly answer.

**The duplicate rows are [`OI-11`](../STATE.md) and are not touched here.** Several numbers appear twice, a branch row beside the row recording that branch's merge, and choosing which of each pair survives is a decision rather than an edit. With the volatile column gone the pairs now differ only in their claimant, which is the form a dedup session will collapse.

**`docs/decisions/ADR-046.md` carried two `## ADR-046` headings** for two unrelated rulings: `OQ-P2-01`'s `CalendarSlice` ruling and `OQ-M10-06`'s reversible contact addresses. It was created by merging PR #40 and PR #41, neither of which had checked that the other claimed the number.
