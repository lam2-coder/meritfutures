## ADR-381: the imprecision three rows declined, where the FIRST decline was an interim that recommended the repair, the two after it inherited the verdict without that qualification, and the ground all three cite for declining is the ground that makes the repair safe (2026-09-06, status: proposed)

**THREE CONSECUTIVE ROWS FOUND ONE WRONG SENTENCE IN [`apps/api/src/start.ts`](../../apps/api/src/start.ts) AND EACH LEFT IT.** [ADR-372](ADR-372.md) section 9 reported it. [ADR-374](ADR-374.md) section 6 read it and left it. [ADR-379](ADR-379.md) section 7 left it "for the third time". This row was dispatched to settle whether that is a well-founded ruling nobody wrote down or a defect everyone assumed somebody else would take.

**IT IS NEITHER, AND THAT IS THE FINDING. IT IS ONE GENUINE FENCE REFUSAL FOLLOWED BY TWO INHERITANCES OF ITS VERDICT WITHOUT ITS QUALIFICATION.** [ADR-372](ADR-372.md) declined under a fence that permitted a `src/` edit only if a finding forced it, and its own section 15 question 3 recorded that decline as an **interim**, listed three dispositions of which two are repairs, and named the cheapest. **Neither row after it mentions that question, that recommendation, or the word interim.** By the third entry the interim is being defended as "a deliberate non-repair" whose reversal would be worse than leaving it alone.

**AND THE CLAUSE EACH ROW ADDED TO SHOW ITS REASON HAD GROWN STRONGER RUNS BACKWARDS.** [ADR-374](ADR-374.md) recorded two controls reddening on the append the sentence invites, [ADR-379](ADR-379.md) measured three. **That count measures how thoroughly the CONSEQUENCE is guarded, which is an argument that the repair is safe rather than an argument that it should not happen.** No entry in the sequence states a reason the sentence should remain false.

**RULED: REPAIRED.** The sentence is corrected in place, line-count neutral, and the emitted program is byte-identical.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `381`, branch `claude/the-imprecision-refused-three-times`, session **576**. ADR number and session number assigned centrally and not derived.
- **MONEY PATH, `E2` READ OWED.** [`start.ts`](../../apps/api/src/start.ts) decides what a deployment serves. Ships `proposed` with an **UNSIGNED** approval line. **Merging is not signing.**
- **ONE `src/` FILE IS CHANGED AND IT IS FOUR COMMENT LINES.** No port is wired, no door is opened, no handler behaviour changes, no triple moves. **The emitted program is byte-identical**, measured in section 7 with the instrument falsified in both directions.
- **NO TEST FILE WAS OPENED FOR WRITING AT ALL**, and section 8 is the reason rather than an omission. No invariant number is minted, no `CI-06` letter is spent, no migration number is taken or reserved, no `status` field is moved, no gate is weakened and no test is skipped, disabled or quarantined.
- **A DISPATCH PROMPT IS NOT A SOURCE** ([ADR-357](ADR-357.md)). Every claim this row carried was re-derived before it was used, and section 1 is that measurement.

> **3. THE FIRST DECLINE WAS EXPLICITLY AN INTERIM AND RECOMMENDED THE REPAIR.** [ADR-372](ADR-372.md) §15 question 3: three options, two of them repairs, *"(b) is the cheapest and this row took (a) as its interim"*. **Neither later entry names that question.** Section 4.

THE "COVERED N WAYS" CLAUSE IS AN ARGUMENT FOR REPAIRING, NOT AGAINST.** Three controls redden on the invited append, measured here. **That is why this repair needs no new case and carries no behavioural risk**, and it is the same fact all three entries cited when declining. ### 7. The premise all three declines share, measured for the first time

**ALL THREE CALL IT "A PROSE REPAIR TO A MONEY-PATH FILE" AND TREAT THAT AS CARRYING RISK. NONE OF THE THREE MEASURED THE RISK, AND IT IS ZERO.**

A comment-only edit cannot change what a deployment serves, and this is checkable rather than arguable, which is the constitution's own preference. **Both versions of `start.ts` were run through TypeScript's emitter with `removeComments`, and the output is byte-identical at 1,726 bytes.**

**THE INSTRUMENT IS FALSIFIED IN BOTH DIRECTIONS**, because a comparison that only ever answers "identical" is not a measurement:

| probe | expected | observed |
|---|---|---|
| the repair as shipped | identical | **IDENTICAL**, 1,726 bytes both sides |
| a different comment reworded | identical | **IDENTICAL** |
| the install commented out | differs | **DIFFERS**, 1,726 against 1,553 bytes |
| the install moved below `await main()` | differs | **DIFFERS at the SAME byte count**, 1,726 both sides |

**THE LAST ROW IS THE ONE THAT MAKES THE INSTRUMENT WORTH ANYTHING.** A reordering that changes no byte count is reported as different, so the check is comparing the program and not its size.

**THIS DOES NOT MAKE MONEY-PATH CAUTION WRONG. IT LOCATES IT.** The caution is owed to edits that change what runs. **An edit that provably changes nothing that runs is owed the ordinary care of getting the words right**, and three rows spent their refusals on a category the edit was never in.

### 8. Why no case is added, and the ruling that decides it

**THE OBVIOUS OBJECTION IS THAT A CLAUSE DEFENDED BY NO CASE IS A CLAIM**, which is this repository's rule and [ADR-374](ADR-374.md) applied it to its own reachability clause. **It does not apply here, for two independent reasons, and the second is a ruling rather than a preference.**

**FIRST, THE LOAD-BEARING HALF IS ALREADY PINNED THREE WAYS.** The half of the sentence that can hurt a reader is *"every install belongs above `await main()`"*. Seeded here: `start-program` red, `start-construction` red, `wiring` red. **The corrected sentence is true exactly when those three cases are green**, so it is a consequence of pinned properties rather than an independent claim needing its own pin.

**SECOND, THE OTHER HALF MUST NOT BE PINNED, AND [ADR-372](ADR-372.md) §8 IS WHY.** *"It is the last install"* is a fact about layout. That entry considered pinning line order in this exact file and refused: *"an assertion that pinned line order would be defending a property no deployment can distinguish, and a check like that is a check nobody can read the reason for later."* **A case added here to hold "the limiter is last" would be the assertion that ruling forbids**, and it would go red on the next route slice's legitimate append.

**AND THE THIRD SHAPE AVAILABLE IS THE WEAKEST ONE IN THE HOUSE.** A case asserting that `start.ts` does not contain the retired phrase asserts an absence, which [ADR-378](ADR-378.md) recorded as the weakest shape in that file because any rewording satisfies it. **This row declines all three and records the reason here so a fifth row does not spend a session rediscovering it.**

**THE HONEST STATEMENT OF THE RESIDUAL RISK:** nothing mechanical stops a later row restoring the false wording. **What stops it is this entry**, and that is the same protection every prose ruling in this corpus has.
