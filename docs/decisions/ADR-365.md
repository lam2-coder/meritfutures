## ADR-365: the admin money-out console refuses correctly and both refusal properties hold, and the entry describing it is wrong about what stops it: it names ONE blocker where the tree has TWO, and the unnamed one is the very door this deployable's OTHER admin port names in its own source (2026-09-06, status: proposed)

**`useAdminPayoutBackend` is the surface on which a human being at Merit approves or refuses a trader's money leaving.** Two rows sit behind it: `POST /admin/payouts/:id/release`, which clears a hold and posts `LT-01`, and `POST /admin/payouts/:id/enforce`, which fails the request and frees the rung. **The ruling is that the port refuses correctly, that neither refusal property can be broken by any path through the shipped default, and that the `BLOCKED` entry describing it retires the question in the wrong direction.**

**MONEY PATH. ADR-003 STRICT. `E2` READ OWED.** Nothing here moves a cent, writes a row, wires a port, opens a door, takes a migration number or mints an invariant. What it decides is what a later session is told this port owes.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `365`, branch `claude/the-admin-payout-backend`, session **560**. ADR number and session number assigned centrally and not derived.
- **A DISPATCH PROMPT IS NOT A SOURCE.** The declaration site the dispatch named was re-derived on this tree before a line was written and it reproduces exactly. **What did not reproduce is the blocker inventory**, and that is section 4.
- **NO `src/` FILE IS CHANGED, AND SECTION 8 IS THE MEASUREMENT THAT DECIDED IT** rather than a preference. The one prose repair this row owes under `RI-14` was WRITTEN, and writing it broke two citations in a file this row does not own. It is reverted and recorded as owed.
- **NO MIGRATION WAS TAKEN OR EDITED.** `git diff --stat origin/main -- packages/db/migrations scripts/db` is **EMPTY**.
- **THE CONTAINER ARRIVED WITH NO REPOSITORY.** `/home/user` was empty, with no clone and no `node_modules`. The tree was attached and cloned by hand before anything could be measured, which is the sixth session in a row to record it.

### 2. THE RULING

**RULED: THE ADMIN MONEY-OUT CONSOLE REFUSES CORRECTLY, AND THE ENTRY THAT SAYS WHY IS WRONG ABOUT WHAT STOPS IT.**

1. **The pair carries EIGHT members and exactly ONE is constructible today.** `AdminPayoutBackend` (`routes/admin-payouts.ts:375`) declares three and `AdminPayoutTx` (`routes/admin-payouts.ts:332`) declares five. `now` (`routes/admin-payouts.ts:394`) needs nothing. The other seven reduce to **TWO** suppliers.
2. **`ApiDb` HAS NO DOOR FOR SEVEN OF THE EIGHT, AND THAT IS THIS ROW'S FINDING.** `operator` (`routes/admin-payouts.ts:383`) needs a handle at `systemDb('operator-console')`, and there is none: `ApiDb` (`apps/api/src/db.ts:173`) declares five doors, no file in this deployable may take the accessor value that yields one, and the file permitted to take handles does not take that one. **The absence is [ADR-171](ADR-171.md) clause 1's ruling**, recorded at `db.ts:79`.
3. **SO THE `BLOCKED` ENTRY'S CLAUSE *"ONE SUPPLIER SHORT, AND THE SUPPLIER IS NOT A DOOR"* IS WRONG IN BOTH HALVES.** Two suppliers short, and one of them is exactly a door. Section 4.
4. **BOTH REFUSAL PROPERTIES HOLD, AND ARE ASSERTED AS CASES RATHER THAN PROSE.** No path through the unwired default can quote a figure, and no path can record anything, because the transaction is never opened at all. Section 5.
5. **A REQUEST MEETS 401 AND NOT 503, DELIBERATELY, AND THE 503 IS UNREACHABLE FROM THE SHIPPED DEFAULT.** `principal` is the only member of the eight any request touches. Section 6.
6. **DUAL CONTROL IS ABSENT ON THIS SURFACE IN FOUR PLACES AND THE MISSING VALUE IS THE FOURTH.** One operator holding `owner` or `ops` releases a held payout of any size. **No threshold is invented here.** Section 7.

### 4. THE FINDING: the entry names ONE blocker and the tree has TWO, and the sibling admin port names the second one in its own source

`wiring.test.ts`'s entry for this port reads, in the clause a session would act on:

> *"ONE SUPPLIER SHORT, AND THE SUPPLIER IS NOT A DOOR."*

**IT INHERITS THAT FROM [ADR-171](ADR-171.md) SECTION 4, WHICH WROTE THE SAME SENTENCE AND MEANT SOMETHING NARROWER THAN THE ENTRY NOW CARRIES.** That section's own words are that this port *"is the only one of the five whose remaining blockers, after `principal`, are all reachable"*, and its table's reason column for this row is *"`principal` rejects, so the backend cannot be constructed"*. **Both are true statements about a type. Neither is a statement about what a wiring slice can build**, and the entry compressed them into a claim that it is.

**THE SAME ADR REFUSES THE DOOR IN ITS CLAUSE 1 AND CONDITIONS IT IN ITS SECTION 9**, and the condition is the half that makes the entry misleading rather than merely short:

> *"A slice may declare `operator(fn)` on `ApiDb` when an `AdminSessionSource` a deployment can install exists in this tree ... **That slice takes an ADR number of its own and the admission is its SUBJECT**, on ADR-117 ruling 4's rule as narrowed by ADR-120 clause 1: a slice whose end is an admin console must decline the door, because the door is then a means."*

**SO THE SECOND BLOCKER IS NOT A LINE OF WIRING. IT IS AN ADR WHOSE SUBJECT MUST BE THE DOOR, WRITTEN BY A SLICE THAT MAY NOT ALSO BE INSTALLING THIS CONSOLE.** A session dispatched off *"one supplier short"* on the day an `AdminSessionSource` lands finds it still cannot write the adapter, and is then one line from either reversing ADR-171 clause 1 or breaking the accessor fence, on the money-out console. **ADR-171 clause 5's own sentence is the standard this entry now fails: *"A reason that misnames the obstruction is worse than a short one, because it retires the question in the wrong direction."***

**AND THE DOOR IS NOT AN UNNAMED BLOCKER EVERYWHERE. IT IS NAMED, IN THIS DEPLOYABLE'S OWN SOURCE, BY THE OTHER ADMIN PORT THAT NEEDS IT.** `READ_SOURCE_UNWIRED` (`routes/admin-reads.ts:1156`) is the message an unwired admin READ source carries, and it says:

> *"the door the wiring slice must take is `systemDb('operator-console')`, and ADR-171 section 9 makes that door takeable by the slice landing an `AdminSessionSource` a deployment can install."*

**TWO ADMIN PORTS WAIT ON THE SAME ABSENT DOOR. ONE NAMES IT AS ITS BLOCKER AND THE OTHER DENIES THAT A DOOR IS ITS BLOCKER, IN THE SAME TREE, ON THE SAME DAY.** That is exactly [ADR-358](ADR-358.md)'s finding: an entry rewritten to repair the clause it was dispatched about inherits the rest, and **the interesting blocker is the one nobody has ever named on this row** even though the identical sentence is already written eleven hundred lines away in a sibling module.

**THIS IS NOT A CLAIM THAT THE DOOR SHOULD OPEN.** ADR-171 section 5 is the strongest argument in that entry and it does not expire: the door lands on the object `databaseAuthBackend` already holds, and `ADR-120`'s `B1` then falls to one line at the reason word `'operator-console'` inside a handler serving an anonymous request. **What this row rules is that the blocker must be NAMED, not that it must be discharged.**

### 5. The two refusal properties, asserted as cases

**PROPERTY (a): NO PATH THROUGH THE UNWIRED DEFAULT QUOTES A FIGURE. IT HOLDS, AND IT IS ASSERTED THREE WAYS RATHER THAN ONCE.**

- **Every member of the default is CALLED.** All three refuse; each message names its member; **no message contains a digit at all**, and no member returns a `number` or a `bigint`. `Cents` is `bigint` in this tree and money is integer cents everywhere, so a value a reader could take as an amount is one of those two and neither is reachable.
- **The wire document is walked at every depth.** The only `number` anywhere in the 401 body is **`401` itself**, and no string in it carries a run of two or more digits. A `detail` quoting cents, a frozen `approved_cents`, or an `errors[]` echoing a body field would each land as a second number.
- **Seeded and watched.** A `detail` reading *"The held payout is 225000 cents."* on the 401 turns **two** cases RED independently: the key-set case and the number-walk case.

**PROPERTY (b): NO PATH RECORDS AN APPROVAL, A STATE CHANGE OR A DECISION. IT HOLDS IN THE STRONGEST FORM AVAILABLE.**

The assertion is not that a recorder saw no writes. **It is that `operator` is never entered**, so `spec.handle` never runs, and there is no `admin_actions` insert, no `payoutRequests` update, no `LT-01` posting and **nothing staged for a rollback to discard.** ADR-361's seed 1 is why the distinction is worth the case: a fixture stages, and a throw discards the staging, so a recorder can read empty for the wrong reason.

**BOTH PROPERTIES ARE MEASURED AGAINST THE SHIPPED VALUE AND NOT A STAND-IN.** The probe wraps `UNWIRED_ADMIN_PAYOUT_BACKEND`'s own members in counting delegates that call through to it, so the behaviour under test is the default's and the only thing added is the tally. A stand-in that merely rejected the same way would be this file agreeing with its own fake.

**AND THIS PORT SURVIVES THE CHECK THAT `PRODUCTION_CHECKOUT_ADAPTERS` FAILED.** [ADR-362](ADR-362.md) found a default named for production whose first-touched member serves and whose purchase commits. [ADR-361](ADR-361.md) found `UNWIRED_WITHDRAWAL_BACKEND` handing out the wall clock from a docblock claiming to refuse every call. **Neither shape is present here, and that is measured rather than inherited from either table**: seed 3 replaced this default's clock with a serving one and reddened two cases.

### 6. What a request meets today, walked from the handler rather than the docblock

**401, ON BOTH ROWS, AND NOT THE 503 THE CLASS DOCBLOCK ADVERTISES.**

`adminPayoutHandler` (`routes/admin-payouts.ts:1035`) reads `principal(request)` before it opens a transaction. The unwired default rejects, and an **inner** catch answers **401 `unauthenticated`**, deliberately, on ADR-192 clause 2: whether this process holds a backend is a fact about the deployment and an unauthenticated caller may not have it. The discrimination goes to the log, where the message names the port member.

| Request | What it meets | Members touched |
|---|---|---|
| `POST /admin/payouts/:id/release` | **401 `unauthenticated`**, five-key document, logged at error | **`principal`, and nothing else** |
| `POST /admin/payouts/:id/enforce` | **401 `unauthenticated`**, five-key document, logged at error | **`principal`, and nothing else** |
| either row, with a PARTIAL install whose `principal` resolves | 503 `service_unavailable` | `principal`, then `operator` |

**SO THE 503 BRANCH IN THE OUTER CATCH IS UNREACHABLE FROM THE SHIPPED DEFAULT.** It is reached only by a partial install. **`admin-payouts.test.ts` already asserts the statuses** and has since ADR-192; what this row adds is the DOCUMENT, the touch count, and the consequence for the docblock.

**AND THE CONSEQUENCE IS ONE SENTENCE OF PROSE THAT IS FALSE OF THE ONLY MEMBER THE DEFAULT EVER REACHES.** `AdminPayoutUnwired` (`routes/admin-payouts.ts:398`) is introduced as *"Answered as 503, never 500."* **That is true of `operator` and of `now` and false of `principal`**, which is answered as 401. It is [ADR-361](ADR-361.md) section 6's shape arriving on the admin side of the same money, with the difference that here **the value is right AND the handler is right, and only the sentence is wrong.** It is not repaired here; section 8 is why.

**ONE THING THIS ROW MEASURED THAT SETTLES HALF OF A SIBLING'S OPEN QUESTION.** `OQ-361-01` asks what convention governs a clock on a fail-closed default, and warns that its option (b) is not free because making a clock refuse BEFORE moving its read turns a money-out 503 into a 500. **This port already holds option (b)'s end state**: the clock throws, and **both** of its read sites sit inside `adminPayoutHandler`'s `try`, asserted by index. So the convention ADR-361 could not choose between has a worked example in the tree, on the adjacent money-out door, and the example is this one.

### 7. Dual control, and the value this row does not invent

**WHAT THE PORT WOULD NEED FROM `dual_control_threshold_cents` IS A SECOND APPROVER, AND THE THRESHOLD IS THE FOURTH THING MISSING RATHER THAN THE FIRST.**

The release row admits `ACCOUNT_ACTION_ROLES` ([`admin-writes.ts:159`](../../apps/api/src/routes/admin-writes.ts)), which is `owner` and `ops`. **One operator holding either role clears the hold and posts `LT-01` for whatever the hold froze, at any size.** For that to be dual controlled the port would need, in this order:

| # | What is needed | State |
|---|---|---|
| 1 | a column on `payout_requests` recording which approval authorised the release | **ABSENT.** No migration puts a `dual_control_*` column on that table |
| 2 | a key in `ADMIN_PAYOUT_TABLES` (`routes/admin-payouts.ts:314`) through which an approval row could be read | **ABSENT.** The union is `payoutRequests`, `adminActions`, `evidencePacks` and a typo is a compile error, so a missing member is an impossibility |
| 3 | a wire field on `PayoutReleaseBody`, whose one member is `reason` | **ABSENT** |
| 4 | the threshold VALUE the amount is measured against | **UNSET, and founder-owed** |

**MEASURED: `admin-payouts.ts` NAMES `dual_control` ZERO TIMES.** So does `payouts.ts` and so does `wallet.ts`; `wallet-withdrawals.ts` names it five times. **[`DELTA_MANIFEST`](../../packages/db/DELTA_MANIFEST.md) already records this in its own words** and this row reproduces rather than discovers it: the threshold gap *"is not [open], on the withdrawal path; it remains open on `payout_requests`, where all four counts are still 0."*

**THE COLUMN IS REAL ELSEWHERE, WHICH IS WHY THE ABSENCE IS A FINDING AND NOT A GAP IN A SPECIFICATION NOBODY WROTE.** `0038` shipped `dual_control_threshold_cents bigint NOT NULL CHECK (> 0)` on `account_adjustments`, `0068` gave it a ceiling of `500000`, and `0070` put a nullable one on `wallet_withdrawals` with six CHECKs around it. **Two of Merit's three money-out or money-adjusting surfaces carry dual control in the schema. The third is the one where a human releases a held payout, and it carries none.**

**SO THE FINDING IS THAT THE PORT CANNOT BE MADE CORRECT BY SUPPLYING A VALUE**, and a row handed the threshold tomorrow would have nowhere to put it. **Whether payout release SHOULD be dual controlled is a founder ruling and this row does not take it. NO THRESHOLD, MINIMUM, FEE, HOLD PERIOD, QUORUM, CURSOR OR TIMEOUT IS INVENTED HERE**, and the suite asserts the module reads none.

### 9. Open questions, recorded as options rather than answered

**OQ-365-01. Must payout release be dual controlled, and if so at what threshold?** Section 7 measures that the surface has none while `account_adjustments` and `wallet_withdrawals` both do. **Options: (a)** rule that payout release is single control by design, because the hold already required a detector flag and the amounts were frozen at request time, and record that as the reason the third surface differs; **(b)** rule that it must be dual controlled, which needs a column, a `ADMIN_PAYOUT_TABLES` member, a wire field and a value, in that order, and is a migration plus a contract amendment rather than a wiring; **(c)** rule that the `admin_actions` row plus the two-role gate IS the control, which is a decision to state rather than build. **This row invents no threshold and takes no option.**

**OQ-365-02. Does the door blocker get named on this row, or does the row get folded into the read port's?** Section 4 measures that `setAdminReadSource` and `useAdminPayoutBackend` wait on the same absent door and describe it oppositely. **Options: (a)** repair this entry's clause to name both suppliers, which is the smallest change and is what section 8 records as owed; **(b)** hoist the door into a single named blocker that several entries reference, since five ports reduce toward it, which stops the divergence recurring but is a change to how `BLOCKED` is structured; **(c)** leave the entry and rely on ADR-171 section 9, which is what has been happening and is how the divergence arose.

**OQ-365-03. Is the `AdminPayoutUnwired` docblock repaired, and by whom?** Section 8 measures that this row cannot make it. **Options: (a)** a row whose fence spans `payouts.ts` makes both edits together; **(b)** the citation grammar stops binding line numbers, which is `RI-15`'s own row and is now owed by three entries; **(c)** the sentence stands and this ADR is the record, which is the state on merge if nobody acts.

### 10. Where this entry is most likely wrong

- **Section 4 rules the entry misleading, and a reviewer may hold that it is merely compressed.** ADR-171 section 4's sentence is defensible in its own context: it was answering *"would the door move this port"* and the answer was no, because `principal` rejects first. **If a reviewer holds that a `BLOCKED` reason may name the PROXIMATE blocker only, then this entry's finding is a documentation preference rather than a defect.** The measurement is the same either way; what differs is whether a reason owes the whole chain. **This row holds it does, on ADR-171 clause 5's own standard, and that is an argument rather than a measurement.**
- **Section 3 says `operator` has no supplier, and that rests on the accessor fence holding.** It is asserted three ways here and pinned independently by `db.test.ts`, but all four assertions read the tree as text. **A dependency that re-exported `systemDb` under another name would defeat every one of them**, and nothing in this row looks for that.
- **Section 7 measures an absence and does not prove it is a defect.** The corpus may deliberately intend single control on this surface, and no ADR this row read either states or refuses it. **A reviewer who rules option (a) makes section 7 a documentation finding rather than a control gap**, and the honest position is that the absence is unexplained rather than wrong.
- **Section 6's claim that the 503 is unreachable is a claim about the SHIPPED default only.** It is reachable the moment anything installs a backend whose `principal` resolves, which is the partial install the third table row measures. **Nothing in this tree goes red on that partial install**, and that is a landmine rather than a finding of this row's.
