## ADR-275: the register that names every invariant in this tree was read by nothing, so a check could land without its row with every gate green  (2026-08-30, status: proposed)

**[ALLOCATION](ALLOCATION.md) row `275` was dispatched on a claim it required be re-derived rather than believed: *"nothing in this tree reads the live `CHECKS` array against this file's `RI-nn` table"*. IT HOLDS, AND THE MEASUREMENT IS SHARPER THAN THE ROW'S WORDING.** Three allocation tables in that document already have gates over them and the fourth did not. `gates.mjs` reads the ADR-number table (`ALLOCATION_DOC`, `ADR_ALLOCATION`), the migration-number table (`MIGRATION_ALLOCATION`) and the `CI-06` letter table (`LETTER_ALLOCATION`, gate `CI-06p`). **The invariant register was the one registry in that file with nothing over it**, and `RI-15` and `RI-16` read the document for CITATIONS rather than for completeness.

**`RI-29` IS MINTED IN THIS COMMIT AND IT LANDED RED ON THE REAL TREE.** Five defects, none of them visible to any other gate: **`RI-11` had no register row at all and never had one**, and `RI-08`, `RI-18`, `RI-27` and `RI-28` each carried a third cell that was not the title the live array holds. **Two of the four asserted in their own text that the title had been copied out of the array while carrying no title at all.**

**THE ROW NAMED A SECOND PROPERTY AND WARNED THAT IT IS PROBABLY NOT BUILDABLE HERE. IT IS NOT, AND THAT IS RULED RATHER THAN FAKED** (section 6). Nothing in this repository can read a dispatch, which is what let sessions 463, 464 and 465 each reserve `RI-26` honestly out of one note at one instant. **The repair for that half is a dispatch-time reservation, which row `275` itself performed**, and no control is invented for it here. That is [ADR-274](ADR-274.md)'s move on `TZ` one wave earlier, applied to the register instead of the clock.

- **Origin:** [ALLOCATION](ALLOCATION.md) row `275`, session **466**, branch `claude/a-register-nothing-reads`. **NO MIGRATION NUMBER IS TAKEN OR RESERVED** and no migration file is written. **`RI-29` was RESERVED to the row rather than read out of the register's next-free note**, which is the first time a number arrived that way after three sessions in one wave read the note honestly and collided.

- **THE DELIVERABLE IS ONE CHECK, ITS SEEDED TESTS, THE REGISTER REPAIR AND THIS ENTRY. NO SHIPPED SOURCE FILE IS EDITED.** `apps/**` and `packages/*/src/**` are untouched in this diff. Ships `proposed` with an **UNSIGNED** approval line. **Merging is not signing.**

- **WHAT IS MEASURED, WHAT IS DERIVED, AND WHAT IS JUDGED.** That nothing read the register is **MEASURED**, by reading every consumer of `ALLOCATION.md` in `gates.mjs` and in the check files (section 3). The five defects are **MEASURED**, by running the check against the tree before the repair (section 4). That each leg fails on the violation it names is **MEASURED**, by seeding the real document six times and restoring it byte-identical (section 7). What is **DERIVED** is that the register's own stated rule was unenforced in both directions. What is **JUDGED** is containment rather than equality for the title leg (section 5), the refusal of an exemption list inside the check (section 5), and the refusal of a dispatch control (section 6).

- **A DISPATCH PROMPT IS NOT A SOURCE.** Every fact row `275` supplied was re-derived at this commit before anything was written, and one of them was understated: the row said nothing reads the register, and the sharper statement is that **three sibling tables in the same document are gated and this one was not**.

### 2. THE RULING

> **1. THE INVARIANT REGISTER IS A DERIVED SPAN AND IS NOW READ AS ONE.** The `RI-nn` table in [ALLOCATION](ALLOCATION.md) is the record of what checks this tree holds, its own rule is that the rows are read out of the live `CHECKS` array and never typed, and until this commit neither half of that sentence was enforced by anything.
>
> **2. `RI-29` IS MINTED IN THIS COMMIT**, in the same commit as its row, with the title copied out of the live array. Three legs: check to row, row to check, and title drift. A sentinel that THROWS on an empty register, because an absence over an empty scope reports PASS in silence.
>
> **3. NO EXEMPTION LIST LIVES INSIDE THE CHECK.** A register row whose id is not in `CHECKS` is admitted only when the row's own third cell links a source file that exists and carries the id, which is how `RI-17` passes. **A list of exceptions kept in the check would be the second copy this register exists to end**, and it would go stale in step with the thing it exempts.
>
> **4. A MALFORMED ROW IS A FINDING RATHER THAN A SKIP.** Any line opening with a backticked `RI-nn` cell must carry the register's three cells. `RI-23`'s row sat outside the table as a two-cell fragment for a wave, seen by nothing: `CI-06/table-row-width` parses rows of tables and a fragment after a blank line is not part of one.
>
> **5. THE TITLE LEG IS CONTAINMENT, NOT EQUALITY, AND THAT IS A JUDGEMENT.** A row may say more than the title and the later rows all do, recording where the check landed and what it was watched doing. What it may not do is fail to carry the title. Section 5 states what this admits.
>
> **6. THE FIVE DEFECTS THE CHECK FOUND ARE REPAIRED IN THIS COMMIT AND EACH ROW SAYS SO.** None is backfilled quietly. `RI-11`'s row is the latest on the page and says that it is.
>
> **7. THE DISPATCH HALF IS REFUSED AND NOT DEFERRED.** Nothing here can read a dispatch, so a control over it would be a control nobody runs. The repair is that a wave reserves each row's invariant number in the row, as row `275` did. Section 6.
>
> **8. NOTHING WAS WIDENED AND NO GATE WAS WEAKENED.** No shipped source file is edited, no migration is written, no fence is widened to finish, and `RI-29` was watched RED on the real tree under six seeds before it was trusted.

### 3. What read the register before this commit, which is nothing

**THE DOCUMENT HOLDS FOUR ALLOCATION TABLES AND THREE OF THEM ARE GATED.**

| Table in [ALLOCATION](ALLOCATION.md) | What reads it | In both directions |
|---|---|---|
| ADR numbers | [`gates.mjs`](../../scripts/corpus/gates.mjs) through `ADR_ALLOCATION`, with reserved-row dispositions | yes |
| Migration numbers | [`gates.mjs`](../../scripts/corpus/gates.mjs) through `MIGRATION_ALLOCATION` | yes |
| `CI-06` letters | [`gates.mjs`](../../scripts/corpus/gates.mjs) `CI-06p`, through `LETTER_ALLOCATION` | yes, with a sentinel that throws when the table parses to nothing |
| **The `RI-nn` invariant register** | **nothing** | **no** |

**THE LETTER TABLE IS THE PRECEDENT AND IT IS AN EXACT ONE.** Its own comment in the runner records that *"for a week nothing read it"*, that the cause was a parser fact rather than an oversight, and that *"the table that was written to end three plan documents hand-maintaining one sequence was itself the one registry with no gate over it, and it said so in its own words."* **The invariant register said so in its own words too**, at [ALLOCATION:523](ALLOCATION.md): *"THE ROWS ARE READ OUT OF `repo-invariants.mjs`'s `CHECKS` ARRAY, NEVER TYPED."*

**WHAT `RI-15` AND `RI-16` DO WITH THIS DOCUMENT IS A DIFFERENT QUESTION.** Both resolve `file:line` pointers: `RI-15` over source, `RI-16` over documents. A register row carries no pointer of that shape, so a row naming a check that does not exist resolves nothing and neither check has an opinion. **`falsify.mjs` edits the file** to prove a corpus gate fires, and restores it. **None of the three asks whether the register is complete**, and completeness is the only question that catches a check landing without its row.

### 4. What the check found on its first run, before anything was repaired

| Finding | What it is |
|---|---|
| **`RI-11` has no register row** | It is a member of `CHECKS`, imported from [`ui-server-endpoints.mjs`](../../packages/tooling/checks/ui-server-endpoints.mjs) on [ADR-138](ADR-138.md) ruling 3, and this table has never carried a row for it in any wave. A paragraph below the table describes it in prose, which is the shape the register exists to replace |
| **`RI-08`'s title had drifted** | The cell read *"No package in this workspace declares the database accessor, in any dependency field"*, which is the EMPTY-`DB_ADMITTED` branch of a title computed from that list. It stopped being what the array holds the day [ADR-120](ADR-120.md) admitted the first package |
| **`RI-18` carried no title** | Its cell states the subject in the check's own vocabulary rather than the title, which is computed from `SUBJECTS` |

**THE TWO KINDS ARE WORTH SEPARATING BECAUSE THEY FAIL DIFFERENTLY.** A row that is missing is a gap somebody could notice by counting. **A row that ASSERTS its title was read out of the array while carrying none is a row that reads as compliant**, and no amount of careful reading finds it, because the sentence claiming compliance is the thing a reader checks against.

**AND TWO OF THE FOUR DRIFTED TITLES ARE COMPUTED.** `RI-08`'s is computed from `DB_ADMITTED` and `RI-18`'s from `SUBJECTS`. **A computed title is the case a typed copy cannot survive**: it moves when a list grows, in a commit whose subject is the list, and nothing points at the register.

### 5. The check

**THREE LEGS, THE FIRST TWO IN BOTH DIRECTIONS ON `0027`'s IDIOM.** It lives in [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) beside every other member, reads [ALLOCATION](ALLOCATION.md) as text, and reads the array as the array.

| Leg | What it asserts | How it fails |
|---|---|---|
| **Check to row** | Every `id` in the live `CHECKS` array has EXACTLY ONE register row | A check landing without its row, and a renumber recorded twice |
| **Row to check** | Every `RI-nn` row names a check that exists | A number in the register with nothing behind it |
| **Title drift** | The third cell carries the live `title` verbatim | A row nobody re-read |

**A ROW IS ANY LINE OPENING WITH A BACKTICKED `RI-nn` CELL, WHEREVER IT SITS.** Not any line inside a table: the fragment class is the one no table gate can see, so the check finds it by shape and then demands the register's three cells. That is `RI-23`'s wave-long orphan caught by construction rather than by remembering it happened.

**LEG 2 IS DERIVED FROM THE ROW AND NOT FROM A LIST HERE, WHICH IS THE ONE PIECE OF DESIGN IN THIS ENTRY.** `RI-17` is in the register and not in `CHECKS`, ruled that way because `packages/tooling` resolves neither `@merit/api` nor `fastify`. The naive shape is an exemption list inside the check. **That list would be a second copy of exactly the thing this register exists to keep single**, and it would go stale silently the day the check moved. So the admission is read out of the row: the third cell must link a `.ts`, `.tsx`, `.mts`, `.mjs` or `.js` file that exists and carries the id. **A row that stops naming a real home goes red without anything in the check being edited.**

**WHAT IT ADMITS, STATED RATHER THAN IMPLIED.** The home link is a text read: a file that merely MENTIONS the id satisfies it, and nothing here confirms that the file DEFINES a check. The title leg is containment, so a row may carry the title plus a paragraph that contradicts it. **Both are the same trade `RI-16` makes with a pointer**: what is mechanical is that the name is there, and what it means stays a reader's job.

**A SENTINEL THAT THROWS, ON `RI-24`'s, `RI-25`'s AND `RI-28`'s PRECEDENT AND ON `CI-06p`'s.** A register parsing to zero rows is an ERROR. Two of the three legs would then be asserting about an empty list, and the third is worse than silent: it would report every check as unregistered and name the wrong defect entirely. **A missing document throws too, because a missing register is not an empty one.**

### 6. The second property, which is not buildable from here

**ROW `275` NAMED IT AND SAID IN ADVANCE THAT SAYING SO WOULD BE BETTER THAN FAKING IT.** The property is that nothing reads the register's next-free note against a DISPATCH, which is what let one wave spend one number three times.

**IT CANNOT BE CHECKED FROM INSIDE THIS REPOSITORY, AND THE REASON IS STRUCTURAL RATHER THAN A MATTER OF EFFORT.** A dispatch is a prompt handed to a session. It is not a file here, it leaves no artifact here, and the three sessions that collided were each reading a note that was TRUE at the moment they read it. **A check that fired after the fact would be reporting a renumber that had already happened**, which the rows already record by hand and better.

**SO NO CONTROL IS INVENTED FOR IT.** This is [ADR-274](ADR-274.md)'s ruling one wave earlier in a different subject: it refused a `TZ=UTC` line in the deployment contract because nothing here can read a deployment's environment, and replaced it with the property that made the setting irrelevant. **The analogue holds only halfway and that is worth being honest about.** There is no property `RI-29` can hold that makes a concurrent reservation impossible.

**WHAT ACTUALLY REPAIRS IT IS NOT A CHECK, AND ROW `275` PERFORMED IT.** The row reserved `RI-29` itself. A wave that reserves each row's invariant number at dispatch removes the shared mutable read entirely, because the numbers are then assigned by the one reader who sees all the rows at once. **The next-free note stops being the reservation mechanism and becomes what it should always have been: a record of what was taken.** The note now says that.

### 8. Where this entry is most likely wrong

**THE TITLE LEG IS CONTAINMENT AND A REVIEWER MAY WANT EQUALITY.** Rows `RI-01` through `RI-16` carry the bare title and would satisfy either rule. Everything from `RI-17` on wraps it in prose that is worth keeping, so equality would mean either deleting that prose or adding a fourth column. **Containment was chosen because the alternative rewrites twelve rows to make a check simpler**, and the failure it admits is narrow: a row carrying the correct title and a contradictory paragraph. `RI-16` makes the same trade with a pointer.

**THE HOME-LINK ADMISSION IS A TEXT READ AND IT IS THE WEAKEST CLAUSE HERE.** A row could link any source file that happens to mention the id. Reading the linked file for an actual check definition is possible and was not taken, because a check `RI-29` cannot import and cannot execute would have to be recognised by pattern, and pattern-matching a definition is how a check ends up asserting about a spelling. **A reviewer who wants the stronger clause should say so**; the cheap version is requiring the linked file's own text to bind the id to an exported symbol.

**AND `RI-29` DOES NOT ASK WHETHER A ROW IS TRUE.** It asks whether the register names the same checks the tree runs, with the same titles. **A row's second cell can claim anything at all about who claimed the number and why**, and this check reads none of it. That is `CI-06p`'s own limit stated in its words: it says nothing about whether a gate does what its row claims, *"which is falsify.mjs and not a parse."*

  1. **IS CONTAINMENT THE RIGHT RULE FOR THE TITLE LEG, OR SHOULD THE REGISTER GROW A FOURTH COLUMN?** Section 8's first paragraph.
