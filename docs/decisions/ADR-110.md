## ADR-110: the method page is a public read of a versioned definition, and the address of a definition is a pair whose second half the path does not carry (2026-08-26, status: accepted)

**[API_CONTRACT](../architecture/API_CONTRACT.md) is `approved`, so the contract half of [P4](../plans/P4-portal-and-site.md) section 8's `P4-f` row is an ADR and not a commit ([C7](../../MERIT_BUILD_MASTER_PROMPT.md)).** This entry is that half. It rules what `GET /public/methods/:statCode` answers with, which is EVERY version of the definition rather than the current one; what `public` costs and buys on a path the surface filter classifies rather than a heading does; and what an endpoint does in a deployable that holds no database handle yet.

### 2. THE RULING

> **1. THE ROW ENTERS [API_CONTRACT](../architecture/API_CONTRACT.md) SECTION 4, AS `GET /public/methods/:statCode`, `Auth: none`.** Section 4 is the contract's public section and this is a public read; M12 owns the endpoint ([M12:218](../plans/M12-transparency-platform.md)) and the contract owns its shape. **The row is the whole of the contract change**: no section is renumbered, no other row is touched, and section 12's matrix gains nothing, because an unauthenticated surface has no negative-authz row to state.
>
> **2. THE RESPONSE IS EVERY VERSION, ASCENDING, EACH WITH ITS OWN `adr_ref` AND `effective_from`.** [M12 section 4](../plans/M12-transparency-platform.md) says "The method page, **all versions**, with the ADR reference for every change", and [M12:144](../plans/M12-transparency-platform.md) says why: when a definition changes "the method page shows both", because "a transparency series with an invisible methodology break is the most sophisticated way to mislead available to a firm that computes its own numbers".
>
> **3. NO VERSION PARAMETER IS ADDED, AND THE SCHEMA IS WHY IT IS NOT NEEDED.** `statistic_definitions_code_version_uq` makes `(stat_code, version)` the address of one definition for all time, and clause 2 puts the whole set behind the first half of that pair, so a caller wanting version 2 selects a member of a response it already holds. **The published surface already carries the other address**: `published_statistics.definition_version` on every row, and a `method_path` spelling `/methods/ST-01/2`. A version selector on THIS path would be a second address for a row that has one, and the second address is the one that goes stale.
>
> **4. `live_version` IS THE UNSUPERSEDED ROW AND IS NOT NAMED `current` OR `effective`.** `statistic_definitions_live_uq` guarantees at most one, so the field costs no arithmetic. It is not "current" because `INV-M12-07` makes `effective_from` **always a future date at write time**, so the unsuperseded row is regularly one that has not taken effect. **NO CLOCK IS READ ANYWHERE IN THE HANDLER.** A cacheable public read whose body depended on the request's date is one two callers sharing a cache entry could disagree about, and the disagreement would be about which method produced a published number.
>
> **5. THE TWO SURROGATE KEYS ARE WITHHELD AND `superseded_by` IS RENDERED AS A VERSION.** [API_CONTRACT section 1](../architecture/API_CONTRACT.md)'s response-shape policy is an allowlist. `id` and `superseded_by` are uuids naming rows; the version they name is the half that means something on a page. **A `superseded_by` that names no version in this statistic's own set is REFUSED rather than rendered as `null`**, because `null` in that field says "this is the live version" and that is a false statement about a superseded definition.
>
> **6. `404` MEANS "NO STATISTIC IS PUBLISHED UNDER THIS CODE" AND NOTHING ELSE.** It is the only answer a caller can cause. This is deliberately UNLIKE the 404 the same status carries on a trader surface, where [API_CONTRACT section 1](../architecture/API_CONTRACT.md) makes it ambiguous between "absent" and "not yours" so the API does not confirm the existence of other people's resources. There is nobody whose definition this could be, so there is nothing to be ambiguous about. **The stat code reaches the source verbatim**: not upper-cased, not trimmed, because a normalising route turns two addresses into one silently.
>
> **7. THE SOURCE IS A PORT, IT IS UNWIRED IN THIS TREE, AND AN UNWIRED SOURCE IS A `500`.** `apps/api` declares `fastify` and nothing else, so this slice cannot read the table without a manifest change that is not its fence. `MethodDefinitionSource` is the seam. **The unwired handler throws, `server.ts` renders `internal_error`, and it is logged**: it does not answer 404, which would say the statistic does not exist, and it does not answer 503, which invites a retry against a process that will never succeed. **The door the wiring slice must use is `firmDb()`** ([`scoped-db.ts:535`](../../packages/db/src/scoped-db.ts)), whose own header names a request handler reading a `firm` table as the case it was added for. Not the per-identity accessor, and not `systemDb`, whose two reasons are `'nightly-batch'` and `'operator-console'` and neither is a request handler.
>
> **8. THE ROW STATES CACHEABILITY THE WAY [M12](../plans/M12-transparency-platform.md) STATES IT AND INVENTS NO TTL.** M12 section 4's sibling public read is "Cached, no session, no rate limit beyond edge protection", and M12 names no number for either. `GET /plans` carries `Cacheable (60s)` because a stale PRICE is `FM-M9-01`, and a method page quotes no purchasable term. **`INV-M9-04` does not reach this endpoint**; section 5 is that argument and the gap it leaves.

### 3. Clause 1 and 6: what `public` means, in two senses that are independent and coincide here

**THE READER IS ANYBODY.** `Auth: none`. No session is required, none is trusted, and no identity is resolved, so the handler opens no per-identity handle at all.

**THE ROW IS NOBODY'S.** [`scope.ts:538`](../../packages/db/src/scope.ts) classifies `statistic_definitions` `firm`: "There is no identity column and there is no correct one, a definition is the method rather than a number about anybody, and it is the same method for every reader."

**A FIRM READ THAT MERELY HAS NO IDENTITY IN HAND IS THE OTHER THING, AND THE DIFFERENCE IS WHICH SIDE THE ABSENCE IS ON.** `firmDb()` takes no reason because no identity is at risk in the ROW; an authenticated operator or a batch reading `plan_versions` is doing that, with a caller who has an identity and a table that has no use for one. Here the absence is on both sides at once, and their coincidence is the whole safety argument: **there is no field in a definition that an identity filter would have had to remove**, so nothing is withheld, nothing has to be remembered by a later reviewer, and the surface cannot regress into one by acquiring a column. A `firm` read whose table later acquired an identity column would be a defect ([ADR-101](ADR-101.md) section 8 records exactly that live defect in the classification's mechanical check); this endpoint would be a **disclosure**, which is why clause 5's allowlist is written as a field list rather than as a spread.

**THE SURFACE FILTER IS NOT A NO-OP ON THIS PATH.** `classifyPath` answers `public`, so `compose` registers the route on the `api` deployment and **withholds it from `api-admin`**, which then answers 404 by having nothing there ([ADR-083](ADR-083.md) section 4). Public does not mean "served by both": only `/health` is, and `surface.ts` states why that one row is not a carve-out. The suite asserts the withheld direction, because a mechanism nobody watches from the negative side is a mechanism that quietly stops working.

### 4. Clause 2, 3 and 4: what the DDL decided, quoted rather than paraphrased

```sql
CREATE UNIQUE INDEX statistic_definitions_code_version_uq
  ON statistic_definitions (stat_code, version);

CREATE UNIQUE INDEX statistic_definitions_live_uq
  ON statistic_definitions (stat_code) WHERE superseded_by IS NULL;
```

[`0021_transparency.sql:124`](../../packages/db/migrations/0021_transparency.sql)

**The first index is the reason the path is not enough and the second is the reason nothing has to be chosen.** A statistic has many versions and the code names none of them, so a route that answered with one row would be answering a question the caller did not ask; a statistic has at most one unsuperseded row, so naming it is a projection of a database guarantee rather than a policy this route invented.

**THREE SHAPES THE DATABASE FORBIDS ARE CHECKED ANYWAY, AND ONE MORE THAT IT DOES NOT.** Two rows at one version, two unsuperseded rows, and a row belonging to another statistic are each ruled out by an index or by the query that would have to be written; a supersession chain in which every row points onward is ruled out by neither. All four refuse. The source is an INTERFACE rather than the database, and the failure that reaches a reader is not "the query was wrong", it is **"Merit published the wrong method beside a number"**, which is the single thing [M12](../plans/M12-transparency-platform.md) exists to prevent.

### 5. `INV-M9-04`, named rather than left for a reader to wonder about

**IT DOES NOT REACH THIS ENDPOINT.** [M09:51](../plans/M09-marketing-site.md) states `INV-M9-04` as "A plan version publish invalidates every page derived from it, before the version is purchasable", its trigger is `POST /admin/plans/versions/:id/publish`, and its record is `page_revalidations` (`SD-M9-03`). A method page is derived from `statistic_definitions`, which no plan publish touches, and this endpoint quotes no price, so neither the invariant's trigger nor its reason (`AS-M9-01`, a stale price honoured at checkout) is present.

**THE NEIGHBOURING GAP IS RECORDED RATHER THAN RESOLVED, because resolving it is a different fence.** A definition version reaching its `effective_from` changes what a method page says, and [M12:236](../plans/M12-transparency-platform.md) gives `stats.definition_changed` the consumers **FEED and EVID**. M9's revalidation is named as a consumer of `stats.published` alone. So **no revalidation contract in this corpus fires when a definition changes**, and any statically rendered method page can be stale for exactly as long as nothing else republishes it. That is a finding for whichever slice renders those pages, and [ADR-095](ADR-095.md) section 9 item 4 already carries its sibling: `INV-M9-04` has an unstated replica-count precondition.

### 6. What this FORECLOSES

1. **`GET /public/methods/:statCode` can never answer with one version.** Any client written against clause 2 reads `versions`, and narrowing the response later is a breaking change, which under [API_CONTRACT section 1](../architecture/API_CONTRACT.md) means `/api/v2` rather than a silent shape change.
2. **A version parameter on this path is closed.** The pair is addressable through the set, and a future selector would be a second address for the same row.
3. **No handler in this file may read a clock.** Clause 4 is what makes one cached response true for every caller who shares it, and an "effective today" field would end that in a way no test of a single response can see.
4. **The two surrogate keys are permanently out of the response.** Adding `id` later publishes a database key into a page whose whole point is that it can be checked without one.
5. **The unwired state is a 500 forever, not a 404.** The day a source is wired this branch stops being reachable; until then, no monitor may be taught that this path returning 404 is normal.
6. **The wiring slice takes `firmDb()`.** If it names the per-identity accessor under `apps/api/src` instead, `VG-3` and `VG-6` report their artifact ARRIVED and `CI-06/vg-inventory` fails at 29 of 30 ([`gates.mjs`](../../scripts/corpus/gates.mjs)'s `VG_PROBES`). That is the gate working, and it is stated here so the next session reads it as good news rather than as breakage.
