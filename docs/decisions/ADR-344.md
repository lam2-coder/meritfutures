**EVERY REFUSAL THE JOB CLAIMS TO HONOUR WAS CHECKED AGAINST THE FILE THAT INSTALLS IT, AND FOUR MATTER MOST.**

1. **THE ROW LOCK, AND THE PRECONDITION RE-READ UNDER IT.** `releaseHold` takes `lockAt`, then re-reads the status AND the clock, and records `superseded` rather than releasing twice. This sweep is the THIRD door onto the hold transition; an operator releasing at 12:59:59 and this job firing at 13:00:00 must produce ONE release.
2. **THE LEDGER KEY IS THE REQUEST'S OWN.** `releaseLedgerKey` builds `` `${PAYOUT_ENDPOINT} ${idempotencyKey}` ``, character for character with `admin-payouts.ts`'s, so a second posting is refused by `ledger_transactions.idempotency_key`'s UNIQUE at the DATABASE rather than by application memory, which forgets on a restart.
3. **A LIVE LEDGER HALT REFUSES THE POSTING AND NO OVERRIDE IS TAKEN.** `postTransaction` asserts against `ledger_halts` unless a caller passes `despiteHalt`, `PostOptions` occurs in no code under `apps/worker/src`, and a refused posting rolls the release back so the request stays `held_pending_review`.
4. **MONEY IS INTEGER CENTS AND A `number` IS REFUSED RATHER THAN COERCED.** `centsOf` throws on anything but a `bigint`. There is no float in the job, in the adapter or in either suite, and the new suite asserts `typeof === 'bigint'` on all four ledger entries the release writes.

**THE THIRD LEG IS THE ONE THAT COULD HAVE GONE WRONG QUIETLY AND IT DID NOT.** `frozen --> settled` is the drawn edge; `payout_requests_settled_has_days` requires `effective_trading_day`; that needs the exchange session calendar; and [`merit/no-calendar-in-expiry-path`](../../packages/eslint-plugin-merit/rules/no-calendar-in-expiry-path.js) bans that import by glob under [ADR-042](ADR-042.md). **THE ADAPTER IS NAMED `expiry-adapter.ts` RATHER THAN `adapter.ts` SO THAT IT FALLS INSIDE THAT GLOB**, which is `apps/**/*expiry*.ts`. The file that hands the sweep a live database is exactly where reaching for the only calendar in the database is tempting, and that rule is wrong on roughly 104 days a year while looking right in review.

### 3. The adapter

[`apps/worker/src/sweeps/expiry-adapter.ts`](../../apps/worker/src/sweeps/expiry-adapter.ts). `expirySweepIo(db, events, now = () => new Date())`.

| Port | Served by | Was it available before this row |
|---|---|---|

| `ledger` | `EXPIRY_LEDGER` | the adapter existed and had **no caller** |

**THE TERMS ARE RE-EXPORTED AND NOT WRAPPED, AND THE WRAPPER IS WHAT WOULD BREAK THEM.** `packages/db` keeps a module-scoped `WeakSet` of every term `mintTerm` built and `isFilterTerm` reads IDENTITY rather than shape, precisely so a caller cannot hand-roll one: a `jsonb` column holding an object that looks like a term is a VALUE, and a shape check would read it as a range. An adapter that rebuilt, spread or froze the returned object would hand the accessor something it refuses, and the refusal would arrive at the first live scan rather than at the line that caused it. **The new suite runs `isFilterTerm` over what the port returns and over all four terms that reach the scan, and seeds the lookalike to watch the predicate refuse it.**

**THE TERM CONSTRUCTORS ARE NOT A SECOND DOOR IN [ADR-165](ADR-165.md) CLAUSE 2's SENSE, AND THE ARGUMENT IS `queueExecutor()`'s RE-RUN RATHER THAN CITED.** The clause counts doors onto TABLES. These two functions take a value and return a value; they have no `rows`, no `insert`, no `updateAt`, no key vocabulary and no scope predicate, and there is no argument position in the accessor where a term becomes a scope. **AND THE HONEST DIRECTION IS THE OTHER ONE**: a term is the thing that makes a read NARROWER, and withholding it would have pushed the next session towards `sqlExecutor`, which [ADR-331](ADR-331.md) section 4 clause 3 prices as arbitrary, unscoped and outside any transaction.

### 4. Why the fifth port is a required argument and not a refusing default

**THE TEMPTING SHAPE WAS A LIVE CONSTANT OVER AN `events` PORT THAT REJECTS**, on [`batch/adapter.ts`](../../apps/worker/src/batch/adapter.ts)'s `EVENT_SINK_BLOCKER` precedent one directory over. **IT IS REFUSED, AND THE DIFFERENCE BETWEEN THE TWO CASES IS THE WHOLE REASON.**

`BatchWritePort.raiseReconciliation` is an EXCEPTION channel: the nightly fold does its work and refuses only when it has a divergence to report, so a live `BatchPorts` with two refusing legs is a batch that runs.

**EVERY LEG OF THIS SWEEP EMITS.** `releaseHold` emits inside the release transaction, `releaseWithdrawalHalt` emits inside its own, and the freeze leg's entire output is `payout.freeze_expiring`. A sweep over a rejecting sink releases NOTHING: every `io.transact` rolls back, every outcome is `failed`, and the hold that was supposed to expire stays.

**THAT DIRECTION IS FAIL-CLOSED AND IT IS NOT THE HAZARD. THE HAZARD IS THE VALUE.** A `LIVE_EXPIRY_SWEEP_IO` exported from this file is a name a later row schedules, and the deployment that follows runs an hourly job whose every release rolls back while [`CRON_INVENTORY`](../ops/runbooks/CRON_INVENTORY.md)'s S1 dead-man switch, **which fires on the JOB'S ABSENCE rather than on its outcome**, reports a job that is present. That is [ADR-239](ADR-239.md)'s defect with a clock in front of it: a process that looks healthy to a supervisor because it exits having done nothing. **It is strictly worse for a trader than the unswept estate the switch alarms on today**, because today the alarm rings.

So the missing capability is a PARAMETER. A wiring row cannot construct the value without naming a sink, and there is nothing in this repository it could name.

**WHY THERE IS NOTHING TO NAME, MEASURED.**

1. `apps/api/src/events.ts` holds `EVENT_CATALOGUE`, `buildEvent`, `makeEventSink` and `TRANSACTION_EVENT_WRITER`, and it is the **only** event producer in this repository. `grep -rln "EventSink\|EVENT_CATALOGUE\|buildEvent" packages/ apps/ --include=*.ts` returns that file, its own suite, and `apps/worker/test/event-sink.test.ts`, which exists to measure this gap. **Nothing under `packages/**` carries one.**
2. `apps/worker` cannot reach it. `RI-04` refuses a deployable that depends on a deployable; `.npmrc`'s `node-linker=isolated` means an undeclared specifier resolves at neither run time nor build time; `test/db.test.ts` section 4 pins this deployable's bare specifiers at exactly `@merit/db`, `@merit/ledger`, `@merit/queue`, `@merit/rules-engine` and `node:crypto`; and `test/event-sink.test.ts` section 3 asserts that no RELATIVE specifier under `apps/worker/src` resolves outside this app, which is the move a wiring session under pressure reaches for.

**AND THE FENCE RUNS THE WRONG WAY ROUND THE HANDLE, WHICH IS THE FINDING RATHER THAN THE INCONVENIENCE.** `apps/api/src/events.ts` states it against itself: [ADR-191](ADR-191.md) clause 5 put `events` in `ScopedTableKey`, `ScopedTx.insert` is generic over `OwnedTableKey` because a scoped insert STAMPS the tenancy column and an `either` row has two and may carry neither, `FirmTx.insert` is generic over `FirmTableKey`, so **"`SystemTx` is the ONE handle in this workspace that can write this table"** and `apps/api` opens only `scoped` and `firm` doors. **THE ONE DEPLOYABLE HOLDING A `SystemTx` IS THIS ONE**, and `WorkerDb.batch` hands one to the callback in the adapter. **So the producer has no handle and the handle has no producer, each in the deployable the other cannot import.** The repair is a package both arrows already reach, which is `P5-n`'s slice and not this row's fence.

**AND THE SINK IS NOT THE LAST BLOCKER, WHICH IS SAID HERE SO NOBODY READS THIS ENTRY AS CLAIMING IT IS.** `test/event-sink.test.ts` section 5 measures that `payout.freeze_expiring`'s payload names neither tenancy column, so `assertTenanted` refuses it AFTER `buildEvent` has accepted the name. That is [ADR-191](ADR-191.md) section 9's registered open item; its repair is a field on the catalogue row for the producer to resolve tenancy from, and `EVENTS.md` owes it. The hold and withdrawal-halt names are both already accepted by the catalogue.
