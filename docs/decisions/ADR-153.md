## ADR-153: `API_CONTRACT` section 12 names `GET /auth/otp`, the contract defines no such endpoint, and the row means `POST` (2026-08-27, status: proposed)

**The negative-authorization matrix carries a row for `GET /auth/otp`. No such endpoint is defined anywhere in `API_CONTRACT`, none is registered by `apps/api`, and the same behaviour is described correctly with `POST` twice in the same document.** This entry rules the row a verb error and repairs it. It is the smallest possible change to a frozen document, and it is an ADR rather than a commit because [CLAUDE.md](../../CLAUDE.md) makes that the rule regardless of size.

- **Origin:** the dispatch loop, sizing the next wave after both waves landed. The measurement was a comparison of `API_CONTRACT`'s verb rows against the routes `apps/api` actually registers, and this row was the ONE apparent gap in fifty-one.
- **Not money path by content.** It edits one word of a matrix row. It touches no route, no migration and no scope rule. The [`E2`](../../MERIT_BUILD_MASTER_PROMPT.md) read is not owed on it.

---

### 1. What the row says, and what the document says twice elsewhere

[`API_CONTRACT:795`](../architecture/API_CONTRACT.md), section 12's negative-authorization matrix:

> \| `GET /auth/otp` with `channel: "sms"` driven past the per-number velocity \| `none` \| `rate_limited`. The pre-identity class is **not** exempt, and a `202` carrying `deferred` is the degraded path rather than a refusal \|

The same endpoint, same channel, correct verb, in the same document:

| Where | What it says |
|---|---|
| [`API_CONTRACT:90`](../architecture/API_CONTRACT.md) | The endpoint is defined as `### POST /auth/otp`. **There is no `GET /auth/otp` heading anywhere** |
| [`API_CONTRACT:191`](../architecture/API_CONTRACT.md) | *"Completes verification of a number challenged through `POST /auth/otp` with `channel: \"sms\"`"* -- the matrix row's exact phrase, with the other verb |
| [`API_CONTRACT:749`](../architecture/API_CONTRACT.md) | The rate-limit table, which is what the matrix row is about, rows it as `POST /auth/otp` |

**So the document contradicts itself once and agrees with itself twice, and the two agreeing sites include the endpoint's own definition.** That is not a close call.

---

### 2. Why this is a repair and not a new decision

A verb is not a design choice here. `POST /auth/otp` **sends** an OTP: it writes a challenge row and dispatches a message. Section 12's row is about that send being driven past a velocity limit, which is a property of the sending endpoint and of no other. A `GET` on the same path would have to be a different endpoint doing a different thing, and the contract defines none, describes none, and rate-limits none.

**The alternative reading was checked rather than dismissed**: that a `GET /auth/otp` exists for polling a challenge's state. It does not. `grep "GET /auth/otp"` returns this one line, `apps/api` registers no such route, and the challenge state a client needs is carried in `POST /auth/otp`'s own response.

---

### 3. The ruling

> **`API_CONTRACT` section 12's `GET /auth/otp` row is a verb error. It reads `POST /auth/otp` from this entry forward. No endpoint is added, removed, or changed by this, because the endpoint the row was always about is `POST /auth/otp`, which exists and is registered.**

---

### 4. Why it is worth an entry rather than a silent fix

**Because the corpus is the specification, and a specification that names an endpoint it does not define will be read as naming one.** The concrete cost was measured this morning: a comparison of the contract's rows against the registered routes reported **one uncovered endpoint out of fifty-one**, and that one was this typo. Left alone, every future run of that comparison reports the same phantom, and the honest response to a phantom is to build it.

`ADR-034`'s rule about derivable counts is the same instinct one level up: **a document that cannot be checked against the tree without a false positive is a document that trains people to ignore the check.**

---

### 5. What this entry does NOT do

- It does not touch `POST /auth/otp`'s definition, its rate limits, or its behaviour.
- It does not rule on whether a polling endpoint SHOULD exist. Nothing in the corpus asks for one, and inventing scope is not a repair.
- It does not touch any other row of section 12's matrix. The other rows were read and each names an endpoint the contract defines.

---

### 6. Approval

**Approval line: PENDING, UNSIGNED.** Not money path: one word of one matrix row, no route, no migration, no scope rule.

**One checkable clause, and it is a command rather than a count.**

> **The contract names no endpoint it does not define.** After this entry, every `METHOD /path` in `API_CONTRACT` section 12's matrix resolves to a route the application registers, and the comparison that found this typo reports ZERO uncovered rows.
>
> ```
> grep -c "GET /auth/otp" docs/architecture/API_CONTRACT.md
> ```
>
> **must print `0`.** Then, with the API's own composition report rather than a grep over route files -- because a grep over route files was wrong twice before this measurement was trusted -- every section 12 row must map to a registered route.
>
> **The direction it fails in is a SECOND typo of the same shape.** This clause passes on a document carrying `PUT /auth/otp` or a verb error on any other row, because it names this one string. What generalises is the comparison in section 4, not this grep, and running that comparison is how the next one is found.

**Cost if wrong:** a contract row describes a refusal for an endpoint that does not exist, so nothing implements the refusal and nothing can. The row reads as coverage.
