They were stated in that pull request's body and in no row's voice, because putting the dispatcher's words in a row's voice makes the record lie about who found what. **This row owns them now, and re-derived every figure from `git show <ref>:<path>` rather than from the dispatch or from a sibling entry.**

**The three-ref table understates the case, because the blob makes it exact.** `packages/tooling/checks/write-guard-set.mjs` is blob **`0806c240286bdfdbf09a8d8962ec247a1ac74bd5`** at `9dd770a`, at `447121c` and at `bbb9e22d`. **Those are not three similar files, they are one file.** No claim distinguishing `ADR-459`'s base from `bbb9e22d` can be true, and the comment made one.

### 3. The third falsehood, which nobody had named

The comment did not merely misdescribe `ADR-459`. **It restated two positions of its own, `:264` and `:278`, and both were already false in the commit that wrote them.**

The sentence was introduced by [`fe20954`](../../packages/tooling/checks/write-guard-set.mjs), `feat(tooling): leg E, the builder callgraph, and leg F, the shared convention literal`. That commit added legs E and F and took the file from **497 lines to 838** in the same diff. Read at `fe20954` itself: `:264` is `throws: 2,`, a data cell in the pinned matrix, and `:278` is `insertUnderStatement: {`. The literal was already at `:198` and leg C's call matcher already at `:486`.

**A correction to a stale pointer, written as a pointer, was stale before it was pushed, in the file it describes, because the same commit grew that file.** This is finding 2 demonstrated inside finding 1's artefact, and it is the fact the ruling in section 4 turns on.

### 4. The ruling on finding 1: REPAIR, and the argument

**The tension is real and the corpus already answers it.** [ADR-386](ADR-386.md) repairs a live pointer, and `write-guard-set.mjs` is live source, so the comment is repairable in principle. But the same claim also sits in [ADR-462](ADR-462.md) at [`:11`](ADR-462.md) and [`:36`](ADR-462.md), a dated record nobody may edit, so repairing only the comment splits live source from its own record. The dispatcher declined to repair for exactly that reason.

**That split is not a side effect to be weighed. It is the prescribed outcome, in one sentence, at [`ADR-386.md:169`](ADR-386.md):**

> **THE PROPERTY IS THAT NO CITED LINE MOVES. Where one must, every pointer in a LIVE file is repaired and listed, and every pointer in a DATED RECORD is NAMED, because that one cannot be repaired by a commit.**

Repair the live one, name the dated one. **The asymmetry is the mechanism working, not the mechanism breaking**, and the corpus is already living in it uncontested: `ADR-459` carries a stale pointer and `ADR-461` names it, and no row has called that a split. Declining to repair the live copy would not close the gap between live source and dated record; **it would only add a second dated-record-shaped thing that nobody is allowed to fix, in a file that is not a record.**

**Naming and leaving would also have been defensible, and it is rejected on one specific ground.** `ADR-386:169`'s leave-it clause is scoped by its own reason: *"because that one cannot be repaired by a commit."* A JSDoc block can be repaired by a commit. The clause does not reach it. And the content is not a dated observation that has aged; **it is three assertions that were false when made**, one of them false about the file it lives in. A live checker whose header misstates its own file's history is a checker a reader stops trusting, which is the failure mode this file's own header names about a check that ships red.

### 5. What the repair says, and what it deliberately does not say

**The repair restates no line number, and section 3 is why.** Every number written into this comment to correct `ADR-459`'s was itself false on arrival. Writing `:198` in its place would reproduce the defect on the next commit that grows the file above line 198, and this file grew by 341 lines in a single commit eight days into its life. **The only repair that does not carry a date on it is one that carries no number.**

Six lines were replaced by six. The file is **838 lines at base and 838 lines at head**, `CONVENTION` is at `:198` in both, and **no cited line in the file moves**, which is the constraint `ADR-386` actually imposes rather than line-count neutrality, as [`repo-invariants.mjs:3008`](../../packages/tooling/checks/repo-invariants.mjs) records. The change was located in `git diff -U6` and not by grepping for a string that occurs elsewhere in the file.

**The repair also removes this file's contribution to the false citation set**, measured in section 7: the string `write-guard-set.mjs:270` no longer appears in live source.

### 7. What the priced widening actually enumerates, measured

[ADR-461](ADR-461.md) section 10 item 3, at [`:216`](ADR-461.md), prices *"a widening of whatever derives a citation set so that a prose pointer of the form ``its own `:NNN` `` inside a sentence naming a file is enumerable."*

That widening was implemented as stated and run over one file: split each line on sentence enders, keep sentences naming `write-guard-set.mjs`, and take every `:NNN`, `line NNN` and `file:NNN` in them. **For this one file it enumerates 26 sentences and 54 site-number pairs, against the current derivation's 7**, and it enumerated 27 and 55 before this row's repair removed one site. Each of the 54 was adjudicated by reading its sentence:

| class | count | share |
| --- | --- | --- |
| **USE**, asserts a position in this file to a reader | **11** | 20.4% |
| **MENTION**, quotes or reports someone else's pointer | **28** | 51.9% |
| **CROSS-ATTRIBUTION**, the number belongs to a **different file** named in the same sentence | **13** | 24.1% |
| **NOT A POINTER**, a column number or a counterfactual | **2** | 3.7% |

**Of the 11 that are pointers at all, exactly one resolves correctly at this base**, `ADR-461:152`'s `:15`. Nine are stale: `:61`, `:101`, `:152`, `:156`, `:243`, `:259`, `:264`, `:270` and `:278` all point into the 497-line file and everything below the growth point moved. The eleventh, `ALLOCATION:459`'s `:191`, held when the dispatcher wrote it and still opens the same comment, whose words this row changed. **Signal rate of the widened derivation: 1 of 54, which is 1.9 percent.**

**The cross-attribution class is the one that condemns the price.** Merit sentences name several files at once, so a sentence-scoped rule with no adjacency requirement harvests numbers belonging to whatever else the sentence cites: `repo-invariants.mjs:3008` from [`ADR-462.md:55`](ADR-462.md), `ADR-458.md:205` from [`ADR-465.md:208`](ADR-465.md), `scoped-db.ts:2282` from [`ALLOCATION.md:452`](ALLOCATION.md), and five numbers from [`ALLOCATION.md:459`](ALLOCATION.md) which are the **line numbers of the seven sites the dispatch lists**, enumerated as lines of this file. It also takes `17` from an ESLint column in `2:17 error` and `114` from an explicit counterfactual, *"one that pinned it to line 114 would not be"*.

**The current derivation's adjacency requirement is not the hole. It is the guard that suppresses all 13 cross-attributions**, and the price removes precisely that guard.

**And the widening does not catch its own motivating case.** The two false pointers this row repaired sat at `write-guard-set.mjs:193`, a continuation line of a wrapped block comment which carries no filename. A line-scoped sentence filter cannot see it, and the implementation confirms it: zero rows for `:193`. **The instrument priced to find prose pointers cannot find the prose pointers that made this row exist.**

### 8. The ruling on ADR-461 section 10 item 3: WITHDRAW

**WITHDRAWN, on three measured grounds, not on judgement.**

1. **It does not improve precision, it destroys it.** 7 pairs at 28.6 percent pointer-density becomes 54 at 20.4 percent, and 1.9 percent correctness.
2. **It converts a citation audit into a defect report about corrections.** Twenty-eight of the 54 are mentions, and the whole of the `270` population exists because somebody wrote down that `270` was wrong. A row running the widened derivation would be handed 28 findings whose only content is that this defect was already reported.
3. **It cannot see its own motivating case**, which is the [ADR-450](ADR-450.md) precedent arriving as an instance of itself.

**No replacement price is proposed, and section 9 is why.** This row does not rule that the corpus should be blind to prose pointers; it rules that this particular widening buys blindness of a worse kind, and that the entry naming what the corpus cannot see, `ADR-461` section 7 item 1, already does the work a price here would have done.

### 9. Whether a mechanical use-versus-mention test exists: NO, and the axis is wrong

**No mechanical test separates a use from a mention over Merit prose, and the measurement says the distinction is not even the one that matters.**

The negative result first. Use and mention differ in what a sentence is *doing*, not in any token it contains. [`ADR-462.md:11`](ADR-462.md) and [`ADR-459.md:186`](ADR-459.md) are near-identical lexically, `write-guard-set.mjs:270` against *"its own `:270`"*, and differ only in that one asserts and one reports. The reporting verb and its subject can sit a clause away, a sentence away, or in a section heading, so a token-local rule cannot reach them and a grep-based derivation is token-local by construction.

**The hardest class is not mention at all, and naming it is this section's real result: the REF-QUALIFIED USE.** *"At `bbb9e22d` the literal sat at `:264`"* is an assertion, addressed to a reader, and evaluable. It is also false. But it is false **against `bbb9e22d`**, and a derivation that reads the working tree scores it against `HEAD`. No token pattern separates it from a live pointer, because the ref that qualifies it is a prepositional phrase that may appear anywhere in the sentence. **A checker that treated it as a live pointer would report it as dead for the wrong reason and would report a correct ref-qualified claim as dead too.** This class is what a history-discussing corpus generates, and it grows every time a row writes about a pointer that moved.

**What IS mechanically decidable is adjacency**, whether a number sits against its filename. That test is already implemented, it is what the current derivation does, and section 7 measures it holding back all 13 cross-attributions. **The productive line is not use against mention. It is adjacent against non-adjacent, and the corpus is already on the right side of it.**

**The durable repair for a fragile pointer is not a better grep, it is a name.** `CONVENTION` at `:198` is that repair: leg A matches with it and leg F searches for its `.source`, so no line number is load-bearing. That worked, and it is the only thing in this episode that did.

### 10. Why this row built no control

**None.** [ADR-450](ADR-450.md) refused to build a control it could not watch fire on its own motivating case, and that refusal is the precedent. Section 7 shows the priced control failing that same test by measurement, and section 9 concludes that the distinction a replacement control would need does not exist mechanically. **Building one anyway would be building a checker to have built something.** The widening was implemented and run to measure it, in the session scratchpad, and **nothing from it is committed**: it is an instrument for this entry's numbers, not a gate.

### 14. Approval

**What a founder read adds and this entry cannot.**

**THE FIRST IS THAT THIS ROW EDITED LIVE SOURCE ON ITS OWN RULING, AND THE DISPATCHER HAD DECLINED TO.** Section 4 argues the repair from [`ADR-386.md:169`](ADR-386.md) and the argument is stated so it can be overturned rather than merely followed. **A founder may reasonably prefer that both copies had been left standing**, on the ground that a live file and its record disagreeing is worse than both being wrong in the same way. This entry says that is backwards, because the corpus already lives in that asymmetry between [ADR-459](ADR-459.md) and [ADR-461](ADR-461.md), but it is a judgement and the diff is six lines in one comment.

**THE SECOND IS THAT WITHDRAWING A PRICE SUBTRACTS FROM ANOTHER ENTRY'S RECORD, AND ONLY THE GROUNDS ARE MEASURED.** Section 7's numbers are derived and re-derivable. **The move from those numbers to WITHDRAW rather than REPLACE is not**, and a founder who wants prose pointers reachable may prefer the price kept OPEN and unpaid over struck. What this entry can say is that nobody has yet described a replacement that survives section 9, and that it looked.

**THE THIRD IS THAT SECTION 9 IS A NEGATIVE RESULT AND NEGATIVE RESULTS ARE THE KIND THIS CORPUS HAS BEEN WRONG ABOUT BEFORE.** *"No mechanical test exists"* cannot be proven, only argued and left unrefuted. [ADR-462](ADR-462.md) reached a structurally identical wall at the callgraph, that *"purpose is not in the syntax"*, and [ADR-459](ADR-459.md) reached it from outside the accessor. **This is the third entry to hit the same wall from a third direction**, and three entries agreeing that something cannot be mechanised is either a settled fact or a shared blind spot. **A founder is the only reader positioned to tell which**, and a ruling rather than a fourth measurement may be what this deserves.

**THE FOURTH IS THE QUESTION IN SECTION 12 ITEM 3, WHICH THIS ROW IS FORBIDDEN TO ANSWER AND WHICH IT MADE STRICTLY HARDER.** The stacked question is whether a dated record's factual error may ever be repaired. Every instance behind it so far is a claim that **aged** into falsity. **Section 3 supplies the first that was false at the instant it was committed**, which is a different thing and may deserve a different answer. It is named and left, per dispatch.
