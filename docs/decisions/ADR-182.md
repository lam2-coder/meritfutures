### 2. THE RULING

> **1. `apps/admin` SERVES HTTP, AND IT NEVER SERVES `/api/v1` OR ANY OPERATOR PATH.** It is a network client of `api-admin`, which is `apps/api` at `MERIT_API_SURFACE=operator`, and both run on `ADMIN_ORIGIN` separated by path. [`INFRA:43`](../architecture/INFRA.md), [`INFRA:44`](../architecture/INFRA.md) and [`INFRA:53`](../architecture/INFRA.md) are the rows and this ruling transcribes them rather than overriding them. **The 27 registered operator routes are the console's DATA SOURCE and not a substitute for it.**
>
> **2. THE FRAMEWORK IS NEXT.JS APP ROUTER, ON THE CATALOG VERSIONS ALREADY ADMITTED.** `next@16.3.2`, `react@19.2.8`, `react-dom@19.2.8`, with `@types/react@19.2.18` and `@types/react-dom@19.2.5`, every one of them a `catalog:` specifier resolved from [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml)'s existing block. **[ADR-095](ADR-095.md) ruling 1's five entries gain a third IMPORTER and no sixth entry.** The catalog block takes no diff and the closure takes no package (finding 12).
>
> **3. `apps/admin/package.json` GAINS `build` AND `dev` AND ITS `start` BECOMES `next start`.** The script change is the load-bearing one. `node --experimental-strip-types src/index.ts` starts a module that prints one line and returns, so a Railway service pointed at it reports a successful start for a process that serves nothing: **a manifest that is wrong in the direction that looks like it works.** `next start` exits 1 with _"Could not find a production build"_ until a page exists, which is wrong in the honest direction. This is [ADR-095](ADR-095.md) ruling 5's argument applied to the third manifest and it is quoted rather than re-derived.
>
> **4. NO PAGE, NO LAYOUT, NO ROUTE, NO `next.config`, AND NO `tsconfig` CHANGE. THIS ENTRY ADMITS A FRAMEWORK AND RULES A BOUNDARY.** [ADR-095](ADR-095.md) ruling 6 is the precedent for the first four. The fifth **departs from the slice this entry was dispatched as** and section 6 is the reason: [ADR-095](ADR-095.md) `F7` places the `jsx` keys and the `dom` lib with the first page, both prior instances did exactly that, and the collision argument that justifies landing the React types early does not reach a file only one slice touches.
>
> **5. NO `NEXT_PUBLIC_` VARIABLE IN THIS DEPLOYABLE, EVER, AND THE API BASE URL IS A RELATIVE PATH.** [ADR-012](ADR-012.md) keeps the admin domain out of the corpus, the repository and any artifact, and a build-time inlined environment value is the single mechanism by which a framework writes a hostname into a client bundle. Section 5 states it as a refusal with a named check rather than as care.
>
> **6. `apps/admin` DECLARES NO DEPENDENCY ON ANY OTHER APP AND OPENS NO DATABASE DOOR.** `RI-04` is the mechanism for the first and it is the constraint that makes the alternative in section 4 expensive rather than merely different. For the second, `apps/admin` is in no admission list, declares no accessor, and reaches every row through `api-admin` over HTTP.

### 3. THE CENTRAL QUESTION, ANSWERED RATHER THAN ASSUMED

> **SHOULD `apps/admin` SERVE HTTP AT ALL?**

**It is a live question and it was worth asking, because the deployable that would absorb it already exists, already has a framework, already runs on the same origin, and already serves every route the console needs.** `api-admin` is `apps/api` at `MERIT_API_SURFACE=operator` on `ADMIN_ORIGIN` under `/api/v1` ([`INFRA:44`](../architecture/INFRA.md)), it registers 27 routes today (finding 3), and one fewer Railway service is a real operational saving at this size. **A plan named for a transport is not an argument, and this entry does not treat it as one.**

**THE ANSWER IS YES, AND THE REASON IS NOT THAT AN APPROVED DOCUMENT SAYS SO.** [`INFRA:43`](../architecture/INFRA.md) does say so, and an entry whose whole argument was _"the row exists"_ would be citing a row rather than defending it. The row is defended by three things that are independently true:

**(a) THE BOUNDARY IS THE PRODUCT HERE, AND IT DEGRADES SILENTLY WHEN IT MOVES.** [ADR-083:49](ADR-083.md) is the general form: _"A surface that CONTAINS the API has a privileged back door by construction, because a handler in the same package is an import away, and no lint can tell the difference between a legitimate internal call and a route bypass in a codebase where both are the same kind of function call."_ It then names this exact deployable, quoting [P1 section 2.1](../plans/P1-monorepo-scaffold.md): _"That choice is invisible for months, is a re-platform to undo, and it silently converts a security control into a URL convention."_ **The corpus anticipated this question at the first commit, in the document that laid out the workspace, and answered it there.**

**(b) THE SEPARATION IS WHAT MAKES THE `ADR-012` OBLIGATION CHEAP RATHER THAN EXPENSIVE, WHICH IS THE OPPOSITE OF THE INTUITION.** Two services on one origin means the console's API calls are **same-origin**, so its client constructs a relative path and never a hostname: no `NEXT_PUBLIC_API_ORIGIN`, no CORS configuration, and nothing for a build step to inline. `INV-M6-02`'s _"shares no CORS policy with any public surface"_ is satisfied by there being no cross-origin request to have a policy about. **A console folded into `apps/api` would satisfy `ADR-012` too, so this is not decisive on its own; it is the reason the separate shape costs nothing here.**

**(c) THE ALTERNATIVE IS NOT A SMALLER DIFF, IT IS A CROSS-PLAN MOVE PLUS AN AMENDMENT TO AN APPROVED DOCUMENT.** Section 4 is the arithmetic.

**AND THE HONEST STATEMENT OF WHAT THIS ANSWER DOES NOT SETTLE.** Nothing here says the console must be a **framework** application; that is ruling 2 and section 4's second alternative is where it is argued. **The two questions were deliberately separated, because collapsing them is how a framework gets admitted on an argument that was only ever about a deployable.**

### 5. `ADR-012`, discharged concretely rather than promised

**[ADR-012](ADR-012.md) is absolute: the admin domain is _"never written into the corpus, the repository, or any public artifact"_ and every reference is the placeholder `ADMIN_ORIGIN`. A framework ruling has to say how that survives a BUILD, because a build is the one step in this workspace that turns an environment variable into a file.**

Four clauses, and the first three are refusals rather than habits:

1. **NO `NEXT_PUBLIC_` VARIABLE IN `apps/admin`, EVER.** That prefix is the framework's own mechanism for inlining an environment value into a client bundle at build time, and a bundle carrying a resolved `ADMIN_ORIGIN` is an artifact with the domain in it. **The prefix is refused by name so that the control is a rule rather than a reviewer noticing.**
2. **THE API BASE URL IS A RELATIVE PATH.** `/api/v1/admin/...` and never an absolute origin. This is available only because [`INFRA:53`](../architecture/INFRA.md) puts `api-admin` on the same origin under `/api/v1`, which is section 3 (b): **the separate-origin shape is what makes the no-hostname rule free.**
3. **`ADMIN_ORIGIN` IS READ AT REQUEST TIME AND NEVER AT BUILD TIME.** [`resolveAdminOrigin`, `origin.ts:104`](../../apps/admin/src/origin.ts) reads [`ADMIN_ORIGIN_VAR:40`](../../apps/admin/src/origin.ts) from the environment, has **no default**, and throws when unset, saying so in its own message. **A build cannot produce a value from it**, and no module in this package may call it at the top level of a file the framework prerenders.
4. **NO `next.config` LANDS IN THIS SLICE**, and when one lands it carries no `env` block, no `assetPrefix` and no `basePath` naming a host.

**WHAT IS MECHANICAL TODAY AND WHAT IS NOT, STATED RATHER THAN BLURRED.** `RI-11` reads a routing config for the API surface and would see an `assetPrefix` only if it spelled an API path, which is not what clause 4 is about. **Nothing in this repository checks clause 1 or clause 2.** `W6-c` is the slice that creates `apps/admin/src/http/client.ts` and its own `apps/admin/test/surface.test.ts`, and section 8 item 2 assigns both assertions to it: **exactly one `fetch(` in the package, and no absolute origin constructed anywhere.** This entry states the rule and names the slice that makes it checkable; it does not claim a control it did not write.

### 6. Why the `tsconfig` does NOT move here, which reverses the slice as dispatched

**`W6-a`'s row in [WAVE-06](../plans/WAVE-06-admin-console-transport.md) put `apps/admin/tsconfig.json` in this fence and said it gains `jsx: preserve`, `jsxImportSource` and the `dom` lib. This entry does not take those keys, and the reversal is argued rather than quietly performed.**

**[ADR-095](ADR-095.md) `F7` is a SIGNED entry's foreclosure and it places them elsewhere:** _"`.tsx` arrives with the first page ... each app's `tsconfig` gains `jsx` and a `dom` lib"_, whose reversal cost cell reads _"One tsconfig each, and it belongs with the first page rather than here"_ ([ADR-095:58](ADR-095.md)). **Both prior instances did exactly that.** `apps/portal/tsconfig.json` and `apps/site/tsconfig.json` each carry the three keys today and each carries a comment saying it is `F7`'s deferral being discharged by the session that wrote the page.

**AND THE COLLISION ARGUMENT THAT JUSTIFIES THE OTHER HALF DOES NOT REACH THIS FILE.** [ADR-095](ADR-095.md) ruling 1 landed `@types/react` early on a specific ground: `pnpm-lock.yaml` is serialized across slices, and a page-writing slice that had to add a type package _"would have to join a serialization it was never scheduled into."_ **That is true of the manifest and the lockfile and it is false of `apps/admin/tsconfig.json`, which exactly one slice in this wave touches.** So the manifest and the lockfile move here, where the serialization is, and the tsconfig moves with the page, where `F7` puts it.

**THE CONSEQUENCE IS A FENCE CHANGE AND IT IS MADE IN THIS SESSION.** [WAVE-06](../plans/WAVE-06-admin-console-transport.md)'s `W6-d` row gains `apps/admin/tsconfig.json`, because the slice that writes `src/app/layout.tsx` must be able to make `.tsx` type-check. **A `W6-d` that found the file outside its fence would be blocked by this entry's tidiness**, which is a worse outcome than a key nobody reads.
