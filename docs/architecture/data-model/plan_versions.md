Indexes: unique `plan_versions_plan_version_uq (plan_id, version)`; unique `plan_versions_public_slug_uq (public_slug)`, unique across every version of every plan rather than within a plan, because the slug is the permanent public URL; `plan_versions_on_sale_idx (plan_id)` where `public_visible`, which is the site's read path.
Constraints: `plan_versions_published_has_timestamp`; `plan_versions_retired_has_timestamp`; `plan_versions_publish_decision_recorded`; `plan_versions_simulation_waiver_not_blank`; `plan_versions_visible_implies_published` (a draft is never on sale, because public visibility on an unpublished version would put an unexecutable contract on the pricing page).

Triggers: `plan_versions_published_immutable` ([`0027`](../../../packages/db/migrations/0027_triggers_invariants.sql), rebound by [`0028`](../../../packages/db/migrations/0028_supersede_plan_version_immutability.sql)); `plan_versions_publish_decision_is_sound` and `plan_versions_publish_decision_is_sound_on_publish` ([`0047`](../../../packages/db/migrations/0047_publish_decision_is_sound.sql), both running `assert_publish_decision_is_sound()`). **Two `BEFORE ROW` triggers on one table fire in NAME ORDER**, and `0047`'s sort first, which is why theirs are scoped to the publish decision: an already-published row must be refused by `0028` in `0028`'s own words.
**Rows with `status = 'published'` are immutable**, enforced by the trigger `plan_versions_published_immutable` in `0027` running `assert_published_plan_version_immutable()`, **whose body is replaced by [`0028`](../../../packages/db/migrations/0028_supersede_plan_version_immutability.sql) under [ADR-035](../../decisions/ADR-035.md)**. It rejects any update other than `published` moving to `retired` with `retired_at` set, pins every other column by comparing the whole row rather than a list of names, and **freezes a retired row absolutely** per [STATE_MACHINES section 9](../STATE_MACHINES.md)'s `retired --> [*]`. `public_visible` is permitted to move because `plan_versions_visible_implies_published` forbids a visible non-published row. Publishing a change means creating a new version. This is what makes "the rules at the time" provable (B4 #12). **That promise was true of this ROW and false of the MONEY until 2026-08-29**: `plan_version_sizes`, where every published cents value lives, carried zero triggers, and it is pinned by [`0066`](../../../packages/db/migrations/0066_published_size_grid_immutable.sql) under [ADR-213](../../decisions/ADR-213.md). A guard on the table people name is not a guard on the table the engine reads.

> **This line named the trigger `plan_versions_immutable_when_published` until 2026-08-15 and `0027` has always called it `plan_versions_published_immutable`.** A citation that does not resolve, in the paragraph describing the corpus's most valuable promise, one line above the trigger that was reading a column that did not exist. Recorded rather than smoothed: **constraint and trigger names cited in prose are not yet checked by any gate**, and CI-06j checks columns rather than object names.
Retention: forever. A retired version is still needed to explain a 2027 payout in 2031.

**A publish records what it was decided on, or says in writing why it was not.** `plan_versions_publish_decision_recorded` ([`0045`](../../../packages/db/migrations/0045_simulation_runs.sql), `SD-M21-02`) is `status <> 'published' OR num_nonnulls(decided_on_simulation_run_id, simulation_waiver_reason) = 1`: **exactly one of two, never neither.** [M21](../../plans/M21-plan-designer.md) `FM-M21-03` names what it ends, "a publish lands with no link to the simulation it was decided on ... the amnesia the module was admitted to end", and the design is to **make the recorded exception cheap and the unrecorded one impossible**. A copy-only publish takes the waiver in one sentence; what no publish can be is silent, because an absent link and a lost link are indistinguishable afterwards.

**It is scoped to `published` on purpose.** A draft with neither field is ordinary authoring and stays writable. A `retired` row is not re-checked because [`0028`](../../../packages/db/migrations/0028_supersede_plan_version_immutability.sql) makes retirement fully terminal, so a published row carries its decision into retirement unaltered.

**`0028` needed no edit, and that is a property of how it was written.** Its published-row guard does not enumerate the columns it pins; it **derives** them, as `jsonb_each(to_jsonb(NEW))` minus exactly three movable keys. Both columns above became immutable on a published row the moment they existed. And the guard fires on `OLD.status = 'published'`, while the publish transition has `OLD.status = 'draft'`, so the one `UPDATE` that writes them is untouched. Both facts are asserted in [`probe_simulation_decision_record.sql`](../../../scripts/db/probe_simulation_decision_record.sql) rather than claimed.

**What the FK does not prove, and what `0047` made it prove.** **This paragraph is amended in place rather than replaced** ([ADR-065](../../decisions/ADR-065.md) T3), because the sentence it opened with is still true of the `CHECK` and is no longer true of the table.

No CHECK can read another table, so `plan_versions_publish_decision_recorded` asserts that a run was **named** and nothing about what it **says**. Writable under it alone: a publish decided on a `failed` run, a publish decided on a run over a draft since edited so `rules_digest` no longer matches, and a publish decided on a run belonging to a different plan. **All three were executed at `0046` rather than predicted**, and the transcript is in [DELTA_MANIFEST section 25](../../../packages/db/DELTA_MANIFEST.md).

**[`0047`](../../../packages/db/migrations/0047_publish_decision_is_sound.sql) closes two of the three** ([ADR-087](../../decisions/ADR-087.md), `OI-29`). `assert_publish_decision_is_sound()` is attached twice, as `plan_versions_publish_decision_is_sound` on INSERT and `plan_versions_publish_decision_is_sound_on_publish` on the `draft -> published` UPDATE, and it fires only on a publish that NAMES a run:

- **`OI-29 check A`: the run's `status` must be `complete`.** Written `= 'complete'` rather than `<> 'failed'`, because `simulation_runs_status_known` admits four values and a `queued` run has produced no numbers at all. It buys a completion time for free, since `simulation_runs_terminal_has_completion` is a biconditional.
- **`OI-29 check B`: if the run names a plan version, it must name THIS ROW.** Stronger than the defect as written: a run over another **version** of the same plan ranged over other rules just as surely as a run over another plan.

**A trigger is a weaker control and [`0004:183`](../../../packages/db/migrations/0004_catalog.sql)'s cost stands unhedged**: it can be disabled and it fires per row. It won because the alternative does not exist. Nothing in `apps/` writes a `plan_version`, and a control that would run in a code path nobody has written is not a control.

**The third state stays open as `OI-29b` and the reason is a measurement.** `simulation_runs.rules_digest` has **no producer anywhere in the tree**, so there is nothing for a comparison to agree with; `pgcrypto` is installed and `digest(rules::text,'sha256')` runs today, but `jsonb::text` is not canonical over numbers, so a draft re-saved with `5.0` where it held `5` would be **refused while being the same rule contract**. And this table carries no `updated_at`, so no temporal proxy exists either. Check B narrows what survives to a run whose `plan_version_id` is `NULL`, which [`0045:66`](../../../packages/db/migrations/0045_simulation_runs.sql) makes nullable on purpose.

**Both directions are asserted in [`probe_publish_decision_is_sound.sql`](../../../scripts/db/probe_publish_decision_is_sound.sql) rather than claimed**, sixteen assertions with five successes leading, and the same file fails at `REJECTION 1` against a database at `0046`. Two of its cases watch the guard **not** firing: a `BEFORE ROW` trigger fires before this table's `CHECK` constraints, so `plan_versions_publish_decision_recorded` must go on refusing its own two states **by name** with `0047` installed.
