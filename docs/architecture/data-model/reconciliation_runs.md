### reconciliation_runs
**Session 374's blocker `B4`**, [`0064`](../../../packages/db/migrations/0064_reconciliation_runs.sql). One row per reconciliation sweep, per nightly batch run ([OVERVIEW section 5.2](../OVERVIEW.md)). It records that the check happened, what it covered, and what it found. **It is an operational fact and never a money movement**: no entry, no balance, no posting, no ledger account and no `_cents` column.

| Column | Type | Constraints | Why |
|---|---|---|---|
| `id` | uuid | pk, default `gen_random_uuid()` | `detector_runs`' key type, and for its reason: the producer holds the run's id before it writes anything |
| `batch_run_id` | uuid | not null, **no fk** | The nightly batch run this sweep is a stage of. [EVENTS section 5.3](../EVENTS.md)'s `run_id`, carried by `batch.started`, `batch.completed` and `batch.failed`. **No foreign key because no batch run is a row anywhere in this schema**, and inventing a table to point at would be a second run record rather than this one. It is what makes `batch.failed`'s `{ stage, account_cursor, error }` reachable without this table copying any of it ([ADR-047](../../decisions/ADR-047.md): a reference beats a copied value) |
| `trading_day` | date | not null | **Unit: trading day**, the day being reconciled, never the day the sweep ran. A redelivery reconciles an older day, which is the case the two clocks come apart on |
| `started_at` | timestamptz | not null | The run's own clock. **`not null` where [`detector_runs`](detector_runs.md)' is nullable**: the row is created BY the start of the sweep, so the instant is always known, and `0008`'s nullability is not inherited for want of a use |
| `finished_at` | timestamptz | null | Null exactly while the run is still running, made structural by `reconciliation_runs_finished_when_not_running` rather than left to the writer |
| `accounts_total` | integer | not null, check `>= 0`, **no default** | What the sweep set out to compare. `EVENTS section 5.3`'s own name, transcribed from `batch.completed`'s payload rather than invented. **No default**, on [`liability_snapshots`](liability_snapshots.md)`.funded_accounts`' reasoning: a `default 0` would let a producer that forgot the column write a run claiming a population of nobody, and `0 of 0` satisfies the completion control vacuously |
| `accounts_done` | integer | not null default 0, check `>= 0` | How many it reached. Defaults to zero because at the instant the row is written it **is** zero |
| `mismatches_found` | integer | not null default 0, check `>= 0` | **What THIS RUN saw.** Not `mismatches_open`, which is a count of the current state of [`reconciliations`](reconciliations.md) and moves when a human resolves one. A run that found three mismatches **succeeded**: finding a discrepancy is the check working, and a schema that put "found something" and "failed" in one column would make an operator unable to tell them apart |
| `status` | text | not null, check in (`running`,`completed`,`failed`) | `text` with a check on section 1's rule for a growing set, and `detector_runs.status`' precedent. **`running` exists because a process that dies mid-sweep updates nothing**, so a row left at `running` with an old `started_at` is the only way a crashed sweep is visible at all. **`degraded` is deliberately NOT taken**: `detector_runs` earns it from the synthetic battery (`SD-M7-01`), a control this table has no analogue of, and a state with no producer is a vocabulary member nobody can write |
| `created_at`, `updated_at` | timestamptz | not null default now() | Section 1: mutable tables carry `updated_at` |

Indexes: `reconciliation_runs_latest_idx (started_at desc)`, the panel's `last_run_at` in one scan ([`reserve_coverage_snapshots`](reserve_coverage_snapshots.md)`_latest_idx`'s shape); `reconciliation_runs_day_idx (trading_day desc, started_at desc)`, every sweep over one day; `reconciliation_runs_unhealthy_idx (started_at desc) where status <> 'completed' or mismatches_found > 0`, the morning read, which is `detector_runs_unhealthy_idx`'s predicate widened by one disjunct because a run that completed and **found** something is also a run somebody must open [RB-02](../../ops/runbooks/RB-02-recon-mismatch.md) for.
Constraints: `reconciliation_runs_status_is_known`; `reconciliation_runs_done_within_total`; `reconciliation_runs_mismatches_within_done`; `reconciliation_runs_finished_when_not_running`; `reconciliation_runs_finished_after_started`; and **`reconciliation_runs_completed_is_whole`**, which is the control.
Retention: forever. **Mutable, and deliberately not append-only**: it is not in the block section 1 marks, and `0026`'s closing `ALTER DEFAULT PRIVILEGES` correctly leaves `merit_app` holding `UPDATE`. Not readable by `merit_analytics`.

**`reconciliation_runs_completed_is_whole` is the control and everything else here is bookkeeping.** `status = 'completed'` requires `accounts_done = accounts_total`. [ADR-199](../../decisions/ADR-199.md) section 5 refuses a fold over per-account clocks for the nightly batch, because OVERVIEW section 5.2 leaves the run *"resumable at the account boundary"* and **a sweep that crashed at account 2,341 of 5,000 would otherwise report a success**. This is that refusal enforced by the database rather than argued in prose, and it is `detector_runs_synthetics_match_status`' shape on a different pair: the state and the counters must agree in the row.

**The record is mutable on purpose, and the cost is stated rather than discovered.** It is written when the sweep starts and updated when it stops, which is what makes *started and never finished* distinguishable from *never started*. A completion-only row cannot make that distinction, and a crashed nightly run would then read as an ordinary stale panel. **What section 1's same sentence also asks for is not here and cannot be**: mutable tables *"emit an event on every meaningful transition"*, and [EVENTS section 5.3](../EVENTS.md) carries `recon.mismatch_detected` and `recon.resolved` and **no `recon.completed`**. That half is an amendment to a frozen document and is owed.

**There is no unique index on `trading_day`, and the absence is ruled rather than forgotten.** One run per day is the normal case and it is not the only case: [RB-02](../../ops/runbooks/RB-02-recon-mismatch.md) section A sends a quarantined day to redelivery, and a redelivered file is applied and reconciled again. `detector_runs` has the same shape for the same reason.

**No column is added to [`reconciliations`](reconciliations.md), and the symmetric design is refused on the DDL rather than on taste.** `risk_flags.detector_run_id` works because a flag is raised once and never re-raised. `reconciliations_account_day_uq` makes a re-run **update** the existing row instead, so a `reconciliation_run_id` there would name the LAST run that touched the row rather than the run that found it, and a column whose meaning changes under a redelivery is worse than no column. The link runs the other way: `trading_day` plus `reconciliations_open_mismatch_idx (trading_day) where status = 'mismatch'` resolves the finding set through an index `0014` already built for it.

**Four existing tables were ruled against before this one was written, and each is refused on its own rules.** [`reconciliations`](reconciliations.md): `account_id` is `not null` and the unique key is `(account_id, trading_day)`, so every row is about one account and the batch-level fact has no row shape there at all. [`detector_runs`](detector_runs.md): a run record, and the closest shape in the schema, but its subject is a **risk detector** -- it keys on `detector` and `detector_version`, and its `synthetic_expected` / `synthetic_found` pair is `INV-M7-07`'s control, which a reconciliation sweep has no analogue of; writing a sweep there would mean inventing a detector name with no `detector_definitions` row behind it. [`ingest_files`](ingest_files.md): `applied_at` is the **ingest** stage's clock, two stages earlier in OVERVIEW section 5.2's sequence, so a file applied at 05:12 whose reconciliation then crashed would report a reconciliation that never finished -- the same defect one stage over. [`simulation_runs`](simulation_runs.md): a run of the simulation harness over a draft plan version, a different subject entirely.

**`mismatches_found` is the run's claim and the database bounds it without verifying it.** `0 <= mismatches_found <= accounts_done` is enforced -- a mismatch is found on an account that was compared, and `reconciliations_account_day_uq` allows at most one row per account per day. *This number equals the mismatch rows this run wrote* is **not** enforced and cannot be without a cross-table trigger. Session 365 wrote and executed exactly that class of guard against this schema and it was refused on a clean A/B over the probes, so `0064` proposes none and names the gap instead.
