### live_account_state
**`SD-M2-07`**, [ADR-164](../../decisions/ADR-164.md), [`0050`](../../../packages/db/migrations/0050_live_cache_and_role.sql). **[ADR-020](../../decisions/ADR-020.md)'s tier 2 live cache, given a medium for the first time.** Four approved documents state a permission over this object and none stated what it was stored in ([P6 section 3.3](../../plans/P6-live-tier.md)). **One row per account, upserted, discardable by design**, and reachable only by `merit_live`.

| Column | Type | Constraints | Why |
|---|---|---|---|
| `account_id` | uuid | pk, fk `accounts(id)` on delete restrict | The grain and the hop to an identity. The feed identifies an account by its platform ref and [`platform_account_refs`](platform_account_refs.md) resolves it; `INV-M2-10` makes that resolution safe **forever**, because the ref is permanently burned and never reused across accounts, so a lookup cannot silently route one trader's ticks onto another trader's row |
| `trading_day` | date | not null | `LiveAccountTick.sequence` is 1-based **per account per day**, so a sequence without its day is not an ordinal. It is also what distinguishes a row left over from yesterday from a quiet market today |
| `sequence` | integer | not null, `> 0` | 1-based, in delivery order. [ADR-020](../../decisions/ADR-020.md) rule 3 makes feed loss a first-class state, and [`stream.ts`](../../../packages/rithmic/src/simulator/stream.ts) states why the ordinal exists: without it *"the only way to notice a gap is a timestamp comparison, which cannot tell a lost tick from a quiet market"* |
| `opening_equity_cents` | bigint | not null | The day's **first** tick equity for this account. Integer cents, `bigint`, `INV-02`. **No non-negative check**: equity goes through zero and a constraint refusing it would drop exactly the ticks a trader most needs to see |
| `equity_cents` | bigint | not null | The latest tick's equity, same type and same reason. [`stream.ts`](../../../packages/rithmic/src/simulator/stream.ts): a tick narrowed to a float *"would be the one place in the package where a cents value could silently lose precision, on the surface a trader watches"* |
| `intraday_movement_cents` | bigint | **generated always as** `(equity_cents - opening_equity_cents)` **stored** | [API_CONTRACT section 8](../API_CONTRACT.md)'s `terms.intraday_movement_cents`, signed, in integer cents. [`0049`](../../../packages/db/migrations/0049_reserve_coverage_snapshots.sql)'s `rcr_bp` precedent: a figure the database computes **cannot disagree with the two numbers stored beside it**, and a movement written by the ingest could. **No baseline is read from an authoritative table to compute it**, which is what keeps `INV-M2-14` tight: the opening is the day's first tick and the stream already carries it |
| `feed` | text | not null | [API_CONTRACT section 6.1](../API_CONTRACT.md)'s `LiveFreshness.feed`, *"which feed the value came from"*. **No CHECK over a value list**, because `V-M2-16` is unanswered and a merged CHECK naming today's feeds could never be corrected ([E2](../../../MERIT_BUILD_MASTER_PROMPT.md)) |
| `as_of_instant` | timestamptz | not null default now() | `LiveFreshness.as_of_instant`, *"when that feed was last read"*. **Our clock, set on write, never the feed's.** [ADR-152](../../decisions/ADR-152.md) clause 1 makes staleness the server's own answer and `LiveFreshness.stale` is *"the SERVER's own answer against its own threshold"*, so the instant it is measured from has to be one a lagging or lying feed cannot move |
| `indicative` | boolean | not null default true, `CHECK (indicative)` | **The label, on the row.** Constant `true` by construction and that is the point: `LiveAccountTick` carries `indicative: true` as a **required literal** so that *"a consumer destructuring a tick cannot fail to see it"*, and a row travels to a renderer the same way. `INV-M4-11`: *"a label in a page footer is not a label on a number."* |
| `created_at` | timestamptz | not null default now() | |

Indexes: the primary key only. **No secondary index, stated rather than omitted**: the table holds one row per account, so the operator's live Open Liability sums a few thousand rows and an index would be cost with no reader.
Constraints: `live_account_state_sequence_is_positive`, `live_account_state_is_indicative`, and the `accounts` foreign key `on delete restrict`.
Retention: **discardable**. Not append-only, not backed up as a fact. Reachable by `merit_live` only; **`merit_app` holds nothing on it at all**, and `merit_analytics` and `PUBLIC` hold nothing either.

**Not append-only, and the departure is deliberate.** Every append-only table in this schema is append-only because its history **is** the product, which is [`0026`](../../../packages/db/migrations/0026_roles_and_grants.sql)'s own reason for putting the ledger first. [ADR-020](../../decisions/ADR-020.md) says the opposite of this one: *"Tier 2 is a view"*, feed loss degrades to the **last closed session** rather than to an older tick, and no document reads a tick's history. An append-only live cache would grow without bound to preserve nothing anybody reads, and would need the expiry sweep [P6 section 3.5](../../plans/P6-live-tier.md) wondered about. **It does not need one, so `P6-c` does not depend on `P5-a`'s range term** and that row of section 3.5 resolves to NO.

**The `REVOKE` is the record and it is stronger than the three that precede it.** [`0032`](../../../packages/db/migrations/0032_trading_calendar_holidays_coverage_revisions.sql), [`0039`](../../../packages/db/migrations/0039_economic_calendar.sql) and [`0049`](../../../packages/db/migrations/0049_reserve_coverage_snapshots.sql) each take `UPDATE, DELETE` back from `merit_app` because `0026`'s `ALTER DEFAULT PRIVILEGES` would otherwise make an append-only table rewritable. **`0050` takes `SELECT` as well**, because the sentence being implemented is about reading: `FM-M12-08` is *"the stats worker holds no read grant on the live cache"*, [SECURITY](../SECURITY.md)'s threat row is *"the engine has no read path to the live cache"*, and [`statistics.ts`](../../../apps/worker/src/batch/statistics.ts) runs as `merit_app`.

**What that costs is a principal, and it is named here rather than assumed away.** [INFRA section 5](../INFRA.md) says `merit_app` is held by *"API and worker at runtime"*, and [`client.ts`](../../../packages/db/src/client.ts) opens one pool from one `DATABASE_URL` read *"here and nowhere else"*. **One process is one role**, so while the API and the worker share `merit_app` no grant can separate *"the API may read the cache"* from *"the stats worker may not"*. **Any process that reads or writes this table connects as `merit_live`.** Which process that is belongs to `P6-b` (the address) and `P6-g` (the mechanism); [ADR-164](../../decisions/ADR-164.md) forecloses only the cheap escape, which is granting `merit_app` `SELECT` here.

**Three columns are deliberately absent.** `kind` is `SimWaypoint['kind']`, simulator vocabulary, and a merged CHECK over an unconfirmed vendor list can never be corrected. `at_utc` is the feed's own clock, read by nothing in the contract, and storing it beside `as_of_instant` invites staleness to be computed from the wrong one. `projected_floor_distance_cents` needs a rule threshold the engine owns, and computing it here would need the grant on `rule_states` that `INV-M2-14` forbids by name; [API_CONTRACT section 6.1](../API_CONTRACT.md)'s field is composed at the read layer instead.

**No monotonicity trigger, and the refusal is recorded so nobody re-derives it.** An out-of-order tick that rewound the row is a display defect on a labeled indicative number and never a money defect, because [ADR-020](../../decisions/ADR-020.md)'s hard rule keeps the figure off every money decision. The guard belongs in the ingest's `ON CONFLICT ... DO UPDATE ... WHERE excluded.sequence > live_account_state.sequence` predicate, which is `P6-f`'s and is **owed**.
