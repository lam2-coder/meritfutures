- **Done:** **[ADR-070](../decisions/ADR-070.md) gap 3 is folded into [M09](../plans/M09-marketing-site.md) and [M03](../plans/M03-billing-checkout.md).** Plan display name, marketed size label and internal size are specified as three independent fields, with the label **versioned with the plan version** (`OQ-F5-04`, answered). M09 gains `INV-M9-12`, `INV-M9-13`, `SD-M9-04`, section 2.1, `FM-M9-09`, `DEP-M9-07`, `OQ-M9-05`, and `GS-309` and `GS-310` written into the test plan. M03 gains `INV-M3-16`, section 3.6, and the publish-diff paragraph in section 3.3. `node scripts/corpus/gates.mjs check`: **23 of 23**. `pnpm vitest run`: **954 pass, 42 skipped, 63 files**.
- **Next:** **`SD-M9-04` is specified and has no migration.** The manifest row points it at `0044`, which is [FOLD-05](../plans/FOLD-05-plan-config-and-designer.md) P5's money-path session and is unwritten. Two amendments are owed and are out of this session's fence, listed under landmines: [`plan_version_sizes`](../architecture/data-model/plan_version_sizes.md)'s column table and [API_CONTRACT](../architecture/API_CONTRACT.md)'s `GET /plans` payload (`DEP-M9-07`).
- **Blockers:** none for the fold. `ADR-070` itself is still `proposed` and unsigned, so what landed here is the fold of a ruling the founder has not yet countersigned.
- **Landmines:**

  - **NO GATE CAN CHECK A MARKETED LABEL AGAINST `size_cents`, AND THAT IMPOSSIBILITY IS THE RULING'S ACTUAL ARGUMENT.** The reflex on reading "a label that drifts from `size_cents` is a disclosure problem" is to write a `CI-06w` or a `CV-nn` that asserts agreement. **There is nothing to assert.** A capital figure, a runway and a style name are all legitimate labels for the same size row, so deciding agreement requires knowing what the label means, and the entire point of the field is that Merit chooses what it means. **That is why the control is immutability rather than validation**: the label cannot change on a published version, so restating it is a new version, which is `validatePlan`, a diff a human reads and dual control where [ADR-010](../decisions/ADR-010.md)'s set applies. A future session that "fixes the missing gate" will be removing the reasoning, not adding a control.

  - **THE EMPTY STRING HAD TO BE MADE UNWRITABLE OR `GS-310` HAS TWO ABSENT CASES INSTEAD OF ONE.** `GS-310` says the site falls back to a stated default *rather than to an empty string*, which reads as a rendering instruction and is really a schema one: a nullable text column admits `null` **and** `''`, and a fallback written for one of them silently renders the other as a blank. `SD-M9-04` carries `check (marketed_size_label is null or btrim(marketed_size_label) <> '')`, so `null` is the only representation of absent that exists and there is exactly one case to render. **The whitespace-only string is the same defect wearing a different hat**, which is why the check is `btrim` rather than `<> ''`.

  - **THE LABEL MAY NOT BECOME THE SIZE SELECTOR'S KEY OR A URL SEGMENT, AND THIS IS THE EASIEST MISTAKE IN THE FOLD.** M09 already addresses sizes by key ([`AS-M9-02`](../plans/M09-marketing-site.md) renders `<PlanValue plan="core_eod" size="50K" .../>`), so a marketed label reads like the natural thing to put there. It is not: a label that addresses a page makes a rename move every URL, and permanent per-version URLs are what `INV-M9-11` and `AS-M9-07` are built on. **The key and the path stay derived from `size_cents`.**

  - **THE LABEL IS NOT MATERIALIZED, IN [`0004_catalog.sql`](../../packages/db/migrations/0004_catalog.sql)'S SENSE, AND NOTHING SHOULD MAKE IT SO.** Session 98 found the MATERIALIZED class the referral's taxonomy was missing: declared in `plan_versions.rules`, projected onto a constrained column at publish, with a `CV-nn` asserting the two agree. `marketed_size_label` is authored on the publish payload's per-size entry **exactly where `price_cents` is**, and lands on the same row in the same transaction (`INV-M3-12`). **There is one place it is written and one place it is read**, so there is no second copy and no agreement to assert. Adding a `CV-nn` would require first creating the duplication it would then check.

  - **THE RESET DIFF IS THE SURFACE THAT WOULD HAVE BEEN MISSED, AND IT IS THE ONE THAT COSTS MONEY.** `GS-098` refuses to take payment on a reset onto a changed version without an acknowledgement **when the rules differ**. A version whose **label** moved while `size_cents` did not changes no rule at all, so it slips past that phrasing while being a changed description of an unchanged account, which is precisely the disclosure `ADR-070` gap 3 is about. M03 section 3.6 puts it in the same acknowledgement rather than a quieter one.

  - **M03'S SECTION 2 READ "FIVE DELTAS" OVER SIX ROWS, AND HAD SINCE [ADR-019](../decisions/ADR-019.md) ADDED `SD-M3-06`.** Repaired in place with the reason stated, [ADR-034](../decisions/ADR-034.md)'s class: a hand-maintained count sitting beside the thing it counts. **`ADR-070` adds no M03 delta**; gap 3's column is M09's, written by M03's publish path.

  - **[`DELTA_MANIFEST`](../../packages/db/DELTA_MANIFEST.md) SECTION 4'S HEADER READS "M09 TO M20, 41 DELTAS" AND THE SECTION HOLDS 51 DELTA ROWS.** Counted, not recalled, before `SD-M9-04` was added. **It is out of this session's fence and is therefore recorded rather than repaired**, and it is the tenth hand-maintained count in this corpus found wrong. The total beside it is a `CI-06g` span and is correct; this header is prose and drifted like prose, which is the position the file itself already records for the numbered/unnumbered split one line above it.

  - **THE FENCE EXCEPTIONS ARE ALL MECHANICAL AND EACH ONE IS FORCED BY A GATE.** `SD-M9-04` cited in `docs/` requires a `DELTA_MANIFEST` row or [ADR-026](../decisions/ADR-026.md)'s gate fails, and that row moves `manifest_changes` from 107 to 108, which `CI-06g` then rewrites in [INDEX](../INDEX.md), [STATE](../STATE.md) and the [data-model README](../architecture/data-model/README.md). **No judgment was exercised outside the fence**: every file touched beyond M09, M03 and this log is a generated span or the row that forces one, which is session 99's precedent applied unchanged.

  - **`plans.name` IS STILL MUTABLE AND UNVERSIONED, AND `OQ-M9-05` RAISES IT WITHOUT RULING IT.** `ADR-070` rules the **size label** onto the version and is silent on the plan name, so the fold is silent too. The residual is real: renaming a plan changes what every trader who ever bought it sees their own account called, with no version to diff. It is a weaker case than the label, because a name describes a product and a label describes a number, and **a fold that closed it on its own authority would be exceeding the ruling it exists to transcribe.**
