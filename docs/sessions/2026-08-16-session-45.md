## 2026-08-16 - Session 45: the synthetic Rithmic simulator, file mode (non-money)

- **Done:** **The simulator emits files.** [`packages/rithmic/src/simulator/`](../../packages/rithmic/README.md) is [M02](../plans/M02-rithmic-bridge.md) section 1.1's second implementation of the platform adapter, in file mode: **EOD report files and their per-fill sibling**, in the vendor's publicly described CSV shape, from a seeded account population, deterministically. Ten source files, nine test files, **79 tests in this package**. Every place the real spec could differ carries the `V-M2-nn` it depends on, and [`assumptions.ts`](../../packages/rithmic/src/simulator/assumptions.ts) plus [`vendor-assumptions.test.ts`](../../packages/rithmic/test/vendor-assumptions.test.ts) make that list **closed against M02 section 11 in both directions, by parsing it**. **`pnpm run verify` green: 390 tests, 6 invariants, 15 gates clean and dirty.**
- **Next:** The **ingest half**, which is the parser this package exists to feed: `ingestEOD` and `ingestFills` over these files, the four-way disposition of section 3.4, and the whole-file transaction INV-M2-01 requires. It is the session that can first claim `GS-084` to `GS-093`. **Streaming mode (ADR-020 tier 2, `V-M2-16`) is a separate later session** and attaches at `SimDay.waypoints`.
- **Blockers:** None for this package. The two gaps below are founder items, not engineering ones, and neither blocks the parser session.
- **Landmines:**
  - **`V-M2-01` NAMES FOUR REPORT FIELDS AND A MARK NEEDS SIX.** `daily_marks` ([`0014`](../../packages/db/migrations/0014_marks.sql)) declares `high_balance_cents` and `low_balance_cents` **NOT NULL**, and the low is **the breach comparison input** (R-21, STATE_MACHINES G-BREACH). [GLOSSARY](../GLOSSARY.md) defines a mark as carrying both, so the corpus assumes the extremes arrive; `V-M2-01`'s summary of the field list names only account ref, session date, opening and closing balance, and realized P&L. **If the real report omits them they are not derivable from closed round trips** (a day that finished flat can still have gone far enough against the trader to trip the liquidator), so the row's blast moves from **edit** to **design**. Recorded in three places and written into M02's table in none: **M02 is at `status: review` under [ADR-005](../decisions/ADR-005.md), adding a row is an ADR rather than a commit, and a session that adds a row to another document's registry while building against it has claimed an identifier it does not own.** This is session 44's restraint on the R-22 disagreement applied to a registry instead of to a rule.
  - **INBOUND FILE NAMING IS RELIED ON AND NO `V-M2-nn` ASSERTS IT.** Section 3.3's `merit_<operation>_<yyyymmdd>_...` is the **outbound** provisioning name, which Merit chooses. Section 3.4's disposition table branches on whether a **vendor** filename has been **seen before**, which is only a signal if the vendor has a convention. `V-M2-03` and `V-M2-04` are the rows that move if it is wrong and both are cited at the naming code. Same reason for not claiming a row.
  - **DRAWS ARE KEYED, NOT STREAMED, AND THIS IS THE ONE DESIGN DECISION THE REST FOLLOWS FROM.** A stream advanced across the run is deterministic only in the weak sense that one program run reproduces itself: add a ninth account to an eight-account population and every draw after it moves, so **every fixture derived against the run moves for a reason that has nothing to do with its scenario**. Keying on `(seed, account, day, purpose)` makes account `i` a pure function of `(seed, i)`. `determinism.test.ts` asserts it at the model level **and again at the file level**, because the two can diverge: an emitter that sorted its rows by a value rather than by population order would pass the first and fail the second.
  - **THE COMMITTED CANONICAL BYTES ARE NOT A `GS-nnn` GOLDEN FILE AND MUST NEVER BE TREATED AS ONE.** TR-01 is that a golden file's expected value is computed **by hand from the prose** by somebody who did not write the code; these are generated by the emitter and prove only that it has not changed. They live in this package rather than in `packages/rules-engine/fixtures`, and the file is `.test.ts` rather than `.golden.test.ts` **so it lands in CI-02's `unit` project and never in CI-03**, whose whole subject is the engine's fixtures. Regeneration (`MERIT_UPDATE_CANONICAL=1`) **fails the run on purpose**, so it can never be mistaken for a pass.
  - **THE POPULATION IS EIGHT ACCOUNTS BECAUSE SIX DREW NO UNPROTECTED ONE.** At a one-in-five unprotected share a population of six draws zero, so the `V-M2-08` case the fixture is partly for would have been **absent** and the test asserting it would have been asserting nothing. The count is a consequence, not a preference, and `canonical.ts` says so where the number is written.
  - **THE SIMULATOR IS TOLD THE SETPOINT AND NEVER DERIVES IT.** M02 section 1.2: "M2 **pushes** a floor value to the vendor as a risk setting. It is told the number; it never derives it." The auto-liquidation modelled here is the **vendor's** behaviour against a number it was handed, which is the one item on [SIMULATION_HARNESS section 4](../testing/SIMULATION_HARNESS.md)'s forbidden list (gate, breach, eligibility, payout amount) that Merit delegates rather than decides. It fires at `<=` rather than `<` because G-BREACH says a clean liquidation lands exactly on the floor and **survives**.
  - **NO PLAN PARAMETER IS A CONSTANT ANYWHERE IN THE PACKAGE.** Account sizes, the setpoint offset, the symbols and their tick values are all caller-supplied. STATE's standing parameter ruling makes plan parameters launch candidates that live as rows in `plan_version_sizes`; a simulator carrying `50_000_00` has made one a constant in the one place nobody looks for plan configuration. The canonical fixture's $10,000 and $25,000 are picked to be **obviously not the lineup** for the same reason.
  - **SESSION BOUNDARIES ARE CALLER-SUPPLIED AND THE FIXTURE'S WINDOW IS NOT A CME SESSION.** There is not one calendar row in this repository ([P2](../plans/P2-rules-engine.md) section 6) and the publication has not been transcribed, so a hardcoded 17:00 CT boundary would be transcription from recollection. `canonical.ts` uses a plain 13:30Z-to-20:00Z block chosen so it **cannot** be mistaken for a real one, which is [ADR-049](../decisions/ADR-049.md)'s calendar-as-data argument one package over.
  - **`time.ts` EXISTS BECAUSE `new Date` FAILS SILENTLY IN TWO DIRECTIONS.** It accepts `2026-02-30` and lands on March 2nd, and it returns Invalid Date rather than throwing on a shape it cannot read, after which every arithmetic is `NaN` and formats as the string "NaN" into a CSV column a parser reads as a value. That failure would be **deterministic and byte-identical**, which is the one class this package's central claim cannot detect. Parsing is a strict regex plus a round-trip check; the civil-date conversions are Hinnant's and are asserted as exact inverses over every day from 1970 to 2100.
  - **`no-clock.test.ts` IS A TEST AND NOT A LINT RULE, ON PURPOSE.** `merit/engine-purity` is a lint rule because the engine's purity is a money-path invariant enforced at CI-01 and asserted in the manifest by `RI-01` as well. This package is non-money and its constraint is narrower, so a test in the package that owns it is proportionate. **If a second package needs the same rule, that is the moment it becomes a lint rule with a glob**, which is the shape `no-calendar-in-expiry-path` already shows.
  - **THE SCAN IS LINE-BASED AND COMMENT-AWARE, AND BOTH DIRECTIONS ARE WATCHED.** This package's own headers argue about `new Date` and `Math.random` at length, so a scanner that could not tell prose from code would fire on the explanation and be disabled within a week. It is watched **firing** on a seeded `Date.now()` and watched **not firing** on the prose, and it says in its header what it therefore cannot see.
  - **`createHash('sha256')` IS DELIBERATELY NOT ON THE FORBIDDEN LIST, AND A TEST SAYS SO.** It is a pure function of its input and it is what `ingest_files.sha256`'s unique index compares (INV-M2-02). A later session tightening the ban by reflex would break the digest the redelivery rules rest on, so the permission is asserted rather than assumed.
  - **THE TWO EMITTED FILES CANNOT DISAGREE, AND THAT IS BY CONSTRUCTION RATHER THAN BY CARE.** Both are rendered from one day model, and `session.ts` throws if the sum of a day's round trips does not equal the balance movement. It is FM-M2-06's two-independent-statements idiom one layer earlier: a simulator whose summary disagrees with its own fills makes the reconciliation suite pass for the wrong reason.

### What the vendor-call diff now is, mechanically

`assumptions.ts` classifies **every** row of M02 section 11 as in scope for file mode or out of scope, with what was assumed and what moves for each. `vendor-assumptions.test.ts` **parses section 11 from M02** and closes three ways:

1. in-scope plus out-of-scope is **exactly** section 11's row set,
2. every in-scope row is **cited** by a `V-M2-nn` comment somewhere in `src/`,
3. every `V-M2-nn` in `src/` names a row that **exists**.

**No count is written down anywhere**, which is [ADR-034](../decisions/ADR-034.md)'s rule applied to this package, and the check **throws rather than passing** if it parses fewer than ten rows, which is `repo-invariants.mjs`'s second standing rule: a check that cannot reach its inputs has not passed, it has failed to run.

**What it does not prove is stated in its own header.** It cannot tell whether the comment citing `V-M2-05` sits on the line that actually depends on `V-M2-05`. That is a reading, and the conformance suite M02 section 8.2 specifies (one case per row, each with the fixture that encodes it) is what turns it into an assertion. This keeps the **list** honest; the suite is what keeps the **claims** honest.

**Five rows are out of scope and the file says so rather than leaving an absence**, which is section 8.2's own idiom: `V-M2-06` and `V-M2-07` are outbound provisioning, `V-M2-14` is server-side copy, `V-M2-15` is a commercial precondition on the provisioning saga, and `V-M2-16` is the streaming tier.

### What was NOT done, named rather than implied

**No `GS-nnn` is claimed.** GS-084 to GS-093 are M02's owned scenarios and each needs a parser to assert against. This package can now **emit** the files several of them need: GS-084's identical-path file, GS-085's hostile-but-legal shapes (BOM, CRLF, reordered columns, an extra trailing column, a zero-account day), GS-086's redelivery under a seen name with a new digest, and GS-087's account with no readable setpoint. **Emitting the input is not asserting the outcome**, and claiming the scenario before the assertion exists is how a registry row stops meaning anything.

**No `EC-nnn` is claimed** for either gap above, on session 44's stated reason: an edge case arrives with a number from the allocation table and a regenerated count, and both belong to the session that rules it rather than to the one that found it.

**`PlatformAdapter` is still unimplemented.** `ingestEOD` and `ingestFills` **consume** files and the simulator **produces** them. INV-M2-11 is that simulator output and vendor output traverse the same parser, which is only true if the simulator stops at the file and the adapter starts there. A simulator that satisfied the interface would be a mock at the parser boundary, which is the one thing STRATEGY section 2 rejected by name.

**No corrections.** `corrects_fill_id` is a column file mode always leaves empty. The correction stream is AS-M2-07 and a later session's, and `V-M2-12` is cited at the column.

**The 200MB file of AS-M2-01 counter 4 is not a quirk and was not built as one.** It is a population size, and `renderRun` will produce one from a large enough spec. Saying so is cheaper than a later reader looking for a `hugeFile: true` and concluding the counter was skipped.
