### 4. Where the rule lives, and what `packages/ledger` deliberately does not gain

**And `reversalPosting` is not the only door.** [`posting.ts:136`](../../packages/ledger/src/posting.ts)'s `PostingHeader` carries `reversalOf?: string`, [`post.ts:176`](../../packages/ledger/src/post.ts) carries it to the INSERT, and [`posting.test.ts:130`](../../packages/ledger/test/posting.test.ts) builds a posting that way in the suite today. A rule in `reversalPosting` is bypassed by the public constructor one file over without a cast and without a lint.

### 7. One error this session made and caught

**The first draft of the probe function declared a local `found boolean`.** PL/pgSQL's `FOUND` is a special variable, declaring one shadows it, `IF NOT FOUND` then read an uninitialised local that evaluates to NULL, and **the branch silently never fired while the foreign key quietly covered for it.** Two concurrency measurements were read wrong before it was caught, and it was caught by instrumenting the function with `RAISE WARNING` rather than by reading it again.

**It is recorded because it is `LEDGER-C1`'s own class of defect**: a guard that reconciles perfectly and is wrong. The shipped function declares one variable, `target_link uuid`, and section 5 rows 4 and 5 are the re-measurement against the shipped text.
