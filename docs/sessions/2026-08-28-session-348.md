### 2. Guard one, and the two measurements that chose the pattern

`apps/admin/src/page.ts` carried, at `9dca218d` line 210:

```
const UUID = /\b[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\b/i;
```

**A `\b` is a WORD boundary**, so a word character on either side of the token removes it and the match is lost. An underscore is a word character, which is why the shape a real payload carries is the one that passed.

**THE HOLE WAS REPRODUCED FIRST.** `M6-A-55` was written against the committed regex and run before anything moved: **4 of 7 cases failed**, naming the neighbour sweep, the superset property, the hex-run family and the three shapes session 344 measured as passing. All 7 pass after.

| Line, writing `ID` for a uuid | at `9dca218d` | now        |
| ----------------------------- | ------------- | ---------- |
| `see ID`                      | throws        | **throws** |
| `manual-review-ID`            | throws        | **throws** |
| `ref:ID`                      | throws        | **throws** |
| `linked_to_ID`                | **passes**    | **throws** |
| `xID`                         | **passes**    | **throws** |
| `IDy`                         | **passes**    | **throws** |

**BOTH BOUNDARIES ARE DROPPED RATHER THAN REPLACED WITH A LOOKAROUND, AND THE REASON IS A PROPERTY.** Removing an assertion from a regex can only ADD matches, so the new pattern refuses a **strict superset** of the old one: no line that used to throw now passes. `M6-A-55` asserts that over a generated corpus rather than trusting the argument, and it holds the only remaining copy of the old regex in the tree so the comparison is derived rather than transcribed.

**The lookbehind was the obvious alternative and it is refused on a measurement.** `(?<![0-9a-f])` succeeds after an underscore and after `x`, so it closes most of the finding; it fails after `d`, because `d` is a hex digit, so `id<uuid>` would still pass. `id` is exactly the prefix an operator screen glues onto an identifier.

**WHAT THE NEW PATTERN REJECTS THAT THE OLD ONE ACCEPTED, stated as families rather than as three examples:**

1. **Every one of the 94 printable ASCII neighbour characters, on either side.** Derived over the range in the suite rather than over a hand-picked list, because the defect was a CLASS of neighbour and a hand-picked list is how it survived the first time.
2. **A uuid shape inside a longer hex-and-dash run.** `0123456789abcdef-1f2d-4c5e-8a7b-9d0e1f2a3b4c` has a 16-hex first group containing an 8-hex one at an offset; `0e9c0b3a-1f2d-4c5e-8a7b-9d0e1f2a3b4cc` has a 13-hex last group. Both were invisible to `\b` and both throw now.

**WHAT IT ACCEPTS THAT THE OLD ONE REJECTED: nothing.** That is the superset property, and it is the reason this shape was chosen over the lookaround.

**THE WIDENING IS IN THE NEIGHBOURS AND NEVER IN THE SHAPE.** Four near misses are pinned as still passing: eleven hex in the last group, a dash missing, a `g` where a hex digit must be, and the groups mis-sized. A control that had become "any long hex string throws" would be a control the next screen writer turns off.

**Which direction is safe here is not symmetric, and the file says so.** The false negative is bulk PII on an aggregate screen, which is `FM-M6-10`. The false positive is a page that refuses to render and says why. `INV-M6-10` is the rule and the page names no subject.
