## 2026-08-23 - Session 145: `ScopedDb` gets a real client, and the scope is a declared registry

- **Objective:** `P3-b`. [`packages/db/src/index.ts`](../../packages/db/src/index.ts) declares `ScopedDb` with one field and says in its own header that neither the client nor the accessor exists. [ADR-008](../decisions/ADR-008.md) is `accepted` and made the `scopedDb(identity)` wrapper *"part of the acceptance, not a follow-up"*; the VG-4 ESLint ban is wired and the wrapper is not, open since 2026-08-13. Write `ADR-084`, build the client and the accessor over a declared scope registry, and supersede the one consequence sentence of ADR-008 this session makes false.

- **Done:** **[ADR-084](../decisions/ADR-084.md), `status: proposed`, approval line UNSIGNED.** `scopedDb(identity)` and `systemDb(reason)` exist, and [ADR-008](../decisions/ADR-008.md)'s *"part of the acceptance, not a follow-up"* clause is discharged after ten days. Five new files in [`packages/db/src`](../../packages/db/src), a rewritten [`index.ts`](../../packages/db/src/index.ts) and a rewritten [`scoped-db.test.ts`](../../packages/db/test/scoped-db.test.ts). **Seven tables of 111 are reachable, reported as seven of 111**: `SCOPE_RULES` is declared against a mapped type over `TableKey`, so the other 104 are a compile error at the call site rather than an unscoped read. The workspace has its **first runtime dependencies**.

- **The count:** **28 of 28 gates**, 7 of 7 invariants, `falsify.mjs` clean-and-dirty over 56 scope cases and 10 loader cases, **`pnpm run verify` green end to end**. **104 test files, 1,512 passed, 1 skipped**, against a baseline measured in this session at **1,487**: the delta is exactly +25, this file's 1 assertion becoming 26. `falsify:ci`, which is **not** part of `verify`, reports **66 of 69** watched failing; the three exceptions are `CI-05` cases whose scanners are absent from this container and are `ERROR` on the baseline too. `gate_count` does not move; `adr_count` moves 83 to 84 under `gates.mjs generate`.

- **Next:** **session 146 (`P3-c`) is unblocked.** `147` and `148` are money path and `148` carries migration `0047`. Three of this session's four fence widenings are inherited by `146`, `147` and `148` unchanged.

- **Blockers:** **nothing is signed.** ADR-084 supersedes a consequence sentence inside a signed `accepted` ADR and puts `pg` and `drizzle-orm` in the tree, neither of which is a session's call.

- **Landmines:**

  - **THE SUITE ASSERTED THE CODE AGAINST ITSELF AND A SEEDED VIOLATION SURVIVED.** Scoping `accounts` by **`user_id`** instead of `identity_id` passed **all 22** assertions, because the predicate test took its expected column FROM THE RULE. A user is a login and an identity is the person ([ADR-041](../decisions/ADR-041.md)), so that seed returns a different row set, silently, for every trader with more than one login: **the exact failure ADR-008 scoped the wrapper to bound.** The repair is that four checks now take their expectation from the **migrations** -- an `owned` column must be declared `REFERENCES identities(id)` -- and the general lesson is that a test whose expectation is derived from the thing under test cannot fail. **Watching a suite reject a seed is not optional and this is what it is for.**

  - **THE FALSIFY HARNESS MUTATES THE WORKING TREE, AND IT WAS RUN IN THE BACKGROUND WHILE FILES WERE BEING EDITED AND COMMITTED.** All five of this session's first commits swept in a seeded rules-engine mutation -- `advance.ts`, `progression.ts`, `clamp.ts`, `settle.ts` and `validate.ts` -- because each `git add -A` caught the harness mid-cycle. One of them committed `if (first.from_ordinal < 1)` where the source reads `!== 1`, **weakening a ladder validation on the money path**. The harness printed *"THE HARNESS CHANGED THE TREE"* and it was read only afterwards. The branch history was rebuilt from `origin/main` with explicit paths and force-pushed, so no commit on it touches `packages/rules-engine`. **Never background `falsify:ci`, and never `git add -A` on a branch a mutating harness has run against.**

  - **`CI-06r` READS A QUOTED SIGNATURE AS YOUR OWN.** Quoting ADR-008's approval line verbatim put the needle `founder approval` and the token `ACCEPTED` on one line of a `status: proposed` entry, and the gate correctly refused it. The gate's own comment says a line carrying the needle and no token is claimed as nothing, so **cite another entry's signature by line reference rather than by quoting it**.

  - **`pg`'S SUPPLY-CHAIN COST IS ITS CLOSURE, NOT ITS DIRECT COUNT.** The dispatching plan said 6, which is `pg`'s direct dependency count; the lockfile says **14 packages, 13 transitive**. postgres.js is 1 and is genuinely the better VG-12 answer read alone. It is refused because [ADR-006](../decisions/ADR-006.md) requires enqueue to share the state change's transaction, a transaction is per-connection, and `pg-boss` declares `pg` as a hard dependency: a second driver is a second pool.

  - **AN ABSENCE NEEDS THE WIDE GREP, AND THE NARROW ONE WAS WRONG.** The plan claimed no `ADD COLUMN` on the seven. Two of the seven **are** named by a later `ALTER TABLE` -- `ledger_transactions` at `0009:105` and `accounts` at `0010:304` -- both `ADD CONSTRAINT`, neither changing a column. The assertion now re-derives `ADD`/`DROP`/`ALTER COLUMN` and `RENAME` on every run rather than trusting a measurement written down once.

  - **A NULLABLE SCOPE COLUMN IS NOT A WEAKER CLASS.** `ledger_accounts.identity_id` is NULL on firm rows, and `= $1` excludes them **without a second predicate** because SQL NULL never equals anything. An added `IS NOT NULL` would look careful and assert nothing.

  - **`ledger_transactions` HAS NO IDENTITY COLUMN AND A JOIN WOULD MULTIPLY ROWS.** Double-entry gives it a trader leg and a firm leg, so a join through `ledger_entries` returns it once per matching entry. The rule is an `EXISTS`, and `traversal` is **checked** rather than trusted: every `hop` must name the via table's primary key and every `semi-join` must not.
