### 2. Link 1, measured rather than asserted

Both deployables start the same way and differ by one statement.

```
$ pnpm --filter @merit/worker start
> @merit/worker@0.0.0 start /home/user/meritfutures/apps/worker
> node --experimental-strip-types src/index.ts

EXIT=0
```

`apps/worker/package.json` declares `"start": "node --experimental-strip-types
src/index.ts"`. [`apps/worker/src/index.ts:1268`](../../apps/worker/src/index.ts)
is `export function main(): void {`, whose body is a `console.log` describing
everything the module does not do, and **the only occurrence of `main(` anywhere
under `apps/worker/src` is that declaration**.
[`apps/api/src/start.ts:149`](../../apps/api/src/start.ts) is `await main();`.

**A PROCESS THAT EXITS 0 HAVING DONE NOTHING IS WORSE THAN ONE THAT CRASHES**,
and it is the failure [CRON_INVENTORY](../ops/runbooks/CRON_INVENTORY.md)'s own
opening names one layer up: *"A scheduled job that stops being scheduled is
invisible."* A supervisor reads this as success.

**Census over all 281 `.ts` files under every `apps/*/src` and
`packages/*/src`:** three name `runNightlyBatch`, and they are the module that
declares it, the barrel that exports it, and
[`routes/account-reads.ts`](../../apps/api/src/routes/account-reads.ts), which
names it **inside a string literal**. A fourth would be a scheduler or an
adapter.

### 3. What was ruled

**RULING 1. The API READS a `RuleState` the WORKER WROTE, and the two deployables
meet at `rule_states`.** Four reasons, of which the first would be enough:

- **`INV-M5-02` is a claim about the number of EVALUATORS, not of call sites.**
  [M05:81](../plans/M05-payout-system.md) states its own control in five words:
  *"A second evaluator would be a second rule."* An API that folded its own state
  would satisfy the letter of that row while producing the input from a path the
  worker's audit has never seen.
- **[ADR-026](../decisions/ADR-026.md) `C-07`'s `state_hash` is the detector for
  exactly this defect and a request-path fold is invisible to it**, because a
  state computed in a request is never stored and never hashed. Both answers
  would look authoritative and only one would be in the ledger.
- **`R-06` makes the intraday answer a different question rather than a fresher
  one.** [M01:470](../plans/M01-rules-engine.md), and
  [M01:785](../plans/M01-rules-engine.md) already worked out the consequence for
  the forecast endpoint: a `RuleState` for a day that has not closed comes only
  from `advanceDay`, whose mark `R-06` guarantees does not exist.
- **The layering says so and the manifests enforce it.** The fold's inputs are
  six per-account fields plus a calendar slice and a watermark. Doing that per
  request is the nightly job with no batch and no advisory lock, and `FM-10`
  names the race the lock exists for.

**RULING 2. The port is NARROWED and not wired**, and a **partial** backend is
refused: `listPayouts` and `idempotency` are constructible today, and installing
them beside a `transact` whose `subject` rejects would put a live-looking route
in front of the arm that approves payouts.

**RULING 3. Nothing in a request path may compute a rule state to get a port
wired**, stated as a standing rule rather than as this session's preference,
because the temptation recurs at every blocked port with a fold in scope.

### 5. The next slice, sized

**SLICE A, the codec, in `packages/rules-engine`.** Both consumers declare that
package and the engine declares no workspace dependency at all (`RI-01`), so the
arrow cannot point back; an encoder in `apps/worker` and a decoder in `apps/api`
is `FM-16`, and `readLiability` cannot import `apps/worker` anyway. One module,
one suite, no migration, no dependency. **It also clears `B5` term 2's
implementation.** It inherits an `E2` debt: ADR-206 is `proposed` and UNSIGNED.

**SLICE B, `BatchPorts` over Postgres.** Ten methods on `apps/worker`'s one door
at `systemDb('nightly-batch')`. `writeRuleState` is already built and needs only
a `RuleStateWriterIo`. The costs the type does not show: `loadAccountDay`
assembles six fields beyond the account id; `FM-10`'s per-account advisory lock
is owed by the adapter and by nothing else; and `raiseReconciliation` and
`raiseDivergence` need an event sink **this deployable cannot reach**, the only
composed writer in the tree being `TRANSACTION_EVENT_WRITER` in
[`apps/api/src/events.ts`](../../apps/api/src/events.ts) against a worker
manifest declaring two packages under `node-linker=isolated`.

**SLICE C, the scheduler, and this is where the migration is.** pg-boss's schema
is in no migration in the tree, `@merit/queue` is in no worker manifest, `main()`
must be called, and `batch.completed` must be emitted or the dead-man switch has
nothing to watch.
