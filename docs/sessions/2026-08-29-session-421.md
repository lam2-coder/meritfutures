**Objective.** Make `GET /verify/:code` serve a real certificate row, which meant
ruling the scope-system question underneath it.

**Outcome.** **It serves.** The ruling is a fifth door, and the more valuable
half of the session is a finding about the code that door is addressed by.

### 2. What was ruled

**A fifth door, `db.publicLookup`**, with a two-part vocabulary
`PUBLIC_LOOKUP_ADDRESS = { certificates: ['code'] }`
([`scoped-db.ts:1697`](../../packages/db/src/scoped-db.ts)). Read only,
non-transactional, one row of one table at one column, disjoint brand, and no
`transaction` overload, so a caller who has proved nothing reaches no write at
any authority.

**The scope registry is untouched.** The class answers who owns a row and it
answers it correctly; the new vocabulary answers what an unauthenticated caller
may address one BY. That is also why `scope.ts` stayed closed: it is session
**420**'s file this week, and the two doors were ruled separately.

### 3. What was refused

- **The third candidate**, resolving the identity from the code and opening
  `db.scoped`. It needs this same read first, so it is not less machinery, and
  the authority it then holds is that trader's whole book.
- **A per-table opt-in on the registry.** `certificates` declares two unique
  keys and only `code` may be public.
- **A shape check on `:code`**, re-examined rather than assumed, and still
  refused: it defends nothing and would read as an answer to section 4.
- **A keyed `code_hash`**, named as the remedy if section 4 resolves the wrong
  way rather than taken today.
- **A migration.** Section 4.3.
- **Any upper bound on the constant-time floor**, which ADR-170 leaves to a
  measurement the deployment owes.

### 4. The finding

#### 4.1 What the corpus commits to

`INV-M11-05`: *"128 bits of entropy, no sequence"*
([M11:54](../plans/M11-certificates-social-proof.md)). M11 section 9: *"The code
space is not walkable, which makes the attack infeasible rather than merely rate
limited"*. [`API_CONTRACT:1473`](../architecture/API_CONTRACT.md): the
catalogue's limit *"is an enumeration budget on a 128-bit token and is
deliberately not inherited here"*.

#### 4.2 What this tree enforces, over `apps`, `packages`, `e2e` and `scripts`

| Leg | State |
|---|---|
| **Entropy** | **Nowhere.** `text NOT NULL`, one unique index, no `CHECK` naming `code` |
| **A minter** | **Does not exist.** Nothing inserts a `certificates` row |
| **The rate limit** | **Does not exist.** No limiter in the tree; `apps/api` depends on `fastify` alone |
| **The anomaly log** | **Live as of this session**, and it is the first of the three to be real |

Two live files describe the first leg as a property this system has
([`certificates.ts:154`](../../apps/api/src/routes/certificates.ts) and
[`verify.ts`](../../apps/api/src/routes/verify.ts)'s header). Neither is false
about the specification and both read as facts about the deployment.

#### 4.3 Why the fix is not here

Row `231`'s fence is `packages/db/src/**` and `packages/db/test/**`, and unlike
rows `230` and `232` it names no migration directory and reserves no number. A
`CHECK` is a migration. **The dispatch asked for the fix in this pull request
and the fence does not carry it; the fence won**, because widening a fence to
finish and weakening a gate to pass it are the same move. The gap is pinned as a
test that goes red the day somebody closes it.
