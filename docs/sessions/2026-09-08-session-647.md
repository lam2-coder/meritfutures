### 5. Landmines

- **THE GUARD CHECKS `values` AND NEVER AN ADDRESS, and widening it to identity columns makes that sharper rather than softer.** Identity columns are exactly what addresses are built from. [`recon/sweep.ts:629`](../../apps/worker/src/recon/sweep.ts) addresses `reconciliations` by its identity `id`. A future row that moves the guard off `values` and onto the statement breaks every addressed write in the estate; leg D's address assertion is what says so.
- **`generatedIdentity !== undefined` IS NOT THE RIGHT TEST and reads as though it were.** `type` is `'always' | 'byDefault'` and only `always` is refused by PostgreSQL. All 20 columns are `always` today, so the wrong clause passes every test in this tree. Nothing watches the distinction; [ADR-452](../decisions/ADR-452.md) section 11 item 7 records that.
- **`includes('id')` IS NOT A DISCRIMINATOR.** Every identity column on this registry is called `id`, and `id` is a substring of "identity" and "invalid". Leg D's identity half requires the QUALIFIED `key.column` for that reason; a later simplification to the bare name would make the leg green for the wrong reason.
- **The corpus's `42601` is wrong and the suite agrees with it**, because [`generated-column-writes.test.ts:380`](../../packages/tooling/test/generated-column-writes.test.ts) asserts the string the guard writes rather than anything a database said. **The six cases that WOULD touch a database are skipped**, so the suite is green on a claim a database refutes.
- **`scoped-db.ts` is widely cited and the ruled property is that no cited line MOVES**, which is not line-count neutrality. The file grew by 17 lines and every one of them is below `4690`, the highest real cited line.
