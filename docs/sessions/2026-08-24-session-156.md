### They disagree, and the disagreement is the whole design question

**Disagreement one, and it is the load-bearing one: the fourth predicate.**

| Source | Predicates named |
|---|---|
| VIBE_FAILURE_POSTMORTEMS:55, `VG-8`'s source | `rm -rf`, prod connection strings, force-push. **Three** |
| STRATEGY:214, `VG-8`'s row | *"blocking dangerous shell"*. **A phrase, enumerating nothing** |
| INFRA:107, `VG-8`'s row | *"PreToolUse hook"*. **A name, enumerating nothing** |
| INFRA:191 and constitution C10 | Those three, **plus writes into `payout/` or `ledger/` without the confirm flag. Four** |

So **"`VG-8`'s `PreToolUse` half" is a proper subset of "C10's `PreToolUse` hook"**, and the two names have been used interchangeably in every record of this finding. A session that read the dispatch and went to INFRA section 10 would have built the payout guard and called `VG-8` done; a session that read only STRATEGY would have had a phrase and no predicate at all.

**The fourth clause is not built, and the reason is not that it is hard.** *"The confirm flag"* is named at INFRA:191 and at constitution C10 and **defined nowhere**: a grep over the whole repository returns exactly those two lines and no definition, no environment variable, no CLI flag, no ADR. Building it would mean choosing what the flag is, which is inventing specification inside an implementation session. Neither `VG-8` row carries the clause, so nothing in `VG-8`'s row is left undone by omitting it.

> **A correction, because the first draft of that argument was wrong.** The hook's header comment and its first commit message both said the clause was moot because *"no `payout/` or `ledger/` path exists in this tree yet"*. **`packages/rules-engine/src/payout/` has existed since 2026-08-21** and holds `clamp.ts`, `evaluate.ts`, `gates.ts` and `settle.ts`. Corrected in `d0f4356` by listing the directory instead of recalling it. The correction **cuts against convenience**: the payout path is live, so defining that flag is real next work rather than housekeeping, and no predicate moved.

### The predicate, and the tradeoff it takes

*"Blocking dangerous shell"* is a phrase. A `PreToolUse` matcher is a decision about every command anybody runs. **A hook that matches nothing to avoid false positives is decoration; a hook that blocks ordinary work is disabled inside a day and then `VG-8` is a finding again with a settings file that claims otherwise.** Both failures end in the same place, so the rule that avoids both is the one worth finding.

**Every predicate here is over BLAST RADIUS rather than over a command name.** That is the tradeoff, stated once:

| Rule | Refuses | Permits | Why the line is there |
|---|---|---|---|
| **DS-1** `rm -rf` | a target not statically provable to sit inside the worktree or a temp directory, plus `.git` | `rm -rf node_modules`, `dist`, `coverage`, `dist/*`, the scratchpad | `rm -rf node_modules` is build hygiene that runs weekly. A rule refusing it is a rule that gets removed. `$VAR` and `$(...)` are refused because containment cannot be PROVED, and `.git` is refused although it is inside the tree because it is the one path the tree cannot restore |
| **DS-2** connection strings | a URI whose host is routable (has a dot and is not loopback) | `localhost`, `127.0.0.1`, a single-label compose service, and `psql "$DATABASE_URL"` | The host decides, not the scheme. Refusing the local database refuses how everyone runs the local database. An env reference carries no literal host, and where it points is `VG-7`'s question |
| **DS-3** force-push | `--force`, `-f` inside any short-flag cluster, `+refspec` | `--force-with-lease`, `--force-if-includes`, `git push -u origin HEAD` | **The deliberate line.** Force-push is banned because it destroys a commit somebody else has. **The lease refuses in exactly that case**, so it IS the property the ban exists to obtain. Refusing the lease form too would refuse the safe way and leave only the unsafe one, and [ADR-D1](../decisions/ADR-D1.md)'s branch-restart case needs it |

**Fails loud, never shut.** An unparseable payload exits **1** with `VG-8 HOOK DEGRADED`, not 2. Blocking every tool call on a payload-shape change wedges a session with no way out but editing `settings.json`, which is a worse control than the one it replaces. A degraded run is visible; a shut one is a self-inflicted outage.

### Why the disposition is `Discharged outside Actions` and not `Wired`

`CI-06/vg-inventory` requires a `Wired` leg to name a workflow, every job it names to be a top-level key in that workflow, and the step or rule to resolve. **No Actions job runs a hook that fires on a tool call**, so `Wired` is not available and claiming it would fail the gate rather than satisfy it.

[ADR-080](../decisions/ADR-080.md) section 5 calls `Discharged outside Actions` **the weakest disposition in this table** when the row *states the control* instead of *rowing the work*. This one rows the work: the settings entry, the matcher, the file, the self-test and its case count. **The repair ADR-080 names for `VG-7` is the same repair here**, and it is one `ci.yml` step running `--selftest`. `ci.yml` is outside this fence, so it is `Next` and not done.

**The row keeps BOTH legs and they stay conjunctive** ([ADR-080](../decisions/ADR-080.md) section 3). The grants leg is untouched, still `Discharged outside Actions` on [data-model](../architecture/data-model/README.md)'s append-only set and the four migrations that revoke on it, and **still with no probe asserting it**. Only the hook leg moved.

### Two things the dispatch asserted that are not true of this tree

**One. The CLAIM table carries no row for 156.** The dispatch said *"Session 156 is already CLAIMED for you in `docs/sessions/README.md`'s CLAIM table, strike that row when you write your log"*. The table's highest number is **152**, and **149 through 155 have no rows at all**. There was nothing to strike, and none was added: the table's own line 25 settles it, *"`119` is this session and is written, which is why it is in the entries below and not here"*. A written session belongs in the ENTRY table only, and adding a claim for a session that has already landed would be the second row [ADR-065](../decisions/ADR-065.md) T3 forbids.

**Two. The fence had to move by one paragraph, and this session's own change is what moved it.** The fence was `STRATEGY` section 4.2's `VG-8` row ONLY. The paragraph under that table read *"Three of the twelve are wired, **two are findings**"*, and turning `VG-8`'s hook leg into a disposition made that sentence false. It is repaired in the same commit, preserving ADR-080's 2026-08-22 measurement of two as the historical claim it is. **Repairing a sentence this diff falsified is not the same as editing a neighbouring row**, which is what the fence was drawn around, but it is a fence extension and it is named rather than absorbed.

**And one more, smaller.** The hook's implementation lives at [`.claude/hooks/block-dangerous-shell.mjs`](../../.claude/hooks/block-dangerous-shell.mjs) and the fence named `.claude/settings.json`. **A settings file can only hold a hook as a shell string on one line**, and the predicate above is roughly 250 lines of it. *"Hooks are law"* (C10) works only if a human can read the law, and an unreviewable control is the failure this whole gate exists to prevent, so the predicate is a file and `settings.json` holds the one line that invokes it. ADR-080 measured *"no hooks directory exists"* as part of the finding, so creating one is what discharging it means. The directory is not read by `eslint .` (dot-directories are skipped in flat config, checked by naming the file explicitly, which lints clean), so it cannot break `CI-01` later by accident.
