## 2026-08-17 - Session 50: the fixture wiring, and the premise ADR-048 rests on (non-money)

- **Landmines:**

  - **`IMPLEMENTED_RULES` IS TRUE OF THE PACKAGE AND FALSE OF THE FOLD, AND THAT IS A HOLE ADR-048 DOES NOT NAME.** The ADR enumerates four ways the derivation can be wrong and closes each, three of them "before any fixture is consulted". **Its failure mode 3 is "a rule id is added to the declared set without the rule being implemented", answered by cross-checking against the passing `RE-U-nn` set.** That cross-check is satisfied here: all 45 declared rules are implemented and every one has a passing unit test. **They are implemented in `advanceDay`, `applySettlement` and `evaluatePayout`, and CI-03 folds `evaluate`**, the scaffold placeholder that returns its input by reference and emits nothing. ADR-048 speaks of "the engine" as one thing and M01 section 1.3 exports six functions; the loader calls none of them. `checkDeclarationAgainstFold` is the check that names it, and it is the retired probe's own warning promoted from a comment, **because the case that header named stopped being hypothetical**.

  - **THE `bigint` DEFECT WAS INVISIBLE AND WOULD HAVE STAYED INVISIBLE UNTIL THE MOMENT IT MATTERED.** `INV-02` makes every money field the engine returns a `bigint`, JSON has no literal for one, and `Object.is(4770000n, 4770000)` is false. Whatever a comparison decides about two types, it may not describe them in a way a reader cannot tell apart.

  - **A COERCION FIX IS ONE CHARACTER FROM BEING WORSE THAN THE DEFECT, SO BOTH DIRECTIONS ARE SEEDED.** The old comparison could never assert a cent. The third seed removes `Number.isSafeInteger`, at which point a fractional expectation reaches `BigInt()` and **throws**: an exception is not a diff, it names no field, and CI-03 would report a crash where a fixture defect belongs.

  - **THE RULE GROUPS ARE READ FROM M01 BECAUSE THE ENGINE STATES THEM IN COMMENTS.** ADR-048 requires coverage to report polarity per rule group and rejects deriving polarity from the group, "because the group is not written on the fixture and would become a second hand-maintained mapping, which is ADR-034's class". **That argument applies to the report too.** `RuleId` in `rules.ts` carries the eight boundaries as comments, which no machine reads; restating the ranges in the loader would have been the second expression.
