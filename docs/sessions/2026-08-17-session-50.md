## 2026-08-17 - Session 50: a disabled consistency gate reports skipped, and the EngineEvent union (money path)

- **Done:** **Two review-desk rulings, both landed, and the first one was repaired by being read out of the sources rather than out of the file.** [`consistencyOk`](../../packages/rules-engine/src/day/consistency.ts) returned `{ ok: true, skipped: false }` when `cfg.enabled` is false, so a gate the plan never configured rendered as **SATISFIED** in every consumer that reads the flag. The repair is **one line**, `skipped: true`, plus the header comment that caused the wrong repair to be proposed first. [`EngineEvent`](../../packages/rules-engine/src/types.ts) is now the **discriminated union** of the eight concrete events rather than the base `{ type: string; tradingDay }`; the base is renamed `EngineEventBase` and `EngineEventType` is derived from the union. New suite [`engine-events.test.ts`](../../packages/rules-engine/test/engine-events.test.ts), six cases. `pnpm run verify` green apart from `falsify:ci`'s absent scanners: **6 of 6 invariants, 663 tests with 30 skipped, 15 of 15 gates clean and dirty, 16 scope cases**. **ZERO fixtures regenerated**, and that is a property of the format rather than a piece of luck: see the third landmine.
- **Next:** **The `apps/worker` leaf-table exhaustiveness hole** recorded below is the follow-up this session declined to take, because it is outside the fence and is a real finding independently of anything here. After it, the fixture-wiring session is still the bottleneck for `GS-080` and `GS-060`, both of which turn on the `skipped` flag this session just made correct and neither of which can be written until `diffEndState` grows a path syntax.
- **Blockers:** None taken. Two things were **reported rather than changed**, both because changing them would have been this session widening a frozen rule on its own authority: `R-37`'s zero-gap case and `scripts/demo/render.ts`'s now-stale comment.
- **Landmines:**

  - **THE WRONG RULING WAS REASONED OUT OF A CODE COMMENT THAT CONTRADICTED FIVE FROZEN CITATIONS, AND BOTH ENDS OF THE REVIEW BELIEVED IT.** [`consistency.ts`](../../packages/rules-engine/src/day/consistency.ts)'s own header read **"`skipped` IS NOT `!enabled`"** and reserved the flag for `R-30`'s denominator rule. That sentence was a previous session's invention. The corpus says the opposite four separate times in nearly the same words: `CV-19` ([M01:286](../plans/M01-rules-engine.md)) "using the **same `skipped` shape** as the consistency denominator rule", [EC-050](../edge-cases/EC-050.md) "the **identical shape** the consistency denominator rule already uses", [ADR-015](../decisions/ADR-015.md) "the **same shape** the consistency denominator rule already uses", [GLOSSARY](../GLOSSARY.md) "reports `pass: true, skipped: true` and renders as disabled", and `GS-080` "the **same shape** the consistency denominator rule uses". The first ruling issued from the review desk therefore called for a **third state** (`evaluated` / `skipped` / `disabled`) and forbade the one-line fix, on the strength of the comment. **The comment is what had to be deleted, not the vocabulary.** This is [EC-157](../edge-cases/EC-157.md)'s shape exactly: **one artifact disagreeing with four, and the disagreeing one winning because it was the one nearest to hand.** There it was an executable `CHECK` constraint against four written identities, and the lesson recorded was that "an executable statement of the wrong identity is still the wrong identity ... the only one of the five artifacts that was never read against the other four". Here it was a code comment against five frozen citations, and it was never read against them either. **A claim nobody re-derived became a fact**, on a money path, for the second time in two days. The comment now carries all five citations, so the next reader is corrected by the file rather than misled by it.

  - **THE ONE SOURCE THAT AGREED WITH THE CODE IS THE REASON THE CODE LOOKED RIGHT, AND IT IS THE WEAKER KIND OF SOURCE.** [M01 section 3.6](../plans/M01-rules-engine.md)'s reference algorithm writes `if (!cfg.enabled) return { ok: true, skipped: false };` verbatim, and `consistency.ts` was a faithful transcription of it. So a reviewer checking the implementation against the primary source found agreement and stopped. **A five-line sketch inside a section about arithmetic lost to a validation rule stated in section 2.4 and repeated in four documents outside M01**, and naming that precedence is the transferable part: the specific and repeated statement governs the incidental one. **No frozen document moved and no ADR was needed**, which is the test that the repair was the right one. A third state would have required amending `CV-19`, `EC-050`, `ADR-015`, the GLOSSARY, `GS-080`'s stated shape and `API_CONTRACT`'s published gate object, to fix a defect whose cause was one comment.

  - **NO FIXTURE COULD EVER HAVE CAUGHT THIS, AND THE FIXTURE THAT WOULD IS HELD BACK ON A DIFFERENT BLOCKER.** `engine_gates` is a **nested object** and [`diffEndState`](../../packages/golden-loader/src/compare.ts) compares flat fields with `Object.is`, so no expectation reaches the `skipped` flag; `GS-021`'s own sibling says so in its `note`. That is why zero `*.expected.json` moved and it is why the claim is worth stating rather than celebrating: **the golden suite was silent because it is structurally incapable of speaking here**, not because the change was safe. `GS-080` is precisely "a gate configured to zero renders as disabled, not as satisfied" and is blocked on that same nested-object limit. **The defect and the test that would have found it were blocked by the same missing loader feature**, which is the argument for the path syntax stated in cost rather than in principle.

  - **`maxDayShareBp` IS NOW LOAD BEARING AND IT IS THE TYPE THAT GUARANTEES IT, NOT A CONVENTION.** Folding the disabled case into `skipped` is only safe because support can still tell **"passed because there was nothing to test"** from **"never configured"**, and that distinction survives with no new field: `ConsistencyRules` is a discriminated union whose `{ enabled: false }` arm **has no `maxDayShareBp` field at all**, so the disabled branch has no limit available to report and `null` is the only value it can carry; `R-30`'s branch is reached only under `enabled: true`, where `CV-06` pins `0 < max_day_share_bp <= 10000` and the value can never be a falsy `0` that reads like an absence. It was **verified against the type before being relied on** and is now asserted in [`rules-e-progression.test.ts`](../../packages/rules-engine/test/rules-e-progression.test.ts), because a property that is the whole reason a third state was not added must not stay a readable coincidence.

  - **`R-37`'s ZERO-GAP CASE IS THE SAME ARITHMETIC SHAPE AND WAS REPORTED RATHER THAN CHANGED.** The case the ruling asked about, **no cadence anchor**, is already correct: [`gates.ts`](../../packages/rules-engine/src/payout/gates.ts) reports `pass: true, skipped: true` and `rules-f-gates.test.ts` already pins it with `CV-19`'s reasoning. What is left is `cadence_gap_trading_days == 0`, where `counted >= 0` is unconditionally true and the gate reports `pass: true, skipped: false`, reading as satisfied. `EC-050`'s **general** rule covers it in its own words: "a gate whose configured threshold makes it unconditionally true reports `pass: true, skipped: true`", and it is the identical shape `CV-19` rules for `R-33`'s zero. **But no frozen document says zero disables `R-37`, and `PW-04` cuts the other way**: it fires a `warning` on `cadence_gap_trading_days == 0` with `required_win_days <= 1` ("approaching uncapped daily extraction"), which treats zero as a live and dangerous configuration rather than an absent gate. **It is unreachable on all three v1 plans** (Core EOD 5, Direct 5, Merit Rapid 1), so nothing is at risk today. Changing it would be this session extending `EC-050` to a gate no document names, one session after being corrected for reasoning from an invention. It needs a ruling, not a commit.

  - **`apps/worker`'s GATE-LEAF TABLE HAS NO EXHAUSTIVENESS TIE, AND ITS COUNT ASSERTION DOES NOT SUPPLY ONE.** [`state-hash.ts`](../../apps/worker/src/batch/state-hash.ts)'s `ENGINE_GATE_LEAVES` is a hand-written list of twenty-five dotted paths, typed `path: string`, with **no `keyof`, no `Record<>` over the interface and no `satisfies`**. `state-hash.test.ts` asserts `toHaveLength(25)`, which pins the list against **itself** and not against `EngineGateResults`. So a field added to any gate interface compiles, is **silently never hashed**, and every test still passes at 25. That is `SD-08`'s divergence surface losing a leaf without a single failure anywhere. **This session's change did not add a gate field**, precisely because the repair turned out to be one line, so the hole is untouched and unexercised rather than newly dangerous. It is recorded here as a follow-up because it is a real finding **independent of anything in this diff** and because the next session that does widen a gate record will hit it without warning. The explicit ordered array is correct and required (M01 section 1.4 bans key iteration); what is missing is the compile-time proof that the array is complete. The shape that supplies it is in [`engine-events.test.ts`](../../packages/rules-engine/test/engine-events.test.ts), where `Record<EngineEventType, true>` makes a missing member a compile error in both directions.

  - **A COMMENT IN `scripts/demo/render.ts` NOW DESCRIBES A WORLD THAT NO LONGER EXISTS, AND IT WAS LEFT THAT WAY ON PURPOSE.** It reads "there is no exported discriminated union, and a per-type renderer would need a cast per event type", which was **true when written and was the best available evidence for ruling 4** (a consumer documenting the cast it was forced into). It is false as of this session. `scripts/demo` is outside the fence, so it is reported rather than edited, and it is reported **loudly** because a stale comment that a later reader trusts is exactly the failure the first landmine on this page describes. The file's behavior is unaffected: it walks `Object.entries` and needs no narrowing.
