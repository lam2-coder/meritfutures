- **Landmines:**

  - **`LC_ALL` CANNOT BE RANDOMIZED IN-PROCESS, AND THE OBVIOUS READING OF STRATEGY 3.1 PRODUCES A SUITE THAT PASSES FOREVER WHILE PROVING NOTHING.** Section 3.1 gives `PT-06` "`TZ` and `LC_ALL` randomized per case, which is how a `toLocaleDateString` gets caught". `TZ` works: V8 re-reads `process.env.TZ` on every `Date` operation, and one instant renders at +00:00, +14:00 and +05:30 under three successive assignments. **`LC_ALL` does not.** Node resolves the ICU default locale **once at startup**, so `Intl.DateTimeFormat().resolvedOptions().locale` stays `en-US` however it is assigned afterwards and a bare `toLocaleDateString()` keeps formatting `1/2/2026` under a Turkish `LC_ALL`. The same values **on the command line** do change it. So the locale half is carried **across processes** by `RE-D-02` and `engine-digest.mjs`, and `localeIsProcessScoped()` **measures** the fact rather than restating it, so a future runtime that fixes this flips the suites on by itself. Written into [STRATEGY section 8.2](../testing/STRATEGY.md) because the next reader of section 3.1 will otherwise implement the sentence literally and ship a vacuous gate.

  - **THE HOLE `RE-D-03` CLOSES IS A PATH, NOT A LINE, WHICH IS WHY FOUR MECHANISMS MISSED IT.** `RI-01` reads the manifest and says so in its own `covers`. `merit/engine-purity` reads one file at a time and returns early on **every** relative specifier (`if (source.startsWith('.')) return`). `eslint.config.js` attaches it to `packages/rules-engine/src/**/*.ts` **and nothing else**. `tsconfig`'s `types: []` removes ambient declarations, not an explicit `import ... from 'node:fs'`. So `packages/rules-engine/impure/x.ts` importing `node:crypto`, reached from `src/index.ts` as `../impure/x.js`, is **invisible to all four at once**. Seeded on this tree: `RI-07` reports both findings with the import trail while `RI-01` and `eslint packages/rules-engine/src` **both stay green**, and the falsification case demands the string `ADDITIVITY: RI-01 green, engine-purity green` in its own needles, so a future change that made the old mechanisms catch it would be reported OFF-TARGET rather than silently accepted.

  - **A MUTANT WHOSE EFFECT NEVER LEAVES ITS FUNCTION PROVES NOTHING, AND THE GATE WAS RIGHT TO SAY SO.** `RE-D-02`'s first seed assigned `toLocaleDateString()` to a variable it then discarded. The digest was byte-identical under every locale and the harness reported "did not fail". The reflex is to assume the gate is broken; **the gate was correct and the seed was worthless**. It is now a `toLocaleString()` thousands separator, which reaches every money figure in the output. The general shape: **a seeded violation must reach the surface the gate compares**, and "I planted something impure" is not the same claim as "I planted something the gate can see".

  - **THE ENGINE'S `types: []` REACHES ITS TEST DIRECTORY, AND THAT IS LOAD BEARING RATHER THAN INCONVENIENT.** `PT-06`'s harness needs `process`; `packages/rules-engine/tsconfig.json` sets `types: []` with `include` covering `test/**/*.ts`, and `tsc` refused the file five times. **Widening that array would have been weakening a gate to pass it**, which the working agreements forbid in as many words and which that file's own comment calls "the strongest of the three mechanisms guarding this boundary". The harness lands in `packages/golden-loader/test/` for exactly the reason that package's tsconfig already gives for the loader itself. **The type error was the design telling us where the file goes**, and the cheap fix was the wrong one.

  - **`INV-17` CANNOT BE VIOLATED ALONE, AND THE COUNTERFACTUAL DECLARES THAT RATHER THAN RELAXING TO ACCOMMODATE IT.** The lifetime bound is `max_payouts * max cap`; while `R-42` clamps every approval and `R-49` bounds the count, it holds **arithmetically** as their conjunction over a life. The settlement counterfactual asserts a **single** finding per inverted rule, so this one is entered in a `JOINT` table as a **compile-checked list of one**, with a test asserting the list has exactly one entry. A counterfactual quietly permitted two findings would be a hole in the one assertion that file's honesty rests on, and it would hide the day some future rule genuinely started breaking two things at once.

  - **THREE COLLATERAL-FINDING DEFECTS IN THE SETTLEMENT GENERATOR WERE FOUND BY THE SINGLE-FINDING ASSERTION, AND EACH WAS FIXED BY MOVING THE INVERSION RATHER THAN LOOSENING THE ASSERTION.** Shifting only the first ordinal to 2 also broke consecutiveness (the whole stream shifts now). This is `day-sequence.property.test.ts`'s stated experience arriving again on a different structure.
