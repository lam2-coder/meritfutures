## 2026-08-17 - Session 50: the State column is deleted, and the letter registry gets `CI-06p` (non-money)

- **Done:** **[ALLOCATION](../decisions/ALLOCATION.md)'s State column is deleted from all three tables**, on [ADR-034](../decisions/ADR-034.md)'s own remedy, and **[`CI-06p`](../testing/STRATEGY.md) is written, seeded and watched failing on each of its three assertions.** The derivable half of the deleted cell is derived at check time by `node scripts/corpus/gates.mjs allocation`, a subcommand that lands with the gate. Letter `p` is claimed in the table it protects. **16 of 16 gates pass, and the full falsification harness passes**: every gate clean and dirty, 18 scope cases including the two new ones.
- **Next:** **`CI-06f`'s missing counterpart on the ADR table**, which is `CI-06p`'s second assertion one registry over: every `ADR-nnn` on disk is claimed by a row, exactly as `CI-06h` already requires of every migration on disk. It is **blocked on [`OI-11`](../STATE.md)** and named as blocked rather than left as an absence: the ADR table claims `039` to `046` twice each and the assertion fails on arrival. `OI-11` needs a ruling on which of each pair survives, and it is now the blocker for two gates rather than one.
- **Blockers:** **`OI-11`, the duplicate rows**, unchanged and untouched here. **The cross-branch job**, still unwritten: `CI-06p` inherits `CI-06f` and `CI-06h`'s two-ref gap verbatim and declares it on arrival.
- **Landmines:**

  - **A DECLARED GAP IS A DESCRIPTION OF A DEFECT, NOT A FIX FOR ONE, AND THIS IS THE MEASUREMENT.** [ADR-036](../decisions/ADR-036.md) ruled the State column prose no gate can check, and STRATEGY carried a paragraph declaring it as a fifth coverage gap. **Both were written before eight of the eleven drift instances.** Every word in them was true, the column was correctly described as unenforceable in two frozen documents, and it went on being wrong roughly every other day. The corpus's existing discipline is that a gate declares what it does not cover; **this session's evidence is that declaring is where the work starts, not where it ends**, because a reader who knows a column is unchecked still reads it and a session that repairs it by hand still leaves it repairable by hand.
  - **THE ELEVEN REPAIRS EACH LOOKED LIKE THE FIX AND EACH WAS THE DEFECT RECURRING.** The rows are the record: `035` was corrected four commits after PR #9 and the row says so, `036` was corrected in the fold that landed ADR-037 and ADR-038, and the session brief that commissioned that correction **was itself wrong about which row was stale inside two days**. Every one of the eleven was a careful person applying care to a class that care does not fix. ADR-034 says this in its own words about counts ("no amount of care fixes this class, because care is what was already being applied") and the column beside its own table was the site that had not heard it.
  - **THE REGISTRY THE SHARED PARSER CANNOT READ IS THE ONE THAT ENDS UP WITH NO GATE, WHICH INVERTS THE INTUITION.** `CI-06p`'s specification was written in the letter table's own prose a week ago, in the file the gate protects, and two harder gates were built beside it while it sat. The reason is mechanical rather than about attention: `allocated()` matches a three-digit or four-digit first cell and **a letter does not parse**, so ADR-036's careful insistence on one parser for both numeric tables became the reason the third table had none. **A registry shaped differently from its siblings is the one most likely to be unguarded**, precisely because reuse is cheapest everywhere else.
  - **GAPLESSNESS CANNOT FORCE A ROW, AND A GATE THAT ONLY ASSERTED IT WOULD BE DECORATION HERE.** A new gate in the runner fills its own hole, so the letters stay gapless forever while nobody claims anything and the table stops being what a sibling branch reads. The assertion that earns `CI-06p` is `CI-06h`'s second one, **every implemented letter is claimed by a row**, and the pair generalises: presence in the artifact and a claim in the registry each imply the other, or the registry is decoration. **`CI-06f` has never had that direction**, which nobody had noticed because the ADR table has been complete by hand.
  - **THE LETTER PARSER'S SECTION BOUND IS NOT THE NUMERIC ONE, AND COPYING IT WOULD HAVE FAILED SILENTLY.** `allocated()` bounds a table on the next `\n## `. The letter table is the **last** `##` section in ALLOCATION.md, so that bound runs to end of file and every table row in the prose below it would claim a letter. It is written to bound on any heading, in both the gate and the harness helper, and the reason is in a comment beside each: the two numeric tables have a `##` sibling beneath them and never had this problem, which is exactly what makes the copy tempting and wrong.
  - **THE SEED CLAIMS TWO LETTERS PAST THE FREE ONE, BECAUSE `expect` IS RESOLVED AFTER THE SEED RUNS.** `CI-06l`'s harness bug is the precedent: a seed that edits the row the expectation is computed from makes the harness ask about a different target than the one the gate names. Claiming `free + 2` opens the hole at `free` and leaves `free` where it was, so the expectation is stable by construction rather than by luck.
  - **THE QUIET DIRECTION NEEDED NO SEEDED CASE, AND SAYING WHY IS THE POINT.** `CI-06h/reserved` exists because a reserved hole passing is indistinguishable from a gate switched off. `CI-06p` needs no such case: **`o` is claimed by [ADR-044](../decisions/ADR-044.md) and implemented by nobody**, so every clean run of the harness already asserts that a sibling branch's reservation is a hole that passes. That is a real control planted in the corpus rather than in a temporary directory, and duplicating it as a scope case would have tested the same tree twice.
  - **WHAT A READER LOSES IS STATED IN THE FILE RATHER THAN GLOSSED.** The tables no longer say which claims are live. They never held that as a fact; they held a fact somebody entered, and the eleven instances measure how long it survived. `git ls-remote` answers it across refs, which is the manual step the `044` collision was written to teach, and the `allocation` subcommand answers the half one ref can honestly answer, labelling `absent` as **absent from this ref and nothing more**.

### What was NOT done, named rather than implied

**No ADR was written for the deletion**, and that is a judgment worth recording rather than an omission. The remedy applied is [ADR-034](../decisions/ADR-034.md)'s, stated in ADR-034's own words and already applied once inside this file to the next-free-number sentence; the gate letter was allocated in the table before the gate was written, per ADR-036. **A new ADR would restate a ruling that exists**, which is the shape [ADR-037](../decisions/ADR-037.md) exists to refuse. If the founder reads the deletion as amending ADR-036's "it cannot verify the State column" consequence rather than executing ADR-034's remedy, that is an ADR and this paragraph is where the disagreement is visible.

**`CI-06o` is still prose.** [ADR-044](../decisions/ADR-044.md)'s money-path model ban has a letter and no gate, and this session claimed `p` around it rather than taking it. The hole it leaves is legitimate under `CI-06p`'s own assertion and is what the clean-tree run proves.
