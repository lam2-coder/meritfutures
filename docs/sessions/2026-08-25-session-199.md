### 2. `journal_entries` is the two-column shape and it is NOT the two-column refusal

The brief says that a table with two identity columns and no obvious owner is left unregistered and the columns reported. **`journal_entries` has two columns that reach a person and the owner is obvious, and the difference from [`identity_links`](../../packages/db/migrations/0002_identity.sql) is worth stating because the shapes look alike from a distance.**

```
identity_id  uuid NOT NULL REFERENCES identities(id) ON DELETE RESTRICT
account_id   uuid NULL     REFERENCES accounts(id)   ON DELETE RESTRICT
```

**One of them is TOTAL over the table and the other is not.** `scope` is CHECKed to `('day', 'round_trip')` and a `day`-scoped entry need name no account, so `account_id` is nullable by design; a rule through it returns a strict subset of a person's own notes, chosen by whether they happened to attach an account, with **no error anywhere**. `identity_id` is the author and is present on every row.

**`identity_links` has no such asymmetry, which is exactly why it stays unregistered**: `identity_a` and `identity_b` are both `uuid NOT NULL REFERENCES identities(id)` under a canonical-order CHECK, so which column a person's id lands in is decided by UUID comparison and by nothing else. **A choice is available here and is not available there**, and this session takes the one and not the other.

**Registering `journal_entries` makes it READABLE and nothing else.** `deleted_at` is a tombstone rather than an end state, so a scoped read returns soft-deleted rows and the purge job ([M13](../plans/M13-trader-analytics-journal.md) section 3.3, `INV-M13-07`) is what makes deletion a promise; no scope rule enforces that and the `why` says so. **`DEP-M13-06`'s missing grant is likewise untouched**: `journal_entries` is in no revoke list in [`0026`](../../packages/db/migrations/0026_roles_and_grants.sql) and [session 164](2026-08-24-session-164.md)'s second landmine stands exactly where it stood.

### 3. `contract_specs` is `firm` as a decision, and the refusal was watched

`firm` is the class with no column to point at, so it is the one a session can reach for by default. **It is not the default here.** `contract_specs` carries `symbol`, `exchange`, two tick-size bigints, `tick_value_cents`, `currency`, `is_micro` and an effective range: **there is no identity column and no correct one**, because a per-identity slice of an instrument's tick value is not a smaller version of it. The composite primary key `(symbol, effective_from)` is transcribed rather than replaced by a surrogate, on [`detector_definitions`](../../packages/db/src/schema.ts)' stated reason: a spec change is another row with its own effective date, which is what makes a per-instrument figure computed months ago reproducible today.

**The consequence at the call site was executed rather than asserted.** A temporary probe naming all five keys against `scopedDb(...).rows(...)`, then `tsc -p packages/db --noEmit`:

```
packages/db/src/__probe__.ts(4,8): error TS2345: Argument of type '"contractSpecs"'
  is not assignable to parameter of type 'ScopedTableKey'.
```

**Exactly one error over five call sites.** `fills`, `roundTrips`, `journalEntries` and `analyticsSnapshots` compile; `contractSpecs` is refused by name. The probe was deleted and `git status` reported clean before this line was written. **vitest cannot see that refusal at all** -- it runs transpiled code -- which is why it is watched here and in [`falsify-ci.mjs`](../../scripts/ci/falsify-ci.mjs) at `CI-01` and not in the suite.
