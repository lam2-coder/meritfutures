## 2026-08-20 - Session 104: the Monte Carlo harness, `packages/harness` (FOLD-05 P7, non-money)

- **Done:** **`@merit/harness` exists and `DEP-M21-01` is no longer a dependency that does not exist.** It is a trial loop and an aggregator over [`packages/rithmic/src/simulator`](../../packages/rithmic/src/simulator/session.ts)'s day model, folded through the real engine: nine source files, seven test suites, 71 cases, and `pnpm run verify` green (74 test files, 1085 tests, 24 gates clean and dirty). The eight outputs [M21](../plans/M21-plan-designer.md) requirement (b) names are produced, each carrying its calibration identity, its digest, its observation date, the seed, the engine and harness versions, and **its own sample size rather than the run's**. `runSweep` produces `HO-08`'s arms as individually traceable runs sharing a sweep id. **Nothing in `docs/` was touched but this file**, per the fence.
- **Next:** **The portfolio risk engine is the next real piece and it is not this one.** `RE-S-07`, `RE-S-08` (`CVaR99` at `rho = 0.30`, the reserve floor) and `RE-S-09`'s ruin table aggregate across a book with a correlation structure (`PP-06`); this package produces the per-account liability distribution such an engine consumes and stops there. Before any band is set from a run, [STATE](../STATE.md)'s surviving item 5 has to close: [SIMULATION_HARNESS section 9.4](../testing/SIMULATION_HARNESS.md) records the committed calibration engine as **stale in four places**, so a band derived from it today would be calibrated against a number that is about to move.
- **Blockers:** None for the harness. **Four doc edits are owed and none was in this session's fence**, listed under landmines below so the next session that holds the fence does not have to rediscover them.
- **Landmines:**

  - **`AS-08` IS A DIRECT REQUIREMENT ON THIS PORT AND IT LIVES IN M01, NOT IN THE HARNESS DOCUMENT.** The first implementation modelled request timing as a random draw, which is what [SIMULATION_HARNESS](../testing/SIMULATION_HARNESS.md) implies and what M01 forbids by name: *"the simulation harness must model request timing as a strategy, not as a random draw, or the CVaR99 estimate that drives the reserve is BIASED LOW. This is a direct requirement on the Monte Carlo port."* A session reading only the harness document would have shipped the biased version and nothing would have said so. **The peak-picking policy uses no lookahead**, because a clairvoyant trader overstates the premium, which is a different error from the one `AS-08` warns of; the random policy survives beside it because M01 section 8.3 wants the estimate reported **under both** so the bias is measured rather than assumed, and `patienceTradingDays: 1` reduces one to the other so the pair is comparable.

  - **`RE-S-nn` NAMES TWO DIFFERENT LISTS AND BOTH DOCUMENTS ARE APPROVED.** [SIMULATION_HARNESS section 5](../testing/SIMULATION_HARNESS.md) says *"`RE-S-nn` is M01 section 8.3's identifier"* and the two tables disagree: M01's `RE-S-02` is INV-17's bound, which is section 5's `RE-S-06`; M01's `RE-S-03` is the peak-picking requirement, which section 5 gives to payouts per payer. The package cites **section 5** throughout, on the ground that it is the harness's own document. **This needs an ADR** and it is the collision most likely to be resolved silently by whichever session hits it next.

  - **`liability per funded account` LOOKS LIKE `RE-S-04` UNDER ANOTHER NAME.** `RE-S-04` is "firm dollars per funded account", and [`mc_lifecycle.py`](../../research/calibration/mc_lifecycle.py) computes it as `avg_firmcost_per_funded` over an accumulator whose own comment reads *"firm cash outflow = trader's split"*, which is the sum of the trader legs over funded accounts. That is the figure M21 section 3.2 lists as **unidentified**. If they are one output, `OQ-M21-03` needs **two** new identifiers rather than three. Reported on the output record itself so the collision is visible at the point of use; not resolved, because the registry's owner rules it.

  - **THE THREE PROPOSED `HO-nn` IDENTIFIERS ARE STILL NOT CLAIMED, AND THAT IS THE FENCE RATHER THAN AN OVERSIGHT.** `OQ-M21-03` proposes `HO-09` to `HO-11` be added "by whichever session builds the harness". This is that session and `docs/` is outside its fence, so the three outputs carry `registryId: null` and a `proposedRegistryId`, and a structural test fails if a later session promotes one without the document moving. **The owed edit is [SIMULATION_HARNESS section 7.1](../testing/SIMULATION_HARNESS.md)**, and the `RE-S-04` question above should be settled first or the registry gains a duplicate.

  - **`SD-M21-01` CARRIES ONE `swept_value_bp` COLUMN AND `HO-08` SWEEPS A COUNT.** The sensitivity sweep of record is over `PP-01`, `PP-07` and `max_payouts`, and a ladder of 5 is five rungs rather than five basis points. The harness records a unit beside the value; whether `0045` grows a unit column is the migration's question and `0045` is unwritten.

  - **THE RISK SETPOINT HAD TO BE PUSHED OR THE BREACH RATE WOULD HAVE BEEN WRONG IN THE FLATTERING DIRECTION.** The day model takes an auto-liquidation setpoint as data and the population spec supplies one at open. Left there, it never moves while the engine's trailing floor rises with every closing high, so the vendor stops liquidating anywhere near the floor the breach comparison uses, and the run produces `GS-087`'s "day low below the floor with no liquidation record" as the **normal** case. The loop therefore hands `RuleState.floorCents` to the day model each session, which is [M02 section 1.2](../plans/M02-rithmic-bridge.md)'s own arrangement (*"M2 pushes a floor value to the vendor as a risk setting. It is TOLD the number; it never derives it"*) and contains no arithmetic. **An unprotected account stays unprotected**, or `V-M2-08`'s condition would be erased by the fix.

  - **THE DAY MODEL IS DRIVEN ONE SESSION AT A TIME, AND THAT IS ONLY LEGITIMATE BECAUSE THE DRAWS ARE KEYED.** A settled payout leaves the platform balance on its effective day and an evaluation pass re-provisions the account at exactly `size_cents`, so the balance a day opens at depends on decisions made one day at a time and a single `simulate()` call over the window cannot express it. `rng.ts` states the property that makes the alternative free; `determinism.test.ts` **asserts it at the seam**, because a property stated in one package and relied on in another is a property nothing checks. It excludes the echoed `SimDay.account`, whose `startingBalanceCents` legitimately differs.

  - **A GREP HOLDS `INV-M21-09` AND `INV-M21-10` ACROSS SESSIONS AND A REVIEWER DOES NOT.** CLAUDE.md's caution is that the reconciliation session's worst errors were failures to check a claim against a primary source and that the fix is a mechanical assertion. So plan-parameter reads are confined to `assertions.ts` and the only bigint literals in `src/` are `0n`, `1n`, `10n` and `10_000n`, both asserted by `no-second-rulebook.test.ts`, **watched failing on a seeded violation of each** before it was committed. A plan figure cannot arrive as a form default.

  - **`pnpm-lock.yaml` IS THE ONE FILE OUTSIDE `packages/` THIS SESSION TOUCHED.** A workspace package is a lockfile importer, so adding one moves it. It is a mechanical consequence rather than a scope decision, and it is recorded in the pull request as such.
