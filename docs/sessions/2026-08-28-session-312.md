### 3. `GS-038` DID NOT SURVIVE THE READING, AND FOUR IS THE HONEST ANSWER

The row is B4 item 9, *"PSP duplicate and out-of-order delivery"*, against *"one account, correct final state"*. [GS-250](../testing/golden-scenarios/31-gs-246-to-gs-255-the-appendix-d0-attack-battery.md) restates the same pin in the corpus's own words: it *"pins that a legitimate duplicate and out-of-order delivery still **resolves** to one correct state"*.

**The duplicate half is asserted whole.** [`webhooks-psp.test.ts:164`](../../apps/api/test/webhooks-psp.test.ts): one event twice is one effect and two indistinguishable 200s, with a SEED that lands the effect twice when the uniqueness check is removed, a rollback that discards the APPLICATION rather than only the row, a two-different-events control and a same-id-other-provider control.

**The out-of-order half is asserted as far as the deferral and no further.** [`:490`](../../apps/api/test/webhooks-psp.test.ts) asserts the event is accepted, applies nothing, stores its re-drive window, stamps no `processed_at` and no `purchase_id`, and stays one row across a redelivery. **The word *"re-evaluated"* is in that block's own title and executes nowhere in this tree**, and three primary sources say so rather than one:

- [`webhooks-psp.ts:373`](../../apps/api/src/routes/webhooks-psp.ts): *"`defer_attempts` counts RE-DRIVES and this is the first arrival. **The re-driver is the batch's**, `psp_webhook_events_deferred_idx` is its index."*
- `grep -rn out_of_order_deferred` over `apps`, `packages` and `scripts` returns the two receivers, their suites, the enum in [`0006:290`](../../packages/db/migrations/0006_commerce.sql) and one design note. **No batch, no job and no worker reads a deferred row.**
- [`scope.ts:640`](../../packages/db/src/scope.ts) describes the re-drive as a thing that has not happened yet: *"the same event belonging to nobody while it is `out_of_order_deferred` and to somebody once it is `applied`."*

**So an out-of-order delivery stops at `out_of_order_deferred`.** A row whose expected end state is reached by code that does not exist is not proven, and the fix for that is a re-driver rather than a comment. **The row keeps `no-fixture-format`** and its citation now names the half, which is a better citation than the one it had; the one it had named the format.

**The comment was written into the file anyway, and it is the one place this session risked making things worse.** Writing `GS-038` into a suite that does not discharge it creates exactly the bait section 39's second trap describes. It is written in capitals, in the first line, that the id is there so the next reader meets the reasoning and **not** as a discharge. The alternative was to leave the next auditor to redo the whole reading, which is the cost session 305 already paid once.

### 5. The convention, and where it actually belongs

**Nobody writing a module suite was told**, which is why five rows with passing assertions sat blocked and why `GS-229` left the queue ahead of them for no better reason than that its author happened to type the id. Section 39 now carries the rule:

> **A suite that proves a `GS-nnn` must carry that id as a LITERAL STRING, in a construct that is not skipped.** Not the scenario's B4 number, not its `AS-nn` or `INV-nn` or `EC-nnn`: the eight characters. Write it in the comment run directly above the `describe`. `CI-06/fixture-inventory` assertion 6 is a **static parse** and cannot run vitest, so it can see that a file exists, that a construct is not skipped, and that a string is in it. **It cannot see that your suite is about `GS-274`. Nothing can, unless you say so.**

**Section 39 is the wrong home and the subsection says so in its own last paragraph.** Nobody writing `checkout.test.ts` opens the fixture-status table. **The two homes a suite author would actually meet, for whoever holds them:**

1. [`docs/testing/STRATEGY.md`](../testing/STRATEGY.md), which is the document a session reads before writing a suite. **One sentence, verbatim:** *"A suite that proves a golden scenario must carry that scenario's id as a literal `GS-nnn` string, in a construct that is not skipped, because `CI-06/fixture-inventory` assertion 6 is a static parse and cannot infer it."*
2. [`docs/testing/golden-scenarios/README.md`](../testing/golden-scenarios/README.md), whose second paragraph already says *"**Tests cite scenario numbers**, never prose"* and is one clause short of saying it. **The clause:** *"...as a literal `GS-nnn` string in a construct that is not skipped, which is what `CI-06/fixture-inventory` assertion 6 reads."*

**Either is one line and neither was in this session's fence.** The `gates.mjs` half is not proposed at all: [ADR-125](../decisions/ADR-125.md) clause 3 holds, the gate is right, and the naming convention was the thing that was never written down.
