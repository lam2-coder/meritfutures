### 6. Landmines

- **`RI-31` HAS FIRED ON FIVE CONSECUTIVE MERGES AND THE NEXT SESSION TO MEET IT WILL SUSPECT THE CHECK.** It is the only check that ever sees this defect and the tree measurement says it is the reason `main` is clean. **A control that has fired five times on a defect that used to land is evidence it is needed.** Do not weaken it, narrow it, re-scope it, make it conditional, or retire it.
- **`CI-06g` DOES NOT MERELY MISS THIS, IT RUNS OVER IT AND LEAVES IT CORRECT.** The gate rewrites every span it finds and compares each to its own query, so `gates.mjs generate` will happily normalize both copies of a duplicated line and `check` will then report every gate green over the broken file. Green gates are not evidence the merge was resolved correctly.
- **`RI-31`'s REMEDIATION SENTENCE IS A HEURISTIC THAT READS AS A RULE.** *"Keep the first and delete the rest"* is right for a merge artifact, where the two copies are the two sides of one hunk. It was not right for at least one of the fifteen [ADR-282](../decisions/ADR-282.md) repaired, where a sentence had been splattered into five session sections of `STATE.md` and its home was a specific session rather than the earliest copy. Confirm which copy belongs where before deleting.
- **`merge=union` LOOKS LIKE THE OBVIOUS FIX FOR THIS AND IS THE EXACT OPPOSITE.** It is the one merge driver built into git that a tracked `.gitattributes` can turn on with no per-clone config, and it produces the duplicate automatically with exit 0 and no conflict at all. A future session reaching for it will be reaching for the defect.
- **A COMMITTED `.gitattributes` NAMING A CUSTOM DRIVER FAILS SILENTLY AND LOOKS INSTALLED.** With no `merge.<name>.driver` in config, git falls straight back to the default text merge with no warning, no error and no diagnostic. Anyone who commits one and does not test it will believe a control is in force that has never run.
- **`scratchpad/` IS NEITHER TRACKED NOR IGNORED.** `git check-ignore -v scratchpad/resolve.mjs` exits 1 and prints nothing. The standing rule against `git add -A` in this repository exists for `falsify.mjs`'s tree mutations, so a session observing it for that reason has no reason to expect an untracked tool sitting in the same tree.
- **THE REPOSITORY WAS NOT PRESENT AT ALL ON ARRIVAL, WHICH IS THE `node_modules` LANDMINE ONE LEVEL UP.** `/home/user` was empty and there was no git repository anywhere, so the clone had to be requested and run first. `node_modules` was then absent too. Neither absence was committed.
