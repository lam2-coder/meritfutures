- **Objective:** make the ADR registry table and the session index GENERATED spans derived from the files themselves, rule on all three questions in [ADR-088](../decisions/ADR-088.md), and write no status-drift gate.
- **Done:** **Both tables are generated.** [`gates.mjs`](../../scripts/corpus/gates.mjs) gains two `SPAN_QUERIES` and three helpers; [decisions README](../decisions/README.md) and [sessions README](README.md) each wrap one table; 146 session files carry one index marker per `##` section; ten ADR headings moved one line each. [ADR-088](../decisions/ADR-088.md) is `proposed` with an unsigned approval line. **The comparison the brief demanded, run and printed: the ADR table is 85 rows in and 85 out with a set difference of ONE row** (`ADR-080`, where the row adopts its own document's capitalisation), and **the session table is 183 rows in and 185 out, two ADDED, none removed and none changed**. `node scripts/corpus/gates.mjs check`: **28 of 28**. `node scripts/corpus/falsify.mjs`: **28 gates pass clean and fail dirty, 56 scope cases, 10 loader cases**. `pnpm run verify`: **7 of 7 invariants, 104 files, 1,512 passed and 1 skipped, exit 0**. **Both new spans were watched FAILING on seeded drift**, each reported by name, and reverted with explicit paths.
- **Next:** [ADR-088](../decisions/ADR-088.md) needs a signature and nothing in it is enforced by a gate that did not already exist. `CI-06/retired-constraints` is still named and unwritten, and [STRATEGY](../testing/STRATEGY.md)'s `CI-06g` row now understates its own gate (below).
- **Blockers:** none.
- **Landmines:**

  - **A DOCUMENT CANNOT QUOTE A SPAN OPENER, AND THE FIRST DRAFT OF THIS SESSION'S [STATE](../STATE.md) SECTION PROVED IT BY LOSING NINE PARAGRAPHS.** Naming the two new spans by writing their opener markers literally, inside backticks, in prose was enough: `generate` read the first as a real opener, matched it against the closer of a `gate_count` span nine paragraphs below, and replaced everything between them with the 85-row ADR table. **`spansIn` uses the `s` flag, which is exactly what makes a table expressible as a span body, so the same property that enables this session's ruling is what swallowed the prose.** `CI-06t` did not see it because the markers happened to balance. Reverted with an explicit path and rewritten to name the spans by name. **The tree now has two spans whose bodies are tables, so the cost of a quoted opener has gone up and nothing warns about it.**

  - **THE BRIEF'S 25 OF 25 IS RIGHT AND REPRODUCES UNDER EXACTLY ONE FRAMING.** `git log --oneline -25 -- FILE | wc -l` returns the last 25 commits **that touch** the file, capped at 25, so it reports 25 for any file touched 25 times ever and never measures "of the last 25 commits" at all. Counted honestly it is **9** of the last 25 raw commits, **11** of the last 25 non-merge commits, and **25 of 25** over `--first-parent`, which is one merge and therefore one session each. **The session is the unit contention is measured in, so the figure stands and its derivation is now written down** in [ADR-088](../decisions/ADR-088.md) section 1, because a later reader running the obvious command gets 9 and concludes the premise collapsed.

  - **THE MOTIVATING DEFECT WAS ALREADY REPAIRED BEFORE THIS SESSION OPENED, AND THE ENTRY REFUSES TO CLAIM IT.** [Session 149](2026-08-23-session-149.md) found twenty ADR rows carrying a stale status word and repaired 27. Today all 85 files are `accepted` and **zero rows disagree with their own heading**, checked rather than assumed. **Generation fixes no live ADR drift; it makes the recurrence impossible.** An entry that implied a repair here would be describing session 149's work as its own.

  - **A SECOND DRIFT IS LIVE, IT IS IN THE OTHER REGISTRY, AND NOTHING IN THE TREE COULD SEE IT.** [`2026-08-20-session-95.md`](2026-08-20-session-95.md) holds **three** `##` sections and the ENTRY table carried **one** row for it, in the registry whose own stated rule is that a thing not in the index does not exist. `CI-06n` asserts file-to-row and row-to-file and is satisfied by one row per FILE, so a file with three sections and one row passes both directions. **[ADR-064](../decisions/ADR-064.md) section 1 is signed and says identity is `(log file, section heading)`**, so generating per section is not a strengthening this session chose; it is the signed identity applied, and the two orphans appear by construction.

  - **THE ENTRY ROWS ARE NOT DERIVABLE FROM THE HEADINGS AND THE OBVIOUS DESIGN WOULD HAVE DELETED 183 SENTENCES.** Checked at source: [session 49](2026-08-17-session-49.md)'s four rows and four headings differ in every one, and the rows carry text the headings never had. So each section gains one machine-readable index line **backfilled verbatim from the row that already existed**, 183 taken literally and 2 derived from session 95's own headings. **The byte guarantee was proved two independent ways**: strip-and-compare inside the writer, and `git` reporting 185 lines added, 0 deleted and 0 additions that were not markers. The marker prefix is distinct from the span prefix, so `CI-06g` and `CI-06t` cannot mistake it for a span.

  - **THE PLAN SAID ELEVEN HEADING EDITS AND THE ANSWER IS TEN, BECAUSE ON THE ELEVENTH IT IS THE ROW THAT IS WRONG.** Five headings were **enriched** to carry the richer sentence their row already held ([ADR-064](../decisions/ADR-064.md), [065](../decisions/ADR-065.md), [070](../decisions/ADR-070.md), [071](../decisions/ADR-071.md), [073](../decisions/ADR-073.md)); five were **capitalisation-normalised** ([ADR-052](../decisions/ADR-052.md), [053](../decisions/ADR-053.md), [055](../decisions/ADR-055.md), [069](../decisions/ADR-069.md), [072](../decisions/ADR-072.md)). **[ADR-080](../decisions/ADR-080.md)'s heading already matched the majority convention, 52 files to 16**, so its row adopting the document is a row repair and not a heading edit. **Exactly one line changed in each of the ten and the `status:` token was not touched**, asserted mechanically rather than reviewed by eye, so `CI-06r` is unaffected.

  - **THE MISFILED-REGISTRY-ROW DEFECT HAS NOW HAPPENED THREE TIMES AND THE THIRD WAS MINE.** An `ADR-079` row sat inside [decisions README](../decisions/README.md)'s *Gate closures* table rather than in the ADR table, written by [session 135](2026-08-22-session-135.md), which was this same author. The first wrap took the contiguous run of `| [ADR-` rows and therefore reached it, and `generate` deleted the entire Gate closures section. **`CI-06n` caught it**, reporting six `gates/` files with no row: the gate this ruling makes vacuous for two registries caught the change that makes it vacuous. Reverted with an explicit path, the wrap redone above the heading, the stray row deleted.

  - **`CI-06n` GOES VACUOUS FOR TWO OF ITS FIVE REGISTRIES AND THAT IS RECORDED RATHER THAN DISCOVERED LATER.** Once the rows are generated from the files, both directions hold **by construction** for `decisions/` and `sessions/`. It still covers `data-model/`, `golden-scenarios/` and `edge-cases/`. **`CI06U_REGISTER`'s sessions-README entry STAYS**: its duplicate first cells are [ADR-061](../decisions/ADR-061.md)'s T3 case, generation makes them structural rather than accidental, and deleting the entry would claim a repair nobody made. Two new duplicate keys arrived with session 95's rows and are registered by name with that reason.

  - **[STRATEGY](../testing/STRATEGY.md)'s `CI-06g` ROW NOW UNDERSTATES ITS OWN GATE, AND IT IS FLAGGED RATHER THAN FIXED.** The row reads *"no document states a quantity a script can derive ... unless the number sits inside a generated span"*, which describes a span as carrying a NUMBER. A span may now carry a **table**. **The fence granted the gate-inventory row, and that row needs no change because this session adds no gate**; the row that is now wrong is the `CI-06g` one, which the fence does not grant.

  - **NO `CI-06x` GATE WAS WRITTEN AND THE LETTER STAYS UNCLAIMED.** The brief made it conditional and the condition resolved: if the rows are generated, a status-drift gate has nothing left to check. [ADR-082](../decisions/ADR-082.md) line 124 already says *"`x` stays unclaimed"* and this session does not change that.
