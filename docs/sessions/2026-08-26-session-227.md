#### 3. The four rulings, each decided on the evidence above

**RULING 1. A PREDICATE IS A TYPED EQUALITY CONJUNCTION OVER DECLARED COLUMNS, NEVER A `SQL` FRAGMENT.**

`RowFilter<K>` is derived from `(typeof TABLES)[K]['_']['columns']`, so the caller may name only the columns that table actually has and a typo is `TS2353` rather than a run-time surprise. **Prototyped and type-checked before this plan was written.**

- **The `SQL` shape is REFUSED and what it would have cost is stated.** It hands every call site the ability to write any predicate, which is the surface [ADR-008](../decisions/ADR-008.md) scoped this wrapper to bound and [ADR-102](../decisions/ADR-102.md) section 5 named again about `executeSql`. A caller holding a legitimate handle could then write a predicate that reaches another identity's row, and the diff a reviewer reads would look like ordinary accessor use rather than like raw SQL.
- **The `byId(id)` shape is REFUSED on evidence rather than on taste.** `idempotency_keys`'s primary key is `key` ([`0017:103`](../../packages/db/migrations/0017_events_and_audit.sql)), `treasury_balances`'s is `(account_code, as_of)`, and **13 registered tables carry a composite primary key**. A `byId` accessor does not serve the table [ADR-109](../decisions/ADR-109.md) exists for, which is the first one it meets.

**RULING 2. AN ADDRESS MUST CONTAIN A DECLARED UNIQUE KEY. A FILTER NEED NOT, AND A FILTER MAY ONLY READ.**

- **A WRITE takes a `RowAddress<K>`:** a `RowFilter` whose named column set CONTAINS at least one primary key or unique constraint the schema declares. Checked at run time against Drizzle's own table config, so it is derived from the schema rather than restated. **An addressed write therefore names at most one row by construction rather than by the caller's care.**
- **A READ may take a plain `RowFilter<K>`**, and the argument is checkable rather than aesthetic: **a filtered read is a NARROWING of a read that already exists at the same authority**, so it grants no reach. `scopedTx.rows` already returns every row this identity owns and `systemTx.rows` already returns every row in the table; a conjunct can only remove rows from either. A filtered WRITE at non-unique columns is different in kind, because the unaddressed write is being removed and there is no wider method for it to narrow.
- **A `null` or `undefined` value in an address is REFUSED.** A unique key over a nullable column does not bound the row count when the predicate is `IS NULL`, and `col = NULL` matches nothing, so neither reading of a null is a row this accessor should write.
- **The address may not name the tenancy column on the scoped path.** [ADR-102](../decisions/ADR-102.md) clause 4 already rules the tenancy column is never the caller's to name in an insert's values or an update's `SET`; an address is the third place a caller could name it, and the handle supplies it there too. On `systemTx` and `firmTx` there is no handle-supplied scope to contradict, so an address there may name any column.

**RULING 3. THE TENANCY PREDICATE AND THE ADDRESS COMPOSE, AND THE WRONG SHAPE DOES NOT COMPILE.**

- `updateStatement` and `deleteStatement` stop accepting `SQL | undefined`. Their `where` becomes a BRANDED intersection with two disjoint members, `ScopedWritePredicate` and `UnscopedWritePredicate`, each with exactly one producer. **So `updateStatement(source, key, values, undefined)` does not compile, and neither does handing the scoped builder an unscoped predicate.** The brand is a type-only intersection and not a `unique symbol`, because [session 222](2026-08-26-session-222.md) measured that `declare const X: unique symbol` type-checks, satisfies every use and **erases** under `node --experimental-strip-types`.
- `scopedWritePredicate(key, identityId, address)` is `and(scopePredicate(key, identityId), addressPredicate(key, address))` and it is the only thing `scopedTx`'s writes call.
- **Asserted in both directions**: every scoped keyed write renders the tenancy predicate the matching read renders AND the address conjunct, over every `ScopedTableKey`; and a scoped keyed update naming a row belonging to another identity is watched returning zero rows rather than one.

**RULING 4. THE SIX UNADDRESSED WRITE METHODS ARE REMOVED.**

`ScopedTx.update`, `ScopedTx.delete`, `SystemTx.update`, `SystemTx.delete`, `FirmTx.update` and `FirmTx.delete` cease to exist. Nothing in the tree calls them (item 5 above), so this breaks no caller, and [ADR-042](../decisions/ADR-042.md)'s finding that a comment is not a control is why they are not left behind one. `rows` and `insert` stay on all three handles unchanged.

**A whole-table write at any authority is FORECLOSED**, named rather than left to be discovered, on [`job-queue.ts`](../../packages/queue/src/job-queue.ts)'s own rule that [ADR-102](../decisions/ADR-102.md) borrows twice: a primitive admitted before a caller exists is a primitive nobody can remove.

**RULING 5. `sqlExecutor`'s VOCABULARY DOES NOT MOVE.** The three needs [ADR-109](../decisions/ADR-109.md) clause 2 names -- a keyed read, a keyed status advance and a keyed stamp -- are served by this construction without raw SQL, so widening the list buys nothing and would spend the admission [ADR-102](../decisions/ADR-102.md) section 5 kept narrow. **What is still not expressible is named rather than implied**: `ON CONFLICT`, `ORDER BY`, `LIMIT` and `FOR UPDATE` have no shape here and each is a later diff with its own argument.
