### 3. `ingest_files` is `firm`, and the tenancy runs the other way

[`0013_ingest.sql`](../../packages/db/migrations/0013_ingest.sql). **A file is a DELIVERY and a delivery belongs to no identity.** One vendor file carries rows for every account that traded the session, and the table declares exactly **one** foreign key: `replaces_ingest_file_id`, which points at **itself**.

**The direction is the argument.** `fills.ingest_file_id`, `raw_ingest_rows.ingest_file_id` and `reconciliations.source_ingest_file_id` all point IN, and two of those three carry their own `account_id`. Nothing points out.

**The quarantine machine is why the grain is the file** (B4 #4, `INV-M2-01`): a file in `quarantined` has committed NO downstream rows, enforced by processing the whole file in one transaction. **At the moment this row matters most there is no account row anywhere that could reach it.**

### 4. `raw_ingest_rows` is the slice's real finding, and the wrong rule is GREEN

**The forward mistake is the one [ADR-094](../decisions/ADR-094.md) and [`scope.ts`](../../packages/db/src/scope.ts) already name.** `ingest_file_id uuid NOT NULL REFERENCES ingest_files(id)` is a `NOT NULL` FK that reads exactly like `daily_marks`' hop to `accounts`, and `ingest_files` is firm, so a `derived` rule through it compiles at every call site and throws on first read. **The bounded chain assertion catches it.**

**The REVERSE edge is worse and nothing in the package catches it.** `fills.raw_row_id bigint NOT NULL REFERENCES raw_ingest_rows(id)` is a declared foreign key in the direction `every derived rule names a foreign key the DDL actually declares` accepts as `reverse`. Seeded:

```ts
rawIngestRows: { class: 'derived', via: 'fills', localColumn: 'id',
                 foreignColumn: 'raw_row_id', traversal: 'semi-join', ... }
```

| Check | Result |
|---|---|
| `pnpm run typecheck` | **exit 0, zero `error TS`** |
| `vitest run packages/db/test/scoped-db.test.ts` | **108 passed (108). GREEN.** |
| the rendered predicate | `exists (select 1 from "fills" where ("fills"."raw_row_id" = "raw_ingest_rows"."id" and exists (select 1 from "accounts" where ("accounts"."id" = "fills"."account_id" and "accounts"."identity_id" = $1))))` |

It resolves, `raw_row_id` is correctly not a primary key so `semi-join` is the honest traversal, and the chain terminates at `accounts`. **It answers a DIFFERENT QUESTION: which raw rows produced a fill on one of this person's accounts, rather than whose raw row this is.** Only some raw rows become fills. An EOD balance row becomes a `daily_marks` input, an unparsed row becomes nothing, and **every row of a quarantined file becomes nothing by design** -- so the reading silently drops exactly the rows a dispute is argued from, which is the evidence [`0013`](../../packages/db/migrations/0013_ingest.sql) says the table exists to keep.

**This is [session 202](2026-08-25-session-202.md)'s `wallet_entries` finding on a different table and it was seeded rather than predicted.** `firm` is what is written, and the reason is in the rule's `why` so the next reader meets the argument rather than the conclusion.

### 8. Two types, one non-edit, and a gap that is not closed

**`payload_hash` and `sha256` are `bytea` and are declared as CUSTOM TYPES.** drizzle-orm 0.45.2's pg-core has no builtin; `text()` would compile, would satisfy the column-name comparison, and would be a wrong transcription of a digest column, which is the axis [ADR-094](../decisions/ADR-094.md) section 3 records this suite does not check. The two custom types already in the file were reused rather than redeclared.

**Two enums were added**: `provisioning_status` (six members, `confirmed_inferred` distinct rather than a synonym) and `ingest_file_status` (five). Both are transcribed from [`0001_extensions_and_enums.sql`](../../packages/db/migrations/0001_extensions_and_enums.sql). **The binding rule over `operation` and `status` -- `set_risk` may never reach `confirmed_inferred` -- is a table CHECK and stays the database's**; nothing here restates it as a type.

**ONE NON-EDIT IS REPORTED RATHER THAN MADE**, on [session 203](2026-08-25-session-203.md)'s precedent. Registering `ingest_files` and `raw_ingest_rows` satisfies [`schema.ts`](../../packages/db/src/schema.ts)'s header condition -- *a column carries `.references()` only when its `CREATE TABLE` body declares the FK inline and the target is one of this file's tables* -- for three columns that are not this slice's: `daily_marks.ingest_file_id` at `:606`, and `fills.ingest_file_id` and `fills.raw_row_id` at `:2915` and `:2917`. **All three carry a comment reading *"which is not one of this file's tables"*, and after this branch merges those three comments are wrong.** They are left alone: `.references()` is compared by nothing in this package, the comment is prose, and touching a table that is not mine is the tail-splice hazard tranche 1 paid for. **It is a two-line repair for whichever session next opens those declarations, and it is named here so it is a record rather than a discovery.**

**THE TYPE AND NULLABILITY AXIS IS ASSERTED NOWHERE**, now across 87 registered tables rather than 80. This session widens that gap by seven tables and closes none of it, and nothing written here implies otherwise.
