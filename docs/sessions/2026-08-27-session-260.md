### 2. THE SEGMENT IS `.ts` AND NOT `.tsx`, AND THAT IS A CONTROL DECISION

Next's default `pageExtensions` is `tsx, ts, jsx, js`, so a `page.ts` is a route exactly as a `page.tsx` is. **What differs is what watches the file.** Four checks in this repository are scoped to files ending `.ts` and none of them sees a `.tsx`, each read at source in this session:

| Control | Scope | What it would have stopped watching |
|---|---|---|
| `merit/no-raw-db-client` | [`eslint.config.js`](../../eslint.config.js), `apps/**/*.ts` | VG-4, on a trader-scoped surface |
| `merit/no-calendar-in-expiry-path` | [`eslint.config.js`](../../eslint.config.js), first two globs name `apps/**` payout paths and end `*.ts` | [ADR-042](../decisions/ADR-042.md). **This segment is inside that glob**, and it is why nothing here reads a clock: a hold deadline is a wall-clock instant the server quotes |
| [`test/inv-m4-01.test.ts`](../../apps/portal/test/inv-m4-01.test.ts) | walks `src/` for `.ts` | INV-M4-01's standing substitute for a lint rule that does not exist. **This is the screen it exists for** |
| [`test/surface.test.ts`](../../apps/portal/test/surface.test.ts) | walks `src/` for `.ts` | The no-network assertion |

**Choosing `.tsx` would have dropped all four on the one screen in this application where money is rendered, silently, by choosing a file extension.** That is weakening four gates to pass none of them, so the element trees are `createElement` and the decision is written into [`page.ts`](../../apps/portal/src/app/payouts/page.ts)'s header where the next author meets it.

**The conversion is a legitimate later change and it is not free.** [`test/payouts-segment.test.ts`](../../apps/portal/test/payouts-segment.test.ts) walks **`.ts` AND `.tsx`** under this directory and asserts all four properties plus three more, so a session that converts to JSX keeps them whether or not it remembers to widen the globs, and the conversion is a diff about syntax rather than a silent loss.

**It also cost nothing in the tsconfig.** `@types/react` type-checks under [`tsconfig.base.json`](../../tsconfig.base.json)'s `lib: ES2023` with `types: ["node"]`, measured before the first file was written, and `next build` did not rewrite [`apps/portal/tsconfig.json`](../../apps/portal/tsconfig.json). **So this segment enters `pnpm run typecheck` today**, through the app's own `src/**/*.ts` include, rather than waiting for 250 to add `jsx` and `.tsx`.

### 4. [ADR-148](../decisions/ADR-148.md): the count is twelve against ten

[`STATE_MACHINES:403`](../architecture/STATE_MACHINES.md)'s `G-ELIGIBLE` is a conjunction of **twelve** terms. [`API_CONTRACT:446`](../architecture/API_CONTRACT.md)'s eligibility response declares **ten** gates. **Two of the twelve have no member in the response**: `identities.status = 'active'`, which is [ADR-062](../decisions/ADR-062.md) section 1's own ruling, and `G-NO-IN-FLIGHT`.

So a `restricted` or `closed` identity, or an account with a request already in flight, receives `eligible: false` **with all ten rendered gates passing**, on the one endpoint whose own header calls it the differentiator that *"shows the whole rule"*. Both terms reach the trader as `identity_restricted` or `conflict` at [`API_CONTRACT:490`](../architecture/API_CONTRACT.md), **on submit**, which is `FM-M4-10`'s *"shown, never hit"* inverted.

**The entry rules the display half and refuses the contract half.** The screen renders a third verdict, `unexplained`, saying the answer arrived without its reason and that this is a gap in what the endpoint reports rather than a rule the trader missed. **It states no cause**, because the response does not carry one and a client that guessed would be inventing a fact on the one screen where a number becomes a money decision. Whether `gates` gains members is left to session 252, which owns the route, with three candidates costed.

**THE TWO WITNESSES ARE NOT EQUALLY LIVE AND THE ORDINARY ONE IS `G-NO-IN-FLIGHT`.** `grep -rn 'identities.status\|identityStatus' --include='*.ts' --include='*.mjs' apps/ packages/ scripts/` returns one enum declaration and one column default in [`schema.ts`](../../packages/db/src/schema.ts), one READ at [`checkout.ts:894`](../../apps/api/src/routes/checkout.ts), and **nothing that writes**. `G-ENFORCEMENT-CLOSE` is *"defined nowhere"* ([`STATE_MACHINES:353`](../architecture/STATE_MACHINES.md)). So the identity leg is unreachable in practice today and becomes reachable the day a writer lands. **`G-NO-IN-FLIGHT` has no such reprieve**: a trader with an outstanding request is the most common thing that happens on this screen, and it becomes reachable the moment `POST /accounts/:id/payout` exists.

**One finding was checked and deliberately NOT reported as a contradiction.** The response declares a `buffer` gate that `G-ELIGIBLE` does not name. Read at [`gates.ts:81`](../../packages/rules-engine/src/payout/gates.ts), `withdrawableCents` computes `balanceCents - sizeCents - funded.bufferCents` clamped at zero, so the guard's `withdrawable_cents > 0` already contains it and `buffer` is a **decomposition** of a term rather than a term the guard forgot.
