#### `M18-C`  the withdrawable balance at graduation, inside the engine

- **Objective.** Decide, then implement, whether the engine reports the surplus that survives graduation. **MEASURED this session by running it, not by reading it.** A CORE-50K account whose fifth settlement takes 50,000c of a 150,000c surplus returns:

  ```
  phase                    = graduated
  balanceCents             = 5200000n
  size + buffer            = 5100000n
  raw surplus              =  100000n
  state.withdrawableCents  =       0n
  withdrawableCents(state) =       0n
  events                   = [ 'payout.win_days_reset', 'account.graduated' ]
  ```

  The cause is an ordering: [`settle.ts:214`](../../packages/rules-engine/src/payout/settle.ts) sets `phase: graduated`, and `:218` then calls `withdrawableCents(withPhase, plan)`, whose first line at [`gates.ts:79`](../../packages/rules-engine/src/payout/gates.ts) is `if (state.phase !== 'funded') return 0n`. **So the number `INV-M18-05` must pay is not readable from the state graduation produces**, and [`rules-h-settlement.test.ts:279`](../../packages/rules-engine/test/rules-h-settlement.test.ts) pins the `0n`. **`GS-067` cannot show this and its own note says so**: its `withdrawable_cents: 0` sits on a balance of 5,100,000 against a size of 5,000,000 and a buffer of 100,000, so the note calls the field *"weak evidence for the closure"* and offers it as none. The run above is the case the fixture could not reach. The stake is [M01](../plans/M01-rules-engine.md) section 1.3 and `FM-16`: the number the trader is shown and the number they are paid come out of **one** function, and any terminal settlement computing the surplus elsewhere is a second one.
- **Fence.** `packages/rules-engine/src/payout/gates.ts`, `packages/rules-engine/src/payout/settle.ts`, `packages/rules-engine/src/types.ts`, `packages/rules-engine/test/rules-h-settlement.test.ts`, `docs/decisions/ADR-0NN.md`.
- **MONEY PATH: YES**, and it is the rules engine itself. **The four invariants, per this slice**: `RI-01` holds, because no dependency field is touched and the package keeps its absent `dependencies` key; `RI-07` holds, because the change is a phase test and integer arithmetic and reaches no Node builtin; `merit/engine-purity` holds, because every import stays relative (`./gates.js`, `../types.js`); `"types": []` holds, because no ambient declaration is needed. **A slice that finds itself wanting `process`, a date or a database has left this package's scope and is `M18-B`'s work, not this one's.**
