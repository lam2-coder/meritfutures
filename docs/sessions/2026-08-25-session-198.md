### 2. `integration_dispatches`, and where it parts from `psp_webhook_events`

**The brief's warning is the whole of this table's argument**: ask what identity the row is ABOUT, not which identity's action caused it. A dispatch exists because an event fired, and the event fired because somebody acted; **the row is the RECORD OF A DISCLOSURE about a person**, and that person is what [M10](../plans/M10-integrations.md) section 4's owned endpoint reads it by. `GET /admin/identities/:identityId/disclosures` is *"every field ever sent about this identity, per vendor"*, and [`0018`](../../packages/db/migrations/0018_integrations.sql) carries a partial index for exactly that read.

**`nullable: true` IS `ledger_accounts`' SHAPE AND THE DDL STATES THE REQUIREMENT IN THE DIRECTION THAT DECIDES IT.** The column's own comment reads *"Nullable because not every dispatch is about a person, and the ones that are not must not be findable by an identity search that returns them anyway."* Filtering `identity_id = $1` excludes them without a second predicate, because SQL NULL never equals anything, which is [`scoped-db.ts`](../../packages/db/src/scoped-db.ts)`:85`'s stated reason for not adding `IS NOT NULL`.

**THE NEAREST REGISTERED ROW IS `psp_webhook_events` AND IT WAS READ BEFORE THIS TABLE WAS CLASSIFIED.** [Session 190](2026-08-25-session-190.md) made it **`firm`**, and the load-bearing half of its `why` is temporal rather than structural: `purchase_id` is nullable **and written late**, bound by the handler during processing, so a rule through it would make a row's tenancy *"a function of whether a job has run yet, the same event belonging to nobody while it is `out_of_order_deferred` and to somebody once it is `applied`"*. **That ruling was taken as it stands and is not re-argued here.**

**`integration_dispatches.identity_id` does not have that property, and the check is the status vocabulary.** `status` is CHECKed to `queued`, `sent`, `failed` and `dropped_by_guard`; **none of the four is a binding step**. What moves across a retry is `attempts`, `response_code` and `dispatched_at`, under `integration_dispatches_idempotency_uq` on `(integration, idempotency_key)`, and `integration_dispatches_sent_has_timestamp` is the only CHECK that ties a status to another column. The identity a dispatch is about is decided when the row is written, so the class does not answer *whose row is this* differently before and after a re-drive.

**`event_id` IS NOT THE SCOPE AND IS NOT EVEN A CANDIDATE.** It reaches `events`, which is Merit's own fact rather than the disclosure of it, and `events` is unregistered besides, so a `derived` rule naming it **would not compile**. The column is transcribed alone with no `.references()`, on [`schema.ts`](../../packages/db/src/schema.ts)'s own stated rule that a `.references()` is carried only when the target is one of that file's tables.

### 3. `support_context_views`, and why there was no second column to choose between

**This is the table the brief's two-identity-column refusal would have applied to if the DDL had written the agent side as a reference, and it does not.** `agent_ref text NOT NULL` is an actor string declaring no foreign key, so there is nothing a predicate could walk and nothing to choose between; the one identity column the database declares here is `identity_id uuid NOT NULL REFERENCES identities(id) ON DELETE RESTRICT`.

**Had it been a `users` reference the answer would still be the subject**, because that is `impersonation_sessions`' ruling one surface out: [`scope.ts`](../../packages/db/src/scope.ts)'s own header names `admin_user_id` as a trap reaching THE ADMIN'S identity rather than the subject's, and [session 191](2026-08-25-session-191.md) registered the table by `subject_identity_id`. **A support read is the same act through a different door**: outside the admin origin's IP allowlist and hardware-key SSO, which is why `AS-M10-01` calls an unaudited one an unmonitored back door into the crown jewel and why [dossier item 9](../../research/ADVERSARY_DOSSIER.md) is social engineering through support.

**Registering it makes it readable and nothing else.** `fields_returned` records what was RETURNED rather than what was requested, and **per-agent breadth monitoring -- the control `FM-M10-07` actually names -- is a property of the read path that no scope rule enforces.** Nothing here implies otherwise.
