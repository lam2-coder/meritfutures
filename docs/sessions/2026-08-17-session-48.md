- **Landmines:**

  - **THE RULING IS THAT A NAMED EXCEPTION IS NOT THE THING "NO EXCEPTION" FORBIDS.** `INV-06`'s clause exists to prevent **unstated** exceptions, and a single named, cited, testable one is the opposite of what it guards against. The alternative, scoping `INV-06` per `(account, phase)`, was rejected because it **makes the invariant true by redefining its domain**: the floor still falls on the pass day, by at least the 260,000c between the locked floor and the funded one and by 400,000c on `GS-019`'s own day, and every future reader has to reconstruct why the invariant no longer speaks to it. [ADR-014](../decisions/ADR-014.md) does not conflict: its permanent lock is about **settlement** never resetting the floor, `R-31` is a **phase transition**, and the balance falls to `size_cents` in the same step so no loss room narrows.

  - **THE EXCEPTION IS PINNED, NOT EXCUSED, AND THAT IS WHAT MAKES THE ADR EXECUTABLE.** A property that merely **skipped** the pass day would accept any floor at all there, which is precisely the unstated exception the clause forbids. So on the one step the exception covers, `RE-P-01`'s assertion gets **stricter**: `>=` becomes `===`, against `size_cents - funded drawdown_cents`. `CI-02/engine-RE-P-01-exception` seeds a reset landing **one cent low** and is watched failing on it, and **no other check in the repository catches that mutant**: `DO-7`'s tripwire compares within one day's trail-then-lock and never spans the reset, deliberately.

  - **THE GENERATOR IS TOLD NOTHING ABOUT PHASES.** `daySequenceArbitrary` draws marks, gaps, halted sessions and adjustments; it does not know what an eval pass is and cannot aim at one. The exception is recognised from the **engine's own event stream**: the step that emits `phase.passed` is the step it applies to. A generator that knew where the exception landed would make the property a restatement of the generator. The reachability block measures that a pass is reached anyway, and that **a pass is watched LOWERING the floor**, without which `if (step.passed) continue` would be excusing nothing.

  - **A MODULE-LEVEL SAMPLING PASS MADE THE FIRST MUTANT SCORE `FAILED OFF-TARGET`, AND THE HARNESS IS WHAT FOUND IT.** The reachability pass was written at module level, copying `day-sequence.property.test.ts`, which is right to do it there because its generator calls no engine code. This one **folds**, so `R-14`'s tripwire can throw inside it, and at module level that throw lands during **collection**: vitest reported `0 test` for the file and every test carrying `RE-P-01` in its name never ran. The needle was absent, `falsify-ci.mjs` scored it off-target and printed "a gate that fails for a reason nobody planted proves nothing". Moved into `beforeAll`. **The property was green throughout; only the falsification run could see this.**

  - **THE MONOTONE MUTANT MOVED FROM `floor.ts` TO `advance.ts` FOR THE SAME REASON THE EXCEPTION MUTANT EXISTS.** Seeded inside `advanceFloor`, a decrease is caught by the tripwire **throwing** rather than by the property **asserting**, so the case would have proved the tripwire works and said nothing about `RE-P-01`. It now writes `R-12`'s account-open expression where `DO-7`'s outcome belongs, one line after `advanceFloor` returns, where the tripwire cannot see it.

  - **THE FOLD ENDS THE DAY AFTER A PASS, AND THAT IS `DO-3` WORKING.** The generator chains `opening(d) = closing(d-1) + adjustment(d)`; `R-31` resets the balance to `size_cents`, so the next mark opens where the **eval** phase left off and `INV-18` refuses it. A generated sequence therefore contributes **at most one pass**, and the pass day itself is folded in full. It is asserted rather than left implicit, so a future change that makes the post-pass day foldable is a red test rather than a silent widening of coverage.

  - **`RE-P-01`'s SETTLEMENT CLAUSE IS COVERED WITHOUT THE SETTLEMENT GENERATOR THAT DOES NOT EXIST.** P2 section 5's arbitrary settlement generator needs payout eligibility, which needs the engine. It is not required here: `INV-18` compares the opening balance against the **pre-settlement** balance plus `adjustment_cents` (`advance.ts` `DO-3`), and `SD-01` puts the settled withdrawal in exactly that column, so a mark the generator **already draws** with a negative adjustment is the day-level shape of a settlement. Pairing it with a `SettlementFact` whose `approvedCents` is that adjustment negated produces a settlement day whose arithmetic closes, and `R-19` is what makes the floor's answer across it interesting.

  - **THE FIRST LOCK REACHABILITY CHECK COUNTED A LITERAL AND FAILED ON EVERY SEED.** It asserted the floor equalled `floor_lock_floor_at_cents` (5,010,000c). Section 3.4's floor at the lock is `max(trailed, locked)`, so on any day that **jumps past** the 260,000c trigger the floor is the trailed value and the literal never appears. Counting the literal measured "the lock engaged exactly on its trigger", which is the one case `CV-12` makes uninteresting. It now reads `floorLocked` off the state.

  - **A FALSIFICATION RUN MEASURED ON A TREE I WAS EDITING IS NOT A MEASUREMENT, AND THE HARNESS SAID SO.** The second run reported **33 of 34** and printed "THE HARNESS CHANGED THE TREE", because documents were being edited in the same working tree while it ran: `falsify-ci.mjs` snapshots `git status` before and after and compares. Its own diagnosis was right and the count was not a fact about the engine. **The clean, uninterrupted run is 34 of 34**, and that is the number recorded. The lesson is the harness's, not a new one: it copies or restores the working tree because "the working tree is what CI and the founder actually read", and a second writer inside that window invalidates the run.

### What batch 4 did about ADR-048, and what it deliberately did not do

**The polarity flip was not wired and the citations were.** [STATE.md](../STATE.md) already names the fixture-wiring session that owns the derivation, and it owns something that has to land first: `diffEndState` compares with `Object.is`, expectations are JSON numbers, and **`Object.is(4750000, 4750000n)` is `false`**. Flipping polarity before that conversion would turn every `direct` fixture red on a comparison rather than on a rule, which is the failure mode ADR-048's own case table does not cover because it assumes the loader can already fold the engine.

So each of the four fixtures **cites only `R-nn` identifiers that resolve in [M01 section 3.5](../plans/M01-rules-engine.md)**, states in its header the polarity that derivation yields, and **names any rule it deliberately did not cite**. All four derive to `direct`. **The next free loader rule number is `L-13`**, which the rule table skips and which the citation rule should take.

### One thing checked rather than assumed, and it changed a paragraph

**The claim "every M1-owned scenario is now accounted for" was written, then checked, then corrected.** The first draft of the held-back table named GS-036 and GS-041 as M1-owned and missed GS-057, GS-058, GS-059, GS-062, GS-141 and GS-241 entirely. **Six missing and two wrong, in a sentence whose whole content was completeness.** It was found by expanding the ownership index's M1 ranges and the table's own ranges into sets and differencing them, which took one script and would not have survived another reading of the prose. The corpus's own lesson applies to its documentation as exactly as it applies to its counts: **prefer a mechanical check to a more careful reader.**
