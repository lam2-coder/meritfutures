- **Landmines:**
  - **THE TWO MODES ARE TWO VIEWS OF ONE PATH, AND THAT IS THE WHOLE DESIGN.** `session.ts` already said it: high and low are max and min over the waypoints, and file mode summarises the path into two numbers. So `stream.ts` **draws nothing and re-derives no balance**; it reads waypoints `simulate` already produced. **A streaming mode that re-simulated from the seed would produce a plausible path agreeing with the file about nothing in particular**, and the two would drift the first time either changed.
  - **The equivalence test compares the fold to the RENDERED CSV, not to `SimDay`.** Both are in-memory objects from one `simulate` call, so comparing them would assert that the run equals itself. Parsing the file back is what makes it an assertion about the boundary `INV-M2-11` cares about.
  - **`LiveAccountTick.indicative` is a required `true` literal rather than an optional flag**, so a consumer cannot construct or destructure a tick without meeting the word. **This file cannot enforce ADR-020's hard rule and says so**: the boundary is a database grant (`C-26`) and a consumer that never reaches for the engine. What a producer can do is refuse to be mistaken for the authoritative path.
  - **`sequence` is per account per day and does not renumber under delivery order.** ADR-020 rule 3 makes feed loss first-class, and a consumer detects it by the ordinal. An ordinal that renumbered under `time` would make gap detection an artifact of delivery rather than a property of the feed.
  - **`STREAM_MODE_VENDOR_ASSUMPTIONS` is separate from the file-mode list on purpose.** A file-mode row moving changes a column or a format; **`V-M2-16` moving decides whether tier 2 exists at all.** Merging them would make "what does the simulator assume" answerable and "what does the LIVE layer assume" unanswerable. The closure check in `vendor-assumptions.test.ts` runs over the union, so no row can escape classification.
  - **The `time` order's tiebreak is population index, and that is load bearing.** Two accounts whose waypoints land on the same second are ordered by their position in the population, which is the key `rng.ts` draws against, so **adding an account to the end of a population cannot reorder the ticks of the accounts before it**. A timestamp-only sort would have been unstable exactly where the file mode is stable.

### Two defects the tests caught, both mine, and both the same class

**The CSV parser hardcoded CRLF against a declared LF quirk.** The whole file arrived as one line and the header comparison reported 152 fields against 18. It reads `DECLARED_CSV_QUIRKS.lineEnding` now. **A test that restates a renderer's constant is a second source for that constant**, and it drifts the same way every other duplicated value in this corpus has.

**Sampling stopped up to one interval short of the close.** A fixed cadence starting at the first tick generally does not land on the last one, so the polled feed held a stale number through the close. That is ADR-020 rule 3's named failure precisely: "a live surface that silently freezes at its last value ... looks exactly like a quiet market" — and it would have frozen at the moment the number matters most. `sampleTicks` now always delivers the close, **stated as a decision in the function's own comment rather than left to the arithmetic**, because the alternative was quietly changing a loop bound to make a test pass.

### What the seam assumption was checked against, rather than assumed

The equivalence rests on the last waypoint equalling `closingBalanceCents`. `session.ts` states the high/low relationship explicitly and **does not state that one**, so it was executed rather than read: across the canonical run's **24 account-days, including both liquidations, zero mismatches and no empty waypoint list**. The probe was deleted once it had answered; the assertion that outlives it is the field-by-field comparison against the rendered file, which fails if the relationship ever stops holding.

### What is NOT here

**No consumer, no cache, no WebSocket.** ADR-020's tier 2 names a live cache and a push to clients; this is the producer only. **No `PlatformAdapter.streamLive` implementation** either: M02 section 3.5 adds that signature to the interface, and the simulator deliberately does not implement `PlatformAdapter` at all, which is file mode's boundary and is unchanged by this session.
