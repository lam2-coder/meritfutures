### What the word "exists" was guarding, which is the only reason a seventh term looked necessary

`outside-loader-boundary`'s row-condition reads *"The code the assertion runs against **exists** and lives outside `@merit/rules-engine`"*. Three things in [ADR-072](../decisions/ADR-072.md) itself say that word is a guard rather than a condition.

1. **W1's own check column is implementation-independent**: *"A symbol in `apps/worker` or `packages/rithmic` fails W1 **whether or not it is implemented**."* [Section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) quotes that same sentence as W1's operative reading.
2. **A term names which condition fails and by what mechanism.** The condition is W1 and the mechanism is the loader import boundary, and both are true of these two rows exactly and permanently.
3. **The word separates the term from `no-module-code`, refused BY NAME**, and the refusal is scoped in its own sentence to *"the 229 rows it would have covered"*.

**[ADR-048](../decisions/ADR-048.md) is what makes that refusal correct for those rows and inapplicable to these two.** Inversion is polarity over the rule identifiers a fixture cites. A row whose expectation is an exit code cites no rule, loads nothing, derives nothing and has no polarity. **So the test that separates the two terms is not *"does the code exist"*, which is the refused term's test, but *"would a fixture format for this module, if one existed, discharge this row?"*** Yes for the 227; no for these two, and no for any format anyone could write.
