### 3. The obstacle that decided the shape of the diff

The ratchet at `payouts.test.ts` is a source-reading case, and a source-reading case cannot be satisfied by a move. Its two assertions name the file.

**The block comment above it is what made the call possible**, because it states the purpose rather than only the rule: the alternative to one statement of the split *"is two of them ... A session that 'finished' ADR-176 by moving `lt01` out **and letting each door write its own** goes red on the second case."*

**The clause after "and" is the property.** One statement of the split in this repository. A move where both doors import it back preserves that; two doors each transcribing it destroys it. So the letter fails and the purpose survives, and **the reason the letter cannot survive is the row's own premise**: a declaration pinned inside `apps/api` is one `apps/worker` must reach illegally or transcribe a second time, which is the hazard the pin exists to prevent.

**Deleting the two assertions was refused.** They are restated as a count over three files, and [ADR-317](../decisions/ADR-317.md) section 3 carries a row-by-row table of what each version fires on, including the two rows where **the old pair was blind and the new case is not**: a second `lt01` inside `packages/ledger`, and a second one inside `payouts.ts` beside the first.

### 4. The choice on `PayoutMoneyError`, and why the tidier answer lost

A package may not import from an app, so the class could not stay in `payouts.ts` and be thrown from the new home. It is thrown at two sites with two different concerns: `centsToJson`, a JSON boundary, and `lt01`'s `INV-M5-03` refusal, ledger arithmetic.

**The measurement is that nothing imports it and nothing catches it**, and `packages/ledger` declares no error class at all, throwing bare `Error`, `TypeError` and `RangeError`. On those facts the tidy answer is obvious: leave the class where it is for the JSON boundary and let the ledger throw in its own style.

**It lost on one word in the row.** Code motion with **no behaviour change**. A class and its `name` are observable on a thrown value whether or not anything reads them today, and "nothing catches it" is a fact about this tree at this moment rather than a licence. **Taking a tidiness ruling inside a motion ruled to change nothing is how a motion stops being one.** So the class moved unrenamed, `payouts.ts` re-exports it, and the awkwardness is written into the class's own docblock with the later ruling named as available.

### 5. Where this session is most likely wrong

1. **The restatement in section 3.** A session that rewrites a gate written to stop it is grading its own paper. The check offered is the table in [ADR-317](../decisions/ADR-317.md) section 3, which is falsifiable row by row; if one row shows the old pair firing where the new case does not, the restatement is a weakening and should be rejected on that row.
2. **The `PayoutMoneyError` choice.** A founder who reads "no behaviour change" as "no OBSERVED behaviour change" takes the other candidate. The entry says so in those terms rather than defending itself.
3. **The census widening in `packages/ledger/test/lt06-approval-builder.test.ts`.** It belongs to another row and this session had the motive to make it green cheaply. The check is that the predicate is byte-identical; only the expected population changed, and one assertion was added that pins `LT-06` harder than the original did.
