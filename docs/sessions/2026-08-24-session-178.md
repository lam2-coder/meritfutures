### ADR-091 is unsigned on purpose, and the reason is a distinction worth keeping

Every clause signed in this project so far has been **checkable against the tree as it stands**. [ADR-091](../decisions/ADR-091.md)'s is executable SQL whose own text says **every conjunct is `false` on the tree as merged today**. That is not a defect: it is an **acceptance test for the superseding migration the ruling specifies**, and writing it that way is better than prose. But it means there is **nothing to execute**, and a signature that recorded "verified by execution" would be describing a check that did not happen.

> **A ruling whose clause is about the future is a different object from a ruling whose clause is about the present, and the signature cannot pretend otherwise.** [ADR-076](../decisions/ADR-076.md) was withheld because its check was run and failed. This one is withheld because its check **cannot be run yet**. Both are refusals to sign something unverified; only the second is about timing.

**What it needs is a decision, not a probe.** ADR-091 rules that analytics **is granted `rule_states`**, on the argument that denying it **forces the very attack the denial cites**. That is a security judgment, and the founder is the one to make it.
