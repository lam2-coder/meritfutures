#### 2. The shape: a machine, and seven computations it drives

**The machine is definition-driven and the arithmetic is code, because `statistic_definitions.numerator_spec` is `text`.** A prose spec cannot be executed, so the code carries a computation per `stat_code` and the definition row carries the policy: the version, the window, the grain, the declared measures, and `min_sample`. The two must agree, so **the machine asserts the definition row's `measures` against the code's declared set and halts on disagreement**, which is the mechanical check `CLAUDE.md` asks for in place of a bigger model.

| File | What lands in it |
|---|---|
| [`batch/ports.ts`](../../apps/worker/src/batch/ports.ts) | **Type-only, as it is today.** The statistic vocabulary as string unions, the five closed-session FACT shapes, `StatisticDefinitionRow`, `PublishedStatisticRow`, `StatisticsReadPort`, `StatisticsWritePort`, `StatisticsPorts` |
| [`batch/statistics.ts`](../../apps/worker/src/batch/statistics.ts) (new) | The runtime vocabulary, the window resolution against `CalendarSlice`, the seven computations, the integer arithmetic with its rounding stated, `inputDigest`, and `runStatisticsRun` |
| [`test/statistics.test.ts`](../../apps/worker/test/statistics.test.ts) (new) | Including the approval line: two runs over one closed window, one digest, ONE ROW |

**The read port declares closed-session facts and nothing else, which is `FM-M12-08`'s stated control** (*"the stats worker holds no read grant on the live cache ... structurally prevented"*) expressed as a type: there is no port through which the indicative tier could arrive, so `INV-M12-01` holds by construction rather than by an application check that could be removed.

#### 3. `input_digest`, which is `ADR-122` and is the hard part

> **The digest is taken over the computation's OWN ARGUMENT, not over a description of the query.**

That single sentence is the ruling. A digest built from a hand-written list of "what we read" can omit a field the arithmetic uses, and then two genuinely different computations carry one digest and the reproduction claim is false in the direction nobody checks. Taking it over the `StatisticInputs` value that is handed to the computation makes the omission unexpressible: anything the arithmetic can see is in the digest, because it is the same value.

**What it covers:** a domain-separated header with a format version; `stat_code` and `definition_version`; the definition row's own content as read, including both prose specs and the exclusions, so an edited definition at an unchanged version changes the digest (`INV-M12-07`); the window's three days; the grain key; and every input fact for that cell, framed field by field, in a total order the machine imposes so the port's read order cannot move it.

**What it deliberately EXCLUDES, each with its reason:**

| Excluded | Why |
|---|---|
| **The value, the numerator, the denominator and the sample size** | They are the OUTPUT. A digest covering its own answer cannot distinguish "different inputs" from "different arithmetic", and the second is the failure worth catching. **Two runs whose digests match and whose values differ is an engine regression**, and it is loud only because the value is outside |
| **`measure`** | `ST-04`'s mean and median are computed from ONE input set. Two rows carrying one digest is the pair's reproducibility stated, not a collision |
| **`computed_at`, `id`, `created_at`** | The clock and the identities the database assigns. A digest that moved every night would claim every window was a different window |
| **The port's read order** | Defeated by sorting, because a reproduction claim that depends on which rows Postgres returned first is not a reproduction claim |

**What it CANNOT cover, named rather than widened:** the build that computed it. `published_statistics` has no `engine_version` column (fact 4) and no migration is in this fence, so a digest cannot carry the code's identity into the row. Folding the worker version into the digest bytes was considered and refused: it would make the digest change on every deploy, conflating a code change with an input change and destroying the one property the exclusion above buys.

**What a reader may therefore conclude from two matching digests:** that both runs read the **same definition over the same window and the same input facts**. Not that they produced the same number, and not that they ran the same code. Both limits are stated on the method page rather than left for a reader to discover.

#### 4. Immutability: the database refuses, and the code does not decline

Per the dispatch, checked before writing an application check. Fact 2 above is the answer, so:

- The write port carries `publishRun(rows)` and **no update verb and no delete verb**. Not because an application check forbids it, but because [ADR-112](../decisions/ADR-112.md) removed the words from the accessor and `0026` revoked the grants.
- **The machine does not read the published series to see whether a window was already published, and does not skip it.** It computes and it writes; the second run's insert meets `published_statistics_window_uq` and is refused by the database. That is "one row rather than two" with the refusal where it belongs, and an application pre-check would be a second control that can drift from the first.
- The run is ONE call carrying every row, because `STAT-C1` is deferred (fact 3).

#### 5. The integer arithmetic, and the three rounding decisions `ADR-031` says are the publisher's

No floats. Cents and durations are `bigint`, counts are `number` at the `sample_size` boundary because the column is `integer`, and every published figure is `bigint` with its unit.

| Decision | Ruling |
|---|---|
| **A rate to basis points** | `(numerator * 20000n + denominator) / (2n * denominator)`, integer division. Round to nearest, ties upward, over non-negative operands. Truncation was refused: it understates every rate systematically, and an unflattering bias is still a bias |
| **A mean to cents** | The same rounding on `sum / count`. At most one cent, stated rather than absorbed |
| **`median` versus `p50`** | They are DIFFERENT MEASURES in the enum and they are computed differently. `median` is the ordered middle, averaging the two middle observations on an even count, which is `ST-04`'s own wording (*"the ordered middle"*). `p50` and `p95` are **nearest-rank with no interpolation**: the observation at `ceil(p * N / 100)`, 1-indexed, which needs no division and invents no value that nobody was paid |
| **A ratio with a zero denominator** | **HALT.** Not zero and not a suppression. Every ratio statistic carries a `min_sample` of at least 50 by ruling, so this is reachable only from a definition row that declares a floor permitting an undefined figure, and that is a definition error rather than an empty window |

#### 6. Two things the corpus does not rule, named rather than invented

1. **`INV-M12-06`'s k-anonymity floor has no number** (fact 9). What exists is `min_sample`, and every definition applies it **per published cell** in its own words (`ST-01`: *"250 completed evaluations per published cell"*; `ST-04`: *"50 settled payouts per cell"*). So the machine suppresses a cell below its `min_sample` and that floor does the k-anonymity job for six of the seven at a level far above any plausible k. **`ST-03` is the one it does not cover**, because its `min_sample` is ruled *"None"*; it is a lineup total over every identity, which is the grain least able to identify anybody, and its surface publishes the count behind it. A separate k floor is not invented here.
2. **The `count` measure is in the enum and no definition declares it.** `G-2`'s open count and `ST-02`'s still-funded count are published *"separately"*, which means their own `stat_code` and their own definition row, and neither exists. Named as owed.

#### 7. What is deliberately NOT built, and the reason for each

- **[`nightly.ts`](../../apps/worker/src/batch/nightly.ts) is in the fence and is expected to need no change.** [CRON_INVENTORY](../ops/runbooks/CRON_INVENTORY.md) rows the statistics run as its OWN scheduled job at 08:00 CT with its own dead-man switch, separately from the nightly batch at 06:00 and the replay self-audit at 07:00. Folding the machine into `runNightlyBatch` would collapse three switches into one, which is the failure that page exists for, and it is [ADR-119](../decisions/ADR-119.md)'s own reasoning about a leg folded into another job: it can neither go red on its own nor be read on its own.
- **No migration.** `published_statistics` and `statistic_definitions` are landed and registered. If one turns out to be needed the session STOPS and reports it.
- **No definition rows are seeded.** Seeding `statistic_definitions` is a write to the money database from a path this fence does not hold, and `effective_from` is a publication policy with a founder sign-off attached.
- **[`apps/worker/src/index.ts`](../../apps/worker/src/index.ts) is OUTSIDE this fence**, and it is the file that re-exports `nightly.ts` and `replay.ts`. So the machine is reachable at `./batch/statistics.ts` and **not** through the package's `exports` map. Reported rather than reached for.

#### 8. The approval line, and why it is scoped to these files

**Two runs over the same closed window produce the same `input_digest`, and one row exists rather than two.** Executable, one checkable clause, and scoped to the two source files this session rules rather than to a package-wide test count, which the dispatch records as having drifted six times in this corpus while the ruling held.

Watched alongside it: a **field-perturbation sweep** over every field of every input fact, asserting each one moves the digest. That is the guard against the failure [ADR-102](../decisions/ADR-102.md) section 13 and [ADR-112](../decisions/ADR-112.md) section 8 both name: a reader that silently stops reading a field looks exactly like a reader finding nothing wrong.
