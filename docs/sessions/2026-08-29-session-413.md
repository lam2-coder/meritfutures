**Objective.** Rule and implement Merit's security response headers, so that
`INV-M6-02`'s origin separation and `INFRA:71`'s "even in principle" stop
resting on a header nothing in this repository sets.

**Outcome.** **All three headers exist on all four surfaces, every one is
asserted by a test, and twenty-five real documents were rendered under the
policy in a real browser before the claim was made.** The row's central premise
held exactly. One of its probes named one of two filenames the installed
framework reads, and the conclusion survives that correction.

### 2. The layer, and what it cost to rule it

**Cloudflare is ruled against as the ONLY layer, on [ADR-221](../decisions/ADR-221.md)
section 6's two grounds.** `INFRA` rules no origin lock anywhere, so a
direct-to-origin request bypasses the edge and would carry no policy at all;
and an edge rule is invisible to every gate, to `vitest` and to the `E2` read,
which is the "control cited and never installed" defect with the halves
swapped. **A Cloudflare transform duplicating these three is compatible with
everything ruled here and is not proposed**, because the edge configuration is
nobody's fence in this repository.

**And the origin is the only layer that can DERIVE the policy.** Its content is
a function of what the applications emit, and every census that produced it
lives here.

### 3. The CSP's content, and the census that produced each directive

Over `apps/{site,portal,admin}/src/**` and every document three real
`next build` runs produced: **`'use client'` 0 files**, so no client component
and no client-side `fetch` of Merit's own exists; **`next/link` 0 files**, so
every navigation is a document load; **`<img` and `next/image` 0**; **`<iframe`
0**; **external hosts in any built document 0**; **`<form` 1**, at
[`account-search.tsx:416`](../../apps/admin/src/app/search/account-search.tsx).

**Inline `<script>`: TWO IN EVERY DOCUMENT, WITHOUT EXCEPTION.** `next@16.3.2`
writes the React Flight payload from `use-flight-response.js` and
`stream-ops.node.js`: a **43 byte** bootstrap identical on every page, and a
per-document payload measured between **6,428 and 7,691 bytes**. Chromium
quoted two different `sha256-` values for the two scripts on one page, which is
why a hash list in a static header cannot cover them.

**Inline `<style>`: the framework's four built-in error documents in all three
apps**, plus `apps/portal`'s own three files. So `style-src 'unsafe-inline'` is
forced whether or not Merit writes a style.

### 4. The nonce was RUN, and it is the trap the row named

The installed framework's own guide says a nonce needs dynamic rendering. **That
was taken as a claim to test.** A `src/proxy.ts` written from it verbatim
registered (`ƒ Proxy (Middleware)` in the build output) and **left all eleven of
`apps/site`'s route entries prerendered**. The served response then carried a
fresh nonce in the header and **zero `nonce=` attributes in the markup**.
Chromium: **8 CSP violations**, six external chunks refused because
`'strict-dynamic'` disables host allowlisting and both inline scripts refused,
`self.__next_f` **undefined**, the page **completely dead**.

**The cost differs per app and that is why it is not one decision.** `apps/site`
is **11 of 11** route entries prerendered and [`M09:23`](../plans/M09-marketing-site.md)
calls it *"a fast statically generated Next.js application, served from the
edge"*, so the nonce there is an **M09 amendment** and not a code change.
`apps/portal` is **3 of 14** and `apps/admin` is **3 of 7**, and both are cheap.
**That is the registered next step and it is a session of its own**: a
`proxy.ts` per app plus a `connection()` per page, in two packages this fence
does not hold.

**A report-only phase is refused rather than deferred.** There is no collector
and none can be configured from this repository, so `report-to` has nowhere to
point. What replaces it is a written end condition.

### 5. `INV-M6-02`, made mechanical

The public surfaces share one policy, the console's differs in **`form-action`**
alone, and that difference is **derived** from the one form rather than chosen:
the console needs `'self'`, the public surfaces take `'none'`, which is strictly
tighter and denies a script injected into the portal a form submission to any
origin at all.

**THE ASSERTION THAT ACTUALLY DISCHARGES "EVEN IN PRINCIPLE" IS NOT THE
COMPARISON.** It is that **no source expression in any of the four policies
names a host or a scheme**. Every one is a quoted keyword, asserted by regex in
all four suites, so no policy CAN span two origins even if somebody later made
the strings identical, and [ADR-012](../decisions/ADR-012.md) holds by
construction rather than by care: there is no shape of edit to these files that
adds a hostname without turning a test red.

The two sibling configs are read **as text and never imported**, on ADR-221's
precedent, because `RI-04` refuses one deployable depending on another and a
cross-app import in a test is that dependency in a test's costume. Each app's
own config is **executed**, so the wiring is covered and not only the constant.

### 6. The `apps/api` half, and the hook order is the ruling in it

`default-src 'none'` with `base-uri`, `form-action` and `frame-ancestors`
spelled out, because **no CSP level falls those three back to `default-src`**
and a policy naming only `default-src 'none'` permits framing.

**The hook is registered BEFORE ADR-221's, and that is the ruling.** The CSRF
hook can END a request with `403`, so a header hook after it would leave the one
response class produced by a deliberate attack as the one class with no policy
on it. The suite asserts the three headers on a 200, the not-found path, a path
outside the base path, the error handler and **the CSRF refusal**, plus the
registration order in the source; both go red when the two `addHook` calls swap.
**`server.ts`'s CSRF comment read "FIRST" and is corrected in the same commit
rather than left as a sentence about a shape that changed.**

### 7. What was refused

`X-Frame-Options` (on ADR-221 section 3.1's own count: a second mechanism that
refuses the same set is a second copy of a control); a report-only phase;
`preload` on HSTS, which is irreversible on Merit's clock and is on the approval
line; `upgrade-insecure-requests` and `sandbox`, both unmeasured;
`Cross-Origin-Resource-Policy` and `Cross-Origin-Opener-Policy`, outside D2's
sentence; `poweredByHeader: false`, which is a removal rather than one of D2's
three; **any edit to `SECURITY.md` or `INFRA.md`**, because a response header
the caller satisfies nothing to receive is not the contract fact the row's
condition names, and because the six citations the audit flagged **become true
with no edit**; `MERIT_BUILD_MASTER_PROMPT.md`; and any migration, environment
variable or hostname. **`X-Content-Type-Options` is the one addition taken and
it is declared rather than smuggled in under D2's three words.**

### 9. Landmines

1. **`script-src 'unsafe-inline'` is a placeholder and not a control**, on all
   three UI surfaces. Nine directives in this policy are controls and one is
   not. `ADR-223` section 4.2 names three things that would end it and prices
   each.
2. **The policies were derived from what these apps emit TODAY.** No client
   component exists, so `connect-src 'self'` has never been exercised by a
   browser-initiated `fetch`; no image exists, so `img-src 'self'` has never
   refused anything; no design-system stylesheet exists, so `style-src` has
   never seen a `<link rel="stylesheet">`. The suites catch the two changes that
   would make a directive WRONG and **nothing catches the change that would make
   one INSUFFICIENT** except a page breaking.
3. **HSTS is a year with `includeSubDomains` and there is no subdomain inventory
   in this repository to check it against.** A subdomain that cannot serve
   HTTPS is unreachable rather than degraded, for a year.
4. **`grep "\.header('"` over `apps/api/src` will not find these headers**,
   because the hook iterates. The next audit's probe needs the file name.
5. **A row in `SECURITY.md`'s control catalogue is owed and was refused on the
   fence's own condition.** The catalogue is where a reader looks and it does
   not carry this control. **The `C-nn` number is deliberately NOT minted on
   this branch**: `CI-06/identifier-series` turned red the moment one was
   named, because nothing defines it, which is the gate saying the right thing
   about an identifier an entry cites and does not create.
