## 2026-08-17 - Session 49: the local demo, and the four things the first watched run surfaced (non-money)

- **Done:** **[`scripts/demo/`](../../scripts/demo/README.md) runs the seeded simulator through the engine and prints what happens**, in memory, with no database, no file written and **no dependency added** (VG-12): the entry is a `.mjs` shim registering a twenty-line resolve hook so Node's own type stripping can load the workspace's TypeScript sources. It seeds a population against **Core EOD at 50K** transcribed from [Appendix A.1](../plans/M01-rules-engine.md), folds `advanceDay` over each account, and prints balance, floor, high-water balance, win days, consistency, every gate with its have and its need, and eligibility. **`--seed` reproduces byte for byte**, asserted on the RENDERED STRING in `scripts/demo/test/determinism.test.ts`, which runs in the `unit` project. **Both sides are in the default run and are themselves asserted**: one account reaches eligibility ($1,022.50 at ordinal 1 of 5), one breaches with the platform's liquidation record as evidence, one **breaches a trailed floor the platform setpoint is nowhere near**. `pnpm run verify` green: **502 tests, 15 of 15 gates clean and dirty, 16 scope cases.** **`packages/rules-engine/src/` and `test/` are untouched**, per the session fence.
- **Next:** Unchanged and not this session's: the fixture-wiring session still owns the `bigint` comparison in `diffEndState`, the `L-13` citation rule, and [ADR-048](../decisions/ADR-048.md)'s polarity derivation. **Three of the four findings below want a ruling before they want code.**
- **Blockers:** **`DEP-M2-03`'s setpoint source is now a question with a number attached** (finding 1). `R-32`'s anchor and its authoritative column still block the `DayInput` amendment. The calendar transcription still blocks group A, and the demo works around it with a weekday sequence that says in three places it is not the CME calendar.
- **STATE.md is deliberately not edited.** Nothing about the post-FREEZE position moved: no rule landed, no fixture landed, no migration was written, and the build sequence is where session 48 left it. A STATE edit that recorded a demo would be a hand-maintained line that says nothing, which is the drift [ADR-034](../decisions/ADR-034.md) exists to end.
- **Landmines:**

  - **MERIT'S FLOOR TRAILS AND THE PLATFORM'S SETPOINT DOES NOT, AND THE DEMO PRINTS THE GAP IN CENTS.** `DEMOSWNG250002` locked its floor at 5,046,250c on 2026-11-16 and breached on 2026-11-19 at a low of 5,009,500c. **The setpoint was 4,750,000c, pushed once at provisioning, so the gap was 296,250c and the platform had no reason to act.** The breach therefore carries **no auto-liquidation record**, and that account closed the day **up 74,500c on its size** and was still breached. Every rule involved is working: `R-13` trails the floor, [ADR-014](../decisions/ADR-014.md) makes the lock permanent, the low is the breach comparison input (`0014`). But [DATA_CAPABILITIES](../../research/DATA_CAPABILITIES.md) section 1 names the EOD report's liquidation record as Merit's breach evidence, and **on this shape of breach there is nothing to cite**. How often M2 re-pushes the setpoint is an M02 question; this run makes the cost of "once, at provisioning" visible.

  - **A DISABLED CONSISTENCY RULE REPORTS AS SATISFIED RATHER THAN AS DISABLED.** `consistencyOk` returns `{ ok: true, skipped: false, bestDayShareBp: null }` when `cfg.enabled` is false, and its own header states that `skipped` **is not** `!enabled`. So Core EOD's `phase.passed` payload reads `consistency={satisfied=true skipped=false}` on a plan whose **eval consistency is disabled**. That is exactly the vocabulary `CV-19` fixed and which the same file quotes: a gate never evaluated must be "visibly disabled in the eligibility breakdown ... so no trader or support agent ever sees a gate that reads as satisfied when it was never evaluated". **The funded gate is enabled on all three v1 plans so nothing in the lineup renders wrong today**; the eval half of `R-28` is where it would surface, in an event payload M16 and M04 both read. **Not fixed here: the engine is another session's.**

  - **`EngineEvent` CANNOT BE NARROWED BY A CONSUMER.** `DayOutput.events` is `readonly EngineEvent[]` and `EngineEvent` is `{ type: string; tradingDay }`. The nine concrete events extend it and **no discriminated union is exported**, so a consumer wanting `PhasePassedEvent.resetFloorCents` must cast. The demo walks each event's own fields instead, which needs no cast, but a portal rendering one event type per screen will reach for one.

  - **THE `R-31` RESET IS A SEAM THE SIMULATOR CANNOT SEE, AND A NAIVE FOLD SHOWS NOTHING ELSE.** `advanceEvalProgression` sets `balanceCents: plan.sizeCents` on the pass day; the simulator carries its own balance and has no notion of a phase. So a single `simulate()` call folded straight through **refuses every funded account with `opening_mismatch` on the day after it passes**. The demo restarts the simulator at the day after the pass, which is what `INV-M2-07` says the platform does (`buildPopulation` already opens every account at exactly `size_cents`), rather than patching a balance the engine returned. **The restart changes no draw**: every `rng.ts` key is `(seed, accountRef, tradingDay, ...)` and none is the session's index.

  - **A BREACH DAY IS NEVER A TRADED DAY.** `DEMORISK500002` traded on 2026-11-02, was liquidated, breached, and its state carries `tradedDaysCount: 0`, because `DO-4` returns before `DO-6`. That is `R-25`'s ordering law working as written and it is worth knowing before someone reconciles a traded-day count against a fill count and finds them off by one on precisely the accounts that closed.

  - **THE DEMO PROVES NOTHING ABOUT THE CSV OR THE NORMALIZER, AND ITS README SAYS SO FIRST.** It calls `simulate()` and converts the day in memory, skipping the file. `INV-M2-11` is that simulator output and vendor output go through the same parser, and **that is exactly the seam this demo steps over**. Three other boundaries are stated in the same place: no settlement ever happens so `R-37` reports `skipped` on every row of every run, the context gates are constants so only the engine half of eligibility moves, and `R-04` is unexercised because the calendar has no halted session to offer.

  - **`scripts/demo` JOINED `vitest.config.ts`'s `SOURCES` RATHER THAN BECOMING A FIFTH PROJECT.** The projects map to CI stages and there is no demo stage; what the directory holds is a unit suite by every ordinary meaning of the word, so it belongs in CI-02 beside the others. `RI-03` reads the config as text and checks the four stage names are present, which they still are. **A test matched by no project does not run**, and a determinism claim nothing runs is a claim rather than a control. The root `typecheck` script names `scripts/demo` explicitly for the same reason: `pnpm -r` walks the workspace and this directory is deliberately not in it.
