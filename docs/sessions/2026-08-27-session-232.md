**THE SESSION TOKEN CARRIES ITS OWN IDENTITY, AND THAT IS A RULING RATHER THAN AN ENCODING.**
`sessionByToken` must find a row before any identity is known, which finding 5 says no door
serves. The token is minted as `<identityId>.<secret>` and the stored hash is over the WHOLE
string, so the identity in the cookie is a HINT the database is never asked to trust: a
rewritten prefix changes the hash and finds nothing, and a colliding hash is still refused by
the scope predicate, which is [ADR-112](../decisions/ADR-112.md)'s composition doing exactly
what it was built for. **The identity is not READ off the row; it is PROVED by the row
coming back.** It discloses nothing: `VerifyResponse.identity_id` and `Me.identity_id` both
already hand the client that value.

### LANDMINES

- **A parser with no minter.** `parseSessionToken` and `sessionTokenHash` exist and nothing
  mints. Whoever writes the minter must call `sessionTokenHash` on the WHOLE token and use
  `SESSION_TOKEN_SEPARATOR`; a minter that hashes only the secret compiles, passes every route
  test, and silently removes one of the two independent refusals in clause 2.
- **`finally { DB_ADMITTED.length = 0 }` was correct only while the list was empty.** It is a
  mutation that happened to agree with the shipped value, and it stopped agreeing today.
  `withDbAdmitted` restores what shipped. Anything else added to that file must use it.
- **`AuthBackendUnwired` now means two different absences** -- no backend at all, and a wired
  backend that cannot express one method -- and both are 503. The word is unchanged because it
  is exported and asserted on; the doc comment carries the distinction.
- **`readElevationFactor` is the whole of `C-27` on the way OUT.** A `value as ElevationFactor`
  there type-checks, satisfies every `@ts-expect-error` in the suite, and honours whatever the
  column holds.
- **`db-recorder.ts` cannot prove a predicate reaches one row.** Any case written against it
  that claims to is agreeing with its own fake.
- **A `falsify.mjs` near-miss case named after the ARTIFACT it bounds becomes uneditable the
  moment an ADR cites it**, and this register now carries TWO stranded that way:
  `fastify-near-miss` by [ADR-085](../decisions/ADR-085.md) and `scoped-db-near-miss` by
  [ADR-100](../decisions/ADR-100.md). Naming the next one after the SHAPE it refuses would
  leave it repointable. Reported at the site rather than repaired, because renaming an
  existing one is the edit the citation forbids.
- **Re-ruling a `VG` artifact is THREE files and not two.** `STRATEGY`'s cell, `VG_PROBES` in
  `gates.mjs`, and the `CI-06/vg-inventory` seed plus its scope case in `falsify.mjs`. Two of
  the three announce themselves loudly; the seed announces itself only because `falsify.mjs`
  requires a gate to FAIL rather than merely to run.
