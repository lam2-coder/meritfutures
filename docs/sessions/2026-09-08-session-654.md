### 1. The objective

Take [ADR-458](../decisions/ADR-458.md) section 11 item 2. That item says legs A and D of [`write-guard-set.mjs`](../../packages/tooling/checks/write-guard-set.mjs) find a write guard by the name `refuse[A-Z]`, that nine declarations honour the convention and nothing requires the tenth to, and that the price is _"a lint rule that no function in `scoped-db.ts` may `throw` outside a function matching the convention"_. The dispatch held the question open on purpose: whether the rule belongs in ESLint at all, whether that predicate is too strong, and whether a NAME is the right target. It required the population to be re-derived rather than taken, and named [ADR-450](../decisions/ADR-450.md)'s precedent as an available refusal.

### 3. What was derived

From the TypeScript AST over `scoped-db.ts` (4,718 lines) at `ddd171f5`: **9** functions matching `/^refuse[A-Z]/`, all top-level `function` declarations with no arrow, method or nested helper among them; **81** throw STATEMENTS; **13** inside the guards, spread 1,1,1,1,1,2,3,1,2; **68** outside them across **24** distinct functions. `grep -c 'throw'` answers **93**, and the 12-site gap is entirely prose, so a rule built on the grep figure would have been built on a number 15 percent too large. ### 4. The verdict, which is BOTH halves

**The priced rule is refused** ([ADR-459](../decisions/ADR-459.md) section 3). It would be red on 68 sites on the tree it ships with, and those 68 are not repairable into it: a schema-drift assertion, a `RETURNING` read-back, a `throw cause` rethrow and a raw-SQL reason refusal are not write guards and would be worse named as ones. The only landing is a 24-name exemption, which [ADR-458](../decisions/ADR-458.md) section 5 already ruled on in a smaller form. **A narrower rule is built** (section 4): a named function that throws and returns nothing must match the convention, plus a vocabulary leg that reaches the two guards which return a value. Green over `packages/db/src` with **no exemption of any kind**. It went to ESLint rather than to a fifth checker leg because it asserts a property of one function decidable from its own syntax, which is what a lint rule is, while `write-guard-set.mjs` asserts a relation between named things; the fence is only the second reason, and that file belongs to PR #742.
