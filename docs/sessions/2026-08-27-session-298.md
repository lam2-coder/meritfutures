#### 4. What is built, and what is stopped

**All three rows are REGISTERED**, on `wallet.ts`'s recorded reason: *"The routes are REGISTERED
because the contract rows exist; a missing route answers 404 and reads as a contract Merit never
wrote."* What differs between them is how far the handler can go before it meets a refusal, and
each refusal is named at the line it stops.

- **`POST /admin/wallet/:identityId/spend-limit`** is COMPLETE. `wallet_spend_limits` is an
  APPEND at `(identity_id, effective_from)`; `set_by` comes from the session and never from the
  body; the precondition is re-read under the lock and answers `conflict`.
- **`POST /admin/wallet/:identityId/correct`** is complete through validation, dual control, the
  row lock, the precondition re-read and the `admin_actions` row. **The WRITE is stopped** on
  findings 4 to 7: four independent disagreements between the contract's body and `0038`'s
  constraints, none repairable from a route file.
- **`GET /admin/wallet/reconciliation`** is complete through the guard and the projection. **The
  READ is stopped** on finding 8, which is [ADR-157](../decisions/ADR-157.md)'s refusal arriving
  at the endpoint that entry predicted would meet it. **It is reported and not widened.**

#### 5. The shape every write follows, from `admin-payouts.ts`

1. `principal()`, then the role check. **Both BEFORE `operator()` opens a transaction**, so a
   `readonly` operator's 403 writes no `admin_actions` row and changes nothing. `INV-M5-23`'s
   shape, asserted by an EMPTY recorder rather than by a status code alone.
2. `lockAt` first, on `identities`, which is `INV-M20-01`'s per-identity lock at the authority
   this module holds.
3. **Re-read the precondition UNDER the lock**, else `conflict`.
4. **Capture the before-state into `admin_actions` BEFORE the mutation**, under the database's
   own column names, because `0017:82` refuses an admin action with no reason and that row may
   be the only durable record.
5. Mutate.
