## 2026-08-20 - Session 85: ADR-064, a session number is an allocation and not an identifier (non-money, but it is a registry and a ruling)

- **Done:** **[ADR-064](../decisions/ADR-064.md) rules the identity function this registry never had, and the merge it was owed is performed.** Identity is the pair `(log file, section heading)`, the heading taken verbatim including its `(money path)` marker; the index row's first cell is a **pointer to the file, not a key**. The renumber is **declined rather than defaulted into**, with the three reasons written out and the door left open for a session that supersedes this deliberately. [`docs/sessions/README.md`](README.md) goes from **236 lines, two delimiter rows and 213 body rows** to **one table of 121 rows over 83 keys**, which is exactly the 83 session files the merge read, and 122 over 84 once this entry lands. `CI06U_REGISTER`'s entry for the file goes **59 keys to 19**. **22 of 22 gates pass**, `CI-06n` among them; `falsify.mjs` green with **30 scope cases and 10 loader cases**; `pnpm vitest run` **939 pass, 42 skipped, 62 files**.
- **Next:** **Two controls are named in ADR-064 and neither is written.** `CI-06/session-index-matches-sections` is the one that matters, and it is the precondition for taking the register entry to zero. The `\d{2,}` widening in section 7 has a deadline the corpus will actually reach. `docs/sessions/ALLOCATION.md` is named, unwritten, and owned by the same session.
- **Blockers:** ADR-064 is `proposed` and unsigned. It rules the identity function of a registry every session writes to and declines a renumber of about thirty sessions, so it is E2's rather than a session's.
- **Landmines:**

  - **THE MEASUREMENT THAT DECIDED THE RULING IS 121 AGAINST 83, AND IT WAS NOT IN THE BRIEF.** The 83 session files the merge read hold **121 `##` sections**; the merged index carries **121 rows over 83 distinct first cells**. A registry with 121 entries and 83 keys does not have a key, and no argument about the convention was needed once that was counted. Everything else in this session followed from it.
  - **ONE ENTRY HAD ALREADY BEEN LOST AND EVERY GATE WAS GREEN.** [`2026-08-16-session-33.md`](2026-08-16-session-33.md) holds **four** sections and carried **three** rows. Its sections at `:70` and `:110` are two different sessions that both ran FOLD-02 session 4, and their headings differ **only** by the `(money path)` marker this index drops on the way to a row. Once dropped they rendered identically, one row was written for both, and the fourth session vanished. **`CI-06n` cannot see this class at all**: the file has a row, so the file is covered. It is the only such mismatch in 83 files, and it is the whole argument for `CI-06/session-index-matches-sections`.
  - **THE BRIEF SAID THE TWO-DIGIT SESSION CAP IN `gates.mjs` WAS LIFTED. IT IS NOT.** [`gates.mjs:218`](../../scripts/corpus/gates.mjs) still reads `session-\d{2}\.md`, and `git log -S` puts that expression in the ADR-043 split commit with no later change. At session 100 `CI-06n` builds `onDisk` from a predicate the file does not match **and** filters README rows through the same predicate, so the registry's only completeness gate goes silent in **both directions**, and the `onDisk.length === 0` sentinel does not trip because the other 83 still match. The corpus is at 88 allocated numbers. **This is the third session in this wave whose brief carried a premise the tree refuted, and checking it cost one grep.**
  - **NEITHER COPY OF THE INDEX WAS A SUPERSET, AND THE TWO NEVER DISAGREED.** Copy 1 alone held 60, 61, 62 and 64; copy 2 alone held 21 more. **All 58 keys they shared carried identical subject sets**, so the union had nothing for [ADR-061](../decisions/ADR-061.md)'s agreement test to answer. A repair that had reached for ADR-061's escalation path here would have found nothing to escalate.
  - **THE 19 THAT REMAIN ARE NOT AN EXEMPTION AND MUST NOT BECOME ONE.** The register's own rule is that it shrinks only. ADR-064 section 4 names the destination: the table's first column is a **dimension** rather than an identity, exactly as `From` is on a transition table, and it cannot reach `DIMENSION_HEADERS` today only because its header is **empty**. Header `Session` plus one `DIMENSION_HEADERS` entry takes it to zero **without renumbering anything**. That is two lines and it is deliberately not taken here: the exemption is corpus-wide and the control that makes it safe is unwritten. **Whoever writes the gate lands both.**
  - **THE FALSIFICATION SEED HAD OUTGROWN THREE ANCHORS AND THE THIRD WAS UNFIXABLE BY DERIVATION.** `CI-06u/a-repaired-register-entry-is-itself-a-finding` anchored on a live register entry, which ties the gate's own falsification to the defect the gate exists to remove: **the wave's success is what ends the case.** Measured before rewriting it, by emptying the register on today's tree: `gates.mjs check` reports `CI-06u` failing with 130 findings and `falsify.mjs` reports 5 problems, the first being `SEED IS STALE`. The seed now builds its own two-rows-under-one-key table and registers it in the **seeded copy**, and the fix was verified the same way: with `CI06U_REGISTER` emptied on this branch, the case still reports `in scope, failed` naming `seeded-register-fixture-key`. **A derived anchor cannot save a seed whose subject the corpus is allowed to delete; only a constructed one can.**
  - **THREE FILES OUTSIDE THIS FENCE ARE NOW STALE AND ARE NOT TOUCHED.** `ALLOCATION.md`'s `064` row stays unlinked, contrary to [ADR-065](../decisions/ADR-065.md) T3, which says the session that lands the artifact links the reservation; ADR-065 is itself unsigned. [STATE](../STATE.md):1806 says the register holds "97 known duplicate keys across 7 files" and the gate now prints 19 across 1. [STRATEGY](../testing/STRATEGY.md)'s `CI-06u` row still says the session index "carries the whole session index twice". All three are recorded in ADR-064's consequences.
