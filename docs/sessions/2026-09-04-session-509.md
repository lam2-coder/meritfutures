### 3. How the body was produced, exactly

```
node scripts/db/assert_pgboss_schema_matches_library.mjs --emit
```

**It printed, on stderr:** `pg-boss@12.28.0 (schema version 38) resolved from packages/queue/package.json` and `QUEUE_SCHEMA = "pgboss" read from packages/queue/src/pg-boss-queue.ts`. **On stdout: 415 newline-terminated lines, 17452 bytes**, ending `COMMIT;` followed by four spaces and no trailing newline. That is what sits between the two markers, unmodified.

**The same script with no argument is the reader**, and it is the mechanical assertion `CLAUDE.md` asks for in place of a bigger model. It asserts the header's `EMITTED-BY` line names the version, the schema and the pg-boss schema version the **installed** library reports; that the quoted region is byte-identical to what that library emits, naming the first differing line when it is not; and that `QUEUE_SCHEMA` still has exactly one declaration site.

**THE NEXT PERSON TO UPGRADE pg-boss NEEDS TWO SENTENCES AND THEY ARE HERE.** The bump turns that assertion red. The remedy is a NEW numbered migration carrying `getMigrationPlans(schema, version)`'s output at the same standard of transcription, **never an edit to `0079`**, because a merged migration is sacred (constitution `E2`).

### 5. The probe, and what it is for

[`probe_pgboss_job_store.sql`](../../scripts/db/probe_pgboss_job_store.sql). **Three successes before the first rejection**, on [DELTA_MANIFEST](../../packages/db/DELTA_MANIFEST.md) section 13's discipline: this migration exists to make enqueueing POSSIBLE, and a schema refusing every write would satisfy all five rejections and still be useless.

| Case | What it holds |
|---|---|
| SUCCESS 1 | `pgboss.version` is exactly one row at `38`, the number `migrate: false` reads at every `start()` |
| SUCCESS 2 | `create_queue` registers an unpartitioned queue against `job_common` and a job for it lands there |
| SUCCESS 3 | a partitioned queue owns its own table, a job routes to it rather than to `job_common`, and `delete_queue` reclaims it |
| REJECTION 1 | a job naming an undeclared queue is refused by `q_fkey`, at the end of the subtransaction because the constraint is `DEFERRABLE INITIALLY DEFERRED` |
| REJECTION 2 | a queue still holding a job cannot be deleted, `ON DELETE RESTRICT` |
| REJECTION 3 | a job state outside `pgboss.job_state` is refused at the write |
| REJECTION 4 | a `key_strict_fifo` job with no `singleton_key` is refused by name |
| REJECTION 5 | **`merit_app` holds nothing at all on this schema**, and cannot read `pgboss.queue` |

**Against `0001`..`0076` the file dies at `SUCCESS 1`** with `relation "pgboss.version" does not exist`, exit 3, which is the counterfactual stated in its header and observed rather than predicted. **`REJECTION 5` was falsified**: `GRANT USAGE ON SCHEMA pgboss TO merit_app` turns it red by name, and the `REVOKE` restores the green run.

### 6. Two gates corrected, and why neither is a relaxation

**`CI-06i` READ A SCHEMA NAME AS A TABLE NAME.** `tablesInMigrations()` matched `CREATE TABLE ([a-z_]+)`, which was the table name for seventy-eight migrations **because every table in this estate was in `public`**. Against `CREATE TABLE pgboss.job` it captured `pgboss`, nine times, and reported nine duplicate definitions of one imaginary table plus a missing design record for it. The parser is now schema-aware and scoped to `public`, which is what [DATA_MODEL](../architecture/data-model/README.md) documents and what `CI-06h` has read from `pg_tables` since it was written. **The `tables` span is unmoved at 118 across the diff, which is the check that the correction did not move a number it should not have moved.** `sql_tables` is deliberately untouched: it is the `^CREATE TABLE ` grep the workflow itself runs, and pg-boss's emitted DDL is indented so that grep never saw it.

**THE `CI-06h` JOB NOW INSTALLS DEPENDENCIES.** The transcript assertion has to import the installed pg-boss, because the version in the catalog is the whole subject of the check. It could not degrade to a skip, on this repository's own rule that a check which cannot run is not a check that passed. `--frozen-lockfile`, on `VG-12`'s first part and because an install allowed to move the lockfile could move pg-boss out from under the assertion.

**`CI-06s` and `RI-24` forced the wiring** and it is complete in both directions: the new `probe_*.sql` and the new `assert_*.mjs` are each a step in [`corpus.yml`](../../.github/workflows/corpus.yml) and a needle in `CI-06h`'s required list. That is why [`gates.mjs`](../../scripts/corpus/gates.mjs) is in this diff.
