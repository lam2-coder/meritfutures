## 2026-08-20 - Session 112: WAVE-04 `W5`, `ADR-073`, what closes `CI-07`, `CI-08` and `CI-09` (non-money)

- **Objective:** rule what closes a row of the [STRATEGY](../testing/STRATEGY.md) gate inventory, so `OI-26` is an answered finding rather than a queue of three workflows, and settle `VG-11`'s two assignments in the same document.
- **Done:** **[ADR-073](../decisions/ADR-073.md), `status: proposed`, unsigned.** A row is closed when it is **implemented** with its workflow file and job name, when it carries a **dated activation condition naming ONE artifact**, or, for `CI-10` alone, when it is **discharged by a register outside Actions**. The condition is two-sided: **the day the artifact arrives the row is a finding until the stage is written.** [STRATEGY section 4](../testing/STRATEGY.md) states the rule and **section 4.1 gains a `Closure` column with a disposition on all ten rows**; `VG-11` is struck from `CI-07`'s contents cell and section 4.2 is untouched. **No gate row added.** One `##` section appended to [STATE](../STATE.md) recording `OI-26`. **24 of 24 gates pass, `pnpm run falsify` clean and dirty over all 24 with 35 scope and 10 loader cases, `pnpm exec vitest run` 74 files and 1085 passing.**
- **Next:** **`W7` builds `CI-09` and builds ONE leg, not three.** `W8`'s `CI-06/gate-inventory` reads the `Closure` column, and **the assertion that does the work is the one that fails on good news**: every artifact named by an activation condition must resolve to **absent**.
- **Blockers:** None for this session. **Two open items handed on rather than taken:** the `VG-12` admission that `CI-09`'s Stryker leg waits on cannot be granted by a session, and [session 23](2026-08-15-session-23.md)'s founder action to enforce it ("Require review from Code Owners" on `main`) is still open; and extending the closure rule to section 4.2's twelve `VG` rows is a second ruling `ADR-073` names and deliberately does not take.

### The finding was wrong by one row, and this repository already knew

**`CI-04` has no Actions job either.** The prompt and [WAVE-04 section 3](../plans/WAVE-04-fixture-backlog-and-gate-inventory.md) both say *"`CI-01` to `CI-06` run in Actions"*. Six jobs exist across three files (`lint-and-types`, `unit-and-property`, `security-static`, `integrity`, `migrations`, `golden`) and they cover **five** stages. [`ci.yml`](../../.github/workflows/ci.yml) says so in its own comment. **[STATE](../STATE.md)'s P1 table already rows *"`CI-04`, `CI-07` to `CI-09` | NOT STARTED"***, so the corrected finding was in the corpus and the plan narrowed it.

**It is load bearing rather than pedantic.** `CI-06/gate-inventory` reads **every** row. A rule applied to three of the four open rows produces a gate that fails on arrival, which is the thing STATE names as the gate somebody switches off. `CI-04` therefore got a condition too, which is a widening past the three rows the prompt named and is stated as one in the ADR and in the pull-request body.

### The citation that settles `CI-07` is not either of the two that were offered

- ***"A gate added as advisory is a gate that stays advisory"*** is the second half of a sentence about **extending** the inventory and governs the **blocking level** at the moment a gate is added. Reaching `CI-07` needs one added step: a stage whose artifact does not exist can only skip, and a stage that always skips is an advisory whatever its `if:` says. **Stretched, and it survives being stretched.**
- ***"`falsify.mjs` makes a gate that cannot pass the tree an ERROR"* names the wrong harness.** `falsify.mjs`'s clean phase runs the **`GATES` in [`gates.mjs`](../../scripts/corpus/gates.mjs)**, which are the `CI-06` corpus checks. Pipeline stages are falsified by [`falsify-ci.mjs`](../../scripts/ci/falsify-ci.mjs), which **has no clean phase at all, by explicit design**: *"THE CLEAN DIRECTION IS THE STAGE ITSELF."* **Stretched, and it does not survive.**
- **What settles it was already in the tree:** [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) rule 2, inherited verbatim by `falsify-ci.mjs`, *"A CHECK THAT CANNOT RUN IS NOT A CHECK THAT PASSED."* It forbids the skip branch by name, and [STRATEGY section 1](../testing/STRATEGY.md)'s one-operator argument forbids the fail-forever branch.

### Landmines

- **"HAS A SUBJECT" AND "HAS AN INPUT" ARE DIFFERENT THINGS, AND THE REPLAY LEG IS WHERE THEY COME APART QUIETLY.** [`replay.ts`](../../apps/worker/src/batch/replay.ts) exists and `runReplayAudit` takes `BatchPorts`, reading `accountsWithStoredState`, `storedRuleStates` and `accountDaysFrom` from a database. **There is no seeded demo world**: [`packages/db/src/seed/`](../../packages/db/src/seed/calendars/README.md) holds calendar source files and nothing else, and INFRA's demo seed is described as a plan. Its `OI-14` refusal fires only when `storedRows > 0 && inScope === 0`, so **with zero stored rows it does not fire** and a nightly built today reports `accountsAudited: 0`, `diverged: 0`, green, every night, over nothing. That is `OI-14`'s own defect one level above the guard written for it. **`W7`: when that leg is built, it refuses on `accountsAudited === 0`.**
- **`RI-02` ALREADY DECIDES HALF OF `OQ-TS-02` BY ACCIDENT.** Its needle `/thresholds\s*:/i` **matches** a Stryker `thresholds:` block in `.mjs` and **does not match** `"thresholds":` in JSON, checked by running the regex rather than by reading it. So the tree forbids one spelling of a mutation threshold at `CI-01` and permits the other, and neither is a ruling anybody made. `RI-02`'s stated argument is about **line coverage**, which generated tests inflate for free; **mutation score is the one metric they do not.** `ADR-073` leaves `OQ-TS-02` open and hands the founder the sharper question.
- **`VG-11`'S TWO ASSIGNMENTS HAVE AN EXACT PROVENANCE AND IT IS NOT A TYPO.** [INFRA](../architecture/INFRA.md)'s gate graph chains `G2 -> G10 -> G11 -> D10`; `CI-07`'s contents cell read *"VG-2, VG-10, VG-11, D0-10"*, **the same four in the same order**. The cell is a transcription of the graph, and **the graph is the half of INFRA that contradicts INFRA's own table one screen below it**, where `VG-11` blocks merge while the graph puts the whole build chain downstream of merge. `CI-07`'s cell is the losing row. **INFRA's graph is the origin and is outside this fence**; so is the `VG-1 to VG-12` row of STATE's P1 table, which carries the same losing assignment. Both are recorded in the ADR and in the STATE append.
- **P1'S DEFINITION OF DONE IS NOT THE GATE INVENTORY, AND `OI-26` OPENED ON A SENTENCE SAYING IT IS.** [DELIVERY_PLAN section 4](../DELIVERY_PLAN.md) makes *"CI with the full STRATEGY gate inventory"* one of P1's **contents**; its **definition of done** is *"every VG gate wired and failing correctly on a seeded violation, VG-12 not deferred"*, and **three of twelve are wired**. A complete `Closure` column closes nothing. Anyone scoring P1 against `ADR-073` will score it wrong.
- **ONE NUMBER IN THE REFERRING PLAN REPRODUCES NOTHING.** WAVE-04 section 3 gives `packages/rules-engine` as **10,264 source lines**; the tree gives **5,732** across 17 files under `src/` and **20,995** including `test/`. It changes no conclusion, since the argument for Stryker on the engine is the purity boundary `RI-01` and `RI-07` hold, not the size. **It is recorded because a number in an approved plan gets copied.**
