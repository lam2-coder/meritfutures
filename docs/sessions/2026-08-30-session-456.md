### 2. The sized remainder was the trap, which is the finding

[ADR-252](../decisions/ADR-252.md) section 10: *"The `CATALOG_TABLE_KEYS` admission, one member plus
ADR-233's argument ... This is the whole remainder of `useCheckoutBackend`'s clause 1."*

**`refuseUncatalogued`'s admission test is MET by this table, so the objection is not that the
argument fails.** It is that a catalogue read is the wrong SHAPE for this number, three times over:

| | What the admission gives a caller | What the named door gives them |
|---|---|---|
| **The fold** | The BASE. The exception is a second read on a second table the caller must remember, in two callers, forever | One integer, exception applied |
| **The dating** | EVERY row the parameter has ever held, because `ORDER BY` and `LIMIT` have no shape in this accessor | The latest arrived row, built once |
| **The grant** | The WHOLE TABLE, forever, including every member the vocabulary later admits | One parameter, one count |

**So the row's own first trap is what decides it.** A caller holding the base is a caller who has to
remember `identities.max_accounts_override`, and the row said that is a control forgotten exactly
once. **Taking the sized remainder would have built it.**

### 5. Where this session is most likely wrong

**THE DOOR READS `now()` AT THE DATABASE AND NOTHING HERE PROVED WHAT `now()` RETURNS INSIDE THE
TRANSACTION IT WILL RUN IN.** That a supersession dated row is read at transaction start time is
taken from Postgres documentation rather than measured, **and it is the whole reason the read is on
the scoped handle instead of `ApiDb.firm`.** A session with a running PostgreSQL should execute it.

**THE UNCONDITIONAL REFUSAL IS A JUDGEMENT AND NO TEST SETTLES IT.** An identity carrying an
operator-written override is refused where no base row has taken effect. The argument is that an
override carries no approver and no written reason; the argument against is that an override IS an
explicit bounded authorisation and refusing it fails the very identities somebody made an exception
for. It is one branch either way.

### 7. Landmines for the next session

- **`prettier --write` IS AN EDIT AND MOVES EVERY POINTER BELOW ITS FIRST REFLOW.** Thirteen
  citations were derived, repaired, and then moved again by 14 when `format:check` ran. **Run the
  formatter BEFORE deriving pointers.** Third session in a row to pay for this ordering.
- **A SECTION HEADING THAT NAMES A DECLARATION HIJACKS A NEARBY CITATION.** `RI-15` resolves a name
  to its NEAREST occurrence, so a comment naming `CATALOG_TABLE_KEYS` two hundred lines above the
  declaration makes a citation unrepairable at the line the first failure message quotes, and
  produces a second, different message when you try. **Repoint at the declaration, not at the number
  the message names.**
- **ASSIGNMENT NARROWING MAKES A REGISTRY GUARD UNCOMPILABLE, NOT UNNECESSARY.** `SCOPE_RULES` is `as
  const`, so a guard reading `rule.class !== 'firm'` is `never` in its own branch and the message
  naming what the class became will not compile. **The guard is about the day somebody edits the
  registry, and that day recompiles clean.** `registeredRule(key)` is the indirection.
- **DRIZZLE'S COLUMN MAPPER COERCES BEFORE ANY GUARD IN THIS TREE RUNS.** A case asserting a wrongly
  typed value is refused may be passing on the mapper rather than on the check it names.
- **`routes/payouts.ts` IS SESSION 455'S FILE THIS WAVE** and one of its citations moved with this
  diff. It is a line-number token and nothing else, and it is the one place this branch can conflict
  with that one.
