**Objective.** Rule whether one transaction may serve a scoped read and a firm
read, and if so what the handle is.

**Outcome.** **Ruled, and the ruling REFUSES the port.** One transaction may not
serve both, and the reason is a measurement rather than an authority argument.
The crossing is two transactions keyed by the scoped result. **And
`usePayoutBackend` stays unwired anyway**, because the catalogue rows the payout
path crosses on are movable and nothing at the database pins them.
`ADR-211` is taken. **No adapter, no migration number, no wiring.**

### Blockers

**The slice's own stop condition fired, and firing it is the result.** The
dispatch says a ruling that refuses is a successful session, and this one
refuses: no arrangement of doors makes `PayoutTx.subject()` return a plan the
approval it feeds can be held to, while the size grid of a published version is
mutable by the role the API runs as.

### Landmines

- **ONE `BEGIN` IS NOT ONE VIEW OF THE DATABASE.** `read committed` takes a
  snapshot per STATEMENT, so two reads inside one transaction straddle a
  concurrent commit exactly as two transactions do. Measured, both directions.
  **Every argument in this tree that treats "one transaction" as "one
  consistent read" is wrong by that much**, and this is the first entry to say
  so.
- **A TABLE CAN BE IMMUTABLE AND ITS CHILD GRID FULLY MUTABLE.** `0028` pins
  `plan_versions` down to the byte and attaches nothing to
  `plan_version_sizes`, where every cents value lives. The guard reads as
  complete because the table it is on is the one people name.
- **AN APPEND-ONLY SNAPSHOT MAKES AN INCONSISTENCY PERMANENT AND
  AUDITABLE-LOOKING.** `INV-22`'s `eligibility_snapshot` would record figures
  the plan version never carried, as the stated basis of an approval. That is
  worse than a transient wrong number.
- **A CITATION REPAIRED IN ONE FILE LEAVES THE SAME CLAIM WRONG IN THREE.**
  `ADR-176`'s row 17 recorded exactly this class one wave earlier and the
  payout blocker's citations drifted again anyway.
- **A DRIFTED LINE NUMBER AND A FALSE CLAIM ARE DIFFERENT REPAIRS WITH
  DIFFERENT FENCES.** `payouts.ts:438` is the second and was registered, not
  fixed, because a ruling that quietly edits the thing it rules is not a ruling.
- **A COUNT INFERRED FROM THE HIGHEST FILENAME IS NOT A COUNT.** The highest
  migration is `0064` and there are **60** files; the entry said 64 in three
  places until it was derived. `CI-06/derivable-counts` treats a dated heading
  as out of scope, so no gate would have caught it.
