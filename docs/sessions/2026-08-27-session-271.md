### 1. What the ruling settled, and the one thing it could not

[ADR-154](../decisions/ADR-154.md) has six clauses and five of them are decisions about the CORPUS: which interface gains a method, what the shared thing is, which operations stay refused, what replaces `GS-084`'s property, and which three documents move together. **Every one of them was satisfiable as written and none needed interpretation.**

**What it does not settle is how a subscription starts, and it could not**, because that is not a question a planning session can see. [M02](../plans/M02-rithmic-bridge.md) section 3.5 gives the signature `streamLive(handler): Promise<Subscription>` and defines `Subscription` nowhere in this corpus. So this slice made exactly two decisions the ruling left open, and both are stated here rather than only in a header:

| Decision | Made this way | Why not the other way |
|---|---|---|
| **What a `Subscription` carries** | `close()`, and nothing else | Feed loss is a first-class state under [ADR-020](../decisions/ADR-020.md) rule 3, the shape of a staleness claim is the SERVER's under [ADR-152](../decisions/ADR-152.md), and [P6](../plans/P6-live-tier.md) section 3.4 holds an event family with no member. **An `onLoss` here would be this slice writing `P6-d`'s contract in a package `P6-d` does not touch** |
| **When the first tick is delivered** | One turn of the event loop per tick, `setImmediate` | Section 3. The obvious implementation is a synchronous loop and it makes `close()` a no-op; the next-most-obvious is a microtask pump and it makes `close()` unreachable from the handler |

---

### 2. Clause 3 is enforced twice, and the second one is the assertion

Clause 3 forecloses in advance the argument that a simulator implementing one operation may implement the others. The natural way to state that is the return type, and `simulatorLiveFeed` returns `Pick<PlatformAdapter, 'streamLive'>` rather than an inferred object literal.

**That annotation is not the assertion.** A `Pick` bounds what a consumer may CALL, not what the object CARRIES: a `simulatorLiveFeed` that grew an `ingestEOD` beside `streamLive` still satisfies `Pick<PlatformAdapter, 'streamLive'>`, and `tsc --noEmit` stays green across the whole repository. So [`adapter.test.ts`](../../packages/rithmic/test/adapter.test.ts) reads the returned object's key set at runtime, which is the only place the extra key is visible:

```
== the simulator feed carries exactly == [ 'streamLive' ]
```

---

### 3. THE DEFECT, WHICH WAS IN THE START AND NOT IN THE SEAM

The first implementation pumped one tick per **microtask**. It type-checked, it delivered every tick, the conformance invariants passed, and it was wrong.

**A microtask queued inside `streamLive` runs before the caller's `await` continuation.** `streamLive` queues the pump synchronously and returns an already-resolved promise; the consumer's `await` schedules its continuation after that. So the first tick reaches the handler while the consumer is still waiting for the `Subscription`, and the ordinary consumer shape

```ts
const subscription = await feed.streamLive((tick) => {
  seen.push(tick);
  if (seen.length === 3) subscription.close();   // <- not yet assigned
});
```

is a temporal-dead-zone reference on the very first tick. **A feed whose subscription cannot be closed from the handler is a feed whose subscription is decoration**, which is the same defect as the synchronous loop wearing a more sophisticated hat.

`setImmediate` is a turn of the event loop rather than a moment: it takes no duration and reads no clock, so [`no-clock.test.ts`](../../packages/rithmic/test/no-clock.test.ts)'s constraint over `src/` is untouched, delivery stays deterministic at one tick per turn, and **every delivery is strictly after the consumer holds the object, whatever the length of its own promise chain.** Driven:

```
== close() from inside the handler after 3: delivered 3 ==
```

### 6. Why `ADR-160` is not taken

The number was reserved against **implementation finding [ADR-154](../decisions/ADR-154.md) could not be satisfied as written**, which is the shape [ADR-102](../decisions/ADR-102.md)'s falsification clause met the day [ADR-112](../decisions/ADR-112.md) removed the methods it seeds.

**Each clause was satisfied and the two that had to survive contact with a compiler both did.** Clause 1's method carries M02 section 3.5's own signature rather than a paraphrase of it. Clause 3's *"one method and no other"* is a type in `src` and a key-set assertion in `test`. Clause 4's conformance suite runs and fails on each violation it claims to see. Clause 6's refusals held: no cache, no container, no socket, no migration number.

**Section 4 is a finding and it is not that finding.** A package README with three stale sentences is a residue to carry to the session that holds the file; it is not a ruling that cannot be applied, and minting an entry for it would spend a number on a `sed`.
