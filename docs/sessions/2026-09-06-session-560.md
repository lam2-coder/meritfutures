### 6. The finding, and why it is not a wording preference

The entry reads *"ONE SUPPLIER SHORT, AND THE SUPPLIER IS NOT A DOOR."* It inherits that from ADR-171 section 4, which wrote the same sentence answering a NARROWER question: *would the door move this port*, to which the answer was no, because `principal` rejects first.

**ADR-171's OWN CLAUSE 5 IS THE STANDARD THIS ENTRY NOW FAILS**: *"A reason that misnames the obstruction is worse than a short one, because it retires the question in the wrong direction."*

**AND THE DIVERGENCE IS INSIDE THIS DEPLOYABLE RATHER THAN BETWEEN A DOC AND THE TREE.** `admin-reads.ts`'s unwired-source message names the door in its own words; this port's entry denies a door is its blocker. **Two admin ports, one absent door, opposite descriptions, same tree, same day.** Neither is lying and the divergence still cost this row its session to find.

**WHAT THIS ROW DOES NOT RULE.** It does not rule that the door should open. ADR-171 section 5 is the strongest argument in that entry and it does not expire: the door lands on the object `databaseAuthBackend` already holds, and `ADR-120`'s `B1` then falls to one line at the reason word `'operator-console'` inside a handler serving an anonymous request. **The ruling is that the blocker must be NAMED, not that it must be discharged.**

### 7. Dual control, which the entry does not mention

**MEASURED: `admin-payouts.ts` NAMES `dual_control` ZERO TIMES.** So do `payouts.ts` and `wallet.ts`; `wallet-withdrawals.ts` names it five times.

For the release row to be dual controlled the port needs, in this order: a column on `payout_requests` (**absent**), a key in `ADMIN_PAYOUT_TABLES` an approval could be read through (**absent**, and the union is closed at three so a missing member is an impossibility), a wire field (**absent**), and the threshold value (**unset, founder-owed**).

**SO ONE OPERATOR HOLDING `owner` OR `ops` CLEARS A HOLD AND POSTS `LT-01` FOR WHATEVER THE HOLD FROZE, AT ANY SIZE**, while both of the other surfaces that move or adjust trader money carry dual control in the schema. **The absence may be deliberate and this row could not find where it was decided.** `DELTA_MANIFEST` already records the gap in its own words, so the finding is reproduced rather than discovered. **Whether payout release SHOULD be dual controlled is a founder ruling and this row does not take it.**
