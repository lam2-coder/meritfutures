- **Landmines:**
  - **"THE CURRENT DEFINITION" IS NOT A SYNONYM FOR "THE UNSUPERSEDED ROW", AND THE OBVIOUS IMPLEMENTATION READS A CLOCK.** `INV-M12-07` makes `effective_from` **always future at write time**, so the row with no successor is regularly one that has not taken effect, and the two answers differ on the ordinary case rather than on an edge one. A clock in a cacheable public read is worse than wrong: two callers sharing one cache entry get one answer, and the answer is about which method produced a published number. Seeded, and it fails **4 of 13**.
  - **`superseded_by` RENDERED AS `null` WHEN IT CANNOT BE RESOLVED SAYS "THIS IS THE LIVE VERSION".** The field is a uuid in the table and a version number in the response, so the mapping can fail, and the null-ish default is the one value that is a false statement rather than a missing one. It refuses instead.
  - **NAMING THE PER-IDENTITY ACCESSOR ANYWHERE UNDER `apps/api/src` FAILS A GATE.** `VG-3` and `VG-6` wait on exactly that artifact ([`gates.mjs`](../../scripts/corpus/gates.mjs)'s `VG_PROBES`, anchored on a word boundary), so `CI-06/vg-inventory` goes to 29 of 30 the moment it appears, including inside a comment. **This route legitimately never needs it** and the phrasing in its header avoids the token deliberately; the wiring slice will trip it and should read the failure as the artifact arriving.
  - **A ROUTE MODULE CANNOT BE HANDED A DEPENDENCY AT COMPOSITION TIME.** [ADR-100](../decisions/ADR-100.md) rule 1 makes the module's contribution the object it default-exports and `compose` gives a handler nothing but the request, so a dependency either lives beside the module or the module has to RUN to receive one, which is the shape that ruling refused. The holder here is read at **request** time rather than closed over, so wiring order cannot silently capture the unset value.
  - **AN ADR AMENDMENT DOES NOT MOVE `last_updated` ON THIS TREE, AND THAT IS THE PRACTICE RATHER THAN A RULE ANYBODY WROTE.** [STRATEGY](../testing/STRATEGY.md) still reads `2026-08-17` after [ADR-100](../decisions/ADR-100.md) amended two of its rows on 2026-08-25, so this session left [API_CONTRACT](../architecture/API_CONTRACT.md)'s frontmatter at `2026-08-16` rather than diverging inside a fence that names one row. **`CI-06b` checks that the field is present and valid, not that it is current**, so nothing catches the divergence in either direction.
