### 4. The three refusals, executed

Every rejection is matched by CONSTRAINT NAME out of `GET STACKED DIAGNOSTICS`, never by exception class, because three of the five raise `foreign_key_violation` or `not_null_violation` and a handler catching the class cannot tell them apart.

```
SUCCESS 1: an accrual of 150000 cents is owed to affiliate db5bd289-...
SUCCESS 2: a clawback names the same affiliate and the pair sums to 0
SUCCESS 3: accrued is 150000 cents for A and 0 rows for B, on (affiliate_id, status)
REJECTION 1: null value in column "affiliate_id" of relation
             "affiliate_commissions" violates not-null constraint
REJECTION 2: a disagreeing commission is refused by
             affiliate_commissions_attribution_owner_fk
REJECTION 3: moving the attribution under a commission is refused by
             affiliate_commissions_attribution_owner_fk
REJECTION 4: an affiliate carrying commission rows cannot be deleted
REJECTION 5: merit_app cannot move a commission to another affiliate
             (affiliate_commissions_attribution_owner_fk)
probe_affiliate_commission_owner: 3 successes and 5 rejections hold against
the applied schema.
```

**REJECTION 3 IS THE ONE A `CHECK` OR A CHILD-SIDE TRIGGER WOULD NOT HAVE HAD.** A composite foreign key constrains the PARENT too, so the disagreement cannot be created by moving the attribution beneath an already-correct commission. [`0012`](../../packages/db/migrations/0012_disputes_and_affiliate_settlement.sql)'s own comment says an affiliate **can be reassigned**, so that is a documented possibility on this exact table rather than a hypothetical.

**THREE ACCEPTANCES COME FIRST** on `DELTA_MANIFEST` section 13's standing rule: `0078` exists to make a CORRECT commission row writable for the first time, and a guard that refused every write would satisfy every rejection above and close nothing.

This is the exact defect [ADR-253](../decisions/ADR-253.md) section 5 and [ADR-304](../decisions/ADR-304.md) section 8 each repaired, and that second file exists to catch it. **Left because repairing it is a rewrite of a shipped refusal, its two assertion files and a liability register entry, in three files under `apps/`, and this row's fence grants citation repair rather than rewriting. It should be the next row on this path**: a refusal is the one place a later session reads to find out what to build, and this one now sends that session to write a migration that exists.
