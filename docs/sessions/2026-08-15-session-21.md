## 2026-08-15 - Session 21: S-A, ADR-036 and the migration allocation table

- **Done.** The second numbered registry in this repository has an allocation table and a gate that reads it. [ADR-036](../decisions/ADR-036.md), [DECISIONS](../decisions/README.md)'s second table, and `CI-06h`'s allocation half. **S-B was not begun**, per the instruction.
  - **The registry with no table was the one that could least afford a collision.** `CI-06h` derived the migration sequence **from the tree**, which is exactly the check a branch can satisfy while colliding with its sibling: two branches forking from one `main` both find `0028`, both write `0029`, both pass locally, and the collision surfaces at merge as two files claiming one position in an ordered set. **[ADR-034](../decisions/ADR-034.md) resolved the ADR collision by renumbering the branch whose number was cited least, and that remedy does not exist here**: E2 makes a merged migration sacred, so a landed number cannot be renamed, only superseded.
  - **It extends `CI-06h` rather than arriving as `CI-06k`, and the brief asked for the sibling.** `CI-06h` already computes the migration number set, and a reserved number **has no file on disk**, so `CI-06h`'s existing gap check fails on the exact hole a sibling gate would exist to permit. `CI-06h` had to become allocation-aware either way; once it is, the sibling is a second expression of one concept **in the runner OQ-P1-04 was ruled about, one session after that ruling**. Argued in the ADR under its own heading rather than done quietly.
  - **One parser reads both tables, and it is STRICTER than the one it replaced.** `CI-06f`'s inline scan read every three-digit numeral in the allocation section's **prose**, so a number mentioned in a sentence was silently reserved. The shared parser reads the first cell of table rows. **That direction is the one that matters: a number reserved by accident is a hole the gate stops reporting.**
  - **Two scope cases, one per direction**, because the change makes the gate quieter on one input and louder on another. `CI-06h/reserved`: a reserved hole must **not** be a finding. `CI-06h/unallocated`: a number on disk that no row claims **must** be one. **Sixteen assertions now hold**, eleven seeded violations and five scope cases, and the counts were derived from `falsify.mjs` rather than stated (the first draft of this entry said fifteen).
  - **Four counterfactuals, all watched.** Reservations ignored gives `READ A FILE IT MUST NOT`; the allocation check removed gives `DID NOT FAIL`; the hole loop disabled gives **`FAILED OFF-TARGET`**, because the seeded tree still fails on a different finding; a renamed table heading gives `ERROR`, the gate refusing to run rather than passing.
  - **The correction rider, and it was four places rather than one.** `P1` section 7's fenced `isCorpusDocument` still carried the pre-ruling `&& file !== 'docs/INDEX.md'`, directly above the paragraph recording that the exclusion was removed. **Verified by extracting the declaration from both files and diffing them**, per the instruction, and the extractor is in the log below because the first version of it ate the regex literals' slashes as comment markers and reported a false difference.

  - **`gates.mjs` held a literal NUL byte and every text tool skipped the file.** `CI-06g`'s `spansIn` masks `<` inside fenced blocks and the mask character was written as the byte rather than as its escape. `grep -rn` over the repository reported `binary file matches` and printed **nothing**. **It cost a real search in this session**: the stale `covers` line below was found by reading rather than by grep. Fixed as its own commit; the escape parses to the identical string, so the change is neutral by construction rather than by testing. **It predates this branch** and is on `origin/main`.
  - **THE STALE CLAIM THAT SURVIVED IN A `covers` LINE IS THE WORST OF THE FOUR.** The 2026-08-15 INDEX ruling amended the plan's prose and the predicate, and left the assertion standing in three more places: the comment block **directly above the predicate** in `gates.mjs`, `CI-06b`'s `covers` string (`"neither is docs/INDEX.md"`), and `STATE`'s "one coverage loss". **A `covers` line is what the `list` command prints as the gate's own statement of what it does not check.** Wrong, it is a documented coverage gap that does not exist, which is the same object as an undocumented one that does, and the runner is where a reader goes to settle exactly this question.
  - **A falsification counterfactual hit the wrong gate and looked like a pass.** Disabling "CI-06h's hole loop" by string replacement hit **`CI-06f`'s identical loop**, four hundred lines earlier, because the two gates share the line `for (let n = 1; n <= max; n++) {` verbatim. The run reported `CI-06h` still failing as required and it was telling the truth about an unmodified gate. **A counterfactual needs to be verified as having landed**, the same discipline `expect` enforces for the seeds, and nothing enforces it for a hand-run experiment.

Anchored on `\s//\s` instead.
