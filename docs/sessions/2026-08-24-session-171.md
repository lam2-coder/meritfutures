### Eight sessions found the same shape without seeing each other

The measurement wave's headline is not in any one log. Measured separately, in fourteen containers, against fourteen different module plans:

> M18 *"schema is finished while nothing reads it"* · M05 *"the schema is finished while nothing can read it"* · M19 *"complete and unreachable"* · M17 *"the schema landed ahead of everything that reads it"* · M20 *"the one module whose schema is finished and whose code is absent"* · M03 *"its schema is the only complete half of it"* · M07 *"schema complete and code empty"* · M06 *"the module's schema arrived without its process"*

**The database was built ahead of the application across the whole estate.** That is the single most useful input a P4 plan can have, and **no single session could have established it** — each one only saw its own module.

**Two individual findings are worth as much as the aggregate.** [Session 162](2026-08-24-session-162.md) found a defect one level below the one [M08](../plans/M08-affiliate-system.md) section 3.4 had already recorded: that section ruled *"one rail"* was not doing the work of a shared **gate**; measured here it is not doing the work of a shared **rail** either, because `payout_transfers.payout_request_id` is `NOT NULL REFERENCES payout_requests(id)` and `payout_requests` is `NOT NULL` to both `accounts` and `plan_versions`, **so an affiliate settlement cannot be a row in either table**, while `affiliate_statements.paid_transfer_ref` is bare `text` with no foreign key, which is the second spelling [ADR-017](../decisions/ADR-017.md) exists to refuse. And [session 164](2026-08-24-session-164.md): *"the role that implements its one money-path invariant revokes the table that invariant reads."*

### The fence held, and the merge shape was the lesson

**All fourteen branches touched exactly two files**: their own new session log, and the one claim row they struck. **Zero files outside `docs/sessions/`**, measured across all fourteen before any merge. That constraint was the entire reason a fourteen-way wave was dispatchable, and it is only dispatchable because [ADR-088](../decisions/ADR-088.md) made the session index a generated span the same morning: before it, that file was touched by 25 of the last 25 merges.

**Merging them one at a time is O(n squared).** `#201` and `#202` merged; `#203` then failed on conflicts, because every merge rewrites `docs/sessions/README.md` — the claim rows 157 to 170 are consecutive lines — and every merge stales the generated ENTRY span. The remaining twelve went through **one integration branch**, resolving each collision by an exact rule rather than a heuristic (take the branch-so-far's README, swap in only that session's own struck row) and regenerating the span **once, at the end, with all fourteen logs present**.

> **`#204` was CLOSED rather than merged, and the distinction matters.** Its log was already byte-identical on `main`. Merging it would have been destructive rather than redundant: the branch predated `#200`, so its diff was 517 deletions and would have removed session 156's log and reverted `STRATEGY`'s `VG-8` row.

### Both money-path signatures rest on probes re-run here, not transcripts read there

**[ADR-086](../decisions/ADR-086.md), the queue.** The clause is written in the direction that passes silently: an enqueue on its own connection still returns a job id, still inserts a row, still looks correct at every call site, and merely stops disappearing when the purchase it belonged to disappears. Deleting `db: tx` from `send` was watched producing **exactly the message the clause names**: `expected [ { …(2) } ] to have a length of +0 but got 1`.

**[ADR-087](../decisions/ADR-087.md) and migration [`0047`](../../packages/db/migrations/0047_publish_decision_is_sound.sql).** Two fresh PostgreSQL 16 clusters, built from empty, forward-only under `ON_ERROR_STOP=1`: **47 migrations at one, 46 at the other**. At `0047` the probe reports **7 rejections and 5 successes**, including two that prove **both triggers are wired** rather than only the insert one. At `0046` the same file **dies on `REJECTION 1`**: `a publish decided on a FAILED run was accepted`.

> **THE SIGNATURE RESTS ON THE DIRECTION THE ENTRY REFUSED TO TAKE.** `0047` closes two of three soundness directions and leaves the digest half open **on a stated reason rather than because it was hard**: the canonical serializer preserves trailing zeros, so a draft re-saved with `5.0` where it held `5` digests differently while being the same rule contract, and a trigger would **refuse a legitimate publish**. A false refusal on the publish path is worse than the hole it closes. The entry's own sentence is the one to keep: *"a money-path migration that installs an unruled constraint because it was cheap is how a schema acquires rules nobody decided."*
