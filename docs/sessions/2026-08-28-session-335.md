### 2. THE CLIENT TAKES NO ORIGIN, AND THAT IS THE DIVERGENCE FROM THE PORTAL RATHER THAN A COPY OF IT

[`apps/portal/src/http/client.ts`](../../apps/portal/src/http/client.ts) is the shape and it is followed everywhere except the one decision that matters most here.

| | Portal | Admin |
| --- | --- | --- |
| Base URL | `resolveApiOrigin(env)` plus `/api/v1`, refusing when `MERIT_API_ORIGIN` is unset | `/api/v1` and the path. **No origin anywhere** |
| Why | [ADR-083](../decisions/ADR-083.md) ruling 1 puts the trader API on its own origin, so a base URL without a host reaches nothing | [`INFRA:43`](../architecture/INFRA.md) and [`INFRA:44`](../architecture/INFRA.md) row `admin` and `api-admin` on the SAME origin and [`INFRA:53`](../architecture/INFRA.md) separates them by PATH |
| The session cookie | One named cookie forwarded by the portal's server, because a browser call cross-origin is refused before the cookie question is reached | **Nothing is forwarded.** Same origin, so the browser presents it and no cookie name appears in this package |
| What it costs | An operator variable that can be set wrong per environment | Nothing, and it is what makes the no-hostname rule free |

**SO THE `ADR-012` OBLIGATION IS DISCHARGED BY THERE BEING NOTHING TO DISCHARGE**, which is [WAVE-06 section 5.3](../plans/WAVE-06-admin-console-transport.md)'s finding that a separate-origin console makes the obligation EASIER. The one hazard that section names is a build-time inlined absolute URL, and this deployable now HAS a build ([ADR-182](../decisions/ADR-182.md) ruling 2), so section 3 is the part of this slice that is not transcription.

**A CONSEQUENCE STATED RATHER THAN LEFT TO BE DISCOVERED BY `W6-d`.** A root-relative path is resolved against a document's origin, so this is a BROWSER client and `fetch('/api/v1/admin/liability')` in a Node process throws rather than guessing a host, which is the correct direction for a refusal in a package whose subject is not writing a hostname down. **A server-rendered read is `W6-d`'s decision and this file does not take it either way**: `ADR-182` section 5 clause 3 permits `resolveAdminOrigin` at REQUEST time, this session's sweep is over WRITTEN origins so it does not stand in the way, and what this file refuses is HOLDING an origin at all, because a client that can take one is a client somebody configures with one.

### 3. THE TWO ASSERTIONS ADR-182 ASSIGNED, AND THE DEFECT THAT SEEDING FOUND IN THE FIRST ONE

[ADR-182](../decisions/ADR-182.md) section 8 item 2: *"No invariant, gate or lint rule refuses a `NEXT_PUBLIC_` variable or an absolute origin in `apps/admin`. `W6-c` is the slice that can make both mechanical."*

**Both sweep the WHOLE PACKAGE and not `src/`**, because *"anywhere in `apps/admin`"* is what the entry says and because [WAVE-06](../plans/WAVE-06-admin-console-transport.md) rule 3 is explicit that a hostname is refused *"not in a default, not in a comment, not in a test fixture, and not in a build artifact"*. A sweep stopping at `src/` would leave the fixture half of that sentence unchecked. **And the walk is over EVERY FILE rather than over `.ts`**, which is `B.2`'s lesson taken rather than re-learned: `W6-d` adds `.tsx`, `ADR-182` clause 4 anticipates a `next.config`, and a `.env` file is the third mechanism by which a value reaches a bundle. All three are covered on arrival.

**THE ORIGIN SWEEP PASSED VACUOUSLY AND ONLY A SEED ON THE REAL TREE COULD SHOW IT.** The comment stripper this file inherited from [`apps/portal/test/surface.test.ts`](../../apps/portal/test/surface.test.ts) is `\/\/[^\n]*`, which is correct for `fetch(` and `WebSocket` and **deletes the `//` of `https://host` along with the rest of the line**, so the origin regex read a file naming a host and found nothing. The repair is a `(?<!:)` lookbehind: a scheme's `//` follows a colon and a line comment's does not, so every real comment is still stripped, including one that quotes a URL. **A sweep watched only in its passing state would have shipped.**

**FIXTURES MAY NAME A HOST AND ONLY A RESERVED ONE, WHICH IS STRICTLY STRONGER THAN EXEMPTING THE FILES.** [`access.test.ts`](../../apps/admin/test/access.test.ts) and [`page.test.ts`](../../apps/admin/test/page.test.ts) need origins to exercise `INV-M6-02`'s containment relation and already use RFC 2606 and RFC 6761 names. Permitting the reserved SET rather than the FILES means a real hostname added to either tomorrow is a finding. **`src/` is separately asserted at ZERO absolute origins, reserved names included**, which is the stricter half and the one that fails on a `localhost` default sneaking into a client.

**AND THE NEEDLES ARE ASSEMBLED FROM FRAGMENTS, INCLUDING THE TEST'S OWN TITLE.** A sweep over the whole package includes the file holding the sweep, so a needle written as one literal is a finding the file reports against itself; the alternative is exempting the file most likely to be edited to defeat the check. The title was the case that actually fired, because a title is a string literal in code rather than a comment.

### 5. THE TWO NEW MODULES ARE NOT BARREL LEGS, AND THE SECOND REASON IS MECHANICAL

[Session 332](2026-08-28-session-332.md)'s handoff offered both shapes: `W6-c` *"adds `src/api/types.ts` and `src/http/client.ts` as legs, or as reasoned entries in `ADMIN_MODULES_NOT_RE_EXPORTED`"*. This session took the second, for three reasons in ascending order of force.

**ONE, THE MERITS.** [`index.ts`](../../apps/admin/src/index.ts) says what the barrel is for: *"The read surface, and the only thing anything outside this app may import."* All 74 names on it are a figure, a fold or a rendering. A wire type is the shape of somebody else's document and `API_CONTRACT` is its authority; the client is this package's only network primitive and putting it on the surface the slice exists to narrow to one file is the wrong direction. **The portal's stated reason for exporting its client is measurably not what its own segments do**: eight files under `apps/portal/src/app/` reach `../../http/client.ts` directly and **not one** reads it through `src/index.ts`.

**TWO, THE FENCE.** `B.5` and `B.7` live in [`test/service.test.ts`](../../apps/admin/test/service.test.ts), which is not in `W6-c`'s fence in [WAVE-06 section 8](../plans/WAVE-06-admin-console-transport.md) and which the collision table gives to *"`W6-b`, and every future write slice"*. `B.7` hardcodes `74` and `8`. Rule 1 is that a slice needing a file outside its fence reports it and does not take it.

**THREE, AND IT IS THE ONE THAT SETTLES IT: LEGS WAS NOT AVAILABLE FOR `api/types.ts` AT ALL.** `B.1` asserts `expect(names.length, '${leg} declares no exports, which cannot be right').toBeGreaterThan(3)` and **this module declares ONE export today**. So making it a leg fails `service.test.ts` even after `B.7`'s two cardinals are moved, and the fix would be weakening an assertion in a file this slice does not hold, to admit a module the assertion was written to describe. **The promotion is owed and its condition is written into the entry**: the module grows as `W6-f`, `W6-g`, `W6-h` and `W6-j` add the shapes their own contract rows carry.

**THE LOST COVERAGE IS PAID FOR IN FENCE.** `B.1` and `B.5` do not reach a module in the hatch, so `surface.test.ts` asserts that the hatch holds **exactly** these two entries, that every other module under `src/` is a leg, and that **neither module's names reach the package surface**. That last case is `B.1`'s inverse: it turns "deliberately absent" from a sentence in a comment into a property the tree enforces, and it fired on seed 7.

### 6. What the fence could not follow, reported rather than smoothed over

**6.1 THE COLLISION TABLE SAYS `W6-c` CREATES `api/types.ts` "with the liability and FEED shapes", AND THE FEED HALF IS NOT DOABLE BY THIS SLICE.** [WAVE-06](../plans/WAVE-06-admin-console-transport.md) section 4.2 is the same plan's own measurement: `M06` section 1.1 names the feed a launch surface, `feed.ts` implements it in 507 lines, and `API_CONTRACT` sections 8 and 9 **carry no endpoint for it**. `W6-e` is the slice that writes the row and is the one slice in this wave that REQUIRES an ADR. Transcribing a feed shape here would mean inventing the contract this file exists to copy, against a file's own stated discipline, while [session 336 holds `API_CONTRACT` concurrently](../architecture/API_CONTRACT.md). **The plan contradicts itself between section 4.2 and section 9's collision row, and section 4.2 is the half with a measurement behind it.**

**6.2 THE OTHER FOUR DECLARED READ SHAPES IN SECTION 8 ARE ABSENT ON PURPOSE, WHICH IS THE SAME COLLISION ROW READ THE OTHER WAY.** *"FIVE SLICES, ONE TRANSCRIPTION ... each screen slice adds the shapes its own contract rows carry."* `AdminAccountSearchItem` is `W6-j`'s, `FlagListItem` is `W6-f`'s, `IdentityGraph` is `W6-g`'s, and `EvidencePackResponse` is wave 5's behind [ADR-171](../decisions/ADR-171.md), because an evidence export is an audited ACT and therefore behind the actor. Writing all four here would take four slices' work and manufacture the merge the table exists to prevent.

**6.3 SECTION 9 CONTRIBUTES NO TYPE, AND THAT IS MEASURED RATHER THAN SKIPPED.** It is a five-row table. Four rows (`POST /internal/batch/run`, `GET /internal/recon/status`, `GET /internal/jobs`, `GET /internal/health/deep`) declare **no response body at all**. The fifth, `GET /health`, is the only one with a fixed body, `{ status: "ok" }`, and the contract marks it **Public**; the client refuses any path outside [`surface.ts`](../../apps/api/src/surface.ts)'s operator prefixes, so this console cannot reach it and a type for it would be a shape with no caller.

**6.4 `@types/node@22`'s `RequestInit` DECLARES NO `cache` MEMBER, AND `apps/admin/tsconfig.json` IS `W6-d`'S.** `apps/admin` sets `types: ["node"]` and `lib: ["ES2023"]`, so the ambient `RequestInit` is undici's, and undici implements no HTTP cache. The browser's does, this is a browser client, and section 4's `no-store` is a real instruction at run time and an unknown property at check time. `apps/portal` never met it because its `tsconfig` carries `lib: ["ES2023", "DOM", "DOM.Iterable"]`, which [ADR-095](../decisions/ADR-095.md) `F7` puts with the first page and [ADR-182](../decisions/ADR-182.md) section 6 moved to `W6-d`. **So the init type is widened in `client.ts`, pinned to the one value section 4 permits, and it becomes redundant rather than wrong the day `W6-d` lands the `dom` lib.**

**6.5 TWO SENTENCES IN THE BARREL WERE FALSIFIED BY THIS SLICE AND BOTH ARE REPAIRED IN IT.** *"there is no route, no client and no write path in it"* gained a client, so the clause is NARROWED rather than deleted and the two that still hold are named as the two the claim rests on; and the hatch's *"IT IS EMPTY TODAY AND THAT IS THE HONEST STARTING STATE"* stopped being true on the same commit. **This is `RI-14`'s error class in a file `RI-14` does not read**, which is the finding [session 332](2026-08-28-session-332.md) made about this same header one slice ago. **The two sentences the dispatch marked KNOWN were left alone**: [`pnpm-workspace.yaml:144`](../../pnpm-workspace.yaml) and [`index.ts`](../../apps/admin/src/index.ts)'s *"there is no server here"*, which is still true in fact until `W6-d` lands a page.
