### 2. Three absences, three words, and only the last of them is a gate

The segment's three inputs fail in three different ways and the type is what keeps them apart:

- **`no_api_origin`.** `MERIT_API_ORIGIN` is unset, so nothing is reachable. [ADR-162](../decisions/ADR-162.md) clause 1 refuses a default rather than guessing, and clause 1's refusal is per read.
- **`nothing_serves_it`.** No approved document defines a read that would answer this. The NFA disclosure text is the one instance and it is not an endpoint, so it is named as a read rather than as a path: writing a plausible `GET /content/:slug` here would be inventing exactly the thing [ADR-168](../decisions/ADR-168.md) clause 3 refuses one row up.
- **`refused`.** A ruling decided nobody will serve it. `RefusedRead` carries the entry that took the decision, so a reader who disagrees has somewhere to go.

The first two are `PendingRead` and reach `unavailable`'s `missing`. The third is a different type and cannot. **`unavailable.missing` is `readonly PendingRead[]`, so a `RefusedRead` in it is `error TS2741: Property 'why' is missing in type 'RefusedRead' but required in type 'PendingRead'`**, measured by seeding `missing: [NFA_DISCLOSURE_READ, ...REFUSED_READS]` into `loadFrom` and running `tsc --noEmit`.

On the screen the same distinction is two lists under two different words. **"Waiting on" is a promise that something is coming. "Not served" is a decision.** A screen that put the refused read under the first would be this application reopening a ruling by wording, which is [ADR-168](../decisions/ADR-168.md) foreclosure 7 exactly: *"it forecloses 'the application named it, therefore it is owed'."*

### 3. The comment the dispatch asked about, and why it is unchanged

The dispatch's job 2 read: *"`screen.ts:307` names `GET /affiliate/creatives` as something the screen is waiting for. That sentence is now false: nothing is coming."*

**The sentence is this**, unchanged since it was written and unchanged by this session:

> the only contract row that carries the text is the RESPONSE to `POST /affiliate/creatives`: there is no `GET /affiliate/creatives` and no read of the disclosure anywhere in API_CONTRACT.

It states an absence. It does not say the screen is waiting, and [ADR-168](../decisions/ADR-168.md) clause 3 does not falsify it: the clause **confirms** it and makes it permanent. That entry read the comment against all three of its clauses and said so in terms, calling `model.ts:182` and this one both survivors and giving the reason: *"a comment edited to look responsive to a ruling that did not touch it is drift."*

**So it survives as written, and the dispatch's own instruction is that saying so is the right outcome.** The only thing that changed in that docblock is its one-line summary, because the function underneath it now renders different words, and a paragraph after it recording why.

### 4. The rendering decision, which is the part that is a judgement

The dispatch assigned it: *"What the screen renders instead is yours to decide and to argue."*

The old copy was **"No creative has been submitted for review."** That is a claim about whether a submission exists, and this application can never observe it: the `null` branch is now reached on every render, permanently, by the same ruling. An affiliate who submitted a creative yesterday would read a false statement from Merit, on the surface `AS-M8-04` is a whole scenario about.

**No action is offered**, and the reason is structural rather than a taste: `ApiClient` declares `get` and no second method ([ADR-162](../decisions/ADR-162.md) foreclosure 1 and 3), and [`surface.test.ts`](../../apps/portal/test/surface.test.ts) asserts that nothing changing a trader account exists in this app. A submit control is a write, is money-adjacent, and is its own session.

So the screen **names the absence and declines the reading it would otherwise invite**:

> Merit serves this screen no record of creatives already submitted: a creative appears here only in the answer to its own submission. An empty space here does not mean nothing has been submitted.

`apps/portal/test/app-referrals.test.ts` asserts both halves and asserts that the old sentence is gone.
