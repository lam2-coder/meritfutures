**Objective.** Re-derive at source the guard [ADR-261](../decisions/ADR-261.md) says
`useCertificateBackend` waits on, establish whether the image port's remedy transfers to it, and
either close it and wire the port or say what closing it would cost.

**Outcome.** The guard is written, the port is wired, and the remedy transfers with one difference
that only the source gives: the image port has one read method and this one has two arms with no
channel between them.

---

### 1. What the row asked to be established first, and what the source added

**ADR-261's claim is right and it is a claim about TIMING.** Its clause 11 reads that what is
missing is *"a check that reads the origin BEFORE the caller's rows are read, and refuses the whole
request"*. **That sentence names when and does not name where**, and where is the whole of the work.

| Fact | Where it is, at source |
|---|---|
| `links` is called only for a row that is not deferred | `projectCertificate` returns three nulls on `state === 'deferred'` **before** `const minted = links(row.code)`. No other path |
| `readCertificates` is called on every request, before any row state is known | the list handler awaits it, then hands `renderCertificates` a `(code) => wired.links(code)` |
| Both arms are read off one capture | `const wired = backend`, so a setter call mid-request cannot split them |

**So the place is `readCertificates`, and it is the only one.** Not the factory: that runs at module
scope in `start.ts`, so a refusal there aborts the process at import and takes down every route in
the deployable including the nine already wired. **No port in this tree behaves that way**, and
[ADR-226](../decisions/ADR-226.md)'s rule is that an absent secret is a refusal, which is a
response.

---

### 2. Whether the remedy transfers, which is the question the row actually asked

**IT DOES, AND THE ANSWER WAS NOT AVAILABLE BY ANALOGY.**

| | `CertificateImageSource` | `CertificateBackend` |
|---|---|---|
| Arm every caller reaches | `lookup(code)` | `readCertificates(session)` |
| Arm a deferral does not reach | the render, **inside** `lookup` | `links(code)`, a **separate synchronous method** |
| Where configuration is read | first line of `lookup` | first line of `readCertificates` |
| What the second arm does | the render runs `assertCopy` again | `links` resolves the same origin again |

**THE ONE THING THAT DOES NOT TRANSFER IS "READ IT ONCE".** There is no channel from the read arm to
the mint, and there is not supposed to be: [ADR-249](../decisions/ADR-249.md) clause 6 passes `links`
a `code` and nothing else on purpose. The second read is safe because both are the same pure function
of the same `Environment`, and it is precedented in the file ADR-261 wrote.

### 4. Landmines for the next session

- **A SUMMARY THAT NAMES A TIMING HAS NOT NAMED A PLACE, AND ON A TWO-ARM PORT THOSE ARE DIFFERENT
  FACTS.** ADR-261's sentence was correct and would have been transcribed into the wrong arm by
  anybody who read it without opening `projectCertificate`. **The row was right to insist.**
- **`routes/verify.ts` IMPORTS `routes/certificates.ts` AT RUN TIME.** `CERTIFICATE_KINDS`,
  `REVOCATION_CLASSES` and `narrowClaims`. So an import back for `VERIFY_PATH` is a real module cycle
  and not an erased type edge; the path is written out a second time and **bound by a test**. A seed
  that moved one spelling turned three cases red.
- **`certificates.code` HAS NO ALPHABET CHECK IN DDL.** What keeps it sane is `RI-22` and the mint
  being the only writer, which is a property of this tree rather than of the database, so the link
  builder percent-encodes. That is a mitigation and not the bound
  ([ADR-235](../decisions/ADR-235.md) section 6.1 still owes it).
- **A CASE THAT PINS AN ABSENCE IS A CASE THE NEXT ENTRY FALSIFIES, AND THE REWRITE IS WHERE THE
  BETTER ASSERTION IS.** `start.ts installs the composition and does NOT install the list backend`
  was ADR-261's and was true. Its replacement asserts the PAIR, which is the stronger claim and the
  one the prose had been carrying for four entries.
- **`pnpm vitest` IS NOT A SCRIPT IN THIS WORKSPACE.** `npx vitest run` or `pnpm test`.
- **DEPENDENCIES ARE NOT INSTALLED IN A FRESH CONTAINER.** `pnpm install` first.
- **A BASELINE IS CHEAPEST IN A WORKTREE.** `git worktree add <dir> origin/main`, `pnpm install`,
  `npx vitest run`, then `git worktree remove --force`. No stash, no risk to the working tree.
