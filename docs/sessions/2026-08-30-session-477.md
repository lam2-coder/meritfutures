### 1. The objective

**[ALLOCATION](../decisions/ALLOCATION.md) row `286`, the second of the three obstructions `usePayoutBackend` names, and a RULING before it is any code.** [ADR-283](../decisions/ADR-283.md) landed the plan-rules codec and explicitly REFUSED to take the size row's decoding, on the ground that the two readers that exist read two different sources under two different key spellings, so a canonical decoder has to make one caller rename, _"which is a ruling somebody owns"_. This row owns it. The fence permitted collapsing the two adapters ONLY IF the ruling was to collapse them, and the row said in terms that a ruling the rename is not worth it is a complete outcome.

### 2. Both readers, re-derived before anything was written

The row's first instruction, and the reason for it was that the entire case for treating this differently from the rules blob rested on the spelling difference being real.

| Claim | Read at |
| --- | --- |
| `apps/worker` reads camelCase | `size_cents: bigintOf(row, 'sizeCents', at),` at `apps/worker/src/batch/adapter.ts:1304` |
| `apps/site` reads snake_case | `size_cents: bigintCents(field(source, 'size_cents', where), ...)` at `apps/site/src/catalog/adapter.ts:498` |
| `packages/db` is the source of the first spelling | `sizeCents: bigint('size_cents', { mode: 'bigint' }).notNull(),` at `packages/db/src/schema.ts:442` |
| `catalogRowAt` returns `Promise<unknown>` | `packages/db/src/scoped-db.ts:3620` |
| the schedule column is `jsonb` holding cents | `packages/db/migrations/0004_catalog.sql:168` |

**All held.** The difference is real, so the row's premise survived and the ruling had to be made rather than dismissed.

### 3. What the manifests said that the readers did not

**The readers show WHICH spelling each uses. They do not show WHY, and the why is what decides the ruling.**

`apps/site`'s dependencies are `@merit/rules-engine`, `next`, `react` and `react-dom`. **It declares no `@merit/db` at all.** `apps/worker` and `apps/api` both declare it. So the split is not two naming tastes to be reconciled; it is a database-side reader and a wire-side reader, each spelling its own source correctly, sharing nothing but the name of their output type. **Two decoders over two different inputs are not `FM-16`**, which is one predicate stated twice.

### 4. The third reader, which is why the count was two

`readSize` (`apps/api/src/routes/catalog.ts:1242`) reads the same table off the same `firm` handle under the same driver spelling as `apps/worker`, and returns a LOCAL row type carrying `price_cents` and `reset_price_cents` and omitting the four floor-lock and daily-loss fields the engine's carries. **A census of the ENGINE type's producers cannot see it.** That is why [ADR-283](../decisions/ADR-283.md) found two, and it is also why the payout path needs no rename: it is already on the driver side.

### 5. The residue, named

A driver-side decoder is needed by exactly the two deployables that declare `@merit/db`, and there is no place both can reach. `RI-01` forecloses the engine, and `apps/api`'s dependency list does not carry `apps/worker` and could not. **So `plan` waits on a HOME.** [ADR-286](../decisions/ADR-286.md) section 5 names both candidates and says which is smaller.

### 6. The finding that was not the objective

The cap schedule is decoded three times under identical keys, and `apps/api`'s copy rounds a payout ceiling past `Number.MAX_SAFE_INTEGER` instead of refusing it. It is two words from correct and it is outside this fence. **The suite asserts the divergence as a live property and is written to go RED on the repair**, which is how the item closes rather than being remembered.

### 10. Landmines

- **A census by NAME and a census by QUOTED KEY are different questions and the first one looks right.** Asking for `cap_cents` anywhere returned eleven files, five of them consumers reading a field off an already decoded value. Only a file that reads the key as a STRING is decoding.
- **A file-wide question about a guard reports the wrong answer when the file has two readers.** `apps/api/src/routes/catalog.ts` does use `Number.isSafeInteger`, in the helper for the `bigint` COLUMNS, and a file-wide assertion reported the divergent `jsonb` reader safe.
- **[ADR-283](../decisions/ADR-283.md) counted producers of a TYPE where the question was about readers of a COLUMN**, and its count of two was wrong for that reason after a careful measurement one session earlier. Any census in this area can be wrong the same way, which is why both are executed on every run rather than written down.
