### Done

**The shell.** `apps/site/next.config.mjs`, `src/app/layout.tsx`, `src/app/build.ts`, `src/app/chrome.tsx`, and ten `page.tsx` modules. `pnpm --filter @merit/site build` exits 0 and prints `/`, `/blog`, `/faq`, `/legal`, `/plans`, `/plans/[slug]`, `/plans/[slug]/rules`, `/plans/[slug]/rules/[size]`, `/restricted-jurisdictions`, `/stats`, and `_not-found`.

**No render logic was rewritten.** `routes/plans.ts`, `routes/rules.ts`, `routes/stats.ts`, `routes/legal.ts`, `routes/geo.ts`, `routes/page.ts` and `routes/paths.ts` are unchanged, and every page calls into them. `SITE_SURFACES` is the navigation and `derivedPaths`' three per-version addresses are the three dynamic routes.

**`INV-M9-01` holds by import.** No page declares a plan shape. `PlanRulesJson` and `PlanVersionSizeRow` reach the pages only through `@merit/rules-engine`, exactly as `apps/site/package.json` says they must.

**`INV-M9-05` moved to the layout and did not weaken.** The footer is on every page structurally. The disclosure a dispute quotes is a `content_documents` row and no endpoint serves one, so `siteDisclosure` returns `null` rather than minting a block carrying a provenance no row backs, and the footer falls back to the GLOSSARY sentence marked as an interim source. `page()` and `planPage()` still refuse a null disclosure, so a marketing surface with no citable block renders no marketing copy at all. That split is `apps/portal/src/app/layout.tsx`'s move, copied rather than re-derived.

**Nothing reads a clock.** `catalog/types.ts` states that "NOTHING IN THIS APPLICATION CALLS `Date.now()`", so the build stamp is read from `MERIT_SITE_BUILT_AT`, validated as an ISO-8601 UTC instant, and cast in exactly one place. A build handed none has no stamp rather than a fresh one.

**`CI-07` builds both UI deployables** and the false comment above it is repaired in the same diff.

### Landmines

**`apps/site/src/app/tsconfig.json` exists and is load-bearing.** Vite resolves a tsconfig per file and the nearest wins, so the app's `jsx: preserve` (ADR-095 `F7`) reaches Vitest as invalid syntax and the suite fails to load before one assertion runs. This file overrides `jsx` for that directory only. It is `apps/portal/src/app/calendar/tsconfig.json`'s mechanism, and that file already records that a root-level `esbuild` block in `vitest.config.ts` was tried and does not work. `next build` was re-run after adding it to confirm Next does not read it.

**`next build` type-checks `apps/site/test/**` too**, because the app's `tsconfig.json` includes it. A test file that only Vitest would have caught fails the production build instead, which is the safe direction and is surprising the first time.

**`process.env` is not `NodeJS.ProcessEnv` here.** `next-env.d.ts` augments `ProcessEnv` with a required `NODE_ENV`, so a test supplying two variables cannot name that type. `build.ts` exports `SiteEnv`, a plain record, for that reason.
