### 4. The counterexample this entry was handed, and it was in a file the dispatch did not name

[`apps/api/src/events.ts`](../../apps/api/src/events.ts) states one in its own header and
calls it *"the counterexample any sixth class has to answer"*. `payout.freeze_expiring`'s
catalogue payload is `{ payout_request_id, flag_id, expires_at, lead_hours }`: an event
about one trader's frozen payout naming **neither** tenancy column.

**The answer is that a row's tenancy columns and its payload are different things.**
EVENTS.md says of `wallet.credited` that `account_id` is *"resolved through
`reference_id` at write time and is carried because TL in section 2's legend is a
per-account view"*. **A producer resolves the row's tenancy from what it has, whatever
the payload happens to name**, and a `payout.freeze_expiring` producer holds a
`payout_request_id` that names an account.

**So it is a PRODUCER defect and not a hole in the class, and it is the sharpest open
item because the failure is SILENT.** The row belongs to nobody, nothing raises, and the
absence is indistinguishable from the event not having happened. **No scope class fixes
it and section 10 of the entry is why no constraint can either.**
