### 1. What the check is, and the one thing it refuses to be

The invariant: every declaration of a name in `SUBJECTS` carries the same field set. Both halves are read live on every run, out of their own source. **There is no stored list of fields anywhere in the check**, which is the whole difference between it and the fourth copy of the shape it would otherwise be. [ADR-034](../decisions/ADR-034.md) deletes a second enumeration of a thing wherever it finds one, and [ADR-185](../decisions/ADR-185.md) ruled the same question one document over this morning: generate the value or delete it and point at the source, there is no third.

A copy is reduced to a set of **field paths**: `as_of`, `reserve.rcr_bp`, `per_plan[].cusum.statistic`. An optional member carries a `?`, so a field made optional in one copy alone is two findings rather than none.

**Four things a green result does not cover**, each stated in the file's own header rather than discovered later:

| Not covered | Why |
| --- | --- |
| Leaf types | `open_liability_cents: number` against `: string` is invisible. Comparing types across a markdown fence, an `interface` and a `type` alias needs a normalisation ruling nobody holds |
| `readonly` | Present in both code copies, absent from the contract by house style. Comparing it reports every field of every shape as diverging on day one |
| A value a handler builds | That is `tsc`'s finding |
| Every shape the contract declares | Section 5 below is the measurement, and it is a scope decision rather than an omission |

### 2. Where it lives, and why it beat the precedent rather than following it

Session 342 wanted `RI-17` in `repo-invariants.mjs`, **measured** that it could not be, and landed it in `apps/api/test/` instead. Its three disqualifiers were re-measured on this branch and **every one is absent here**:

| Session 342's disqualifier | This check |
| --- | --- |
| `packages/tooling` cannot resolve `@merit/api` | **Imports no deployable.** It reads files as data, which `RI-08`, `RI-09` and `RI-10` already do across every deployable |
| It cannot resolve `fastify` either | **Needs neither** |
| `Invariant.run` is synchronous, `discoverRouteModules` is not | **The parse is synchronous** |

And the reason that session refused the fallback does not reach this check, on a **difference in kind rather than in degree**. It refused reading `routes/*.ts` as TEXT because a grep over route files has been wrong twice here *and* because a strictly better input existed: `CompositionReport.registered` over a real `compose()` answers "which routes exist" and a regex does not. **There is no such better input for a type.** A TypeScript type is erased before anything runs, so no composition, no import and no runtime value can be asked what fields `LiabilityResponse` has. The declaration is the only source there is.

So the reading is a **parse and not a grep**. `typescript` is already a devDependency of `packages/tooling` and `pnpm install --frozen-lockfile` installs it in every CI job, so nothing is added to any manifest. Its parser reads the contract's fenced block, `apps/api`'s `interface` and `apps/admin`'s `type` alias under one grammar; it **follows** a type reference rather than comparing it as a leaf, which matters because `admin-reads.ts` factors `eligible_next_7d` out into `EligibleNext7d` and a reader that stopped at the name would report agreement about a nested shape it never opened.

**The cost is stated rather than absorbed.** A static `import ts from 'typescript'` is 465ms on every invocation of `repo-invariants.mjs`, including the `RI-01` single-check form its own usage line advertises. It is loaded lazily inside `run` through `createRequire`, typed `@type {typeof import('typescript')}` so nothing is bought with an `any`.
