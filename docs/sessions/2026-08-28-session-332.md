### 2. What was taken from `admin-source/index.ts`, and what was not

**[`apps/api/src/admin-source/index.ts`](../../apps/api/src/admin-source/index.ts) carries two independent defences and its header argues both. Only one of them transfers, and the reason is written down one file over rather than discovered here.**

**THE `Pick`-OVER-DATA HALF DOES NOT TRANSFER.** [`IMPLEMENTED_ADMIN_READS:178`](../../apps/api/src/admin-source/index.ts) is data and the return type is a `Pick` over it, so dropping either half is a type error naming the member. That shape needs a runtime OBJECT for the type to be taken over. **A barrel of re-exports has no such value**, and [`apps/worker/src/index.ts`](../../apps/worker/src/index.ts) already records it: *"there is no value here for a type to be taken over, so the same trick does not transfer and forcing one would mean minting a runtime object whose only purpose is to be checked."* Minting one would put a second copy of the surface in the file whose entire job is to hold one copy of it.

**WHAT TRANSFERS IS THE PRINCIPLE: ONE DEFENCE IS NOT ENOUGH AND THE TWO MUST FAIL AT DIFFERENT TIMES.**

| Half | Where it lives | What it catches | What it cannot catch |
|---|---|---|---|
| **A, compile time** | all 74 names imported FROM THE BARREL by name, each bound to its own module's declaration | a name DELETED from `index.ts`, as a `tsc` error naming the member, before any suite runs | a name that was **never added**, because a name nobody imports is a name nobody misses |
| **B, run time** | each module's SOURCE read as text, the barrel asserted to re-export every name it declares | a name never added, which is what all 23 were; and a whole module the barrel never met | it fails at test time rather than at build time, and it reads presence rather than identity |

**NEITHER SUBSUMES THE OTHER**, and `B.4` is a third property neither can reach: the barrel's binding must BE the module's binding, so a name re-exported from the wrong place fails **while it is present in the text and type-checks**.

**`B.5` KEEPS SECTION A HONEST IN THE ONE WAY IT COULD ROT SILENTLY.** Section A is hand-written, and a name added to a module and to the barrel but not to section A would leave `tsc` covering less than it appears to. The covered set is **derived from the test file's own source** rather than kept in a second list, so what is counted is exactly what `tsc` reads, and it is compared against the modules in both directions.
