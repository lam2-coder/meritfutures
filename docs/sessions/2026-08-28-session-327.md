### 2. THE FINDING: the openness was at one line, and the allocation row said it was at a call site

The row this session was dispatched under says the stake is *"a redaction profile somebody invents at a call site"*. **Measured on the base commit, no call site could invent one.**

`EvidenceRedactionProfile` read

```ts
export type EvidenceRedactionProfile =
  (typeof EVIDENCE_REDACTION_PROFILES)[keyof typeof EVIDENCE_REDACTION_PROFILES];
```

so it was **exactly the two values the map held**, at every call site, and `EvidencePackRow.redaction_profile` refused anything else. A handler writing `'redacted'` was already a type error.

**What was open is the map, and the map is annotated `Readonly<Record<EvidencePackAudience, string>>`.** `string`. Seeded on the base commit:

```
regulator: 'regulator-detail'   ->   pnpm run typecheck   exit 0
```

**A derived vocabulary cannot refuse a member. It is whatever its map says: a map wearing a type's clothes.** And the line it is open at is not an arbitrary line. **It is the line a vocabulary change is made on.**

**THE FAILURE THIS SHAPE ACTUALLY PRODUCES IS NOT A MALICIOUS EDIT, IT IS A LEGITIMATE RULING WITH A SIDE EFFECT.** `OQ-F4-03` asks whether an impersonation record appears in a regulator pack, [ADR-068](../decisions/ADR-068.md) section 3 puts it with counsel, and a ruling either way may give `regulator` its own profile. Under the derived shape that ruling is a one-line map edit that turns red **two assertions, both of which are about the MAPPING**, in a case whose own comment calls the mapping a transcription. A session whose ruling IS about the mapping reads those failures as "update me", updates them, and **the vocabulary has grown with nobody having argued the new member.**

Under this entry's shape the same edit is `TS2322` naming the type, at [`evidence.ts:252`](../../apps/api/src/admin-source/evidence.ts) and at `redactionProfileFor`'s return, plus a case that says the set is closed and why. The session then adds a member deliberately, or does not.

### 3. Why CLOSED, when the profile does not itself perform the redaction

**It is worth stating that the analogy to `SystemReason` is imperfect, because the entry rests on the part that survives.** `SystemReason` is an INPUT that grants authority: `systemDb(reason)` hands back a handle that reads every table. `redaction_profile` grants nothing. The redaction is performed by three other things: the allowlist projection, the computed sweep, and the refusal that throws.

**So what closing it buys is not authority. It is that the LABEL and the BEHAVIOUR cannot diverge.** [M06:301](../plans/M06-admin-ops-console.md) is explicit about what the column is for:

> *"Every export records which profile was used, so a later argument about what was disclosed is answered by a row rather than by memory."*

A free-text label lets two exports that performed the **same** redaction be labelled differently, and lets one row name a redaction **no code in this tree performs**. Neither is visible until the argument the column exists for is actually happening, which is the worst moment for the record to be unreadable. `AS-M6-01` sets the bar: [EC-071](../edge-cases/EC-071.md) prices the disclosure at one burned evaluation and the dossier says these groups coordinate, so the damage is permanent on a single occurrence. **A vocabulary closed by habit is closed until the first hurried session.**

### 4. What each member promises, and the three statements that are not the same length

**`GS-112` is the shortest of three approved statements of the same promise, and it is the one the code was built from.**

| Source | Positives | Negatives |
|---|---|---|
| [M06:485](../plans/M06-admin-ops-console.md), `GS-112` | five: fill, mark, rule state, gate result, the plan's rule text (plus the flag's fact and clause) | three: no detector parameter, no threshold, no other identity |
| [M06:299](../plans/M06-admin-ops-console.md) | **six**: the same, plus **the computation trace** | **four**: the same, plus **no comparison against a population** |
| [EC-071](../edge-cases/EC-071.md) | six | four |
| [wave 3 batch 1 gate closure](../decisions/gates/wave-3-batch-1-gate-closure-2026-08-14.md) | conduct, rule text, the trader's own trades | thresholds, detector internals, parameters and **population comparisons** at internal and counsel tier |

**A profile is a promise, so the promise is the UNION**, and the entry states it that way. Two consequences, one of which cost a test case and one of which cost a report.

- **The fourth negative was correct in the code and asserted by nothing.** A population comparison can only reach a pack through the `evidence` bag or a `detectors` section, and the trader projection admits neither, so it never arrived. Nothing named it. **It is carried by the ALLOWLIST rather than by the sweep**, which is worth writing down because a later session looking for "where is the population comparison stripped" will not find it in the strip list: a comparison is a name nobody registered.
- **The computation trace is in two of the three statements and is not in the tree.** Section 5.

**And one asymmetry in `full-detail` is stated because the name hides it.** `full-detail` bounds the DETAIL and never the SCOPE. The subject is one account: `readSubject` takes an account id, and `exportEvidence` refuses a subject whose `account_id` is not the requested one. **A reader who has not read M06 is likelier to misread that than to misread the detector question**, so it is asserted as its own case rather than left to the docstring.

### 5. Three things reported and not built, each an absence with a reason

- **THE COMPUTATION TRACE IS NOT A COLUMN AND THE PACK CARRIES ITS INPUTS.** `grep` for `computation_trace` over `packages/` and `apps/` returns nothing at all. [M01:772](../plans/M01-rules-engine.md): *"The nightly self-audit, the CI golden suite, the evidence pack's computation trace, and the live batch all call `advanceDay`."* **A trace is a REPLAY**, and `M06` section 3.2 asks the console to read the stored row rather than recompute, which is the same tension `SD-06` resolved for gate results one column over. Building it here would be reopening `GS-112`'s content, which this fence forecloses, and it is larger than a section: it is the rules engine invoked from an export path.
- **THE FREE-TEXT CHANNEL IS CLOSED FOR ONE NEGATIVE AND NOT FOR THE OTHERS.** `tos_clause` is prose an operator writes and `GS-112` REQUIRES the pack to carry it. The uuid scan reaches an identifier inside it **because a uuid has a shape a runner can match**, which is `P7-j`'s own repaired defect. A population comparison written in prose has no such shape, and neither does a threshold quoted in a clause. **The entry says which negative is mechanically enforced in free text and which are enforced by the operator writing the clause**, rather than claiming the sweep covers them.
- **`evidence.pack_exported` STILL CARRIES `redaction_profile` AND IS STILL NOT EMITTED.** `M06` section 6, and the catalogue is outside this fence as it was outside `P7-j`'s. The audit is not lost: `0008_risk.sql` calls export *"ITSELF AN AUDITED ACT"* about the ROW.

**And the closure's own limit, which is the fourth thing and is a clause rather than a report.** This ruling closes the vocabulary at the layer that COMPOSES the value and not at the layer that STORES it. [`0008_risk.sql:257`](../../packages/db/migrations/0008_risk.sql) is `text NOT NULL` with no `CHECK` while `audience` at [`:254`](../../packages/db/migrations/0008_risk.sql) has one, and [`schema.ts:1836`](../../packages/db/src/schema.ts) types the column `text`. **The DDL for both constraints is written out in the entry** and no migration number is taken: a merged migration is never edited and only superseded, and `packages/db/migrations` is another session's this wave.

### 6. Landmines

1. **`ADD CONSTRAINT` ON `evidence_packs` IS SAFE TODAY FOR A REASON THAT EXPIRES.** The table has no rows, because `EvidencePackWriter` is a port nothing implements. The day the operator door opens and the first pack is exported, the second constraint in the entry's DDL needs a backfill argument.
2. **THE ENTRY'S SECOND CONSTRAINT MAKES THE MAPPING A DATABASE RULE, AND THE MAPPING IS THE HALF MOST LIKELY TO MOVE.** `OQ-F4-03`. It is recommended and not written, and the argument is in the entry so its author inherits the reasoning rather than the conclusion.
3. **A PROMISE IS A SET AND ONE-AT-A-TIME ASSERTIONS DO NOT ADD UP TO ONE.** Section 7 is the receipt. Any future field added to `EvidenceFlagRecord` or to `EvidenceDocument` must be placed in an audience's promise deliberately, because the two exact-set cases will fail on it and the correct repair is a ruling about that field rather than an updated expectation.
4. **`full-detail` IS THREE AUDIENCES SHARING ONE NAME AND THAT IS RULED, NOT INCIDENTAL.** A session that gives one of the three its own behaviour must change the vocabulary and not only the map, and both are now diffs somebody has to argue for.
