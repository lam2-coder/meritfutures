### THE PLAN, written into the first commit rather than into plan mode

**This session has no human watching, so [P5](../plans/P5-payouts-and-wallet.md) section 11's plan-mode clause is discharged HERE**, in the stub commit rule 1 requires, and the plan is the thing the rest of the branch is measured against.

**Baseline reproduced on the dispatch SHA `552c918` BEFORE anything was written**, which rule 11 requires and which is the only reason any figure below will mean anything: 33 of 33 gates, 11 of 11 invariants, `typecheck` exit 0, `lint` exit 0, **170 test files / 3,115 passed / 6 skipped**. It matches the dispatch's stated baseline exactly.

#### 1. The shape, and it is `accounts.ts`'s rather than a new one

A `WalletBackend` PORT, an `UNWIRED_WALLET_BACKEND` that rejects every call and is answered **503**, a `databaseWalletBackend(db: ApiDb)` that reads through the accessor, and `withSessionContext` for the auth. That is [`accounts.ts`](../../apps/api/src/routes/accounts.ts)'s and [`payouts.ts`](../../apps/api/src/routes/payouts.ts)'s idiom unchanged, and its reason is theirs: *"a backend that returned plausible values would be a fixture serving real traffic"*. The route is REGISTERED either way, because the contract row exists and a missing route answers 404 and reads as a contract Merit never wrote.

**The projection is an allowlist built field by field**, section 1's API3 control, and never the accessor's row spread.

#### 2. The balance is the row with the greatest `id` and NOT the greatest `occurred_at`

`wallet_entries.balance_after_cents` is a STORED running balance, computed at APPEND time, so the current balance is the last row APPENDED. Ordering is `id`, which is `bigint GENERATED ALWAYS AS IDENTITY`. **The statement's ORDER is `occurred_at DESC` and that is a different question**, which the contract answers separately for `GET /wallet/entries`; a backdated `occurred_at` would make the two disagree, and only one of them is the balance.

#### 3. The cursor is composed in the ROUTE, and the inclusive bound is the argument `P5-a` invited

[ADR-157](../decisions/ADR-157.md) refused the aggregate and gave a RANGE term, so the page is composed from rows the accessor returns. `scoped-db.ts` names this slice by name: *"a cursor over `wallet_entries` is `P5-g`'s and an inclusive bound re-reads its boundary row, so if that is unacceptable it is an argument `P5-g` makes rather than one this entry makes for it."* **It is acceptable and this session makes no such argument.** The cursor carries `occurred_at` and `entry_id`, `atMost(occurredAt)` renders the inclusive bound, and the route drops the rows at or after the anchor's position under the full `(occurred_at DESC, id DESC)` order. A strict inequality would still not be enough, because the tie-break is a second column and no term in the vocabulary is a tuple comparison.

#### 4. THE COST ADR-157 SECTION 5 NAMES IS PAID HERE AND ITS SIZE IS RECORDED

*"The rows crossing the boundary are the window's rather than the match's."* Concretely: `GET /wallet` reads the identity's WHOLE statement to render one balance, and `GET /wallet/entries` reads every entry at or before the cursor's instant to render one page of at most 100. There is no `LIMIT` and no `ORDER BY` in the accessor and this slice adds neither.

#### 5. What is expected to be a FINDING rather than a transcription

**`held_cents` under `chargeback_window` has no input in this tree.** [ADR-158](../decisions/ADR-158.md) clause 6 makes `available_at` null because no landed column carries a purchase's chargeback-window end; the same absence decides MEMBERSHIP of the hold and not only its release. This is measured before it is written up, and it is reported rather than papered.

No `SqlExecutorReason` member, no `SystemReason` member, no `pg` import, no cast past a key type, no edit to [`scoped-db.ts`](../../packages/db/src/scoped-db.ts), no ADR, no migration. Money is `bigint` cents inside the file and a JSON integer on the wire, refused rather than rounded. The fence is [`apps/api/src/routes/wallet.ts`](../../apps/api/src/routes/wallet.ts), [`apps/api/test/wallet.test.ts`](../../apps/api/test/wallet.test.ts), [STATE](../STATE.md) appended at the END, and `docs/sessions/`.
