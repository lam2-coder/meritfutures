### 3. THE RULING

**RULED: certificate revocation CANNOT be served by this deployment.** Three obstructions, section 5 of [ADR-359](../decisions/ADR-359.md), none of them this row's to decide.

**RULED: what a request does today is CORRECT and is not changed.** It refuses, writes nothing, and invents nothing.

**RULED: the refusal's shape is the GOOD one.** `UNWIRED_ADMIN_CERTIFICATE_BACKEND` has no live arm: all four members refuse and each names itself, so there is no plausible value a caller could mistake for an answer.

**RULED: the wire-level muteness is correct and STAYS, and the log is therefore load-bearing.** That is the one thing about the tree this row changes: the log line is now a held control instead of a comment.

### 4. What a request does today, walked rather than inferred

The dispatch asked for a silent success to be checked first. **There is none, and the reason is an ordering.**

1. `:676` returns the unwired default (`:397` initialises it and nothing under any `src/` reassigns it).
2. `:689` `await active.principal(request)` is the **first** member touched; the default rejects.
3. `:691` catches, `:692` logs at error level, `:693` answers **401 unauthenticated**.
4. `active.operator(...)`, the only thing in the module that opens a transaction, is **never reached**.

| asked | measured |
|---|---|
| 500? | **No.** Both legs catch, and the outer catch re-throws only what is neither a `Refusal` nor unwired/unconfigured |
| silent success? | **No, and it cannot be.** The refusal is one statement ahead of the transaction opener; the recorder observes an empty call list |
| refuses cleanly? | **Yes, at 401**, not the 503 the class docblock advertises |

**THE 503 MOVED BEHIND THE 401 AND IS UNREACHABLE FROM THE FULL DEFAULT.** `:366` reads *"Answered as 503, never 500"*, which is true of three members and false of the one reached first. The `:738` branch is live only for a partially installed backend. **The docblock is not edited**: the sentence is about the class and is true of the class. It is recorded because a reader grepping for `503` would otherwise predict the wrong status for the deployment as it stands.

### 5. Which channel discriminates, and the finding that follows from it

| channel | what it carries |
|---|---|
| **the wire** | `401 unauthenticated`, **indistinguishable** from a genuinely anonymous caller's document. Same `type`, `title`, `status`, `code`; only `instance` differs |
| **the log** | `request.log.error({ err }, ...)` at `:692`, carrying the error itself, whose message names the refusing member **and** `useCertificateRevokeBackend` |

The muteness is deliberate and the handler argues it: whether this process holds a backend is a fact about the deployment, and an unauthenticated caller may not have it.

**THE CONSEQUENCE IS THE FINDING. Because the wire says nothing, the log is the ONLY place the fact exists**, and an operator with valid credentials gets the same 401, because `principal` refuses before consulting any session. **The wire tells them their credentials are wrong.**

**And nothing executed was holding it.** Deleting `:692` left the suite GREEN.
