#### 3. The ruling, and what it forecloses

ADR-023's rollout is graduated and step 1 is observe mode: *"Signals recorded, scored, and reported; nothing is blocked. The purpose is to learn the distribution on Merit's own traffic."* Step 3, the soft decline plus review queue, is not this session's. **So there is no code path in this slice where an enrichment outcome changes what checkout returns, and that is asserted rather than promised.** Three structural controls carry it, in preference to a comment:

1. **`observeEnrichment` returns `Promise<void>`.** There is no value for a call site to branch on. This is [`packages/psp`](../../packages/psp/src/port.ts)'s second rule ("nothing in the interface returns a decision") tightened one notch, because the psp port at least reports what the provider said and this one reports nothing at all to its caller.
2. **It never throws.** Every failure direction is caught inside it. A throw inside checkout's transaction is a rollback, so a throwing enrichment call is enforcement by exception, which is the "silent decline" ADR-023 forbids even in the mode that is allowed to decline.
3. **The package contains no decision vocabulary at all**, and a test greps its own source to prove it: no `severity`, no `decline`, no `refuse`, no `block`, no threshold constant and no mapping from a score to a `risk_flags` band. A scorer that silently gains authority is the failure this ruling forecloses, so the absence is a mechanical assertion.

#### 4. Where the signals go, and the one place the corpus made this a decision

`identity_signals.kind` carries `footprint_enrichment` as `U-04`, added for exactly this vendor ([`0002`](../../packages/db/migrations/0002_identity.sql) and [`0029`](../../packages/db/migrations/0029_phone_identity_and_auth.sql)), so the recorded half has a home the corpus already built. **The scored half does not, and inventing one is a migration this fence forbids.** The available shape is `risk_flags`, whose `source` column is reserved `'vendor:<name>'` in its own DDL comment "so a vendor detector plugs in without a migration", and **this session does not write one.** Three reasons, and the first is the corpus's own precedent:

- **`D-12` already ruled this shape for a detector that observes without accusing:** *"Output is a watched-cluster set, not a flag: it seeds D-13 and D-14 rather than accusing anyone."* Observe mode accuses nobody by construction.
- **`risk_flags` is money-adjacent and a severity is not a score.** [ADR-040](../decisions/ADR-040.md)'s `G-HOLD-REQUIRED` holds a payout on an unresolved flag of severity 4 or above, and [M03 section 7.9](../plans/M03-billing-checkout.md)'s open question on whether the same band should stop a purchase is still open. Writing a severity from an untuned score would let this slice acquire authority over money going out while claiming to have none over money coming in.
- **A flag per checkout is a queue nobody works**, and `risk_flags.status` defaults to `open`.

**So the score is computed, carried in the reported outcome, and has no persisted column until a migration gives it one.** That is stated in the pull request body and in [ADR-115](../decisions/ADR-115.md) rather than papered over by writing a band into `value_preview`, whose DDL says it is a display fragment of the value it previews.

#### 5. What the accessor permits, which decides the write shape

[ADR-112](../decisions/ADR-112.md) landed in [#301](https://github.com/lam2-coder/meritfutures/pull/301) today: `rowAt`, `updateAt` and `deleteAt` name ONE row, `scopedDb` ANDs its tenancy predicate onto the address, and `update` and `delete` no longer exist on any handle. Two facts read out of it decide this slice's shape:

- **`identity_signals` has exactly one addressable key and it is `id`.** `uniqueKeys` reads Drizzle's table config for inline and table-level primary keys and unique constraints, and **it does not read a `uniqueIndex`**. `identity_signals_identity_kind_value_uq` is a `CREATE UNIQUE INDEX` in [`0002`](../../packages/db/migrations/0002_identity.sql) and [`schema.ts`](../../packages/db/src/schema.ts) declares no key for it, so `updateAt('identitySignals', { kind, valueHash }, ...)` is refused by `refuseUnaddressed`. **A repeat observation is therefore a `rowsWhere` then an `updateAt` addressed by `id`.**
- **A blind insert would roll back the purchase, and on the most ordinary path there is.** A returning trader buying a second account presents the same enrichment values, the unique index raises `23505`, the error poisons checkout's transaction and Postgres turns its `COMMIT` into a `ROLLBACK`. **That is enrichment blocking a checkout through the database rather than through a decision**, and it is precisely the outcome this ruling forecloses. Reading before writing is what avoids it.

#### 7. The timeout, and what happens on each side of it

`ENRICHMENT_TIMEOUT_MS` is **800**, integer milliseconds, and it is a constant this package exports rather than a number a call site passes, so an operator reading one file learns the whole latency budget checkout carries for this. When it fires: the pending vendor promise is **abandoned and its eventual rejection swallowed**, so a late failure cannot surface as an unhandled rejection after the request is gone; nothing from the vendor is recorded, because there is nothing to record; the outcome `timed_out` is reported to the injected sink, which is what [RB-11](../ops/runbooks/RB-11-verification-provider-outage.md) step 5 means by watching the enrichment vendor separately; and **`observeEnrichment` resolves normally, so checkout commits.**

**Cost if wrong:** observe mode silently becomes enforcement by outage, which is the silent decline ADR-023's step 3 forbids even when enforcement IS enabled.
