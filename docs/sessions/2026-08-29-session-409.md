### 2. The verb

**Measured through a real `compose()`**, which dispatch protocol section 5 makes
the only reliable source: the `public` surface registers **46** routes and
withholds **27** of **73** declared, and the 46 are **24 `GET`** and
**22 `POST`** with no other method. Three of the 22 are provider webhooks, so
**19 trader writes** were unreachable before this session and are unreachable
by any page after it.

`post` takes one argument, returns the same `ApiResult` the read does, adds no
member to `PortalErrorKind`, and shares the response mapping with `get` rather
than copying it.

### 3. The CSRF ruling, and the gap it found

**No token is minted here**, on three measurements: nothing on the server reads
one, this client's request is not a browser request and no page can cause one to
be issued, and `SameSite=Lax` already closes the cross-site case.

**What `Lax` does not close is the same-site case, and Merit's trader surfaces
share a site.** [`INFRA`](../architecture/INFRA.md) section 2.1:

| Service | Origin |
|---|---|
| `site` | `meritfutures.com` |
| `portal` | `app.meritfutures.com` |
| `api` | `app.meritfutures.com`, under `/api/v1` |

Those two hostnames have one registrable domain, so a request issued by a page
on the marketing origin to the API is **same-site**, `Lax` permits it, and the
host-only `merit_session` cookie is sent because the destination host matches.
**The corpus already reasons this way one origin over**: `INFRA` hard rule 3
puts the admin console and `api-admin` on a **separate apex domain** and states
that cookie scope, CORS and the CSP never span the two. The operator surfaces
were separated at the site boundary on purpose. The trader surfaces were not.

**It is registered rather than repaired**, because the control is a server-side
one and `apps/api` is outside this fence by the row's own terms.

### 4. Two things `post` cannot do, and both are said out loud

**It cannot deliver a session.** Three registered `POST`s answer with a
`Set-Cookie` and this client receives all three and delivers none:
`next@16.3.2` permits a cookie write only in a Server Action or a Route
Handler, and [ADR-138](../decisions/ADR-138.md) section 3 with `RI-11` refuse
the first outright. **So `post` is necessary and not sufficient for sign-in**,
independently of session 408's finding that the served set admits no complete
sign-in, and this half does not lift when delivery lands.

**It cannot read a problem document.** `409 conflict` and
`409 idempotency_key_reuse` both land on `unexpected`, and `required_factor` on
a `403` is unreachable. That is `shell/app-shell.ts`'s vocabulary rather than
the transport's, and the first caller of `post` will meet it.

### 5. Eleven prose sites, repaired

The sentence "`ApiClient` declares `get` and nothing else", or one of its
spellings, was load-bearing prose in **eleven** places across nine files, every
one outside this fence and every one false the moment `post` landed. They were
repaired in a commit of their own, each site's surviving conclusion preserved
and only its dead reason replaced. **Every control named at those sites is
still inert and every `submits_to` and `revokes_at` is still the literal
`null`.**

**Two more were forced by gates rather than by judgement**, and both are the
direction a control should fail in: `RI-15` on two pointers the insertion moved
in `app/payouts/page.ts`, and `kyc-source.test.ts`'s assertion that
`Object.keys(client)` was exactly `['get']`, which was a guard on the very fact
this session changed.

### 6. This session's own two false claims

**Recorded rather than folded away, because they are the defect class this
slice sits inside.** The first commit's section 6.1 quoted
`grep -rni csrf apps packages` and said it returns nothing; it returns 16 lines,
because the section making the argument is itself under `apps/`. The claim the
argument needs is `grep -rni csrf apps/api packages`, which does return nothing.
**`RI-20` would not have caught it**, and the sentence was written believing a
runner would settle it.

The second was a literal **NUL byte** in the illegal-key table, where `'a b'`
was intended. The case asserting that an internal space is refused was really
asserting that a NUL is; an internal space is legal in an HTTP field value and
the guard accepts it. Every control character in that table is now an escape,
and the acceptance direction asserts the boundary explicitly.

### 7. Declined inside the fence

**`ApiSuccess` does not gain a status.** Four segments already reported wanting
one and each refused because `client.ts` was outside their fence. This session
holds that fence and still declines: adding the field would make those four
sentences false in four files this fence does not hold, which is four new stale
citations bought to save one, on the day this session repaired eleven of that
exact shape. The slice is one type change plus five call sites, over `client.ts`
and the four segments together.

### Landmines

- **`post` exists and nothing calls it, which is a state a later session can
  misread as an oversight.** It is not: [ADR-190](../decisions/ADR-190.md) is
  why, and wiring one is a deliberate slice with the problem-document question
  attached.
- **Section 3's second measurement is the one that ages.** It reasons that no
  browser calls this API. The day a browser-side client is admitted for any
  reason, clause 1 becomes a client refusing to send a token in exactly the
  situation a token is for, and the only guard is `surface.test.ts` holding
  `fetch(` at one file, which catches the accident and not the deliberate
  widening.
- **The `204` arm is keyed on the status alone.** If `apps/api` ever answers
  `204` with a body, or `200` with none on a route that means success, the arm
  is on the wrong side of that line and nothing here would say so.
- **`DISPATCH_PROTOCOL` section 4 still reads "It was 18 when this row was last
  repaired".** The runner's own last line reports **19**. That file is outside
  this fence, and this is the seventh session to report the drift without
  repairing it.
