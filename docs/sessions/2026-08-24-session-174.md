- **Landmines:**

  - **`ADR-017`'s TITLE AND ITS DECISION LINE ARE DIFFERENT CLAIMS, AND ONLY ONE OF THEM IS TRUE OF THE MERGED TREE.** The title is *"Every outbound payment in Merit uses one rail and **one transfer table**"*. The decision line is *"**One rail, one destination table, one detector.**"* [Session 162](2026-08-24-session-162.md) quoted the title, read it as *"`payout_transfers` widened"*, and rowed the question as one it could not determine. **It is determinable and the answer is in the same file**: `wallet_withdrawals` at [`0011:126`](../../packages/db/migrations/0011_wallet.sql) is a merged second transfer table with no foreign key to `payout_requests` or `payout_transfers` and its own `destination_ref text NOT NULL` at [`0011:132`](../../packages/db/migrations/0011_wallet.sql), ruled by [ADR-028](../decisions/ADR-028.md) and `SD-M5-06`. **The title has been false since that migration and the decision line has never stopped being true.** A title is a shorthand for a ruling the entry's own body owns, which is [ADR-037](../decisions/ADR-037.md)'s shape one level up from a parameter.

  - **M08 SECTION 3.4 PERFORMED TWO OF ITS THREE PREMISES AND CITED THE THIRD, AND THE ONE IT CITED IS THE ONE THAT IS FALSE.** Row one quotes a migration line. Row three is an execution (*"Nothing read `identities.status` on this path"*). **Row two, *"There is one outbound rail and one destination check"*, is marked TRUE on the strength of [ADR-017](../decisions/ADR-017.md), `INV-M8-10`, `INV-M8-11` and `AS-M8-05`: four documents and not one migration line.** That is the precise object section 3.4's own next paragraph names, *"a control that exists in the paragraph explaining why the attack fails, and nowhere that binds, is the attack succeeding on schedule"*, arriving inside section 3.4's own evidence column one row above where it was written. **This is what makes the two halves separable**, which the brief required and which the table answers itself: the authorization half is ruled and `INV-M8-12` is its remedy; the mechanism half is this session's and it is false at the migration.

  - **`paid_transfer_ref` IS NOT A SECOND SPELLING OF THE DESTINATION, AND THE CORRECTION CHANGES WHAT A MIGRATION WOULD WRITE.** [Session 162](2026-08-24-session-162.md) calls it *"the second spelling [ADR-017](../decisions/ADR-017.md) exists to refuse"*, and the same log proves otherwise three landmines later: `grep -in destination` over [`0005`](../../packages/db/migrations/0005_affiliate_program.sql) and [`0012`](../../packages/db/migrations/0012_disputes_and_affiliate_settlement.sql) returns **zero lines**, so there is no first spelling for it to be the second of. **Both halves of that log are true and they name two different objects.** The distinction is load bearing because `D-09` is a **concentration** query and concentration is only expressible over an identifier that **repeats**: [`0010:290`](../../packages/db/migrations/0010_payouts.sql) declares `payout_transfers_provider_transfer_uq` **UNIQUE** on `(provider, provider_transfer_id)`. **A `D-09` grouped on a transfer identifier returns groups of size one on every input, forever**, so the cheapest available repair, renaming `paid_transfer_ref` and wiring it in, makes the strongest mule detector in the system report clean from inside the query with the row present. **That is strictly worse than the visible absence it replaces**, and it is why the ruling names a column contract rather than a foreign key.

  - **THE `gen:adr_count` LINE IS DUPLICATED VERBATIM IN BOTH `STATE.md` AND `INDEX.md`, AND `CI-06g` CANNOT SEE IT.** Found by running `gates.mjs generate` and reading the diff: the generator rewrote **two** identical lines in each file. `git show` over the last twelve commits touching STATE puts the count at 1 before [`72e6b8c`](../STATE.md) and 2 from [`4cc6006`](../STATE.md), whose subject is *"Merge origin/main into session 146, taking the generated registry spans"*. **It is a merge keep-both and it has been on `main` since.** The gate is blind by construction: it rewrites every span it finds and compares each to its own query, so **two identical copies both pass**, which is the count gate unable to see the one defect a duplicated count line is. **It is the fifth instance of the keep-both shape [session 162](2026-08-24-session-162.md) counted four of, and the first in a file neither `CI-06u` nor any registry parser reads as a table.** **Reported and NOT repaired**: the fence holds INDEX at its row and STATE at an append, deleting a line is neither, and the durable fix is a gate change rather than a delete.

  - **`OI-06` COMPOSES WITH THIS RULING RATHER THAN COMPETING WITH IT, AND THAT WAS CHECKED.** [FOLD-01](../plans/FOLD-01-phone-identity.md)'s recommendation is a registry keyed on `(identity_id, destination_ref)`, and [`0005`](../../packages/db/migrations/0005_affiliate_program.sql) declares `affiliates.identity_id uuid NOT NULL REFERENCES identities(id)` with the comment *"An affiliate is an identity."* **So the key works on the affiliate leg unchanged, with no second key shape and no nullable half**, the moment the leg has a `destination_ref`. `M08-9` is therefore downstream of `OI-06` alone, which is one blocker fewer than session 162 rowed. **`INV-M8-11`'s 48 hour cooling window still has no storage on any of the three legs**, and that is `OI-06` and not this entry.
