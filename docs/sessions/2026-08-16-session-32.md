### The retrieval that did not happen, and why nothing was written in its place

**The environment's egress policy answers `403` to `CONNECT www.cmegroup.com:443`**, and to `iana.org` and `nyse.com` besides; only GitHub and the package registries are reachable. The proxy's own instruction for that class is to report the blocked host rather than route around it.

**So the holiday and early-close lists are `null` and nothing was written into them.** The reason that is the right outcome rather than a shortfall is worth stating where the next session will look:

> A holiday list written from recollection is exactly the failure `TR-01` names, "every value transcribed from the named authority and never from an implementation", **with the added defect that the implementation in question is a memory of the publication rather than the publication**. It would look identical to a correct transcription, it would pass every structural check in `generate.mjs`, and the first mechanism that could falsify it is `SD-M2-04`'s divergence alarm, **retrospectively, after trading**.
>
> And it defeats OQ-SE-04 in the same stroke. The ruling rejects a calendar package because "it encodes someone else's reading of the same publication, a second instance of the same error class rather than an independent check". **Two recollections of one publication are worse**: they are perfectly correlated by construction, so the diff comes back empty and proves nothing, which is the ruling's own stated failure mode in its own words.

Everything that does not depend on those values is finished. **What is owed is the transcription, the retrieved artifact and its SHA-256, the generated sessions file, and the second reader's file.** No part of the generator, the contract or the checks waits on them.

### One finding needing a founder ruling, and it is a transcription rule rather than a schema change

**CME publishes the word "holiday" for days that still carry a shortened Globex session.** The ruled model has no state for that:

| State | What `0032` enforces |
|---|---|
| **A holiday** | **No session at all.** `session_open_at` and `session_close_at` are `NULL` under `trading_calendar_holiday_has_no_session` ([ADR-042](../decisions/ADR-042.md) F-1) |
| **An early close** | A **full trading day for every counter** (B4 #3, [EC-005](../edge-cases/EC-005.md)) with `session_close_at` brought forward |

**A day published as a holiday on which a fill can still occur has no session to contain it, so R-01's containment lookup finds none.** That is the same orphaned-fill failure **F-3** exists to prevent, arriving through the other door: F-3 guards a close time that is too early, and this is a session interval that is absent entirely.

**Recommendation, offered without deciding it:** a day on which any of `ES`, `MES`, `NQ`, `MNQ`, `CL` or `GC` trades at all is an **early close**, however the publication labels it, and `is_holiday` is reserved for days on which none of them trades. The cost is that `is_holiday` will disagree with the word "holiday" on the exchange's page, which is a documentation problem rather than a containment one, and the disagreement belongs in `notes`.

**It has to be settled before the transcription rather than after**, because both readers must be given the same rule or the second transcription is answering a different question than the first, and OQ-SE-04's empty diff would then be empty for the wrong reason.
