### `admin_actions` is FIRM, and the rule it is not is the one that returns rows

**A table whose subject is an operator is not thereby firm, so the question was asked of the ROW.** An `admin_actions` row records that Merit did something. The columns that could reach a person:

| Column | What it is | Why it is not the scope |
|---|---|---|
| `actor text NOT NULL` | who performed it | An operator string, not a `users` row and not an identity |
| `subject_id uuid NOT NULL` | the OBJECT touched | **Polymorphic, discriminated by `subject_kind`, declaring NO foreign key.** A session, a phone-change request, a payout request, a plan version |
| `on_behalf_of_identity_id uuid NULL` | whose own act it was | Set **exactly when `initiative = 'trader_request'`**, by [`0043`](../../packages/db/migrations/0043_admin_attributed_actions.sql)'s biconditional CHECK |

**The third column is the trap and it is a good one, because it is structurally identical to a rule that is correct one table over.** `ledger_accounts` is `owned` with `nullable: true`, and there the NULL rows are genuinely the firm's: `firm_treasury`, `psp_clearing`, `fees_revenue`, `reserve`. **Here the NULL rows are not the firm's. They are rows about a trader with no column naming them** -- an `enforcement` action is Merit acting against a person, and the person is reachable only through `subject_id`, which declares nothing. So a nullable-`owned` rule would answer *"everything we did to you"* with *"the things we did for you"*, silently, and would read in an audit exactly like a complete answer.

**That is [ADR-084](../decisions/ADR-084.md) section 7's failure with a different shape**: not a transcription agreeing with its own expectation, but a predicate agreeing with the subset it can see.

### The finding: one file folds one column reader and not the other

**[ADR-094](../decisions/ADR-094.md) folded `ddlColumns`. It did not fold `ddlColumnDefs`, and three assertions read through the second one.**

| Reader | Reads | Used by |
|---|---|---|
| `ddlColumns` + `foldTable` | `CREATE TABLE` **plus every later `ADD COLUMN`** | the per-table drift assertion |
| `ddlColumnDefs` | the `CREATE TABLE` body **alone** | *"every owned rule names a column the DDL declares REFERENCES identities(id)"*, *"every derived rule names a foreign key the DDL actually declares"*, *"no firm table carries a column referencing identities"* |

**The loud consequence was watched.** Seeding the refused rule -- `admin_actions` as `owned` on `on_behalf_of_identity_id` -- fails with:

```
AssertionError: admin_actions.on_behalf_of_identity_id is not a column: expected undefined to be defined
```

**A true refusal for a false reason.** It *is* a column; it is on the folded set the assertion three tests up compares against. The suite refuses the rule this session refused, and refuses it for a reason that would refuse a correct rule on any drifted table just as readily.

**The silent consequence is the one that matters, and it is measured rather than feared.** Run here over all 47 migrations, matching the drift assertion's own multiline `ALTER TABLE ... ;` algorithm and keeping only `ADD COLUMN` statements that declare `REFERENCES identities(id)`:

```
tables with a LATER ADD COLUMN referencing identities(id): 1
 - admin_actions | 0043_admin_attributed_actions.sql | ALTER TABLE admin_actions ADD COLUMN on_behalf_of_identity_id uuid NULL REFERENCES identities(id) ON DELETE RE
```

**One table of 111, and it is the one this session registered `firm`.** *"no firm table carries a column referencing identities, so the class is not hiding one"* passes on `admin_actions` **because it cannot see the column**, not because the column is absent. **The `firm` ruling above stands on its own argument and the suite is not evidence for it**, which is stated here so a later reader does not mistake a green run for a second opinion.

**IT IS REPORTED AND NOT REPAIRED, AND THE REASON IS THE FENCE'S OWN TEST.** Folding `ddlColumnDefs` changes what three assertions read on all 34 registered tables at once, its failure direction is unmeasured, and the fold's vocabulary for a *definition* is not the fold's vocabulary for a *name* -- an `ALTER COLUMN ... DROP NOT NULL` is a no-op on a name set and is not a no-op on a definition. **That is a ruling, this session has no ADR number because a transcription rules nothing, and wanting one is the stop signal rather than the licence.** It belongs to a session that holds this file alone.
