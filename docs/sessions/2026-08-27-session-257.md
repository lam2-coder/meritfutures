### 1. THE PLAN, committed before a source file was touched

[ADR-003](../decisions/ADR-003.md)'s money-path regime requires the plan to exist before the diff does, and plan mode wedges a remote session, so the discipline is discharged here: **this section was committed on its own, ahead of `admin-writes.ts`.** Everything below it is what the session then did.

#### 1.1 What "the four writes" resolves to, against the contract

The dispatch names **`POST /admin/accounts/:account`, `POST /admin/flags/:flag`, `POST /admin/plans/:plan`, `POST /admin/plans/versions/:version`**. None of those four is a row in [API_CONTRACT](../architecture/API_CONTRACT.md) section 8. **Each is the PATH PREFIX of one or more rows that are**, with the action segment cut off and the parameter abbreviated:

| The dispatch's name | API_CONTRACT section 8's rows under it |
|---|---|
| `POST /admin/accounts/:account` | `/admin/accounts/:accountId/freeze`, `/unfreeze`, `/close`, `/note` |
| `POST /admin/flags/:flag` | `/admin/flags/:flagId/status` |
| `POST /admin/plans/:plan` | `/admin/plans/:planId/versions` |
| `POST /admin/plans/versions/:version` | `/admin/plans/versions/:versionId/publish` |

**The corpus is the specification, so the rows are what get written: seven routes under four prefixes.** Writing four collapsed endpoints, each taking an action discriminator, would be a shape the contract does not carry, and writing only four of the seven would leave three admin writes with no owner: session **256** holds the reads and this session holds the writes.

#### 1.2 THE RULING THAT SHAPES ALL SEVEN

`admin_actions.reason` is `text NOT NULL` under a comment reading **"NO UNEXPLAINED ADMIN ACTION, EVER. NOT NULL is the whole control."** Verified at [`0017_events_and_audit.sql:82`](../../packages/db/migrations/0017_events_and_audit.sql), the line the dispatch cited, which is correct.

So the ruling is a shape and not a check:

> **The audit row is written FIRST, in the same transaction, and the mutation is downstream of it. The route never supplies `reason`, never defaults it, and never substitutes a neighbouring field for it. An operator write carrying no reason is refused by the DATABASE, and the route's job is to report that refusal rather than to pre-empt it.**

Ordering is the half that makes this structural. If the target row moved first and the audit row were appended afterwards, "no unexplained admin action" would depend on both statements running. Inserting the audit row first makes the explanation a **precondition of the mutation** in the only place that cannot be forgotten: the transaction itself.

#### 1.3 The door, and why it is `systemDb('operator-console')`

Two of the four subject tables are `owned` and two are `firm`:

| Table | `SCOPE_RULES` class | Reachable by |
|---|---|---|
| `accounts` | `owned` on `identity_id` | `scopedTx`, `systemTx` |
| `risk_flags` | `owned` on `identity_id` | `scopedTx`, `systemTx` |
| `identities` | `root` | `scopedTx`, `systemTx` |
| `plans`, `plan_versions`, `plan_version_sizes` | `firm` | `firmTx`, `systemTx` |
| `admin_actions` | `firm` | `firmTx`, `systemTx` |

**`firmTx` cannot reach `accounts` or `risk_flags`** (`FirmTableKey` excludes every `owned` table, by construction), and an operator write reaches across identities by definition. **One door serves all seven and it is `systemDb('operator-console')`**, which is the reason [ADR-084](../decisions/ADR-084.md) accepted that word for and the one [ADR-102](../decisions/ADR-102.md) section 10 is least comfortable with. **`SystemReason` is not widened and `SqlExecutorReason` is not touched.**

The accessor is [ADR-112](../decisions/ADR-112.md)'s keyed one: **`rowAt`, `updateAt`, `deleteAt`.** `update` and `delete` are not methods on any transaction handle in this workspace, which ADR-112 section 6 states in exactly those words and which the tree confirms.

#### 1.4 Roles

[M06](../plans/M06-admin-ops-console.md)'s `INV-M6-09` is the ruling and it is one line: **"`readonly` cannot mutate anything, and `ops` cannot change config, roles, or plan versions."**

| Route | Roles |
|---|---|
| `freeze`, `unfreeze`, `close`, `note`, flag `status` | `owner`, `ops` |
| `POST /admin/plans/:planId/versions` | `owner` only. It is a plan version |
| `POST /admin/plans/versions/:versionId/publish` | `owner` only. It is a plan version |

`readonly` is refused all seven, which is [API_CONTRACT section 12](../architecture/API_CONTRACT.md)'s row *"`readonly` role calls any admin mutation | `admin_sso` | 403"*.

#### 1.5 The surface

`/admin` is one of `OPERATOR_PREFIXES`, so [`registry.ts`](../../apps/api/src/registry.ts)'s `compose` **never registers this module on the public deployment** and the public 404 is the router's. That is [ADR-083](../decisions/ADR-083.md) section 4 and it is not a permission check.
