### The sharpest judgement is not `ADR-073`'s, and the answer is that the leg is the unit

**`ADR-073` gave `CI-09` a disposition and never a partial-implementation rule.** Session 114 built one of the four legs its `Contents` cell states, so a gate that asks *"is this row implemented"*, sees the word and stops **reads one leg as four**. The ruling nowhere forbids that, because the ruling is not where the answer is.

> **A DISPOSITION APPLIES TO A LEG AND NEVER TO A ROW. A row is CLOSED when it carries at least one leg and every leg it carries is well formed. A row is OPEN for each activation condition it carries, WHETHER OR NOT it also carries an implementation.**

So `CI-09` is closed, is partially implemented, and is open on three legs, all three at once, and **no single number describes it**. The runner therefore prints three counts rather than one:

| What the runner reports | Count | What it means |
|---|---|---|
| Stage rows | **10** | Section 4.1 entire |
| Implemented outright | **5** | `CI-01`, `CI-02`, `CI-03`, `CI-05`, `CI-06` |
| Carrying an implementation **and** a condition | **1** | `CI-09`, on one leg of four |
| With no implementation leg at all | **3** | `CI-04`, `CI-07`, `CI-08`. **This is the brief's three** |
| Discharged outside Actions | **1** | `CI-10` |
| Activation conditions over the table | **6** | 1 + 1 + 1 + `CI-09`'s 3 |

**The two readings of "how many are open" give 3 and 6, and both are printed**, because a gate that printed one of them would be choosing for the reader. The brief predicted three and the gate reports three; the second number is the one a reader who stopped at the first would have missed.

**The obvious alternative was decomposing the `Contents` cell instead, and it is wrong by measurement.** `CI-01`'s contents are `tsc --noEmit`, ESLint and prettier, implemented by **one** job. A rule splitting on contents reports eight open legs across five rows that are entirely built. **The `Closure` cell is where a disposition is written down, so the `Closure` cell is where the legs are.**

### Which of the two readings of the activation condition was implemented: both, split per artifact

The brief named the choice and it is the whole value of the gate. **Every condition must be present, dated and name exactly one artifact** (pure form, applies to all six). **Every artifact that is a fact about THIS TREE is additionally probed and must resolve to ABSENT** (`ADR-073` section 8's *"the only one that fails on good news"*).

**`CI-04`'s Neon branch is not a fact about this tree**, so for that row the gate asserts the **condition** and never the **artifact**, and the runner says exactly that in one sentence. Refusing the absence assertion wholesale on the strength of the one artifact that cannot be read would have dropped the assertion ADR-073 calls load bearing, on the row where it is easiest to deliver.

| Condition | Read | How |
|---|---|---|
| `CI-07` a `build` script in any `apps/*/package.json` | **PROBED** | Four app manifests, `scripts.build` on none |
| `CI-08` `@playwright/test` in the lockfile | **PROBED** | The package name at a key, never the word |
| `CI-04` a Neon branch provisioned for CI | Registered | Estate, not tree. No file here changes when it is provisioned |
| `CI-09` a demo-world seed script | Registered | Names neither a path nor a manifest key |
| `CI-09` the `VG-12` admission | Registered | `.github/CODEOWNERS` plus a branch-protection setting; [session 23](2026-08-15-session-23.md): *"a job can see the dependency surface changed and cannot see that a human agreed"* |
| `CI-09` [M07](../plans/M07-risk-abuse.md)'s detector code | Registered | Names a module plan, not a path or a key |

**They are REGISTERED with a reason, never exempted.** An entry naming no live condition is itself a finding, so the register shrinks the day a ruling gives one of the four a path, and `register-shrinks-when-an-artifact-is-re-ruled` asserts exactly that. **The probe table and the register are written and never computed** ([ADR-074](../decisions/ADR-074.md) section 2), so a new condition **fails** until somebody decides in the runner whether its artifact can be read at all.

**Finding 3 is the one worth reading twice.** The ruling requires a path or a manifest key so that a condition can be checked, and then gives four conditions that cannot be. It is not a drafting slip: `VG-12`'s admission and a provisioned database branch are genuinely not repository facts, and the ruling was right to state them anyway. **What is missing is the ruling's own acknowledgement that two of its six conditions are unenforceable by construction**, which is the difference between a condition that reopens a row and a condition that reads like one.

### The gate's own first run was red, and the runner was the thing that was wrong

**`artifactKey` stripped `*` as emphasis and ate a glob.** `CI-07`'s artifact is `apps/*/package.json`; the normalizer produced `apps//package.json`, which matched no register entry, so **one run reported the live condition unreadable and the live probe stale**. The text being normalized is already the **inside** of a bold span, so a surviving `*` is content and not markup.

That is `CI-06u`'s `_` with a different character and the same argument: a character that is markup in one register and content in another, where inventing a mismatch is worse than folding two spellings together. It is also **a reader narrower than the property it claimed**, which is the class [`CI-06t`](../testing/STRATEGY.md)'s row enumerates, and it was caught by running the gate rather than by reading it.

### One seed and six scope cases, and which assertion each one buys

**`SEEDS` holds one violation per gate and the one chosen is the ARRIVAL**, because it is the only assertion in this runner that fires on a commit somebody was **right** to land: a `build` script appears in an app manifest and `CI-07` reopens on the day it lands. Every other finding here is a document written badly.

- **`no-disposition-at-all`** is the ruling's headline sentence, watched here rather than in `SEEDS` and with the cost of that choice written down.
- **`implementation-names-no-workflow`** and **`job-must-resolve`** are finding 1 and the way it rots: a workflow link keeps resolving after a job is renamed.
- **`condition-inside-an-implemented-row`** is the case the whole leg rule rests on. A runner that sees the word "Implemented" and stops goes **silent** on it, which is reading one leg as four, and there is no other way to prove a runner believes the rule.
- **`register-shrinks-when-an-artifact-is-re-ruled`** is the stale direction, which is what separates a register from an exemption list.
- **`playwright-near-miss`** is a `PASS` with a control that fires. `pnpm-lock.yaml` names `@vitest/browser-playwright` today, so a probe grepping the word would reopen a merge-blocking row on a package nobody installed. That is `CI-06s`'s step-against-mention boundary on a different registry.

**Every selector was checked stable under its own seed** rather than trusted, which is session 115's `CI-06l` lesson applied before it bit: `no-disposition-at-all` selects the first row **by position**, because selecting on what the cell says would re-derive to the next row after the seed and report `FAILED OFF-TARGET` while the gate was right.
