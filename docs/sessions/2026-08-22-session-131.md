### The plan's specification is refused, in writing, and that is the whole item

[WAVE-05 section 2](../plans/WAVE-05-tier2-fixture-shapes.md) specifies the assertion as *"every such row's citation resolves and its file names the row's id"*.

**Both are true of `GS-072`.** `scripts/demo/test/replay-determinism.property.test.ts` exists, it names `GS-072` twice, and its cited block asserts nothing:

```
describe.skipIf(!replayExists)('PT-06: arrival-order permutation', () => {
```

`replayExists` is `Object.keys(engine).includes('replay')`, which is false, so the block reports a named skip, never enters its body, and the body **throws** rather than asserting. **[ADR-076](../decisions/ADR-076.md) is withheld on exactly that**, so a gate built to the plan's sentence would have admitted the defect that withheld the ruling and then been cited as evidence for signing it. [ADR-076 section 1](../decisions/ADR-076.md)'s governing rule is implemented instead: **a row is discharged when its assertion is EXECUTED somewhere a gate can read.**

### How execution is detected is ruled here, because the ruling says "a gate" and not which one

**A STATIC PARSE.** The citation must name a **test** file that resolves and names the row, and must not name it **only** from inside a construct carrying a modifier from `TEST_DISABLERS`, or inside the comment run immediately above one. The comment run is part of the block on purpose: this corpus writes the `GS-nnn` a block discharges in the comment **above** the `describe`, which [session 123](2026-08-21-session-123.md) did for all six sites so a gate could find them, and a reader taking only the body would find `GS-072` nowhere inside the skip and report the row clean.

**A `vitest` RUN IS REFUSED, AND ON FALSIFIABILITY RATHER THAN COST.** It is genuinely stronger: it would see a case that runs and fails, which the parse cannot. [`falsify.mjs`](../../scripts/corpus/falsify.mjs) copies the tree **without `node_modules`**, on a decision its own loader-cases block states in terms, so a gate needing a workspace resolution **could never be watched failing** — and a gate nobody has watched fail is not a gate, which is the criterion this whole runner was chosen on. [STRATEGY](../testing/STRATEGY.md) says the same thing one level up: *"a gate with an install step is a gate that stops running on the day the install breaks."*

One finding, on the execution ground, and the seed was removed. **Then the same seed with `.skipIf` removed from the describe and nothing else changed: `1 of 1 gates pass`.** Neither direction means anything alone; together they say the boundary is **the skip** and not the row, the file or the citation. Both run on every push as `CI-06/fixture-inventory/covered-elsewhere-must-execute` and its control, and the seed **derives the row from the tree** rather than pinning `GS-072`, so the day the engine exports `replay` the case announces itself instead of retargeting quietly.

**The pass direction is also the honest statement of the limit.** With the skip gone that block's body still throws, so what the case proves green is a suite that would fail if it ran. That sentence is in the case's own comment rather than only here.

### What assertion 6 cannot see, stated in the gate rather than in prose nobody reads

| | |

| **An outcome** | A cited case that runs and FAILS reads exactly like one that passes. The suite asserts that and `CI-01` runs the suite |

**The stricter reading is deliberately not taken.** *"Every naming must be live"* would refuse a file naming the row from a live assertion AND from a skipped one, and that reader is **broader than the property**: section 39's rule is that a named suite runs an assertion for the row, which such a file satisfies. It is not discarded, it is **counted** — the note prints how many rows name themselves from inside a disabled block as well as outside it, which is **zero** today and is the number to watch.
