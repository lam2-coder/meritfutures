### Landmines

**THE `.d.mts` CAN DRIFT FROM THE `.mjs` AND NOTHING CHECKS THAT IT HAS NOT.** The home must be `.mjs` because `repo-invariants.mjs` runs under bare `node` with nothing compiled, and the suites importing it are type-checked by packages whose `tsconfig.json` sets no `allowJs`, which is outside this fence. The consumers would fail to typecheck on a wrong shape, which is weaker than an assertion.

**THE REGEX HEURISTIC IS A HEURISTIC AND 30 CALL SITES DEPEND ON IT.** Whether a `/` opens a regular expression or divides is not decidable from characters alone. The home uses the preceding-character rule, excludes `<` and `>` so `</div>` in a `.tsx` file does not open one, and says in its header that it is a heuristic. It is exercised over all 704 source files by the offset-equivalence case and the whole suite is green on it, but it is the one part of this diff that could be wrong in a way no case here would notice.

**`RI-30`'s SENTINELS ARE UNCONDITIONAL, SO THE SYNTHETIC FIXTURE CARRIES THE HOME.** A session that adds a check and finds `RI-30` throwing against `cleanTree()` should add to the fixture, not soften the sentinel. The softening is the defect this whole entry is about.

**A NAME LEG THAT READS A REGEX LITERAL REPORTS ITS OWN CHECK.** `RI-30`'s leg 1 requires a trailing `[(=<:]` for exactly this reason, and the scanner now correctly treats a regex literal as code, so any future text leg over source has the same trap waiting.
