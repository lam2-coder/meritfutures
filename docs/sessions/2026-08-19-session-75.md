## 2026-08-19 - Session 75: `CI-06u`, and the survey that decided its scope (non-money)

- **Done:** **`CI-06u` is written, claimed and falsified: an IDENTIFIER heads at most one row of any `docs/` markdown table.** `u` was claimed in [ALLOCATION](../decisions/ALLOCATION.md) before a line of the gate existed. **22 of 22 gates pass clean and fail dirty, 29 scope cases hold**, four of them this gate's. The fence held: `scripts/corpus/`, [STRATEGY](../testing/STRATEGY.md), [ALLOCATION](../decisions/ALLOCATION.md), plus this log and the `gate_count` spans the runner's own `generate` rewrites.
- **Next:** **Seven files carry real duplicates and repairing them needs a documentation fence this session did not hold.** The ratchet is the handoff: every count may shrink and may never grow, and lowering it is compulsory.
- **Blockers:** None.
- **Landmines:**

  - **THE SURVEY CHANGED THE GATE, WHICH IS THE WHOLE REASON IT CAME FIRST.** A blanket "no table has duplicate first cells" found **123 duplicated keys across 12 files**, and **most are legitimate**: a transition table's first cell is a FROM state and repeats once per transition, a STRIDE table repeats its category, `WAVE-01` repeats a wave number, a session log repeats a rule group down a Group column, and `ALLOCATION` stacks superseded numeric generations on purpose. **A gate that fired on those would have been switched off inside a week**, which is STATE's own sentence about gates that fail on arrival. Written without the survey, this gate would have been correct, unusable, and abandoned.

  - **THE SCOPE IS A RULING AND NOT A RELAXATION, AND THE DIFFERENCE IS WHETHER IT NAMES A CLASS.** What none of the legitimate cases is, is an **identifier**. The defect worth a gate is an id that resolves to TWO THINGS. Scoped to a first cell that is a corpus identifier or a document link, the 123 fall to **78 and every survivor is a real defect**. That is a narrower assertion, not a weaker one: relaxing would have been exempting the files that tripped it.

  - **THE SCOPE SEPARATES BOTH CLASSES INSIDE ONE FILE, WHICH IS WHY IT IS NOT AN EXEMPTION LIST.** [`STATE_MACHINES`](../architecture/STATE_MACHINES.md) carries both. Its transition tables repeat `active` and `provisioning_pending` by design and fall out of scope; its gate table defines **`G-ELIGIBLE` TWICE WITH CONTRADICTORY PREDICATES** -- `identities.status <> 'restricted'` on one row and `identities.status = 'active'` on the other, **both citing ADR-041, on the payout path**. A file-level exemption would have hidden that, and a first draft of this gate was heading for one.

  - **THE SHARPEST FINDINGS ARE NOT MERGE ARTIFACTS AT ALL.** [`M05`](../plans/M05-payout-system.md) carries `INV-M5-17`, `INV-M5-18` and `INV-M5-19` **twice each with different meanings** -- "a held request that reaches auto-release pays" against "no hold and no freeze outlives its expiry". [`M12`](../plans/M12-statistic-definitions.md) does it with `S-14` and `S-15`, [`M20`](../plans/M20-wallet.md) with `INV-M20-06`. **Two requirements sharing one identifier is strictly worse than a duplicated row**: a reader citing `INV-M5-17` cannot know which is meant, and until now nothing in the tree could see it.

  - **AND THE LARGEST IS INVISIBLE TO THE DEDUPE FOR A REASON WORTH KNOWING.** [`docs/sessions/README.md`](README.md) carries **the entire session table twice**, 58 duplicated keys, one copy raw and one prettier-formatted. **The column padding is exactly why the dedupe missed it**: it drops byte-identical lines, and reformatting makes duplicated rows non-identical. That is the same hazard [session 71](2026-08-18-session-71.md) recorded from the other side, where running prettier on `docs/` reflowed 101 lines of this very file.

  - **IT IS A RATCHET AND THE RATCHET NEEDED ITS OWN FALSIFICATION.** Seven files carry duplicates now and this session could not repair them, so the known set is a count per file that may shrink and never grow. **A count that may only shrink is worth nothing if nobody lowers it**, so `CI-06u/ratchet-stale` repairs `M20` and requires the gate to report the stale count. Without that case the ratchet decays into an exemption list, which is the shape it was built to replace.

  - **WHAT IT CANNOT SEE IS DECLARED IN ITS OWN `covers` RATHER THAN LEFT AS AN ABSENCE.** A repair and a new duplicate in the same file cancel in that file's count. It does not read the merge script, which runs on one machine and is not in this tree. It says nothing about two rows with DIFFERENT ids stating one thing. And **a duplicated LABEL is out of scope even when it is corruption**: STATE's P1 table repeats "**CI-06, corpus integrity**" four times and this gate cannot see it, because a rule that could would fire on every Group column in the corpus. That one is a real gap and is stated as one.
