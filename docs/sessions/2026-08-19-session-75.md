### The register, and why it is a register rather than an exemption list

**A gate landing red on 105 findings cannot land at all**, and that is a mechanical constraint rather than a preference: [`falsify.mjs`](../../scripts/corpus/falsify.mjs) runs every gate against the tree as it stands and **a gate that cannot pass there is an ERROR**. None of the eight files is inside this session's fence, and the three contradictory pairs are not repairs a session can make unilaterally: which half of `G-ELIGIBLE` is the ruling is a founder question.

So `CI06U_REGISTER` pins the exact `(file, key)` pairs that exist on `main` today, **and it shrinks only**. A register entry that no longer names a real duplicate is **itself a finding**, so the day a file is repaired is the day its lines go. That assertion is not decoration and it is watched: `CI-06u/a-repaired-register-entry-is-itself-a-finding` seeds the REPAIR rather than the damage, deleting one of M20's two `INV-M20-06` rows, and the gate objects to its own register.

**The same rule runs over the exemption list.** A `DIMENSION_HEADERS` entry matching no table under `docs/` is a finding too. An exemption nobody can point at a table for is how a scope decision stops being reviewable.

### The four boundaries, each watched in both directions

None appears in one direction only, per this file's own rule.

| Case | Boundary | Control |
|---|---|---|
| `a-dimension-column-repeats-and-is-not-a-finding` | a repeating `From` column is out of scope | the SAME table with `From` changed to `Term` in the header row and nothing else |
| `a-repaired-register-entry-is-itself-a-finding` | the register decays loudly | in scope, must fail |
| `two-separate-tables-may-share-a-key` | the unit is one TABLE, not one file | the same two tables with the blank line between them removed |
| `an-empty-first-cell-claims-nothing` | an empty cell claims no key | the same three rows given one identical non-empty first cell |

### Landmines

- **THE SEED CARRIES TWO DIFFERENT SECOND CELLS AND THAT IS NOT COSMETIC.** A byte-identical duplicate pair is exactly the population the review desk's dedupe **already removes**, so seeding one would have proved the gate fires on rows that never reach `main`. The rows that survive the merge are the rows that disagree, and the seed is written to be one of those.

- **`two-separate-tables-may-share-a-key` IS THE CASE THAT DECIDES 58 OF THE 105.** A table here is a **maximal run of consecutive `|` lines** carrying at least one delimiter row, which is what GitHub renders as one table. A parser that started a new table at the SECOND delimiter row would read `docs/sessions/README.md`'s duplicated index as two tidy tables and report **nothing at all**, because the second copy sits under a re-inserted header with no blank line above it. The control removes one blank line and is the whole of the difference.

- **`_` IS DELIBERATELY NOT STRIPPED FROM A KEY** while `` ` ``, `*` and `~` are. It is an emphasis marker in markdown and an identifier character in this corpus, where first cells carry `held_pending_review` and `phone_hash`. Stripping it folds `hold_expires` and `holdexpires` into one key and **invents a duplicate**, and inventing one is worse than missing one here: a false finding in a merge gate is how the gate gets switched off.

- **THE EXEMPTION IS A RECORDED READING OF SIX TABLE SHAPES, NOT A DERIVATION.** A new table whose first column is a dimension under a header not on the list is a false finding, and the remedy is another argued entry, never a looser match. The cheapest way to make this gate quiet is to widen `DIMENSION_HEADERS` until it stops matching anything, which is why the stale-exemption assertion exists in the same run.

- **THE GATE SEES ONE REF, exactly as `CI-06f`, `CI-06h` and `CI-06p` do.** A pull request appending a row a sibling branch has already appended is the precise defect this gate is for, and this run cannot see the sibling. It catches the duplication **at the merge**, which is one merge later than anybody would like and is still before `main`.

- **[ALLOCATION](../decisions/ALLOCATION.md)'s `r` rows are NOT in the register and their absence is the evidence.** That duplicate is argued in the file as deliberate, and the two rows are byte-identical but for one link, **so the review desk's own dedupe reached it** and only one row survives on `main`. It is the one place in this survey where the merge script worked as designed, and it is worth knowing that the dedupe is not useless, only far too narrow.

- **Files touched:** [`gates.mjs`](../../scripts/corpus/gates.mjs) (`CI-06u`, `DIMENSION_HEADERS`, `CI06U_REGISTER`, `markdownTables`, `rowCells`, `firstCellKey`), [`falsify.mjs`](../../scripts/corpus/falsify.mjs) (one seed, four scope cases), [STRATEGY](../testing/STRATEGY.md) (the section 4.4 row), [ALLOCATION](../decisions/ALLOCATION.md) (the `u` claim), [STATE](../STATE.md) (one section appended), [sessions/README](README.md) (this session's row), this file. Ten `gate_count` spans moved 21 to 22 by `gates.mjs generate`, which is a one-character edit inside each span and touches no prose.

### What was NOT done, named rather than implied

**Not one of the 105 duplicates was repaired.** Eight files carry them, seven are outside this session's fence, and the eighth ([ALLOCATION](../decisions/ALLOCATION.md)) carries eighteen whose repair means deciding for each number whether the reservation row or the merged row stands. **The register is the honest record of that, and the gate fails the moment somebody repairs one without removing its line.**

**The merge script itself is untouched**, which was the instruction. It still resolves keep-both and still dedupes only byte-identical lines over 60 characters. `CI-06u` does not make it correct; it makes its output visible on every pull request instead of on the day somebody reads a table closely.

**Nothing asserts which half of a contradictory pair is true.** The gate reads the first cell and nothing else, so two rows that contradict each other and two that are identical are the same finding here. `G-ELIGIBLE`'s two conditions, `M05`'s two purposes and STATE's `21` against `Eleven` are named in this log and in the runner's comments so that the next reader has them, and every one of them is a ruling rather than a parse.
