- **Gap 1 needed no ledger concept and barely needed schema.** `promotional_credit` is 0009's class and [`promotional_credit_grants`](../../packages/db/migrations/0024_offers.sql) is 0024's table, already carrying amount, expiry, consumption, revocation and a funding purchase. So the delta is **one nullable FK naming the settlement** plus **a partial unique index making one fee-back per settlement structural**. `funding_purchase_id` is reused for the `evaluation_fee_paid` amount mode rather than duplicated, because the evaluation purchase both sets the amount and is what a chargeback claws back, which is that column's stated purpose.

- **`repeats` SHIPS LOCKED, AND THIS IS THE SESSION'S REAL CONTENT.** The plan filed it as an open question and the review desk ruled that an open question alone leaves a field somebody can set to `true` before anyone has ruled. `AS-M20-01` counter #5 says the promotional budget is bounded because **"the promotional budget is capped per identity and per resolved entity, which is M17's issuance discipline"**. A fee-back credit is issued **by a payout, by the plan version**, not through M17's issuance path, so it sits outside that cap; with `repeats: true` the scenario's five steps close into a loop that funds itself, under zero denial, with no ceiling. `plan_versions.fee_back_repeats` is therefore materialized at publish on [`0004:183`](../../packages/db/migrations/0004_catalog.sql)'s own pattern and **pinned to `false` by a named CHECK**. Unlocking it is a migration that drops one named constraint, which has a date and an author; setting a boolean has neither.

- **`OQ-F5-03` is answered by which table the key points at, not by a filter.** A hard merge **repoints ownership into the surviving `identities` row**; `identity_links` carries the soft and hard-link edges and repoints nothing. So `identities.id` **is** the hard-merged grain and `plan_size_unlocks.identity_id` **is** [ADR-070](../decisions/ADR-070.md) section 3 rather than a field it constrains. A soft-linked pair sharing an unlock is **unrepresentable**.

- **`INV-M18-07` is asserted rather than argued**, on the review desk's instruction that this corpus prefers a gate over care. [`plan-size-unlocks.test.ts`](../../packages/db/test/plan-size-unlocks.test.ts) **derives the rule-scalar vocabulary from `plan_version_sizes` itself** rather than listing it, and asserts `plan_size_unlocks` has nowhere to put one. **It runs in the `unit` project, not `integration`**: that stage needs a Neon branch, cannot run on a fork pull request and is not selected by CI-02, so an assertion filed there reports nothing. Watched failing on a seeded `unlock_drawdown_cents` column, on its own finding, reverted.
