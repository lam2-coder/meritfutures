### 1. The plan, written before the work (ADR-003 strict, no interactive plan mode)

**This session has no human watching, so the plan is committed rather than approved.** The dispatch
delegates the founder's answer and requires the ruling to be argued; what follows is the argument as it
stood after the sources were read and before any file was written.

**THE READING THAT WINS IS 1: A POSTGRES TABLE PLUS A FIFTH ROLE.** The table is `live_account_state`,
one row per account, and the role is `merit_live`.

**The four load-bearing arguments, each from a source rather than from preference.**

1. **`GS-132` is `P6`'s own done-gate and only reading 1 keeps it executable.** [DELIVERY_PLAN section 4](../DELIVERY_PLAN.md)
   states the done-condition as *"`GS-132` byte-identical with the cache poisoned"*, and `GS-132` itself
   reads *"the live cache is **populated** with values that would flip eligibility, a breach, and a payout
   clamp"*. A process-local store inside the socket server cannot be populated by a test outside that
   process, which is the cost [P6 section 10 item 1](../plans/P6-live-tier.md) names, and it is decisive
   rather than merely expensive: a medium that makes the phase's stated done-condition unwritable has
   failed the phase.
2. **`INV-M2-14`'s own words are *"a permission rather than a convention"*, and only a Postgres grant is
   one on this tree.** The apparatus already exists and is landed: [`0026`](../../packages/db/migrations/0026_roles_and_grants.sql)'s
   grant-then-revoke idiom, [`0034`](../../packages/db/migrations/0034_reversible_contact_addresses.sql)'s
   enumerated-role idiom, and [`assert_append_only_grants.mjs`](../../scripts/db/assert_append_only_grants.mjs).
3. **[`0034`](../../packages/db/migrations/0034_reversible_contact_addresses.sql) is the precedent and its
   sentence is exactly on point:** *"you cannot withhold DELETE from the send path until the send path is a
   principal the database can name."* The live path needs to be a principal the database can name, and that
   is a fifth role, minted the way the fourth was.
4. **Coherence with a fence the plan already wrote.** `P6-f`'s ingest is fenced to `apps/worker/src/live/ingest.ts`,
   a process that is not `apps/api`. A process-local store in the socket server makes that fence unbuildable.

**What reading 2 costs, named rather than waved at.** `GS-132`'s poisoning step becomes untestable from
outside the process. [INFRA section 2.1](../architecture/INFRA.md) deploys `api` and `api-admin` as **two
services**, so a process-local cache is two caches that diverge, and the trader's dashboard and the
operator's live Open Liability would read different numbers from the same feed. Each additional instance
of either service is a third and a fourth. And `P6-f`'s ingest would have to leave `apps/worker`.

**What reading 3 costs, and the honest part is that [OVERVIEW section 3](../architecture/OVERVIEW.md)'s
sentence reaches it only halfway.** The sentence is *"pg-boss (Postgres-only) rather than BullMQ plus
Redis: one fewer stateful service to back up, restore, and reason about, and the job store participates in
the same transactions and the same PITR as the money data."* **Neither limb transfers cleanly.** A cache
whose entire content is discardable by design needs no backup and no restore, so the first limb reaches
only the words *"reason about"*; and `INV-M2-14` makes the streaming ingest write **nothing but the
cache**, so there is no second write for a transaction to be atomic with and the PITR limb does not reach
at all. **The queue's argument therefore does not decide this, and this session does not pretend it does.**
What decides it is that **Redis would make the separation a convention again**: the engine's inability to
read the cache would rest on the worker not importing a client, which is an absent import rather than a
permission, and `INV-M2-14`, `C-26`, `FM-M12-08` and `FM-M13-07` all say permission. A new stateful service
is additionally a `VG-12` admission and an [INFRA](../architecture/INFRA.md) and
[OVERVIEW](../architecture/OVERVIEW.md) row, all three of which are `P6-b`'s and none of which is in this
fence.

### 2. The finding that makes reading 1 cost something, stated before it is paid

**[INFRA section 5](../architecture/INFRA.md) says `merit_app` is held by *"API and worker at runtime"*,
and [`client.ts`](../../packages/db/src/client.ts) opens exactly one pool from one `DATABASE_URL`, read
*"here and nowhere else"*.** So **one process is one role**, and while the API and the worker share
`merit_app` **no Postgres grant can separate "the API may read the cache" from "the stats worker may
not"** -- which is precisely what `FM-M12-08` and `DEP-M12-08` require.

**This session does not resolve that, because the address is `P6-b`'s and the mechanism is `P6-g`'s.** It
does two things instead: it states the requirement (**any process that reads or writes the live cache
connects as `merit_live`**), and it **forecloses the one cheap escape**, which is granting `merit_app`
`SELECT` on the cache. That grant is the move that makes `FM-M12-08` false silently, on the day somebody
finds the read path blocked and reaches for the smallest diff.

### 3. What the table stores, and the three columns it deliberately refuses

Columns are `account_id` (grain and scope hop), `trading_day`, `sequence`, `opening_equity_cents`,
`equity_cents`, `intraday_movement_cents` **generated** as the difference of the two beside it
([`0049`](../../packages/db/migrations/0049_reserve_coverage_snapshots.sql)'s `rcr_bp` precedent), `feed`,
`as_of_instant`, `indicative` and `created_at`. Every money column is integer cents in `bigint`.

**Three refusals, each with its reason, because a merged migration may never be edited (`E2`).**

- **`kind` is not stored.** It is `SimWaypoint['kind']`, simulator vocabulary, and `V-M2-16` is
  unanswered. [`stream.ts`](../../packages/rithmic/src/simulator/stream.ts) states that the tick shape is
  one of the two things the mechanism decides. A merged `CHECK` over an unconfirmed vendor vocabulary is a
  constraint that cannot be corrected.
- **`at_utc` is not stored.** Nothing in the landed contract reads it, and storing the feed's own clock
  beside ours invites staleness to be computed from the wrong one, which is what
  [ADR-152](../decisions/ADR-152.md) clause 1 and `LiveFreshness.stale` (*"the SERVER's own answer against
  its own threshold"*) forbid.
- **`projected_floor_distance_cents` is not stored.** The floor is a rule threshold the engine owns.
  Storing it here would put a rule input in the indicative tier, and computing it here would need a grant
  on `rule_states` that `INV-M2-14` forbids by name. The contract's field is composed at the read layer.

**No monotonicity trigger, and the refusal is deliberate.** An out-of-order tick that rewound the row would
be a display defect on a labeled indicative number, not a money defect, and the guard belongs in `P6-f`'s
`ON CONFLICT ... DO UPDATE ... WHERE excluded.sequence > ...` predicate. It is named as OWED rather than
added to a money-path migration this slice was not asked to widen.

### 4. What the ruling settles for other slices

[P6 section 3.5](../plans/P6-live-tier.md) left open whether the accessor needs an expiry sweep. **It does
not**: the table is one row per account, bounded, and `merit_live` is granted no `DELETE`. So `P6-c` does
not depend on `P5-a`'s range term and that row of section 3.5 resolves to NO.
