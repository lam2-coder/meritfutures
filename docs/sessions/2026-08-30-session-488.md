### 6. Landmines

- **A DOOR WITH NO CALLER IS THE CHEAPEST THING IN THIS REPOSITORY TO CHANGE, AND IT WILL NEVER BE THIS CHEAP AGAIN.** `catalogRowAt` has never been called from any application file. The row that finally calls it will also be the row that inherits its shape, and after that the shape has a constituency.
- **"THE `unknown` IS DELIBERATE" WAS BELIEVED FOR A WHOLE WAVE AND IS NOT WRITTEN ANYWHERE.** [ADR-233](../decisions/ADR-233.md) never mentions it. The citation that was supposed to hold it is about `ON CONFLICT` and `ORDER BY`. **A premise repeated between entries is not a premise checked**, and this one decided a preference between two candidates.
- **THE ENGINE ALREADY KNOWS EVERY COLUMN NAME OF THIS TABLE, ON PURPOSE.** `RI-01` and `merit/engine-purity` would not catch a decoder in the engine reading `'sizeCents'` either. The foreclosure is a principle the corpus holds and not a check the runner runs, which means it has to be stated precisely enough to apply or it will be applied to the wrong half.
- **`readSize` IS NOT ON THE PAYOUT PATH's DOOR.** It reads through `firmDb()`, which opens a second transaction on a second connection, which is the exact thing [ADR-233](../decisions/ADR-233.md) was written to avoid. A session that reads [ADR-286](../decisions/ADR-286.md)'s *"the same `firm` handle the payout transaction would use"* as permission to reuse that reader will write a price read outside the transaction the purchase commits in.
- **THE NAME `PlanVersionSizeRow` MEANS THREE DIFFERENT SHAPES IN THIS TREE, TWO OF THEM INSIDE `apps/api`.** A future `import type { PlanVersionSizeRow }` in that deployable gets whichever file it reached for, and one of the three is in the driver spelling while the other two are in column names.
- **THE CODEC WITHOUT THE COLLAPSE MAKES THE TREE WORSE.** Section 7's row is two halves and only the pair is an improvement; a session that lands the codec alone has written a fourth statement of the payout ceiling.
