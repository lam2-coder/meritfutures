### 2. `identity_links`, and exactly which column could not be chosen

The table is [`0002_identity.sql`](../../packages/db/migrations/0002_identity.sql). It carries **`identity_a`** and **`identity_b`**, both `uuid NOT NULL REFERENCES identities(id) ON DELETE RESTRICT`, and one constraint decides the whole question:

```
CONSTRAINT identity_links_canonical_order CHECK (identity_a < identity_b)
```

**An edge is stored ONCE, canonically ordered, so which of the two columns a given person's id lands in is decided by UUID comparison and by nothing else.** `OwnedRule` names one `column`. Naming `identity_a` returns a person exactly the edges where their id happens to sort first; naming `identity_b` returns the complement. **Neither is a subset a person would recognise, neither raises anything, and both return rows** -- which is the failure [ADR-008](../decisions/ADR-008.md) scoped the accessor to bound, arriving in the direction that produces an answer rather than an error.

**A `derived` rule is not the escape either.** `DerivedRule` names one `localColumn` against one `foreignColumn`, so it expresses the same single-column choice one hop further out, and the hop would be to `identities`, which is `root`. The vocabulary has no member for a row that reaches **two** identities symmetrically, and inventing one is a ruling.

**[ADR-092](../decisions/ADR-092.md) section 9 names this table by name as a per-table ruling and takes neither column.** A transcription rules nothing. **So the table is not declared in [`schema.ts`](../../packages/db/src/schema.ts) at all** -- not declared-and-unregistered, which would leave a `pgTable` that no drift assertion compares, since `DDL_NAMES` derives from `TABLE_KEYS`. Unregistered is unreachable and unreachable is safe.

**Watched rather than asserted.** A seeded call site `scopedDb(id).rows('identityLinks')` is refused with:

```
src/s192-probe.ts(3,56): error TS2345: Argument of type '"identityLinks"' is not
  assignable to parameter of type 'ScopedTableKey'.
```

**What this costs, stated.** `SD-M7-04`'s dispute path (`disputed_at`, `dispute_note`, `suppressed`, `suppressed_by`) is on this table, so **M07's dispute work cannot read the graph through either accessor until somebody rules the column**. That is a real block and it is named here rather than discovered later. It is **not** the only thing blocking that path: [session 161](2026-08-24-session-161.md)'s second landmine measured that `identity_links` is in [`0026`](../../packages/db/migrations/0026_roles_and_grants.sql)'s `REVOKE UPDATE, DELETE` list at :98 and that the `SECURITY DEFINER` function the suppression needs does not exist, so the path is blocked by a **grant** as well as by a scope rule.

### 3. `correlation_groups` is `firm` as a refusal, and the two reasons have different strengths

**It cannot be traversed**, which is the weaker reason: `member_account_ids` is `uuid[]`, `DerivedRule` names one `localColumn` against one `foreignColumn`, and an array is neither a `hop` nor a `semi-join`.

**It must not be traversed**, which is the one the rule rests on. `correlation_groups_is_a_group` starts the table at three members -- [`0028`](../../packages/db/migrations/0028_supersede_plan_version_immutability.sql) re-states it over `cardinality` for the empty-array case -- and [M07](../plans/M07-risk-abuse.md) section 3.4 filters same-identity clustering **at the detector**, so a row that exists is a finding about more than one identity by construction. **Returning it to each member would tell every member which OTHER accounts the detector grouped them with.** That is a cross-identity read, and it is worse than a leak of one row because the row **is** the association.

**Seeded the other way and caught.** Declared `owned` on `member_account_ids`, the suite fails naming the column and quoting its DDL:

```
AssertionError: correlation_groups.member_account_ids must reference identities(id),
  and its DDL is: member_account_ids uuid[] NOT NULL
```

`statistic` and `threshold` are `numeric` and that is **not** a no-floats violation: the rule governs financial paths, a correlation coefficient is not one, and rounding it to cents would be the actual error. [`0008`](../../packages/db/migrations/0008_risk.sql)'s own comment says so and the transcription follows it.

### 4. [ADR-094](../decisions/ADR-094.md)'s fold applies nothing here, measured

Over all 47 migrations: **no `ADD COLUMN`, no `DROP COLUMN`, no `ALTER COLUMN` and no `RENAME` touches any of the six.** Each of the five is created exactly once, which the suite asserts.

**Two later `ALTER TABLE`s do touch this set and both are constraint work.** [`0028`](../../packages/db/migrations/0028_supersede_plan_version_immutability.sql) re-states `correlation_groups_is_a_group` over `cardinality`, and [`0029`](../../packages/db/migrations/0029_phone_identity_and_auth.sql) supersedes `identity_signals`' `kind` CHECK with a wider one over **ten** values, adding `phone` and `phone_carrier` for [ADR-039](../decisions/ADR-039.md). The fold's shape filter reads neither as a column change and discards both, correctly.

**The `0029` widening is a transcription fact even though it is not a column fact**, and it is written into [`schema.ts`](../../packages/db/src/schema.ts) for that reason: the table is read **as of the last migration**, and a reader taking `0002`'s eight-value list as current would be eight of ten.

### 5. `risk_flags`, where "registered" and "trader-readable" had to be said apart

A scope rule answers **how a row reaches an identity**. It does not answer who may read it, and [ADR-092](../decisions/ADR-092.md) section 9 already says registering a table makes it readable and nothing else. On this table the distinction is worth stating in the file, because the table is the flags queue:

- **`INV-M7-10` is enforced on `evidence_packs`**, by [`0008`](../../packages/db/migrations/0008_risk.sql)'s `evidence_packs_trader_gets_no_detector_detail`. That is a **different table** and it is **not registered here**. Nothing in this rule grants a trader a read of `evidence` or `flag_type`.
- **`account_id` is not the scope because it is nullable.** `entity_cap`, `payment_velocity` and `name_mismatch` are identity-level findings with no account named, so a derived rule through `accounts` would silently drop exactly the flags that are about the person rather than about one of their accounts.
- **Severity 4 is why the table is money-adjacent.** [ADR-040](../decisions/ADR-040.md)'s `G-HOLD-REQUIRED` holds a payout on an unresolved 4+ flag, so a rule returning another identity's flags would hold the wrong person's money.

**Seeded and caught.** `risk_flags` scoped by `account_id` instead of `identity_id` fails naming the column and quoting its DDL: `account_id uuid NULL REFERENCES accounts(id) ON DELETE RESTRICT` against the requirement that an owned column be declared `REFERENCES identities(id)`. Dropping `sla_due_at` from the transcription fails the per-table drift assertion at 16 columns against 17, with the missing name printed.

- **Next:** the registry's remaining slice is **85 tables**, dispatched per [ADR-092](../decisions/ADR-092.md) with no roster. **`identity_links` needs a per-table ruling before it can be registered, and `attributions` is the same shape** ([ADR-092](../decisions/ADR-092.md) section 9 names both). Both are founder items rather than session items: the choice is not between two readings of a document, it is a decision about what a scoped read of a symmetric edge should mean.

The boundary is stated in both files; it is not a control.

  - **`INV-M7-02` IS CONTRADICTED BY THE TREE, NOT MERELY UNBUILT, AND REGISTERING `risk_flags` DOES NOT MOVE IT.** [Session 161](2026-08-24-session-161.md) measured it: the invariant names a **permission** as its enforcement, [`0026`](../../packages/db/migrations/0026_roles_and_grants.sql) creates three roles and no detector role, and `merit_app` holds `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES` with `risk_flags` absent from the `REVOKE UPDATE, DELETE` list. **The `risk_flag_status` enum is transcribed with all four members** because a reviewer legitimately moves a flag through them; the enum is not the missing control and [`schema.ts`](../../packages/db/src/schema.ts) says so beside it, so a later reader does not mistake a faithful transcription for an enforcement. **Repairing this is a migration and this fence has none.**

  - **`CI-06/retired-constraints` CAUGHT THIS SESSION'S OWN COMMENT AND THE FIX WAS THE COMMENT RATHER THAN THE REGISTER.** The first draft named the constraint `0029` superseded on `identity_signals`, and the gate failed by file and line with the correct reading: a retired name may appear only where the appearance **retires** it or **records** it, and [`schema.ts`](../../packages/db/src/schema.ts) describes the live schema. **Adding the file to `RETIRED_REGISTER` would have been widening a register to fit a comment**, which is the same move as weakening a gate to pass it. The comment now names the live constraint alone and says why the other is absent. This is [session 141](2026-08-23-session-141.md)'s class arriving in a **new** file rather than in an old citation.

  - **COLUMN TYPE AND NULLABILITY ARE ASSERTED NOWHERE, NOW ACROSS TWENTY-SIX TABLES.** `identity_signals.value_hash` is `bytea` and `risk_flags.severity` is `smallint`; both were transcribed rather than approximated, and **nothing in the suite would have noticed either being `text` or `integer`.** [ADR-094](../decisions/ADR-094.md) section 3 names this axis and states why it is not closed inside a money-path slice. **Nothing in this session closes it and nothing written here implies it is closed.** The `nullable: false` on the two new `owned` rules is in the same position.

  - **`detector_definitions` IS THE FIRST REGISTERED TABLE WITH A COMPOSITE PRIMARY KEY**, `(detector, version)`, transcribed with drizzle's table-level `primaryKey({ columns: [...] })` rather than replaced by a surrogate. The suite's `hop` assertion reads `column.primary`, so **a future `derived` rule hopping to this table would need a foreign column that is a PK, and neither half of a composite PK is marked `primary` on its own**. Nothing derives through it today; the shape is recorded so the first session that tries does not read the failure as a drift.

  - **THE SUITE'S FIRM-REFUSAL TEST STILL NAMES THREE TABLES BY HAND WHILE ITS OWN COMMENT SAYS "EVERY firm TABLE".** There are now **twelve**. That gap predates this session, it was left rather than repaired because four sessions are transcribing into this file concurrently and re-writing a test somebody else is appending to converts a loud conflict into a merge somebody has to think about. **The compile-time refusal is total** (`ScopedTableKey` excludes every firm key by construction, watched here on `correlationGroups` with `TS2345`), so what the hand-written list under-covers is the runtime throw and not the type-level refusal.
