### 1. The objective

**Row `284`, the third of three clauses and the only one that is a WRITER.** `useCheckoutBackend`'s lead clause reads *"A CAP WHOSE ROW AND DOOR BOTH EXIST AND WHOSE TABLE IS EMPTY"*, and the row's own framing was that what is missing is a row, which means a writer, which means an operator path. It reserved `RI-33` conditionally, reserved migration `0076` conditionally, forbade reopening the door's shape, forbade reaching into the SSO purchase, and named dual control a live question to be ruled rather than inherited.

### 2. The citations, re-derived first

A session that starts from a dispatch inherits its errors, so nothing was written until all four were read.

**All four held.** The three that sit below this diff's own thirteen-line insertion have moved by thirteen and are repointed; `RI-15` and `RI-16` went red on four of them and are what found them.

### 3. The finding, and it is an order rather than an object

**The row asked for a writer. What a writer needs first is a CONTROL, and the order is the whole finding.**

`firm_parameters` ships empty and refusing, which `0074` and [ADR-265](../decisions/ADR-265.md) both rule correct. The tempting reading of "what is left is an empty table" is that somebody should fill it. **Filling it is the last step and not the first**: the first cap row is a limit on the firm's exposure, and written before any control exists it is a number approved by nobody, recorded nowhere, and indistinguishable afterwards from one that was.

**So `0076` makes the unapproved row unwritable and writes nothing.** Five separately rejectable parts, on `0033`'s and `0048`'s precedent.

### 4. What was measured, and every one of the three was found by executing

| Query, against `0001`..`0075` applied from empty | Result |
|---|---|
| `uuid` columns on `firm_parameters` | **zero, over six columns** |
| `admin_actions.subject_id`, `dual_control_approvals.subject_id` | both `uuid NOT NULL` |
| foreign keys referencing `operators` | **three, and none on `dual_control_approvals`** |
| `merit_app` grants on `firm_parameters` | `SELECT, INSERT, UPDATE, DELETE` |

**The first two together are a hard blocker and not a preference.** The audit row API_CONTRACT section 8 requires of every admin mutation addresses its subject as `(text, uuid)`, so it could not name a cap row at all. That is `0048` item 0's shape a second time, and like that one it was found by writing the fixture rather than by reading the file.

### 5. What was ruled, and where the judgement is

- **A `firm_parameters` write is inside [ADR-010](../decisions/ADR-010.md)'s sensitive set.** The other reading is real and is written down: `D4`'s *"cap/split/gap"* is the payout triple by the constitution's own usage of the word. It is refused because what `D4` protects is the parameters through which economic sabotage is silent, and this is the anti-fleet control. **The asymmetry decides it**: a control on an empty table costs a second key nobody has used, the other way costs the exposure ceiling to one owned session.
- **A lowering is not exempted.** A control with a direction is a control with a case analysis, on a supersession-dated table, and the incident tool for a compromised buyer is `identities.status` and a freeze, which [M05](../plans/M05-payout-system.md) rules explicitly outside dual control.
- **Both hands are ACTIVE `owner`s**, from API_CONTRACT section 8 and ADR-010's own word.
- **The delay window is owed and not invented.** No duration exists in the corpus. `FP-DC7` installs the half that needs no number: a row may not take effect before it was approved.
- **The operator bootstrap is deploy access and is not performed.** `0070`'s asymmetry, and no name is written into this repository.

### 6. What went red, and the restores

Two success cases COMMIT, fourteen rejection cases REFUSE by their named tags, and three seeded defects were watched RED: the payload leg disabled (a cap approved at 9 landed as 900), the audit trigger's `actor` leg removed, and the role leg reduced to a status check (red at the database AND in the new vitest case). **Every restore verified byte-identical with `sha256sum -c`.**

**And [ADR-265](../decisions/ADR-265.md)'s own named likeliest error was discharged**, because it asked for exactly this: `now()` inside a transaction is the transaction's start time, and the door's read shape returns the latest row whose `effective_from` has arrived while ignoring two future ones.

### 7. What was NOT done, and the fence

- **The fence was too narrow, it was reported rather than widened, and the dispatcher extended it to `packages/db/test/**` and nothing else.** Four cases were red before that. All four are repaired on the property each one states about itself, **and none is skipped, disabled or scoped away from the table it was wrong about**.
  - **Ruling 10**, which the extension asked for rather than granted: `firm-parameter-vocabulary.test.ts`'s sweep guards a VALUE SURFACE and not the `ALTER` statement. The file's own header states the closure as a pair and names `text_value` as what it fears; the case's comment gives the same reason in the same words. **The absolute reading is stated and rejected**, because the only other home for `0076`'s two columns is a side table where the approval citation stops being `NOT NULL` on the row that needs it.
  - **Each strengthening was watched RED under a seed**, and the vocabulary one twice over: a seeded second membership list was measured **GREEN under the old form and RED under the new**, which is the strengthening in one pair of runs rather than in a sentence.
  - **The fourth was a pre-existing cross-file regex leak**, repaired in one token and watched red by restoring it. Every restore was verified byte-identical with `sha256sum -c`.

- **`RI-33` is not taken.** The register is in `ALLOCATION.md`, which the fence names, but the check is in `packages/tooling/**`, which it does not.
- **No `scripts/db` probe ships**, because `CI-06s` and `RI-24` require a `corpus.yml` step and a `CI-06h` needle in `gates.mjs` for anything that lands there, and an unwired script would be `OI-07`'s own shape.
- **No admin route, no identity provider, no operator row, no cap row, no secret.**
- **`pnpm run verify` and `falsify.mjs` were not run.**

### 8. What the next session should know

- **`admin_actions` is not `0017`'s five columns.** `initiative` (`NOT NULL`, closed vocabulary from `0043`) and `on_behalf_of_identity_id` arrived later with a CHECK tying them together. A fixture written from `0017` fails on the first insert, as this one did. A firm parameter change is `operational`.
- **`SET CONSTRAINTS ALL IMMEDIATE` is how you watch a deferred trigger fire inside a `BEGIN ... EXCEPTION` block.** Without it every rejection case passes for the wrong reason, because the trigger has not run yet.
- **A PostgreSQL is buildable in this container** with `initdb` and `pg_ctl`, no Docker. The `postgres` OS user needs `+x` on every ancestor of the data directory, and the failure reads as a permissions bug in the data directory itself.
- **`price_floors` has the same `uuid` gap `0076` just closed on `firm_parameters`**: six columns, none of them a `uuid`, so an `admin_actions` row cannot name a price floor either.
- **The payload digest is a canonical encoding invented here.** It is length prefixed and renders its timestamp in UTC rather than casting it, so it is injective and session independent. What is unproved is what a client written later will do with an incoming RFC 3339 string before it reaches the digest, and that failure would read as `FP-DC5`, which says the second person approved something else.
