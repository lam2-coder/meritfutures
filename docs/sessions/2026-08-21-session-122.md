### The finding that decides all four, and it was on disk before the plan was written

**`GS-083` is asserted, both halves, at [`plan-validate.test.ts:874`](../../packages/rules-engine/test/plan-validate.test.ts)**, in a file whose header says it lives there *because* it cannot live in `fixtures/`. [Section 39](../testing/golden-scenarios/39-fixture-status-and-blockers.md) rows the same scenario `blocked | format-cannot-express`.

**Both are true and they answer different questions.** The row has no golden fixture; the scenario has an executable assertion. [ADR-072](../decisions/ADR-072.md)'s status column can only say the first, so a reader infers the second from it, and the inference is wrong on seven of the fourteen. **That is the governing rule**: a registry row is discharged when its assertion is EXECUTED somewhere a gate can read, not when a file appears in [`packages/rules-engine/fixtures`](../../packages/rules-engine/fixtures/README.md).

**The remedy is a fourth `status` value, `covered-elsewhere`, and NOT a seventh blocker term.** A blocker names which of `W1`, `W2`, `W3` fails; on these rows none has. Reopening a vocabulary [ADR-072](../decisions/ADR-072.md) closed, for a term meaning "not blocked", would have been the worst available first exception.

### Two things checked rather than inherited, and each moved the answer

**`GS-030`'S ARITHMETIC IS FALSIFIED AND IT TOOK RUNNING THE GENERATOR TO SEE IT.** The row and [EC-012](../edge-cases/EC-012-to-033-appendix-b4-battery.md) both pin *"the 23 hour and 25 hour sessions each produce exactly one trading day"*. That describes a 24-hour session and CME's is not one: the transcribed `session_rule` is 17:00 CT on the prior day to 16:00 CT, which is **23 hours every day of the year**, and both US DST transitions fall at 02:00 CT on a **Sunday**, inside the gap between Friday's close and Sunday's open. **Sixteen sessions generated across the two 2026 transition weeks, every one 23 hours.** There is no 25-hour session. The 23 is not a DST artifact at all; it is the ordinary length of every CME weekday session, and the coincidence of the number is what kept the row from being read.

**SIX OF THE EIGHT ASSERTION SITES DO NOT NAME THEIR ROW.** The `covered-elsewhere` status was proposed with a gate assertion attached — the cited file resolves and contains the row's id — and running that grep before writing it down is the half that mattered. Only [`plan-validate.test.ts`](../../packages/rules-engine/test/plan-validate.test.ts) (for `GS-083`) and [`rules-f-context.test.ts:140`](../../packages/rules-engine/test/rules-f-context.test.ts) (for `GS-052`) name theirs. **So the gate is not assertable on arrival**, [`falsify.mjs`](../../scripts/corpus/falsify.mjs) makes a gate that cannot pass the tree an ERROR, and the six comments are `X1` rather than a follow-up.
