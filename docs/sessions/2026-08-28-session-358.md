### 5. Item 3, and the sentence in ADR-191 that turns out to name a different event

**THE CLASS IS NOT THE DEFECT AND THE SILENCE IS.** [ADR-191](../decisions/ADR-191.md)
ruled the sixth scope class `either` correct and ruled that a row reaching neither leg
belongs to no identity and falls out. What it registered as its sharpest open item is what
happens next: the producer writes such a row, nothing raises, and the absence is
indistinguishable from the event never having happened, on a table that is append-only.

**NO CONSTRAINT ON THIS TABLE CAN CATCH IT** and that is settled rather than assumed: both
columns are nullable by design, and migration `0058` was written out against three
candidate constraints and returned to the pool. **So the write path is the only place, and
`assertTenanted` is there.** It runs inside `buildEvent`, which runs inside `emit`, which
runs inside the caller's transaction, so a refusal rolls the state change back WITH the
event rather than committing the pair.

**THE REFUSAL IS ON THE ROW AND NOT ON THE NAME.** `payout.freeze_expiring` is the one
catalogue row DECLARING neither field, derived over the eight rather than named; a payload
that arrives without the field its row does declare writes the identical untenanted row
and refuses identically. The seven others build, which is what keeps the refusal from
being a blanket one.

**THE REPAIR THE MESSAGE NAMES IS THE PRODUCER'S.** A field on the catalogue row to read
the tenancy from, which EVENTS.md has to give, or a row that says it belongs to the firm.
**No row in EVENTS says that today, so no field is invented here**, on ADR-159 clause 1's
rule that a name is a row on the registry's authority and no other.

**THE WHOLE CATALOGUE WAS READ, AND THE MEASUREMENT IS BOUND IN THE SUITE RATHER THAN LEFT
IN PROSE.**

| | |
| --- | --- |
| catalogue rows | **105** |
| payload given by REFERENCE, excluded rather than assumed | **3** |
| of the remaining 102, naming NEITHER tenancy column | **34** |
| of those 34, carrying the `TL` consumer | **1** |

**THAT ONE IS `payout.settled` AND IT IS NOT THE NAME THIS ENTRY WAS HANDED.**
`payout.freeze_expiring`'s consumers are ALERT and FEED, so ADR-191's sharpest sentence,
the row never appearing in the trader's TIMELINE, is not this name's; what is this name's
is that no trader-scoped read of `events` reaches the row at all. **`payout.settled` has
no producer in this tree yet and is the second instance of this shape waiting for the
slice that writes it.** That is reported and not acted on: `ADR-191` is merged and a change
to it is an ADR rather than a commit.

**A ROW THAT GAINS THE SHAPE TURNS THE SUITE RED ON PURPOSE.** The cardinals above are
asserted rather than written down, because the refusal being TOTAL rather than
timeline-only rests on that distribution.
