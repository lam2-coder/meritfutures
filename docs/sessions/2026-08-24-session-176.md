### The finding: a seventh site, in fence, invisible to the search that defines the task

[`apps/api/src/surface.ts:92`](../../apps/api/src/surface.ts) read:

> *"INFRA section 2's table names four services and none of them is this one; see ADR-083 section 7, which reports that rather than editing a document outside this session's fence."*

**That sentence is false on this tree, and ADR-089 is what falsified it.** [INFRA section 2.1](../architecture/INFRA.md) rows `api` and `api-admin` with a `MERIT_API_SURFACE` value each. The comment is the same defect as the two comments above -- a claim about INFRA section 2 that INFRA section 2 outgrew -- **carried by a file that contains no occurrence of `portal-api`**.

**It is repaired, and the reason it was taken rather than reported is that all three tests point the same way**: it is inside the declared fence (`apps/api/**`), the ruling that makes it false is the signed ruling this session applies, and the repair is the same two-word quotation refresh ADR-089 section 7 scoped as this follow-up's work. Leaving it would have meant refreshing one comment's citation of INFRA section 2 while its neighbour in the same directory kept the stale one.

> **The transferable part is the search, not the sentence.** A rename dispatched as *"retire the sites"* defines its own work by a string, and a stale claim about a renamed thing does not have to contain that thing's name. The six sites and the seventh were stale for the identical reason; only six of them were findable by the method the task names.

### Every edit is line-count neutral, and that was a constraint rather than a coincidence

**ADR-089 cites these files by `file:line` eleven times**, six of them in section 5's site table and two more inside the **signed** checkable clause in section 8, which quotes [`surface.ts:99`](../../apps/api/src/surface.ts) for `SERVICE_BY_SURFACE` and `:168` for `resolveSurface`. A comment rewrite that added two lines to any of these files would have left a signed entry citing the wrong lines in the files its own ruling moved.

So each replacement was written to the line count it replaced, and the result was checked by re-resolving every citation after the edit:

| Citation | Still resolves to |
|---|---|
| `apps/portal/src/index.ts:41` | `export const SERVICE = 'portal' as const;` |
| `apps/portal/test/service.test.ts:7` | `expect(SERVICE).toBe('portal');` |
| `apps/portal/test/surface.test.ts:39` | `expect(portal.SERVICE).toBe('portal');` |
| `apps/portal/package.json:6` | the `description` |
| `apps/portal/src/index.ts:12` | the comment, first line |
| `apps/api/src/index.ts:12` | the comment, **and the line still carries the word `portal-api`** |
| `apps/api/src/surface.ts:99` | `export const SERVICE_BY_SURFACE = {` |
| `apps/api/src/surface.ts:168` | `export function resolveSurface(env: Environment): ApiSurface {` |

**This is why the two test assertions were changed and not annotated.** A note explaining that `portal-api` is foreclosed *"under any spelling"* would have been worth having and would have pushed the assertion three lines down, breaking the one citation in ADR-089 section 5 that names it. **ADR-089 section 6 already carries that foreclosure and INFRA already records the retirement**; a third copy in a test file would have cost a signed entry's citation to say what two documents say.
