- **Landmines.**
  - **A MERGED MONEY-PATH MIGRATION CONTAINS A DEFECT, AND IT WAS FOUND BY EXECUTING THE INVARIANT RATHER THAN READING IT.** `assert_published_plan_version_immutable()` in `0027` reads `NEW.config` and `OLD.config`. **`plan_versions` has no `config` column**; the rule contract is `rules`. PL/pgSQL resolves record fields at execution, so the migration installs cleanly and the function is only ever wrong when it fires. Every `UPDATE` against a published row raises `record "new" has no field "config"`. **The immutability promise survives by accident**, because the error rejects the write. **What does not survive is retirement**: `0004`'s own comment and DATA_MODEL §4 both state the one permitted transition is `published -> retired`, and that transition raises too, so **no plan version can be retired**. A draft row updates normally, which is exactly why the 27-file install and every probe in DELTA_MANIFEST section 10 passed. **`0027` is merged and is not edited**: the fix is a superseding migration and a founder ruling, and it takes the set from 27 files to 28.
  - **The probe table was an inventory of what somebody thought to test, and the gap in it was not visible from inside it.** Section 10 probes STAT-C1 five ways, the window uniqueness, both unit constraints and NO-FLOATS in both directions. It probes **none of the four triggers**. The one thing never executed is the one thing that was broken. That is the `array_length` lesson again, one file over and one session later, and the general form is worth more than either instance: **an invariant that was reviewed and not executed has not been checked.**

Each admits the empty array because `array_length` returns `NULL` on it and a `CHECK` evaluating to `NULL` passes.
