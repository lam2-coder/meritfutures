### Landmines

- **A DESIGN RECORD THAT CLAIMS A GUARD IS WHY NOBODY LOOKS FOR IT.**
  `plan_version_sizes.md` has said *"Immutable once the parent version is
  published (same trigger)"* since `0004`. Sixty-two migrations went by. **The
  document was more convincing than the schema**, and no gate reconciles the two.
- **A GUARD ON THE TABLE PEOPLE NAME IS NOT A GUARD ON THE TABLE THE ENGINE
  READS.** `0028` pins `plan_versions` down to the byte and attaches nothing to
  the child grid where every cents value lives.
- **A PROBE THAT DIES IS NOT A PROBE THAT REPORTS.** Seed 1 raised a
  `unique_violation`, which is not `check_violation`, so it escaped its handler
  and took the whole `DO` with it: **zero failing rows printed while four cases
  were broken**, and the error named a case three positions downstream of the
  defect.
- **A `NULL` VERDICT IS AN ABSTENTION, NOT A FAILURE.** `verdict <> 'PASS'` is
  `NULL` for a `NULL` verdict and does not count. Ten failures reported where
  there were eleven, and only the counterfactual run could produce it.
- **THE PERMISSIVE SIDE IS THE ONE TO LIST.** Deriving the refused set as *not
  `draft`* means a status a later migration adds is refused by default. Listing
  `published` and `retired` instead is `0027` item 3's defect, and seed 3
  reproduces it exactly.
- **AN ACCEPTANCE CASE IS WHAT STOPS AN OVER-CORRECTION.** Six of seventeen
  cases pass on both legs of the A/B and none of them is decoration: a guard
  refusing every write to this table passes all eleven refusals.
