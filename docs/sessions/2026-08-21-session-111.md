## 2026-08-21 - Session 111: M04's read surfaces, `apps/portal` from 33 lines to a rendering layer (non-money, read-only)

- **Objective:** build [M04](../plans/M04-trader-portal.md)'s READ surfaces only. Account view, marks, timeline, eligibility display, section 3.8's economic-calendar panel, and [ADR-068](../decisions/ADR-068.md)'s persistent impersonation banner slot. No auth, no payout request, no destination change, no contact change: all four are `C-27` money path under [CLAUDE.md](../../CLAUDE.md)'s regime table and belong to their own [ADR-003](../decisions/ADR-003.md) sessions.
- **Done:** **eleven source files and twelve suites in [`apps/portal`](../../apps/portal/src/index.ts)**, on branch `claude/m04-portal-read`, one commit and one push per file. **85 test files and 1165 passing, 24 of 24 gates, `RI-01` to `RI-07`, `falsify` clean.** The app was 33 lines and one stub; it is now a rendering layer with four of the module's invariants expressed as types rather than as habits.
- **Next:** the framework, and then the write surfaces one ADR-003 session each. `SC-M4-01` (auth), `SC-M4-04` (payout center), `SC-M4-06`, `SC-M4-07`, `SC-M4-08`, `SC-M4-09`, `SC-M4-10` and `SC-M4-11` are all unbuilt, and section 3.7's authority boundary is the one that must not be folded into a read session.
- **Blockers:** None for the read surfaces. Four things are OWED by other owners and are listed below; none of them stopped a file landing.

### What was built, and what each invariant cost

The module's own sentence is "render exactly what the engine computed, never recompute it, and never round it", and its invariants are almost all statements about **what a component is handed** rather than about how it paints. That is why a rendering layer with no framework is not a compromise: a component handed [`AccountCardView`](../../apps/portal/src/view/accounts.ts) cannot render a balance without its trading day, cannot do arithmetic on a money value, and cannot show a skipped gate as satisfied, because none of those is reachable from what it was given.

| Invariant | How it is enforced here |
|---|---|
| `INV-M4-01` | Every money field on every view model is a **formatted string**. [`format/money.ts`](../../apps/portal/src/format/money.ts) is the only place a money value is divided, it is integer-only over `bigint`, and it **refuses** a value that is not an exact integer rather than rendering it |
| `INV-M4-02` | `AccountState` is the required `as_of_trading_day` prop, and every view model carrying a money number extends it |
| `INV-M4-05` | `GateState` is `pass`, `fail` or **`disabled`**, three values rather than a boolean, so a gate reported `skipped: true` cannot be rendered as satisfied even when it also reports `pass: true` |
| `INV-M4-08` | `CopyBlock` is a branded string whose only producer reads `plan_versions.copy_blocks`. A field typed `CopyBlock` **cannot be satisfied by a literal**, which makes section 3.4's placement 2 structural: the eval progress card requires the funded-reset sentence and cannot be built without the pinned plan version having published one |
| `INV-M4-07` | The error vocabulary in [`shell/app-shell.ts`](../../apps/portal/src/shell/app-shell.ts) **has no `forbidden` member** for a `404` to be mapped onto |
| `INV-M4-16` | No type in the calendar panel has a URL, and the suite walks the built view rejecting any key an origin could be assigned to |
| `INV-M4-17` | The banner takes no `dismissible` prop and no `onDismiss`, and the suite asserts its key set **exactly** rather than listing absences, so a sixth spelling of "close" fails too |

**`GS-285` and `GS-100` are asserted in `apps/portal/test` and NO `GS-nnn` FIXTURE FILE WAS WRITTEN.** The fixture format is `packages/rules-engine/fixtures/GS-NNN-*.yaml`, a day stream folded through the engine, and neither of these is an engine scenario: `GS-285` is one calendar row rendered in two timezones and `GS-100` is a meter visible on a passing account. This is [session 107](2026-08-20-session-107.md)'s finding arriving from the other side, that "243 have no module code and no fixture format", and the half it did not say is that **module code landing does not by itself create somewhere for those fixtures to go**.

### The three decisions this session took rather than deferred

**There is no Next.js and the plan names one.** Section 1.1 says `apps/portal` is "a Next.js App Router application". The workspace holds none, and admitting one is a `VG-12` dependency decision plus a root lockfile change, which is [P1](../plans/P1-monorepo-scaffold.md)'s scaffold rather than a read-surface session's, and the root lockfile is outside this session's fence in any case. What a framework would render is what the app now exports.

**Money crosses the wire as `number` and [M01](../plans/M01-rules-engine.md) `INV-02` says `bigint` at every boundary.** [API_CONTRACT](../architecture/API_CONTRACT.md) declares every `_cents` field as `number` because the wire is JSON, and `packages/rules-engine/src/types.ts` declares `type Cents = bigint`. Both are approved and the portal is the first consumer to stand between them. **It routes around rather than resolving:** the app does no arithmetic on money at all, so the width never matters to it, and the formatter accepts `number | bigint`. When the transport moves, no call site moves. **The disagreement itself is the founder's and is recorded rather than settled.**

**The chart carries two representations of each number and the seam is named.** Displayed money is a formatted string. Plot magnitudes are `bigint` and carry **no `_cents` suffix**, because a pixel offset is not a displayed money value. Whatever draws the chart must write `Number(point.plot.balance)` to reach floating-point space, which puts the one cast in a reviewer's diff instead of leaving a `_cents` field to drift into float arithmetic three files away.

### Landmines

- **SESSION 111 WAS ALREADY ALLOCATED AND THIS SESSION TOOK IT ANYWAY, ON THE FOUNDER'S CALL.** [WAVE-04](../plans/WAVE-04-fixture-backlog-and-gate-inventory.md) section 7 claims session-log numbers **108 to 115**, one per wave session, and **111 is `W4`**, "four fixtures, the day fold and its boundaries", money path. The collision was found before this file was written and put to the founder, who ruled that 111 stands here. **`W4`'s author must take a different number**, and 116 is the first free one. [ADR-064](../decisions/ADR-064.md) permits parallel sessions to share a number **in one file on one day**; two files on two dates under one number is not that case, and `CI-06n` will not catch it because both files would have rows. This is [session 107](2026-08-20-session-107.md)'s `OI-19` landmine repeating one registry over, and it repeated **inside a wave plan written to prevent exactly this**.

- **`INV-M4-01`'s LINT RULE DOES NOT EXIST AND THIS SESSION DID NOT WRITE IT.** The invariant's enforcement column names "a lint rule banning arithmetic operators on any field whose name ends `_cents` or `_bp`". `packages/eslint-plugin-merit` holds three rules and none is this one. [`test/inv-m4-01.test.ts`](../../apps/portal/test/inv-m4-01.test.ts) stands in for it over this app's own source, its header states exactly how it is weaker (text rather than AST, one app rather than every app path), and it says that whoever writes `merit/no-money-arithmetic` **owns deleting it**. A substitute left in place beside the real rule is the second-expression-of-one-concept defect `OQ-P1-04` was about.

- **THAT SUBSTITUTE FIRED ON ITS FIRST REAL DIFF, ON A FALSE POSITIVE, AND THE SOURCE WAS CHANGED RATHER THAN SUPPRESSED.** `/_cents$/` in the timeline view reads to a text check as a `/` beside a money-suffixed identifier. The resolution was `key.endsWith('_cents')`, because a check with no parser cannot be taught the difference and **a suppression comment is the first hole in a control on its first working day**. Both the check and the source record it.

- **A CLAIM THIS SESSION EXPECTED TO MAKE CAME BACK FALSE WHEN CHECKED.** The obvious argument for an integer money formatter is that `(cents / 100).toFixed(2)` drifts by a cent somewhere. **Over every integer from 0 to 2,000,000 cents it does not**; the two agree on all of them. The surviving argument is narrower and is the one now written into the file and asserted in the suite: that agreement holds only inside the safe-integer range and `Number(9007199254740993n) / 100` reports `...409.92` where the exact answer is `...409.93`. **The false version is kept in the source beside the true one**, because it is the argument the next reader will reach for.

- **THE CONSISTENCY HEADROOM IS SPECIFIED, IS NOT COMPUTABLE HERE, AND IS NOT RETURNED BY ANY ENDPOINT.** Section 3.3: "when the share is under the limit it also shows the headroom." That is `max_bp - best_day_share_bp`, arithmetic on two `_bp` fields, which `INV-M4-01` bans outright. Both numbers render so the shape is visible and **the subtraction is owed by the engine**, beside `profit_needed_to_dilute_cents`, which is the harder half of the same rule and is already computed there.

- **THE ECONOMIC-CALENDAR PANEL HAS NO CONTRACT ROW.** `grep economic_calendar` over [API_CONTRACT](../architecture/API_CONTRACT.md) returns nothing. `DEP-M4-09` states the obligation ("the portal is served the current revision plus the calendar's freshness") and section 4 records that rows for fold surfaces land with the contract in the registries session. The type in [`api/types.ts`](../../apps/portal/src/api/types.ts) is the minimum that discharges `DEP-M4-09`, every field is a column in [`0039`](../../packages/db/migrations/0039_economic_calendar.sql), and it is **labelled as not a transcription** so the reconciliation is a diff on one file rather than a search.

- **THERE IS NO `copy_blocks` KEY VOCABULARY ANYWHERE IN THE CORPUS.** `grep -r copy_blocks docs/` returns prose. The corpus says what must be published and never what the keys are called, so `COPY_KEYS` in [`copy/copy-block.ts`](../../apps/portal/src/copy/copy-block.ts) **proposes** `eval.funded_reset` and collects it in one constant so reconciling against [M03](../plans/M03-billing-checkout.md)'s publish gate is a one-file diff. A key spelled two ways in two components is a sentence that renders on one screen and throws on the other.

- **NO CURRENCY SYMBOL AND NO DISPLAY LOCALE IS RULED, SO THE FORMATTER RENDERS NEITHER.** `grep -i currency` over [API_CONTRACT](../architecture/API_CONTRACT.md) and [DESIGN_SYSTEM](../design/DESIGN_SYSTEM.md) returns nothing: there is no currency field on any response. The formatter emits grouped digits and no symbol, because a symbol the corpus never chose would be `FM-M4-05`'s failure pointed at a unit instead of at a rule. The symbol and the locale belong with the design system.

- **NO `M4-R-nn` ORDINAL IS CLAIMED.** Section 8.1 puts the render-contract suite at 22 and the visual suite at "one per screen", and section 8.1's own paragraph replaced two hand-maintained counts with the rules that produce them under [ADR-034](../decisions/ADR-034.md) after finding one of them already wrong. The suites here carry the `M4-R` prefix in their headers and no number. **`M4-R-nn` has no allocation table and no gate**, which is the same hole `OI` has, and claiming an ordinal into it would be a number nobody can reconcile.

- **`INV-M4-03` IS HALF-DISCHARGED AND THE FILE SAYS SO.** `eligible` and `max_payout` are the server's, passed through, and computed nowhere. **The button is owed**, with section 3.2's confirm machine, the re-fetch at confirm (`INV-M4-04`, `AS-M4-02`) and the idempotency key, all of which are money path. A read session that had built the control would have spent the payout session's care budget without its fresh context.

- **`INV-M4-17`'s SECOND DIVERGENCE IS NOT BUILT, AND CANNOT BE FROM HERE.** The operator sees the trader's screen "plus one band and minus the affordances for the routes [ADR-068](../decisions/ADR-068.md) blocks". The band is built. The disabled affordances need the write surfaces to exist first, so they land with [M05](../plans/M05-payout-system.md), [M19](../plans/M19-kyc-identity.md) and [M20](../plans/M20-wallet.md). **The refusal is the server's in every case** and no component here refuses anything, so nothing is missing that was ever this file set's to provide.
