## 2026-08-17 - Session 51: CI-03 folds `advanceDay`, 24 of 30 pass, and the six that do not have three causes (non-money)

- **Done:** **[`runFixture`](../../packages/golden-loader/src/run.ts) folded `evaluate`, the identity stub, so thirty golden fixtures diffed the output of `return { newState: input.accountState, events: [] }` and `RE-D-01`/`RE-D-02`'s golden half was vacuous.** It now folds **`advanceDay`** over the day stream, carrying state and stopping on the first refusal (FM-05). **24 of 30 fixtures pass.** The stage enforces the derived direction on its own: `declaration.holds` went true the moment the fold ran the functions the declaration describes, which is exactly what the 2026-08-17 founder ruling and [ADR-048](../decisions/ADR-048.md) built it to do, with **no fixture edited and no flag removed**. **`AWAITING_ENGINE_INPUT` is empty**, which is what [STATE](../STATE.md) item 3 said M01 landing would mean. `pnpm run typecheck`, `lint`, `format:check` clean; **16 of 16 gates pass clean and fail dirty, 18 scope cases, 10 loader cases**; **730 tests pass and the 6 failures are the six fixtures**. **`packages/rules-engine/src/` and the fixture files are untouched**, per the session fence.
- **Next:** **The six are a fixture-directory session's and a founder ruling's, not the loader's.** Five want two more sessions on [`cme-2026.json`](../../packages/rules-engine/fixtures/calendars/cme-2026.json), one before `2026-11-02` and one after `2026-11-06`; the sixth wants the section 3.4 versus 3.6 ruling. **`resolvePlan` (P2-1) deletes [`src/plan.ts`](../../packages/golden-loader/src/plan.ts) when it lands** and that is stated in the file's first paragraph rather than left to a reader.
- **Blockers:** **CI-03 IS RED AND IT IS RED TRUTHFULLY.** Six named fixtures fail, each printed with the field that moved, in the stage's own output on every run. Nothing was edited to make it green: a fixture edited to match an engine proves only that the code agrees with itself (TR-01), and a directory-wide known-failures list is the `pending: true` TR-03 forbids, one level up. **The founder's alternatives are the two repairs above or reverting one commit.**
- **Landmines:**

  - **NONE OF THE SIX IS AN ENGINE DEFECT, AND THE FIRST FOUR SHARE ONE CAUSE WITH THE FIFTH.** `GS-054`, `GS-055`, `GS-061` and `GS-064` state `phase: funded` with `opened_on: 2026-11-02` and then consume **all five** of the fixture calendar's sessions, so the first mark falls on the account's own open day and `advanceDay` refuses `not_forward` (`INV-14`, `R-06`). `GS-020` passes its eval on `2026-11-06`, the **last day the calendar covers**, so `R-31`'s consistency period starts outside the slice and the day is refused with the typed `calendar_coverage_miss` [ADR-049](../decisions/ADR-049.md) rules for exactly this. **Five of six are one calendar two sessions short**, and the eight funded fixtures that start on `2026-11-03` all pass, which is the control that makes the diagnosis a finding rather than a guess.

  - **`GS-024` IS THE FLOOR-LOCK JUMP DISAGREEMENT ARRIVING AS A NUMBER.** The fixture pins `floor_cents: 5,010,000` and the engine produces `5,050,001`. M01 **section 3.4**'s floor machine is `max(trailed, locked)` and **section 3.6** states the locked value; the engine follows 3.4, the fixture follows 3.6, and [session 49](2026-08-17-session-49.md) already lists this as a standing blocker. **Neither side is wrong and this session did not pick one.** It is the founder's, and it now has a fixture failing on it instead of a paragraph describing it.

  - **THE PROBE HAD TO MOVE WITH THE FOLD, AND A PROBE LEFT BEHIND WOULD HAVE BEEN SILENT FOREVER.** `engineIsIdentityStub()` called `evaluate`; while the stage also folded `evaluate` the two agreed. Had it stayed, `declaration.holds` would have remained false after the switch, the derived assertions would never have switched on, and **the stage would have sat inside its own escape hatch with nothing left to escape** while reporting the premise it was running on as false. `polarity.ts`'s "fourth failure mode" comment describes the condition this repository was in; the fix is that the probe and the fold are one function's worth of code apart.

  - **THE LOADER MAY CHOOSE AN ARGUMENT AND MAY NOT COMPUTE A STATE, AND THE FUNDED START IS WHERE THAT BIT.** `initialState` opens an account in `funded` exactly when `plan.eval === null`, so **there is no exported way to construct a funded state on a plan that HAS an evaluation phase**: in production it arises only inside `advanceDay` through `R-31`. The loader reaches it by opening the account against `{ ...plan, eval: null }`, which takes every field from the engine's own arithmetic including the funded drawdown. The alternative was writing `floorCents: size - drawdown` in the loader, which is `R-12` reimplemented, and a fixture graded against it would be checking the engine against **the loader's** reading of the rule.

  - **`src/plan.ts` IS A SECOND RESOLVER AND ITS OWN FIRST PARAGRAPH SAYS SO.** `advanceDay` takes a `ResolvedPlan`, `resolvePlan` is P2-1 and does not exist, and nothing else can turn a config record into the value the fold requires. Every money value is **read** from the records' materialized `size` block rather than recomputed from basis points; **exactly one value is derived and it is an addition** (`floorAtCents = size + locked_floor_offset_cents`, ADR-014). It is FM-16's shape if it survives beside the real one, so the condition for deleting it is written where a reader of the file will see it.

  - **THREE SPELLINGS OF ONE CONFIG FIELD, AND READING TWO OF THEM REFUSED FIVE FIXTURES.** Eval consistency is `"disabled"` on `CORE-50K`, `{ max_day_share_bp: 3000 }` on `MERIT-RAPID-50K`, and a bare number in every funded block. A fourth spelling still refuses rather than defaulting: a consistency rule the reader could not parse would otherwise resolve to a **disabled gate**, which is a money rule switched off in silence.

  - **`traded_day` IS NOW CHECKED RATHER THAN DROPPED.** `DailyMark` carries no such field because `R-08` derives it from `fill_count`, so a fixture stating both can state a contradiction. `L-10` refuses one. It sits on a new `DERIVED_BY_THE_ENGINE` list rather than on `AWAITING_M01_INPUT`, because a field the engine RECOMPUTES is a different thing from a field it has no home for, and merging them would have made the empty list look occupied.

  - **THE REPORTING WAS COSTING NOTHING AGAINST A STUB AND COST THE FINDING AGAINST A FOLD.** `describeDiff` printed the **expected** event list twice on a noted diff and never the actual one, so "expected 9 event(s), engine emitted 7" did not say **which** seven. The coverage block listed each failing fixture with `derivation.because`, which answers why it is asserted in that direction and nothing about the number that moved. And a refusal read as eight independent wrong fields when there is one cause upstream of all of them. All three are fixed and all three were invisible while every fixture was inverted.

  - **ONE EDIT LANDED OUTSIDE THE STATED FENCE AND IT IS NAMED RATHER THAN FOLDED IN.** [`scripts/ci/engine-digest.mjs`](../../scripts/ci/engine-digest.mjs) read `outcome.result.newState`, which the new `FixtureOutcome` does not carry. It is a consumer of the loader's public API, `RE-D-02`'s determinism digest runs it, and leaving it broken to stay inside the fence would have traded a two-line change for a dead harness. It now also digests `assertions`, because **two runs that refused different days have not agreed**.
