### What `RI-15` asserts, and the window

Three things, and the third is the one that needed an argument. **The path resolves** to a file in
this tree. **The file reaches the line.** And where the pointer is preceded by a backticked name
with nothing but glue between them, **that name appears within two lines of the line cited**,
matched case-insensitively as a substring.

**IT DOES NOT TRY TO READ MEANING AND IT SAYS SO.** The proxy is the shape these citations are
actually written in: a backticked name, then the pointer, `` `principal(request)`
(`admin-writes.ts:269`) ``. Nothing else is inferred, and a pointer with no name beside it is
checked for resolution and range only.

**THE WINDOW IS TWO AND IT IS MEASURED RATHER THAN CHOSEN.** Over every citation in the files it
reads, the widest TRUE citation is one line off: `` `firm` `` cited at `scope.ts:535`, where the
word sits on `:536` because `:535` opens the entry. The narrowest FALSE one on record is three:
`admin-writes.ts:266` for a declaration at `:269`. **Two is the largest window that still catches
every false citation on record and the smallest that admits every true one measured**, and the
price is stated rather than discovered: a drift of one or two lines passes.

### The first draft was armed for 215 lines and disarmed for the rest

It paired backticks from the start of the file. `wiring.test.ts:215` writes ``the engine`s own
`RuleState```, using a backtick as an **apostrophe**, and one stray backtick inverts every pairing
after it: the "name before the pointer" became the prose between two pointers, which has spaces and
is rejected. **All three restored copies of the historical defect went quiet and the check reported
PASS.** It now reads the two backticks immediately before the pointer, so a stray one costs a
single binding rather than every binding below it, and the regression has its own case.

**IT WAS FOUND ONLY BECAUSE THE SEEDS WERE RUN ON THE REAL TREE.** A synthetic fixture nobody wrote
an apostrophe into has even parity, so a suite built first and run against fixtures only would have
reported twelve green cases over a check that could not see the thing it was written for.

on the day they fix the thing this asked them to fix.

### `docs/decisions` is deliberately not an input

The obvious second input is the ADRs and it is the wrong one twice over. **AN ADR IS A DATED RECORD
OF THE TREE AS IT WAS**: its citations were true at its date, they go stale by design when the tree
moves, and repairing one is an amendment requiring an ADR rather than a commit. `ADR-172`'s
`routes/payouts.ts:395` for `PayoutTx.ledger` is 324 lines out today **because `ADR-176` deleted
that member**, which is the entry being right rather than wrong.

**AND THE TWO FINDINGS IT ACTUALLY MAKES THERE ARE BOTH THIS CHECK MISREADING A DOCUMENT WRITTEN
FOR A READER.** `ADR-172:29` cites `wallet-withdrawals.ts:840-863` for `WithdrawalTx`, a RANGE
naming the members while the declaring line sits above it, at `:831` the day the entry was written
and `:835` now. `ADR-176:32` writes a bare `` `:331` `` whose path is two markdown table rows up,
and a bare pointer inherits the nearest full path within six lines, which lands on `start.ts` and
reports a file of a hundred and nine lines. Both are stated as limitations in the `covers` line.

**THE FILE IS HONEST AND THE REGISTER IS NOT.** `index.ts:126` states it in its own words: *"there

that tracks the class**, which is what a register is for.

**IT MATTERS BEYOND TIDINESS AND THAT IS WHY IT IS WRITTEN DOWN.** [ADR-171](../decisions/ADR-171.md)

server was built here**: that is a phase plan's to size and not this session's.
