## 3. What is being built

**Three units, and the split is F8 and the worker rather than taste.**

### 3.1 `packages/kyc`, a new library with no dependencies

**The trigger set cannot live in `apps/api`.** `pre_funded` fires at `phase.passed`, which is [`apps/worker`](../../apps/worker/src/index.ts)'s moment, and [ADR-100](../decisions/ADR-100.md) ruling 2 forbids anything outside `apps/api/src/routes/` from importing anything inside it. A trigger evaluator the worker cannot reach is half a deliverable, which is [`packages/ledger`](../../packages/ledger/src/index.ts)'s own justification one slice over.

### 3.2 `apps/api/src/routes/kyc.ts`

`POST /kyc/session` and `GET /kyc/status`, declared on [`auth.ts`](../../apps/api/src/routes/auth.ts)'s `EndpointSpec` machinery so the required factor is applied in ONE place for every route on this surface, exactly as [`me.ts`](../../apps/api/src/routes/me.ts) does. Both declare `session`, which is [API_CONTRACT:571](../architecture/API_CONTRACT.md)'s *"Auth: session"*. Persistence is a `KycBackend` port that fails CLOSED on every method, so a deployment with no database answers `503` rather than a plausible value.

`POST /kyc/session` evaluates the gate from facts the backend supplies, so **the evaluator has a real caller inside this slice** and `G-PLACEMENT-REACHED`'s checkout call site stays the seam it has to be while [session 220](2026-08-26-session-220.md) holds `checkout.ts`.

`GET /kyc/status`'s `action_required` is `INV-M19-09`: a CLOSED vocabulary of trader-safe next steps, computed here, and **never the provider's own reason**. The suite hands the backend a row whose rejection reason is a provider string and asserts that string appears nowhere in the response.

### 3.3 `apps/api/src/routes/webhooks-kyc.ts`

`POST /webhooks/kyc/:provider`, following [`webhooks-psp.ts`](../../apps/api/src/routes/webhooks-psp.ts)'s shape rather than inventing a second one, and importing its `rawBodyOf` and `installRawWebhookBodyParser` rather than re-deriving them.

**The document screen is this file's own control and it is `INV-M19-07` at run time.** A verified payload is screened for document-bearing keys before anything stores it. A provider that posts an image or a document number is a misconfiguration Merit must not silently persist, so the event is refused with `422 validation_failed`, and the refusal record carries **the offending key names and never their values**.

## 4. The ruling this session takes, which is [ADR-114](../decisions/ADR-114.md)

**The trigger set is not re-decided. [ADR-021](../decisions/ADR-021.md) took it and this session transcribes it.** What needs a ruling is three places where the ruled set meets a tree that has moved since, which is exactly the condition the number was reserved under.

1. **THE TIE-BREAK WITHIN ONE OCCASION, AND WHY THE VOCABULARY'S OWN ORDER IS THE ANSWER.** "Earliest fires" is a statement about time, and two configured triggers can be true at the same evaluation. One value must reach `kyc_verifications.placement`, which is `NOT NULL` under a CHECK. The corpus writes the vocabulary in FUNNEL ORDER three times and all three agree ([ADR-021](../decisions/ADR-021.md)'s table, [M19 section 1.2.1](../plans/M19-kyc-identity.md)'s table, [`0003:76-84`](../../packages/db/migrations/0003_kyc.sql)'s CHECK list), so the earlier-in-funnel trigger names the firing. **The property that makes a snapshot answer a question about time is MONOTONICITY**: a purchase count never falls, a second concurrent account having existed is not undone by closing it, and an evaluation pass is latched. Every condition in the set is monotone, so the earliest-reached trigger of a snapshot IS the earliest-in-time trigger. **That is stated as a clause because a non-monotone trigger added later silently breaks it.**
2. **WHERE THE TRIGGER SET MEETS THE ACCESSOR, AND IT DOES NOT.** `F2`, `F3` and `F4` together: the KYC webhook's contractual anchor names no table, the pair it is made of is not a unique key and must not become one, and no authority admits a request handler with no identity. **So the webhook's store is a PORT with no implementation and `productionDeps` resolves `null`**, which is [ADR-109](../decisions/ADR-109.md) clause 3's shape reached from a second direction. The migration that would close it is a later session's; `0048` stays free.
3. **WHERE THE PORT MEETS A VENDOR.** `F6`: one ordering rule, two implementations, because the first is branded to the payment provider set. The duplication is recorded with the assertion that binds them and with the one edit that would end it.
