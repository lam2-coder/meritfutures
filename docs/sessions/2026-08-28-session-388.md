**Objective.** Rule where the per-account eligibility forecast comes from, or that it should not exist.

**Outcome.** It comes from one gate, under five assumptions that are part of the ruling. The field
stands; the sentence claiming it is `evaluatePayout` projected forward does not.

### 1. The premise that did not survive, and why it mattered

The dispatch and the allocation row both say the forecast has **no source anywhere**. `M01:785` is a
source, it names a function, and **the function cannot be called**: `evaluatePayout` is a pure
function of the `RuleState` it is handed, a `RuleState` for a future day comes only from `advanceDay`,
and `advanceDay` requires that day's `DailyMark`.

**That is worse than an absence rather than better.** A session grepping for a producer finds one, in
an approved plan, and moves on. Sessions 363, 374, 377 and 380 each measured this field and none of
them cites `M01:785`.

### 2. Eleven conditions, one answer

| Knowable at `D+7` from a stored row | Conditions |
|---|---|
| **YES** | `R-37`, the cadence gap. Anchor moves only on settlement; days are published data |
| **NO** | `R-33`, `R-34`, `R-36` (the trader has to trade), `R-35`, `R-39` (the balance has to move), `R-40`'s four and `R-38` (an operator or an event has to act) |

And the one that is knowable is, by [`gates.ts:228`](../../packages/rules-engine/src/payout/gates.ts)'s
own comment, dominated or co-binding on every plan in the lineup. **The only thing a projection can
advance is not the thing the account is waiting for.**

### 3. What the ruling does and does not buy

**Does**: a checkable population, a placement rule that makes `sum(by_day[]) == total_cents` an
identity rather than an opinion, five assumptions a producer may not choose, and a stated direction of
error in each.

**Does not**: `AS-09`. The wave crosses the win-day gate and the field carries no identity dimension,
so the launch requirement is exactly as unserved as this session found it. **Saying so is the
deliverable's second half**, because a ruling that read as clearing it would be the drift.

### 4. `B5` leg 2, refuted

Session 380 recorded leg 2 as a missing `trading_calendar.sequence`. The column is confirmed absent and
**the conclusion does not follow**: every reader of `sequence` is slice-local, so the base is free and
only density inside one covered interval is load bearing, and a slice built from `trading_calendar`
over one covered interval cannot have a hole. **The number was returned before it was taken.**

### Landmines

- **A NAMED PRODUCER IS NOT A DERIVATION, AND IT IS HARDER TO SPOT THAN AN ABSENCE.** Four sessions
  measured this field. The sentence that made it look producible is one table cell in an approved plan.
- **NOTHING CHECKS A CITATION INSIDE AN ADR.** Not the name, not whether the path resolves, not whether
  the file reaches the line. `RI-16` excludes any file whose level-2 heading names a date, and an ADR's
  title heading does. **Derive every pointer by hand, after the last edit above it.**
- **A LINE INSERTED INTO A PLAN SHIFTS EVERY POINTER INTO IT AND NOTHING GOES RED.** Amend a document
  on the line the cell already occupies.
- **A CLEARING CONDITION CAN NAME AN ARM ITS BODY CANNOT OBSERVE.** `B5`'s says *"a rule_states writer
  lands, or a ruling defines the forecast"* and asserts three mechanical facts, none of which a ruling
  moves. This entry is the second arm and the case stays green.
- **AN ALLOCATION ROW CARRIES NO ENFORCED STATE.** Leaving one reading `RESERVED` after its entry
