- **Done:** **[ADR-054](../decisions/ADR-054.md) is written, `status: proposed`, with an unsigned founder-approval line.** `054` was claimed in [ALLOCATION](../decisions/ALLOCATION.md) before a line of it was written, naming the holder the review desk's reservation left as "in flight". **The ruling is that `GS-064` is right and the engine is wrong**: the fixture's `20,000` is what M01's own reference algorithm produces, field for field, across all fourteen pins. The registry row, the two `adr_count` spans and STATE's founder item follow it. **17 of 17 gates pass and `falsify.mjs` is green.** **No fixture and no engine file was touched**, which was the fence.
- **Next:** **Two rulings are now pending one signature each and they empty `CI-03`'s red set between them.** [ADR-052](../decisions/ADR-052.md) repairs `GS-024` in [`floor.ts`](../../packages/rules-engine/src/day/floor.ts); ADR-054 repairs `GS-064` in [`advance.ts`](../../packages/rules-engine/src/day/advance.ts) by deleting one call. **Whoever applies both should expect the count to reach zero**, and a third failure appearing is evidence one of the two fixes is wrong rather than a new discovery. `RE-U-025` is the mechanical remedy the ADR names and it is not written.
- **Blockers:** **None for this session's fence.** `pnpm run verify` still exits 1 on `GS-024` and `GS-064`, both pre-existing, both now ruled and both awaiting the founder's signature before any code moves.
- **Landmines:**

  - **THE ARITHMETIC WAS NEVER IN DISPUTE AND THAT IS WHY THREE READINGS SURVIVED SO LONG.** All three sides agreed on `R-35`'s formula. What none of them had checked is **whether `R-35` runs on that row at all.** It does not: `R-35` is one of `R-33` to `R-41`, which is `DO-9`'s row; `DO-5`'s row reads "**nothing after this runs**"; and section 3.6's breach block enumerates **eight** fields of which `withdrawableCents` is not one. **The answer was four words in a table nobody re-read**, because everybody went to the formula.

  - **THE ENGINE'S GUARD IS A FAITHFUL TRANSCRIPTION AND THE DEFECT IS THE CALL SITE.** `withdrawableCents` returning `0n` outside the funded phase is M01's `withdrawable()` verbatim. The error is that [`advance.ts`](../../packages/rules-engine/src/day/advance.ts) calls it **from inside `DO-5`**, a site M01 does not have. **Checking the function and stopping there confirms the engine.** The finding only appears when you ask where the function is called, which is the difference between reading a line and reading a control flow.

  - **THE GUARD'S `closed` ARM IS UNREACHABLE IN M01's OWN ALGORITHM, AND THAT IS THE SHARPEST FACT IN THE RULING.** At section 3.6's only call site the phase can be `eval` or `funded` and nothing else: `DO-1` refuses a closed prior, `DO-2` returns on `graduated`, and `closed` is set only by the breach block, which returns. **So the guard is the eval phase's.** The engine reached the `closed` arm by adding a call site and then read a policy out of the arm it had just created. It is separately reachable through `R-32` expiry, which does fall through to `DO-9`, so **this ruling does not make the guard dead code** and that was checked rather than assumed.

  - **A CONTEXT CONCERN WAS LIVING IN HASH INPUT 9.** The engine's stated reason is "must not **present** a positive withdrawable", which is a presentation rule. [`0015_rule_states.sql`](../../packages/db/migrations/0015_rule_states.sql) puts `withdrawable_cents` at position 9 of the `state_hash` input list and excludes `context_gates` in the same comment block, citing `INV-23`. **A merged migration is the strongest source available (E2), and it draws the line the comment crossed.** The protection the comment wants is already stated three times: `R-40`, `R-41`, and `maxPayoutCents` "0 when not eligible". `engine_eligible` on the row is already `false`.

  - **THE DATABASE DOES NOT DECIDE IT, AND LOOKING WAS WORTH THE MINUTE.** `0015`'s only constraint on the column is `withdrawable_cents >= 0`, which both readings satisfy. Recording that stops the next reader hunting for a tiebreak that is not there.

  - **NET LIABILITY IS ZERO EITHER WAY, WHICH IS WHY AN ENGINE SESSION COULD PICK EITHER WITHOUT NOTICING.** The field is not payable through any path, so no consequence argument decides it and the ordering law has to. **A disagreement with no cost attached is the kind that survives longest**, and `GS-064` is the only fixture in the directory positioned to surface it.

  - **`40,000` IS PRODUCED BY NO READING AND IS RECORDED ANYWAY.** It needs both `DO-9`'s `R-35` run inside `DO-5` **and** M01's phase guard discarded. STATE named three readings, and a ruling that dismissed one silently would leave it alive for the next session to rediscover.
