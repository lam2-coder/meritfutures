### 1. What was done

**[ADR-249](../decisions/ADR-249.md) ruled the renderer entire and deliberately landed none. This session landed it.**

[`apps/api/src/certificate-card.ts`](../../apps/api/src/certificate-card.ts) holds `renderCertificateCard`,
a pure function from one `CertificateCardInput` to `image/png` bytes plus `FM-M11-05`'s derived
version. It encodes the PNG itself, colour type 3 against a four-entry palette, and draws with a
5 by 8 bitmap typeface held as data in the module. **Its only imports are `node:crypto` and
`node:zlib`**, and the suite asserts that as an exact list rather than as a denylist.

[`apps/api/test/certificate-card.test.ts`](../../apps/api/test/certificate-card.test.ts) is
**twenty-three cases**. The route's own `assertPng` is the oracle for the bytes rather than a
signature check written twice, and the chunk stream is parsed by a reader that recomputes every CRC
from the polynomial, because a checksum verified by its own author verifies nothing.

### 3. The trap, and the four things that shut it

1. **Every copy refusal runs on every render**, all five sentences and the disclosure, including the
   four this card will not draw. That is `routes/verify.ts`' own rule. A deployment with a broken
   `fact_untrue` string fails its first fetch of ANY card rather than its first revocation.
2. **The layout is fixed.** Three-line statement box, five reserved claim slots, a state line drawn
   at the same pixel for `issued` and `revoked`. A claim block that grew past its reservation is a
   refusal rather than a shove.
3. **A deferred row has no member of the state union to arrive as.**
4. **An undrawable character is REFUSED in copy and REPLACED in a row value.** Refusing a row value
   would turn one odd row into a revocation that never renders, which is the trap itself.

**And the route half is executed**: a wired source renders a revoked card and the real request
answers 200 with `image/png` and the exact bytes.
[`certificate-card-home.test.ts`](../../apps/api/test/certificate-card-home.test.ts) already asserts
the 500 beside it, so both directions of `INV-M11-08` now run.

### 6. The seed that passed, which is this session's real finding

**A renderer that ignored `revocation_class` and drew the `valid` sentence on every revoked card
passed the entire suite.**

The case meant to catch it asserted that the four classes produce four DISTINCT cards. They still do,
because the class is also drawn in the state line, so the assertion held for a reason that has
nothing to do with the sentence. **A count of distinct outputs is not a test that the right one was
chosen.**

The replacement is a bijection rather than a count: retune exactly one of the five sentences and
exactly one of the four cards may move. A renderer drawing `valid` everywhere moves NONE of them and
one drawing all five moves ALL of them, so both failure directions are refused. It was watched red
on the same seed. **The weaker case is kept**, with its own comment recording that it was watched
passing on a defect and saying what it actually measures.

### 10. Where this session is most likely wrong

**THE TYPEFACE IS NINETY LINES OF HAND-WRITTEN DATA AND NOTHING VERIFIES ITS SHAPES.** The module
refuses a malformed glyph at load, so a short row or a stray character cannot ship, and the suite
asserts that every symbol of `CERTIFICATE_CODE_ALPHABET` has a glyph. **Nothing asserts that the
glyph for `A` looks like an A.** A transposed pair would draw a wrong character into a plan code or a
certificate token on a public surface, every case here would pass, and a trader would find it. The
cheapest control is one human looking at one rendered alphabet once.

**AND THE LABELS ARE THIS SESSION'S WORDS ON A PUBLIC ARTEFACT.** `EVALUATION PASS`, `PAYOUT`,
`PLAN`, `SIZE`, `TRADING DAY`, `ISSUED` and `CLAIM SCHEMA` are strings this session chose. They are
drawn from columns rather than invented as facts, which is the half that matters and is asserted;
what they are CALLED is ruled nowhere. **Section 6 is the pattern to be suspicious of here: an
assertion that a value is drawn is not an assertion that it is drawn correctly.**

**THE COPY REFUSAL IS A FOOT-GUN IN THE DIRECTION IT WAS CHOSEN FOR.** A typographic apostrophe or a
curly quote pasted into `MERIT_VERIFY_DISCLOSURE` fails every card fetch. That is fail-closed and
state-independent, which is the argument, and neither character is banned anywhere in this corpus.
