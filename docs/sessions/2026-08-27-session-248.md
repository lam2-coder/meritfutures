### 3. `GS-001` looked like a `W1` row, and the tie-break needed the tree rather than the reading

**Its assertion is a containment lookup over a fill's execution timestamp**, which [`rules.ts`](../../packages/rules-engine/src/rules.ts) files among the rules the engine does not declare: *"`R-01` is a containment lookup over a fill's execution timestamp and `DailyMark` carries `fillCount` and no instant."* Ingest owns it, and ingest is M2.

**So `outside-loader-boundary` is the term to check, and its condition is not "the code is elsewhere". It is that the code EXISTS and is elsewhere.** It does not. `packages/rithmic/src` is `index.ts` and a `simulator/` directory; `grep` over `packages`, `apps` and `scripts` for a function mapping an instant to a trading day returns nothing outside the simulator, and [`session.test.ts:88`](../../packages/rithmic/test/session.test.ts) names `GS-001` only to say the simulator stamps every fill strictly INSIDE its session so it never manufactures the boundary case by accident.

> **That comment is the exact shape `CI-06/fixture-inventory` says it cannot see**: *"a comment naming a row beside a live suite that asserts something else entirely passes here."* It is a live suite, it names the row, and it asserts the opposite of the row. **The row does not move**, and the reason it does not is a desk read the gate is not able to perform.
