| [`apps/api/package.json`](../../apps/api/package.json) declares no `@merit/queue` | A job enqueue goes through that package and not through raw SQL, and [ADR-117](../decisions/ADR-117.md) section 5 measured from this very package that the manifest line is the ONLY place the capability can be acquired |

**AN UNSET PORT IS A 500 AND NOT A 503, and the tree's two precedents disagree, so the choice is argued in the file rather than copied.** [`auth.ts`](../../apps/api/src/routes/auth.ts) answers 503 ([ADR-120](../decisions/ADR-120.md)); `public-methods.ts` answers 500 because 503 *"would invite a retry against a process that will never succeed"*. **The second is decisive here because of the batch trigger**: an operator working an incident who is told "service unavailable" retries, and every retry is another manual batch trigger against a process that cannot ever run one.

### 6. There is no in-process factor check, and that is the ruling

[`auth.ts`](../../apps/api/src/routes/auth.ts)'s `authorize` **refuses `admin_sso` unconditionally** and its own comment says why: that module serves the public surface, and an endpoint in it declaring the operator token would be an operator route on the trader origin. `auth.test.ts` asserts no endpoint there declares it.

**Two consequences, and both are stated in the route file rather than left to be inferred from an absence.**

1. **Routing these four through `endpointHandler` would answer 403 to every operator**, which is a route that cannot work.
2. **Writing a second, operator-flavoured `authorize` here is the exact mistake [ADR-083](../decisions/ADR-083.md) section 4 refuses.** *"403 is what a permission check returns. 404 is what an absent route returns"*, and a process that registered the path and then refused it *"can be made to answer 404, and every future handler, middleware ordering and error mapper is another chance to get that wrong."*

**The two controls that hold this surface are the SURFACE and the EDGE.** `C-22` states the pair in one line: *"`/internal/*` only on the admin origin"*. `ADMIN_ORIGIN`'s value is never written into this repository ([ADR-012](../decisions/ADR-012.md), [INFRA section 13.2](../architecture/INFRA.md)), so the edge half is deliberately not expressible here.

**`INTERNAL_REQUIRED_FACTORS` is still written down**, because section 12 requires a server-side declaration per endpoint rather than discipline. It is derived from the same array the routes are, so the table and the registration cannot disagree, and it declares `admin_sso` on all four. **It is a declaration and not the thing that applies it**, and the file says so three times because a reader who assumes otherwise concludes the surface is checked in process.
