- **Landmines:**
  - **Dropping `NOT NULL` from a column named inside an existing `CHECK` does not make the `CHECK` null-safe. It makes it VACUOUS on exactly the rows that now carry `NULL`**, because a `CHECK` that evaluates to `NULL` **passes**. This is [ADR-035](../decisions/ADR-035.md)'s `array_length` defect arriving a second time through a different door. It was **executed rather than reasoned about**: a scratch schema carrying the weak reading, ruled `CHECK` and all, **committed a holiday with a fabricated close instant and no open**, in a containment table, on a day the exchange is shut. Any future session widening a column inside a constraint must re-derive the constraint, not just the column.
  - **F-1's ruled `CHECK (is_holiday = (session_open_at IS NULL))` names ONE of the two session columns.** On its own it leaves a holiday free to carry a `session_close_at`. The pairing inside the rewritten ordering constraint is what closes that, and a later session that "simplifies" the ordering constraint back to `close > open` reopens it silently.
  - **`0026`'s closing `ALTER DEFAULT PRIVILEGES` grants the application role full DML on every table a future migration creates.** So **append-only is false by default** for any new table until the migration that creates it revokes. `0032` is the first migration to hit this. The rule is now written into [DATA_MODEL section 1](../architecture/data-model/README.md) rather than left to be rediscovered, and the append-only set is **twenty** tables across two migrations.
  - **`CI-06g`'s span parser read the name as `[a-z_]+`, with no digits**, so the `e2_files` span was **not a span at all**: invisible to the checker and to the generator, green while the number was wrong. INDEX said 18 files carry an `E2 READ` header against 19 on disk, **in the same sentence calling it a generated span**. Found only because `0032` became the nineteenth. Fixed to `[a-z0-9_]+` and **watched failing on a seeded violation and passing when restored**. A span that cannot be parsed is worse than a hand-maintained number, because it reads as checked. **Any new span name with a digit was silently dead until today**, and `e2_files` was the only one.
  - **Prose that quotes the literal span syntax becomes a span.** Writing the `e2_files` marker out in full inside a STATE paragraph made `CI-06g` parse the rest of the section as span content and fail. Fenced blocks are masked; inline backticks are not. Describe a span by name, never by writing its delimiters.
  - **STATE said "zero `interval` in any case" across the migration set and a case-insensitive grep now returns five**, all the English word in `0032`'s comments. **Zero `interval` arithmetic is the property; zero occurrences of the letters is not.** ADR-042's SQL shape check must **parse the construct**, or it will fire on a comment and still miss `date + '5 days'::interval`. The sentence also said "merged migrations" beside a span that counts the directory, and `0032` is not merged. Both corrected.
  - **The 36 perturbations are not a committed probe.** `scripts/db/probe_trading_calendar.sql` is S-E4's deliverable beside the loader it exists to test. A run that is recorded and never wired is the shape RIDER 2 in [`corpus.yml`](../../.github/workflows/corpus.yml) was added to end.
  - **Two perturbations were written expecting the wrong constraint and the schema corrected the expectation.** Checking by message is what made that visible; an exception-class check would have scored both green and proven nothing about which constraint is load-bearing.
  - **`dependent_row_count` is one column more than ADR-042 lists**, and it is flagged in the migration header for the founder to reject if the ruling is read as five fields exactly. Without it `incident_ref` is nullable with nothing saying when, and "an incident, not a data edit" stays a convention.
  - **That `prior_row.trading_day` equals the row's `trading_day` is NOT a `CHECK`.** The comparison needs a jsonb rendering of a date, which is `STABLE` rather than `IMMUTABLE`, and PostgreSQL rejects a non-immutable expression in a `CHECK`. It belongs to the loader and its probe.
