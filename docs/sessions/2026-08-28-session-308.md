### The experiment, because reading is not the same evidence as watching

PostgreSQL 16.13 in the session container, `initdb` as the `postgres` user, `0001` through `0051` applied forward-only under `ON_ERROR_STOP` with **no failure at any file**. Fixture: one identity, the `trader_wallet` and `fees_revenue` ledger accounts an adjustment posts to, and one prior wallet CREDIT of `50000` cents from a settled payout, landing as `wallet_entries.id = 1`.

| | The write | What the database said |
|---|---|---|
| **A** | The correction **exactly as the contract instructs**: the corrected entry's id into `reference_id` | `ERROR: invalid input syntax for type uuid: "1"` |
| **B** | The same correction through `0038`'s door: `reference_id` is the ADJUSTMENT's id | **`COMMIT`.** `wallet_entries.id = 2`, `provenance = 'correction'`, `balance_after_cents = 60000` |
| **C** | The correcting DEBIT the contract's body admits, with no `reverses_adjustment_id` | `ERROR: ... violates check constraint "account_adjustments_debit_is_a_reversal"` |
| **D** | The `admin_actions` row [`admin-wallet.ts:1504`](../../apps/api/src/routes/admin-wallet.ts) already writes | **`COMMIT`**, and `before->'corrected_entry'->>'id'` answers `1` |
| **E** | A `goodwill` credit, which corrects no entry at all | **`COMMIT`.** `wallet_entries.id = 3`, `provenance = 'correction'`, `reason_code = 'goodwill'` |

Plus two catalog queries that prove the negative: `pg_constraint` returns **zero** foreign keys with `confrelid = 'wallet_entries'`, and the only `information_schema.columns` rows in `public` matching `%entry%`, `%corrects%` or `%corrected%` are `fills.is_corrected` and `round_trips.entry_fills`, neither a wallet reference.

**Write A is the one that could not have been settled by reading.** A decimal string is not a uuid was reasoned by session 298 and by the dispatch; that PostgreSQL refuses it **before any constraint, trigger or invariant gets a turn** is a fact about where the failure happens, and it is why the contract's instruction has never been possible in any deployment, fixture or test.
