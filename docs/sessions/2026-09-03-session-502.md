### 1. The objective, and the shape the session took

Row `311` dispatched [ADR-287](../decisions/ADR-287.md) section 7 slice 7: build `listPayouts()` so `GET /payouts` answers from `payout_requests` with all ten declared fields sourced.

**The session ran in two halves and the first one built nothing on purpose.** Row `311` carries the instruction that a fence-versus-stop-condition conflict is the dispatcher's error and is reported rather than resolved. There was one, it was not cosmetic, and the session stopped at it and pushed the report. **The dispatcher ruled, extended the fence by one needle, and the second half built the slice.** Both halves are recorded here because the stop is the reason the fence moved.

### 2. The re-count, derived here rather than restated

**TEN declared, EIGHT with columns, TWO without**, which is [ADR-290](../decisions/ADR-290.md)'s number arrived at independently.

`PayoutListItem` is [`payouts.ts:260-271`](../../apps/api/src/routes/payouts.ts), **ten fields one per line at `:261` through `:270`**. `payout_requests` is [`0010_payouts.sql:42-124`](../../packages/db/migrations/0010_payouts.sql) with **twenty-four** columns, and `grep -rn 'ALTER TABLE payout_requests' packages/db/migrations` returns **two** lines, both in [`0031`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql), at `:46` adding five columns and `:61` adding a CHECK. **Twenty-nine.**

The full table, field by field with the migration line each was opened at, is [ADR-311](../decisions/ADR-311.md) section 1. **Every one of the eight was opened rather than carried.**

### 3. The two ruled absences, and the source that was opened

**Neither decision is this session's** and that is what slice 2 running first bought. [ADR-290](../decisions/ADR-290.md) ruled both and [API_CONTRACT](../architecture/API_CONTRACT.md) section 6 states both in its own words.

- **`failure_note` is `null` on every row, by construction.** The field describes `failed` and nothing else, both edges into it are enforcement acts, and no row on this tree can reach it. The nearest candidate supplier, `admin_actions.reason`, is refused because the contract excludes admin reasoning from every trader projection in terms and the portal renders this field verbatim.
- **`timeline` is `[]`, and its named source was opened.** `events` is [`0017_events_and_audit.sql:26-62`](../../packages/db/migrations/0017_events_and_audit.sql) and carries every part of the addressing at the lines [ADR-290](../decisions/ADR-290.md) names. The ruling's own measurement was re-run: no deployable constructs an event writer, so `[]` is the projection of the relation. **The member does not query `events`.**
- **The fold over this table's own timestamps is refused in code as well as in writing.** `payout_requests_hold_is_complete` and `payout_requests_freeze_is_complete` are biconditionals, so two of the four state timestamps are NULLed on exit and a fold renders a settled payout that was held with no hold in it.

### 4. The conflict, and how it was answered

[`rule-state-producibility.test.ts`](../../apps/api/test/rule-state-producibility.test.ts) required [`payout-backend.ts`](../../apps/api/src/payout-backend.ts) to contain `` new PayoutBackendUnwired('listPayouts') ``. That file is a census over every deployable and is not `payout-backend.ts`'s suite, so it sat outside the stated fence. Editing it would widen the fence, leaving the case red would end a session on a red suite, and keeping the literal in a comment to satisfy the grep would be weakening a gate to pass it.

**And it was a ruling rather than a line**, which is why it was reported rather than worked around: the assertion encodes `usePayoutBackend`'s closing rule that a partial backend refuses as a whole.

**The dispatcher ruled the fence its own error and extended it to the `listPayouts` needle only**, on two grounds this session verified at source before acting on them:

- **The needle's stated premise had died.** It justified itself as installing these members *"beside a `transact` whose `subject` rejects"*, and the assertion three lines below it in the same block already reads `` expect(backend).not.toContain("new PayoutBackendUnwired('subject')") `` because [ADR-308](../decisions/ADR-308.md) built that member.
- **[ADR-287](../decisions/ADR-287.md) orders slice 7 ahead of slice 9.** Slice 7 is a build blocked only on slice 2; slice 9 is blocked on slices 1 to 7. Reading the needle as "refuses until slice 9" would let a test reorder the plan it serves.

**The whole-refusal ruling is not rewritten and still binds.** `holdFlag` keeps its needle and `idempotency` keeps its absence, so the backend is still partial and installing it is still slice 9's. **[`wiring.test.ts`](../../apps/api/test/wiring.test.ts) was not touched**, on the dispatcher's ruling: its entry is rewritten by slice 9, which deletes it rather than shrinking it.

### 5. What was built

`PayoutBackend.listPayouts` opens the scoped door on the session's identity, reads `payoutRequests` in one call, and maps each row to a `PayoutListItem`. `payoutRequests` is scope class `owned` on `identity_id`, so the handle's own predicate is the whole of the tenancy and the member names no identity a caller could point at somebody else. It is not on `PayoutTx`, on `readCertificates`' shape: a read that decides nothing has no business inside the transaction that approves payouts.

**`approved_at` is suppressed on `held_pending_review`**, which is [ADR-290](../decisions/ADR-290.md) `F6`: the column is `NOT NULL DEFAULT now()` and `0031` relaxed nothing, so a held row carries an insert time in a column the wire calls an approval time, and the contract says `null` while held. **The `hold` block is read two sided**, matching its own biconditional in both directions. **`settled_at` is checked present on `settled`**, which is that constraint's one running direction. **Every refusal is a `PayoutRowError` and therefore a 500**, on this module's existing ruling: an unbuilt member is retryable and a malformed row is not.

**The suite's enum census is derived from the migrations rather than written beside the adapter**, so a sixth `payout_status` member arriving in a later migration turns it red on the commit that adds it. **Three seeds were watched failing before the suite was trusted**: dropping the `F6` suppression, folding a two-entry timeline out of `settled_at`, and adding a sixth enum member to `0030`.

Cause traced: commit `2464c2d` deleted `eligibility_snapshot_id` from `PayoutResponse`, so everything below moved up one and everything above did not, which is why that entry's `:145-147`, `:229` and `:256-259` still resolve exactly. **All three were true when written.** Not repaired: [ADR-290](../decisions/ADR-290.md) is outside the fence and this diff moves no line in that file.
- **No ordering is ruled for `GET /payouts` anywhere.** The accessor has no `ORDER BY` ([ADR-112](../decisions/ADR-112.md) foreclosure 3) and the portal declares it renders in server order and deliberately does not sort. The list is served in the order the read returns, on `readCertificates`' precedent, and [ADR-311](../decisions/ADR-311.md) raises it to the founder rather than choosing a sort key here.

### 7. Landmine

**`RI-15` caught one of this session's own citations and it was repaired at the content rather than by moving a number.** A docblock cited `0030_payout_hold_enum.sql:57` with `` `held_pending_review` `` bound to it, and the checker's rule is that the cited line must declare the bound name or that the enclosing declaration be named: an `ALTER TYPE ... ADD VALUE` line satisfies neither reading. The sentence now names the `ALTER TYPE` and puts the member after the pointer, which is the shape the same docblock's `0001` citation already used. **The finding only appears in the full run**, because `RI-15` reads every source file in the tree.
