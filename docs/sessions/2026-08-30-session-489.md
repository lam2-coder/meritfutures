### 1. The objective

**[ALLOCATION](../decisions/ALLOCATION.md) row `296`: rule what `scripts/corpus/gates.mjs` should report when a gate's body throws, and repair it.** One objective, non-money, tooling. [ADR-294](../decisions/ADR-294.md) section 7 item 2 is the debt this discharges.

### 2. What was read before anything was written

Row `296` in full, then `CLAUDE.md`, [STATE](../STATE.md) and the tail of [docs/sessions](README.md). Then, at source rather than through the row, the thing the row is about: `gates.mjs`'s reporting loop and its file header. Then [ADR-294](../decisions/ADR-294.md) in full, as the entry being transposed, and `repo-invariants.mjs`'s `runChecks` as the shape to transpose.

**The premise was measured before it was ruled on, and the measurement is what kept this entry from restating ADR-294's argument.** The dispatcher's own first paraphrase of this defect was ADR-294's whole shape moved over unchanged, and it was corrected before row `296` was written. Reading the loop first is what makes the difference legible: three of the four things ADR-294 repaired were **already right here**.

### 3. What the runner already did right, and what it did not

| | `repo-invariants.mjs` before ADR-294 | `gates.mjs` before this row |
|---|---|---|
| Prints the word `ERROR` | yes | **yes** |
| Denominator shrinks on a crash | no | **no** |
| Exits non-zero on a crash | yes | **yes** |
| Crash counted apart from a violation | no | **no** |
| Exit code distinct from a violation | no | **no** |
| Held-sentence suppressed on a crash | no | **no** |
| The sentence it printed over a crash | `29 of 30 invariants hold.` | `32 of 33 gates pass.` |

**The two runners were never equally broken and the entry says so.** `29 of 30 invariants hold.` put an unmeasured check on the **held side** of the arithmetic. `32 of 33 gates pass.` is arithmetically true: thirty-two gates did pass. **What is false is the clause beside it** and the impression the pair leaves, and that is a narrower defect wanting a narrower fix.

### 4. The proof, and how the crash was seeded

**One `throw` as the first statement of `CI-06r`'s body**, run, transcript and exit code captured without a pipe, then removed. **Appending a thirty-fourth gate was tried first and rejected on the transcript it produces**: `GATES.length` is the `gate_count` generated span, so a seeded gate turns `CI-06g` red with **182** findings across `INDEX.md` and `STATE.md`, and a transcript carrying that is a transcript about `CI-06g` rather than about a crash. The claim under test is what a crash reads on a thirty-three-gate run, so the run has to have thirty-three gates in it.

Four transcripts, two pairs, all in [ADR-296](../decisions/ADR-296.md) section 3.

### 5. The ruling

Three-way tally, denominator held, exit `3` dominating a violation, and the pass sentence suppressed on a crashed run. `EXIT`, `runGates` and `GATES` are exported and `process.exit(main())` is now guarded by `invokedDirectly`, which is what makes the report readable by a suite. Full ruling and the four decided properties in [ADR-296](../decisions/ADR-296.md) section 4.

### 6. The fence judgement, which is the one thing to check

**The row put *"tests over it"* IN the fence and `packages/**` OUT of it, and on this tree those two clauses meet.** `packages/tooling/test/` is where the twin suite lives and was tried first. It does not work: `packages/tooling/tsconfig.json` sets `checkJs: true`, so importing `gates.mjs` from a suite there pulls nine thousand lines of never-typechecked JavaScript into a strict program and it fails by the screen. **The two ways past are to type-check the whole runner, which moves every cited line in it, or to disable checking for that file, which weakens a control to land a test.** Both were refused.

**So the suite went beside the runner, and `scripts/corpus` became a Vitest source root and a `tsc` project**, which is what `scripts/demo` already is, for reasons both files already state in their own words. `packages/**` is untouched, which is what the row's exclusion was protecting. The cost is three lines across `vitest.config.ts`, `package.json` and a new `scripts/corpus/tsconfig.json`. **It is written up in [ADR-296](../decisions/ADR-296.md) section 8 and raised again in the approval note, because a founder may read the fence the other way and the repair is to move one file and delete three lines.**

### 8. Landmines for the next session

- **`git checkout -- <file>` reverts the whole file, and it took a finished change with it once in this session.** The seeded crash was removed with it while the fix was still uncommitted. Nothing was lost because the patch was scripted and re-applied byte for byte, verified by re-running the transcript capture and diffing against the one taken before, but the lesson is the cheaper one: **commit the fix before seeding anything into the file it lives in.**
- **`scripts/corpus` is now a Vitest source root and a `tsc` project.** A `.test.ts` added under `scripts/corpus/test/` runs in CI-02 from now on, and `checkJs` is OFF in that project deliberately, which is argued in the tsconfig's own `//` key rather than left as a flag somebody flips.
- **`GATES` is exported.** Nothing but the suite reads it. It is named in the approval note as a thing a founder may want unexported.
- **The `note:` lines gate bodies print are not routed through `emit`.** A caller supplying its own `emit` collects the runner's lines and not the notes. Stated in the code and in ADR-296 section 7 item 4.
- **`node_modules` was absent on arrival for the fourth session running in this container.**
