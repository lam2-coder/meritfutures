### 2. The premise was read before it was ruled on, and it did not survive

The dispatch and the ALLOCATION row both said five ports wait on `systemDb('operator-console')`. **Each was read at its own declaration rather than in the blocked list that named it.**

| Port | What it waits on, at source | Door? |
|---|---|---|
| `setAdminSessionSource` | **The admin identity provider.** [`admin-reads.ts:186-197`](../../apps/api/src/routes/admin-reads.ts): the mapping from a session to an actor and a role *"is the admin identity provider's"*. **The database holds no operator**: `admin_actions.actor` is `text NOT NULL` with no foreign key, and `grep -rn "admin_sessions\|admin_users\|admin_actors\|operator_sessions" packages/db/migrations/` returns nothing | **No, and none could** |
| `useAdminWriteBackend` | `principal(request)`, `tradingDay()`, and a `ValidationResult` to `PlanValidation` projection | No |
| `useAdminPayoutBackend` | `principal(request)`. **MONEY PATH** | No |
| `useAdminWalletBackend` | `principal(request)`, `writeCorrection`, `reconcile`. **MONEY PATH** | No |
| `setAdminReadSource` | **A read shape**, [`admin-reads.ts:667`](../../apps/api/src/routes/admin-reads.ts) | No |

**`principal(request)` resolves only through `AdminSessionSource`** ([`admin-reads.ts:800`](../../apps/api/src/routes/admin-reads.ts), which throws when nothing is wired), so three of the five reduce to the first. **The honest restatement of session 302's sentence is that four of the five are one ruling and it is not this one.**

### 3. The argument that would hold even if the count were five

**`ApiDb` is a parameter and not an import.** Every adapter is `databaseX(db: ApiDb)` and every one is handed `LIVE_DB` by [`start.ts`](../../apps/api/src/start.ts). So a third method is not a capability the admin adapters acquire, it is a capability **[`databaseAuthBackend`](../../apps/api/src/auth-backend.ts) acquires** -- and `NO_PRE_IDENTITY_READ`, the constant that answers twelve of that port's sixteen methods, refuses on precisely the sentence a door would defeat: *"`systemDb`'s reason vocabulary is `nightly-batch | operator-console`, which a request handler is not in."*

`SystemTx` is declared over every `TableKey` with `insert`, `updateAt` and `deleteAt` on it ([`scoped-db.ts:1798-1831`](../../packages/db/src/scoped-db.ts)). **The two existing doors are narrowings of the estate; the third is the estate.**

### 4. The suite found the convention already broken, which is worth more than the seeds

The case was first written as [ADR-165](../decisions/ADR-165.md) section 10 finding 5 words it, *"exactly one file under `src` imports the accessor"*, and **it failed on its first run**:

```
AssertionError: expected [ 'src/db.ts', ...(1) ] to deeply equal [ 'src/db.ts' ]
+   "src/routes/account-reads.ts",
```

`atMost` mints a frozen `FilterTerm` and yields no handle, so the drift is benign. The case therefore pins a MAP of file to the values it takes off the accessor, and asserts separately -- first, and with a message naming the file and the name -- that **no file but `src/db.ts` takes any of `firmDb`, `scopedDb`, `systemDb` or `transaction`**. `src/db.ts`'s paragraph describing the older tree is replaced.

**Then three seeds, each reverted:**

| Seed | Cases red | What it said |
|---|---|---|
| `operator(fn)` on `ApiDb` and `LIVE_DB` at `systemDb('operator-console')` | **3 of 3** | `expected [ 'scoped', 'firm', 'operator' ] to deeply equal [ 'scoped', 'firm' ]` |
| `systemDb` added to the import list, unused | **2 of 3** | the import-list equality, naming `systemDb` |
| `import { scopedDb }` added to `routes/wallet.ts` | **1 of 3** | `[ "src/routes/wallet.ts takes scopedDb" ]` |

**The third is the one that matters**: `tsc`, `eslint` and every other suite in this deployable accept it in silence. **The handle assertion was moved before the map assertion after watching it**, because both fail on that diff and only one of them names the file and the handle.

### 5. One error was made inside the session and it is recorded rather than quietly fixed

**`prettier --write` was run over three files under `docs/`.** This repo's `format` and `format:check` are scoped to code -- `"*.{js,mjs,ts,json}"` and `"{apps,packages,e2e}/**"` -- so `docs/` is never prettier-formatted here. The run padded every table cell in [STATE](../STATE.md) and [ALLOCATION](../decisions/ALLOCATION.md), **and broke `CI-06g` by reformatting the generated `adr_registry` span in [decisions/README](../decisions/README.md) so it no longer byte-matched its own generator's output.**

It was caught by running the gate rather than by reading the diff, and both files were restored from `origin/main` with only the intended edits re-applied. **The commit that did it and the commit that reverted it are both on the branch**, which is the form this project uses for an error made and repaired inside a session.

### 6. One full-suite run reported a failure and the case was NOT captured

**Stated plainly because a run that went red is not a run to round down.** One `pnpm vitest run`, chained behind `typecheck`, `lint` and `format:check` in a single command, reported `1 failed | 4090 passed | 6 skipped` with a duration of **98.76s against a 33s norm**. Only the tail was kept, so **the failing case's name is not known.**

**Five subsequent full runs were clean**, three unloaded and two behind the identical chain, all `192 passed | 4091 passed | 6 skipped`. **The suite holds exactly two wall-clock-dependent assertions and both are outside this diff:**

- [`packages/enrichment/test/observe.test.ts:448`](../../packages/enrichment/test/observe.test.ts), `Date.now() - started < 5_000` against a 15ms race, whose own comment says *"the bound is loose because a scheduler is not a clock"*. **It is the only assertion in the suite whose outcome can turn on contention alone**, and a run taking three times its normal wall time is the condition it is loose against.
- [`apps/api/test/checkout.test.ts:1436`](../../apps/api/test/checkout.test.ts), a LOWER bound of `ENRICHMENT_TIMEOUT_MS - 50`, which contention cannot breach.

**The first is named as the candidate and is NOT asserted to have been the failure**, because the evidence for that is exactly the evidence that was not captured. `packages/enrichment/test/**` is outside this fence, nothing was changed there, and the finding is reported for whoever holds it next.
