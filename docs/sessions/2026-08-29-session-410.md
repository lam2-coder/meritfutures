### 3. Nothing is repaired by writing the right numeral

[ADR-034](../decisions/ADR-034.md)'s remedy has exactly two branches: **generate
the value, or delete it and point at the source.** [ADR-212](../decisions/ADR-212.md)
refused the rewrite for `CITATION_WINDOW` and [ADR-214](../decisions/ADR-214.md)
refused it for `DISPATCH_PROTOCOL`'s invariant count, on the same ground: a number
written down goes stale and rewriting it only resets *when*.

**Eleven sites take the second branch.** The count leaves the sentence and the
sentence keeps its point, which was never the number: *"One error class and a
DISTINCT REASON PER REFUSAL is what makes a 503 from `POST /auth/otp` a different
fact from a 503 from `POST /auth/passkey/login/options`."* Every retired sentence
is quoted as history rather than deleted, on `RI-14`'s rule that a false sentence
deleted leaves nothing for the next reader to check.

**One site takes the first**, and it is the port docblock in `routes/auth.ts`:

> `grep -rn "    async " apps/api/src/auth-backend.ts` returns 5 lines, one per
> method that file implements against the accessor, and
> `grep -rn ": blocked" apps/api/src/auth-backend.ts` returns 11 lines, one per
> refusal.

That is `ADR-214` clause 3 applied to a COUNT rather than to an existence claim.
The burden lands on the sentence making the claim rather than on every sentence
that is not making one, and `RI-20` executes both on every `CI-01`.

### 4. A claim must not be able to satisfy itself

**This is the part that is not obvious and it decided the layout.** A grep over
the file a sentence is written in matches the sentence. Writing the refusal count
into `auth-backend.ts` would put `: blocked` on one more line of the file the
command reads, so the sentence would change the number it is asserting and a true
count would be **unwritable there**.

So the two claims are **crossed**:

| The file | States | Settled over |
|---|---|---|
| `routes/auth.ts` | 5 implemented, 11 refused | `auth-backend.ts` |
| `auth-backend.ts` | 16 port members | `routes/auth.ts` |

`grep -rn ": unwired" apps/api/src/routes/auth.ts` returns 16 lines because
`UNWIRED_AUTH_BACKEND` has one entry per port method, and
`UNWIRED_AUTH_BACKEND: AuthBackend` makes that list the port's own membership at
**compile time** rather than a second copy of it. A case in
[`repo-invariants.test.ts`](../../packages/tooling/test/repo-invariants.test.ts)
asserts the self-matching failure rather than describing it: three refusals plus
the claim about them is four, and the finding is off by exactly the line the claim
occupies.

### 5. Does an existing check already reach this? No, and it is measured at zero

**`RI-20`'s grammar over the three auth files as they stood moves 0 sites.** It
runs a reason's own quoted command; a bare numeral quotes none, so the check is
structurally blind to this class. That is the same boundary `ADR-214` drew for
schema objects, arriving one class over.

**The closest check in the tree is [`CI-06/derivable-counts`](../../scripts/corpus/gates.mjs)
and it already knows it does not reach this.** Its own `covers` line records that
it reads **markdown only**, that the same recogniser over every `.ts`, `.tsx`,
`.mjs` and `.sql` finds **17** further sites, that closing them **needs a
comment-span generator**, and that its vocabulary "is a recorded reading of eight
populations, not a derivation, so an underivable one is unpoliced". The auth
partition is exactly that: deriving it needs a query that reads TypeScript, and
`SPAN_QUERIES` reads migrations. **So the remedy that gate names is much larger
than `RI-20`'s, and `RI-20`'s is the small extension the row asked to be
considered.**
