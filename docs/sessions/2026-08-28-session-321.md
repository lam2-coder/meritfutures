- **Objective:** seed and rule the chart of accounts. `ledger_accounts` is the table every posting
  in this system names and nothing has ever populated it. `ADR-177` required, migration `0052`
  reserved and expected to be taken.

- **Done:** **[ADR-177](../decisions/ADR-177.md)** and
  **[`0052_chart_of_accounts.sql`](../../packages/db/migrations/0052_chart_of_accounts.sql)**,
  which adds `ledger_accounts_kind_matches_code` binding four codes to a kind and seeds
  `fees_revenue`. [ALLOCATION](../decisions/ALLOCATION.md) row `177` amended in place
  ([ADR-065](../decisions/ADR-065.md) T3). New
  [`chart-of-accounts-kinds.test.ts`](../../packages/ledger/test/chart-of-accounts-kinds.test.ts)
  watches the four ruled kinds **and the three refused ones**, so a code cannot leave the open list
  quietly. [`probe_ledger_constraints.sql`](../../scripts/db/probe_ledger_constraints.sql) repaired.
  [`packages/rail`](../../packages/rail/src/settlement.ts)'s finding C updated where it had gone
  stale.

- **Next:** **`LT-07`'s repair is still blocked, and on ONE question rather than an absence:**
  which of the two unanimous halves of this corpus is wrong about `firm_treasury`. Section 3 of
  [ADR-177](../decisions/ADR-177.md) lays both readings out and section 8 names the choice as the
  founder's, because it is answerable in a sentence by somebody who can say which half to
  disbelieve and is not answerable from the tree at all.

- **Blockers:** **Nothing creates a ledger account for an identity, at any point.** There is no
  INSERT against `ledger_accounts` anywhere in the application, `LedgerReadKey` is a read key, and
  [`chart.ts`](../../packages/ledger/src/chart.ts) only reads, so the three per-identity classes
  have no writer and `postTransaction` REFUSES rather than creating one. **The money path is
  blocked on that independently of this session's subject and the seed does not unblock it.**

- **Landmines:**

  1. **`0052`'s HEADER QUOTES ITS OWN STATEMENTS AND TWO SEPARATE FILES READ THE PROSE AS SQL.**
     Anything parsing that migration must strip `--` comments FIRST. The two failures were in
     opposite directions and both looked like passes for a moment: one anchored on
     `INSERT INTO ledger_accounts` three screens above the statement and sliced an empty string
     that satisfied every loop over it, and one counted two INSERTs where there is one. Both
     readers now strip first and one of them throws on an empty slice.
  2. **THE `ELSE true` IS LOAD BEARING AND DELETING IT CHANGES NOTHING VISIBLE.** Without it the
     `CASE` returns NULL for the three refused codes, and a CHECK passes on NULL, so the
     constraint would behave identically and say something else entirely. The word is the only
     thing telling a reader the hole is deliberate.
  3. **DO NOT READ THE PROBE'S FIXTURES AS THE CHART.** Three of this session's four derivations
     agree with [`probe_ledger_constraints.sql`](../../scripts/db/probe_ledger_constraints.sql)'s
     literals, and the agreement was noticed AFTER the derivations were taken from the postings.
     [ADR-174](../decisions/ADR-174.md) section 4 is right that a fixture chosen to make a
     constraint reject something is not a statement of the chart, and two readers reaching one
     answer is still not a source.
  4. **`REVOKE UPDATE, DELETE ON ledger_accounts` IS THE OBVIOUS NEXT MOVE AND IT IS A FROZEN
     DOCUMENT AMENDMENT.** It would make the table append-only by
     [`assert_append_only_grants.mjs`](../../scripts/db/assert_append_only_grants.mjs)'s own
     definition, which asserts that set against [DATA_MODEL](../architecture/data-model/README.md)
     section 1 in both directions. A session reaching for it without an ADR turns that gate red.
  5. **THE SEED IS A PLAIN `INSERT` ON PURPOSE.** Making it `ON CONFLICT DO NOTHING` reintroduces
     the exact defect this session found one file over, where a silent skip left a CI probe passing
     while it had stopped probing.

**THE TWO MISSES HAVE ONE CAUSE AND IT IS WORTH MORE THAN THE TWENTY PASSES.** `0052`'s header argues its ruling at length and quotes its own SQL while doing so. [`chart-of-accounts-kinds.test.ts`](../../packages/ledger/test/chart-of-accounts-kinds.test.ts) anchored on `INSERT INTO ledger_accounts` and found the mention in the prose three screens above the statement, sliced to the next `;`, stripped the comments from that slice, and got an **empty string** which satisfied every `for` loop over it. [`lt-07.test.ts`](../../packages/rail/test/lt-07.test.ts) counted `INSERT INTO ledger_accounts` over the raw file and got **two** where there is one. **The first failure mode is the dangerous one**, because an empty slice is green, and it is now a thrown error rather than a passing test. Both readers strip comments before matching.

**A gate nobody has watched fail is not a gate, and this session's most useful measurement was of a gate it nearly broke.** The CI ledger probe would have kept its shape, kept its name and kept passing while no longer probing `LEDGER-C1`, which is the constraint its own header calls the one that matters most.
