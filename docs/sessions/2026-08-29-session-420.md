**Outcome.** **The door is built and the route does not serve.** The row named that outcome in advance and called it real progress: *"a written account of the one thing that still refuses it."* There are three things, and two of them were not in the `BLOCKED` entry.

### 2. What was built

`PairRule.writer`, **required**, two arms, each carrying its own reason. `ScopedTx.insertAsParty` over `PartyWritableTableKey`, which is **derived from the registry** rather than an `Extract` down to one member: that is the opposite of `ParentedTableKey`'s choice and is made on the same reasoning, because there the CLASS is not the ruling and here it is.

**The narrowness is a stamp.** The writer's column is written from the handle and refused to the caller in both spellings; the counterparty is required and is the caller's; there is no `RETURNING`.

**16 cases, three directions, one control case.** The stamp, the refusal (with **nothing sent** when it throws), and the absence of any new read. The control case runs the same call on a second identity, because a door that refused everything would pass every negative in the file.

**Two seeded defects were watched failing** the row's own assertion by name: the caller's values spread after the stamp, and the refusal loop short-circuited. **A third refusal is a compile error**, falsified by flipping the `@ts-expect-error` literal and watching `tsc` report `TS2578`.

`clickByToken` ([`:753`](../../apps/api/src/routes/checkout.ts)) and `couponByCode` both return an `AffiliateRef` carrying `affiliates.identity_id`. `affiliates` is `owned` ([`scope.ts:1093`](../../packages/db/src/scope.ts)) and `affiliate_clicks` is `derived` through it ([`scope.ts:1109`](../../packages/db/src/scope.ts)), whose reason says *"A CLICK BELONGS TO THE AFFILIATE AND NOT TO THE PERSON WHO CLICKED."* **A buyer-scoped read of either returns the empty set** and `resolveAttribution` folds every referral as organic. **A wrong answer that returns rows**, which needs a ruling and not a door.

### 6. Landmines

- **A `pair` WRITE AND A `pair` READ ARE DIFFERENT QUESTIONS AND THE FILE NOW SAYS BOTH.** A reader who meets `scopePredicate`'s `pair` branch throwing, or `PairTableKey`'s docblock, will read a refusal that is still completely true and is about reads only. Every one of those sites carries the distinction now; **the failure mode is a later session deleting the refusal because a door exists.**
- **A GUARD REFUSING A SELF-DEAL COUNTERPARTY LOOKS STRICTLY SAFER AND IS NOT.** It would make `attributions`' voided literal self-deal row unwritable. There is a test whose only job is to hold that line.
- **`insertAsParty` HAS NO CALLER AND NOTHING HAS RUN IT AGAINST A DATABASE.** Every assertion reads SQL that was built and never sent, which is `write-accessor.test.ts`'s stated limit inherited rather than solved. **What that cannot catch is a `NOT NULL` this door does not know about.** The failure direction is a refused write and never a wrong row.
- **`attributions` HAS NO NAMED UNIQUE CONSTRAINT.** `purchase_id uuid NOT NULL UNIQUE` is inline at [`0012:77`](../../packages/db/migrations/0012_disputes_and_affiliate_settlement.sql), so PostgreSQL names it `attributions_purchase_id_key`. A first draft of the registry reason here cited `attributions_purchase_uq`, **a name this tree has never had**, and it was caught by reading the DDL and by no gate: `RI-20` reaches a quoted COMMAND and not a constraint name.
- **`RI-15` AGAIN, FOURTH CONSECUTIVE SESSION IN THIS NEIGHBOURHOOD, AND THE WORST CASE SO FAR AT 27 POINTERS.** A declaration inserted into `scope.ts` moves every citation below it in this file and in every file pointing into it. **Derive pointers last**, and note that committing the source change first makes a diff-hunk line map read as empty: compute the map against `origin/main`, not against `HEAD`.
- **`repo-invariants.mjs` reports fewer than its full count with `node_modules` absent**, and the shortfall is an `ERROR` rather than a violation. `pnpm install` first, then read the runner's own last line.
- **`DISPATCH_PROTOCOL` section 4's invariant row still reads 18** against a runner reporting 20. Outside every fence, reported again, now twelve sessions behind.
