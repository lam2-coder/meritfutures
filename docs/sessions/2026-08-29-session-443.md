**Objective.** Rule on both of `useAffiliateDeps`' obstructions before building anywhere, register
`affiliate_commissions` and the issued-link table if and only if the rulings support it, and repair
the retired sentence the wiring entry registered as outside its own fence.

**Outcome.** **Both rulings are refusals, and they are refusals of different kinds.** The first is a
refusal to write a scope rule, because none of the six is true. The second is a refusal to take a
migration, because the thing it would model is not an object this schema has. **The session's one

making was the one the tree could not catch.

### 2. The first ruling, and why `firm` is the dangerous answer rather than the obvious one

The enumeration is in [`packages/db/test/affiliate-commissions-unregistrable.test.ts`](../../packages/db/test/affiliate-commissions-unregistrable.test.ts) and reads the migrations rather than `schema.ts`, because the subject is a table `schema.ts` does not contain.

`scope.ts` has argued with this table by name since [ADR-106](../decisions/ADR-106.md), and its argument
covers exactly one of the six. What the session found is that **the argument is right and is not the
whole refusal**. Two further `derived` edges exist on the row, one of which would actually terminate,
and `firm` is available and is accepted by everything.

**`paid_in_statement_id` IS THE PLAUSIBLE MISTAKE.** The walk through it ends at `affiliates`, which
is `owned`, so the mechanical chain check passes. It is refused on nullability and on the population
that nullability hides: `status` admits four members and only `paid` is bound to carry a statement,
so the hop returns the paid rows and drops every `accrued`, `payable` and `clawed_back` one. Those
are the rows an affiliate arguing about money is arguing about.

**`firm` IS THE ONE THAT MATTERS.** The row declares no column against `identities(id)`, which is the
whole of the predicate the suite reads for its firm assertion. So a `firm` rule compiles, satisfies
the totality clause, satisfies that assertion, and makes the row readable through `firmDb()`, which
takes no reason on the ground that no identity is at risk. **Here one is.**

### 3. The second ruling: an issued link is not a row

[`apps/api/test/affiliate-issued-link.test.ts`](../../apps/api/test/affiliate-issued-link.test.ts) carries it.

The token a buyer presents names a click, `affiliate_clicks_token_uq` is UNIQUE over it, and
`resolveAttribution`'s own docblock leans on that index when it says it does not sort. **One issued
link is clicked many times and a UNIQUE column holds a value once**, so the handle an affiliate is
issued and the token a buyer presents are two objects. The module header already refused a write at
issue time on the `clicks_30d` denominator; this refusal is independent of that count.

**No link row is owed**, on three measurements: `affiliate_clicks` already carries `affiliate_id` and
`landing_path` at click grain, `affiliates.code` is already a unique public handle, and nothing under
`apps/api/src` writes a click row, so a link table's only reader would be absent.

**The contract collision is REPORTED and not repaired.** API_CONTRACT names the response field
`click_token` and it is a link handle wearing a click token's name. That document is frozen and
outside this fence.

### 4. The control

**A `firm` rule carries a reason and no columns, so the registry holds nothing to check a firm claim
against. The migrations do.** The new case walks every relation registered `firm`, reads its
`CREATE TABLE` body, and refuses any `NOT NULL` foreign key whose parent reaches an identity. It is
green over every firm relation with zero violations, and it was watched failing on the real seeded
registration rather than on a synthetic one.

**Under the seed, `pnpm run typecheck` exits 0 and the existing firm assertion stays green.** The new
case goes red with one violation. The only other tenancy-relevant red is a hand-maintained arity.

**What it would have caught on `origin/main` is nothing**, and that is reported rather than dressed
up. It is written because the mistake it refuses is available right now to the next session that
opens `scope.ts` on this table.

### 5. Blockers, landmines and what is owed

- **`useAffiliateDeps` stays BLOCKED on `stats`** and the entry now says the table is a class away rather than a registration away.
- **The seventh class is a slice with its own row.** The argument for it is in [ADR-253](../decisions/ADR-253.md) section 6, with a standing condition attached: it rests on `attribution_id` being opaque to its holder, and any door that ever resolves an `attributions` row from its id for a party brings ADR-106's ground back one hop out.
- **The click-ingestion slice is named as absent**, and two things are owed to it that this session deliberately did not take: the handler, and `campaign` as a column beside `landing_path`.
- **The contract field is misnamed** and repairing it needs an entry allowed to touch API_CONTRACT.
- **LANDMINE:** the control checks a NECESSARY condition and not a sufficient one. A table can satisfy it and still be wrongly `firm`. An entry reading it as validating firm rules in general is reading it too widely.
