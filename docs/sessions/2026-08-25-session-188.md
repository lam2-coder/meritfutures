### The finding: a derivation chain that ends at a firm table is a throw nothing was watching for

**`DerivedRule.via` is typed `TableKey`, and `TableKey` includes every `firm` key by construction.** So this compiles:

```ts
planVersionSizes: {
  class: 'derived',
  via: 'planVersions',      // firm
  localColumn: 'plan_version_id',
  foreignColumn: 'id',
  traversal: 'hop',
  why: '...',
},
```

`scopePredicate` recurses into `rule.via` and the `firm` branch of that switch **throws**. The table is therefore a member of `ScopedTableKey`, `scopedDb(id).rows('planVersionSizes')` type-checks at every call site, and the first read raises. **Both halves were executed rather than reasoned about:**

| Seeded | Command | Result |
|---|---|---|
| `plan_version_sizes` declared `derived` via `plan_versions` | `vitest run packages/db/test/scoped-db.test.ts` | **41 passed. GREEN.** Every existing assertion satisfied |
| the same seed | `scopePredicate('planVersionSizes', 'i-1')` | **THREW**: *"planVersions belongs to no identity (...) and has no scoped reading. Use systemDb(reason)"* |

**The type checker cannot refuse this and narrowing `via` would be worse**: a rule must be able to name a table before that table's own class is known, so the check belongs in the suite. **`plan_version_sizes` is the first registered table where the mistake is plausible rather than perverse.** Every derived rule before it hops to an `owned` table; `plan_version_sizes.plan_version_id` is a `NOT NULL` foreign key that reads exactly like `daily_marks.account_id` and `rule_states.account_id`, and is not one, because `plan_versions` is `firm` and `daily_marks` and `rule_states`' parent is not.

**The check is one test and it is BOUNDED**, because a cycle among derived rules would otherwise recurse until the stack ran out, here and inside `scopePredicate` alike. Both directions watched:

| Seeded | Result |
|---|---|
| the firm terminus above | **RED**, naming the chain and the offending table: *"planVersionSizes derives through planVersionSizes -> planVersions, and planVersions is firm"* |
| `daily_marks` via `ruleStates` and `ruleStates` via `dailyMarks` | **RED in 6ms**, *"dailyMarks's chain revisits dailyMarks: dailyMarks -> ruleStates -> dailyMarks"*, plus the FK assertion beside it. **No hang** |
| nothing | 42 passed |

**No ADR was minted for this and none is needed.** It widens no vocabulary, relaxes no refusal and rules nothing: it asserts a property [`scope.ts`](../../packages/db/src/scope.ts) and [`scoped-db.ts`](../../packages/db/src/scoped-db.ts) already state in prose, in the file `P4-b`'s fence already holds, which is the constitution's own *"prefer a new CI gate over a bigger model whenever the error is checkable."*

| Table | Class | Reaches an identity by |

| `proof_links` | `firm` | nothing. What Merit publishes about itself |

**Nine of the twenty-one registered tables are now `firm` and twelve are reachable through the scoped accessor**, so `falsify:ci`'s `CI-01/scope-firm-table-refused` was re-watched with three times the firm surface it was written against.

### Ten of ten, and the direction that makes a slice smaller

[Session 182](2026-08-24-session-182.md) registered **four** tables where its slice named three, because `DerivedRule.via` is typed `TableKey` and `sessions` reaches an identity only through `users`. **The same shape arose here and resolved the other way.** `daily_marks` is the only new `derived` rule and it names `accounts`, which [session 182](2026-08-24-session-182.md) and [ADR-084](../decisions/ADR-084.md) had already registered. **The registry's totality reached past the slice and found the table already there.**

That is [ADR-092](../decisions/ADR-092.md) section 9's *"a slice of M17's four tables, minus whatever is already registered"* -- the cost it states rather than solves -- **arriving in the direction where the cost is negative.** Reported as **ten of ten** rather than as ten of ten with nothing to say about it, because the count could have been eleven and the reason it is not is a fact about the tree rather than about the plan.
