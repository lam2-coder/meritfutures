### 3. The count, honestly: one of two

**`OI-28` closes. `OI-29` does not.**

`0047` shut two of its three states at the write. `OI-29b` carries the third. **ADR-156 measures how far "at the write" reaches and the answer is one statement**, so a row moved to closed on the strength of that control would be [`RI-04`](../../packages/tooling/checks/repo-invariants.mjs) again: a check cited to protect something it asserts nothing about. The corpus has paid for that shape once and the row stays open.

**The remedy is named and unnumbered.** *A `simulation_runs` row cited by a `published` `plan_versions` row must not have `status` or `plan_version_id` changed, except for the anchor moving from `NULL` to the row that cites it.* No migration number, because a migration is never edited once merged and this fence forbade one; no `OI` number, because the allocator's `OI` table is held here for two rows.

### 4. The measurement, and why it is a negative control

PostgreSQL 16.13, every migration applied forward-only into an empty database under `ON_ERROR_STOP=1`, which is the construction `0047`'s own defect measurement used. [`probe_publish_decision_is_sound.sql`](../../scripts/db/probe_publish_decision_is_sound.sql) run first and green on all of its assertions, **so the control under test was known to be the installed one rather than assumed**. Then one rolled-back transaction under `SET LOCAL ROLE merit_app`, because a hole only a superuser can reach is a different finding.

```
 BASELINE            | a publish decided on a COMPLETE run anchored to THIS row is written,
                     | both checks satisfied
 A: run -> failed    | UPDATE accepted, run status is now 'failed', and the published row still
                     | cites it (1 row)
 A: run -> queued    | UPDATE accepted, run status is now 'queued' with completed_at NULL: the
                     | publish cannot be dated against the run it names
 B: run re-anchored  | UPDATE accepted, the cited run now ran over plan B version <uuid>, and
                     | plan A version 1 is still published citing it
 C: publish side     | REFUSED: plan_version <uuid> is published and immutable
 D: re-publish touch | REFUSED: plan_version <uuid> is published. The only permitted transition
                     | is published -> retired
```

**Every falsification case in this repository seeds a defect and watches a gate go red. There is nothing here to watch go red**, which is the finding: the assertion is that a guard does not fire. ADR-156's checkable clause is written in that direction deliberately and rots when the hole is closed, not when it is widened.
