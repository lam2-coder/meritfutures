### 1. The objective, and the answer

**Row `269` asked for one sentence to be re-derived before anything was built**, and said plainly that finding it still true would be an equally good outcome.

**IT IS FALSE.** The full ruling is [ADR-269](../decisions/ADR-269.md), ten sections, `proposed` and UNSIGNED.

The clause said `eligible_next_7d`'s *"last term is a `writeRuleState` implementation under `apps/worker/**` or `packages/**`"*. Four files in the scope the clause itself named say otherwise.

| What the clause needed absent | Where it is |
|---|---|
| the implementation | `writeRuleStateVia`, [`apps/worker/src/batch/state-writer.ts`](../../apps/worker/src/batch/state-writer.ts), declared `BatchWritePort['writeRuleState']` |
| the composition | `writeRuleState: writeRuleStateVia({ ... })` inside `postgresBatchPorts` ([`adapter.ts`](../../apps/worker/src/batch/adapter.ts)). **An exported function nothing supplies would still satisfy the clause**, so this is asserted and not only the declaration |
| the caller | `await ports.write.writeRuleState(fold.row)` ([`nightly.ts`](../../apps/worker/src/batch/nightly.ts)) |
| a row that landed | [ADR-264](../decisions/ADR-264.md) section 2, PostgreSQL 16.13, **zero rows to one** |

### 2. The finding, which is larger than the clause

`liability.ts`'s `B5` enumerated three terms. **ALL THREE ARE SPENT**: term 3 by [ADR-208](../decisions/ADR-208.md) (session 397), term 2 by [ADR-206](../decisions/ADR-206.md) (session 394), term 1 by session 395's writer.

**AND THE FIGURE IS EXACTLY AS ABSENT AS IT WAS.** `RI-19` exists because that condition was once stated twice with two of its three terms each; that defect is fixed. **This is a different one and no control in this tree looks for it.** All three terms were about getting a ROW. Not one was about what stands between a row and a rendered number, and there is no vantage point inside a blocker from which the layer underneath is visible.

**THE CHEAPEST CONTROL WAS ALREADY PAID FOR AND IT FAILED.** `admin-read-constructibility.test.ts` carried a case whose own comment read *"the day a real implementation lands, this case goes red and says which figure it unblocks."* What it asserted was `expect(liability).toContain('writeRuleState')` -- **a string inside a comment of the module it was reading**. ### 3. What was built

[`apps/api/src/admin-source/eligible-next-7d.ts`](../../apps/api/src/admin-source/eligible-next-7d.ts), the body the entry said did not exist.

- **The calendar is asked FIRST and the order is the dependency order.** An uncovered estate refuses `calendar_uncovered` and an exhausted one `horizon_exhausted`, **before a single account row is read**, so an unloaded calendar can never be reported as an unrun batch. A case asserts zero accessor calls on that path.
- **The state comes from `ruleStateOn`** ([ADR-264](../decisions/ADR-264.md)). `RuleStateAbsent` takes the account out of the covered population; `RuleStateUnreadable` is rethrown, because a malformed row silently skipped is a liability quietly missing an account whose row exists.
- **The gates come from the engine's `resolveExternalGates`** over five raw columns, the whole KYC chain and every payout-request status. Every value handed over is the raw column, on `adapter.ts`'s reason.
- **Nothing recomputes a gate.** `projectPayout` decides and this module folds. [ADR-204](../decisions/ADR-204.md) ruling 3 is honoured by the shape: one bucket per horizon day and an account in at most one, so `sum(by_day[].cents)` equals `total_cents` and a case asserts it.
- **Cents are `bigint` from the row to the wire.** `centsOf` deliberately does not narrow where `liability.ts`'s `cents` does: this value is summed across a whole funded population, so a fold that narrows first is a fold that rounds first. `toWireEligibleNext7d` is the one narrowing and it refuses past 2^53.

### 4. What actually blocks it, and it is one input of five

`calendar`, `horizon`, `state` and `gates` are all producible in this fence today. **`plan` is not, and the reason is `FM-16` rather than an absent row.** The rows exist and `resolvePlan` is exported; what does not exist in `apps/api` is the DECODING of `plan_versions.rules`, which lives once in this repository as `toPublishedRules` in `apps/worker/src/batch/adapter.ts`, roughly 250 lines, unimportable from here.

A second one written on the read side is `FM-16` **on the blob that fixes every cents value and every gate threshold a payout is decided against**. [ADR-239](../decisions/ADR-239.md) slice A rules the shared home is `packages/rules-engine`; [ADR-264](../decisions/ADR-264.md) set the precedent for meeting that finding inside a fence that does not hold it: **REGISTER it, do not take it.** So the term is `EligibleFoldIo.resolvePinnedPlan`, injected, whose unwired default throws `EligibleFoldUnwired` naming the member and citing the ruling.

### 5. The trap, and why the wire cannot answer it

**`EligibleNext7d` declares `total_cents`, `account_count` and `by_day[]` and NOT ONE MEASURED TERM.** There is no field a basis could ride on and no pair of fields a reader could tell apart. `RI-18` binds that shape atomically across three files, all outside this fence.

So the basis rides on the module's own value, as data: `ELIGIBLE_FIGURE_TERMS`, fourteen entries, each with `basis`, `source` and the [ADR-204](../decisions/ADR-204.md) assumption ids. **Every number the figure carries is `projected`**; the measured terms are the last closed day, the three population counts, the horizon's days and the four per-account inputs. The suite walks the produced figure's own leaves against the table **in both directions**, so a field added and not declared is a red case rather than a number with no stated basis.

**AND RULING 7 MAKES THIS A TERM RATHER THAN A PREFERENCE.** [ADR-204](../decisions/ADR-204.md) ruling 7 requires both halves of the figure to be stated wherever it is shown, so a wire that cannot state them cannot show the figure.

### 6. The two zeroes

**Empty `rule_states` with funded accounts refuses `no_folded_state`**, `awaiting` naming the run, detail carrying the count. A row for a DIFFERENT day is the same refusal, because `R-06` permits one day and there is no `latest` arm on this path.

**A genuinely empty funded population is a MEASURED zero and is produced**, with `population.funded` at `0` and its term marked `measured`. The two produce the same `0` and mean opposite things.

**A PARTIAL FOLD IS PRODUCED AND THAT IS A JUDGEMENT.** An account funded today has no mark, so a fully covered population is the exception rather than the rule; refusing on any shortfall leaves the operator with nothing on every ordinary day. The shortfall is a measured term instead. The alternative and its cost are in [ADR-269](../decisions/ADR-269.md) section 6 and section 10 puts it to the founder.

### 9. Landmines for the next session

- **THE INSERTION LANDMINE FIRED FOR THE FOURTH SESSION RUNNING.** Adding paragraphs to `liability.ts`'s header moved `rowsWhere('reconciliations', ...)` from `:1193` to `:1212` and turned `RI-15` red on `wiring.test.ts`. **It is repaired as a NAME rather than a number** ([ADR-212](../decisions/ADR-212.md)), because that pointer has now been broken twice the same way. **Derive pointers last** is four sessions old and has cost four sessions.

Both are repaired and both say why. **A third module that names the batch in a message will turn both red again.**
- **`RI-19` PAIRS A MODULE WITH THE TEST FILE WHOSE NAME IS ITS PATH WITH SLASHES FLATTENED**, and it reads BOTH directions: a term the case does not name, and an identifier the case names that no term carries. A restatement carrying a spent term's identifier is red. The new module deliberately contains no `CLEARING CONDITION` marker, so it declares no pair.
- **`pnpm vitest` IS NOT A SCRIPT IN THIS WORKSPACE** and `npx vitest run <path>` must be run from the REPO ROOT, not from `apps/api`. **Dependencies are not installed in a fresh container**: `pnpm install` first.
