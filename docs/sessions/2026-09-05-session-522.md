### 4. What was measured and NOT taken

- **A transparent executor**, returning `pg`'s result unchanged the way pg-boss's own driver does. It works, and it requires `JobTransaction.executeSql` to admit `Result[]`, which puts a driver's shape inside the vendor-neutral interface [ADR-006](../decisions/ADR-006.md) made a review criterion. Refused.
- **Importing `unwrapSQLResult`.** It is not on pg-boss's public entry point, so it needs a deep import, and `packages/db` naming the vendor breaks the one-module containment `surface.test.ts` asserts over the whole tree. Refused, and the semantics are bound by three cases instead of copied silently.
- **A second `SqlExecutorReason` member.** Section 4 of the entry. Refused because the shape it would bless is the wrong one, not because the need is unreal.
- **A pool-shaped executor exported from `packages/db`.** It is what the next row needs and it is a bigger authority object than the one this row touches. Named as owed, left unwritten.
- **`Array.isArray(result)` alone, with no thought about where the rows sit.** The dispatch warned about it and the measurement is why it would have been wrong: the payload arrives in the middle of the array, so only a flatten recovers it.
