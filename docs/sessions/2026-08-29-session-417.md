### 2. The ruling, in one table

| Class | What it covers | How approval is obtained |
| --- | --- | --- |
| **A. A ruling** | lands no money-path file | **granted** on authority, delegated approval legitimate and precedented, recorded as `GRANTED (delegated)` and never as a founder read |
| **B. A checkable money-path diff** | central claim is a PROPERTY | **earned** by a named mechanical assertion. Granted by nobody |
| **C. The residue** | central claim is a CHOICE | **read** line by line, `:358` undiluted, the founder alone |

**The four conditions on a class B assertion** are that it falsifies the entry's
own central claim, that it was watched red before and green after with the
transcript in the entry, that it is named in a registry a gate runs, and that it
was not weakened to pass. **The fourth exists because minting a gate to clear
one's own queue is the most likely way this ruling gets faked.**
