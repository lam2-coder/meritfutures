### 2. The finding arrived as a red gate on the second edit, which is the best way for it to arrive

`GS-155` and `GS-223` were moved to `covered-elsewhere` on evidence that was executed and watched. `CI-06/fixture-inventory` refused both, in these words:

```
GS-155 is "covered-elsewhere" and no cited suite EXECUTES it:
apps/api/test/certificates.test.ts does not name GS-155 anywhere.
```

**The gate is not wrong.** [ADR-076 section 1](../decisions/ADR-076.md)'s rule is that a row is discharged when its assertion is EXECUTED **somewhere a gate can read**, and the reader this corpus built is a static parse whose own comment refuses the alternative: shelling out to vitest is *"an install step wearing a different hat"*, and `falsify.mjs` copies the tree without `node_modules` so such a gate could never be watched failing.

**So the discharge condition in practice is: an assertion that runs, AND somebody having written the id into the file.** Every row in this table whose module code landed with its own suite is subject to the second half, and nobody writing those suites was told about it. Both rows were returned to `blocked` with citations that say what runs, that it passes, and why it cannot move.

### 4. The three worst errors this session could have made, and the one it made

The constitution's caution is that the reconciliation's worst errors were failures to check a claim against the primary source rather than capability failures. Three were available here and one was taken.

1. **Discharging a row on a citation nobody ran.** Avoided by construction: every cited file was executed, in five separate runs whose counts are in the pull request, and the five third-state rows say `EXECUTED 2026-08-27` because they were.
2. **Moving a row into another session's term.** **TAKEN.** `GS-311` was rewritten from `vendor-call` to `no-fixture-format` because this session built one batch from a registry section rather than from the blocker column. It was caught by the generated span moving, `vendor_call` reading 13 where it must read 14, and the row was restored from `origin/main` byte for byte. **The repair that matters is the second one**: the script now refuses any row that is not already `no-fixture-format`, and it refused `GS-138` on the very next batch.
3. **Writing 90 variations of one sentence**, which is the defect [ADR-125](../decisions/ADR-125.md) exists about, committed a second time by the session sent to fix it. Guarded against by the rule that each citation names a `file:line` a second reader can open, and `RI-12` held at every commit.

**A fourth error was made and repaired inside the session.** `GS-117`'s first citation said none of the row's three reversals has a route. Unfreeze has one. The claim was written from the row rather than from `ADMIN_WRITE_ROLES`, which is exactly the failure mode item 2 above is an instance of, and it is recorded here rather than quietly fixed.
