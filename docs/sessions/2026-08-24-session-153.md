- **Objective:** `RI-04`'s `DEPLOYABLES` literal in [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) reads `['site', 'portal', 'admin', 'worker']`. [ADR-083](../decisions/ADR-083.md) is signed and ruled [`apps/api`](../../apps/api) a fifth deployable, and `apps/api` exists. Add `api`, fix the title that says *"four"*, and watch the widened check reject a seeded violation. Reported by [session 144](2026-08-23-session-144.md) and open since.

- **Done:** **`DEPLOYABLES` is `['site', 'portal', 'admin', 'api', 'worker']`**, ordered to match [OVERVIEW](../architecture/OVERVIEW.md) section 2's `subgraph Merit`. **`apps/api` needed no edit**: both of RI-04's loops were checked against it *before* the literal was widened, and it satisfies both already. Its `package.json` exists with the distinct name `@merit/api`, and its only dependency fields are `@types/node`, `typescript` and `vitest`, none of which is an app package name. **The invariant was narrower than the tree; the tree was not wrong.**

- **RI-04 PASSED WHILE ASSERTING NOTHING WHATSOEVER ABOUT `apps/api`, WHICH IS THE FAILURE MODE THE FILE'S OWN RULE 1 NAMES.** [ADR-083 section 3](../decisions/ADR-083.md) leans on this check **by name** as the mechanical reason the API cannot live inside one of the three UI surfaces: *"`RI-04` refuses an app that depends on an app."* A list that omitted `api` left that argument unenforced against **the one deployable it was written about**. Three green runs between sessions 144 and 151 were evidence about four apps and were read as evidence about five.

- **The title is COMPUTED from the list rather than written beside it.** It read *"site, portal, admin and worker are four separate deployables"*, so the count and the list were two hand-maintained facts that had to be edited together. It is now a template literal over `DEPLOYABLES` and renders as *"site, portal, admin, api, worker are 5 separate deployables"*. [`RI-05`](../../packages/tooling/checks/repo-invariants.mjs)'s own `covers` line already names this defect class: *"a hand-maintained count in a different costume, and it drifts the same way."* Nothing reads this file as text and the test uses `c.title` only as a label, so a computed title costs nothing here.

- **THE SEEDED FAILURES, RUN BEFORE THE CHECK WAS TRUSTED.** Three, because RI-04 has two loops and the new entry enters both, and a seed that only exercises one of them would leave the other asserted rather than watched. Each was reverted immediately.

  **Seed B is the one worth having.** Seed A proves `api` is now iterated as a subject; **seed B proves it entered the `byName` map**, so the four older deployables are now checked for a dependency *on it*, which is the direction ADR-083's three drawn arrows actually run.

- **Landmines:**

  - **THE FIXTURE HELD A SECOND COPY OF THE LIST, AND THAT IS WHY THE DRIFT SURVIVED A SUITE THAT EXISTS TO CATCH DRIFT.** `cleanTree()` in [`repo-invariants.test.ts`](../../packages/tooling/test/repo-invariants.test.ts) built its synthetic tree from its own literal `['site', 'portal', 'admin', 'worker']`. The two lists agreed **by coincidence** until ADR-083 put `apps/api` in the tree and **neither list learned about it**, so the clean-tree case stayed green on a fixture that was stale in exactly the same way as the thing it was testing. Adding `api` turned it red, correctly. **The repair is not to add `api` in two places.** `DEPLOYABLES` is now `export`ed and the fixture loops over it, so there is one list read twice instead of two lists maintained in step. **A fixture that maintains its own copy of the thing under test cannot fail when that thing goes stale; it goes stale alongside it.**

  - **THE FENCE DID NOT NAME THE TEST FILE AND THE CHANGE IS NOT COMPLETE WITHOUT IT.** The fence was `repo-invariants.mjs`, `sessions/` and `STATE`. Widening the check turns its companion suite red, so `packages/tooling/test/repo-invariants.test.ts` is a **fence widening**, declared here rather than taken quietly. It collides with nothing: session 146 holds `gates.mjs` and `STRATEGY.md`, and both are untouched. The checker's own header points at this file by path -- *"Each one is watched failing on a seeded violation in `../test/repo-invariants.test.ts`"* -- so a fence that holds one and not the other cannot be satisfied.

  - **RI-04 STILL CANNOT SEE A SIXTH `apps/` DIRECTORY, AND ITS `covers` LINE NOW SAYS SO.** The check iterates `DEPLOYABLES` and never reads `apps/`, so an application added without an entry here is invisible to it **exactly as `apps/api` was for four sessions**. Deriving the list from `readdirSync('apps')` would close it and was **not** taken: it is a different check with a different failure mode (a stray directory becomes a deployable by existing), and this session's fence is one literal. Recorded as the standing gap rather than left as a surprise. **The fix that was taken is the one that makes the next drift loud: the fixture now fails when the two lists disagree.**

  - **THE CONTAINER'S `node_modules` WAS STALE AND THE FIRST `verify` FAILED IN `packages/db` FOR NO REASON THIS SESSION CREATED.** Seven `TS2307` errors on `drizzle-orm` and `pg`, which [session 145](2026-08-23-session-145.md) added as the workspace's first runtime dependencies. **`pnpm-lock.yaml` was already correct** -- `pnpm install --frozen-lockfile` reported *"Lockfile is up to date, resolution step is skipped"* and added 16 packages. **A red `verify` on a fresh container is a missing install before it is a defect**, and the check that distinguishes them is whether the lockfile resolves without changing.

  - **PRETTIER WAS RUN OVER THE DOCS AND THE DIFF HAD TO BE THROWN AWAY.** `format:check` covers `*.{js,mjs,ts,json}` and `{apps,packages}/**`, and **markdown under `docs/` is outside it**, so formatting `STATE.md` and `sessions/README.md` rewrote 865 lines of files no gate asks to be formatted, burying a 22-line append. Reverted and re-appended by hand. **Run the repo's own `format` script rather than `prettier` by hand; the glob is the specification of what is formatted.**

  - **[INFRA section 2](../architecture/INFRA.md)'S RAILWAY LIST IS REPORTED AND NOT TAKEN, AND THE REASON IS NOT ITS SIZE.** It reads ``Railway services: `site`, `portal-api`, `admin`, `worker` `` where ADR-083 needs six, the two additions being `api` and `api-admin`. It is **one table cell**, not a row: the table is `Concern | Choice | Why`, and services are a list inside one cell. Mechanically that is a small edit. **INFRA is `status: approved` corpus, and changing a frozen document requires an ADR rather than a commit**; this session carries none. **The naming is also not mechanical**: `portal-api` is the *portal's* service, and a list that names both `portal-api` and `api` invites the reading that they are one thing, which is the exact confusion ADR-083 section 3 spent its length refusing. It wants the ADR that renames or explains it, not a cell rewrite. **Left open, still the second of session 144's two twin defects; the first is closed by this entry.**
