- **Next:** `S9`, [ADR-064](../decisions/ADR-064.md) and the session registry, **last and alone**. And [ADR-065](../decisions/ADR-065.md) section 5's slug migration, whose stated precondition is now live: see landmine 1.

### The repair is the parser, not a third reading of the file

`allocated()` and `allocatedLetters()` accumulated claims into a **`Set`**. Two rows claiming `0034` produced one member, so gaplessness held, every-number-on-disk-is-claimed held, and **the registry whose entire purpose is to make a double claim visible could not see one**.

Both are now views over a claims **multiset**: key to the line of every row claiming it. `allocated()` is `new Set(allocatedClaims(...).keys())` and no caller changed behaviour.

**`CI-06w` does not parse ALLOCATION.** It asserts over the maps `CI-06f`, `CI-06h` and `CI-06p` already resolve their own answers through. Writing a second parser inside the new gate was the obvious shape and it is the wrong one: two expressions of *what does this table claim* agree until they do not, which is the defect session 20 removed from this runner when `CI-06b` and `CI-06c` carried one document set twice, ten lines apart. **The brief asked for the assertion at the semantic level so that a future refactor folding the claims back into a `Set` cannot make the check vacuous, and that is only true if the gate reads the shared map.**

### Why this is not `CI-06u`'s job, stated rather than elided

Two gates whose scopes are not separable is how a gate gets deleted later, so the distinction is written into `covers`, into the commit and into [STRATEGY section 4.4](../testing/STRATEGY.md).

**`CI-06u` reads TABLES. `CI-06w` reads CLAIMS.** `CI-06u` does read all three of these tables and it would report two verbatim duplicate rows in this file. It did not catch the `u` collision because that row sat in an **orphan fragment**, which `S7`'s `CI-06v` now closes. On the population that actually occurs, two verbatim rows, the two gates agree.

**Three things separate them, and none is hypothetical:**

1. **A range overlap is not a duplicate row.** These tables are written in ranges. `| 001 to 032 |` and a later `| 032 |` are two textually distinct first cells and `CI-06u` is right to pass them. They claim `032` twice.
2. **`CI-06u` is defeated by presentation.** Its key is the first cell after emphasis stripping and link flattening. `CI-06w` reads the number, never the spelling of the cell.
3. **`CI-06u` cannot go vacuous by refactor and `CI-06w` can, which is the point.** `CI-06u`'s reach over this file is an accident of the tables being tables. Fold `allocatedClaims` back into a `Set` -- the exact edit that created `OI-11` -- and `CI-06u` goes on passing while every double claim becomes invisible again. `CI-06w` breaks loudly instead.

**And one asymmetry that matters for a merge gate:** `CI-06u` can be silenced per `(file, key)` by its register. `CI-06w` has no register, no exemption list, and no way to accept a claim twice.

### The fourth assertion is an addition to the three commissioned, and it is named as one rather than slipped in

The brief and [WAVE-03](../plans/WAVE-03-duplicate-registry-keys.md) section S8 name three tables. **`CI-06w` also asserts that each gate id appears at most once in the runner's `GATES` list**, which is six lines.

`implementedLetters()` builds the runner's own letter set with `new Set(GATES.map(...))`. **Two gate objects carrying one id collapse to one member**, so `CI-06p` reports a letter implemented twice as implemented once and both gates run under one name. That is the same defect, the same mechanism and the same file, one level in.

It is not a thought experiment. **[PR #112](https://github.com/lam2-coder/meritfutures/pull/112) and [PR #114](https://github.com/lam2-coder/meritfutures/pull/114) each define `id: 'CI-06u'` independently, #114 is open, and a keep-both merge of it lands exactly here.** [ADR-065](../decisions/ADR-065.md) section 4.1 names that hazard and says nothing in the tree could see it. Something can now.

**It is flagged rather than folded in silently, and it is one delete wide if the founder rules the scope wrong.**

### The `105`, which was doing two jobs, and that fusion is why it drifted

**The tree carried five sites in [`gates.mjs`](../../scripts/corpus/gates.mjs), not the four the brief names.** [Session 81](2026-08-20-session-81.md) had already measured five and corrected its own log to say so; the brief inherited the older figure. Both sites in [STRATEGY](../testing/STRATEGY.md) are this session's too.

**The runner has printed `106` on every run since the gate landed, and after `S6` it prints `19`.** The numeral was serving two questions at once:

| Role | Recomputable? | Where it lives now |
|---|---|---|
| **The 2026-08-19 survey figure**, what was measured on `main` | **No.** It measures a tree that no longer exists | **Kept, once**, dated and attributed, corrected to `106` |
| **A live description of the register** | **Yes**, and the runner prints it | **Deleted**, pointing at the printed note |

**THE SHAPE CHOSEN: remove the count everywhere it describes the register or the current tree and point at the printed note; keep exactly one dated historical figure, at one site, phrased so it cannot be read as a claim about the register.**

**Why not simply correct `105` to `106` at all five.** Four of the five are **about the register**, and the register moves on every repair. Correcting them makes them wrong again at the next one, and that has already happened twice: [ADR-062](../decisions/ADR-062.md)'s session took the guard table to zero and left *"ten of the 105 are"* standing, and `S6` took the register to 19. **Those sentences must not carry a number at all.**

**Why not delete the historical figure too.** The register's shrink-only rule is meaningless without a starting size, and [session 75](2026-08-19-session-75.md), [WAVE-03](../plans/WAVE-03-duplicate-registry-keys.md) and [ADR-061](../decisions/ADR-061.md) all cite `106`. Deleting it would leave the gate unable to say what it was written against and would silently rewrite a measurement three documents cite. **A frozen measurement that nothing recomputes is not a hand-maintained count in [ADR-034](../decisions/ADR-034.md)'s sense**; the defect ADR-034 names is a hand copy of a number something else computes, and that is the copy that is gone.

**The `ten of the 105` line is corrected factually and not only numerically.** It is where **none** of them are. [Session 78](2026-08-20-session-78.md) and [ADR-062](../decisions/ADR-062.md) both recorded that and neither could repair it inside its fence.

### The recommendation on PR #114: **rework, not close, executed by closing the branch**

[ADR-065](../decisions/ADR-065.md) section 4.1 already recommends adopting #114's scope rule into the shipped gate and keeping #112's register for the label class only. **Nothing found this session disturbs that and one thing sharpens it.**

- **It cannot merge as it stands and never could.** `mergeable_state` is `dirty`, it branched before #112 merged, and a keep-both resolution yields **two gates with `id: 'CI-06u'` in one runner**.
- **That last hazard is now gated.** Before this session nothing in the tree could see it. `CI-06w`'s fourth assertion fires on it, so the risk that made "close it quickly" tempting is a loud failure now rather than a silent one.
- **The design is adopted, not rejected.** #112's register currently exempts `g-eligible`, **a live money-path contradiction with two opposite identity clauses both citing [ADR-041](../decisions/ADR-041.md)**, because a `(file, key)` entry was the only tool it had. #114's first-cell-shape scope would still fire on it. **A defect parked in an exemption list is a defect the ratchet has stopped ratcheting on.**
- **Its successor takes a slug and not a letter.** [ADR-065](../decisions/ADR-065.md) section 5 rules the successor identifier is a slug, and after this session the alphabet is genuinely spent. See landmine 1.

**Recommended: close #114 without merging, carry its scope rule into a follow-up session against the shipped `CI-06u`, and cite ADR-065 section 4.1 in the closing comment so the design is visibly adopted rather than discarded.** The letter question is settled and needs no further ruling.

### Landmines

- **`w` WAS THE LAST LETTER, AND [ADR-065](../decisions/ADR-065.md) SECTION 5's PRECONDITION IS NOW LIVE RATHER THAN PENDING.** That section rules the successor identifier is a slug and names its migration as *"its own session with a stated precondition: it must land before any twenty-fourth gate is written, because there is no letter for one."* **The twenty-fourth gate is written.** It consumed no new letter, because `w` was reserved for it before a line was written, so the precondition was met on a technicality rather than violated. **The next gate has no such reprieve:** `a` to `w` are claimed and `x` is reserved to the falsification harness, since `CI-06p`'s seed takes `nextFreeLetter()` and claims two past it. **There is no letter for gate twenty-five and the slug migration is now the only way to write one.**

- **A CONTROL SEEDED ITS OWN `expect` INTO BEING WRONG, AND IT BIT DURING WRITING.** `CI-06w/adjacent-ranges-do-not-overlap`'s control first seeded a range straddling the top of the claimed region. That range claimed the first **free** number, which pushed `nextFree` upward; `expect` resolves against the **seeded** tree, so it then named a number claimed only once and reported a working gate as broken. The control's range now sits entirely inside the claimed region. **This is the `CI-06l` lesson arriving for the third time in this harness** and it is recorded at the case rather than only here.

- **THE BRIEF'S SITE COUNT AND LINE NUMBERS WERE BOTH STALE, WHICH IS THE DEFECT THIS WAVE IS ABOUT.** It named four sites at `:3747`, `:3755`, `:3800` and `:4060`. The tree carried **five**, at `:3752`, `:3760`, `:3762`, `:3805` and `:3976`, because `S6` and `S7` moved everything below them. **A hand-maintained line number in a prompt is the same class as a hand-maintained count in a comment**, and the prompt for the session written to remove one carried four of the other.

- **`CI-06w` INHERITS THE ONE-REF GAP AND IT IS THE COMMONEST FORM OF THIS DEFECT, NOT A CORNER.** Two **branches** each claiming `0046` is exactly what `ADR-046` and `ADR-047` did, and this run sees one ref. The gate catches it at the merge, which is one merge later than anybody would like and is still before `main`. `CI-06f`, `CI-06h`, `CI-06p` and `CI-06u` each declare the same gap.

- **ONE REGISTRY IS STILL OUT OF REACH AND IT IS THE ONE THAT RACES MOST.** `docs/sessions` **has no allocation table at all**, so no claim of a session number exists for `CI-06w` to read. Every session's end ritual appends a row to that index, and under the current convention a concurrent pair appends a duplicate key. That is `S9`'s work and [ADR-064](../decisions/ADR-064.md) is asked to name who closes the gap and where the table lives.

- **NOTHING ASSERTS THAT AN IMPLEMENTED GATE HAS A [STRATEGY](../testing/STRATEGY.md) ROW.** [Session 83](2026-08-20-session-83.md) raised this as landmine 4 and it is still true: `CI-06p`'s three assertions are uniqueness over rowed letters, implemented against ALLOCATION, and gaplessness. **None is "implemented against STRATEGY."** `CI-06w`'s row was written by hand and no gate would have noticed its absence.
