### 1. What the page is, and the two files it renders rather than rewrites

| File | What it is |
|---|---|
| [`page.ts`](../../apps/portal/src/app/kyc/page.ts) | The App Router page at `/kyc`. `export const dynamic = 'force-dynamic'`, because the App Router's default is to prerender a page with no dynamic input and a prerendered KYC status is one trader's verification state served to every trader from a cache |
| [`screen.ts`](../../apps/portal/src/app/kyc/screen.ts) | The pure render. Synchronous, no `Promise`, no IO, which is what lets the suite hand it a payload and read the bytes |
| [`source.ts`](../../apps/portal/src/app/kyc/source.ts) | The port, the runtime screen, and a default that refuses every method |

**`view/kyc.ts` decides what the screen may say and this page did not second-guess it.** `toKycStatusView` carries `SC-M4-07`'s two refusals, an unknown `kyc_status` member and section 7.9's vocabulary over the server's own sentence, and the page routes the payload through it rather than around it. A page that projected the wire shape itself would be a second, weaker copy of a check that already exists.

**`view/disclosure.ts` is what makes the footer impossible to omit.** `PublishedDisclosure.text` is a `DisclosureBlock`, so a screen cannot be assembled from a literal, and `disclosureBlock()` refuses a blank one. The footer element is a SIBLING of the content branch rather than a child of it, so no content state can drop it.

### 2. THE CLAUSE, ASSERTED BY TRYING

> [ADR-114](../decisions/ADR-114.md) clause 6: **"MERIT NEVER PROXIES A DOCUMENT, AND THE INVARIANT IS ENFORCED IN TWO PLACES BECAUSE ONE OF THEM CANNOT SEE INSIDE A JSONB BLOB.** The port has no method returning a document and no field one could be assigned to. The receiver SCREENS a verified payload before anything stores it, **REFUSES rather than redacts**, and records **key paths and never values**."

**Both places are here, one deployable over, and neither alone is the control.**

| Place | What it is | What it cannot see |
|---|---|---|
| **The type** | `KycScreenSource.status()` returns `KycStatus`, API_CONTRACT section 7's five fields. There is no `documents()`, no `hostedUrl()` and no `applicantRef()`, and no field an image could be assigned to | A wire payload. TypeScript is structural and JSON is not typed at all, so an object carrying `document_image` beside the five fields satisfies the type at compile time and arrives intact at run time |
| **The runtime screen** | `screenKycStatus` walks the payload that actually arrived, REFUSES on a document-shaped or screened-value key, and projects five fields by name | A field nobody has sent yet |

**A test that checks the status field renders passes on a page that also leaks a passport.** So the assertion is the other way round: the render path is handed a payload carrying four different shapes of leak, and the bytes it produced are searched for the VALUES.

| Shape | Key | Value planted |
|---|---|---|
| A document at the top level | `document_image` | a `data:image/jpeg;base64,` string |
| A screened value that is not a document at all | `rejection_reason` | `INV-M19-09`'s provider reason code |
| A PII attribute the surface has no field for | `date_of_birth` | a birth date |
| **A document NESTED inside the provider's own blob** | `provider.raw_result.selfie_url` | a vendor URL |

**Every needle is proven findable before it is proven absent**, on `falsify.mjs`'s rule that a check which cannot fail is not a check. What the page emitted, in full:

```html
<article data-screen="SC-M4-07"><main><h1>Identity verification</h1><section data-content="server_error"><p>We could not load this just now. Try again shortly.</p></section></main><footer data-disclosure="simulated-environment"><h2>About Merit</h2><p>Merit evaluations and funded accounts trade in a simulated environment. No order reaches a live market and no customer funds are traded.</p></footer></article>
```

**None of the four values, and none of the five KEYS either**, because a field name is a statement that the field exists and `data-field="document_image"` on an empty element would be a page announcing that Merit holds one. **The refusal itself names the four key paths, including the nested one, and quotes no value**, which is asserted the same way: each planted value is proven findable, then proven absent from `ScreenedFieldError.message`. That message is written to a log, and a message quoting what it screened out would be the leak it exists to stop.

**And the control for it**, without which "a passport is absent" is satisfied by a page that renders nothing: the same payload with the four keys removed renders `data-state="verified"`, `data-badge="verified"` and the state label.

**Two tiers, because "unknown" and "document-shaped" are different facts.** An unknown key is DROPPED by the five-field projection, since API_CONTRACT can add a field and a portal that refused every response carrying one would break on an additive change. A screened key is REFUSED, because a screen that quietly dropped the field would render correctly forever while the response kept carrying a passport to every other consumer of that endpoint.

**One assertion runs in the direction this check must never fail in**: no member of `SCREENED_KEY_TERMS` matches any member of `KYC_STATUS_FIELDS`. A term that matched a contract field would refuse every well-formed response, and the screen would look like a broken endpoint rather than like an over-broad list.

### 3. What rendering forced, and why neither view module changed

**Rendering found one real defect, and it was found by reading the bytes rather than by reasoning.** The first render put section 7.9's own prompt, *"You passed. One quick step to activate your funded account, about 2 minutes"*, under a heading reading *"Why you were asked"* on a verification that was **already verified**, and again on one that had **failed**. The corpus sentence is a call to action and it is only true at the trigger moment.

**The repair is in this segment's catalogue and not in `view/kyc.ts`.** `KYC_PLACEMENT_PROMPT` is the contextual prompt and renders only where the control shape is `verify`; `KYC_PLACEMENT_REASON` is a noun phrase that stays true after the check is over. **The condition reads the CONTROL SHAPE and not the state**, so a second copy of `NEXT_STEP` cannot drift out of step with the first.

| What rendering asked for | Whose it turned out to be |
|---|---|
| A trader-facing label for each `kyc_status` member | This segment's. `view/kyc.ts` says so itself: it decides the SHAPE of the next step and never its words |
| A sentence per `placement` member | This segment's, and it needed TWO per member, above |
| A refusal on a `placement` the CHECK cannot produce | This segment's. `view/kyc.ts` deliberately passes `placement` through as the server sent it, which is right for a value and wrong for copy: an unmapped member would render the raw wire token |
| The vocabulary lint section 7.9 asks for | This segment's, and section 4 below is not where it went |

**So `view/kyc.ts` and `view/disclosure.ts` are byte-identical to `main`.** Both were built to be rendered and both were.

**M04 SECTION 7.9's LINT NOW HAS SOMETHING TO READ.** [`view/kyc.ts`](../../apps/portal/src/view/kyc.ts) reported it owed and unbuildable in its own words: *"Section 7.9 asks for a lint over the portal's string catalogue. THERE IS NO STRING CATALOGUE HERE AND THE STRING IS NOT THIS MODULE'S."* That was right on both counts, and the second half is why: a view model that projects a wire shape authors no sentences, so there was nothing to lint. **A page authors sentences.** `traderFacingStrings()` gathers every one of them, derived from the catalogues rather than maintained beside them, and the suite runs `INTERNAL_TIER_TERMS` over all of them, reusing `view/kyc.ts`'s list rather than keeping a second copy. A second assertion runs `forbidden`, `not allowed`, `denied` and `permission` over the same set, because `INV-M4-07` keeps that vocabulary off the screen by TYPE and copy could reinstate by wording what the type refuses to carry.

**THERE IS NO JSX IN THIS SEGMENT AND THAT WAS MEASURED RATHER THAN PREFERRED.** [ADR-095](../decisions/ADR-095.md) foreclosure `F7` assigns the `jsx` and `dom` additions in `apps/portal/tsconfig.json` to the slice that writes the first page. **Six slices are writing a first page at once** and that file is in none of their fences, which is [ADR-114](../decisions/ADR-114.md) section 6's manifest collision in a different file. Executed on this tree:

| Spelling | `pnpm --filter @merit/portal run typecheck` |
|---|---|
| A `.tsx` component imported from a `.ts` file, tsconfig untouched | **exit 2.** `error TS6142: Module './probe.tsx' was resolved to ... but '--jsx' is not set` |
| The same component written with `createElement` in a `.ts` file | **exit 0**, unchanged |

JSX compiles to exactly these calls and nothing about the rendered output differs, so this segment is written in the spelling that needs no shared edit and the tsconfig line is reported to whoever holds it.

### 8. Why no ADR

**`ADR-150` was reserved CONDITIONALLY**, for *"the case where rendering forces a ruling on what a KYC screen may show"*. **It did not fire, and the number stays free.** Every refusal this page makes transcribes a ruling that is already taken: [ADR-114](../decisions/ADR-114.md) clause 6 rules the no-proxy invariant and both of its enforcement points, `INV-M19-09` already keeps the provider's reason code off every response, `INV-M4-09` and constitution section 6 already make the disclosure an obligation, and M04 section 7.9 already rules the vocabulary. Enumerating `SCREENED_KEY_TERMS` and splitting a prompt from a reason are implementation inside a settled rule, and an ADR for either would spend a founder gate relitigating a sentence the corpus has already written.

**What did arrive is a finding rather than a ruling**, and it is `CI-07`'s row rather than a KYC question. [ALLOCATION](../decisions/ALLOCATION.md)'s `150` row is amended in place per [ADR-065](../decisions/ADR-065.md) T3 to say so.
