### 2. `W6-i`, and the decision inside it that is worth reading twice

**THE PASS RENDERS A FIXTURE AND NOT THE ROUTE, AND THE REASON IS TWO MEASUREMENTS RATHER THAN A PREFERENCE.**

The obvious shape is to point Playwright at `next start`. It is refused on two grounds that are facts about this tree.

**First, `e2e/pass.ts:76` navigates to a `file:` URL built from `Surface.path`**, and that file is not in this slice's fence. A served URL would need the harness to grow a second mode, which is a repository-wide change made to serve one surface.

**Second, and this is the one that would have cost a session: importing the route imports a `.tsx`, and `e2e/tsconfig.json` sets no `jsx` key.** TypeScript follows an import into the file it names and compiles it under the IMPORTING project's options, so a `.ts` spec here reaching for `page.tsx` fails `tsc -p e2e` on a file it does not own. That is the same class of failure [ADR-182](../decisions/ADR-182.md) section 8 item 4 sends this slice to repair one directory over, arriving from the opposite direction.

**SO THE FIXTURE IS THE SERVED DOM PLUS A STYLESHEET, AND THE SECOND HALF IS THE GAP.** Everything from `<main>` down in the compliant fixture is what `next build` prerendered into `.next/server/app/index.html`, with the framework's own streaming markers dropped and nothing else changed. `apps/admin/src/app/layout.tsx` ships no stylesheet, so the tokens are this session's, written in the form [`apps/portal/e2e/fixtures/dashboard.compliant.html`](../../apps/portal/e2e/fixtures/dashboard.compliant.html) uses. **Dark first**, on `OQ-DS-03`'s _"light-first for the site, dark-first for the portal and admin"_.

**What the pass therefore asserts, stated so nobody has to infer it:** this console's markup is compliant when the design system is applied to it. **What it does not assert:** that the shipped page applies one. Section 6 finding 5 carries that with its owner.
