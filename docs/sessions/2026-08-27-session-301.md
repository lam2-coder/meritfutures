### 1. The claim was reproduced before it was ruled on

The dispatch has been wrong about this class of thing twice in one day, by its own account, so the two greps it named were run first and the ruling waited on them.

```
$ grep -n 'verify_url' docs/architecture/API_CONTRACT.md
530:  verify_url: string;                 // public verification page
750:  verify_url: string | null;
765:**`code`, `verify_url` and `image_url` are `null` while the state is `deferred` ...
$ grep -n '/verify/' docs/architecture/API_CONTRACT.md ; echo "EXIT=$?"
EXIT=1
```

**Both halves held.** The field ships in two response types and the page it addresses is defined in no section. Everything after that is a ruling about what the page says, and nothing in this session rests on the dispatch's framing of it.

### 2. The four-to-three mapping is the entry's best finding and it came from reading two CHECKs against each other

Neither `M11` nor `API_CONTRACT` says anything about `admin_actions.initiative` in connection with a certificate. The row is what says it:

| Source | Constraint |
|---|---|
| [`certificates`](../architecture/data-model/certificates.md), `0020` | `revocation_class` CHECK in (`fact_untrue`, `account_enforced`, `issued_in_error`, `trader_request`) |
| [`admin_actions`](../architecture/data-model/admin_actions.md) | `initiative` `NOT NULL`, no default, CHECK in (`enforcement`, `trader_request`, `operational`) |
| [`admin_actions`](../architecture/data-model/admin_actions.md) | `admin_actions_on_behalf_matches_initiative`: `(on_behalf_of_identity_id IS NOT NULL) = (initiative = 'trader_request')` |

**`trader_request` is the same word in both vocabularies**, and the biconditional then forces the identity column on that one branch and forbids it on the other three. The mapping is total, so the endpoint has nothing left to ask the operator for. **An `initiative` field in the request body would be a way to write an audit row that lies about whose act it was**, which is the misattribution that constraint was written to prevent, and the only reason it was noticed is that the row was written from the `CHECK` rather than from `M11` section 4's sentence.

### 3. What was checked and refuted rather than dismissed

Two alternative readings were live and both were run down at the source before the ruling went the other way.

1. **That `withheld` is expressible as deferred-plus-revoked with class `account_enforced`.** Coherent against every `CHECK` in `0020`, which is what made it worth checking. **Refuted by `AS-M11-05`**, which fixes that class as *"the claim stands and the account was later closed"*, while `M11` section 3.1 says withheld means *"Merit never made the claim"*. Publishing "the claim stands" for a claim never made is exactly backwards, and section 3.1 says the two states are different *"on purpose"*.
2. **That the response union should match `certificate_verifications.result`'s four members**, which `ADR-168`'s finding 14 could be read as supporting. **The finding is about the log and this is a response**, and the three reasons in `ADR-170` section 3.1 run the other way, the decisive one being that `INV-M11-09` defers on an open severity 4+ flag and [M07](../plans/M07-risk-abuse.md) does not publish detector detail.

### 4. Why two rows and not four, stated as a count rather than as a posture

`ADR-168` left four endpoints undefined. **Two landed here and the honest report is that the other two were refused on evidence rather than left for want of context.** `GET /public/leaderboard`'s field set is `OQ-M11-03`'s answer and that question is open in `M11`'s own section 10; `PATCH /me/leaderboard`'s approved semantics require removing historical entries from a table that `grep -rl 'leaderboard' packages/db/migrations/` shows does not exist, one file and two reserved columns being the whole of it. **The revoke row was taken because it is the producer of the only state the verify row publishes that is not simply the claim**, and an entry specifying how a revocation is published without specifying how one is recorded leaves the published half with no producer.

**`M11` section 4's six endpoints stand at four defined and two undefined after this entry**, and the two undefined are blocked on a founder question and a migration.
