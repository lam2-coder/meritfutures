### The five things the file argues rather than asserts

1. **The revision is a row, not an update.** A revised release time inserts at the next `revision`; both consumers read `economic_calendar_current`, whose only definition of "current" is the highest revision. `GS-286` is mechanical because **there is no "both" to move separately.**
2. **The staleness clock is a second table**, on [`trading_calendar_loads`](../architecture/data-model/trading_calendar_loads.md)'s precedent, which is the footing `FM-M7-08` names. Without a coverage bound, an exhausted calendar returns no releases and that is byte-identical to a quiet week.
3. **`tier` is a column, not an import filter.** A narrow Tier-1-only import makes "Tier-1" a property of what was loaded rather than one that can be re-derived, and a retroactive re-tiering would change history with no row to show for it.
4. **There is no timezone column.** One instant, converted per trader at display. A stored timezone would be the second source of truth for "when was the news" arrived at from inside the building.
5. **`release_trading_day` is transcribed, never derived.** B4 #1: a release at 23:30 UTC is not on the UTC calendar date the engine counts in.

### Landmines

**The one that cost the most time, and it is a real contradiction in the tree rather than a mistake made here.**

[`packages/db/test/migrations.integration.test.ts`](../../packages/db/test/migrations.integration.test.ts) asserted the on-disk migration sequence is `1..n` contiguous, under a comment claiming `CI-06h` "asserts the same thing" and that the local copy was **"the weaker half"**. **Both halves of that claim were false.** It was not weaker; it was **stricter in the one direction [ADR-036](../decisions/ADR-036.md) rules out.** The one allocation parser both gates read says gaplessness is asserted over allocated **plus reserved**, "so a branch holding a reservation shows a hole and passes", and [ALLOCATION](../decisions/ALLOCATION.md)'s own `0041` row says it again.

**`0038` is reserved for the money-path adjustment migration and FOLD-03 sequences it LAST**, so any branch writing `0039` first has a legal, reserved hole at `0038`. **The ruled workflow could not produce a green test run.** Demonstrated rather than argued: with `0039` on disk, `CI-06h` passes and the vitest assertion fails, on the same hole.

**The fix defers the gapless half to `CI-06h` by name and keeps the duplicate check, which is the assertion the file actually exists for.** It is not a weakened gate: the property is asserted by the gate that owns it, in the form the ruling specifies, and what was removed is a second disagreeing expression of one property. **Re-implementing the allocation parser inside vitest was considered and rejected**: the parser's own header names writing a second scan as `OQ-P1-04`'s defect, and `gates.mjs` ends in `process.exit(main())` so it cannot be imported to share the one copy. Recorded in [DELTA_MANIFEST section 4b](../../packages/db/DELTA_MANIFEST.md).

**A second, smaller one. A test that has only been seen pass is indistinguishable from one that cannot fail, and one of these could not.** The no-timezone assertion was `/\btime_?zone\b/`, which **cannot match `display_timezone`**: `_` is a word character, so there is no boundary before `timezone`, and a seeded timezone column passed. Found only because the seeded-violation pass is a step rather than a formality. Replaced by pinning the whole column set, which is strictly stronger.

**A third, named because a later session will meet it.** `0039` creates two tables and is **not** added to [DELTA_MANIFEST](../../packages/db/DELTA_MANIFEST.md) section 1's file table, on [`0032`](../../packages/db/migrations/0032_trading_calendar_holidays_coverage_revisions.sql)'s precedent: that table records what the fold created and is closed at 27. A session that adds a row there will find the count is a span and the rows are not.
