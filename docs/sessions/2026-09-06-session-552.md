### 1. The objective

Row `357`: rule whether `{declared: 25, wired: 11, blocked: 14}` in [`apps/api/test/wiring.test.ts`](../../apps/api/test/wiring.test.ts) is honest, given that at least one of the fourteen is not blocked, and repair it if it is not.

**One objective, and it resolved into a ruling plus five repairs and one gate.** The dispatch was explicit that finding the count right and the wording wrong was a complete outcome, and that moving a number to make a point was not. **The count is right, and the thing that misleads is neither the number nor the entry.**

It is an accounting identity that has been read as a census of obstructions.

---

### 3. THE RULING

**The triple is honest as arithmetic and misleading as vocabulary. The number does not move; the words and the missing measurement are the repair.**

Of the fourteen, measured at their module-scope bindings:

| shape | count | ports |
|---|---|---|
| `null` | 3 | `setAdminReadSource`, `setAdminSessionSource`, `setInternalOpsSource` |
| an `UNWIRED_*` stand-in | 7 | the four admin backends, `useCheckoutBackend`, `usePayoutBackend`, `useWithdrawalBackend` |
| a `production*` value that resolves nothing | 3 | `useAffiliateDeps`, `useKycDeps`, `useCheckoutAdapters` |
| **a working vendor adapter** | **1** | **`useTurnstileVerifier`** |

**THE THIRD SHAPE IS THE DANGEROUS ONE**, because its name says production and its behaviour says 503. **And it is not homogeneous**: two refuse by holding an `UNWIRED_*` member, while `PRODUCTION_CHECKOUT_ADAPTERS` names no such value and refuses by being empty. That is why section 5's classification is a ruling rather than a pattern match.

**THE DIFFERENCE THE ROW WAS DISPATCHED TO ESTABLISH.** `productionKycDeps` carries `provider: null` and `returnUrl: null` and cannot serve under any environment, because the code that would serve does not exist. `cloudflareTurnstileVerifier()` is complete and reads its secret per call. **A live default that refuses unconditionally and a live default that refuses only until configured are not the same fact**, and only the second is a deployment question.

### 4. Why the count must not move, which was measured rather than argued

Deleting the entry to report `blocked: 13` was tried on this tree. **It reddens TWO tests**, and the second is the point:

```
AssertionError: expected [ 'useTurnstileVerifier' ] to strictly equal []
  wiring.test.ts   expect(unaccounted).toStrictEqual([]);
```

A port that is live by default is still a port `start.ts` does not call, so removing its reason re-opens the hole the file exists to close: **a port with no wiring and no recorded reason.** The tree refuses to let the number move.

### 5. What is bound mechanically

`DEFAULTS` pins the initializer all fourteen module-scope variables carry, read back off the declaring modules. `LIVE_DEFAULT` records the ruling. The third assertion reports `{blocked: 14, refusing: 13, live: 1}`.

**THE REGEX WAS WRITTEN AND REFUSED ON ITS OWN RESULT.** A probe asking *"does the initializer name an `UNWIRED_` value"* classifies thirteen correctly and reports `useCheckoutAdapters` live. **The input is measured and the judgement is written down beside it**, because a probe that reads the WORD is the failure `RI-35`'s register carries its comments about.

**IT FAILS ON GOOD NEWS.** Row `356` is concurrently wiring `setAdminReadSource`; that removal will redden this until `DEFAULTS` moves with `BLOCKED`, which is the conflict being visible rather than silent.

### 6. Five stale facts, and the gate that should have caught two of them

Four in `wiring.test.ts` and one in a live plan, all repaired beside their originals under `RI-14`. Two drifted citations landed inside interface bodies; two prose counts were true when written and went stale when the list shrank and when ADR-347 landed.

**`RI-15` WAS MEASURED RATHER THAN BLAMED.** The bad citation was restored and `RI-15` re-run: it **PASSED at 35 of 35**, and `CITATIONS_OWNED_ELSEWHERE` holds no entry for it. `IDENTIFIER_GLUE` admits one linking word from a closed set of four, and *"at module scope ("* is three, so no name binds. **Three citations in this file are written in that exact shape.** Widening the grammar re-reads 225 citations across the tree and is `RI-15`'s own row, **so the hole is named and the remedy is not taken.**

### 7. Open questions, recorded as options rather than values

1. **Whether `blocked` should be renamed.** Options: leave it and keep the new numbers beside it (taken); rename to `unwired` and repoint every citation; report four members. The first is the smallest change that removes the ambiguity.
2. **Whether `MERIT_TURNSTILE_SECRET` is set in any deployment.** **This repository cannot see that.** The ruling is about the code. If the secret is unset everywhere, the anti-bot control on the sign-in path is refusing every request and is an operational finding rather than a wiring one.
3. **Whether a live-without-wiring port belongs in `BLOCKED` at all**, or in a third list `unaccounted` also honours. That is a structural change to the file and is not taken.

### 8. Landmines

- **`DEFAULTS` is a second list keyed on `BLOCKED` and will conflict with any row that wires one of the fourteen.** That is intended. **Count rather than subtract** when merging: the assertion compares key sets, so a stale `DEFAULTS` entry fails loudly.
- **Three citations in `wiring.test.ts` are in a shape `RI-15` cannot bind.** They are correct today and nothing defends them.
- **`wired` counts installation and not liveness.** Eleven ports are installed by `start.ts` and twelve are live in the code. A future reader taking `wired` for a count of working ports is wrong by one, and the entry says so.
