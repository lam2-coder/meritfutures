### 1. The five decisions, and where each is argued

**They are not summarised in the client's header on purpose.** Each is stated beside the code that makes it, which is the shape [`app-shell.ts`](../../apps/portal/src/shell/app-shell.ts) uses for the `403` refusal it spends a paragraph on.

| # | Decision | Where | The argument, compressed |
|---|---|---|---|
| 1 | **The base URL** | `client.ts` section 1 | `MERIT_API_ORIGIN`, **no default**, on `resolveSurface`'s idiom rather than `PORT`'s: a wrong port is unreachable within a second by everything at once, and a wrong API origin fails QUIETLY, because the screen renders the same honest unavailable state it renders when the API is merely down. A path, query or fragment is refused rather than trimmed, and `http` is refused outside `localhost` because the cookie is `Secure` and a withheld cookie is a 401 that looks like an expired session |
| 2 | **The session cookie** | `client.ts` section 2 | The request is the SERVER's, and it forwards exactly `merit_session`. Three measurements in order: [ADR-083](../decisions/ADR-083.md) ruling 1 puts the API on another origin, **`apps/api` sets no CORS header at all**, and the cookie is `httpOnly` so page script could not attach it by hand either. What remains is a server holding the inbound header, and it forwards ONE NAME because relaying the whole header hands every cookie the portal's origin accumulated to another deployable on every read |
| 3 | **The error mapping** | `client.ts` section 3 | `toPortalErrorKind(status)` and **no member added to `PortalErrorKind`**. A failure that never reached a status line is `server_error` with `status: null`: there is no number, inventing `503` puts a sentence in the server's mouth, and `unexpected` is reserved by `app-shell.ts` for a case it calls *"a rendering bug until proven otherwise"* while an unreachable API is an outage |
| 4 | **The cache** | `client.ts` section 4 | `no-store`, with no option to say otherwise, and the third reason is the decisive one. `INV-M4-04` and [M04 section 1.2](../plans/M04-trader-portal.md) are about staleness; **the identity scoping is about a leak**. A cache is a key and a value, and a key that omits the session serves one trader's payouts to another |
| 5 | **One client for six segments** | `surface.test.ts` | Expressed as an assertion rather than a paragraph, per needle rather than per file |

### 3. The thing the full suite caught that reading could not

**Wiring `load` to a real client turned [`payout-center.test.ts`](../../apps/portal/test/payout-center.test.ts) red, and that file is in nobody's fence.** It renders `PayoutsPage()` with no environment and asserts the unavailable state, so a `load` that resolves an API origin per request throws where that test expected a constant.

**The repair was not to widen the fence.** `load` catches `ApiConfigError` **and nothing else**, on an argument rather than on convenience: an unset `MERIT_API_ORIGIN` means this deployment has no API, so both endpoints are genuinely unreachable, which is what the screen's `unavailable` state already says. A transport failure or a bug in a path is NOT converted and propagates, because converting those would make every fault in this application look like a pending endpoint. **[`payouts-source.test.ts`](../../apps/portal/test/payouts-source.test.ts) asserts the narrowness in both directions**, including that `load` with an origin set and no request scope rejects rather than rendering.

**It also falsified one sentence this session had already written.** `resolveApiOrigin`'s header said the refusal happens *"at start"*. Nothing in this application runs at start; the first `serverApiClient()` of a request is where it is reached. The sentence is corrected in the file rather than left standing.

- **`apps/api`.** `GET /accounts/:accountId/eligibility` is one route module away and registering it would have made the payout centre's `ready` branch reachable from a browser. It is outside the fence and it is reported instead.

- **`apps/portal/test/payout-center.test.ts`.** Editing the assertion that turned red would have been the cheapest repair available and is the one section 3 refuses.
- **The other five segments.** Each is one `load` and one guard, and each is a follow-on session.
- **`packages/db`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`.** No dependency was admitted: `next` was already in the catalog and already a dependency of `@merit/portal`.
