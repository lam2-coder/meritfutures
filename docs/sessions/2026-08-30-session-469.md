### 1. The objective, and what it turned out to be about

**Row `278` dispatched one repair: land the rename [ADR-272](../decisions/ADR-272.md) specified and could not fence, and take `RI-26`'s exception out in the same commit.**

The rename itself is the small half. It installs, it moves no data, and nothing in the catalogue depends on the old name. The entry is [ADR-278](../decisions/ADR-278.md), five clauses, `proposed` and UNSIGNED.

**The large half is that the check the row named as the finish line cannot see the finish line.** [ADR-272](../decisions/ADR-272.md) section 5 wrote the exception entry as a self-cancelling reminder: *"which turns RED on the day the rename lands and is what will tell that session it is not finished."* Row `278` repeats it and so did this session's dispatch. It is false, and both halves were watched rather than reasoned:

| Watched, on the real tree | Result |
|---|---|
| `0075` installed, exception left in place | **PASS `RI-26`**, `27 of 27`. The repair is invisible to the check |
| Exception removed, reader unchanged | **FAIL `RI-26` (1)**: *"calibration_observed_at is declared `date` in 0045_simulation_runs.sql ... Rename it by a superseding migration"* |

`RI-26` builds its population from `CREATE TABLE` bodies and `ADD COLUMN` clauses. `E2` forbids editing `0045`. So the declaration stands forever, the column is a violator forever, and the stale-entry arm that was supposed to fire can never fire.

### 2. The clause that is not about one column

**A DDL reader's population is the schema the migration set INSTALLS, not the union of its `CREATE TABLE` bodies.**

Those were the same answer on every tree this repository has ever had. Measured: `grep -rniE "RENAME +COLUMN|RENAME +TO|DROP +COLUMN" packages/db/migrations/*.sql` returned nothing over all 68 migrations then on disk. **Summing declarations was free and correct, and nobody was checking because there was nothing to catch.**

`0075` ends that, and `E2` makes it permanent: a superseded declaration stands in a file nobody may edit. Every reader that sums declarations is now stating something false about `simulation_runs`.

### 4. The one place this entry worked around a defect instead of fixing it

**The [`simulation_runs`](../architecture/data-model/simulation_runs.md) design record now carries both column names in one cell.** `designRow` matches a column inside a code span in a row's first cell, so a cell naming `calibration_observed_on` and `calibration_observed_at` answers for both, which is the same mechanism the estate already uses for a row declaring `created_at, updated_at` together.

It is true content: `0045` declares the old name permanently, so `CI-06m` still asks this record about it. **It is also, read unkindly, a document shaped around a reader's defect**, and the cell says so in its own words rather than leaving a later reader to work it out. ADR-278 section 10 names this as the clause to attack hardest.
