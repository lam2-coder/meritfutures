producer in this tree has ever written one. The payload survived the `jsonb` round trip with

### 3. What was actually missing, which was the first half of the work

**THE DISPATCH NAMED THREE CANDIDATE DEFECTS AND THE ROW HITS TWO OF THEM ON TWO DIFFERENT
FIELDS.** Establishing which is what turned one guess into two clauses.

**ABSENT.** `events.subject_id` is `uuid NOT NULL` at `0017:47` and the payload named no field
at all. The subject exists: `detector_runs.id` is a `uuid PRIMARY KEY` at `0008:61`, and
`detector_run_id` is already this schema's spelling for a reference to that table at
`0008:134` and `0008:216`. **So the field was not coined here; it was transcribed from a
column and then written into the frozen document by clause 1.**

**NOT AMBIGUOUS ANYWHERE, and this was checked field by field rather than assumed.** All six
original fields resolve to a definition. `duration_ms` is the only one with no column and it
is not undefined either: [`0064`](../../packages/db/migrations/0064_reconciliation_runs.sql)
states that a run record stores no `duration_ms` because *"`finished_at - started_at` is the
same number and a stored copy can disagree with the two instants beside it"*, and `runner.ts`
computes exactly that subtraction. **The third candidate defect is therefore refuted rather
than left open.**

**AND THE SECOND BLOCKER IS NOT A DEFECT IN THIS ROW.** A detector run belongs to nobody and
there is no correct owner to resolve: `detector_runs` declares no column against
`identities(id)`, and `0064` says of the same shape *"There is no identity column and there is
no correct one... That is `detector_runs`' sentence."* ADR-191's write-time resolution is
**exhausted** here rather than unused. What was missing was the catalogue's vocabulary, which
`assertTenanted`'s own message has been asking for in terms: *"say so on its row in EVENTS. No
row says that today."*

### 4. The derivation that was available, refused on evidence

**THE TEMPTING RULE IS "NO `TL` CONSUMER MEANS FIRM-LEVEL"**, and it needs no new notation at
all. It is wrong on the one row this corpus has already decided. `payout.freeze_expiring` at
`EVENTS:255` is consumed by `ALERT, FEED` and by no `TL`, and it is a fact about **one
trader** whose producer holds a `payout_request_id` that names an account. **Under the
derivation it would be admitted as a firm fact and that trader's warning would be written
untenanted, forever, on an append-only table.**

**Of the 34 readable rows naming neither tenancy column, 33 have no `TL` consumer**, so the
derivation would have admitted all 33 in one move. The mark is explicit and per row because
33 rows can be decided one at a time and cannot be decided wrong all at once.

**TWO FIGURES IN `assertTenanted`'s OWN DOCBLOCK WERE OFF BY ONE AND ARE RE-DERIVED RATHER
THAN ADJUSTED.** It said 35 and 34; the document gives **34** and **33**, and the suite in the
same file already asserted 34 while the prose above it said 35. The one untenanted row a `TL`
reads is `payout.settled`, whose payload carries a `payout_request_id` and which is therefore
ADR-191's write-time resolution rather than a firm fact.
