### 1. The objective

Row `343`: wire the operator session source and the admin read source so the console answers, composing what exists rather than rewriting it, and argue two reserved judgements rather than assume them.

**One objective, and it resolved into a refusal plus a defect.** The wiring is refused on both halves with the argument written out. What lands is the unauthenticated crash path the dispatch found underneath it.

### 3. The two refusals

**THE VERIFIER.** `SECURITY` C-08 is _"RBAC on admin, admin on a separate origin, IP allowlist, hardware-key SSO"_ and its threat row S answers a phished admin credential with phishing-resistance and nothing else. A verifier satisfying this repository must establish five things: signature against the configured JWKS, issuer, audience, unexpired and unreplayed `assertionId`, **and that the authentication behind the assertion was actually phishing-resistant**. Items 1 to 4 are a library and a cache. **Item 5 is the whole control**, it is a fact about a provider Merit has not bought, and an implementation that skipped it **would pass every test anybody would write for it**. That is the dispatch's own sentence about a security hole with a green test suite, and it is why none is written.

**And item 4 has a second blocker that is not the provider.** A verified assertion becomes a session by writing an `operator_sessions` row and **nothing in this repository can write one**: Merit is passwordless by [ADR-039](../decisions/ADR-039.md) and [ADR-237](../decisions/ADR-237.md) section 8 already ruled that a session source over an empty table answers every real operator 401.

**THE COMPOSITION.** `readLiability` and `exportEvidence` are **left owed**. Composing anything onto `AdminReadSource` needs an `AdminSourceBackend`, whose one method yields an `AdminSourceTx`, for which `systemDb('operator-console')` is the only supplier. `ApiDb` declares five doors and none is it; [ADR-171](../decisions/ADR-171.md) clause 1 refuses to add it and section 9 conditions it on the session source refused above. **A partial liability figure would also be the worse failure the row named**: `EligibleNext7d` declares `total_cents`, `account_count` and `by_day[]` and not one measured term, so no field could carry the fact that a number was incomplete.

### 6. Next, blockers, landmines

**Next.** Nothing in this area is a code task. The operator console needs the identity-provider purchase, then a verifier, then a directory write, then a login route, then the door.

**Blockers.** All of the above reduce to one purchase. **Nine wiring entries now reduce to it**, which is the schedule exposure [STATE](../STATE.md)'s surviving-items table already names in six of nine rows.

**Landmines.**

1. **`RI-18` errors rather than fails when `node_modules` is absent**, and the runner correctly refuses to report a lower count. A session that reads the pre-install line as a baseline will report 34 of 35 and be wrong about which check is unknown.
2. **The `/admin/*` census cannot be taken by grep.** Three modules build their paths through their own builders. Injection over `compose()` is the only honest reader, and 16 is the number a needle returns.
3. **The surface sweep now has two legs and a third is missing**: nothing injects a WELL-FORMED cookie against a wired session source across the whole surface, because no deployment can wire one. The day the verifier lands, that leg is owed.
4. **`admin-writes.ts` and `admin-reads.ts` each declare their own `adminHandler` and `toAdminRoutes`.** They are different functions with the same names and different refusal shapes. A reader who greps one name and reasons about the surface will be reasoning about half of it.
