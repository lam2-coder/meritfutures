- **Landmines:**

  - **THE GATE WOULD NOT HAVE CAUGHT THE DEFECT THAT COMMISSIONED IT, AND SAYING SO IS THE MOST USEFUL THING IN IT.** The brief's framing implies otherwise and it is worth contradicting plainly. `2026-08-17` carries three declared rulings ([ADR-050](../decisions/ADR-050.md), [ADR-051](../decisions/ADR-051.md), [ADR-052](../decisions/ADR-052.md)), so the miscitation resolves. **What was wrong was never that the date had no ruling; it was that the rulings it has do not say what the citation claimed.** `CI-06q` checks that an authority EXISTS. Existence and correct attribution are different properties, and a gate sold as the second while checking the first is the shape [ADR-038](../decisions/ADR-038.md) exists to refuse. It catches a **fabricated** authority, which is a real and cheap error, and it is stated in `covers`, in STRATEGY, and here.

  - **THE OBVIOUS DEFINITION OF "RESOLVES" IS CIRCULAR, AND THE GATE WOULD HAVE PASSED ON ITS OWN CAUSE.** "Some file under `docs/` mentions that date near the word ruling" is satisfied **by the citations themselves** — two session logs cite the 2026-08-17 ruling in exactly that shape. The gate would have read one citation as the authority for another. So resolution is to a **registry declaration**, of which there are two structural shapes: an ADR heading parenthetical carrying the date, or a `gates/` filename carrying it. **Neither can be produced by writing a sentence.** A date in an ADR's BODY declares nothing either, which ADR-052 demonstrates by citing `2026-08-16` while ruling on `2026-08-17`.

  - **THE FENCE PROBLEM DISSOLVED AND WAS WORTH CHECKING BEFORE DESIGNING ANYTHING.** The two false citations had **already been removed** by a sibling session, leaving one comment in `coverage.ts` that *describes* the defect and therefore contains the phrase. A gate keyed on the phrase alone would flag the note documenting the defect the gate exists to catch — red on a clean tree, in a file this session may not edit. A quote-versus-use rule was designed for it and then **discarded as unnecessary**, because date-level resolution passes that note on its own. **The cheap check first is what stopped an elaborate mechanism being built for a problem that no longer existed.**

  - **A SEED WHOSE EFFECT NEVER REACHES THE ASSERTION PROVES NOTHING, AND THE HARNESS SAID SO TWICE TODAY.** The scope case first reported `DID NOT FAIL ... Expected a finding containing "undefined"`, because a `SCOPE_CASES` entry declares itself out-of-scope by setting `expect: 'PASS'` and mine set only `control.expect`. The harness was correct and the case was malformed. This is the same lesson as `RE-D-02`'s first seed one file over, which read a locale into a variable it discarded: **read the runner rather than pattern-matching a neighbour's fields.**

  - **`INV-21` LOOKED LIKE A SECOND DUPLICATE AND WAS AN EXTRACTION ERROR.** A sweep for `^| INV-nn ` reported both `INV-06` and `INV-21` twice. `INV-21`'s second hit is line 1219, a **worked-example row in a different table** whose first cell merely begins `INV-21 worst case:`. Bounded to section 1.5 the count is 25 rows over 24 ids and `INV-06` is the only duplicate. **This is batch 6's lesson arriving in a new registry** — there, a count exceeding its own partition was the signal that the extraction rather than the table was wrong — and it is precisely why the uniqueness gate must bound its parser to the section, which is the landmine `CI-06p` recorded about the letter table.

  - **THE DEDUP DECIDES NOTHING, AND ON A FROZEN DOCUMENT THAT DISTINCTION IS THE WHOLE JUSTIFICATION.** Both `INV-06` rows were ADR-050's amendment written twice by two branches, and **each was missing something the other had**: the first named `R-12`, `R-31` and `GS-019` in the rule text and attributed the amendment correctly but dropped `GS-019` from its enforcement column; the second carried `GS-019` there and split the attribution. The survivor is the **strict union**, so the edit removes a keep-both merge artifact rather than changing a specification, which is why it needs no ADR.

  - **TWO WAYS FOR THE NEW GATE TO GO QUIET ARE REFUSED BY THROWING.** Fewer than 100 files scanned, or zero citations found, each raise rather than return clean, because a glob that stopped matching and a needle that stopped matching produce **exactly the same output as a corpus with no defect in it**. Resolving against an empty declaration set throws for the third form of the same reason: it would report 59 defects rather than one broken check.
