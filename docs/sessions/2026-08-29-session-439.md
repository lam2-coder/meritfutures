**Objective.** Rule where a certificate card comes from and where it lives, which is the single
absent artefact two ports are waiting on.

**Outcome.** **Ruled, in four parts, and the fourth part is ruled in the negative.** No URL reaches
the row, so `certificates` needs no column and no migration number is spent. The card carries no
signature either, and that question was ruled explicitly rather than inherited.

### 2. The answer, in one paragraph

**On fetch, from the live row, by whatever answers this deployable's own image row, into no store at
all, addressed by a URL derived from `code` and signed by nothing.** Three of the four were already
in the corpus and the work was to say what the alternatives cost so the answer is chosen rather than
inherited; the fourth, the signature, is a real removal, and it is argued on the ground that the only
thing a signature buys is an expiry while the code beside it never expires.

### 3. The migration, and why the number is not taken

`0075` is the next free number, being the one after [ALLOCATION](../decisions/ALLOCATION.md)'s
migration table's last row, and it is left where it is. Every value the card draws is already a
column; the address is a function of `code`; and the cache version is a digest rather than a stored
counter. **`0074` above it stays session 431's returned-unspent hole and this session neither fills
nor widens it.**

### 6. Where this session is most likely wrong

**THE DERIVED RENDER VERSION IS ASSERTED SUFFICIENT AND NOTHING EXECUTES THAT IT IS.** The digest
cannot drift only while the template draws nothing the digest did not see, and no template exists to
check that against. A renderer reaching for the clock, for a plan-version lookup or for a fetched
asset has a rendering input the row does not carry, and the cache would then serve a stale card
nobody can tell is stale.

**AND THE RENDERING PARTITION IS THIS SESSION'S READING OF WHAT A CARD DRAWS.** `INV-M11-01` bounds
the claim and `INV-M11-04` fixes the disclosure, but no approved document lists the card's fields, so
the split between `RENDERED` and `NOT_RENDERED` is derived from invariants rather than transcribed
from a spec.
