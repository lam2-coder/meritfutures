### The build question was settled by running it, and the answer was that creating a build is somebody else's cell

The dispatch declined to choose between *"create the minimum page that makes a build exist"* and *"lint the MDX source independently of Next's build"*, and said to say which was taken and why. It was taken by executing the first one.

```
$ mkdir -p apps/site/src/app && printf 'export default function Page() { return null; }' > apps/site/src/app/page.tsx
$ node scripts/corpus/gates.mjs check
FAIL   CI-06/gate-inventory  Every pipeline stage row is implemented in a workflow or waits on a dated artifact  (1)
       docs/testing/STRATEGY.md:190 CI-07: the artifact "a page, layout or route file under apps/*/src/app/"
       HAS ARRIVED (apps/site/src/app/page.tsx is an App Router file), so the row reopened on the commit
       that added it and the stage is not written.
29 of 30 gates pass.
```

**That is [ADR-073](../decisions/ADR-073.md)'s half that fails on good news, and it names its own remedy: *"Write the stage, or take a ruling that moves the row."*** Both are outside this fence. Writing the stage names a job in [`ci.yml`](../../.github/workflows/ci.yml) and [ADR-095](../decisions/ADR-095.md) section 6 gives that to `P4-i`; moving the row edits [STRATEGY](../testing/STRATEGY.md) section 4.1, which this fence does not admit and which [ADR-095](../decisions/ADR-095.md) already ruled on this exact day. **Creating the page to make the lint's subject exist would have been widening the fence to finish.**

So the lint is a check over the authored source and over the page models built from it. **In this tree that IS the build**: M9's content is `content_documents.body_mdx` reaching the site over HTTP ([ADR-096](../decisions/ADR-096.md) ruling 1), the package's own shape is *"every surface is a pure function from config to a page model"*, and a document that fails the check never becomes a page. It is the same mechanism [`disclosure.ts`](../../apps/site/src/render/disclosure.ts) already uses for INV-M9-05 and [`rules.ts`](../../apps/site/src/routes/rules.ts) for INV-M9-02. The seed was removed and `git status --porcelain` reported clean before anything else was written.

### The OG image path is the design rather than a second rule, and the surfaces are discovered

`GS-144` is *"the build fails, INCLUDING on the OG image path"*, and [session 186](2026-08-24-session-186.md) measured that path as four sites, every one a comment. So there were two halves owed: a lint that reads the card, and a card to read.

**On the authoring side, any `og_*` frontmatter key is a surface.** They are enumerated by scanning the frontmatter rather than by a list in the source, so `og_card_headline` is covered on the day somebody authors it rather than on the day somebody remembers to extend a list. That is INV-M9-05's *"a new page cannot omit it by being new"* pointed at content.

**On the render side, [`routes/og.ts`](../../apps/site/src/routes/og.ts) refuses three ways**, and only the third is the obvious one:

| Refusal | Why it is not obvious |
|---|---|
| Title, description **and alt text** each take VG-M9-2 | Alt text is spoken and indexed. A card whose image is honest and whose alt text reads "90% pass rate" has published the figure without its window in the one place nobody reviews |
| `OgCardInput.statistic` is typed `RenderedStatistic`, never a string | A `string` there would let a call site pass `rendered.value`. AS-M9-03's screenshot IS that call site, eighteen months later. The only producer of the card's figure is `statisticText`, and there is no `justTheValue` to reach for |
| `assertWindowAttached` runs on the card | `GS-144`'s first leg was executable already and bound only its call sites. This is a call site, and it is the one the row names |

### The lint and the renderer contradicted each other, and the test found it rather than a reading

The first run of the OG suite went red on an assertion nobody expected to be interesting: that a built card's own strings pass the content lint. They did not.

```
AssertionError: expected [Function] to not throw an error but 'ContentLintError' was thrown
  GS-143 in body: a percentage, "14.7%", is stated in prose.
```

`statisticText` emits `14.70% (2026-04-14 to 2026-08-20, as of 2026-08-20, n=2803)`. **The lint would have refused the only sanctioned output of the only sanctioned accessor**, which is a lint somebody disables in its first week, correctly. `GS-144`'s sentence is *"rendered WITHOUT its trailing window"*, so a figure carrying its window is the row's PASSING case and has to read as one.

**The carve-out is pinned to `statisticText` by an assertion and not by a comment**, which is [CLAUDE.md](../../CLAUDE.md)'s own rule that a mechanical assertion beats a second reading of the source. Real `statisticText` output is fed through the expression for every unit [ADR-031](../decisions/ADR-031.md) enumerates (`bp`, `cents`, `count`, `duration_seconds`) and for INV-M12-05's suppressed shape, and a further test asserts the carve-out does not swallow a neighbouring bare figure:

```
lintAuthoredContent(`The cap is $1,500 and the rate is ${attached}.`)  ->  ['$1,500']
```

### The honest ceiling, stated rather than discovered later

**The lint is tier 3 of three and it is not the strongest tier.** [P1 section 2.3](../plans/P1-monorepo-scaffold.md) already wrote why: *"A numeric-literal lint is evadable by arithmetic and by naming."* An author who writes "five winning days" passes this lint. P1 names the stronger check and gives it to P2, a property asserting that every parameter in the config changes some output, and nothing here substitutes for it. [M09 section 5](../plans/M09-marketing-site.md) makes the image case a standing rule rather than a gate for the same reason: a number burned into a thumbnail is not text.

**And the authored corpus is empty.** `apps/site/content/` holds no `.mdx`, the step prints that count on every run, and what the lint guards today is its own specimens and the page models `og.ts` builds. That is a real limit and it is printed rather than left for a reader to infer from a green step.
