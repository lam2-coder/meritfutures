### Where the projection went, and the ruling cited for it

**Three places were available and the dispatch named all three.**

| Place | Verdict |
| --- | --- |
| `admin-source/account.ts` | **REFUSED.** [`ADR-184:48`](../decisions/ADR-184.md) ruling 3: the withholding is "A PROPERTY OF THE RESPONSE AND NOT OF THE RENDERER", and its control runs "over the serialized body and not over the rows". An adapter hands over rows. [`scope.ts:237`](../../packages/db/src/scope.ts) rules the same division about this exact pair of keys: "that exclusion is a PROJECTION and not this rule" |
| `projectAccountDetail` | **REFUSED, and narrowly.** That function is the section allowlist in both directions and takes no subject. The licence needs the path's `accountId`, and folding a second rule into it would give one function two reasons to refuse |
| **the route module, beside it** | **TAKEN.** Same position `admin-feed.ts` holds for the feed, same layer, and the port's own declaration at `admin-reads.ts` already says it: "the withholding itself stays on the RESPONSE ... because it is a property of the bytes and not of the rows" |

**What it licenses.** [`accountDetailLicence:1433`](../../apps/api/src/routes/admin-reads.ts)
admits **two ids and no more**: the account the PATH named, and the identity that account
row names. The second is the contract's doing rather than a widening.
`ACCOUNT_DETAIL_SECTIONS` names `identity` as one of the eight and the only way to reach
it is `accounts.identity_id`, which [`0007:39`](../../packages/db/migrations/0007_accounts.sql)
declares `uuid NOT NULL REFERENCES identities(id)`. Withholding the owner would blank a
section section 8 asks for while serving that person's whole row beside the hole.

**What it refuses.** Every other id, under any key ending `identity_id` or `account_id`,
at any depth, including inside the four stored `jsonb` bags. `kyc.dedupe_hit`'s
`matched_identity_id` and `identity.merged`'s `merged_identity_id`, which
[`scope.ts:232`](../../packages/db/src/scope.ts) names rather than counts, are covered by
the key shape rather than by enumeration. A `subject_id` is gated only where the sibling
`subject_kind` says it is a person or an account, which is `withholdForScope`'s rule kept
rather than re-decided.

**The root is checked against the path FIRST and inside the same function.** A licence
taken from a response nobody checked licenses whatever the port returned, and a page
headed by the id an operator typed whose rows belong to another human is the answer they
cannot detect. `W6-g` checks the root first for that reason and this is the server half
of it. It is one function and not two because two would leave an order a later caller can
get wrong, which is `FM-M6-10`'s shape exactly.

**No `withheld` flag is added to a row**, where the feed's `AdminEventItem` carries one.
The adapter serves the DDL's own columns under the DDL's own names, so a boolean this
route invented would be the contract-designing that module refuses. The value reads
`withheld` in place.

### The finding not in the dispatch, and it is why the feed's code is not imported

**A VALUE IMPORT FROM `admin-reads.ts` BACK TO `admin-feed.ts` REGISTERS AN ADMIN ROUTE
WITH NO ROLES, SILENTLY, UNDER THE RUNTIME THE SUITE USES.**

`admin-feed.ts` imports `ADMIN_READ_ROLES`, `LIMIT_DEFAULT`, `LIMIT_MAX`,
`adminRoleTable`, `adminValidationFailed` and `toAdminRoutes` from `admin-reads.ts`, so
importing `namesASubject` back is a cycle. **Both ends were measured on this branch
rather than reasoned about**, by adding the import and reading what came out:

| Runtime | What the cycle produced |
| --- | --- |
| `node --experimental-strip-types` | `ReferenceError: Cannot access 'ADMIN_READ_ROLES' before initialization`. A hard break |
| **Vitest / Vite's transform** | **NO THROW AT ALL.** `ADMIN_FEED_ENDPOINTS` evaluates as `[{ method: 'GET', path: '/admin/events', roles: undefined }]` and `ADMIN_FEED_ROLE_TABLE` as `{ 'GET /admin/events': undefined }` |

**The second row is why the import is refused rather than ordered around.** A hard crash
is a defect somebody finds; an admin route registered with no role requirement and a
green suite over it is the other kind. [`admin-reads.ts:99`](../../apps/api/src/routes/admin-reads.ts)'s
existing import from the same module is `import type` and is erased, so it is not that
cycle and never was.

**So the rule is restated and the two transcriptions are BOUND BY AN ASSERTION**, which
is session 357's repair for the same shape: `WITHHELD` is compared against
[`admin-feed.ts`](../../apps/api/src/routes/admin-feed.ts)'s and `namesASubject` at
`:1310` against [`admin-feed.ts:312`](../../apps/api/src/routes/admin-feed.ts)'s over a
corpus of thirteen keys, **both halves asserted non-empty before they are compared**,
which is that session's own landmine. **The one-file repair is reported and not taken**:
`admin-feed.ts` importing these three names from `admin-reads.ts` and deleting its own is
a deletion in a file this fence does not hold.

### Landmines

1. **A DRILL-DOWN CAN NOW 500 BECAUSE OF TEXT A HUMAN TYPED.** `admin_actions.reason` is
   `NOT NULL` so that no admin action is unexplained, and it is free text. An operator who
   pastes a second person's uuid into a freeze reason, on an account whose drill-down also
   carries that uuid under a gated key, gets `AdminDetailLeak` and a 500 on the whole
   screen. **That is the control working and it is the feed's identical behaviour**, but
   it is a 500 whose cause is in a text box rather than in code, and the case that proves
   it is the case that documents it.
2. **THE KEY RULE AND THE CONSOLE'S RULE FAIL ON DIFFERENT THINGS AND NEITHER SUBSUMES
   THE OTHER.** The server gates by the SHAPE OF THE KEY, so a third party's uuid stored
   under a key of some other shape passes it. `apps/admin`'s own check is a UUID PATTERN
   over the served strings, so it catches that and would refuse a legitimate id the server
   licensed if the screen ever rendered a section member. **Two layers, two mechanisms,
   and the day one is retired the other does not cover it.**
3. **THE SERVER'S LICENCE IS TWO IDS AND THE CONSOLE'S IS ONE**, and they are not in
   conflict today only because `apps/admin`'s document renders a count per section and
   never a member. **The first screen that renders one field of the `identity` section
   trips `assertServedAccountDetailStrings`** with an id the server correctly licensed.
4. **`admin-reads.ts` AND `admin-feed.ts` NOW STATE ONE RULE TWICE INSIDE ONE
   DEPLOYABLE**, which is a third copy counting `apps/admin`'s.
   [ADR-184](../decisions/ADR-184.md) section 6 took the second knowingly; this one is
   taken on a measurement, is bound by an assertion, and its repair is one deletion in one
   file. **It is still two copies and must be read together until that lands.**
5. **A CONTROL THAT SWEEPS A ROUTE MODULE FOR A RAW STRING CONSTRAINS ITS PROSE**, and
   the next session to explain something in `admin-reads.ts` will discover
   `admin-source-flags.test.ts:1229` the way this one did: by a green edit turning a
   suite red for a reason with nothing to do with the edit.
