## 2026-08-23 - Session 138 (P2-g): `hash.ts` into `packages/rules-engine` (money path)

- **Objective:** write [ADR-081](../decisions/ADR-081.md) and move canonical state hashing out of [`apps/worker/src/batch/state-hash.ts`](../../apps/worker/src/batch/state-hash.ts) into [`packages/rules-engine/src/hash.ts`](../../packages/rules-engine/src/hash.ts), where [M01 section 1.3](../plans/M01-rules-engine.md)'s layout puts it, without changing a single digest.

- **Done:** **[ADR-081](../decisions/ADR-081.md), `status: proposed`, approval line unsigned.** `hash.ts` is in the engine with a **hand-rolled SHA-256** and a hand-written UTF-8 encoder; the public surface goes **fourteen names to twenty, gaining exactly two functions**; `apps/worker/src/batch/state-hash.ts` survives as the `Buffer` boundary and one wrapped call. **The digest is unchanged.** Two new engine test files, a differential block and a pinned digest in the worker's.

- **The count:** **`pnpm run verify` exits 0.** 7 of 7 invariants (`RI-07` walks `hash.ts` and reports no Node builtin), **103 files / 1476 passed / 1 skipped** against 101 / 1417 / 1 measured on `origin/main`, so **+2 files and +59 tests**. 28 of 28 gates; `falsify` reports **all 28 pass clean and fail dirty**, 55 scope cases and 10 loader cases.

- **The baseline, and the order it was taken in.** On `origin/main` at `acd65a6`, through the `createHash('sha256')` that lived in `apps/worker` at the time, the fixture subject serializes to **309 bytes** and hashes to **`6f640ab71dacea9cb5f7c8502e2e11cafb8ab126d1c79c9c9761087112f60d60`**. It is the first commit of the session on purpose: a before-value measured afterwards with the new code is not a before-value, and that distinction is easy to lose at the last commit.

- **Next:** **session 140 holds [`apps/worker/src/batch/replay.ts`](../../apps/worker/src/batch/replay.ts)** and folds it onto the engine's `replay`. It imports `HASHED_COLUMNS`, `ENGINE_GATE_LEAVES` and `StateHashSubject` from `./state-hash.js`, which is now a re-export shim, so **that path keeps resolving and 140 may point it at `@merit/rules-engine` directly or leave it**. `OI-29`'s enforcement half, a trigger or an application publish path, is P3's and is now the only half of it outstanding.

- **Blockers:** **this branch waits on the founder's `E2` read and must not be merged before it**, and this one is asked for rather than assumed. `134` and `135` merged on delegated authority without one, which [P2 section 9](../plans/P2-rules-engine-build.md) records. **A hand-rolled cryptographic primitive on the money path is the strongest case for a real read this project has produced.**

- **Landmines:**

  - **THE DECISION THIS SESSION LOOKED LIKE IT HAD TO MAKE WAS ALREADY MADE.** [`state-hash.ts`](../../apps/worker/src/batch/state-hash.ts)'s header called the choice between a scoped lint exception and a hand-rolled SHA-256 *"not a decision to make in passing"*, and the [2026-08-17 review desk](../reviews/2026-08-17-review-desk.md) section 3 had ruled it on 2026-08-17: hand-roll, no exception, and **the alternative refused by name** because amending `RE-D-03` to exempt `node:crypto` is *"out on constitution grounds. Working agreements, section 9: never weaken a gate to pass it"*. **Read the review desk before re-deriving a ruling from a file header that predates it.**

  - **THE DESK NAMED TWO MECHANISMS AND THERE ARE THREE, AND THE THIRD IS THE ONE THAT SETTLES IT.** `RI-07` walks the graph and `merit/engine-purity` reports the import, and both are arguable in the way a check is arguable. [`tsconfig.json`](../../packages/rules-engine/tsconfig.json)`:14`'s `"types": []` makes `node:crypto` and `Buffer` a **compile error**, which its own comment calls *"the only one a lint-disable comment cannot route around"*. **The hand-roll is forced, not preferred**, and a session that frames it as a preference will spend the ruling arguing.

  - **THE UTF-8 ENCODER IS THE SUBTLEST THING HERE AND NO FIXTURE REACHES IT.** `Buffer.byteLength` does not exist in the engine, so the encoder is written out, and it has to agree with Node on **unpaired surrogates**, which both replace with `U+FFFD`. Every value in a real `rule_states` row is ASCII, so a fixture passes while the encoder is wrong. **The control is the differential block**, which drives lone highs, lone lows, a high followed by a non-surrogate, a high at end of string, valid pairs and a reversed pair through the real serializer and asserts **both halves each time**: the digest **and** the byte-length prefix. A digest that matched while the prefix disagreed would mean both sides are wrong the same way.

  - **THE BEST TEST IN THIS SESSION IS ONE NOBODY WROTE FOR IT.** [`apps/worker/test/state-hash.test.ts`](../../apps/worker/test/state-hash.test.ts) transcribes the whole serialization by hand from ADR-026 C-07 and hashes it with `node:crypto`. **Routed through the shim, and with not one of its 603 existing lines edited**, it became an independent implementation of the serialization AND an independent SHA-256 checked against the hand-rolled one. Under `"types": []` the engine's own `test/` cannot import `node:crypto` either, so it is the **only** place in the repository where the hand-roll meets OpenSSL. **Preserving an existing test can be worth more than writing a new one, and it was here.**

  - **`EXCLUDED_COLUMNS` IS EXPORTED FOR A DIFFERENT REASON THAN THE OTHER FIVE, AND THE ADR SAYS SO SEPARATELY.** `HASHED_COLUMNS` and `ENGINE_GATE_LEAVES` are walked in **production** at [`replay.ts`](../../apps/worker/src/batch/replay.ts)`:167` and `:173`. `EXCLUDED_COLUMNS` has **no production consumer at all**: `apps/worker/src/index.ts:55` re-exports it and the test asserts over it, and that is the whole list. It is exported to keep the differential oracle reachable, which is legitimate **precisely because** that test is an independent implementation. Written as two cases rather than six instances of one, so a later session does not read it as precedent for exporting a frozen table nothing reads.

  - **`CI-06f` MATCHES THE BOLDED RESERVATION PHRASE, SO A QUOTATION OF IT RE-ARMS THE GATE.** The [ALLOCATION](../decisions/ALLOCATION.md) row is amended in place per [ADR-065](../decisions/ADR-065.md) T3 and keeps its original wording after *"Originally reserved as"*, which is session 134's shape. **It failed `CI-06f` twice before it passed**: once because the quoted original still carried its emphasis, and once because the sentence explaining the first fix quoted the matched pattern in backticks. Both were watched failing. **Quote a struck reservation with its emphasis dropped and do not name the pattern.**

  - **[ADR-078](../decisions/ADR-078.md) SECTION 5 IS WRONG BY ONE NUMBER AND IS DELIBERATELY NOT REPAIRED.** It says *"`apps/worker/src/batch/replay.ts` is NOT migrated onto the export. Sessions 138 and 140 hold that file."* This session's fence does not include `replay.ts` and neither does `P2-g`'s in the [build plan](../plans/P2-rules-engine-build.md), which says it is **140**'s alone. ADR-078 is accepted, and a signed entry moves by amendment rather than by a later session editing it in passing. **Recorded in ADR-081 section 5.**

  - **THE FENCE HELD TO ONE FILE IN `apps/worker/src` BECAUSE THE SHIM EXISTS.** `P2-g`'s fence in the build plan lists `nightly.ts`; this session's did not. `nightly.ts:66`, `replay.ts:77` and `src/index.ts:52` all import from `./state-hash.js`, so making that path a re-export left all three compiling untouched. **A narrower fence was satisfiable only because the original module was written as a file move**, which is what its header claimed and turned out to be true.

  - **THREE FILES OUTSIDE THE FENCE WERE FORCED BY GATES, REPORTED BEFORE BEING TOUCHED.** [`decisions/README.md`](../decisions/README.md) (`CI-06n`), and the `adr_count` spans in [`INDEX.md`](../INDEX.md) and [`STATE.md`](../STATE.md) (`CI-06g`, written by `gates.mjs generate`). Session 134 hit the identical shape: **a session fenced out of the file that validates its own change cannot end green.** [STRATEGY](../testing/STRATEGY.md)`:385` carries the same span inside a fenced block, which `spansIn` masks, so the generator left that frozen document alone.

  - **THE HAND-ROLL'S WALL CLOCK, REPORTED AND NOT TUNED.** At the nightly's 5,000 accounts, `stateHash` costs **121 ms** against **80 ms** for `node:crypto` over the identical serialization: **24.3 µs against 16.0 µs per account, 1.5x, 41 ms across a whole night.** Written down so nobody has to guess later. It is not a licence to optimise a primitive whose correctness is the only property that matters.

  - **`sha256` AND `utf8Bytes` ARE MODULE EXPORTS AND NOT PACKAGE EXPORTS**, which is `clampPayout`'s precedent exactly: section 1.3's list governs the **entry point**, not every module boundary. The engine's tests already import internals by relative path, and without that the 28 known-answer vectors could only reach the primitive through nineteen framed columns. **A primitive testable only that way is one whose failures arrive as a state hash nobody can localise.**
