### 4. What was not done, and why

- **The sink is not wired.** There is no address in this tree where a caller can stand, and forcing one would have meant either violating `RI-04` or performing a 31-file relocation dispatched as a wiring.
- **No system door was opened in `apps/api`.** [ADR-165](../decisions/ADR-165.md) clause 5 refuses it by name, and amending that clause is a second and separate decision from the relocation: the relocation unblocks the worker's nine call sites and unblocks none of the API's four catalogue rows.
- **The six refused emits were not repaired.** Four need an EVENTS row, one needs a catalogue field this file may not invent, and one is `apps/worker/src`'s one-line payload repair already registered by [ADR-205](../decisions/ADR-205.md) section 7.
- **`apps/api/src/start.ts` was not touched**, as the dispatch required. Nothing here needs a registry line, because nothing is installed.
- **The rest of the `RI-35` register was not audited** for the probe class [ADR-338](../decisions/ADR-338.md) found. The two probes added here are written against that lesson; the others were not re-read.

---

### 5. Blockers and landmines

- **THE ESTATE RECORDS NO TRANSITION AT ALL, AND THIS IS THE LANDMINE RATHER THAN A BLOCKER ON THIS ROW.** `events` is append-only by grant, so history not written today cannot be written later by anything the application holds.
- **A WIRING SESSION THAT INSTALLS A SINK AND STOPS WILL SHIP SIX SILENT REFUSALS INSIDE MONEY-PATH TRANSACTIONS.** Three of nine call sites would write. The other six throw, and because `emit` runs inside the caller's transaction the throw rolls the state change back. That is correct behaviour and it is not what a session declaring the slice done would expect.
- **`flag.raised` HAS NEVER BEEN RUN AGAINST A DATABASE.** Session 379 ran the two then-writable names against live PostgreSQL and both wrote; `flag.raised` became a catalogue row afterwards and its place in the 3-of-9 column is derived from source rather than observed.
- **THE NO-CALLER CLAIM IS OVER STATIC TEXT.** Two greps and one probe. A caller reached through a dynamic import or a string-keyed lookup would defeat all three; this workspace appears to have no dynamic import anywhere, and that was not measured.
