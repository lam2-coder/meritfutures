- **Landmines:**

  - **`@merit/db` CANNOT SUPPLY THE EXECUTOR, AND [ADR-084](../decisions/ADR-084.md) SECTION 2 SAYS THIS SESSION BUILDS ON THAT POOL.** Both are true and the entry says so in one sentence rather than choosing. **Measured by importing the package and printing its surface, not by reading its header**: eight value exports, `SCOPE_RULES TABLES TABLE_KEYS closeClient schema scopePredicate scopedDb systemDb`, and `scopedDb(identity)` carries `__brand identityId rows` while `systemDb(reason)` carries `__brand reason rows`. **Neither has `executeSql`**, and `closeClient` is the only export whose name is about the connection: it closes the pool rather than lending it. **No second pool was opened**, which is what the brief asked for if this turned out to be the case.

  - **THE PACKAGE CANNOT OPEN A POOL EVEN BY MISTAKE, AND THAT IS WHY THE SESSION COULD FINISH AT ALL.** `packages/queue` declares no `pg`, no `drizzle-orm` and no `@merit/db`; the connection and the transaction are both arguments. Had the adapter been written to construct its own pool the fence would have hidden the finding behind working code.

  - **`merit/no-raw-db-client` BANS `drizzle-orm` HERE, WHICH DECIDES THE PORT'S SHAPE.** pg-boss ships `fromDrizzle(tx, sql)` and it needs the `sql` tag imported from `drizzle-orm`, which VG-4 refuses outside `packages/db`. So `JobTransaction` is a bare `executeSql` port and the Drizzle-to-executor adaptation, if it is ever wanted, belongs on the `packages/db` side of the boundary. **The rule chose the design; the design did not route around the rule.**

  - **pg-boss DEFAULTS `migrate` TO TRUE.** `dist/attorney.js`: `config.migrate = ('migrate' in config) ? config.migrate : true`. The stock configuration runs DDL against the money database at `start()`, from a library, outside the migration set [ADR-008](../decisions/ADR-008.md) makes reviewable and E2 makes sacred. **It is off**, so `start()` against an uninstalled schema fails with `pg-boss is not installed` and emits nothing. Flipping the flag makes the case report `expected [ 'CREATE SCHEMA IF' ] to deeply equal []`.

  - **TWO OF THE SUITE'S EXPECTATIONS WERE WRONG ON FIRST RUN AND pg-boss CORRECTED THEM**, which is the whole argument for reading the vendor's output rather than the adapter's intent. `startAfter` crosses the wire as an **ISO-8601 string** because pg-boss `JSON.stringify`s the job into `$1`; `declareQueue` calls the schema's **`create_queue` function** under an advisory lock rather than inserting a row. **A suite that had taken its expectation from `pg-boss-queue.ts` would have agreed with itself about both**, which is [ADR-084](../decisions/ADR-084.md) section 7 exactly.

  - **`x` IS NOT A FREE `CI-06` LETTER AND THIS SESSION SPENT NO LETTER AT ALL.** No new gate: the property is a runtime one and belongs in the `unit` project, which runs on every push, rather than in a corpus gate.
