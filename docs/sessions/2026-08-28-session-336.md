### 2. Ruling 1, and the measurement that decided it

**The naive reading favours a private port and it is the reading four files support.** `admin-certificates.ts`, `admin-payouts.ts`, `admin-wallet.ts` and `admin-writes.ts` each declare their own backend, which looks like one-module-one-port.

**Enumerating the 23 declared ports breaks it: all four of those are WRITE backends, and there is exactly ONE admin READ port.** Writes are per-module because each is a different authority over a different table. Reads are not, and `AdminReadSource` is the only one.

**The stronger argument for a private port is about a reason string, and it fails on a precedent one slice old.** `setAdminReadSource`'s `BLOCKED` entry ([`wiring.test.ts:139-147`](../../apps/api/test/wiring.test.ts)) is a SHAPE reason: *"None of the six methods is a projection of one table ... A live adapter today would have to reach `sqlExecutor`"*. That is false for the feed, which is a keyed range read over one table. **But it is already false for two methods on the port**, and [`admin-source/index.ts`](../../apps/api/src/admin-source/index.ts) records the resolution in terms: for `listFlags` and `readIdentityGraph` the reason *"is now MEASURED FALSE"*, and *"this slice reports the narrowing rather than editing it"*. **The tree's settled answer to this exact question is that the method stays and the narrowing is reported.** This entry does the same rather than inventing a second answer for the third instance.

**Both defences are kept and they move differently, which is them working rather than disagreeing.** The `Partial` plus `AdminSourceNotComposed` half is about what a DEPLOYMENT has composed, so it gains one arm. The `IMPLEMENTED_ADMIN_READS` plus `Pick` half is about what THAT DIRECTORY implements, which is no feed module, so it is untouched. One says the port has seven methods, the other says the directory supplies two, and both are true.

**The fence is wrong in a specific and checkable way.** `AdminReadSource` is DECLARED at `admin-reads.ts:694` and only COMPOSED in `admin-source/index.ts`, so row `184` fences the file holding the smaller half. **The plan's own row named the right file and the reservation replaced it with the wrong one.** Neither names edit 3, and edit 3 is not optional.

**So the entry rules and the code waits, which is what an unsigned ruling means.** Implementing an unsigned ruling's port would be asserting the signature the entry is asking for. **What landed is every part that needs no port**, and the request half is the half `INV-M6-10` lives in.

**One shape was considered and refused by name.** A port could be spelled so `wiring.test.ts`'s `DECLARES` regex misses it. **That is weakening a gate to pass it**, and [`wiring.test.ts:373`](../../apps/api/test/wiring.test.ts) exists for exactly the state it would create. The route module therefore declares no port, and a test asserts that it does not, so the next slice is forced to notice the obligation.
