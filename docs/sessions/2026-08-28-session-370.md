### 3. The ruling, and why the three losers lose in their own terms

**A `_cents` VALUE IN AN `events.payload` IS A JSON STRING HOLDING THE DECIMAL INTEGER
NUMBER OF CENTS**, `/^(0|-?[1-9][0-9]*)$/`, `null` preserved as `null`, exact over every
integer, no ceiling.

**A JSON NUMBER: the magnitude argument does not carry it, and saying so was the point.**
The dispatch asked whether 2^53 is a real ceiling for a firm-level treasury figure, with
the largest producible value named and cited. **It is theoretical.** `Number.MAX_SAFE_INTEGER`
is 9,007,199,254,740,991 cents; the payout cap at the largest size is **450,000c**
([`M01:1215`](../plans/M01-rules-engine.md)) over a ladder shortened to **5** by
[ADR-024](../decisions/ADR-024.md), so one account's lifetime commitment is bounded near
`2,250,000c`, and the largest firm-level payload figure, `remaining_ladder_exposure_cents`
defined at [`0009:181`](../../packages/db/migrations/0009_ledger.sql) as
`sum((ladder - payouts_settled) * cap)`, needs on the order of **four billion funded
accounts** to reach 2^53. [`catalog.ts:515`](../../apps/api/src/routes/catalog.ts) is
right that it "will not happen".

**What decides it is the type a consumer holds, forever.** `JSON.parse` yields a
JavaScript `number`, which is an IEEE-754 double. A JSON number would guarantee that
**every JavaScript reader of this table holds money as a double**, and that is the one
type `assertPayloadRules` refuses on the way in, in its own words, "because a `number`
reaching here may already have lost digits". The check is decidable at the writer because
the value arrives as a `bigint`; it becomes **undecidable at every reader forever**.
A string parses back to `bigint` and stays decidable, including at the 2031 audit reading
a 2027 row that EVENTS section 1 names. **And producing the number is itself that
coercion**: there is no way to emit a `bigint` as a JSON number token without
`Number(value)` first.

**A TYPED ENVELOPE: priced, not assumed away.** `{"unit":"cents","value":"150000"}` buys
self-description. It costs three things and the first decides it. **The unit is already in
the key**, so the envelope states one fact twice and **nothing on the row would say which
wins** when a `_cents` key carries `{"unit":"bp"}`, on a table that cannot be repaired
after the first producer spells it wrong. It **re-specifies 33 catalogue rows** to buy
that, the fenced block at [`EVENTS.md:224`](../architecture/EVENTS.md) included, where a
decimal string changes their type and leaves their shape. And it is the largest of the
four on a forever-retained table, on the row EVENTS calls "the single most audited event
in the system", which carries six money fields.

### 4. The fourth option, which was already in this workspace

**IT WAS FOUND BY SEARCHING RATHER THAN GIVEN, AND NEITHER THE DISPATCH NOR THE
ALLOCATION ROW NAMED IT.** [`asJsonNumber`](../../apps/worker/src/detectors/graph.ts) at
`graph.ts:394` converts a `bigint` "to a `number` when it is exactly representable and to
a DECIMAL STRING when it is not", over `risk_flags.evidence`, which is **the same `jsonb`
problem one deployable over**. Its own header states the same finding: "a `bigint` CANNOT
BE `JSON.stringify`d AND `evidence` IS `jsonb`".

**IT LOSES ON ONE PROPERTY AND IT IS DECISIVE FOR THIS COLUMN.** The type varies with the
value. Section 3's arithmetic says every value this system can actually produce is under
2^53, so **a consumer written against real data sees `number` and only `number`**; the
string branch is code no fixture, no suite and no deployment ever executes, and the day it
does is the day a figure crossed ninety trillion dollars, which is the single row where
being wrong costs most. A uniform string has no rare branch. **And it cannot be
versioned**: EVENTS makes shape a function of `schema_version`, and a magnitude-conditional
type makes shape a function of the VALUE, which no version number can express.

**IT IS NOT OVERTURNED AND NOT TOUCHED.** `apps/worker` is not this fence and
`risk_flags.evidence` is not EVENTS' column. The divergence is landmine 2.

### 5. The dispatch's third premise is false

It priced a JSON string as *"a format no document in this corpus states, so every reader
of the feed acquires an undeclared parse"*. **Three prior rulings state it.**

| Where | What it already states |
| --- | --- |
| [ADR-158](../decisions/ADR-158.md) clause 3 | "`entry_id` is a DECIMAL STRING, and it is the first non-uuid identifier this contract carries" |
| [API_CONTRACT:681](../architecture/API_CONTRACT.md) | "a `bigint` on the wire as a JSON `number` ... admits a value above `Number.MAX_SAFE_INTEGER` that has already lost digits by the time anything reads it" |
| [`graph.ts:394`](../../apps/worker/src/detectors/graph.ts) | a `bigint` reaching a `jsonb` column becomes a decimal string when it is not exactly representable |

**So the cost priced as an undeclared parse was smaller than it looked and the argument
for the number was correspondingly weaker.** What was still owed is the DECLARATION,
because none of the three is about `events.payload`, and EVENTS is where a reader of the
feed looks. That is section 13.
