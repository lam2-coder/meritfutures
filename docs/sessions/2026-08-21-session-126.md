### `ADR-076` was refused because the check it asked for was run

**Its approval line named the cheapest check in the entry and called it *"the one worth performing rather than accepting"***: section 6 moves seven registry rows to `covered-elsewhere`, and each is one grep. **[Session 123](2026-08-21-session-123.md) performed it and one of the seven failed.**

`GS-072`'s cited site is [`replay-determinism.property.test.ts`](../../scripts/demo/test/replay-determinism.property.test.ts)'s arrival-order block, which is `describe.skipIf(!replayExists)` over `Object.keys(engine).includes('replay')`. That is false, so the block skips and its body **throws** rather than asserting. Confirmed by running it rather than by reading it:

```
↓ PT-06: arrival-order permutation > any permutation of arrival order yields byte-identical stored state
  PT-06: arrival-order permutation is UNEXPRESSIBLE (the engine exports no replay; P2-8)
```

> **The entry predicted its own failure mode exactly**: *"if that is wrong the cost is seven rows marked covered that are not."* Six are. One is not. **The check worked, and running it is why this line reads WITHHELD rather than GRANTED.**

**The consequence lands on `X8` and not on the file.** After session 123's comment, `GS-072`'s citation resolves and its file names the row's id, so `covered-elsewhere` as [ADR-076](../decisions/ADR-076.md) specifies it -- *"the cited path exists and contains the row's own id"* -- **passes on a row whose assertion never executes**. A gate that cannot distinguish a skipped block from a running one is not a gate. Both remedies are in the approval line.

### `ADR-074` was signed on the amendment, and the amendment is what made it signable

The unamended section 3 stated **118 series and 1,086 members** *"so `W8` can check that its transcription reproduced it"*. `W8` ran the check and it failed. What replaced it is **117 and 1,083 as one cell of a partition of all 215 series and 2,106 members**, and both columns close: 50+117+36+12 = 215, 698+1,083+281+44 = 2,106. **118 agreed with the sum of its own four rows while two of them were wrong by `+3` and `-2`**, which is how a total that adds up hides compensating errors and a partition that adds up cannot.

**The gate reports 115 and 1,070 on `main` and is not wrong about the tree**; it reads the pre-amendment scope. Section 8's five runner edits are owed.
