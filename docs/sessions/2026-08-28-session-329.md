### 2. The central question, and the shortest section in the plan

The dispatch called it the plan's central question and asked for an argued answer rather than a default. **It is ruled, in an approved document, twice.**

| Source | What it says |
|---|---|
| [`INFRA:43`](../architecture/INFRA.md) | service **`admin`**, codebase `apps/admin`, `MERIT_API_SURFACE` **not set**, origin **`ADMIN_ORIGIN`**, serving *"The operator console"* |
| [`INFRA:44`](../architecture/INFRA.md) | service **`api-admin`**, codebase `apps/api`, `MERIT_API_SURFACE` **`operator`**, origin **`ADMIN_ORIGIN`, under `/api/v1`** |
| [`INFRA:53`](../architecture/INFRA.md) | *"Two services share each public-facing origin, so Cloudflare routes by path. `/api/v1/*` reaches `api` on `app.meritfutures.com` and `api-admin` on `ADMIN_ORIGIN`; everything else reaches `portal` and `admin` respectively."* |
| [`INFRA:71`](../architecture/INFRA.md), hard rule 3 | *"Two services run on `ADMIN_ORIGIN`, a separate apex domain: the admin console (`admin`) and the operator API (`api-admin`)"* |

**So `apps/admin` serves HTTP, and it never serves `/api/v1`.** Three mechanisms already refuse the other shape and none of them is new: `RI-04` ([`repo-invariants.mjs:363`](../../packages/tooling/checks/repo-invariants.mjs)) refuses `apps/admin` importing `apps/api`, `RI-09` ([`:1318`](../../packages/tooling/checks/repo-invariants.mjs)) refuses a PATH spelling the API surface outside `apps/api`, and `RI-11` ([`ui-server-endpoints.mjs:168`](../../packages/tooling/checks/ui-server-endpoints.mjs)) refuses a Server Action anywhere with no exemption.

**A SIDE EFFECT WORTH RECORDING: THE CONSOLE'S API BASE URL IS SAME-ORIGIN.** Both services sit on `ADMIN_ORIGIN`, so the client calls `/api/v1/admin/...` as a relative path, needs no hostname and needs no CORS configuration. `INV-M6-02`'s *"shares no CORS policy with any public surface"* is satisfied by there being no cross-origin request to have a policy about, and [ADR-012](../decisions/ADR-012.md)'s *"never written into ... any artifact"* survives a build step **because a relative base URL cannot be inlined into a bundle**. That is the plan's section 5.3 and it is stated as a constraint on `W6-c` rather than as a happy accident.

**What is genuinely undecided is the framework**, and [ADR-095](../decisions/ADR-095.md) ruling 2 says so in its own words: *"`apps/admin` gets none by this entry: the admin console is M06's and is in no P4 slice, so an entry whose fence is P4 `P4-c` may not decide it."* [`playwright.config.ts:11`](../../playwright.config.ts) records the same absence from the third side. **That is `W6-a` and it is one of two slices in the wave that requires an ADR number.**

### 4. Three findings

**4.1 The barrel omits 23 exported names and one whole module.** Measured by reading each module's top-level exports against `index.ts`: `feed.ts` is not in the barrel at all (14 exports), `liability.ts` is short by 8 (`TreasurySource`, `TREASURY_SOURCES`, `requireTreasurySource`, `ReserveCoverageSnapshot`, `RCR_BREAKER_BP`, `formatRatioBp`, `ReserveCoverage`, `reserveCoverage`) and `page.ts` by one (`assertFloatIsNotReserve`).

**This is [P7](../plans/P7-risk-and-abuse.md) section 5.5's defect class in the fourth deployable, and here nothing was deleted: the names were never added.** The consequence that matters is not tidiness. [`index.ts:47`](../../apps/admin/src/index.ts) states that the `exports` map publishing `.` alone is what stops a consumer reaching past the barrel, so a module outside it is unreachable from anywhere in this workspace; and [`service.test.ts`](../../apps/admin/test/service.test.ts) asserts *"the public entry point exports nothing that reads as a mutation"* by filtering `Object.keys(admin)`, so **a module outside the barrel is outside the only control the package has over its own exports**. `feed.ts` renders identity and account ids on its subject-named arm, which is this package's highest read-side risk.

**The repair is green under the existing test and that was READ rather than assumed.** The runtime values the barrel would gain are `FeedError`, `WITHHELD`, `namesASubject`, `buildFeed`, `thread`, `mayReadEventFeed`, `renderRow`, `renderFeed`, `assertWithheld`, `TREASURY_SOURCES`, `requireTreasurySource`, `RCR_BREAKER_BP`, `formatRatioBp`, `reserveCoverage` and `assertFloatIsNotReserve`; none begins with any of the 21 verbs in that test's list, and the type-only names never reach `Object.keys`.

**4.2 The two `INV-M6-10` assertions read a line array a rendered page will not use.** [`assertNamesNoSubject:219`](../../apps/admin/src/page.ts) and [`assertWithheld:498`](../../apps/admin/src/feed.ts) both take `readonly string[]`, and `feed.ts`'s header gives the ground: *"A redaction that is a CSS class is a redaction a copy-paste undoes."* A React page renders a DOM. **If a slice builds the document from the structured value and leaves the assertions on the lines, both controls stop covering the served bytes and both suites stay green** -- which is exactly the miss [STATE](../STATE.md) records for `projectFlag` on 2026-08-28, where an assertion ran before the projection. The plan carries the remedy as a rule every rendering prompt inherits rather than as a discovery.

**4.3 `API_CONTRACT` sections 8 and 9 carry no event-feed endpoint.** Enumerated from the contract rather than grepped: liability, eligible-forecast, loss-ratios, cusum, accounts and account detail, four account writes, flags and its status write, certificate revoke, identity graph, evidence, two plan writes, two payout writes, three wallet rows, and section 9's four `/internal` rows. **No feed.** `M06` section 1.1 names the event feed a launch surface and `feed.ts` implements it in 507 lines with 421 lines of tests. `W6-e` is the row and it needs an ADR, because `API_CONTRACT` is `approved`.
