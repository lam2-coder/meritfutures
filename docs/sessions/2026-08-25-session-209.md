### 1. The shape decision, which is the row's actual deliverable

**`P4-d`'s money column is the only one in [P4](../plans/P4-portal-and-site.md) section 8 that carries a consequence instead of a yes or a no:** *"no by content, and **high consequence**: the registry's SHAPE decides whether M19's seven route slices serialize."* [Session 168](2026-08-24-session-168.md) states it in the direction that fails: *"`M19-1` must create a registry that is **per-module rather than one array**, or these seven serialize."*

**Two designs were available and the arithmetic decides between them.**

| | An array in one file | The directory listing |
|---|---|---|
| Adding a route | one import line and one array element, in the same two places, in one file | one new file |
| Fifteen concurrent slices | fifteen branches on two lines: each merges cleanly alone, none merges with another | fifteen disjoint paths, any order |
| Forgotten registration | the file is on disk, the module's own test passes, the endpoint 404s and nothing says so | impossible: the listing IS the definition |
| Duplicate `METHOD /path` | merges, and Fastify refuses the second registration at startup | refused by `compose`, naming both modules |
| Checked by `tsc` | yes, at the import site | at the DEFINITION site, via `defineRoutes` |

**The fifteen are named rather than counted from memory**: [P4](../plans/P4-portal-and-site.md) section 9's `apps/api/src/routes/index.ts` row lists `P4-f`, [M03](2026-08-24-session-157.md)'s `M3-i` and `M3-j`, [M05](2026-08-24-session-159.md)'s `M5-5` and `M5-8`, [M16](2026-08-24-session-165.md)'s `S4`, `S7` and `S8`, and [M19](2026-08-24-session-168.md)'s seven, which that session's own collision table gives as `M19-2`, `M19-3`, `M19-6`, `M19-7`, `M19-8`, `M19-9` and `M19-11`.

**The row-3 failure is the one that decided it.** An array's collision is loud, and the corpus has already paid for the loud kind: [session 204](2026-08-25-session-204.md) resolved five branches on `schema.ts` where *"git aligns the hunk on lines two unrelated tables merely happen to share"*. What an array cannot do is notice a slice that wrote its route file and forgot the import line. **A directory listing has no such state**, and it is the refusal this repository already makes in the two places it has been checked: [`repo-invariants.mjs`](../../packages/tooling/checks/repo-invariants.mjs) is *"SEEDED FROM THE MIGRATION DIRECTORY AND NEVER FROM A HAND LIST"*, and [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml)'s catalog refuses *"a number written in seven manifests"*.

**What discovery costs was paid rather than absorbed**, and [`registry.test.ts`](../../apps/api/test/registry.test.ts) watches each of the three, at **15 tests**. The strongest is an **equality and not a count**: the discovered module names must equal the `.ts` files in the directory, so a module added by any future slice appears with no line of that test changing.

**`apps/api/src/routes/index.ts` is not created.** Section 9 names it as a **BARRIER** that fifteen slices queue behind; under this ruling there is nothing to register into, so the barrier is removed rather than scheduled. `P4-f`'s fence names that file and simply will not need it.

### 4. The 404 is the router's, watched over a real socket

**[`surface.test.ts`](../../apps/api/test/surface.test.ts)'s header said the suite that watches a real 404 *"arrives with the routes"*. It arrived.**

Two processes, two ports, **the same module set**, composed under `node --experimental-strip-types` with nothing built:

```
############ PUBLIC (service api, port 3111) ############
--- GET /api/v1/health
HTTP/1.1 200 OK
content-type: application/json; charset=utf-8
{"status":"ok"}
--- GET /api/v1/internal/jobs
HTTP/1.1 404 Not Found
content-type: application/problem+json; charset=utf-8
{"type":"https://meritfutures.com/problems/not_found","title":"Not found","status":404,
 "code":"not_found","instance":"req-3"}
--- GET /api/v1/admin/liability   404
--- GET /health (no base path)    404
--- GET /openapi.json             404
############ OPERATOR (service api-admin, port 3112) ############
--- GET /api/v1/health            200
--- GET /api/v1/internal/jobs
HTTP/1.1 200 OK
{"depth":0}
```

and the public process's own startup line, which is the evidence the mechanism is live rather than merely absent:

```
{"service":"api","surface":"public","modules":["health","ops"],
 "registered":["GET /health"],"withheld":["GET /internal/jobs"],
 "msg":"merit api: 1 route(s) registered, 1 withheld from this surface"}
```

**`GET /api/v1/internal/jobs` is 404 on one origin and 200 on the other, and the difference is which routes each process registered at startup.** No permission check ran on either side, which is the whole of [ADR-083](../decisions/ADR-083.md) section 4: *"403 is what a permission check returns. 404 is what an ABSENT ROUTE returns."*

**The same matrix is asserted in the suite as well**, at three levels: [`server.test.ts`](../../apps/api/test/server.test.ts) through Fastify's real pipeline via `inject` (9 tests) and [`listen.test.ts`](../../apps/api/test/listen.test.ts) over a real ephemeral-port socket with `fetch` (3 tests). The `ops` module in both is **synthetic and that is stated in the file**: this slice owns no operator route, and waiting for one means the mechanism ships unwatched.

**The 404's BODY is contract-shaped and that is a small deliberate addition.** Fastify's default is `{"message":"Route GET:/api/v1/... not found","error":"Not Found","statusCode":404}`, which is neither [API_CONTRACT section 1](../architecture/API_CONTRACT.md)'s media type nor section 2's shape and which echoes the requested path back. `server.test.ts` asserts the key set exactly and asserts the path does **not** appear. **Fourteen of section 2's sixteen codes are deliberately not implemented**: they belong to handlers that compute something.

|---|---|---|

**[ADR-083](../decisions/ADR-083.md) is NOT edited and its ruling 3 is not weakened.** Its section 5 measured a `.ts` entry point serving 200 under this runtime in a scratch directory and that measurement stands; what it did not measure is this tree's specifier convention, because `apps/api` then had one relative import and nothing to run.

**The repair is two things together and it was EXECUTED in a scratch copy outside this repository**, on ADR-083 section 5's own precedent: `./x.js` becomes `./x.ts` throughout the affected `src/`, **and** the tsconfig gains `allowImportingTsExtensions: true`, without which `tsc` reports `TS5097` on every rewritten line (watched, on one line, before the finding was written). With the specifiers rewritten by `sed` and **nothing else changed**, both surfaces started and served, which is section 4's transcript. **`apps/api/tsconfig.json` is outside this fence and the other two deployables are outside it entirely.**

**FINDING 2: [ADR-085](../decisions/ADR-085.md)'s signed clause is the eighth of its class.** [ADR-099](../decisions/ADR-099.md) section 4 named the class -- ruling holds, enumeration drifts -- and counted six, with `ADR-095`'s the seventh. ADR-085's says `29 of 29` where the tree is **30 of 30**, and says the gate is watched failing *"when a real `fastify` key is seeded into the lockfile"*, which now reopens nothing. **Its RULING is untouched and correct.** A signed entry moves by a superseding ADR and never by a session, so it is recorded in [ADR-100](../decisions/ADR-100.md) section 7 and left standing.
