- **Landmines:**

  - **ONE OF THE SIX REJECTIONS IS UNREACHABLE, AND FINDING THAT OUT COST A SEED THAT SILENTLY PASSED.** `absorbed-session-not-claimed` is the reverse pass: a trade date follows a holiday and no holiday names it. **It cannot fire.** Let `D` trade with a holiday at `D - 1`. If that holiday says `null`, `absorbed-null-but-next-day-trades` fires because `D` is the next calendar day and it trades. If it says an object, `absorbed-trading-day-not-next` requires it to name `nextTradingDay(D - 1)`, whose walk starts at `D` and returns `D`, so `D` is claimed. Both branches close before the reverse pass runs. **The seeded violation written for it built, and the harness said so**, which is the one thing that separates this from shipping it green. It is kept because the ruling enumerates it, and its `describe` block carries the proof plus a case per branch asserting the finding that actually catches each. **If that block ever goes red the backstop has become reachable and owes a seed.**

  - **A CHECK THAT CANNOT FAIL IS NOT A CHECK, AND THE TEMPTING FIX WAS TO WRITE A SEED THAT FAILS ON SOMETHING ELSE.** Any of the three obvious seeds for it reject on `absorbed-null-but-next-day-trades` or `absorbed-trading-day-not-next`, and each would have read as coverage in the file whose own header says "a rule that rejects for the wrong reason and a rule that accepts for the wrong reason are the same defect". **Deleting the rejection was also available and was not taken**: it is one of the ruling's six and removing it is a change to the ruling rather than to its enforcement.

  - **A SECOND LIMITATION, OUTSIDE THE SIX AND NOT INVENTED HERE.** A run of consecutive holidays lets **two** entries claim one trade date, and both are legitimate: `nextTradingDay` skips a holiday, so Wednesday and Thursday both correctly name Friday, whose session opened Tuesday evening before the run. **Nothing requires the two to state the same bounds**, and `generate` keys them by trade date so the last one wins silently. There is a passing test for the agreeing case, written because the shape reads like a duplicate claim and the next reader will assume it is a defect.

  - **ADR-055's OWN SNIPPET WRITES `date` AND THE GENERATOR HAS ALWAYS PARSED `day`.** Section 3's illustrative JSON uses `"date": "2026-09-07"`; `readHolidays` has read `h.day` since it was written. **The file follows the merged code, and the discrepancy is named in three places** a transcriber will actually be looking at: the source file's `_holidays_note`, the README's step 2, and a test that asserts the note says so. The ADR rules `absorbs_into`; it does not rule a rename, and silently renaming a key the merged generator reads would be a change nobody asked for.

  - **THE COMMITTED FILE CARRIES FOUR INDEPENDENT REFUSALS AND THE CASE ASSERTING THREE WAS WRONG.** It was written expecting `status`, the null exception lists and `evidence_to`, and the run reported `provenance-field-missing` sitting between the last two. **The count was corrected to what the runner said rather than the runner argued with**, and the case now peels all four off in order, which is what a transcriber will actually experience.

  - **THE MONEY-PATH LINE IS ONE LINE IN `generate`, AND EVERYTHING ELSE IS A GUARD AROUND IT.** A trade date whose session was absorbed opens where the exchange says it opened, not where `open_day_offset: -1` computes. Without it the row is a strict **subset** of the real session and a fill on the Sunday evening of Labor Day weekend falls inside no session in the file, which is `R-01`'s condition. **Three positive-control cases pin it**: the absorbed row opens Wednesday rather than Thursday, every unabsorbed row is unchanged so the exception stays an exception, and the absorbed open does not reach back past the preceding close, which is how this rule breaks.

  - **`absorbs_into` JOINED THE `OQ-SE-04` BLIND DIFF, BECAUSE A TRANSCRIBED VALUE NO SECOND READER IS COMPARED ON HAS NO SECOND READER.** It uses a shared-keys variant rather than `diffMaps`, so a holiday one reader missed reads as **one** disagreement instead of two and the count in the diff stays equal to the number of things to go and check.

  - **ONE PRE-EXISTING CONVENTION VIOLATION IS NAMED AND NOT FIXED.** [`generate.mjs:225`](../../packages/db/src/seed/calendars/generate.mjs) carries an em-dash, which Appendix F bans. It is inside the fence and one character, and it is left alone on the same reasoning as the `date`/`day` discrepancy: a drive-by edit in a file under review is diff noise, and naming it here is what makes it fixable by whoever is next in the file.
