- **Blockers:** None.
- **Landmines:**

  - **`RE-U-025` ALREADY EXISTED, AND THE EXPECTED TEST COUNT IS WHAT PROVED IT.** The brief said to write it "which does not exist", and `reU('R-25')` renders as `RE-U-025  R-25  ...` ([`rule-coverage.ts`](../../packages/rules-engine/test/rule-coverage.ts)), so the test has existed since group D landed. What did not exist was its **assertion**. The tell was arithmetic: a NEW test would have produced **749** passing, and the brief predicted **748**, which is reachable only by `GS-064` flipping alone. **The count was the specification and it disagreed with the prose**, so the count won. ADR-054 agrees in its own words: "`R-25`'s asserts the carried-field set directly."

  - **A STALE LOCAL INSTALL MADE THE BASELINE LOOK WRONG BY EIGHT TESTS, AND THE FIRST INSTINCT WAS TO DOUBT THE BRIEF.** The tree reported **739** passing against the brief's 747. The cause was not the code: [session 55](2026-08-17-session-55.md) added `fast-check` to the ROOT `package.json` for `scripts/demo`, this container's `node_modules` predated it, and `replay-determinism.property.test.ts` **failed to collect** rather than to assert. Vitest reported it as `2 failed` test FILES against `1 failed` test, which is the only visible difference between a file that failed and a file that never ran. **A test that does not run is not a test that passed**, and the count it silently removes looks exactly like a brief with the wrong number in it. `pnpm install` restored 747 and the brief was right all along.

  - **THE FALSIFY HARNESS OUTLIVED ITS OWN INVOCATION AND WAS STILL SEEDING MUTANTS INTO THE TREE.** `falsify-ci.mjs` was run in a loop of three, each wrapped in `timeout 300`, and the outer Bash call died first. **The node process survived as an orphan and kept mutating**: three consecutive `git status` calls named three different dirty files (`breach.ts`, then `floor.ts`, then `gates.ts`), which is what a live mutation harness looks like from the outside. **This is [session 49](2026-08-17-session-49.md)'s landmine in a new shape.** That session's repair was a journal replayed by the NEXT invocation, and it is intact and did its job; what it does not cover is a run that is never killed at all and simply outlives the shell that started it. **The tree was verified clean before anything was committed**, and no commit was made while the harness was live.

  - **AND THE LOOP WAS WRONG BEFORE IT WAS SLOW.** `falsify-ci.mjs` takes a STAGE argument (`falsify-ci.mjs CI-01`), which `package.json`'s own note says. Running it three times bare and grepping the output for `R-24`, `R-25` and `R-35` ran the entire suite three times to answer a question one filtered run answers. The cost was not the wasted minutes; it was that a long unattended run is exactly the condition the landmine above needs.

  - **THE REMEDY WAS PROVED IN BOTH DIRECTIONS RATHER THAN ASSERTED.** A remedy that cannot fail is worth nothing, so `RE-U-025` was watched failing before it was trusted. **Runtime**: reintroducing the exact deleted call turns it red with `expected 0n to be 20000n`. **Compile time**: deleting one key from the `Record<keyof RuleState, 'written' | 'carried'>` classification produces `TS2741: Property 'lifetimeSettledCents' is missing`.
