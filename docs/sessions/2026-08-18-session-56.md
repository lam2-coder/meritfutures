## 2026-08-18 - Session 56: `INV-07` gains a proposed `R-31` exception, and the ruling ratifies the engine (non-money, ADR only)

- **Done:** **[ADR-056](../decisions/ADR-056.md) is written as `status: proposed` with an unsigned founder-approval line**, giving `INV-07` a stated, cited, testable exception at the `R-31` funded reset in [ADR-050](../decisions/ADR-050.md)'s shape. **`056` was claimed in [ALLOCATION](../decisions/ALLOCATION.md) before the ADR was written and after all twenty-eight remote refs were read**, by file and by claim. **No document was amended, no engine file was touched, and no fixture was written.** 17 of 17 gates pass clean and fail dirty, 19 scope cases hold.
- **Next:** **The signature, and the ADR asks for a run before it.** The second-funded-day breach the ruling turns on is a **derivation from the `DO` ordering, not an execution**, and [ADR-053](../decisions/ADR-053.md)'s precedent is that a defect of this shape is executed rather than argued. On acceptance: three `M01` amendments (`INV-07`, `R-31`'s effects list, `R-15`'s permanence clause), the `RE-P-02` row, and **one fixture that starts in eval, crosses the pass and pins `floor_locked: false`** — named in the ADR and deliberately not written.
- **Blockers:** **Approval is `PENDING` by design**, not by omission. The ruling amends a frozen invariant, a frozen rule's effects list and a frozen rule's permanence clause, all money path, so it is not taken on a session's authority ([E2](../../MERIT_BUILD_MASTER_PROMPT.md)).
- **Landmines:**

  - **THIS RULING RATIFIES THE ENGINE RATHER THAN REVERSING IT, WHICH INVERTS WHERE THE RISK SITS.** [ADR-052](../decisions/ADR-052.md) and [ADR-054](../decisions/ADR-054.md) both decided against the engine, so their exposure was shipped behaviour. Here the engine is **right** and undocumented: [`progression.ts`](../../packages/rules-engine/src/day/progression.ts) already writes `floorLocked: false`. **The exposure is therefore a session reading `INV-07` and `R-15` literally and "correcting" the code toward the document** — a change that would look like restoring a frozen invariant and would breach every funded account. An undocumented correct behaviour is not a smaller problem than a documented wrong one; it is a problem whose repair looks like diligence.

  - **`ADR-052` CONVERTED A FROZEN FLOOR INTO A BREACH, AND THE SESSION BRIEF WAS RIGHT THAT THIS GOT SHARPER.** Under the superseded `max` reading, carrying the lock left the floor merely stuck: `R-13`'s guard freezes `hwb`, so the trailed term never moves. Under the **assignment**, `DO-7` re-assigns `floor_lock_floor_at_cents` on the first funded day, which is `size + 10,000` on all three v1 plans while `R-31` set the balance to exactly `size`. **The floor lands 10,000c above the balance and the account breaches on its second funded day.** The `max` and the assignment differ in kind here, not in degree.

  - **THE REPAIR THAT MATTERS MOST IS TO `R-31`, NOT TO `INV-07`.** `R-31`'s effects list is explicit and finite — phase, balance, `hwb`, floor, three counter groups, the consistency period start — and it silently omits **the one field that decides whether the funded phase exists at all**. The engine had to answer it in a comment because the rule did not. An invariant amendment alone would leave the next reader deriving the same answer from `R-13`'s guard a third time.

  - **A DECISION WITH NO AUTHORITY IS A LAYER BELOW A CITATION OF AN AUTHORITY THAT DOES NOT EXIST, AND `CI-06q` CANNOT SEE IT.** [Session 53](2026-08-17-session-53.md) wrote `CI-06q` because a merge-blocking stage cited a founder ruling that never happened. **The `floorLocked` derivation is the same class one level down**: not a false citation, but a real decision recorded only in a source comment, citing nothing. `CI-06q` matches a written form and a comment that cites nothing matches nothing. **The gate's own stated blind spot turns out to have an instance sitting in the engine**, which is worth more than the gate would have been if it had covered it.

  - **THE FIXTURE CLAIM WAS VERIFIED RATHER THAN INHERITED, AND IT IS STRONGER THAN THE BRIEF STATED.** The brief said no **batch-4** fixture pins `floor_locked` across an eval pass. Checked against the directory: **no fixture at all does.** All nine that pin the field — `GS-015`, `GS-016`, `GS-054`, `GS-055`, `GS-056`, `GS-061`, `GS-064`, `GS-065`, `GS-070` — **start in the funded phase**, so none crosses the reset; the two that do cross it, `GS-044` and `GS-242`, pin **no floor field at all**. A first pass over the yaml files reported three false positives by matching rule **citations** rather than a phase transition, which is the extraction error [session 51](2026-08-17-session-51.md) and [session 53](2026-08-17-session-53.md) each recorded in a different registry.

  - **`CI-06n` CAUGHT THIS SESSION'S OWN FIRST COMMIT.** The stub was committed before anything else, per the brief, and it had no row in the sessions README. The gate reported it on the next run. Recorded rather than quietly repaired, because it is the cheapest possible demonstration that the registry-index gate is live on a file written minutes earlier.
