### What the parse had to survive, and both cases are already in the tree

**`ADD CONSTRAINT` APPEARS IN A COMMENT AND IT IS NOT A RE-ADD.** [`0032:88`](../../packages/db/migrations/0032_trading_calendar_holidays_coverage_revisions.sql) reads *"every `ADD CONSTRAINT` below validates against an empty table and cannot be read as evidence that any row satisfies it"*. A naive `matchAll` reads the words `ADD CONSTRAINT below` and adds `below` to the live set, which is harmless; the same reader would read a comment naming a REAL constraint as a re-add and **remove a needle**. **A shortened needle list is the failure this gate cannot see itself have**, so SQL comments are stripped before both matches, and the vacuity throw is the backstop for the case where the whole list goes.

**BOTH EDGES OF THE MATCH ARE LOAD-BEARING, AND NEITHER IS HYPOTHETICAL.**

| Edge | What is actually in the tree | What a loose edge would do |
|---|---|---|
| **Right** | `0037` names its replacement by SUFFIXING the retired name | Report the LIVE constraint as a citation of the dead one at every site that names it, including the probe written to assert the replacement |
| **Left** | Every supersession migration's FILENAME is `NNNN_supersede_<the retired name>.sql` | Turn every link to that file into a finding: [INDEX](../INDEX.md), [ALLOCATION](../decisions/ALLOCATION.md) and a dozen session logs carry one |

**This is the `@vitest/browser-playwright` lesson on a name that is a PREFIX of a live one**, and it has its own scope case with the `SEEDS` entry as its control: `the-filename-and-the-suffix-are-not-citations` writes both shapes into a file that is in no permitted class and requires **PASS**, and the control writes the bare name into the same path and requires the finding. A gate that had stopped reading anything at all would pass the first and fail the control.
