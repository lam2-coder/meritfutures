### 2. What was ruled

**`cancelled` is the terminal edge, and it lands because `LT-06` has not
posted.** `G-TRADER-CANCELS` is drawn from `requested` and `cooling`, both
before approval, so the trader's wallet claim was never extinguished and there
is nothing to discharge. `0057`'s own `COMMENT ON FUNCTION` says exactly this.

**`settled` is not built, in either form, and it is held by a rail rather than
by a decision.** Nothing can have observed money leaving, so an operator door
would record an assertion with no possible referent. **`failed` is refused on
that ground plus `WD-C1`'s demand for `LT-09`**, which needs the ledger
authority ADR-165 declined and a worker door outside this fence.

**A cancellation carries no guard except the halt.** Approval's eight holds each
guard a movement; a cancellation moves nothing, so an identity, KYC or
destination term would trap the row open and the identity behind it, which is
the lockout this edge exists to end. **No dual control at any amount.**

**The halt holds a cancellation, fail closed, and the database does not agree.**
Executed: every constraint permits a halted `requested` row to reach
`cancelled`. The hold is ADR-232 section 5's direction one arrow over, it is one
branch of one function, and it is named as overturnable.

### 3. What `0072` does, and the sentence it repairs

**`WD-C1` holds three ways and one of them is a claim about an arrow set nothing
enforced.** EXECUTED before a line changed: **an `UPDATE` from `approved` to
`cancelled` LANDS**. Harmless today only because no door drives the approval
edge; the day `LT-06` posts it leaves the obligation standing with the wallet
claim already extinguished, which is the exact defect `0057` exists to refuse.

**`WD-C2`, two assertions under one id**: a terminal status is never LEFT, and
is ENTERED only along a drawn arrow and never at `INSERT`. Plus `cancelled_at`,
the third terminal clock and the last one missing, with `0070`'s pair shape.

**It is `NOT DEFERRABLE` where `WD-C1` is deferred**, because it reads only
`OLD` and `NEW`. **The ordering that creates with `0031` is executed rather than
argued**: a frozen `approved --> settled` still refuses on
`wallet_withdrawals_live_freeze_blocks_settlement`, so `probe_payout_hold.sql`
passes unchanged and still tests the halt.
