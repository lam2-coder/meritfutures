### Why `exportEvidence` still does not join `IMPLEMENTED_ADMIN_READS`

**A METHOD IS NOT A PORT, AND HERE IT IS NOT EVEN A WHOLE METHOD.** `composeImplementedAdminReads` takes ONE parameter, an `AdminSourceBackend`, and two of `exportEvidence`'s three dependencies cannot come from a door onto this database.

**`EvidencePackStore` is object storage and nothing in this tree is one.** It returns a `storage_ref`, a signed `download_url` and an `expires_at`; `evidence_packs.storage_ref` is `text NOT NULL` carrying the DDL's own comment, *"Private object storage, signed URL only. Never a public path"*. A sweep over every `.ts` file under `apps/api/src` finds **exactly one** that mentions `EvidencePackStore`, and it is the file that declares it. A store is not a table, so no registration reaches it, and a `download_url` invented in this file is a pack an operator cites and nobody can open.

**`EvidencePackWriter` is an INSERT and its home already exists one directory over.** [`routes/admin-writes.ts`](../../apps/api/src/routes/admin-writes.ts) names `evidencePacks` in `ADMIN_WRITE_TABLES` and `AdminWriteTx` declares `insert`. **This directory's stated property is that it holds a handle it CANNOT WRITE THROUGH** -- `FlagsTx`'s docblock says `insert`, `updateAt`, `deleteAt` and `sqlExecutor` are "ABSENT rather than unused", and `admin-source/index.ts` says `AdminSourceTx` is read-only "because every arm of the intersection is read-only". Minting a write arm here to serve one method would trade that property, directory-wide, for a row a file that already may write it can write.

**So `admin-source/index.ts` is not touched at all.** `IMPLEMENTED_ADMIN_READS` stays at four, the missing list stays at three, `start.ts` calls no setter and `{ declared: 23, wired: 6, blocked: 17 }` is re-run rather than predicted.

**The `setAdminReadSource` entry's stated reason is narrowed by this slice and is not retired by it**, which is `events.ts`'s move and is adopted. That reason reads "A READ SHAPE ... None of the six methods is a projection of one table ... A live adapter today would have to reach `sqlExecutor`". For `exportEvidence`'s READ that is now measured false: eleven keyed reads plus ordinary code, no executor, no `pg`, no cast. **What is left for that method is not a shape at all, it is a store and a write door.** `wiring.test.ts` is not this fence and reporting the narrowing is the whole of what the precedent allows.

### Three corpus findings, each read at source

### 1. There is no `rule_text` column and "the plan's rule text" is `copy_blocks`

`GS-112` requires a trader pack to carry "the plan's rule text". `plan_versions` carries `rules`, `copy_blocks` and no such column.

- [`0028_supersede_plan_version_immutability.sql:24`](../../packages/db/migrations/0028_supersede_plan_version_immutability.sql) names it in its own words: a retirement must not "have rewritten `copy_blocks` (the published rule TEXT)".
- [`M04:48`](../plans/M04-trader-portal.md)'s `INV-M4-08` says the same from the reading end: "Every rule sentence on any screen comes from `copy_blocks` on the account's pinned plan version".

So the map carries `copy_blocks` whole and invents no `rule_text` key. **The existing suite's `plan_version` fixture uses one**; that is a fixture's shape and this adapter answers to the schema. A case pins both halves: the map has `copy_blocks`, and `schemaColumns('planVersions')` has no `ruleText`.

### 2. A flag's detector lives on the run

`risk_flags` has `detector_run_id` and no `detector` column; `detector_runs` carries `detector` and `detector_version`. That is [`flags.ts`](../../apps/api/src/admin-source/flags.ts)'s reading of the same two tables, with the version it does not need. **An unattributed flag carries `null` and not a sentinel**, because `EvidenceFlagRecord` types the field nullable and the two answers are a value and no value; `flags.ts` renders `UNATTRIBUTED_DETECTOR` because its queue column is a string, which is a different field with a different type.

### 3. The ToS clause is two keyed reads and a refusal

STATE's finding B and `EvidenceFlagRecord`'s own docblock: `risk_flags` carries no clause column, a clause lives on the ENFORCEMENT that cites the flag, and `DEP-M7-05` still owes two of the three texts. Both enforcements are reachable by equality:

- `payout_requests.hold_flag_id` and `hold_tos_clause`, both-or-neither under `payout_requests_hold_is_complete` ([`0031:62-72`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql)).
- `identity_restriction_episodes.flag_id` and `tos_clause`, both `NOT NULL`.

**Where the two cite one flag under DIFFERENT clauses, this refuses.** `EvidenceFlagRecord.tos_clause` is one string, a pack is the document a dispute is argued from, and an exhibit stating one clause while the firm's record holds two is the pack citing a rule the firm did not cite for the other enforcement. It is `EvidenceExportError` because that class's own sentence is "the generator was asked for something it must not guess about". **A ruling that makes the field a list retires this refusal, and it is registered as owed rather than pre-empted.**

### Three values `canonicalJson` cannot render, and only one fails loudly

The pack IS `canonicalJson(document)` and `content_sha256` is the digest over exactly those bytes, so a value that renders wrongly is an exhibit that is wrong **and self-consistent about it**.

| Value | What happens | Demonstrated by |
|---|---|---|
| `bigint` | `JSON.stringify` THROWS. Every surrogate key and every cents column on these tables is one | `canonicalJson({ balance_cents: 5012500n })` throws `TypeError` |
| `Date` | Reaches `asRecord` through the branch every record takes, has no own keys, renders as `{}`. **Silently** | `canonicalJson({ executed_at: new Date(...) })` is `'{"executed_at":{}}'` |
| `Uint8Array` | Renders as an object keyed by byte index | `'{"source_hash":{"0":222,"1":173}}'` |

Each is asserted FAILING before the projection is asserted fixing it, because a suite that only checked the projected row would pass against a projection that had never been needed.

**An identifier is text and a quantity is a number, and the split is `events.ts`'s ruling reused.** API_CONTRACT section 8 carries `events.id` as a string because "a JSON number loses that ordering past 2^53", and `fills.id`, `daily_marks.id` and `rule_states.id` are the same `bigint GENERATED ALWAYS AS IDENTITY` column. Money goes the other way and `assertIntegerAmounts` is why: it walks the finished document and refuses a fractional NUMBER, and a cents column carried as a string would walk past that control. So `int` carries cents as a number **and refuses anything outside the safe integer range**, which makes the precision this file will not lose silently the precision it fails on.

### The suite found a real defect in this session's own guard

`jsonSafe` exists to refuse a `jsonb` value `canonicalJson` cannot render. **Its first version was written on `asRecord`** -- and `asRecord` accepts any non-array object, which is the exact predicate that renders a `Date` as `{}`.

The seeded case (a `Date` inside `rule_states.engine_gates`) went red on the first run with the projected `engine_gates` rendering as `{"at":{}}`. **A guard against a predicate cannot be spelled in terms of that predicate.** `plainRecord` checks the prototype instead, `asRecord` stays where it is correct -- over documents this file composed itself -- and the case that caught it is kept with the reason in the docblock.

### The column maps are the trader allowlist, which is why they are maps

`buildEvidenceDocument` filters `flags` through `TRADER_FLAG_FIELDS` and carries `account`, `identity`, `fills`, `marks`, `rule_states` and `plan_version` **through whole, at every audience**. So whatever this adapter puts in those six is what reaches a trader, and a column added to `accounts` next year would reach one the day it landed if the adapter read rows with a spread.

`EVIDENCE_COLUMNS` names every column of the six tables, with the Drizzle property name AND the column name, and the suite reads [`packages/db/src/schema.ts`](../../packages/db/src/schema.ts) and asserts each map against it **in both directions**. A name the map has and the table does not is a typo nothing else would catch; a name the table has and the map does not is a decision somebody has to make. **A new column is a red suite, not a disclosure.**

**The reader is asserted non-vacuous first**, on `falsify.mjs`'s own warning about a table that went from 36 rows to 0 while every gate stayed green: a case checks that `schemaColumns('accounts')` has more than twenty entries and that `schemaColumns('thisIsNotATable')` has none, so an empty regex cannot make every map case pass by matching nothing.
