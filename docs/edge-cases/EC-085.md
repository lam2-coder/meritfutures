## EC-085: A rules page that is removed breaks the evidence it was cited in  (2026-08-14, module: M9, status: specced)
- Scenario: A trader is pinned to plan version 1 and enforced under it. The public rules page shows version 4. If superseded versions are removed, every link ever shared to that page breaks, including links inside evidence packs and inside the trader's own email history. If they are kept but unlabeled, a stranger can land on a superseded document and read it as current. Both failures land on the same page, and the evidentiary one is worse: M6's packs include the pinned `plan_version` and its `copy_blocks` precisely so the rules as marketed and the rules as executed are both in the pack, and that guarantee weakens if the public artifact those blocks came from is unreachable or has quietly become a different document at the same address.
- Correct behavior: Every plan version receives a **permanent public URL** (`plan_versions.public_slug`, SD-M9-01) that survives being superseded. A superseded page resolves forever, is unmistakably labeled, names the version that supersedes it, and is excluded from indexing and from every navigational path, so it is reachable by link and unreachable by browsing. The portal's per-account rules page (SC-M4-05) renders the account's pinned version and links to that version's permanent URL, so the public and private surfaces agree by construction. Support quotes the account's pinned version retrieved from the admin console, never the public site, and a runbook says so.
- Golden scenario ref: GS-148.
