## EC-091: The public verification page is an oracle about the firm's own book  (2026-08-14, module: M11, status: specced)
- Scenario: `GET /verify/:code` is public, unauthenticated, and answers a yes-or-no question about whether Merit issued a claim. Short, sequential, or low-entropy codes let an attacker enumerate and harvest every pass and payout Merit ever certified, with amounts, plans, sizes, and dates. The strategic damage is not privacy: it lets a competitor compute Merit's real pass rate, payout volume, and average payout independently and contradict the transparency page using Merit's own signed artifacts. The smaller version re-identifies traders by joining an enumerated corpus against public handles and shared screenshots.
- Correct behavior: Make the space unwalkable rather than merely rate limited: **128 bits of entropy, no sequence, no structure**, plus constant-time responses so timing does not become the oracle the code space is not. Rate limit per IP and per ASN, record `certificate_verifications` with hashed inputs, and emit `certificate.verify_anomaly` on the signature no legitimate traffic makes (high distinct-code rate with a near-total unknown rate). Keep claims minimal (INV-M11-01) so even a complete harvest yields facts about accounts and never about people. And hold a stated position for the case where an outsider does derive an aggregate that disagrees with M12: **publish the method difference rather than dispute the arithmetic**, which is available precisely because M12's numbers carry a published method.
- Golden scenario ref: GS-158.
