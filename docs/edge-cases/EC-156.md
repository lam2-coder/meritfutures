## EC-156: A halt that is representable and unenforced  (2026-08-16, module: M20, status: specced)
- Scenario: [`0011`](../../packages/db/migrations/0011_wallet.sql) gave `wallet_withdrawals` a full freeze vocabulary: `frozen_at`, `freeze_flag_id`, `freeze_expires_at`, and an index over the freeze expiry. **`wallet_withdrawal_status` has no frozen value and never had one.** So an operator could write every column a halt consists of, the row would carry a cited flag and a live clock, the freeze-expiry index would find it, and **nothing would refuse settlement**: the row still matched `wallet_withdrawals_open_idx`, the rail still read it as `approved` or `transferring`, and the money still left. **The halt was fully representable and entirely unenforced**, which is the most dangerous shape a control can take, because every artifact a reviewer would check for exists. This is the external leg of [ADR-040](../decisions/ADR-040.md)'s ruling, where a flag is raised **after** wallet credit and the money is already the trader's, so it is also the case where an unenforced halt is least recoverable.
- Correct behavior: **The external leg gets enforcement rather than a state**, and the asymmetry with `held_pending_review` is deliberate rather than an oversight. On `payout_requests` the hold **replaces** approval and is mutually exclusive with every other status, so it is a status. On `wallet_withdrawals` the halt is **orthogonal** to the rail state, because a halted withdrawal is still `approved` or `transferring` as far as the rail is concerned, and collapsing an orthogonal hold into the rail's status column is precisely `SD-M5-06`'s named mistake. So [`0031`](../../packages/db/migrations/0031_payout_hold_and_identity_restriction.sql) adds `wallet_withdrawals_live_freeze_blocks_settlement`, a CHECK that a withdrawal carrying a live freeze cannot be `settled`, and **re-creates the open index so a halted row stays visible** to the operator and to the sweep, because a halt that removes the row from the only index anyone scans is a halt nobody can find. The same 48 hour clock runs on the same hourly sweep. **Release resumes the rail and does not re-pay**, because the money is already the trader's, which is the discriminator that separates this from the pre-approval hold entirely.
- Golden scenario ref: GS-277
