## EC-158: An additive conflict resolution duplicates a generated line, and the only check that sees it looks like the noisy one  (2026-08-30, module: tooling, status: specced)
- Scenario: A wave merge of `origin/main` into a session branch conflicts in [`docs/STATE.md`](../STATE.md) or a registry README, because both sides appended a section at the tail. **When one line is byte-identical on both sides of a single hunk, an ADDITIVE keep-both resolution writes it twice.** In this corpus that line is very often a generated one: session sections carry a formulaic position sentence holding two `gate_count` spans, and the registry preambles carry `manifest_changes`, `migration_files`, `ec_count` and `e2_files`. **Two of the three checks that could plausibly see the result are silent by construction.** [`CI-06g`](../testing/STRATEGY.md) rewrites every span it finds and compares each to its own query, so two correct copies of one correct span both pass and `gates.mjs check` reports every gate green over the broken file; `RI-12`'s ceiling is 8 and the duplicate sits at 2, and that ceiling cannot fall because [ADR-282](../decisions/ADR-282.md) measured it saturated by a legitimate line. **`RI-31` is the only check that ever sees it**, and it has now fired on five consecutive merges, which is where the landmine is. **A session meeting a check that has failed five times in a row will consider that the check is noisy, and it has the sign backwards.** Measured on this tree at [ADR-300](../decisions/ADR-300.md): across the sixty commits of `main` in which `RI-31` exists, the number carrying a duplicated generated line is **ZERO**; across the ten in which it does not yet exist, it is all ten, and `9f4a8f4a`, a first-parent merge commit on `main` itself, carries **thirteen duplicated generated lines over three files at fifty excess copies**. **The four firings are four occasions on which a thing that used to land on `main` was stopped at the branch.** The defect belongs to the resolver's keep-both branch and not to registry merging in general: the fifth merge in the run, `3a1e1aa6`, resolved three markdown conflicts by hand and is clean.
- Correct behavior: **Resolve the conflict by whatever means, then run the mandated verification set, and if `RI-31` is red, collapse exactly what it names.** Its message gives the file, every line number, the copy count and the first ninety characters of the offending line, so the repair is mechanical. **`RI-31` IS NOT TO BE WEAKENED, NARROWED, RE-SCOPED, MADE CONDITIONAL OR RETIRED**, and neither is `RI-12`, which stays for the reason its own header gives. **No repository-side preventive control is available and this was tested rather than assumed** ([ADR-300](../decisions/ADR-300.md) section 3): a committed `.gitattributes` naming a custom merge driver falls back to the default text merge **silently**, with no warning of any kind, because the driver definition lives in per-clone untracked git config; and `merge=union`, the one driver built into git that needs no config, merges with **exit 0 and no conflict at all** while producing the duplicate, so it institutionalizes the defect and removes the conflict marker that is the only reason anybody reads the hunk. **One caveat on `RI-31`'s own remediation sentence, which is a heuristic that reads as a rule.** It says *"Keep the first and delete the rest"*, which is right for a merge artifact, where the two copies are the two sides of one hunk. It was **not** right for at least one of the fifteen instances ADR-282 repaired, where a sentence had been splattered into five session sections of `docs/STATE.md` and its home was a specific session rather than the earliest occurrence. **Confirm which copy belongs where before deleting.**
- Golden scenario ref: **none owned.** This is a defect in a merge tool that is not tracked in this repository and it owns no product behavior, so there is no fixture to write and no rules-engine path to pin. Its executable record is `RI-31` itself, which runs in the mandated pre-push set and in `CI-01` on every push and every pull request, and whose nine suite cases in [`repo-invariants.test.ts`](../../packages/tooling/test/repo-invariants.test.ts) include four directions it must stay quiet in.
