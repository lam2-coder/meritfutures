## EC-093: A certificate system becomes an aggregate publisher by accretion  (2026-08-14, module: M11, status: specced)
- Scenario: Nobody decides this. A trader's card list makes a "lifetime paid" total one addition away. A profile page makes a count obvious. An affiliate widget showing "Merit has issued 4,102 payout certificates" is true and appealing. At the end of those steps M11 publishes aggregates about Merit's payout book from a system with no method page, no trailing window, no sample-size floor, and no reconciliation, competing with M12, which has all four. And the numbers are subtly wrong: cards are deferred, withheld, revoked, and issued per ladder ordinal, so a count of certificates is not a count of payouts in a direction nobody has characterized.
- Correct behavior: A hard scope rule rather than a guideline. **M11 issues and verifies individual claims and never sums, counts, or averages anything for publication**, on the verify page, a profile, a widget, or an API response. A trader's own list may total the trader's own cards, because that is arithmetic they can already do and it is not a published statistic. Every request for a public aggregate routes to M12, which will publish it with a method, a window, and a sample-size floor, or will decline to; that routing is the entire reason M12 is a separate module rather than a page in this one.
- Golden scenario ref: GS-161.
