## EC-145: A widening that is safe for login is a hole at the point of action  (2026-08-16, module: M04, status: specced)
- Scenario: [ADR-039](../decisions/ADR-039.md) widens C-01 from two passwordless factors to three, **any single factor sufficient for login**. SMS OTP is the new one, and it is the only factor in the set that can be stolen without touching the customer's device or credentials: a SIM swap moves the number, and SS7 or signalling interception, device malware or a code rendered on a lock screen read it while leaving the number exactly where it is. **The widening is correct and the hole is not in the widening**, which is why this entry exists at all: an attacker who completes SMS OTP holds a genuine, correctly issued session, and every control that guards the login moment has already passed. If sensitive actions are reachable from any valid session, the third factor has silently become the weakest link on the money path, and the two interception rows are separate threats because interception never trips the phone-change controls.
- Correct behavior: **C-27, the authentication and authority boundary**, and it is written down rather than left as an emergent property of two rules. Any single factor establishes a session sufficient for **every read surface**. No single factor, and **specifically never SMS alone**, is sufficient for a sensitive action: payout destination change, contact change of either kind, or external withdrawal. Each requires a **passkey assertion or a dual-channel confirmation**, which **elevates** the session rather than re-establishing it. **A SIM-swapped session can see everything and change nothing.** The enforcement is a vocabulary rather than a handler: `sessions.elevated_by_factor` admits `passkey` and `dual_channel` and nothing else, so an SMS-established session **cannot elevate itself at all**, because the database has no value for the thing it would have to write. `sessions.auth_factor` is what makes the refusal possible in the first place, since a handler cannot refuse a session for how it was established if the session never recorded it, and that is why the delta exists rather than being an optimisation. **A widening is not a weakening**, and the stuffing-immunity claim in [SECURITY §2.6](../architecture/SECURITY.md) is unchanged and is the reason: immunity to stuffing is a property of retaining no password, not of how many passwordless factors exist. **The boundary is shown rather than hit**: a non-elevated session sees each sensitive action disabled with its reason and its route, instead of failing after the fact. `CI-06k` asserts the declaration exists and is non-single for every action C-27 names, because an enforcement that lives only inside handlers is one no reviewer can audit.
- Golden scenario ref: GS-266, GS-267, GS-268
