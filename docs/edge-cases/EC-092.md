## EC-092: An opt-in leaderboard is a target list ordered by value  (2026-08-14, module: M11, status: specced)
- Scenario: DATA_MODEL reserves `display_name` and `leaderboard_opt_in`, and every competitor publishes a leaderboard. From the adversary's side it is a curated, continuously updated list of the most valuable targets in the estate: the largest balances, the traders most worth impersonating, and the people a paid-passing service most wants to recruit or advertise against (dossier item 3). Three uses need nothing broken: recruit the top names into an account-management arrangement now prohibited by the copy-trading clause but only detectable after it starts; target them for account takeover, since the list says which sessions are worth stealing; or advertise against them.
- Correct behavior: Opt in, reversible, and **retroactive on opt out**, because a leaderboard nobody can leave is a publication rather than a feature. Display names never legal names. **No plan size on a public entry**, since size is the field that converts a ranking into a target list ordered by value, and publish ranks and relative performance rather than absolute balances. Treat opt-in status as a risk signal rather than a risk factor: M7 raises session and destination-change monitoring for participants, which is cheap and is the correct response to a self-selected high-value population. Whether it ships at launch is OQ-M11-03, and the recommendation is that it does not, because it is a retention feature with a security cost in a quarter whose retention problem is not yet measured.
- Golden scenario ref: GS-160.
