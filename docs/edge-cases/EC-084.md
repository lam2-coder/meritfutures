## EC-084: Solicitation and sale are different acts, and only sale was defended  (2026-08-14, module: M9, status: specced)
- Scenario: Geo restriction is enforced server side at checkout (M3) and at verification (M19), so a resident of a restricted jurisdiction cannot buy. The marketing site is nonetheless a global, indexed, actively promoted surface making an offer in every jurisdiction, and paid acquisition plus affiliate creatives are evidence of solicitation independent of whether any sale occurred. Every engineering control is present and working; the gap is that "cannot buy" and "was not solicited" are different claims and only the first was designed for.
- Correct behavior: Treat the site notice as **disclosure and courtesy, never as a control**, and say so in its own documentation so nobody later reads it as enforcement. Edge geo lookup replaces the call to action with a notice naming the jurisdiction; a VPN defeats this and is expected to. The restricted list is **published as a page** rather than only enforced as an error. Paid acquisition and affiliate campaign targeting read the same `geo_restrictions` table checkout reads, so the targeting configuration and the enforcement configuration cannot drift apart. Whether the correct posture is a notice, a hard block, or the normal page is a counsel decision raised as OQ-M9-03 rather than assumed by an engineer.
- Golden scenario ref: GS-145.
