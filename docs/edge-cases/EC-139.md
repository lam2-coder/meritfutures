## EC-139: Cross-account loyalty rewards the population that completes ladders reliably  (2026-08-14, module: M14, status: specced)
- Scenario: [ADR-025](../decisions/ADR-025.md) replaces progressive cap release with perks earned by completing the **Nth ladder** across an identity's accounts. A completed ladder is five settled payouts on one account, which is a bounded, gated, detected achievement and therefore a defensible thing to reward. It is also exactly what a hedged pair or a small ring is engineered to produce. [EC-105](EC-105.md) establishes that a hedge earns streaks mechanically and [EC-123](EC-123.md) establishes that the graduating population is enriched for whatever M07 missed, so the identity reaching a third or fourth completed ladder fastest is not reliably the durable retail trader the program exists to keep. Three harms, ascending: a discount spent on somebody who was buying anyway, which is a bounded marketing loss; **bonus credit funding the next evaluation in the rotation**, which is [EC-132](EC-132.md)'s conversion machine fed by a rule a ring can satisfy on purpose rather than by a campaign somebody targeted; and **review-pool priority ordering M18's discretionary queue by the metric a ring optimizes**, which would hand the adversary the one thing [ADR-024](../decisions/ADR-024.md)'s discretion exists to withhold. What this is emphatically **not** is a liability finding: INV-M14-11 holds, INV-17's bound is identical for every identity at every tier, and the worst case is a bounded marketing loss plus a mis-ordered queue rather than a 40 percent increase in what an undetected ring may extract. Recording that comparison is half the point of the entry, because at review "rings can farm this too" reads like the same finding as [EC-104](EC-104.md) and is a different order of magnitude.
- Correct behavior: Perk issuance inherits **every exclusion win-backs already carry** (INV-M14-08), evaluated at computation **and again at issuance**: open severity 4+ flag, active restriction, chargeback in the window, reset-velocity ceiling. An identity under review **earns the milestone and receives nothing** until the review closes, and the milestone is **not revoked** when it closes, because the fact is true (INV-M14-09). Completed-ladder cohorts are an M07 input and never a trust signal (INV-M14-05, INV-M14-12). Bonus credit is **`promotional_credit`, never `trader_wallet`** (INV-M14-10), so value derived from it meets M20's P-1 hold on first withdrawal exactly as [EC-132](EC-132.md) already requires: loyalty is a new **source** of promotional credit and deliberately not a new **class** of it, so it inherits an existing control rather than needing one. Review-pool priority is an **ordering key with no trader-facing rendering** in v1; it never gates entry to the pool and it never implies an invitation. And the **perk budget is a configured ceiling** reported per cohort, so the failure mode is a budget alarm rather than a liability discovery.
- Golden scenario ref: GS-244, GS-245, and GS-243 for the bound invariance.
